## 日常使用

1. 在 AI.js Pro 运行 `main.js`（完整工程），或从主页面打开 `悬浮窗运行与测试.js`（悬浮窗面板）；只想先看识别效果就运行 `基础示例.js`（单文件演示，不依赖工程模块）。需要让游戏保持前台时用悬浮窗。
2. 选「只识别」先看棋盘与红黑识别；确认无误后用「着法建议」。只有「自动走棋」会点击棋盘。
3. 自动模式先选我方颜色；非标准开局需要明确声明「现在轮到我」。未知格、轮次不明、几何不可靠或落子未确认时，驱动应停止出手并给出原因。
4. 排障先记 **宿主 dev 版本 + 本工程版本 + 面板启动指纹**。APK 更新不会覆盖手机里已经导入的工程副本，旧副本需单独更新。

悬浮窗参数行可点「限时 / 固定层数」切换 Pikafish 搜索。限时模式默认自动按局面分配首搜与复核时间，总计不超过面板设置的时间上限（默认 5 秒）；策略菜单可关闭自动分配。关闭后使用手动预算：已确认盘面剩 16 子或更少时最多加到 7 秒，剩 10 子或更少时最多加到 12 秒；未知格不加时。固定层数模式滑动「目标」选 6～24 层，默认 12 层。模式按钮循环「限时 → 固定 3s → 固定 6s → 固定 10s → 限时」，默认最多等 3 秒；到时使用已完成的最深结果。因此目标层数固定，实际层数仍可能因超时或棋局结束而低于目标；日志会同时显示两者。K40 中局实测：12 层约 0.9 秒，16 层约 2.5 秒，20 层在 6 秒内仍未完成，追求速度可选 12～14 层。模式、层数、最长等待、线程和哈希保存在本机；自动运行配置可写 `"searchDepth": 12, "depthTimeoutMs": 3000`，`"searchDepth": 0` 恢复限时模式。固定层数需要包含新原生接口的 AI.js Pro 宿主。

棋盘定位优先使用本地 C++ SIFT：模板带有交点标定，平移和缩放后仍按比例计算 9×10 交点。字形、棋规和独立圆心校验通过时直接采用，省去粗扫校准；模板未找到时继续 Canny/Hough、图色格线法。逐帧复查两块河界文字参照，最多每 30 次再用 SIFT 复查；参照变化只触发 SIFT 复查；几何未变则继续读盘，确实变位才重新定位，暂未找到则拒绝帧等待稳定。多帧合并不能退回旧坐标。只缓存几何，每帧仍重新识别字形、判红黑并检查圆心证据。详见 [SIFT 模板与标定](assets/board-sift/README.md)。

## 一条运行主线

完整说明见 [项目架构与运行流程](项目结构.md)：包含模块职责、启动步骤、跨引擎通信、SIFT 几何缓存、搜索 Worker、落子确认、悬浮窗避让、求胜候选比较及日志排障入口，按 0.6.72 当前源码更新。

```text
main.js 主页面 → page-actions / panel-bus → 同工程悬浮面板
悬浮窗运行与测试.js → panel-app（也可直接启动）
  → bootstrap / game-session（装配服务与驱动）
  → board-service（稳定截图 → SIFT/格线定位 → 字形与颜色）
  → auto-driver（可靠局面、轮次、状态机）
  → search-worker → engine-router → 开局库 / 原生 Pikafish
  → move-ticket / click-executor（自动模式出手）
  → 新截图 → move-verifier（确认落子）→ 等对方 / 下一轮
```

`src/chess/` 是纯棋规和 FEN；`src/vision/` 负责生产定位、字形、颜色与证据融合；旧 YOLO 分类/OCR 融合位于 `experiments/`。图像与输入能力通过 `src/runtime/aijs-adapter.js` 适配，界面模块仍直接使用 UI/浮窗能力。`assets/models/chessai_160x320_v5r.onnx` 提供检测框等几何证据，生产棋子分类使用字形链；Pikafish 原生能力由宿主提供，NNUE 路径可配置。运行问题从入口、棋盘服务、驱动、引擎四层依次定位。

## 改动后验证

发布前必须同时通过场景回归、自检和悬浮窗启动检查。

在本工程目录运行 `node tools/run-regress.js`，它会运行场景回归、自检和格子契约。真机先用面板的只识别模式；`tools/vision-pipeline-probe.js` 仅用于旧链对照；**完整自动对局需要另行验收**，离线测试不能替代点击回屏和内存观察。

改识别链（`src/vision/**`）再跑一条 `node tools/glyph-pc-eval.js`：它用真实截图（仓库 `docs/reports/chess-skin-eval/` 的 9 帧、含真值）在**电脑上跑同一份** `glyph-recognizer.js`，不用刷机就能看到「严格盘面级 / 未知格 / 抢救」三个数字。

日常工具见 [tools/README.md](tools/README.md)；目录与模块职责见 [项目结构.md](项目结构.md)。PC 端测试留档统一收在 `reports/`（contract=契约 / regress=回归 / selfcheck=自检；git 已忽略、不参与运行）。23 个不再维护的 P4 一次性探针已移到仓库 `docs/archive/xiangqi-p4-probes/`，不再随 APK 内置示例发布。原长篇说明留在 `docs/archive/xiangqi-project-readme-before-simplification.md`，仅作历史记录。
