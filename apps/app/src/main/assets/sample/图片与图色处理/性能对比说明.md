# Rhino 与 QuickJS 图色耗时对比

原有图色实例使用默认 Rhino 引擎，耗时日志以 `[Rhino耗时]` 开头；QuickJS 新实例以 `[耗时]` 开头。

建议在同一台手机、相同屏幕画面和相同截图方向下，各运行 5 次后比较中间值。首次运行可能包含截图授权、OpenCV 初始化和文件缓存开销，不适合作为稳定结果。

- 单点和多点找色：运行 `多点找色耗时对比.js`，再运行 `QuickJS 新引擎/图色处理/02-截图找色与多点找色.js`。
- 模板匹配：运行 `找图/找出所有问号方块.js`，再运行 `QuickJS 新引擎/图色处理/04-模板匹配.js`。
- 截图和保存：运行 `截图并保存.js`，对照 QuickJS 图色处理实例的截图与保存耗时。

所有耗时实例均使用单调高精度时钟并保留 3 位小数：QuickJS 使用 `performance.now()`，Rhino 使用 `System.nanoTime()`。因此小于 1 毫秒的操作会显示为例如 `0.137 ms`，不再被 `Date.now()` 截断成 `0 ms`。

## 统一截图策略

- 普通单次找色和模板匹配继续使用 `captureScreen()`，立即取得最新缓存帧。
- `找到QQ红点位置.js`、`颜色获取和检测.js` 和实时触摸取色会使用 `images.captureScreen(true, timeout)`，操作后优先取得新画面。
- `截图并保存.js` 使用 `images.captureScreen(true, 100)`，保存当前新画面；100ms 未刷新时回退最近有效帧。
- QuickJS 的普通识别使用 `fresh: false`；持续视觉使用 `fresh: true, timeout: 50`；全分辨率保存使用 `fresh: true, timeout: 100`。

`fresh` 超时只会回退到最近有效帧，不会无限等待；首次还没有任何缓存帧时才会报告超时。
