# QuickJS 图色处理实例

这个目录内的脚本只使用 QuickJS 新引擎。截图和中间图像保存在 C++ `cv::Mat` 中，JS 中的 `NativeFrame` 只是句柄。

- `01-图色 API 自动回归.js`：优先运行，会自动检查像素、找色、多点找色、裁剪、缩放、灰度、压缩、保存和模板匹配；同时输出正常多点匹配耗时和 3 次全屏无命中扫描的总耗时/平均耗时。
- `02-截图找色与多点找色.js`：实际业务写法，分别输出截图、单点找色和多点找色耗时。
- `03-裁剪缩放灰度与保存.js`：图像处理和文件输出，分别输出每项 Native 操作的耗时。
- `04-模板匹配.js`：复用原项目 `图片与图色处理/找图/` 中的 `super_mario.jpg` 和 `block.png`，输出读图、单结果找图和多结果模板匹配耗时。
- `05-全分辨率与视觉加速对比.js`：在当前手机上分别测试全分辨率、720p 和 640p 截图及全屏找色耗时，并验证快速帧坐标自动映射。
- `06-快速帧模板坐标回归.js`：用全分辨率截图生成模板，在 720p 快速帧中自动缩放匹配，并验证返回的仍是原屏幕坐标。
- `07-截图首帧与稳定耗时测试.js`：分别统计首次截图、预缓存业务调用和连续截图吞吐，输出每帧数据、平均值、最小值、P95 与最大值，用于区分首帧等待和稳定耗时。

## 截图模式

```javascript
const precise = captureScreen({ mode: 'full', fresh: false });
const fast720 = captureScreen({ mode: 'fast', size: 720, fresh: false });
const fast640 = captureScreen({ mode: 'fast', size: 640, fresh: false });
const live720 = captureScreen({ mode: 'fast', size: 720, fresh: true, timeout: 50 });
const saveFrame = captureScreen({ mode: 'full', fresh: true, timeout: 100 });
```

全部图色和 YOLO 案例统一遵守以下规则：

- 普通单次找色、模板匹配和单帧 YOLO：`fresh: false`，直接读取最新缓存，启动延迟最低。
- 持续找色、实时 YOLO、点击后复检：`fresh: true, timeout: 50`，优先取新画面，超时回退缓存，不会卡死。
- 保存截图、要求画面与操作时刻一致：`mode: 'full', fresh: true, timeout: 100`，优先保证原始分辨率和时效。
- 性能对比案例会显式写出 `fresh: false` 或 `fresh: true`，避免把缓存耗时和等待新帧耗时混在一起。

不传 `fresh` 时等同于 `fresh: false`。设置 `fresh: true` 后会等待一张新帧；等待超过 `timeout`（默认 100ms，范围 0～5000ms）时自动回退到最近的有效帧。首次截图还没有任何缓存可回退时，超时会抛出异常。

Rhino 兼容引擎使用 `captureScreen()` 获得最新缓存帧；需要等待新帧时可使用 `images.captureScreen(true, 100)`。

视觉加速模式按屏幕短边缩放 Native 图像。`frame.width`、`frame.height` 仍是原屏幕尺寸，`frame.pixelWidth`、`frame.pixelHeight` 是实际参与计算的尺寸。`pixel`、找色、多点找色、模板匹配和 YOLO 的区域参数与返回结果都会自动换算为原屏幕坐标，因此 `click(result.x, result.y)` 不需要手动缩放。

全分辨率模式适合像素级精确找色和细小目标；720p 是默认视觉加速档，640p 更快但小目标与严格颜色阈值可能损失精度。快速模式中的坐标量化误差通常在原屏幕 1～2 像素以内。

长循环中必须在 `finally` 里调用 `frame.recycle()`，以便立即释放 Native 内存。`images.compress()` 是例外：它会按需要把编码后的字节复制成 `Uint8Array`。

实例计时使用 QuickJS Native 提供的 `performance.now()` 单调高精度时钟，日志统一保留 3 位小数，避免小于 1 毫秒的操作显示成 `0 ms`。
