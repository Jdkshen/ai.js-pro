Web#

网页注入（web）让脚本加载一个网页，并和页面里的 JavaScript 双向通信：脚本可以往页面里注入代码、读取 DOM；页面也可以反过来调用脚本里的函数。常见用途是用 HTML + Vue / Vant 之类的前端框架写复杂界面（比原生控件更好排版），然后用脚本提供数据与能力。

  • newInjectableWebView([activity]) <WebView> 创建一个自带注入能力的 WebView
  • newInjectableWebClient() <WebViewClient> 创建一个可注入的 WebViewClient，用于已有的 WebView（例如布局里的<webview>）

两个引擎都支持。和 Auto.js Pro 的差别是：Pro 用$ui.web.jsBridge配合autojs://sdk/v1.js注入页面 SDK；本引擎页面里提供的是rhino对象（用法见下文），页面代码不用改协议、直接rhino.call() / rhino.eval()即可。

页面里的rhino对象必须在loadUrl()/loadData()之前注册：Android 的 WebView 只在「文档开始」时把addJavascriptInterface注册的对象注入页面，注册晚了页面里永远是undefined。引擎已经替你把时机处理好了（设置 WebViewClient 时立即注册），只有自己用别的方式创建 WebView 时才需要手动attach()。

newInjectableWebView([activity])#

  • activity <Activity> 可选，WebView 所属的 Activity；不传则用当前 Activity
  • 返回 <WebView> 一个InjectableWebView，本质就是android.webkit.WebView

这是一个独立的控件：必须把它加进界面（或悬浮窗）才会显示并执行页面脚本：

var view = newInjectableWebView();
ui.layout(
    <vertical>
        <frame id="box" w="*" h="*" />
    </vertical>
);
ui.box.addView(view);
view.loadUrl("file:///sdcard/网页/index.html");

页面里的 JS 可以直接调用脚本里的全局函数：

<button onclick="rhino.call('onClicked', document.title)">点我</button>
<script>rhino.eval('doSomething(1, 2)');</script>

newInjectableWebClient()#

  • 返回 <WebViewClient> 可注入的 WebViewClient

用于界面里已经有的 WebView（布局<webview>标签或findViewById拿到的）：

"ui";
ui.layout(
    <vertical>
        <webview id="web" w="*" h="*" />
    </vertical>
);
var client = newInjectableWebClient();
ui.web.setWebViewClient(client);   // 这一步会同时把页面桥（window.rhino）注册好
client.inject('document.title = "来自脚本"');   // 排队到页面加载完成后执行
ui.web.loadUrl('file:///sdcard/网页/index.html');
  • client.inject(script[, callback]) / view.inject(script[, callback]) <void> 在页面里执行一段 JS；页面还没加载完时会先排队；callback收到的参数是页面里这段代码的求值结果（JSON 字符串）
  • view.loadUrl(url) <void> 加载网址，支持file://、http(s)://与data:
  • view.loadData(data, mimeType, encoding) <void> 直接加载一段 HTML
  • view.reload() / view.stopLoading() / view.getUrl() <void / string> 刷新、停止加载、取当前地址

client.attach(webView)#

  • webView <WebView> 目标 WebView
  • 返回 <void>

把页面桥（页面里的rhino）和 WebView 设置（开启 JS、允许file://页面访问本地文件）提前应用到目标 WebView。必须在loadUrl()/loadData()之前调用。

正常用法下不需要手动调用：webView.setWebViewClient(webClient)时引擎会自动完成（Auto.js 的经典写法就是先设置 client 再 loadUrl）。只有把 WebView 交给别的 client、或自己封装加载流程时才需要显式attach()。

页面里的 rhino 对象#

  • rhino.call(name, arg1, arg2, ...) <void> 调用脚本里的全局函数name，参数按字符串传入
  • rhino.eval(code) <string> 在脚本引擎里执行一段脚本代码，返回结果的字符串形式

示例：页面点按钮时，把数据交回脚本处理。

<button onclick="rhino.call('saveData', JSON.stringify({ name: '张三', age: 18 }))">保存</button>

global.saveData = function (json) {
    var data = JSON.parse(json);            // 参数按字符串传，JSON 自己解析
    files.write('/sdcard/数据.json', JSON.stringify(data));
    toastLog('已保存 ' + data.name);
};

rhino.call的参数只有字符串可靠（Android 的 JS 桥限制：Object参数收到null，可变参数直接丢失）。要传结构化数据请先JSON.stringify()。数字、布尔同样会被转成字符串。

注入时机（重要）#

页面里的rhino只有在页面开始加载之前注册才可见。三种写法引擎都会处理好：

  1. ui.web.setWebViewClient(newInjectableWebClient()) —— 引擎在setWebViewClient时就完成注册（推荐，兼容 Auto.js 经典写法）；
  2. newInjectableWebView() —— 控件创建时注册，之后随便 loadUrl；
  3. 手动 client.attach(webView) —— 在loadUrl()之前调用。

另外要注意：inject(script)注入的代码在页面加载完成后才执行，所以页面自己的脚本跑起来时脚本注入的代码可能还没到。页面里要用脚本注入的东西（例如自定义的$autojs对象），先进轮询等待：

whenBridgeReady(function () {
    // 这里再用注入进来的对象
});
function whenBridgeReady(fn) {
    if (window.$autojs) { fn(); return; }
    setTimeout(function () { whenBridgeReady(fn); }, 30);
}

完整示例#

"ui";
ui.layout(
    <vertical>
        <webview id="web" w="*" h="*" />
    </vertical>
);

var client = newInjectableWebClient();
ui.web.setWebViewClient(client);
ui.web.loadData(
    '<html><body><h1 id="t">hello</h1>' +
    '<button onclick="rhino.call('onClicked', document.getElementById('t').innerText)">读标题</button>' +
    '</body></html>', 'text/html', 'utf-8');

// 页面 → 脚本
global.onClicked = function (text) {
    toastLog('页面里的标题是：' + text);
};

// 脚本 → 页面：读 DOM，结果通过 callback 回到脚本
sleep(1500);
client.inject('document.getElementById("t").innerText', function (value) {
    console.log('页面标题 = ' + value);
});

复杂前端界面（Vue2 + Vant 的单文件组件、依赖全部随示例携带、离线可跑）可参考示例复杂界面/Vue2+Vant(SFC)。

引擎差异与已知限制#

  • 页面 → 脚本的时机：Rhino 引擎里rhino.eval/rhino.call是在脚本线程上同步执行的，脚本正好在sleep()或长循环里时，页面的调用要等脚本空下来；QuickJS 引擎则是入队异步执行（不会互相卡住）。
  • injectAndWait：QuickJS 引擎不支持（需要跨线程同步求值），会直接报错，请改用inject(script, callback)。
  • 页面的 console.log 不会出现在脚本控制台，需要回传时用rhino.eval('console.log 的内容交回脚本')或让页面调用rhino.call()。
  • iOS / 桌面端没有该模块。
