共享截图与连续触控

AI.js Pro 扩展 API，Rhino 和 QuickJS 均支持。已内置到引擎，无需外置 dex / so。

images.shareScreenCapture()

先成功申请截图权限，再调用本函数，返回字符串共享凭据。重复调用返回当前会话的同一凭据。

if (!images.requestScreenCapture()) throw new Error("未授权");
var token = images.shareScreenCapture();
var childSource = '// @engine quickjs\n' +
    'images.useSharedScreenCapture(' + JSON.stringify(token) + ');\n' +
    'var img = images.captureScreen();\n' +
    'try { console.log(img.width, img.height); } finally { img.recycle(); }\n' +
    'images.stopScreenCapture();';
var child = engines.execScript("共享截图子引擎", childSource);

主引擎保持运行，直到子引擎执行 useSharedScreenCapture。完整的等待和收尾用法见内置“引擎共享截图”示例。

images.useSharedScreenCapture(token)

子引擎通过凭据连接已有截图会话，成功返回 true，无效或过期凭据抛错。子引擎无需重复请求授权；随后照常使用 images.captureScreen()。

各引擎持有独立图片：一个引擎截图或回收不会影响其他引擎保留的图片。同一引擎再次截图仍遵循原来的自动回收上一张图片规则。

images.stopScreenCapture()

共享时只释放当前引擎的引用。主引擎停止或退出后，已连接的子引擎仍能截图；最后一个参与引擎停止或退出时才释放系统截图会话。重复调用安全。

普通同步截图与无障碍截图支持共享。async: true 和 mode: "auto" 暂不共享，会明确报错。凭据仅在当前应用进程内、会话仍存活时有效，不能保存后重新申请授权。系统撤销授权后 getScreenCaptureOptions() 返回 null。

touch.create(options)

也可使用 $touch.create(options)。backend 默认 root；可选 root、shizuku、adb。root 需要设备 Root 与 su 授权；shizuku / adb 需要运行中的 Shizuku 和应用授权。

var finger = touch.create({backend: "root"});
try {
    finger.down(0, 300, 500);
    finger.move(0, 350, 550);
    finger.up(0);
} finally { finger.exit(); }
会话 API作用
down(id, x, y)按下手指，参数顺序与 touch.zip 一样
move(id, x, y)移动已按下的手指
up(id)在该手指的最后坐标抬起
pointerCount()当前按下的手指数
isAdb() / isClosed()查看通道和关闭状态
exit()抬起全部手指并关闭，重复调用安全

root 最多跟踪 10 指，设备实际槽位数可能更少。Shizuku / adb 仅支持单指，第二指会明确报错。id 为 0～31；坐标是当前屏幕像素，必须为非负整数。先 down 再 move / up；重复 down 或未按下就 move / up 会报错。

异常、脚本退出或停止时自动抬起未释放的手指。原 ZIP 的物理触摸监听请使用已有 events.observeTouch() / events.onTouch(...)，回调遵循 events 格式。此实现使用内置 RootAutomator2，不执行 ZIP 的全局 chmod 或 SELinux 设置。
