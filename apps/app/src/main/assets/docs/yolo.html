Yolo#

Stability: 1 - Experimental（需要内置 OpenCV 的完整版 APK）

Yolo 模块用内置的 OpenCV 5.0 DNN跑 ONNX 目标检测模型，用来替代「找色/找图」完成更灵活的任务：识别按钮、图标、游戏元素、裁剪区域等。模型只要导出成 ONNX（YOLO 风格输出）即可，不需要额外装 ncnn 之类的库。

模型可以放在设备的任意路径，也可以直接引用 APK 内的示例资源：路径写成asset://sample/…，引擎会把模型复制到缓存目录后再加载。

  • yolo.isAvailable([backend]) <boolean> 该后端是否可用（当前只有opencv）
  • yolo.getUnavailableReason([backend]) <string> 不可用原因，可用时返回''
  • yolo.getVersion([backend]) <string> 运行时版本，不可用时返回'unavailable'

yolo.isAvailable([backend])#

  • backend <string> 后端名，默认'opencv'；dnn、opencv5、opencv-dnn、cpu都是opencv的别名
  • 返回 <boolean>
var backend = 'dnn';
if (!yolo.isAvailable(backend)) {
    throw new Error('YOLO 不可用：' + yolo.getUnavailableReason(backend));
}
log('YOLO 运行时版本：' + yolo.getVersion(backend));

yolo.load(options)#

  • options.model <string> ONNX 模型路径（也支持onnx作为别名）；asset://开头表示 APK 内资源
  • options.backend <string> 可选，默认'opencv'
  • options.inputSize <number> 可选，模型输入边长，默认640；长方形输入可用inputWidth/inputHeight（QuickJS 引擎支持）
  • options.threads <number> 可选，推理线程数，默认min(4, CPU 核数)
  • options.labels <Array<string>> | <string> 可选，类别名数组；QuickJS 引擎还支持传标签文件路径（每行一个类别）
  • 返回 <Detector> 检测器对象

加载会同步读模型（几百 KB 的模型通常在几十毫秒级），建议在脚本开始时加载一次并复用。检测器不再使用时请close()释放。

var detector = yolo.load({
    backend: 'dnn',
    model: 'asset://sample/QuickJS 新引擎/YOLO目标检测/DNN/models/yolo26_160.onnx',
    labels: 'asset://sample/QuickJS 新引擎/YOLO目标检测/DNN/models/labels.txt',
    inputSize: 160,
    threads: 4
});

detector.detect(image[, options])#

  • image <Image | Frame> 待检测的图像：Rhino 引擎传images模块的图像（如captureScreen()、images.read()）；QuickJS 引擎传captureScreen(options)返回的帧
  • options.confidence <number> 可选，置信度阈值，默认0.25
  • options.nms <number> 可选，NMS 阈值，默认0.45
  • options.region <Array<number>> 可选（QuickJS 引擎），只检测[x, y, width, height]区域
  • 返回 <Array<Object>> 检测结果数组（见下节），并额外带preprocessMs/inferenceMs/totalMs三个耗时字段（毫秒）
if (!requestScreenCapture('portrait')) {
    throw new Error('没有截图权限');
}
var frame = captureScreen();
try {
    var result = detector.detect(frame, { confidence: 0.25, nms: 0.45 });
    result.forEach(function (item) {
        console.log(item.label + ' ' + item.score.toFixed(2) +
            ' @ ' + item.bounds.centerX + ', ' + item.bounds.centerY);
    });
    console.log('推理耗时 ' + result.inferenceMs.toFixed(1) + ' ms');
} finally {
    frame.recycle();
}

检测结果#

  • item.classId <number> 类别序号
  • item.label <string> 类别名（没提供labels时是序号的字符串）
  • item.score <number> 置信度
  • item.bounds.left / top / right / bottom <number> 检测框的屏幕坐标
  • item.bounds.width / height / centerX / centerY <number> 宽高与中心点，点按目标时直接用centerX/centerY即可

QuickJS 引擎在detect()里已经把坐标系换算回屏幕坐标（截图缩放时不用自己乘换算系数）；Rhino 引擎传的是Image，坐标就是图像坐标。

var item = result[0];
if (item) {
    click(item.bounds.centerX, item.bounds.centerY);   // 直接点按目标
}

detector.close()#

  • detector.close() <boolean> 释放检测器（释放后不能再detect()）
  • detector.isClosed() <boolean> 是否已释放

脚本退出时引擎也会统一回收本脚本创建过的检测器，但长时间运行的循环里建议自己管理生命周期。

示例#

// Rhino：找屏幕上的目标并点它
var detector = yolo.load({
    model: '/sdcard/yolo/det.onnx',
    labels: ['按钮', '开关'],
    inputSize: 640
});
requestScreenCapture();
while (true) {
    var img = captureScreen();
    var result = detector.detect(img, { confidence: 0.4 });
    img.recycle();
    for (var i = 0; i < result.length; i++) {
        if (result[i].label === '按钮') {
            click(result[i].bounds.centerX, result[i].bounds.centerY);
            break;
        }
    }
    sleep(500);
}

可运行的完整示例见QuickJS 新引擎/YOLO目标检测（环境测试、单帧直连、实时直连、区域检测、基准测试、持续识别，以及模型管理）。

模型库与模型切换#

发布包内置两个模型：默认 yolo26_160.onnx（inputSize 160，最快、小目标易漏）与保底 yolo26_640.onnx（inputSize 640，最准），删不掉；其它模型放进模型库后即可切换使用（竖屏手机推荐导入 160×320），不必让发布包为每个模型变大。

  • 库目录默认/sdcard/脚本/模型库；把 .onnx 放进去即可（同名 .txt 会当作标签一起识别）。
  • 管理界面用QuickJS 新引擎/YOLO目标检测/模型管理.js：导入（手动输入路径，或自动在 Download / Documents / 脚本 目录里找）、切换当前模型、设置 inputSize 与标签文件、删除、重命名、更换库目录。列表每行有「使用 / 验证 / 删除」，「验证」= 用当前画面跑一帧，随时可点，不必重新导入。
  • 用「导入模型」导入时会按文件名推断 inputSize（yolo26_640.onnx → 640）并做加载（可选跑一帧）校验；直接用文件管理器丢进库目录的模型默认按 640 加载，其它尺寸请在菜单里改。
  • 校验分两步报：加载（模型本身）与截图（拿一帧画面）。截图这一步没成时只会提示「跳过推理验证」并说明怎么处理（系统弹「开始录制或投屏」要点「立即开始」，页面会等你最多 9 秒），不影响导入；只有真正推理报错才会显示「✗ 推理失败」。
  • 在文件管理器里给模型改名、增删模型后，面板每 2 秒自动跟上，不用点「刷新」；用面板里的「重命名模型」改名还会把 inputSize、标签设置与「当前模型」一起迁到新名字（同名 .txt 一起改）。
  • 标签要填「.txt 的完整路径」：填成名字或不存在的路径会被直接拦下；以前存过的失效路径会在下次读取时自动忽略并清除（列表里会提示「已忽略并清除」），不会再因为这个把好好的模型报成「✗ 加载失败」。
  • 标签的自动查找顺序：模型同名 .txt → 模型库里的 labels.txt → 发布包内置的默认标签（COCO 80）。导入的模型没带 .txt 也会显示类别名而不是 classId 数字；自定义类别的模型请「设置标签」指到自己的 .txt。
  • 输入尺寸支持竖屏矩形：方形填一个数（640），竖屏矩形填「宽x高」（160x320）；文件名里带 160x320 的模型导入时会自动识别。竖屏手机屏幕套方形输入会有一半像素浪费在灰边上（1080x2400 套方形 320 时真实内容只有 144x320），换竖屏模型可做到「同速度更高精度」：实测（K40）方形 160 = 7.4ms、竖屏 160x320 = 12.4ms（精度≈方形 320）、竖屏 288x640 = 37ms（精度≈方形 640）、方形 640 = 80ms。
  • 当前选择存在应用存储里（storages 的 aijspro.yolo.models），与脚本放在哪无关；库内正在使用的模型被删掉会自动回退内置模型。
  • 内置示例会打印[模型] 本次识别使用：<名称>（inputSize=N，来源：…），结构化输出里也带 model 字段，便于确认本次是用哪个模型识别的。

注意事项#

  • 需要完整版 APK（内置 OpenCV 5.0）；lite 版本没有该模块，yolo.isAvailable()返回false，用yolo.getUnavailableReason()看原因。
  • 模型输出格式：YOLO 风格（[x1, y1, x2, y2, score, class]角点坐标、像素值，附带可选的前两个数值作为耗时）。导出模型时别用中心点格式。
  • 模型里若已包含 TopK 但没有 NMS，本模块会在detect()里按nms阈值过滤。
  • 检测框坐标是像素，点按前可用setScreenMetrics()对齐不同分辨率。
  • YOLO 只适合“学习过的目标”；纯颜色/图形匹配仍然用images.findColor()、images.matchTemplate()更快更省电。
