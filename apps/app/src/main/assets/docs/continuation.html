Continuation#

Stability: 2 - Stable（仅 Rhino 引擎）

continuation模块提供了把异步回调写成同步代码的能力：调用await()时脚本在当前位置挂起，等到resume()时再到挂起处继续执行。

与sleep()不同，挂起不会阻塞线程：Rhino引擎通过continuation机制把JS调用栈展开（抛出ContinuationPending），把线程交还给脚本的事件循环，因此挂起期间定时器、事件回调、其它线程都能继续运行。sleep()则会让当前线程彻底停下来，该线程上的定时器和事件回调都会延迟。

注意：continuation是Rhino引擎特有的能力（continuation.enabled为true）。QuickJS引擎是单线程执行模型，没有可挂起的continuation：continuation.enabled恒为false，delay退化为阻塞式sleep，await/create会直接抛错并提示改用async/await语法。

continuation.enabled#

  • 返回 <boolean> 当前引擎是否支持continuation

Rhino引擎返回true，QuickJS引擎返回false。可以用来写兼容两个引擎的代码：

if (continuation.enabled) {
    log("当前引擎支持阻塞式等待");
} else {
    log("请使用 async/await 或 .then() 回调");
}

continuation.create([scope])#

  • scope <Object> 可选，恢复时使用的JS作用域，默认为全局作用域
  • 返回 <Continuation> continuation对象

创建一个continuation对象，随后可以用它把某个异步结果"搬"成同步返回值：

var cont = continuation.create();
setTimeout(function () {
    cont.resume("定时器结果");
}, 1000);
var result = cont.await(); // 挂起1秒后拿到结果，且期间事件循环照常运行
log(result); // 定时器结果

continuation.await(any)#

  • any <Promise> 要等待的Promise
  • 返回 <any> Promise的完成值

等待一个Promise并返回其结果，Promise被拒绝时把异常抛回当前代码位置。传入非Promise对象会抛出TypeError。

var response = continuation.await(http.get("https://www.example.com"));
log("状态码 = " + response.statusCode);

注意：continuation.await()只接受Promise（不是任意对象、也不是线程）。要等待子线程的结果，请在子线程里cont.resume(result)（见下面的例子）。

continuation.delay(millis)#

  • millis <number> 延迟毫秒数

挂起指定毫秒数（等价于setTimeout+await），挂起期间事件循环继续运行。

for (var i = 0; i < 3; i++) {
    log("第 " + (i + 1) + " 次");
    continuation.delay(1000);
}

Promise.prototype.await()#

  • 返回 <any> Promise的完成值

便于链式书写的语法糖，等价于continuation.await(promise)：

var result = http.get("https://www.example.com").await();
log(result.statusCode);

Continuation 对象#

由continuation.create([scope])返回，包含以下方法。

cont.await()#

  • 返回 <any> resume(result)传入的结果

挂起当前脚本，直到有人调用cont.resume(result)或cont.resumeError(error)。若被resumeError恢复，则在这里抛出该错误。

cont.resume(result)#

  • result <any> 恢复后await()的返回值

恢复被挂起的脚本。同一个线程调用时立即恢复（await()处同步继续），其它线程调用时会被投递到该脚本的定时器队列（0毫秒后执行），因此可以安全地在线程间传递结果：

var cont = continuation.create();
threads.start(function () {
    sleep(2000);
    cont.resume("子线程算完了");
});
log(cont.await()); // 2000ms 后输出：子线程算完了

cont.resumeError(error)#

  • error <any> 抛回await()位置的错误，不能为null或undefined

用异常的方式恢复脚本，典型用法是把回调里的失败转成同步异常：

var cont = continuation.create();
http.post(url, data, function (res, err) {
    if (err) {
        cont.resumeError(err);
    } else {
        cont.resume(res);
    }
});
try {
    var res = cont.await();
    log("成功：" + res.body.string());
} catch (e) {
    log("失败：" + e);
}

注意事项#

  • resume()/resumeError()必须在await()挂起之后调用，否则抛出IllegalStateException: call resume() without suspend()!；同一个continuation重复await()会抛出call suspend twice!。
  • 挂起的是"当前线程的当前执行位置"，不是整个脚本：其它线程、定时器和事件监听都在继续工作。
  • 脚本被停止（例如音量键停止所有脚本）时挂起的continuation不会恢复，脚本直接结束。
  • UI模式下脚本运行在ScriptExecuteActivity的脚本线程里，挂起不会卡住界面。
  • QuickJS引擎：enabled === false、delay()为阻塞sleep()、await()/create()抛出Error；require("continuation")可以拿到该对象用于特性探测，但请改用async/await语法。
