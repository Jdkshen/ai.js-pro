# 安装包瘦身：插件化与子集

主 APK 从 **253MB 降到 ~141MB** 的做法汇总。四件事，各自独立、都能单独回退；
原则是「只有用到的人付体积」。

| # | 搬走了什么 | 体积 | 现在在哪 |
| --- | --- | --- | --- |
| 1 | ImGui 中文字体全量 → 子集 | −11.8MB | 子集在 `apps/app/src/main/assets/fonts/`，全量在 `third-party/fonts/` |
| 2 | Pikafish NNUE 权重 | −48.3MB | 随[象棋引擎插件](../../plugins/xiangqi-plugin)分发 |
| 3 | 「象棋自动走棋」工程（331 文件） | −11.1MB | 仓库根 [samples/象棋自动走棋](../../samples/象棋自动走棋)，随象棋插件分发 |
| 4 | 打包运行时模板 `template.apk` | −40.8MB | 随[APK 打包插件](../../plugins/apkbuilder-plugin)分发 |

## 1. ImGui 字体子集

ImGui 只用到 `imgui_font.h` 里 `GetGlyphRangesChineseSimplifiedCommon()` + `AddText(...)` 的实际字形，
全量 Noto Sans CJK 没必要常驻。

```powershell
python tools\imgui-font-subset.py --write     # 重新生成子集（读 imgui_font.h 里的 ranges）
python tools\imgui-font-subset.py --check     # 校验子集与源码 ranges 一致（Gradle preBuild 会跑）
python tools\imgui-font-subset.py --ranges    # 只打印解析出来的 ranges
```

- 全量字体留在 `third-party/fonts/NotoSansCJKsc-Regular.otf`（连同 OFL 许可），子集 0.57MB。
- `:app:verifyImGuiFontSubset` 挂在 `preBuild`，改了 `imgui_font.h` 的字形范围却忘了重新生成会直接失败。
- 验证标准：真机启动日志里的 `font atlas: fonts=… glyphs0=…` 与全量字体时一致（实测 `glyphs0=3260`）。

## 2. NNUE 权重

宿主 `$pikafish` 不再自带权重：`apps/app/build.gradle` 的权重 staging 改为**显式开关**
`-PwithPikafishNnue`，默认不打包。找不到权重时 `$pikafish` 会提示权重可以放在哪三个位置，
象棋插件也会自己从插件 APK 解包（见[象棋插件指南](象棋插件_打包与使用.md) §4）。

```powershell
.\gradlew.bat :app:assembleMiuixCompatDebug -PwithPikafishNnue   # 想给宿主带上权重时
```

## 3. 象棋工程

工程整体移到仓库根 `samples/象棋自动走棋`（`tools/xiangqi-release.py` 的 `RELATIVE`、
`tools/dev-update.ps1`、`tools/prepare-sift-chess-fixtures.py` 都已同步）。
主 APK 不再内置它，但**不会删用户手机上已有的那份**（`BundledSampleSync` 只增不删）。
插件里有完整一份，`xq.installProject()` 可以随时还原到手机。

## 4. 打包运行时模板

模板是 arm64 未签名运行时（~43MB），只有要打包应用的用户才用得到，现在随
[APK 打包插件](../../plugins/apkbuilder-plugin)分发：

- 打包页检测不到模板时显示提示卡片，可一键「下载并安装打包插件」（从更新源取
  `apkbuilder-plugin.apk`），也支持手动把 `template.apk` 放到 `/sdcard/template.apk`。
- `ApkBuilderPluginHelper.openTemplateApk()` 的查找顺序：`/sdcard/template.apk` →
  `files/apk-builder/template.apk`（插件落地缓存）→ 反射调用插件的 `ensureTemplate(File)` →
  主程序自带 `assets/template.apk`（老版本包）→ 抛带指引的异常。
- `:inrt:buildApkPlugin` 的输出路径改为 `plugins/apkbuilder-plugin/src/main/assets/template.apk`，
  该模块的 `merge*Assets` 依赖它；主 APK 不再需要这条依赖。
- 仪器测试（`ApkBuilderEncryptionTest`、`DshClientSamplePackagingTest`）在装不了插件的机器上会
  **跳过**并说明原因；要跑它们就装插件，或 `adb push template.apk /sdcard/template.apk`。
- 发布：`tools/dev-update.ps1` 把插件 APK 作为 `update.json` 的**附件**
  （`serve-updates.ps1 -Extra`，不进 `assets`，否则会被当成主程序安装包）；GitHub Release 由
  `.github/workflows/android.yml` 上传 `apkbuilder-plugin.apk`。

## 验证清单

```powershell
. .\tools\jdk17.ps1 | Out-Null
.\gradlew.bat :app:assembleMiuixCompatDebug -PdevPluginUsbDiscovery=false --console=plain   # → 141MB
.\gradlew.bat :apkbuilder-plugin:assembleDebug --console=plain                               # → 43MB
.\gradlew.bat :xiangqi-plugin:assembleDebug --console=plain                                  # → 60MB
.\gradlew.bat :app:testMiuixCompatDebugUnitTest --console=plain
python tools\xiangqi-release.py verify-apk --plugin --apk plugins\xiangqi-plugin\build\outputs\apk\debug\xiangqi-plugin-debug.apk
```

真机（小米 8 / Android 15）已验证：

| 场景 | 结果 |
| --- | --- |
| 主 APK 体积 | 141.6MB（`assets/template.apk` 与 `pikafish.nnue` 均不再打包） |
| 图表无障碍字形 | 启动日志 `glyphs0=3260`，与全量字体一致 |
| 棋盘识别/算棋 | 插件自带引擎与权重，`$plugins.load` 后正常算棋 |
| 未装打包插件打包 | 打包页提示缺失，`openTemplateApk` 抛可操作异常 |
| 装打包插件后打包示例工程 | 通过（`DshClientSamplePackagingTest`，真实 ApkBuilder 全链路） |
| 打包加密回归 | 19 项中 18 通过；1 项失败与本轮改动无关（`IMAGE_MODULE_LIBS` 未包含已发布模板里的 `libopencv_features.so`，属既有的清单/模板不同步） |


## task-120：Node 24 运行时改为按需下载（2026-10-18）

- 移除：`modules/engine/src/main/assets/source-engine-upgrade`（未压缩 94.4MB：libnode.so 97,079,800B + libc++_shared.so 1,822,720B + libajsnode24bridge.so 72,088B + runtime.json；打包进 APK 约 30MB 压缩）。该目录是 task-58 Node 24 第三引擎运行时，原被 `Node24Libraries.java` 以 assets 前缀引用，非纯历史遗留。
- 新方案：`Node24RuntimeDownloader`（engine）：从更新源 `http://192.168.10.7:8080/node24-runtime.zip` 下载 → 解压到 `files/node24-runtime/current` → 用 runtime.json 中三个库的 SHA-256 pin 校验 → `.ready` 标记；支持 3 次重试、进度 Toast/logcat `C-NODE24: download progress`、失败中文提示、已缓存跳过。
- `Node24Libraries.prepareFiles`：优先 `files/node24-runtime/current`；旧 APK 若 assets 仍有 runtime 则沿用旧解压路径；都没有时触发下载。Node24/Node UI 首次使用需联网下载一次，之后离线可用。
- 减重：主 APK 移除该 assets 预计减小约 30MB（压缩后）；download 包需按 runtime.json pin 同步发布到更新源。


### task-124（2026-10-18）：回滚为内置 assets（下载仅兜底）

- 用户决定 Node 24 运行时改回**内置 assets**：已从 dev-1050 APK 恢复 `modules/engine/src/main/assets/source-engine-upgrade`（4 文件，未压缩 98,974,880B；APK 体积会回升约 30MB，属预期）。
- `Node24Libraries.prepareFiles` 顺序改为：**assets 优先 → files/node24-runtime 缓存（日志 `C-NODE24: runtime cached dir=...`）→ 按需下载兜底**；断网/无缓存时 Node UI 仍可用。
- 修日志：downloader 先记录 zip 长度再删除，`runtime ready ... bytes=N` 不再恒为 0；内置路径日志 `runtime from bundled assets prefix=...`。


### task-127（2026-10-18）：Node24 彻底不下载

- 用户明确「不要下载」：`Node24Libraries.prepareFiles` 只允许内置 `assets/source-engine-upgrade`；assets 缺失时抛中文 `IOException`「此版本未内置 Node24 运行时…本机不会联网下载」，**不触发任何网络请求**。
- `Node24RuntimeDownloader` 类保留但已无调用（无下载分支）；日志只有 `C-NODE24: runtime from bundled assets prefix=...`，不会出现 `C-NODE24: download` 行。
