# 象棋引擎插件（Auto.js 插件 APK）

> 2026-10-23：插件 **1.1.0/code3** 已加入预算引擎；[构建与实测记录](../reports/2026-10-23_象棋引擎插件预算升级.md)。
> 同步 JNI 接口保留。Node 可用 `engine.createUci()` 创建异步会话，支持 ponder/ponderhit，自动选择通用/优化 ARM64 引擎。

```javascript
"nodejs";
(async function () {
    const xq = await require("plugins").load("com.jdkshen.xiangqi.plugin");
    const info = xq.engine.uciInfo(); // {ok,binary,evalFile,variant,dotprodSupported,...}
    const uci = xq.engine.createUci({ threads: 2, hashMb: 128 });
    try {
        await uci.start();
        // analyze(fen, options)、beginPonder(predictedFen, {positionCommand})、finishPonder(extraMs)
        // stop() 排空旧 bestmove；业务必须验证实际盘面再命中预算。
    } finally { await uci.quit(); }
})();
```

> 当前工程版本：**0.6.73**（`project.json`）；宿主 dev 通道 **dev-1112**。插件源码与象棋工程同源，构建时整棵拷贝。

把「象棋自动走棋」工程的**识别 + 棋规 + 算棋**装进一个可独立安装的 Auto.js 插件 APK：
宿主脚本一行 `$plugins.load("com.jdkshen.xiangqi.plugin")` 就拿到这些能力，
**不要求宿主自己有 `$pikafish`** —— Pikafish 引擎与 NNUE 权重都随插件分发。

- 插件工程：[plugins/xiangqi-plugin](../../plugins/xiangqi-plugin)
- 能力来源：[samples/象棋自动走棋](<../../samples/象棋自动走棋/项目结构.md>)（**构建时整棵拷贝**，插件里不是第二份代码）
  —— 这份工程已从主 APK 移出（原来在 `apps/app/src/main/assets/sample/…/象棋自动走棋`），
  装入插件后可用 `xq.installProject()` 在手机上还原成可运行工程。

## 1. 加载链路

宿主（AI.js Pro 或官方 Auto.js Pro）按 `AndroidManifest.xml` 里的
`org.autojs.plugin.sdk.registry` 元数据反射注册类，插件不需要依赖任何 SDK：

1. `PluginRegistry.loadDefault(宿主Context, 插件Context, runtime, scope)` → 插件 SDK 实例
   （[PluginRegistry.java](../../plugins/xiangqi-plugin/src/main/java/com/jdkshen/xiangqi/plugin/PluginRegistry.java)）；
2. 宿主把插件 `assets/scripts/` 整棵拷到 `cache/plugin-scripts/<包名>/`，`require` 入口 `index.js`；
3. `index.js` 的导出函数收到「插件对象」，**它的返回值就是 `plugins.load(包名)` 的结果**
   （[index.js](../../plugins/xiangqi-plugin/src/main/assets/scripts/index.js)）。

两个引擎都支持，区别只在入口脚本拿到的东西和宿主给的能力：

| | QuickJS | Rhino |
| --- | --- | --- |
| `$plugins` | [modules/qjs-plugins.js](../../modules/engine/src/main/assets/modules/qjs-plugins.js)（传入官方文档形状的插件对象） | [modules/\_\_plugins\_\_.js](../../modules/engine/src/main/assets/modules/__plugins__.js)（本仓库同样传包装对象，`unwrap()` 拿 SDK 实例） |
| 插件脚本目录 | `plugin.getMainScriptPath()` / `sdk.scriptDir()` | 同左 |
| 工程库（棋规/识别） | 可用（工程本来就是 QuickJS 工程） | **不可用**：Rhino 的 `const` 语义过不去工程代码（`redeclaration of const`），插件只降级这部分并给出 `rulesError`，引擎不受影响 |

## 2. 构建

### 2.1 原生引擎（首次，或改过 `pikafish_jni.cpp` / Pikafish 源码之后）

```powershell
.\plugins\xiangqi-plugin\src\main\cpp\build-native.ps1
```

- 与随包的 `libpikafish.so` **同一份源码**（`modules/engine/src/main/cpp/pikafish/pikafish_jni.cpp`），
  JNI 导出名由编译期宏 `PIKAFISH_JNI_CLASS` 换成插件自己的桥接类 —— 所以只有一份胶水，不会两边跑偏。
- ⚠️ 库名必须是 `libxiangqi_engine.so`：插件与宿主是两个 APK，同名 `.so` 会被 Android 链接器按 SONAME
  复用，插件就可能拿到宿主那份（它的 JNI 符号指向宿主类）。
- 产物落在 `src/main/jniLibs/arm64-v8a/libxiangqi_engine.so`（只有 arm64-v8a，和宿主一致）。

### 2.2 打包 APK

```powershell
. .\tools\jdk17.ps1 | Out-Null
.\gradlew.bat :xiangqi-plugin:assembleDebug --console=plain
```

产物 `plugins/xiangqi-plugin/build/outputs/apk/debug/xiangqi-plugin-debug.apk`（arm64-v8a，≈59MB，
其中 NNUE 权重 50MB + 工程 JS/模板 13MB）。

- 正式分发包用 `:xiangqi-plugin:assembleRelease`，签名读与主应用同一套
  `AIJSPRO_KEYSTORE` / `AIJSPRO_STORE_PASSWORD` / `AIJSPRO_KEY_ALIAS` / `AIJSPRO_KEY_PASSWORD`；
  没配环境变量时用 debug 签名（本地自测够用）。
- 权重来自 `third-party/Pikafish/src/pikafish.nnue`（不进 Git）；缺了 Gradle 只警告，
  真机上插件会明确报「找不到 pikafish.nnue（<原因>）」而不是静默降级。
- 包内脚本由 `stagePluginScripts` 把整棵工程（含 `tools/`、`tests/`、`reports/`）拷进 `assets/scripts/`，
  这样 `installProject()` 能在手机上还原出与工程源码一致的目录；发布校验
  （`tools/xiangqi-release.py verify-apk --plugin`）要求插件里就是「源码文件全集 + 插件入口脚本」。

## 3. 安装与使用

```powershell
C:\Android\platform-tools\adb.exe -s <设备> install -r plugins\xiangqi-plugin\build\outputs\apk\debug\xiangqi-plugin-debug.apk
```

```javascript
var xq = $plugins.load("com.jdkshen.xiangqi.plugin");

xq.version;                  // 插件 APK 版本
xq.capabilities;             // {engineAvailable, engineLoadError, nnue, nnueError, hostRuntime, …}
xq.paths.scriptDir;          // 工程代码与模板所在的脚本目录

// 算棋（自带引擎，与宿主 $pikafish 同形状）
xq.engine.available();                                    // .so 加载成功？
xq.engine.start({ threads: 2, hashMb: 128, contempt: 40 }); // {ok, evalFile, threads, options, …}
xq.engine.analyze("rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w - - 0 1", 1000);
// → {ok, move:'h2e2', scoreCp, depth, candidates:[{move,scoreCp|mate,depth,pv}], raw}
xq.engine.analyzePosition("position fen <FEN> moves h2e2 h7e7", 1000);  // 带已确认着法历史
xq.engine.stop(); xq.engine.quit();

// 识别（宿主提供截图/取色能力，插件带工程模板）；第一帧会慢一点（要载模板）
var image = xq.board.capture("full", 2000);
var reading = xq.board.read(image);      // {ok, layout, chars, unknownCells, validation, …}
xq.board.readFile("/sdcard/shot.png");   // 从图片文件读（离线回放也能用）
xq.board.releaseFrame(image);

// 棋规（纯 JS；Rhino 宿主上是 null，原因看 rulesError）
xq.rules.legal.allLegalMoves(board, "red");
xq.rules.fen.parseFen(fen);

// 让工程自己的算棋链路改用插件带的引擎（业务代码不用改）
xq.usePluginEngine().analyze(fen, { movetime: 800 });   // 返回工程 pikafish 适配器的结果

// 把整套工程装到手机上（主 APK 不再内置象棋工程）
xq.installProject();                    // 默认 <脚本目录>/象棋自动走棋
xq.installProject("/sdcard/象棋自动走棋", { overwrite: true });  // 指定目录 / 覆盖已有文件
// → {ok, files, skipped, targetDir}；默认只补缺，不动已有文件
```

`xq.load("src/vision/board-scan.js")` 可以按插件脚本目录取工程里的任意模块。

## 4. 权重（NNUE）解析顺序

`engineStart(evalFile)` 显式路径优先；否则依次找：

1. 宿主自己那份 `files/pikafish.nnue`（装了宿主 `$pikafish` 的老用户会有；**主 APK 现在不带权重**，
   所以新装的宿主里通常没有这份，直接落到第 2 步）；
2. 插件解包出来的副本 `files/xiangqi-plugin-pikafish.nnue`；
3. `externalFiles/xiangqi-plugin-pikafish.nnue`；
4. `/sdcard/xiangqi-p4/pikafish.nnue`（用户手工放置）；
5. 都没有就从插件 APK 资产解包到宿主 files 目录（首次约 1–2 秒）。

⚠️ 解包目标是**宿主**的目录：插件脚本跑在宿主进程里、用的是宿主的 uid，写插件包自己的私有目录会被拒
（这条在真机上踩过：只报「找不到权重」，看不出原因；现在失败原因会写进 `nnueError`）。

## 5. 已知边界

- 只有 **arm64-v8a**；32 位设备上 `engineAvailable=false`，报错里带 `.so` 加载失败原因。
- 工程库是 QuickJS 工程代码，**Rhino 宿主只能用到自带引擎那部分**（棋规/识别在 Rhino 上是 `rules=null`）。
- `board.*` 需要宿主有截图/取色/OCR 能力；缺能力时 `adapter.missingRequired()` / `adapter.capabilities()` 会说明缺哪个。
- 插件的 `assets/scripts/` 每次加载都会重新拷到缓存，**改插件脚本必须重装插件 APK**。
- 引擎会话是进程级单例：多个脚本同时算棋会串行等待（与宿主 `$pikafish` 同一约束）。
