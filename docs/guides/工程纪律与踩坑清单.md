# 工程纪律与踩坑清单（2026-11-12，W3 汇总）

> **为什么有这份**：以下每条都对应**一次真实事故**（多为 P0/P1/P2 批次里花的冤枉时间）——不写下来会丢。
> **标注约定（两类）**：**✅ 可复算** = 仓库工件（file:line / 命令 / commit）；**📌 会话事故** = 发生在会话里、**没有仓库工件是正常的**，但必须写全**五要素**：**日期 + 阶段批次 + 当事人 + 现象 + 是否已修**（这样才可追溯）⇒ 本文档**不再单列「来源待考」**。
> A 类 = 写代码时的坑；B 类 = 验证纪律（最值钱）；C 类 = 本项目特有的运行期事实。

## A 类：写代码时的坑（都踩过）

### A1 锚点只框住要改的那一段，前后各留一行不动
- **结论**：用「文本锚点」做大范围替换时，锚点**不要跨进相邻语句**——否则会把相邻的 `if (…) return;` 之类**一起吞掉**。
- **出处**：📌 **2026-11-12** · **P2-3 样板批** · 当事人 **W4** · 现象：替换 `permission_guide.dart` 的 `deviceState` 调用时**锚点跨进相邻语句** ⇒ 编译报 `Undefined name missing`，**且吞掉** `if (await _permissionGuidePrompted()) return;` ⇒ 触发「未引用」warning · **已修**（当事人自查恢复、`flutter analyze` 复绿）。
- **复核方式**：改完**读回改动区域的上下文**（不是只读改的那一行）：`git diff -U8 <file>`；跨行替换优先改成「最小唯一锚点 + 只替换该行」。

### A2 同名符号必须显式别名（否则自递归）
- **结论**：包装函数/本地 helper 与它调用的实现**同名**时，很容易写成 `return 自己(…)` ⇒ 无限递归（现象是校验脚本直接崩）。
- **出处**：✅ 正确形态就在代码里：`tools/plugins-manifest.mjs:46-57` —— `readJson()` 委托给 **`readJsonLib()`**、`sha256()` 委托给 **`sha256File()`**（**名字不一样**）。事故本身：📌 W2（会话）。
- **复核方式**：`node tools/plugins-manifest.mjs --check <path>`（应给出「找不到文件/解析失败」的点名错误，而不是栈溢出）。

### A3 字符串替换要把引号一起替换
- **结论**：替换模式**必须包含结尾引号**，否则会留下多余引号 ⇒ 在 Dart `part` 机制下**整库**报一堆莫名其妙的语法错。
- **出处**：✅ 机制可复算：`flutter-ui/lib/catalog_page.dart:1` 等多个文件都是 `part of 'main.dart'`（由 `main.dart` 用 `part` 组装）⇒ 一处引号破损会污染整个库。事故本身：📌 W4（会话）。
- **复核方式**：改完立刻跑该语言的**解析级**检查（Dart：`flutter analyze`；Java：`javac`；PS1：见 A4），别只看「替换发生了」。

### A4 `.ps1` 改完必须核 BOM + 解析 0 错
- **结论**：编辑工具会**静默丢 BOM** ⇒ PowerShell 5.1 按 GBK 解析中文注释/字符串 ⇒ 一次报 26–32 个语法错（看着像「代码坏了」，其实只是编码）。
- **出处**：✅ 已有门禁 `tools/check-ps1-encoding.mjs`；历史教训记在 `AGENTS.md`（模板脚本必须带 BOM；用编辑工具改一次就把中文注释读成 ANSI 而解析失败）。
- **复核方式**：`node tools/check-ps1-encoding.mjs`；或 `Get-Content -Encoding Byte -TotalCount 3 <file>` 看是否 `EF BB BF`；再 `pwsh -NoProfile -Command "[void][ScriptBlock]::Create((Get-Content -Raw <file>))"` 确认解析 0 错。

### A5 括号计数只是弱代理，编译器才是真门禁
- **结论**：朴素的「括号配平」启发式会**假报**（它报不配平，而 HEAD 上同样如此）⇒ **javac/编译器通过才是权威**。
- **出处**：📌 Lead 亲自验证（会话）；✅ 同类启发式的已知误报在仓库里有记录：`tools/ui-contrast.mjs:52-75` 自述「括号深度启发式，不是真解析」并列出误报类。
- **复核方式**：以编译器为准（`./gradlew :engine:compileDebugJavaWithJavac` 或 `javac`）；启发式脚本只当「定位线索」。

## B 类：验证纪律（最值钱的一类）

### B6「已跑绿 / 已落」必须在实跑之后才写
- **结论**：报告里的「绿/通过/已落」只能来自**本次实跑**；预写会让结论与事实脱节。
- **出处**：📌 W1 三次预写（会话）；✅ 正面样板：`tools/doc-contracts.mjs:48` 打印的断言条数是**当次 evaluate() 的返回值**（不是手写常量）。
- **复核方式**：把数字从「手写」改成「程序内先取实跑值再拼接」；复核者重跑一次即可对齐。

### B7 不信口述、只信可复算证据
- **结论**：审查时**拒绝采信**对方口述的测试数/结论，只看 diff + 读码 + **自己复算**。
- **出处**：✅ 硬例子：P1-4 我报「15 处同名碰撞」，W4 **独立复算**得 **17**（他扫 src/** 与 build/generated/**，共 1,657 文件）；我修扫描域后复现 17 并重冻结基线。证据：`docs/guides/源集与同名类索引.md` §1.1 范围声明 + `tools/source-set-index.baseline.json`（17 条）。
- **复核方式**：`node tools/source-set-index.mjs --list` 的末行应为 `# total=17 SRC=8 TEST=3 GEN=6`。

### B8 批准的是文件，落地前必须逐点证明等价
- **结论**：即使 Lead 批了「改这 3 个文件」，动手前也要**逐点确认存在可证同的转换点**；没有就**拒绝硬改**并回报。
- **出处**：📌 **2026-11-12** · **P2-3 样板批** · 当事人 **W4**（Lead 批了 3 个文件）· 现象/决策：逐点核对后发现**没有可证同的转换点** ⇒ **拒绝硬改**：`flutter-ui/lib/toolkit_page.dart:28` 的失败文案**只去前缀**（`e.toString().replaceFirst('Bad state: ', '')`，**无 160 字截断、无未知错误兜底**）；`flutter-ui/lib/task_page.dart:187` 与 `flutter-ui/lib/computer_connection.dart:567/602` 是 `failure.toString()`/**原文不洗** ⇒ 改了会动边缘文案 · **已按决策执行**：改做真正可证同的 `flutter-ui/lib/catalog_page.dart` **11 处**。
- **复核方式**：落地前先写「每处改动 = 旧形式 → 新形式 + 等价判据」清单；判据不能写「应该一样」，要能跑（见 B10）。

### B9 改完要跑目录级、精确调用形态的 grep 复核
- **结论**：复核引用时**裸词会把自己刚写的日志/文案数进去** ⇒ 要限定目录与调用形态（`foo(` 而不是 `foo`），并**写明语料范围**。
- **出处**：✅ 两个真实例子：① 统计 `C-PKG` 标签时发现**运行期渲染带空格**（见 C14）；② 同一轮把「疑似无主脚本」从 **36 收紧到 18**（只改语料范围，数字就变）⇒ 记在 `docs/reports/2026-11-12_P0-3_reverse-native清理清单（W3）.md` §7。
- **复核方式**：复核命令写清 `-Path <dir>` + 形态（`\bfoo\(`）+ 排除自己文件（`| Where-Object { $_.Path -ne $MyFile }`）。

### B10 干跑有副作用 ⇒ 用「逐字等价证明」代替
- **结论**：脚本会 push / 打公网 / 删文件时**不要真跑**；改成断言「新拼法与旧字面量**逐字相等**」。
- **出处**：✅ 仓库里的钉子：`tools/tests/lib.test.mjs:42-47` ——「`releaseBase/rawBase` 与**既有字面量逐字一致**（P2-4 第①批的钉子）」，实现见 `tools/lib/update-source.mjs:42`。
- **复核方式**：`node tools/tests/lib.test.mjs`（该断言失败即说明拼法与历史字面量不一致）。

### B11 oracle 必须独立于被测实现
- **结论**：对拍/回归的 oracle **不能是被测实现自己**（否则等于自证）；换成同一个 lib 会**削弱测试独立性**。
- **出处**：✅ 正面样板：SJBC 的 VM 用**用户参考实现** pc-tools/vm.js 当 oracle（比**结果 + 步数**）：`modules/engine/src/test/java/com/stardust/autojs/sjbc/SjbcVmTest.java:18-20`、`tools/sjbc/oracle.mjs:2`。事故：📌 W2 指出「测试文件本身当 oracle」（会话）。
- **复核方式**：`./gradlew :engine:testDebugUnitTest --tests '*SjbcVmTest*'`（oracle 与实现分属两份代码）。

### B12 负例必须真跑（只报「能跑通」不算）
- **结论**：门禁/校验类改动，必须证明「**故意改错 ⇒ 必须红**」，且失败信息要**点到具体那一条**。
- **出处**：✅ 本轮实证：`tools/doc-contracts.mjs`（正向 9 + 反向 3）+ `tools/tests/doc-contracts.test.mjs`（7 例：恰好 1 条失败且 what 出现在输出里 / 作用域外 ⇒ 0 / 历史标记 ⇒ 0）。**这套负例当场抓出我自己的两个真 bug**：作用域常量复制两份（漏字 ⇒ 反向断言空转）与正则转义过头（`\d` 写成双反斜杠 ⇒ 永不匹配）⇒ 已修。
- **复核方式**：`node tools/tests/doc-contracts.test.mjs`（应 `PASS=7 FAIL=0`）；再任取一处改错跑 `node tools/doc-contracts.mjs --check --doc <副本>`（应 exit 1 且点名）。

### B13 预算有限时：宁可少抽/少改
- **结论**：样本小、预算紧时，**少改**优于「顺手重构」；定点细读经常**推翻初判**（本轮 P2-1 的结论就是 **(a) 0 条**）。
- **出处**：✅ **结论工件已存在**：`docs/reports/2026-11-12_P2-1跨桥同名方法判定（W1）.md` —— §1 结论句「P2-1 经**逐方法定点并排细读** ⇒ **(a) 可抽 0 条**」（`:3`）+ §4「**重开条件与范围声明**」（`:43`）。⚠️ 别引错：`docs/reports/2026-11-12_Phase2优化总清单（Lead汇总待拍板）.md:46` 是**计划行**、不是结论。
- **复核方式**：这类结论落地前要求给出「候选清单 + 逐条否定理由」；没有清单就不改。

## C 类：本项目特有的运行期事实

### C14 logcat 的 TAG 会被渲染成「名称 + 空格 + 冒号」⇒ grep 要搜正文
- **结论**：`grep 'C-PKG: …'` **匹配不到**；要搜**正文**（`template available` / `ocr removed` / `apk-builder` …）。
- **出处**：✅ 本轮实证且已写入文档：`docs/guides/瘦身打包模板生成.md` §6.3（含两条原始日志与 grep 注意）；AGENTS 也记过「dev-1466：logcat 渲染成 `C-PKG   :` ⇒ 要用 `grep 'ocr removed'`」。
- **复核方式**：`adb logcat -d | Select-String 'template available'`（用正文匹配，不要用 `C-PKG:`）。

### C15 设备侧用哪个模板：看**缓存来源 marker + `files/apk-builder/<宿主versionCode>/`**，不是那条 `template available=true source=…`
- **结论**：那条日志来自 **状态函数** `templateStatus()`，**不等于实际选择**；②③④ **共用同一个缓存文件**，**谁先占坑谁生效**。
- **出处**：✅ 读码 + 实测：`apps/app/src/main/java/com/jdkshen/aijspro/build/ApkBuilderPluginHelper.java:96-140`（选择链 ① `/sdcard/template.apk` → ② 宿主缓存 → ③ `mergedBundledTemplate()` → ④ 插件 `extractTemplateFromPlugin()` → ⑤ 内置 assets；②③④ 同路径 `:270-271` / `:377-407`）· `:184-209`（`templateStatus()` 的链**不同**：装了插件就直接报「最后手段」）· `:405`（marker 写插件版本）· 完整说明与两条真机日志见 `docs/guides/瘦身打包模板生成.md` §6。
- **复核方式**：① 看缓存目录的 versionCode 与 marker 文案（「模板来源：<插件版本>」= 插件产；「内置模板与宿主 lib 合成」= 内置产）；② `adb logcat -d | Select-String 'apk-builder'`；③ 想让内置模板生效 ⇒ 卸插件 / 清缓存目录 / 升 versionCode。

### C16 产物启动失败必须可解释（失败四类 + 第 5 类）
- **结论**：别让失败静默。**五类反模式**：① 空/仅注释 `catch`；② 非空「安全」`catch`（catch 里再抛 ⇒ 被吞）；③ 只 `printStackTrace()`；④ 返回空 data（**分不清「没结果」与「失败」**）；⑤ **跨进程/类初始化失败**（`:script` 进程的 `ExceptionInInitializerError`）。
- **正面样板**：**无条件 logcat 打在最前** + **用户可见通道**（notify/Text） + **每层 try/catch**。
- **出处**：✅ `apps/app/src/main/java/com/jdkshen/aijspro/ui/SplashActivity.kt:109`（注释明写「必须捕获 `Throwable`：静态初始化失败抛的是 `Error`（`ExceptionInInitializerError`）」）；✅ `docs/reports/2026-11-12_P0-2审查记录（W2）.md:12/21`（审查判据「失败路径仍可见：无新增空 catch + 仍走 notify」）。**第 5 类实例（`:script` 进程 `ExceptionInInitializerError`，P0.5）也有工件**：✅ 提交 **`ffddc1c5`**（`fix(inrt): P0.5 产物启动失败对用户可见`，作者 W1 · 审查 W2 通过 · 验证 Lead 真机；commit message 含完整证据链：正例/反例、栈点 `prepare():339`、探针输出）⇒ 复核 `git show ffddc1c5`；✅ 截图 **`.artifacts/v2-acceptance/p05-fix.jpg`**（LogActivity 里那行黄色点名原因）与对照 **`p05-neg.jpg`**（同目录另有 `p05b-orig.apk` 等留档）。
- **复核方式**：用 `Select-String` 找空 catch（`-Pattern 'catch \(.*\) \{\s*\}'`）；关键路径确认有 `Log.*` + 用户可见提示；启动失败先看 logcat 是否跨进程初始化错误。
