# AI.js Pro 编译指南

> 路径/版本核对日期：**2026-10-20**（基线 `main`，Flutter-only UI；历史日期只作背景）。
> 本文路径均以仓库根目录为基准；发版/更新的雷区细节见 [AGENTS.md](../../AGENTS.md)，接手总纲见 [HANDOFF_AI.md](../HANDOFF_AI.md)。

> **两个容易混淆的概念**
> 1. **`miuixCompat` 只是保留的 Gradle 变体名**（历史命名 + CI/release 产物目录沿用），**不代表界面还是 Miuix**。
>    自 dev-1112 起 UI 只有 Flutter（`flutter-ui/` → AOT `libapp.so` 随包），旧 Miuix/Compose 页面已移出构建。
> 2. **普通 Android 构建**（不带 `-PflutterPoc=true`）不会打入 Flutter UI 资源，只适合引擎/单测等非 UI 验证；
>    **可安装的完整 App（本地 Debug 安装、dev 通道发布）都必须带 `-PflutterPoc=true` 并先准备好 Flutter payload**。

## 0. 三套命令（先看这里）

```powershell
# 0) 所有构建前：默认 JDK 是 8，必须切 17
. .\tools\jdk17.ps1 | Out-Null

# A. 本地 Debug 构建 + 装机（完整 Flutter UI）
.\gradlew.bat :app:assembleMiuixCompatDebug -PflutterPoc=true -PdevPluginUsbDiscovery=false --no-daemon
adb -s <serial> install -r apps\app\build\outputs\apk\miuixCompat\debug\app-miuix-compat-arm64-v8a-debug.apk

# B. dev 通道构建 + 发布（自动 AOT + gradle + 校验 APK 含 libapp/libflutter，再发更新源）
tools\flutter-poc\publish-poc-build.ps1 -VersionCode <N> -VersionName "dev-<N>"
.\tools\publish.ps1 -ReleaseNotes "..." -SkipBuild -PcHost 192.168.10.7 -AllowMultiDevice -DeviceId cccc62c7

# C. 只跑测试 / lint（不产出完整包）
.\gradlew.bat :app:testMiuixCompatDebugUnitTest :app:lintMiuixCompatDebug --no-daemon
```

- 首次 clone、或改过 Flutter UI 后，先跑 **`tools\flutter-poc\build-aot.ps1`**（见 §3）；payload 缺失时 Gradle 会直接报错。
- 同机装有正版 Auto.js Pro 时必须加 **`-PdevPluginUsbDiscovery=false`**（否则 provider authority 冲突，安装报 `INSTALL_FAILED_CONFLICTING_PROVIDER`）。
- ⚠️ 不要用管道过滤 gradle 输出（会提前关闭管道并杀掉 gradle 进程）；重定向到日志文件再读。
- ⚠️ `build-miuix-debug.ps1` **默认编译成功后会自动发布一版**；只想编译请加 `-NoPublish`。日常建议直接用上面的 gradlew 命令。

| Python | **3.11+**（CI 3.11；本机 3.14.5 验证）；`python -m pip install -r requirements-build.txt` | Gradle 里的 `prepareXiangqiRelease` / `verifyImGuiFontSubset` |

| CMake | **≥ 3.18.1**（`CMakeLists.txt` 要求）；本机用 VS 自带 **4.3.1-msvc1**；脚本 `-CMakePath` 可覆盖 | **仅原生重编** |
| Ninja | 本机 VS 自带 **1.13.2**；脚本 `-NinjaPath` 可覆盖 | **仅原生重编** |

> 原生脚本的默认 NDK/CMake/Ninja 路径是原作者 Visual Studio 安装位置。换机时**必须用参数覆盖**
> （`-NdkPath` / `-CMakePath` / `-NinjaPath`），或把工具放到同版本路径。
> Gradle 组装本身**不需要** NDK/CMake/Ninja —— 它直接消费仓库里 LFS 的预编译 `.so`。

## 2. 原生库：何时复用 LFS 预编译 `.so`、何时必须重编

### 2.1 默认：直接复用（绝大多数情况）

仓库已跟踪预编译原生库（Git LFS）：

```text
modules/engine/src/main/jniLibs/armeabi-v7a/{libquickjs.so,libquickjs_jni.so,libaijscrypto.so}
modules/engine/src/main/jniLibs/arm64-v8a/{libquickjs.so,libquickjs_jni.so,libaijscrypto.so,libppocr.so,libpikafish.so}
modules/engine/src/main/jniLibs/x86/{libquickjs.so,libquickjs_jni.so,libaijscrypto.so}
```

只要 `git lfs pull` 成功，**Gradle 构建不需要 NDK/CMake/Ninja**。CI 也是这种模式。

### 2.2 必须重编的情况

| 改动 | 必须执行 | 产物 |
| --- | --- | --- |
| `modules/engine/src/main/cpp/` 下的 QuickJS/JNI/CMake/NativeFrame/象棋识别/PP-OCR 源码或 `CMakeLists.txt` | `modules\engine\src\main\cpp\build-quickjs.ps1` | 三个 ABI 的 `libquickjs.so` / `libquickjs_jni.so` / `libaijscrypto.so`（arm64 另含 `libppocr.so`） |
| `third-party/Pikafish/` 象棋引擎源码/CMake | `modules\engine\src\main\cpp\build-pikafish.ps1` | 仅 arm64 `libpikafish.so` |
| ImGui 字体范围 `modules/engine/src/main/cpp/imgui_font.h` | `python tools\imgui-font-subset.py --write` | 重新生成 `apps/app/src/main/assets/fonts/NotoSansCJKsc-Regular.otf` 子集 |
| 原生库改完但忘记重编 | Gradle 会在 `preBuild` 由 `verifyQuickJsNativeLibrariesFresh` **直接失败** | 提示 `Native libraries are older than their sources. Run ...build-quickjs.ps1` |

`verifyQuickJsNativeLibrariesFresh` 监控的源文件（见 `apps/app/build.gradle`）：
`CMakeLists.txt`、`quickjs_jni.cpp`、`native_frame_store.*`、`xiangqi_board_detector.*`、`script_crypto.c`、`ppocr/*`。
它用 **mtime** 判断新旧；`build-quickjs.ps1` 跑完会把产出 `.so` 的修改时间刷成当前时间（ninja 对未受影响的库不会重新链接，否则会误报）。

> 16KB page-size：原生链接已带 `-Wl,-z,max-page-size=16384`（arm64 必须），用
> `tools\verify-16kb-alignment.ps1` 校验（需要 NDK 的 `llvm-readelf`，通过 `-LlvmReadelf` 或 `ANDROID_NDK_HOME` 指定）。

## 3. Flutter AOT 与 payload（仓库内自包含）

**源码与基础 payload 都在仓库里**（2026-10-20 起，commit `0da90aed`）：

- `flutter-ui/`：Dart 源码（`lib/`、`pubspec.yaml/lock`、`third_party/`、pubspec 引用的 `assets/`）——唯一真源。
- `flutter-payload-base/`：Flutter 3.3.4 基线 payload（`jniLibs/arm64-v8a/libflutter.so`、
  `flutter_embedding_3.3.4.jar`、`assets/flutter_assets/`，LFS）。
- 工作目录：`output/flutter-poc/`（**gitignore**，可删除后自动重建）。

构建 AOT：

```powershell
# 需要 Flutter 3.3.4；默认在线 pub get，离线环境用 -Offline（要求本机已有 pub 缓存）
tools\flutter-poc\build-aot.ps1
tools\flutter-poc\build-aot.ps1 -Offline          # 可选
tools\flutter-poc\build-aot.ps1 -FlutterSdk D:\flutter-3.3.4   # 可选
```

脚本做什么：`flutter-ui/{lib,assets,third_party,pubspec.*}` → `output/flutter-poc/src` →
`flutter pub get`（默认在线）→ `flutter assemble ... android_aot_bundle_release_android-arm64` →
`build/arm64-v8a/app.so` 复制为 `output/flutter-poc/payload/jniLibs/arm64-v8a/libapp.so`；
payload 的其余文件（`libflutter.so` / embedding jar / `flutter_assets`）从 `flutter-payload-base/` 自动补齐。
成功后打印 `libapp.so` 的 size/sha256 与 payload 路径。

修改 Flutter UI 的流程：改 `flutter-ui/lib` → `tools\flutter-poc\build-aot.ps1` → Gradle 组装/发布。
新增 pubspec 资源时，同步更新 `flutter-payload-base/assets/flutter_assets`（或构建后把新资源合入 base 再入库）。

Gradle 侧约定：`-PflutterPoc=true` 时（见 `apps/app/build.gradle`）读取 `output/flutter-poc/payload`
（`assets/flutter_assets`、`jniLibs`、`flutter_embedding_3.3.4.jar`）；payload 目录缺失会直接抛出
`flutterPoc: payload 缺失，先运行 tools/flutter-poc/build-aot.ps1`。

## 4. 本地 Debug 构建与安装

```powershell
. .\tools\jdk17.ps1 | Out-Null
# 如改了 Flutter UI 或 payload 丢失：
tools\flutter-poc\build-aot.ps1
# 组装（同机有正版 Auto.js Pro 时务必加 -PdevPluginUsbDiscovery=false）
.\gradlew.bat :app:assembleMiuixCompatDebug -PflutterPoc=true -PdevPluginUsbDiscovery=false --no-daemon
# 安装（arm64）
adb -s <serial> install -r apps\app\build\outputs\apk\miuixCompat\debug\app-miuix-compat-arm64-v8a-debug.apk
```

- 变体 `MiuixCompatDebug` = **保留的历史变体名**；MiuixLiteDebug 是更旧的精简变体，同样只是构建配置。
- 不带 `-PflutterPoc=true` 的 `assembleMiuixCompatDebug` 只用于非 UI 验证（引擎单测等），产物不含 Flutter UI。
- 安装后若桌面/首屏无 Flutter 内容，优先检查是否漏了 `-PflutterPoc=true` 或 payload 是否为旧版本。

## 5. dev 通道构建与发布

```powershell
# 1) 构建（自动 AOT + Gradle + 校验 APK 内 lib/arm64-v8a/{libapp,libflutter}.so）
tools\flutter-poc\publish-poc-build.ps1 -VersionCode <N> -VersionName "dev-<N>"
# 2) 发布到本地更新源（不要裸跑 tools\dev-update.ps1；-NoServe 仍会发布）
.\tools\publish.ps1 -ReleaseNotes "本版改了什么" -SkipBuild -PcHost 192.168.10.7 -AllowMultiDevice -DeviceId cccc62c7
```

- 版本号规则：`expected = max(仓库 project-versions.json, 已发布 update.json, 在线设备 versionCode) + 1`；
  `publish.ps1` 会校验，版本号不匹配即失败。
- `publish-poc-build.ps1` 会自动临时改写 `project-versions.json` 注入 versionCode/Name，构建后恢复；**不要手工改它**。
- 只算下一版本、不发布：`.\tools\publish.ps1 -ReleaseNotes "..." -DryRun`。
- `tools\dev-update.ps1` 会真的发布（`-NoServe` 不能阻止），见 AGENTS.md 雷区。

## 6. 输出位置（2026-10-20 修正）

```text
apps/app/build/outputs/apk/miuixCompat/debug/app-miuix-compat-arm64-v8a-debug.apk   # 本地 Debug/可安装
apps/app/build/outputs/apk/miuixCompat/debug/ 等（一版多 ABI）                        # CI 上传的 debug APK
output/flutter-poc/payload/                                                          # gitignore；Flutter 组装输入
  ├─ jniLibs/arm64-v8a/libapp.so        # 每次 AOT 重新生成
  ├─ jniLibs/arm64-v8a/libflutter.so    # 来自 flutter-payload-base（LFS）
  ├─ flutter_embedding_3.3.4.jar
  └─ assets/flutter_assets/
apps/inrt/build/outputs/apk/{debug,release}/                                         # 脚本 APK 运行时模板
plugins/apkbuilder-plugin/src/main/assets/template.apk                              # 打包插件使用的模板（:inrt 产物）
apps/app/src/main/assets/template.apk                                               # 主 APK 瘦身校验用模板（LFS 预编译资产）
.artifacts/                                                                          # 日志/截图/发布记录（gitignore）
```

> 旧文档里的 `apps/app/build/outputs/apk/common/debug/` 已作废（`common`/`coolapk` flavor 已退役）；
> 旧脚本位置 `output/flutter-poc/build-aot.ps1` 也已作废，脚本统一在 `tools/flutter-poc/`。

- 主 APK 瘦身模板：`verifySlimPackagingTemplate` 在 `apps/app/src/main/assets/template.apk` **存在时严格校验**
  （6–20MB、无 `lib/`、含 Manifest/DEX/资源表、`excluded-zip-files.json` 齐全）；模板缺失的 CI 环境会跳过并打印
  `C-TEMPLATE: slim template not present; skip ...`。模板由 `apps/inrt` 生成，当前以 LFS 预编译资产入库。
- 打包插件模板仍由 `:inrt` 的 `:apkbuilder-plugin` 资产流程同步（`:inrt:assembleRelease` 可单独刷新）。

## 7. 校验 / 测试命令

```powershell
.\gradlew.bat :engine:testDebugUnitTest --no-daemon --console=plain          # 引擎 JVM 单测
.\gradlew.bat :app:testMiuixCompatDebugUnitTest --no-daemon                 # App 单测
.\gradlew.bat :app:lintMiuixCompatDebug --no-daemon                         # lint
.\gradlew.bat :apkbuilder-plugin:assembleDebug --no-daemon                  # 打包插件
```

`preBuild` 还会自动跑这些生成/校验任务（失败即停）：
`prepareXiangqiRelease`（`tools/xiangqi-release.py`）、`verifyImGuiFontSubset`（`tools/imgui-font-subset.py`）、
`verifyQuickJsSamplesMarked`、`verifyBundledSamplesNoNode`、`verifyBundledYoloSamples`、`verifyBundledFindImageAssets`、
`verifyQuickJsNativeLibrariesFresh`、以及模板存在时的 `verifySlimPackagingTemplate`。

CI（`.github/workflows/android.yml`）：Ubuntu + JDK17 + Python 3.11 + `requirements-build.txt`，跑
`:app:testMiuix*/lintMiuixCompatDebug/assembleMiuix*/apkbuilder-plugin:assembleDebug`（LFS 拉取预编译原生库，不跑 Flutter AOT）。

## 8. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 构建开头就报 JDK 版本/字节码错误 | 没有切 JDK17：先 `. .\tools\jdk17.ps1` |
| `INSTALL_FAILED_CONFLICTING_PROVIDER` | 同机有正版 Auto.js Pro：加 `-PdevPluginUsbDiscovery=false` 构建 |
| `payload 缺失` / APK 打不开/黑屏 | 先 `tools\flutter-poc\build-aot.ps1`；确认 `-PflutterPoc=true` |
| `Native libraries are older than their sources` | 改过原生源码：跑 `build-quickjs.ps1`（pikafish 改动跑 `build-pikafish.ps1`） |
| `缺少瘦身打包模板` / 模板大小异常 | `git lfs pull` 取回 `apps/app/src/main/assets/template.apk`；不要用运行时大模板顶替 |
| `verifyImGuiFontSubset` 失败 | `python -m pip install -r requirements-build.txt`（fonttools）；或按提示重跑 `python tools\imgui-font-subset.py --write` |
| `verifyQuickJsNativeLibrariesFresh` 误报（刚 clone） | 先确认 `git lfs pull` 完成；仍报则跑一次 `build-quickjs.ps1` |
| `R.style.Theme_AppCompat_Light` 找不到符号 | 不要改回现代 `nonTransitiveRClass`/`nonFinalResIds` 默认；见 `gradle.properties` 注释 |
| flatDir 警告 | `autojs` 模块通过 flatDir 引入本地 AAR，属预期 |
| 中文路径检查失败 | `gradle.properties` 已设 `android.overridePathCheck=true` |
| 原生工具找不到 | 给原生脚本传 `-NdkPath/-CMakePath/-NinjaPath` |
| 修改目录后读取旧缓存失败 | 删 `.gradle/`、各模块 `build/`、`.cxx/` 后重建 |
| 脚本 APK 覆盖安装签名冲突 | 模板由 TinySign 重签；安装前卸载旧包或使用相同签名 |

## 9. 脚本 APK 打包（模板链路）

```text
打包插件运行时模板（plugins/apkbuilder-plugin 的 assets/template.apk）
  + 用户脚本或项目
  → apps/app/.../autojs/build/ApkBuilder.java
  → 写入 assets/project、修改应用元数据并签名
  → 独立 APK
```

这是修改 `:inrt` 运行时模板，不是重新生成一套 Android 工程；架构细节见[源码项目说明](../architecture/项目说明.md)。

打包页的「图色模块」开关（关闭 = 移除 OpenCV）按前缀删掉产物里**全部** `libopencv_*.so` 与 `libtbb.so`；
但它只是「删干净」，**不代表关掉安全**：模板的 `libquickjs_jni.so` / `libppocr.so` 直接依赖
`libopencv_java5.so`，关闭后这些原生库加载会失败（内置示例「dsh 手机客户端」README 也写明不要关闭）。
