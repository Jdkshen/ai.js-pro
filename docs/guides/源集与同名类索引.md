## 1. 口径（两个都留，避免再出现「到底是几处」的分歧）

**口径 A（本工具的定义，默认）**：
- **扫描域 = `apps/**` 与 `modules/**` 下的 `src/**` 与 `build/generated/**`**（两者都算）；
- **不扫**：`build/intermediates`·`build/tmp`·`build/outputs`·`build/reports`·`build/test-results`、`node_modules`·`.gradle`·`.cxx`·`.git`；
- 比较单位 = **文件 basename**（`.kt`/`.java` 一起算）；同一 basename 出现在 **≥2 个文件**即算碰撞；
- 分类：`SRC`（真源码）· `TEST`（`src/test`|`src/androidTest`）· `GEN`（路径含 `/build/`）；
- **结果：17 SRC=8 TEST=3 GEN=6**。

**口径 B（Lead 的定义）**：只比「**apps 各源集 ↔ modules**」的跨单元同名 ⇒ **6 处**：`App.kt` · `AutoJs.java` · `VolumeKeyDeduplicator.java` · `Config.java` · `Database.java` · `Pref.kt`。

**口径差异（为什么 6 vs 17）**：
- B 的 6 条 ⊂ A 的 8 条 `SRC`；
- A 多出的 SRC：`AccessibilityService.kt`（`modules/automator` ↔ `modules/engine`，**同属 modules**）与 `Colors.java`（**同一 module 内两个包**）⇒ B 不比；
- A 另把 `TEST`(3) 与 `GEN`(6) 单列：生成物/AIDL/测试样板**不需要**命名纪律，但**搜索会误命中**，必须能一眼排除。

### 1.1 ⚠️ 范围声明（**这就是 2026-11-12 被退回的根因，改扫描域必须同时改这里**）

- 本索引与基线的**全集** = `apps/**` 与 `modules/**` 的 `src/**` + `build/generated/**`（W4 独立复算：1,657 个文件 ⇒ 17 处）；
- **v1 基线的缺陷**：`tools/source-set-index.mjs` 的 `ROOTS` 只列了 apps 侧的 `src/main|miuix|flutterpoc`，**漏了 apps 侧 `src/test` 与 `build/generated`** ⇒ 少了两处（`VolumeKeyDeduplicatorTest.java`、`IScriptHost.java`）；
- **纪律**：扫描域的唯一真值是 `tools/source-set-index.mjs` 里的 `ROOTS/INCLUDE/SKIP`；**改它必须同步改本节**（反之亦然）——否则下一个人又会以为这是全集。

## 3. 怎么用（触发时机与动作）
1. **定位文件前**：先在上表搜 basename；命中 ⇒ 用**完整路径**确认是哪一个（别靠 IDE 模糊匹配）。
2. **新增类命名**：`src/miuix` ⇒ 前缀 `Miuix`；`src/flutterpoc` ⇒ 前缀 `Poc`；apps/inrt 侧与 app 侧同名 ⇒ 建议 `Inrt` 前缀；**同一 module 内两个包同名**（如 `Colors.java`）⇒ 改名或合并。
3. **自检**：`node tools/source-set-index.mjs --check` ⇒ 0 = 与基线一致；1 = 出现新同名碰撞（日志点名 basename + 文件）。
4. **确要新增同名** ⇒ 显式 `--write-baseline` 重冻结，并在提交信息里说明（重冻结 = 有意决策）。

## 4. 基线、工具与已验负例
- 基线：`tools/source-set-index.baseline.json`（`collisions[]`：name/kind/files）；工具：`tools/source-set-index.mjs`（`--list` / `--check [--baseline <p>]` / `--write-baseline [p]`）。
- **负例 1（新碰撞）**：把基线里的 `Pref.kt` 删掉再 `--check` ⇒ **FAIL / exit 1**，点名 `Pref.kt [SRC] 新碰撞` + 两个路径。
- **负例 2（基线非法 JSON）**：给一个坏 JSON 当基线 ⇒ 现在给**点名错误**「基线文件不是合法 JSON：<path>（解析错误：…）」并 **exit 2**（原来是未捕获的 SyntaxError）。
- **负例 3（基线缺失）**：`--check --baseline <不存在>` ⇒ 点名 + **exit 2**。
- **负例 4（条目消失）**：基线里的碰撞在当前树里消失 ⇒ **WARN** 建议重冻结（不误报为 FAIL）。

## 5. 未做 / 边界
1. 只覆盖 **basename 碰撞**，不覆盖功能重复/包名相同等其它形态；
2. `GEN` 类（`BuildConfig`/AIDL）随 clean build 变化 ⇒ 出现 `WARN …已消失` 属正常（重冻结即可）；
3. `--check` 只比 basename 与文件集合，**不做引用/语义分析** ⇒ 不能据此判断「哪个该删」；
4. 扫描域**不含** `build/intermediates` 等中间产物（见 §1.1）——那里也有大量同名生成物，但对「定位源码」无意义。
