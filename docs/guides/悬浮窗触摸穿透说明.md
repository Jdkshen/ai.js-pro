# 悬浮窗触摸穿透与圆形形状说明

> 结论先说：**「按区域接收触摸」（圆内可点、圆外穿透）在 Android 上做不到**，
> `clipToOutline` 只裁剪本窗口的绘制，不会改变窗口对系统的输入区域。
> 本文给出实测数据与真正可行的替代方案。
> 环境：Mi8 `ce4d2bdb`（LineageOS / Android 15，SDK 35）+ 小米 2602BRT18C（Android 16，SDK 36）

## 1. 为什么 `clipToOutline` 解决不了触摸

Android 的窗口（`TYPE_APPLICATION_OVERLAY`）向输入系统注册的可触摸区域**永远是窗口矩形**：

```
窗口矩形 ─────────────┐        系统只认这个矩形
│  ╭──────╮           │        → 矩形内的触摸一定先进本窗口
│  │  ●   │  ← 视觉圆形 │        → 圆外方角同样会命中本窗口
│  ╰──────╯           │
└─────────────────────┘
```

`clipToOutline="true"` + 圆形/圆角轮廓只做两件事：

1. 让控件按轮廓裁剪**绘制**（圆外不画）；
2. 影响 `View` 层级内部的命中测试（`ViewGroup` 用它决定子 View 是否被裁剪）。

它**不改变**窗口在 WindowManager 里的输入区域。因此：

- ✅ 视觉上是圆了（`cardCornerRadius="50%"` + `clipToOutline="true"`，QuickJS 与 Rhino 都支持）；
- ❌ 圆外方角仍然拦截触摸，事件不会落到下层 App。

### 想精确收缩输入区域需要隐藏 API，但实测不存在

`WindowManager.LayoutParams#setTouchableRegion(Region)` 这类按区域输入的接口在 AOSP 里
只服务于 IME 等系统窗口；在 Android 15 真机上实测：

```
floaty.touchRegionInfo()
→ {"supported":false,"api":"","android":35}
```

（`getDeclaredMethod("setTouchableRegion", Region.class)` 与 `getDeclaredField("mTouchableRegion")`
都取不到 ⇒ 引擎侧已把它做成「能力位 + 尽力而为」，`supported=true` 的设备才会真正生效。）

## 2. 真正可行的两类方案

### 方案 A：整窗穿透（实测有效 ⭐）

`win.setTouchable(false)` → `FLAG_NOT_TOUCHABLE`，窗口内所有触摸直接穿透到下层。

真机实测（下层 App = 计算器，点 "7" 键）：

| 配置 | 结果 |
|---|---|
| `setTouchable(true)` + `alpha=1.0` | 点击被拦截，计算器 `formula` 仍为空 |
| `setTouchable(false)` + `alpha=0.5` | 点击**穿透**到计算器，`formula=7` |
| `setTouchable(false)` + `alpha=1.0` | 点击**穿透**到计算器，`formula=7` |

（Android 12+ 的 `FLAG_NOT_TOUCHABLE` 文档要求在「同 UID / 可信窗口 / 不可见 / alpha ≤ 0.8」等条件下
才允许穿透；本机实测只要 `FLAG_NOT_TOUCHABLE` 就穿透，保险起见可视区域不透明的窗口建议同时 `setAlpha(≤0.8)`。）

### 方案 B：容器穿透 + 菜单项独立小窗口（环形菜单推荐）

```js
// 容器：只负责“占位/视觉”，不吃触摸
var container = floaty.window('<frame w="520px" h="520px" bg="#00000000"/>', { x: 560, y: 1200 });
container.setTouchable(false);   // ← 整块矩形都不再拦截触摸
container.setAlpha(0.6);         // ← 透明度 ≤0.8 更稳妥

// 菜单项：各自一个小窗口，只遮挡自身小方块（用 50% 圆角 + clipToOutline 视觉成圆）
var item = floaty.window(
    '<card id="c" w="120px" h="120px" cardCornerRadius="50%" '
    + 'cardBackgroundColor="#F0E91E63" clipToOutline="true"/>',
    { x: 800, y: 1000 });
item.c.click(function () { /* 菜单动作 */ });
```

- 容器整块矩形（原来 87% 的无效遮挡）彻底不拦截触摸；
- 剩下的遮挡只剩「每个菜单项自身的小方块」，比整块容器小一到两个数量级；
- 需要更小遮挡就继续缩小菜单项尺寸，或让菜单项相互不重叠。

## 3. 形状 API 一览（QuickJS）

| API | 作用 |
|---|---|
| `win.view` / `view.view` | 拿到真实 `android.view.View` 代理（等同 `javaView`） |
| `view.setClipToOutline(true)` / XML `clipToOutline="true"` | 按轮廓裁剪绘制 |
| `win/view.setOutlineShape('circle'\|'roundRect'\|'rect'[, radius])` | 设置轮廓形状（`'circle'` = 椭圆轮廓，正方形即圆） |
| `win/view.setCornerRadius(60)` / `setCornerRadius('50%')` | 圆角；`'50%'` 直接给圆 |
| XML `cardCornerRadius="50%"` | CardView 圆角百分比（相对短边，50% = 内切圆） |
| `win.setShape(shape[, radius])` | 轮廓 + **尝试**按形状收缩输入区域（需 `supported=true`） |
| `win.setTouchShape('circle'\|'rect')` / `setTouchableRegion(x, y, r)` / `clearTouchRegion()` | 显式控制按区域输入（不可用时 `console.warn` 提示） |
| `win.getTouchRegion()` | 读回当前输入区域：`{supported, api, shape, cx, cy, r, touchable}` |
| `floaty.touchRegionInfo()` / `floaty.supportsTouchRegion()` | 能力探测，脚本先用它决定走哪条路线 |
| `win.setTouchable(false)` | 整窗穿透（方案 A） |

## 4. 顺带修掉的两个问题

1. **XML 根控件自带 `w/h` 时窗口量成 0×0**：`<card w="200px" h="200px"/>` 作为 `floaty.window` 的 XML 根时，
   引擎原先用 `MATCH_PARENT` 把它加进 `wrap_content` 的根 FrameLayout，内容被量成 0×0
   （窗口不显示、也不吃触摸）。现在窗口 `wrap_content` 的维度会按内容自带尺寸排布。
2. **控件代理链式返回值不统一**：`win.c.setCornerRadius(60) === win.c` 以前是 `false`（返回了内部对象），
   现在统一返回代理自身，与窗口代理一致。
