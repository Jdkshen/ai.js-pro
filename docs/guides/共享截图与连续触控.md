# 共享截图与连续触控

AI.js Pro 扩展 API，Rhino / QuickJS 都支持。来自用户提供的“引擎共享截图权限.zip”和“touch.zip”的用法，已接入引擎，不需要外置 dex / so。

## 引擎共享截图

主引擎先申请授权，再发布共享凭据：

```js
if (!images.requestScreenCapture()) throw new Error("未授权");
var token = images.shareScreenCapture();
var source = '// @engine quickjs\n' +
    'images.useSharedScreenCapture(' + JSON.stringify(token) + ');\n' +
    'var img = images.captureScreen();\n' +
    'try { console.log(img.width, img.height); } finally { img.recycle(); }\n' +
    'images.stopScreenCapture();';
var child = engines.execScript("共享截图", source);
```

主引擎应保持运行直到子引擎执行 `useSharedScreenCapture(token)`。随后主引擎可以退出或停止截图，子引擎仍能截图。最后一个参与引擎停止或退出时，系统截图会话才释放。每个引擎拿到独立图片，另一个引擎截图或回收不会使其图片失效；同一引擎再次截图仍遵循原来的自动回收上一张图片行为。

| API | 作用 |
| --- | --- |
| `images.shareScreenCapture()` | 返回字符串凭据，重复调用返回当前会话的同一凭据 |
| `images.useSharedScreenCapture(token)` | 连接会话；成功返回 `true`，无效/过期凭据抛错 |
| `images.getScreenCaptureOptions()` | 返回共享会话的截图配置；系统撤销授权后返回 `null` |
| `images.stopScreenCapture()` | 释放当前引擎的引用，重复停止可安全调用 |

支持普通同步截图与无障碍截图。`mode: "auto"` 和 `async: true` 暂不共享，会明确报错。凭据只在当前应用进程内有效，不是可以保存后重新申请截图的授权凭据。系统停止录屏、切换应用进程、重启应用后需要重新申请。共享会话不重复使用 Android 的授权 Intent，也不创建第二个虚拟显示。

内置示例：**示例 → Rhino 引擎 → 图片与图色处理 → 引擎共享截图**，以及 **QuickJS 引擎 → 图色处理 → 引擎共享截图**。示例一次申请、启动两个子引擎、等待结束并释放。

## 连续触控

```js
var finger = touch.create({backend: "root"});
try {
    finger.down(0, 300, 500);
    finger.move(0, 350, 550);
    finger.up(0);
} finally { finger.exit(); }
```

| API | 作用 |
| --- | --- |
| `touch.create(options)` / `$touch.create(options)` | 创建独立触控会话；`backend` 默认 `root` |
| `finger.down(id, x, y)` | 按下指定手指 |
| `finger.move(id, x, y)` | 移动已按下的手指 |
| `finger.up(id)` | 抬起指定手指，使用最后坐标 |
| `finger.pointerCount()` | 当前按下的手指数 |
| `finger.isAdb()` / `finger.isClosed()` | 查看通道与关闭状态 |
| `finger.exit()` | 抬起所有手指并关闭，重复调用安全 |

`root` 需要设备 Root 与 su 授权，最多同时跟踪 10 指（设备实际槽位数可能更少）；`shizuku` / `adb` 需要运行中的 Shizuku 和应用授权，仅支持单指。无权限时第一次注入明确抛错。参数为非负整数，手指 id 为 0～31，坐标为当前屏幕像素。先 down，再 move / up；重复 down、未按下就 move / up、在单指通道按下第二指都抛错。脚本退出或被停止时自动抬起未释放的手指。

此 API 的 down / move / up / exit 沿用 ZIP 的参数顺序，使用项目内置 RootAutomator2 通道。原 ZIP 的物理触摸回调 `setCallback` 由已有 `events.observeTouch()` / `events.onTouch(...)` 提供，回调格式遵循 events 文档，不是 ZIP JNI 回调格式。不会执行 ZIP 中的全局 chmod 或 SELinux 设置。脚本注入使用像素坐标，示例缩放坐标可由脚本自行换算。

内置示例：**示例 → Rhino 引擎 / QuickJS 新引擎 → 触控 → Root 多点触控 / Shizuku 单指触控**。每个演示在确认后等待 3 秒，便于切到测试页面。
