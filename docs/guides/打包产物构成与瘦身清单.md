## 2. 规则与现状（为什么长这样）

### 2.1 `lib/` 为什么会在产物里 —— 「宿主 lib + 合并模板」三段
1. **宿主的 `lib/` 是内建运行时**（quickjs / aijscrypto / ppocr / mlkit-ocr / OpenCV 拆库…）⇒ 打进宿主 APK。
2. **打包时从宿主 APK 取 lib 合并进瘦身模板**：`excluded-zip-files.json` 列「瘦身模板需要但自己没有」的条目（现状 **general 12 / opencv 10 / v8 0**），由 `ApkBuilderPluginHelper.mergedBundledTemplate()`（`apps/app/src/main/java/com/jdkshen/aijspro/build/ApkBuilderPluginHelper.java:259-310`）合并；该函数在模板选择优先级链的 **③**（`:96-120`：① `/sdcard/template.apk` → ② 宿主缓存 → **③ 合并瘦身模板** → ④ 插件落盘 → ⑤ 内置 assets）。
3. **再按策略逐 `.so` 判 KEEP/DROP**：`NativeLibPolicy`（`modules/engine/.../build/NativeLibPolicy.kt:13-64` 的 `TEMPLATE_REQUIRED` / OpenCV+TBB / OCR / `libv8|flutter|node`=leak）。

### 2.2 已有排除（现状，逐条带证据）

| 排除项 | 机制 | 证据 / 效果 |
|---|---|---|
| **v7a 组** | `excluded-zip-files.json` 里已有 **6 条 v7a 条目**（general 5：`aijscrypto`/`c++_shared`/`mlkit`/`quickjs`/`quickjs_jni`；opencv 1：`libopencv_java5.so`） | 清单 `:10-14` / `:26`；**但产物实际只有 arm64**（Flutter 页面常量带 v7a，见「打包模板重建」`3 的待定夺） |
| **工程 `build/` 里的旧产物** | `PackageOutputExclusions`（「像产物目录且无源码才排除」） | device4 同工程重打 **99,566,757 → 40,412,540 B（−59.15 MB）** |
| **`libpikafish.so`** | **仍在清单 `general` 里**，但 `NativeLibPolicy` 判 **leak ⇒ DROP** | 产物解包 `*pikafish*` 消失（策略层过滤，不是清单层） |
| **模板构建时跳过资源** | `tools/build-slim-template.ps1:127` 逐条打 `[C-SLIM] 跳过资源：<entry>` | 瘦身模板必须**不含 `lib/` 条目**且跳过资源；结束时打 3 行汇总：`:183` `[C-SLIM] size=… sha256=… shaBefore=…`、`:184` `[C-SLIM] libs total=… general=… opencv=… v8=…`、`:185` `[C-SLIM] plugin template untouched: …` |
| **`assets/autojs.keystore`** | 打包时剔除（第三方打包器默认签名身份） | logcat `removed bundled signing identity assets/autojs.keystore (2062 B)` |

### 2.3 不能随便删的（既有硬结论，别重复踩）
- **`libopencv_dnn.so` 是 DT_NEEDED 必需**：arm64 `libopencv_java5.so` 的 `DT_NEEDED` = core/imgproc/dnn/imgcodecs/features/geometry/flann；`libopencv_core.so` 又 NEEDED `libtbb` ⇒ **10/10 全必需、0 个可删**（删任一即 `UnsatisfiedLinkError`）。
- **单库化收益 = 0**：只减文件数、不减代码量，且名字只能是 `java5`（详见 [打包模板重建-来源调查](../reports/2026-11-09_打包模板重建-来源调查（OpenCV与v7a）.md) 的 §8–§10）。
- **AOT 只有 mtime 能当门禁**（明文判据已被证伪）——与体积无关但同属「出包前必看」。

## 3. 复跑命令（都能只读跑，不需要构建）

> **首选现成工具**（W2 已有，比手搓 awk 更全）：`python tools/audit-apk-size.py <apk>` —— 输出 **raw / 压缩贡献 / 条目数 / 占比**，另有 `--json` / `--baseline` / `--max-total-mib`；出处 [打包体积：模板/宿主继承部分取证（W2）](../reports/2026-11-10_打包体积模板侧取证（W2）.md) §0。下面 §3.1–§3.5 是**手边没这脚本时的等价写法**（我这次用的就是 §3.2）。

### 3.0 ⚠️ 设备侧（toybox）注意：**`unzip` 不支持 `-Z`/`-Z1`**

toybox 的 `unzip` **没有 `-Z`/`-Z1`**（那是 Info-ZIP 的 `zipinfo` 接口）⇒ 在 Android/设备上列条目名**不要**用 `unzip -Z1`，改成：

~~~bash
# 只列条目名（toybox 兼容）
unzip -l app.apk | sed -n 's/^ *[0-9][0-9]* *[0-9-][0-9-]* *[0-9:][0-9:]* *//p'
~~~

PC 上嫌慢也可以用本仓脚本：`node tools/apk-native-lib-audit.mjs <apk> --by-module --json`（只覆盖 `lib/`），或 §3.2 的 python 单行（覆盖全部条目）。

### 3.1 顶层构成（Linux/设备侧）
~~~bash
# 未压缩大小降序 top-32（约 2,400 条目里的大头基本都在这里）
unzip -l app.apk | sort -k1 -n -r | head -32
# 各桶小计（未压缩）——纯 shell 版；嫌长就用 §3.2 的 python 单行
unzip -l app.apk | awk '$4 != "" { b=$1; p=$4; if (p ~ /^lib\//) k="lib"; else if (p ~ /^res\//) k="res"; else if (p ~ /^assets\//) k="assets"; else if (p ~ /^classes/) k="dex"; else if (p ~ /^META-INF\//) k="META-INF"; else if (p ~ /^org\/antlr/) k="org-antlr"; else next; n[k]++; s[k]+=b } END { for (k in s) printf "%-10s %5d %12d %7.2f MiB\n", k, n[k], s[k], s[k]/1048576 }'
~~~

### 3.2 同一件事的 PC/本机等价写法（我这次用的就是它）
~~~powershell
# 需要 python（本机 python 在 PATH 即可）；把 <apk> 换成你的产物
python -c "import zipfile,sys,collections; z=zipfile.ZipFile(sys.argv[1]); i=z.infolist(); print(len(i), sum(x.file_size for x in i)); [print(x.file_size, x.filename) for x in sorted(i,key=lambda x:-x.file_size)[:32]]" <apk>
~~~

### 3.3 `lib/` 逐 `.so` + 模块占比（本仓脚本）
~~~bash
node tools/apk-native-lib-audit.mjs <apk> --by-module            # 人类可读：模块 / MiB / MB / 占比 / 成员
node tools/apk-native-lib-audit.mjs <apk> --by-module --json      # 机器可读（byModule[]）
node tools/apk-native-lib-audit.mjs <apk> --expect-abi arm64-v8a --fail-on-leak
~~~

### 3.4 `assets/` 顶层计数（Linux）
~~~bash
unzip -l app.apk | awk '$4 ~ /^assets\// {split($4,a,"/"); print a[2]}' | sort | uniq -c | sort -rn
~~~

### 3.5 工程侧找大文件（打包前自查；设备上 `toybox find` 没有 `-printf` 时用 `ls -lR` 兜底）
~~~bash
# 工程目录里 >1MB 的文件（含旧产物；build/ 里的旧 APK 是历史最大坑）
find . -type f -size +1M -printf '%s\t%p\n' | sort -rn | head -32
~~~
