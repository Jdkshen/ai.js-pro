# 瘦身打包模板生成（:inrt → 宿主内置 template.apk）

> 脚本：[tools/build-slim-template.ps1](../../tools/build-slim-template.ps1)
> 产物：apps/app/src/main/assets/template.apk + apps/app/src/main/assets/excluded-zip-files.json
> 校验：:app:verifySlimPackagingTemplate

## 1. 为什么需要瘦身模板

打包脚本 APK 时，主程序会以 :inrt 运行时 APK 为模板，替换脚本/工程资源后再签名。
如果直接把 :inrt 的完整 release APK 当模板，所有用户都要为 lib/*（约 54MB 未压缩）、
Node24 的 97MB libnode.so 和 6.5MB new_api_database.ser 付体积。

因此入库的是「瘦身模板」：

- 模板里不包含任何 lib/*；
- 模板里不含 assets/source-engine-upgrade/node24/arm64-v8a/libnode.so
  与 resources/new_api_database.ser；
- 打包时从已安装的宿主 APK 按 excluded-zip-files.json 的
  general/opencv/v8 清单补齐 lib/*；
- 插件目录 plugins/apkbuilder-plugin/src/main/assets/template.apk 的 70MB 旧模板
  不由本脚本生成/覆盖，单独发插件版本时才处理。

## 2. 生成步骤

`powershell
# 完整流程：:inrt:packageRelease → 去 lib/ → 写 assets/template.apk + excluded json → 自动校验
.\tools\build-slim-template.ps1

# 复用已有 inrt release APK（只重新切片/写清单）
.\tools\build-slim-template.ps1 -NoBuild

# 只调脚本时跳过 gradle 校验（不推荐）
.\tools\build-slim-template.ps1 -NoBuild -NoVerify
`

脚本内部使用 :inrt:packageRelease，不是 :inrt:assembleRelease；
后者会 finalizedBy buildApkPlugin，把新模板复制到插件目录。本脚本只写
apps/app/src/main/assets/，不会动插件模板。

生成物：

| 文件 | 说明 |
|---|---|
| apps/app/src/main/assets/template.apk | 无 lib/* 的瘦身模板（约 16–17MB，arm64-v8a） |
| apps/app/src/main/assets/excluded-zip-files.json | 本次剔除的全部 lib/*，分 general/opencv/v8 |

## 3. lib 匹配要求（关键）

1. 一一对应：inrt APK 中每个 lib/ entry 必须恰好出现在
   excluded-zip-files.json 的某个数组里，不能漏、不能多；
   脚本会按排序严格比对，不一致直接失败。
2. 分类规则：
   - opencv：libopencv_*.so 与 libtbb.so；
   - v8：libv8*.so / libnode*.so（当前为 0 个，保留字段兼容未来 Node/V8）；
   - general：其余 lib/*（crypto、c++_shared、MLKit OCR、pikafish、ppocr、quickjs 等）。
3. 宿主必须真的有这些 entry：打包时按清单从
   context.getPackageCodePath()（宿主已安装 APK）逐条补；任何一个不存在都会
   导致打包失败。因此模板和 excluded 清单必须与当前宿主 APK 的原生库集合同批生成。
4. 模板不能含 lib/：verifySlimPackagingTemplate 会硬失败；体积必须
   6–20MB（当前约 16.4MB）。
5. 不要手工编辑 excluded-zip-files.json：改 :inrt 依赖或宿主 ABI 后重新跑脚本。

## 4. 校验与排错

脚本最后自动执行：

`powershell
.\gradlew.bat :app:verifySlimPackagingTemplate --console=plain
`

校验内容：模板存在、6–20MB、无 lib/、含 AndroidManifest.xml / classes.dex / resources.arsc、
excluded 三字段齐全且 general/opencv 不同时为空、AXML 包名探测。

常见失败：

- 尺寸 >20MB：漏跳过了 libnode.so 或 new_api_database.ser（检查脚本里的
  excludedAssetNames 与本次 inrt 产物）。
- excluded 缺少 lib / 打包补全失败：宿主 APK 与模板不是同批构建；以当前
  :app:assembleMiuixCompatDebug 产物重新生成模板和清单。
- 模板仍含 lib/：不要用 assembleRelease 产物原地改名；必须走本脚本的过滤逻辑。

## 5. 真机冒烟（可选）

模板/清单生成后，可按打包链路做一次 K40 冒烟：

1. 构建并安装含新 assets 的宿主 APK；
2. 打包页选一个小工程，生成脚本 APK；
3. 安装生成 APK 并启动，确认脚本能运行、原生库/OpenCV/QuickJS 与模板匹配。

> 插件模板（70MB）不参与本流程；需要更新插件时单独用新 :inrt release 重建插件。
