# 双引擎功能对比（Rhino / QuickJS）

> 更新日期：2026-09-11 ｜ 依据：Mi8 上 `list_engine_api` 实测（Rhino 225 项 / QuickJS 212 项 / 缺 24 项，见 `.artifacts/engine-api/engine-api-diff.json`）与源码实现
> 变更：P0（选择器 / UiObject、setScreenMetrics）、P1（顶层别名、`random/sync/auto/print/err`、应用快捷别名、选择器动作全局形式）、P1b（`gesture/gestures`、`input`、RootShell 按键助手）与 P2（`crypto`/`zips`/`util`/`automator`/`context`/`rawInput`/`sqlite` + 运行时状态全局）已上线：QuickJS 全局 61 → 212，缺口 173 → 24。
> 普通 `.js` 走 Rhino 1.7.7.2；首行 `// @engine quickjs` 走 QuickJS（libquickjs.so）

## 1. 总览

| 功能 | Rhino 引擎 | QuickJS 引擎 |
|------|------------|--------------|
| 悬浮窗 | ✅ 完整支持（XML 布局窗口、rawWindow、多控件、可拖动） | ✅ 支持（XML 布局/文本、控件代理、触摸/按键监听、焦点与调整模式、onClose/exitOnClose） |
| JSX 语法 | ✅ 支持 | ❌ 不支持 |
| 拖动功能 | ✅ 流畅 | ✅ 悬浮窗支持拖动 |
| 点击菜单 | ✅ 完整 | ⚠️ 使用对话框替代 |
| UI 界面（ui / $ui） | ✅ 完整（`ui.*`，XML 布局 + 事件 + attr） | ✅ XML 布局完整控件 + click 回调 view 参数 + list/grid setDataSource + item_click/item_long_click |
| 模块系统 | ✅ CommonJS require | ✅ CommonJS require（内置模块） |
| 稳定性 | ✅ 成熟稳定 | ⚠️ 开发中（持续对齐 Auto.js Pro） |

`require` 先解析内置模块名（`crypto`/`zips`/`util`/`automator`/`context`/`rawInput`/`sqlite`），其余按脚本相对路径从**磁盘**加载 `.js`；Rhino 的 `assets/modules/__*.js`（`web`/`io`/`plugins`/`continuation` 等）尚未迁移，选择器请用全局函数（`text()`…）或 `selector()`。

> `select` 在 Rhino 里被选择器的同名动作占用（历史遗留），QuickJS 取 Auto.js 文档里的对话框语义（`select(title, items)`）。

## 4. 主要差距（QuickJS 待补，剩 24 项）

> 按 2026-09-11 Mi8 实测差异归并；逐项清单见 `.artifacts/engine-api/engine-api-diff.json` 的 `onlyRhino`。

| 缺口 | 优先级 | 说明 |
|------|--------|------|
| Java 类注入（`Intent/Module/Shell/MutableOkHttp/Canvas/Image/Paint/Promise/Input/KeyEvent/RootAutomator`） | 中 | Rhino 通过 Java 类注入提供；QuickJS 白名单桥下常用场景已由 `keys`/`device`/`app`/RootShell 助手/`rawInput` 覆盖，剩余为类名与反射入口（需先定好互操作边界） |
| 剩余模块（`web`（含 `newInjectableWebView/Client`）、`io`、`plugins`、`continuation`） | 中 | 模块级能力未迁移（`crypto`/`zips`/`util`/`automator`/`context`/`rawInput`/`sqlite` 已对齐） |
| 控制台浮窗（`openConsole/clearConsole/addFilter`） | 低 | 现有 QuickJS 控制台输出已可用，浮窗/过滤未迁移 |
| `selection`、`progress`、`filter`/`findAndReturnList` | 低 | Rhino 通过 `__selector__.js` 把 UiSelector 的方法挂到全局（`filter` 还依赖 JS 回调），日常脚本罕用 |
| `Promise` | — | **非真缺口**：QuickJS/quickjs-ng 原生就有 `Promise`（可 `await`），只是它不可枚举，`list_engine_api` 按可枚举属性枚举，所以差异表把它归入 Rhino |
| `debugger`（断点/单步/变量） | 中 | 现有 Dim 调试器仅 Rhino |
| JSX / JSX 编译、UI 动态绑定（{{item.name}}） | 中 | 语法层与项目级 inflater 绑定 |
| Java 互操作（`importClass`/`Java.type` 任意反射） | 高（设计边界） | QuickJS 有意采用白名单桥接，不提供 Rhino 式任意反射；需先定正式兼容边界 |

## 5. 如何验证当前支持面

MCP 工具（需运行授权）：
```
list_engine_api {engine: "quickjs"|"rhino"}   # 枚举全局 API
probe_engine_api {engine: "rhino", name: "app"}  # 探测类型与成员
```

一次拿到差异表：

```powershell
.\tools\compare-engine-api.ps1 -Device <serial>   # 产物 .artifacts/engine-api/engine-api-diff.json
```

> PowerShell 5.1 的 HTTP 栈会给请求带上 `Expect: 100-continue`，而这个轻量 HTTP 服务按协议直接回 `417 Expectation Failed`（见 `McpHttpServer.serve`）；脚本改用系统自带 `curl.exe` 并显式 `-H "Expect:"` 去掉该头，会话内与子进程都能跑。
