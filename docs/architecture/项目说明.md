> **历史说明：** 本文包含早期 ImGui 主工作台和旧构建链描述，部分内容已不再代表当前实现。当前架构、构建命令和设备状态请先阅读 [项目现状与接手说明](../PROJECT_STATUS.md)。

> 本文根据当前本地源码快照整理，路径核对日期：2026-09-04；根目录 `README.md` 是项目入口，本文中的代码路径均以仓库根目录为基准。

## 1. 项目概览

这是一个面向 Android 的 JavaScript IDE 与自动化运行时。它通过无障碍服务、悬浮窗、屏幕捕获、控件选择器和 Rhino JavaScript 引擎，让用户可以直接在 Android 设备上编写、运行和打包自动化脚本。

主要能力包括：

- 使用 JavaScript 编写 Android 自动化脚本；
- 基于无障碍服务查找控件并执行点击、滑动等操作；
- 支持坐标手势、Root Shell、通知监听和按键监听；
- 支持截图、找图、找色和 OpenCV 图像处理；
- 内置脚本编辑器、示例、离线文档、控制台和布局分析工具；
- 支持悬浮窗、定时任务、Tasker 插件和桌面开发插件；
- 可把单个脚本或 AI.js Pro 项目封装成独立 APK。

### ImGui 混合迁移状态

项目已经加入 ImGui 主工作台，并将其设为应用唯一主页。工作台现按 AI.js Pro 的手机布局使用黑色双层工具栏、五个实心图标分页和铺满分页宽度的薄荷绿色选中指示线；五页分别承载脚本、内置示例、资源、插件市场和运行任务。脚本页使用 `#303030` 全宽紧凑列表，路径、返回上级、排序和漏斗筛选位于同一行，每项显示真实类型、修改时间、直接运行和更多菜单，并区分普通文件夹、AI.js Pro 项目和脚本文件。资源页使用紧凑资源卡片及“全部/我的”底栏，插件页使用两列封面卡片，任务页使用“运行中任务/任务”两个可展开列表。脚本文件不再进入旧 `EditActivity`，而由独立的 Pro 风格工作区承载左侧文件树、多文件标签、五组工具、查找替换、跳转、格式化、代码折叠、程序员快捷键、内嵌日志和终端；调试、单文件/项目 APK 打包与 `ui.layout`/`setViewFromXml` 设计预览也已接入真实能力。输入法、权限和系统设置仍使用 Android 系统能力。

- `SurfaceView + EGL + OpenGL ES 2 + JNI` 渲染链路；
- Dear ImGui 1.92.4 和 Noto Sans CJK 简体中文字体；
- 模拟 Pro 主界面的“脚本 / 示例 / 资源 / 插件 / 任务”五个图标分页；
- 使用 ImGui 绘制双层工具栏、五等分实心图标分页、项目类型分类图标、三行文件信息、行运行入口、更多菜单和带阴影的菜单式悬浮按钮；
- 示例页复用完整文件管理结构；资源页提供紧凑卡片、代码图标、描述、标签、大小、下载入口及底部分类；插件页提供两列封面卡片；任务页提供两组可展开任务列表；

- 触摸采集使用独立的短时输入锁，不再等待包含 `eglSwapBuffers` 的整帧渲染临界区，减少 Android UI 线程和 ImGui 渲染线程之间的输入竞争；
- 无障碍状态、运行脚本数量的 Java/C++ 状态桥接；

- 右下角悬浮菜单支持新建脚本/目录，并支持重命名和删除；输入使用原生键盘，删除必须二次确认；

### Rhino / QuickJS 双引擎状态

项目已采用双引擎并存模式：普通 `.js` 继续进入 `LoopBasedJavaScriptEngine → RhinoJavaScriptEngine`，保持旧 Auto.js API、UI、E4X、CommonJS 模块和 Java 互操作兼容；第一条非空行写有 `// @engine quickjs` 的脚本进入 `QuickJsJavaScriptEngine → JNI → libquickjs_jni.so → libquickjs.so`。QuickJS 固定为官方 `2026-06-04` 版，首批桥接了控制台、Toast、可中断 sleep、坐标手势、全局系统动作、剪贴板和前台应用信息。详细覆盖范围见 [Rhino / QuickJS 双引擎架构](QUICKJS_ENGINE.md)。

## 4. 关键运行流程

主应用启动流程：

```text
apps/app/src/main/java/com/jdkshen/aijspro/App.kt
  → 初始化全局上下文、主题、崩溃收集和定时任务
  → apps/app/.../autojs/AutoJs.java 创建应用层 AutoJs 单例
  → modules/autojs/.../AutoJs.java 创建 ScriptEngineService
  → ScriptEngineManager 注册 Rhino、QuickJS 与 RootAutomator 引擎
  → ScriptRuntime 注入 console、files、images、shell、accessibility 等 API
  → modules/automator 通过 Android 无障碍服务执行控件操作
```

脚本打包流程：

```text
脚本文件或项目目录
  + apps/app/src/main/assets/template.apk
  → 解包模板 APK
  → 写入 assets/project
  → 修改应用名、包名、版本、图标和 resources.arsc
  → 加密 JavaScript 文件
  → 重新打包并签名
  → 输出独立 APK
```

这里的“打包”不是重新编译一套 Android 工程，而是以 `inrt` 运行时 APK 为模板，替换脚本和应用元数据。当前内置模板由 `:inrt:assembleRelease` 生成，最低 API 21，包含 arm64-v8a 的 `libopencv_java5.so`；打包不再依赖设备上安装旧版外部插件。

## 6. 构建环境

该工程使用 2018 年前后的 Android 构建链。JDK 8 仍是最省事的选择；当前机器也已经使用 JDK 17 加临时模块兼容参数完成构建。ImGui 原生部分使用 NDK r27c、CMake 和 C++17，最低 API 21，并启用 flexible page-size 支持。

必需环境：

1. 64 位 Windows、Linux 或 macOS；
2. JDK 8；
3. Android SDK Platform 28；
4. Android SDK Build Tools 28.0.3；
5. 可访问当前 Gradle 和 Maven 镜像；
6. 如需安装或调试 APK，安装 Android Platform Tools/ADB。

不加兼容参数直接用 JDK 17 构建会在 Gradle 或 ButterKnife 阶段报模块访问错误，例如：

```text
Unable to get mutable Windows environment variable map
Caused by: java.lang.reflect.InaccessibleObjectException
```

这是 Gradle 4.10.2 与现代 JDK 模块访问规则不兼容造成的。根目录的 `build-common-debug.ps1` 会仅在当前进程中设置所需参数，构建结束后恢复原环境变量。

在根目录创建不提交的 `local.properties`，使用本机真实 SDK 路径，例如：

```properties
sdk.dir=C:/Android/Sdk
```

PowerShell 会话中临时切换 JDK：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk1.8.0_xxx'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
java -version
.\gradlew.bat --version
```

## 7. 常用构建命令

在项目根目录执行：

```powershell
# 查看全部模块
.\gradlew.bat projects

# 构建 common 渠道 Debug APK
.\gradlew.bat :app:assembleCommonDebug

# 当前机器：重建 ImGui 与 QuickJS 原生库并用 JDK 17 构建 common Debug APK
.\build-common-debug.ps1

# 只重建 QuickJS 三 ABI 原生库
.\modules\autojs\src\main\cpp\build-quickjs.ps1

# 已有原生库时跳过 CMake/NDK 步骤
.\build-common-debug.ps1 -SkipNative

# 构建 coolapk 渠道 Debug APK
.\gradlew.bat :app:assembleCoolapkDebug

# 同时构建主应用与独立脚本 Debug 运行时
.\build-common-debug.ps1 -SkipNative -IncludeInrt

# 构建独立脚本 Release 模板；完成后会同步 arm64 模板到 app assets
.\gradlew.bat :inrt:assembleRelease --max-workers=1

# 运行所有本地单元测试
.\gradlew.bat test

# 清理构建产物
.\gradlew.bat clean
```

主应用同时启用了渠道和 ABI 拆分，因此一次构建会分别生成 `armeabi-v7a`、`arm64-v8a` 与 `x86` APK。产物位于：

```text
apps/app/build/outputs/apk/
apps/inrt/build/outputs/apk/
```

安装时选择与设备 ABI 匹配的文件：

```powershell
adb shell getprop ro.product.cpu.abi
adb install -r '<生成的 APK 绝对路径>'
```

## 9. 权限与运行条件

多数自动化能力依赖用户在系统设置中主动授予权限：

- 无障碍服务：控件查找、点击、滑动和布局分析；
- 悬浮窗：控制台、悬浮按钮和布局检查器；
- 屏幕捕获：截图、找图和找色；
- 存储访问：读写脚本、图片和项目；
- 通知读取：通知监听 API；
- Root：可选，用于更强的 Shell、输入与录制能力。

应用清单还允许明文网络流量，并包含网络、开机广播、前台服务、录音、定位和使用情况访问等声明。二次发布前应根据实际功能删减权限并复核隐私说明。

## 10. 已知问题与维护提醒

1. **工具链陈旧**：Gradle、AGP、Kotlin、AndroidX 和大量第三方依赖版本较老，不宜一次性跨多个大版本升级。
2. **JDK 17 需要兼容参数**：本机已构建通过，但直接运行旧 Gradle 仍会失败；使用 `build-common-debug.ps1` 或切换到 JDK 8。
3. **版本标识不一致**：目录名、`project-versions.json` 和旧 `version.json` 表示不同版本，构建版本以 `project-versions.json` 为准。
4. **ABI 范围**：Gradle 已输出 `armeabi-v7a`、`arm64-v8a` 与 `x86`，仍未配置 `x86_64`。旧终端 AAR 没有 arm64 原生库，arm64 上的终端能力仍需单独移植与回归。
5. **Release 签名**：主应用 Gradle 中没有 `signingConfigs`；正式发布前需要明确配置。AI.js Pro 内部用 TinySign 给“脚本打包 APK”签名，这是另一条流程。
6. **脚本打包 ABI**：应用已改用内置 arm64 Release 模板，当前手机端打出的独立 APK 是 arm64-v8a；如需在应用内输出 v7a/x86 独立 APK，还需增加模板 ABI 选择。可选的外部插件工程当前不存在，不影响 arm64 内置打包。
7. **网络仓库**：依赖仓库已改为阿里云镜像，Gradle Wrapper 使用腾讯云镜像；若镜像下线，需要更换仓库地址或准备离线缓存。
8. **统计与崩溃收集**：主应用初始化代码包含 Flurry 和 Bugly。二次分发前应确认是否保留、替换应用 ID，并补齐隐私合规处理。
9. **现代 Android 兼容性**：该工程以 API 28 为目标，存储、后台运行、悬浮窗、包可见性和通知等行为在新版 Android 上可能受限，需要真机回归。
10. **QuickJS API 尚在扩展**：已支持 Native Frame、图色、OpenCV YOLO、文件、网络和定时器等白名单 API；依赖 `ui`、E4X、Rhino Java 互操作、`require()` 或其他未桥接 API 的脚本仍应使用默认 Rhino。
