# 与 AutoJs Pro 9.3.11 对齐方案（2026-11-09）

> **对齐目标**：**能力面对齐**，**不追求形似**。每条交付都必须有**可验收的观察**（真机字段/计数/命令），并写清未验证边界。
> **证据底座**：[架构阅读](2026-11-09_AutoJsPro9.3.11脱壳源码树架构阅读.md) · [project.json 与加密链对照](2026-11-09_与Pro9.3.11对照_project.json与脚本加密.md) · [类兼容/自动化/启动](2026-11-09_与Pro9.3.11对照_类兼容与自动化与启动.md) · [真缺口二分与两项评估](2026-11-09_与Pro9.3.11对照_真缺口二分与两项补齐评估.md) · [真缺口功能级复核终表](2026-11-09_Pro真缺口功能级复核终表.md) · [①量测报告](2026-11-09_Pro对齐①手势回调表泄漏量测（dev-1437）.md)（均在 `docs/reports/`）。

## 0. 一句话结论

**核心运行时已经同源**（Pro 505 个业务类里 **258 个**与我们同名同包；自动化三层文件级全同），差距集中在 **4 处结构差异** + **60 条能力缺口**。本方案把「要做的 / 要你拍板的 / 有意不做的」分成 A/B/C/D 四档排期。

## 1. 基线（数字都有出处）

### 1.1 类兼容

| | 数量 | 说明 |
|---|---:|---|
| Pro 业务类（文件级） | **505** | `com.stardust.*` + `org.autojs.*` |
| 我们 main 源集类（文件级） | **1,173** | `com.stardust.*` **536** · `com.jdkshen.aijspro.*` **592** · `org.autojs.source.*` **39** · 其它 6 |
| 精确同 FQN 交集 | **258** | ≈ Pro 的 51% |
| 仅 Pro 有 | 248 → **真缺 159 → 非 V8 复核 124** | 真缺 60 / 已等价 50 / 待定 16 / 忽略 2 |

### 1.2 已同源（**不用动**）

- **自动化三层**：`automator/filter` **16/16**、`search` **3/3**（DFS/BFS/SearchAlgorithm）、`simple_action` **10/10**；`AccessibilityBridge`/`UiObject`/`UiObjectCollection`/`UiGlobalSelector` 同名同包。
- **引擎与执行链**：`ScriptEngineManager`/`RhinoJavaScriptEngine`/`LoopBasedJavaScriptEngine`/`ScriptExecution*` 同一套（Pro `ScriptService` ↔ 我们 `ScriptEngineService`）。
- **工程格式**：`project.json` **15 个键共有**（name/versionName/versionCode/packageName/main/assets/launchConfig/build/icon/scripts/useFeatures/type/androidResources/permissionConfig/encryptLevel）。
- **旧密钥派生公式两边一致**（Pro 多一步「常量再加密」，见 §3 档 D-3）。

### 1.3 结构性不同（4 项，处置见 §2/§3）

| 维度 | Pro 9.3.11 | 我们 | 关键数字 |
|---|---|---|---|
| 布局 | 单 app + 混淆包 | 宿主 + 模块 | **12 个模块**（settings.gradle include） |
| 主界面 | `MainActivity extends FlutterActivity`（Flutter 壳） | 原生 MainActivity + Flutter 独立 activity（`-PflutterPoc=true`） | Flutter 侧 **24 文件 / 14,709 行**（+ `flutterpoc` 32 文件 / 12,663 行） |
| JS 引擎线 | Rhino **+ V8/Prolog** | 只有 Rhino（+ node24 引擎池） | Pro V8 线 **39 文件 / 11,207 行** + `System.loadLibrary("v8")` 与大量 `native` 方法 |
| 进程 | 主进程 + 少量服务 | **10 个 `android:process`** | `:script :node24 :node24_1..3 :tools :background :inspector :native :nodeui` |

### 1.4 能力缺口（真缺 60 的分布，取自功能级复核终表）

`core.image`(6) · `project`(6) · V8 线(40，未逐条核) · `com.stardust.app`(4) · `core.console`(4) · `view.accessibility`(4) · `core.pref`(3) · `core.util`(3) · `execution`(3) · IDE 可视化编辑器族 · 单点（`Aapt2`/`LooperThread`/`BuiltInAndUrlModuleSourceProvider`/`ShellOptions`/`Paint`/`ModelDatabase`/`SafeWindowBridge`/`ScriptNotification`/`CloseableManager` …）。

## 5. 风险与红线

1. **许可**：Pro 是**闭源商业版**；`源码树/` 与 `.artifacts/pro-*` 都是反编译产物。**只把「行为/接口形状」当需求输入，不复制代码/注释**；V8 与 j2v8 本体是开源，无此问题。
2. **跨版本外推**：K40 是 **Android 16**，而 Pro 用户多在 Android 9–13；凡涉及框架内部（如手势回调表）的结论**必须标注适用范围**。
3. **证据制**：每条完成都要有「可观察的验证」；未验证就写未验证。禁止「照单全收」外部分析。
4. **纪律红线**：构建/装机/LAN 发布/git 提交由 Lead 独占（**只本地，不 push**）；只 `git add` 本批明确文件（避免带走队友在制改动）；临时产出进 `output/<任务名>-<日期>/`，构建产物进 `.artifacts/`。
5. **回归风险**：A1-4（`project.json`）会动**打包产物读回**路径，必须先有 Pro 样例工程的解析测试；A1-1（`ImagePool`）会动图像生命周期，必须带长跑内存对照。
