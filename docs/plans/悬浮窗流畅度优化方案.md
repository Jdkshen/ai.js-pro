# AI.js Pro 悬浮窗流畅度优化方案

> **状态更新（2026-09-10）：** 涉及 ImGui 主工作台的条目（目标描述中的 ImGui 空闲负载、2.1、3.1、4.1）已随工作台删除失效（见 [项目现状与接手说明](../PROJECT_STATUS.md)）。悬浮球条目中，2.3、2.4、2.5、3.3、3.4、3.5 已落地；按帧合并（2.2、3.2）未在源码中核验到实现。

## 1. 优化目标

对齐 Auto.js Pro 9.3.11 的悬浮窗交互，降低 ImGui 主界面的空闲负载，解决悬浮球拖动、松手吸附和菜单展开/收起时的卡顿。

目标体验：

- ImGui 界面静止时不再持续满速渲染。
- 悬浮球拖动与手指位移实时同步，不积压窗口更新。
- 松手后吸边动画连续，不抖动、不跳帧。
- 点击悬浮球后菜单立即响应。
- 菜单展开和收起使用单一帧同步动画。
- Release APK 的实测流畅度接近 Auto.js Pro。

## 2. 当前已确认的问题

### 2.1 ImGui 空闲时仍满速渲染

当前 `ImGuiSurfaceView` 的渲染线程在 `while (mRunning)` 中持续执行：

1. `ImGuiNativeBridge.renderFrame()`
2. OpenGL 绘制
3. `eglSwapBuffers()`
4. 轮询无障碍节点修订和原生动作

即使没有触摸、滚动、动画或数据变化，仍会持续重绘。

真机前台静止数据：

| 应用 | 前台静止 CPU |
| --- | ---: |
| 当前 AI.js Pro Debug | 约 49%–53.5% |
| Auto.js Pro 9.3.11 Release | 约 0% |

### 2.2 拖动时窗口更新过密

`DragGesture.onScroll()` 对每个 `MotionEvent` 都直接调用 `WindowManager.updateViewLayout()`。触摸采样率可能高于屏幕刷新率，因此同一显示帧内会提交多次中间位置。

结果是主线程、Binder、WindowManager 和 SurfaceFlinger 产生不必要的排队。

### 2.3 拖动热路径中存在日志

当前每次 `onScroll()` 都执行：

```java
Log.d("DragGesture", "onScroll");
```

真机 1 秒拖动产生约 73 条日志。Debug APK 中这会进一步放大卡顿。

### 2.4 菜单动画使用两套系统

当前 `CircularActionMenu` 同时使用：

- 每个菜单项独立的 `ViewPropertyAnimator`。
- 旧式 `ScaleAnimation`。
- 多个子 View 上的重复动画监听器。

Auto.js Pro 9.3.11 使用一个 `ValueAnimator` 统一更新所有菜单项的位移和缩放。

### 2.5 单击需要等待双击判定

当前使用 `onSingleTapConfirmed()`，需等待系统确认本次不是双击。Auto.js Pro 使用 `onSingleTapUp()`，手指松开即响应。

### 2.6 对比构建类型不同

当前真机安装的是 Debug APK，Auto.js Pro 是 Release APK。Debug 构建保留日志、调试信息和额外检查，不能作为最终性能结论。

## 3. 实施方案

### 3.1 ImGui 改为按需渲染

涉及文件：

- `apps/app/src/main/java/com/jdkshen/aijspro/ui/imgui/ImGuiSurfaceView.java`
- `apps/app/src/main/java/com/jdkshen/aijspro/ui/imgui/ImGuiNativeBridge.java`
- `apps/app/src/main/cpp/autojs_imgui.cpp`

实施方式：

1. 为渲染线程增加“脏帧”和“持续动画”状态。
2. 触摸、页面滚动、惯性、吸附动画、数据刷新和弹窗变化时请求新帧。
3. 静止且没有待处理动作时，渲染线程通过 `wait/notify` 或等价机制休眠。
4. 活动期间按屏幕 VSync 节奏渲染，不进行无上限循环。
5. Activity 进入 `onPause/onStop` 后显式暂停渲染，`onResume` 后请求一帧并恢复。
6. 无障碍虚拟节点只在修订号变化时通知，不依赖永久轮询。

注意：ImGui 的上下惯性、左右分页、抽屉吸附和按钮动画运行期间必须保持连续帧，不能被误判为静止。

### 3.2 拖动位置按屏幕帧合并

涉及文件：

- `apps/app/src/main/java/com/jdkshen/aijspro/ui/floating/gesture/DragGesture.java`
- `third-party/EnhancedFloaty/lib/src/main/java/com.stardust.enhancedfloaty/WindowBridge.java`

实施方式：

1. `ACTION_MOVE` 只更新最新的目标 `x/y`。
2. 通过 `Choreographer.postFrameCallback()` 请求下一个显示帧。
3. 同一帧内的多个 `MOVE` 事件只提交最后一个位置。
4. 每帧最多调用一次 `WindowManager.updateViewLayout()`。
5. `ACTION_UP/ACTION_CANCEL` 先提交最终位置，再开始吸边。
6. 窗口关闭时取消已排队的帧回调，避免操作已移除的 View。

### 3.3 删除拖动热路径日志

删除 `DragGesture.onScroll()` 中的逐帧 `Log.d`。

如仍需要调试信息，仅保留：

- 拖动开始坐标。
- 拖动结束坐标。
- 吸边目标坐标。
- 整次拖动的帧提交数和丢帧数。

这些日志需受 `BuildConfig.DEBUG` 与独立调试开关控制。

### 3.4 菜单动画改为单一 `ValueAnimator`

涉及文件：

- `apps/app/src/main/java/com/jdkshen/aijspro/ui/floating/CircularActionMenu.java`

实施方式：

1. 移除每个子项独立的 `ViewPropertyAnimator`。
2. 移除旧式 `ScaleAnimation` 与 `startAnimation()`。
3. 用一个 `ValueAnimator.ofFloat(0f, 1f)` 控制所有菜单项。
4. 展开时使用 `animatedFraction`，收起时使用 `1f - animatedFraction`。
5. 同一回调内统一设置：
   - `translationX`
   - `translationY`
   - `scaleX`
   - `scaleY`
6. 动画开始前取消上一个 Animator，支持快速连续点击时反向播放。
7. 动画完成只通知一次状态监听器。

### 3.5 单击改为松手立即响应

涉及文件：

- `apps/app/src/main/java/com/jdkshen/aijspro/ui/floating/gesture/DragGesture.java`

实施方式：

1. 将 `onSingleTapConfirmed()` 替换为 `onSingleTapUp()`。
2. 保留拖动阈值，保证拖动结束不误触点击。
3. 点击与吸边的先后顺序要固定，避免同一次 `ACTION_UP` 同时展开菜单和启动吸边。
4. 添加 `ACTION_CANCEL` 状态清理。

### 3.6 生成 Release APK 并对比

对比对象：

- 优化前 Debug APK。
- 优化后 Debug APK。
- 优化后 Release APK。
- Auto.js Pro 9.3.11 Release。

构建产物需要同时记录：

- APK 绝对路径。
- 文件大小。
- SHA-256。
- ABI。
- `versionName/versionCode`。
- `debuggable` 状态。
- 签名信息。

## 4. 验收指标

### 4.1 ImGui 空闲负载

- 主界面静止 5 秒后，进程 CPU 平均占用应从约 50% 显著下降。
- 目标：Release 版静止 CPU 接近 0%–5%。
- 静止时渲染帧数不应持续增长。
- 触摸、页面切换和数据更新后必须立即恢复渲染。

### 4.2 悬浮球拖动

- 60Hz 屏幕：每秒 `updateViewLayout()` 不超过约 60 次。
- 120Hz 屏幕：每秒不超过约 120 次。
- 不得出现逐 `MOVE` 日志。
- 手指快速拖动后，最终落点误差不得因帧合并而增大。
- 松手后只启动一次吸边动画。

### 4.3 点击与菜单动画

- 单击松手后菜单应立即开始展开，不再等待双击超时。
- 展开/收起期间仅有一个主 Animator。
- 连续快速点击不得卡在 `mExpanding` 或 `mCollapsing` 状态。
- 动画期间的平移和缩放必须保持同步。

### 4.4 功能回归

- 悬浮球拖动、左右吸边和半隐藏。
- 横竖屏切换后的位置校正。
- 菜单展开/收起。
- 脚本列表、录制、布局分析、停止全部脚本和设置入口。
- 显示/隐藏悬浮窗。
- Activity 前后台切换。
- Android 13 与 Android 16 真机回归。
- 长时间运行不得出现帧回调泄漏、已移除 View 更新或窗口异常。

## 5. 实施顺序

1. 先保存优化前的 CPU、日志数和录屏基线。
2. 删除拖动热路径日志，作为低风险基线修复。
3. 实现悬浮窗位置的 VSync 合并更新。
4. 将单击改为 `onSingleTapUp()` 并回归点击/拖动边界。
5. 将圆形菜单改为单一 `ValueAnimator`。
6. 改造 ImGui 按需渲染，单独回归所有惯性和动画。
7. 构建 Debug APK，完成 Android 13 真机验证。
8. 构建 Release APK，完成数据对比。
9. Android 16 设备连接后完成最终回归。

## 6. 风险与回退点

### 高风险：ImGui 按需渲染

如果脏帧判定不完整，可能造成动画停止、新数据未显示或无障碍节点不刷新。需要将该改造与悬浮窗优化分开提交，便于独立回退。

### 中风险：拖动帧合并

必须确保 `ACTION_UP` 前的最终坐标不被丢弃，并处理视图关闭和服务销毁时的帧回调。

### 中风险：菜单动画替换

快速反向动画需要从当前 fraction 继续，不能每次都从 0 或 1 跳变。

### 低风险：日志和单击回调

可以分别独立实施和回退。

## 7. 完成标准

以下条件全部满足后，本轮优化才算完成：

- 六项改造均已实现。
- Debug 和 Release 均构建成功。
- Android 13 真机通过功能与流畅度回归。
- Android 16 真机通过安装、启动、悬浮窗与长时间运行回归。
- 静止 CPU、拖动提交次数和动画体验均达到验收指标。
- 输出 Release APK 路径、SHA-256 和对比结论。
