### 2.1 用户报错路径 __ui__.js:408/409

当前源码（以及 apps/app/build/... 和 modules/engine/build/... 里的构建副本）中：

- __ui__.js 第 408、409 行就是用户报错的 view.getClass().getName()；
- 第 132 行不是 getClass：当前源码第 132 行是 throw err;（wrapUiAction 的异常重抛）；全文件 getClass 只有 408/409 两处。用户提到的 “132” 应该是旧版本行号漂移或外部副本，不是当前源码的 Class API 调用。
- 修复链路：view.getClass() 返回 java.lang.Class，WrapFactory 包成 AijsNativeJavaClass；get("getName") 先查 CLASS_API_NAMES（由 Class::class.java.methods/fields 生成），再用 classInstanceMember 对 NativeJavaObject(Class) 调实例方法；has("getName") 同步为 true。
- 现有 JVM 回归 modules/engine/src/test/java/com/stardust/autojs/rhino/AijsNativeJavaClassTest.java 的 classInstanceApiStaysReachableOnWrappedClasses 已覆盖：
  - String(java.lang.String.getClass().getName()) == "java.lang.String"
  - String(java.lang.String.getClass().getSimpleName()) == "String"
  - String(Packages.java.lang.String.getName()) == "java.lang.String"
- 因此 408/409 在修复后都应通过；修复前两处都会在 “has no public instance field or method named getName” 处失败。

## 6. 怎么验证

1. **静态复扫**：本报告脚本按 getClass()\s*\.\s*(method)\(、\.class\s*\.\s*(method)\(、Packages\.…\.(method)\( 扫描，method 限定为 java.lang.Class 公开实例 API；engine assets 与 app sample 均只读。
2. **Rhino 回归测试**：运行 AijsNativeJavaClassTest.classInstanceApiStaysReachableOnWrappedClasses；或设备上执行
   - view.getClass().getName()
   - view.getClass().getSimpleName()
   - view.getClass().isArray()
   - Packages.java.lang.String.getName()
   预期不再报 has no public instance field or method。
3. **用户原路径**：在 K40 上打开带 ui 的打包版脚本/示例，确认 __ui__.js:408/409 的 JsListView/JsGridView 分支能正常进入；这正是用户原报错路径。
4. **反向检查**：修复前的对照是 dev-1380~1382 的 AijsNativeJavaClass（只解析静态成员）；可用旧版本打出的包复现，不应再把 Class.getName() 归到目标类静态成员。

## 7. 扫描边界

- 正则按源码单行直接形态统计；var c = x.getClass(); c.getName() 这类先赋变量、跨行链式调用未计入，数量是直接形态的下界。
- 只扫源码树，排除 build 产物、node_modules、二进制；构建副本与源码当前行号一致（__ui__.js 132 亦为 throw err）。
- 未在本轮修改任何产品代码；本清单只用于回归面确认和后续清理排序。
