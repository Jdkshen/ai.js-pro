# 打包页真机点检清单（task-108）

> 对象：K40 + dev-1465 之后任一候选；页面：脚本列表 ⋮ →「项目配置与打包」。
> 格式：**步骤 → 期望 → 失败时看哪里**。全部只读/只影响打包选项，不改脚本运行。

## 0. 前置（每次先做）
1. 确认 MCP 在线（先探活再跑，避免白跑一轮）：`curl -s -m 5 http://<设备>:<port>/...` 或直接跑一条最小 `get_status`。
2. 确认这一版是**带本次 Dart 改动**的包：`-RebuildAot` 已加（否则文案/开关看不到）。判据：页面上能看到「移除内建 OCR（产物少约 7.8 MB）」。
3. 准备一个工程目录：建议用现成的 SjbcE2E（或任意含 main.js 的工程）。记下当前 project.json 的内容（后面要比对）。

## 1. 勾 / 取消「移除内建 OCR」→ 保存 → 重进页面看回填
- 步骤：进页面 → 勾「移除内建 OCR」→ 点「保存」→ **返回再进**（或「从磁盘重新读取」）→ 看该勾是否仍勾着。
- 期望：① 保存成功（页面状态变「已保存」）；② 重进后该勾**仍勾着**；③ project.json 里 `optimization.removeOcr=true`。
- 失败看哪里：① 保存失败 → 页面顶部错误行 + logcat 里 `projectSave` 相关；② 重进后没勾 → 看 `projectLoad` 返回的 `config.optimization.removeOcr` 是否为 true（这是回填路径）；③ 文件里没有该键 → 保存没写进去。
- **再取消勾选**再保存：期望 project.json 里 **removeOcr 这个键消失**（不是 `false`）——这是 task-108 改过的行为；失败看：文件里仍是 `removeOcr=false` 说明跑的是旧包（AOT 没重建）。

## 2. 没勾过的工程：project.json 不应出现 removeOcr
- 步骤：拿一个**从未勾过**「移除内建 OCR」的工程 → 进页面 → 只改别的（例如改个名字）→ 保存 → 看 project.json。
- 期望：`optimization` 里**没有** `removeOcr` 键；其它既有键行为与以前一致。
- 失败看哪里：若出现了 `removeOcr=false` → 默认值被写回（检查初始 map 是否含该键 / 取消勾选是否删键）。

## 3. 打包：大小构成里「内建 OCR」桶应为 ~0.0 MB
- 步骤：勾上「移除内建 OCR」→「保存并打包」→ 等打包完成 → 看「本地打包」卡的 `大小构成（未压缩）` 行。
- 期望：该行里 **`内建 OCR ~0.0 MB`**；同时产物 OCR 条目 = 0。
- 失败看哪里：① 行整行不显示 → 看 logcat 有没有 `apkBreakdown 失败`（有=桥失败；没有=桥没被调到）；② 行显示 `暂不可用（…）` → 原因就在括号里；③ OCR 桶不为 0 → 抓 logcat 的 `C-PKG:` 行（policy / ocr removed）。

## 4. Node.js 选「不包含」→ 打包 → 「引擎与模板」桶应下降
- 步骤：`运行库与资源` 卡里把「Node.js 运行库」选 **「不包含 Node.js 运行库（产物少约 1.4 MB）」** → 保存并打包 → 看大小构成。
- 期望：`引擎与模板` 桶比默认态**下降约 1.4 MB**（node24 + source-engine-upgrade 不再随包，27 → 0 条目）。
- 失败看哪里：① 选项没有该项 → AOT 未重建；② 桶没降 → logcat 找 `node24 assets skipped`；③ 打包失败 → 看打包日志里的 `C-PKG:`。

## 5. 无 sjbc 字段的工程：不显示 SJBC 行
- 步骤：拿一个 project.json **没有** `sjbc` 字段的工程 → 进页面 → 看「运行库与资源」卡。
- 期望：**不出现** `SJBC 资源目录：…` 那一行（不是显示空值）。
- 失败看哪里：① 显示了但值为空 → 取值层级错了（应取 `loaded['config']['sjbc']`，见 `sjbcConfig()`）；② 该显示却没显示 → 看 `projectLoad` 返回的 `config` 里有没有 sjbc。
- 对照：带 sjbc 的工程应显示 `SJBC 资源目录：assets/sjbc（检测到 N 个 .sjbc）` + `期望指纹：<前12位>…（只读，真值在 project.json）`；**N 拿不到时只省略括号里的计数**，那一行仍在。

## 6. 什么情况下「大小构成」整行消失（别误判功能没了）
- **整行消失**：① 还没打出有效产物（`validArtifact` 假：路径不是绝对 / sha256 不是 64 位十六进制 / size 非正）；② 桥调用成功但 `buckets` 为空。
- **整行不消失但换文案**：桥调用失败或回非对象 → 显示 `大小构成：暂不可用（<原因>）`（task-100 加的，不再静默）。
- 失败看哪里：logcat 关键字 `GlassFlutterPoc` + `apkBreakdown 失败`。

## 7. 复查结论（代码级，供对照）
1. **removeOcr round-trip**：默认不勾 ⇒ 不写键；勾上 ⇒ 写 `true`；**取消勾选 ⇒ 删键**（task-108 改；只针对 removeOcr，既有 4 键行为不变）。
2. **加载侧两条路径不冲突**：`for (final key in optimization.keys)` 只覆盖「当前 map 里已有的键」（默认 4 个 + 若已勾过则含 removeOcr），显式分支 `if (rawOptimization.containsKey('removeOcr'))` 只在文件确实有该键时补一条；Dart map 字面量**后者覆盖前者**，两者取值同源 ⇒ 不存在「同键被两条路径写成不同值」。**未知键不会抖动**：回填只认当前 map 的键 + removeOcr 这一个显式键，文件里的其它 optimization 键不会被读进 payload（有意，避免把不认识的键写回）。
3. **口径统一**：主口径统一为**产物**（removeOcr 约 7.8 MB / nodejs 约 1.4 MB），未压缩值只在 OCR 说明里作为补充并写明单位。
4. **取值层级**：sjbc 取 `loaded['config']['sjbc']`（已修 ✓）；大小构成走桥 `apkBreakdown{path}`，失败有明确降级文案。
