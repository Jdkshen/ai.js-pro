## 0. 一句话

交接单待办⑤里「P1-4 真机成功路径」此前只有 JVM 合成夹具；本轮**造出带空隙的真实 arm64 .so**，在真机上跑通了失败路径与成功路径，并用 logcat 证明 gadget 确实在 dlopen 阶段被 DT_NEEDED 拉起（把注入的 Provider 指到惰性进程以排除替代解释）。

## 1. 为什么需要夹具

`ToolkitElfNeeded`（apps/app/src/main/java/com/jdkshen/aijspro/mcp/ToolkitElfNeeded.kt:148-192）只就地改字节、**绝不改变文件大小**，所以目标 .so 必须已经具备：

1. `.dynstr` 有空隙：`freeStart = 最后一个非零字节 + 2`，`have = dynstrSize - freeStart ≥ 17`（等价于**尾部至少 18 个连续 NUL**），或 `.dynstr` 里已存在 `libaijsgadget.so`；
2. `.dynamic` 有一个「改掉后仍保留 DT_NULL 终止符」的空槽（某个 tag==0 的条目其后一条也是 tag==0）。

真实 .so 通常两条都不满足。本轮用 **NDK clang 编一个 5KB 的 `libdtprobe.so` + Python 手术**造出空隙（把 `.dynstr`/`.dynamic` 的副本搬到文件尾并扩出 NUL padding / 备用 DT_NULL，同时更新 PT_DYNAMIC、DT_STRTAB、DT_STRSZ、包含段的 filesz/memsz 与节头），再用 aapt2+d8+apksigner 打一个最小可安装 APK（MainActivity 里 `System.loadLibrary("dtprobe")`），使 gadget 的加载时机可直接观察。

## 2. 真机证据（K40，dev-1414）

### 2.1 失败路径（未 padded 的 .so）

- `apk_inject_gadget{preloadMode:"dt_needed"}` → `PRELOAD_DT_NEEDED_FAILED`，`details.targets[0]={path:lib/arm64-v8a/libdtprobe.so, reason:"DYNSTR_NO_ROOM:17x0"}`，`nextActions` 给出 patchelf 回退；
- 输出目录里**只有输入 APK、没有产物** → 「失败不产出半坏 APK」成立。

### 2.2 成功路径（padded .so）

- `applied=true / verified=true / earlyLoad=true / preloadImplemented=true / method="in-place DT_NEEDED" / sizeUnchanged=true`；
- `targets[0]={path:lib/arm64-v8a/libdtprobe.so, strtabOffset:64, dynamicIndex:23}`（正好用上我们造的尾部 padding 与备用 DT_NULL 槽）；
- 输出 APK 14,711,074B，签名 RSA·C=CN,O=AI.js Pro，schemes V1+V2，`installable=true`；`partial=true` 的原因是**目标自带 .so 的 PT_LOAD 页对齐**（夹具用 4KiB 对齐，K40 是 4096 页设备；16KiB 设备/上架校验会判不合格），工具如实标注。

### 2.3 独立字节核对（不采信工具自报）

把输出 APK 拉回本地，抽出 `lib/arm64-v8a/libdtprobe.so` 与注入前的 padded 版本逐字节比对：

- 大小不变（5536B），**只有 18 字节变化**（16 字节是 dynamic 条目 tag/value，2 字节是写入串的首字节差异；其余位置与原文相同）；
- `DT_NEEDED = [libdl.so, libc.so, libaijsgadget.so]`，`DT_NULL` 终止符仍在（剩余两项）；
- `.dynstr` 里确实含 `libaijsgadget.so`；变化位置全部落在实现声明的 `changedRanges` 内。

### 2.4 运行时：gadget 真的在 dlopen 阶段被拉起

第一次运行（Provider 默认进程）里 gadget 确实加载了，但顺序显示是**注入的 Provider** 先加载的（`nativeloader ... caller=base.apk!classes2.dex`，早于我们 Activity 的静态初始化）→ 这条不能证明 DT_NEEDED 的效果。

于是**把 Provider 指到惰性进程**（`providerProcess=":probe_only"`，`providerProcessSource=explicit`，Provider 永远不被实例化）重做一次，logcat 顺序（同一 PID）：

```
22:05:21.783 I/DTPROBE  : before System.loadLibrary(dtprobe)
22:05:21.831 D/nativeloader: Load .../lib/arm64/libdtprobe.so ... : ok
22:05:21.833 I/DTPROBE  : after System.loadLibrary(dtprobe)
22:05:21.836 I/Frida    : Listening on 127.0.0.1 TCP port 27043
22:05:21.838 I/DTPROBE  : MainActivity.onCreate (gadget should already be loaded)
```

即：gadget 是作为**目标 .so 的 DT_NEEDED 依赖**在 dlopen 期间被加载并完成初始化的（Frida 已经真的在监听端口），**不是** Provider 或 Java 代码触发的。
