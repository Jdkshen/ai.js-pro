## 1. 接手结论

项目已经不是早期的 ImGui 主界面版本。当前主线是 **Compose/Miuix 显示层 + Android View 业务/编辑器/终端 + QuickJS Native Core + Rhino 兼容提供器 + OpenCV DNN**。

现有提交值得保留，但“构建成功、API 名称数量增加”不等于“所有功能已完整验证”。文件列表迁移和 Native Frame 长稳测试仍有明确缺口。

本轮只新增接手报告，没有修改业务源码，没有提交、推送、发布、安装或变更手机授权。

## 3. 近期主要修改与新增

### 3.1 界面与文件列表

- 主界面转向 Compose/Miuix；旧 ImGui 工作台、渲染桥和动态库已移除。
- 编辑器、终端分别迁入 `ui.editor`、`ui.terminal`，保留 Android View 实现。
- 设置、服务、日志、文档、资源、示例、插件、任务、MCP 等页面接入 Miuix。
- 删除 legacy channel 和多处反射桥，改为编译期直连。
- 清理旧 Activity 的业务壳及部分 XML 资源，保留旧入口转发契约。
- 新增纯状态 `ExplorerNavigationState`、`ExplorerListRows`，并增加排序/页面栈单测。
- 新增实验性 `MiuixScriptListHost`，接入目录导航、排序、长按/更多、重命名、删除、运行、打包、定时任务和快捷方式。
- Compose 文件列表仍由 `aijspro.experimental.miuix_file_list` 控制，源码默认值是 `false`；旧 `ExplorerView` 尚未全部退役。

### 3.2 QuickJS 与引擎分层

- 新建脚本/项目默认 QuickJS；旧无标记脚本保持 Rhino，支持文件与项目引擎配置。
- 增加选择器/UiObject、手势、屏幕坐标缩放、顶层兼容别名。
- 增加 Java 互操作：`Packages`、`importClass`、`importPackage`、`Java.type`、public 方法/字段、嵌套类及 Java 类对象。
- 补充 crypto、zips、sqlite、io、web、continuation、运行时状态与控制台浮窗等模块。
- 扩充 UI/floaty 控件属性、真实 View 句柄、原生动画、跨线程窗口访问、生命周期与触摸透传。
- compat 注册 Rhino 执行提供器；lite 不注册 Rhino，但仍保留 Rhino language 类型依赖，不能称为完全去除 Rhino。
- 新增/更新全模块、UI Floaty 等回归案例；文档中的 228 项/250 API 等数字属于历史设备快照，本轮没有重新执行这些设备脚本。

### 3.3 图色与 YOLO

- Native Frame 增加编码图像、拼接、全点找色等能力及调试池统计。
- 入口仍是 `Image.Plane DirectByteBuffer → JNI → NativeFrameStore`。
- full 入口会复制到自有 Mat；fast 入口 resize 到自有 Mat，不是绝对零拷贝。
- 池当前上限为 4 帧、50 MB；`release()` 在对象仅由 Store 持有时才回收到池，降低悬空引用风险。
- 增加 Frame↔OpenCV Mat 桥与更多图像 API。
- YOLO 继续使用 OpenCV DNN；`detectRgba()` 用 DirectByteBuffer 包装 Mat 视图，没有整帧 Java 数组复制。
- 当前固定 YOLO 模型输出按每行 6 个值解码，不应在未确认模型语义时随意增加第二次 NMS。

### 3.4 打包、保护与发布

- 增加用户签名证书管理、复用和修复路径，避免打包总使用公开证书。
- 打包页支持五档：不加密、AES、编译快照、加密 so、快照 so。
- 编译快照区分 Rhino class 与 QuickJS bytecode，运行时配套读取。
- 解密链路下沉到 native crypto，并增加随机盐/签名绑定相关实现。
- 增加自建更新源、下载校验、更新历史和本地开发发布脚本。
- 发布事故修复涉及多设备参数、输出路径、假版本污染与 `-DryRun`；这些脚本不能当普通只读检查执行。
- 以上是实现存在的确认，不是五档打包当前设备端到端测试通过的声明。

## 5. 源码确认的问题

### P1：Compose 列表返回/刷新会丢滚动位置

位置：`MiuixScriptListHost.kt:115`、`:145`、`:258`；`ExplorerNavigationState.kt:11`。

`reload()` 会先设置 loading，再把 LazyColumn 从条件分支中移除；没有显式保存每个目录的 LazyListState。页面栈仅存 ExplorerPage，没有首个可见项/偏移信息。返回父目录时会重建列表，有重新回到顶部的风险。

建议：页面状态同时保存稳定路径、首个可见项 key 与偏移；loading 时保留列表主体，不销毁滚动状态；为返回、刷新、编辑器往返分别补测。

### P1：实验模式下新建菜单无响应

位置：`MainActivity.java:352` → `MyScriptListFragment.java:229`。

新建按钮转交 `onClick()`；该方法在 `mExplorerView == null` 时直接 return。Compose 模式没有创建旧 ExplorerView，因此文件、文件夹、导入、项目四项都没有接到新 Host。

建议：抽公共文件动作宿主，以当前目录为参数，按当前模式分发；不要为新建动作重新构造一个隐藏旧列表。

### P1：搜索定位只有切目录，没有定位和高亮

位置：`MiuixScriptListHost.kt:121`。

`revealFile()` 注释称会高亮，但实现只 push 目录并 reload。没有目标 key、scrollToItem 或高亮状态；以当前目录作 startsWith 检查，还会拒绝当前目录以外的合法搜索结果。字符串 startsWith 也不是完整的目录边界检查。

建议：以工作区根做规范路径约束，重建有意义的导航栈，加载后定位目标 key，并使用可自动消退的高亮。

### P1：删除后刷新时机错误

位置：`MiuixScriptListHost.kt:602`；`ScriptOperations.java:368`、`:380`。

Host 调 `delete()` 后立即 reload，但真正删除发生在用户确认之后的异步回调。Host 未订阅 ExplorerChangeEvent，也没有删除完成回调，确认后的删除可能仍显示旧条目。

建议：仅在成功删除之后刷新；取消删除不得改变列表和滚动位置；失败保留条目并显示错误。

### P2：Host 生命周期没有完整接入

位置：`MiuixScriptListHost.kt:141`；`MyScriptListFragment.java`。

Host 定义了 `dispose()`，但 Fragment 当前没有 onDestroyView 清理 Host 的代码，也未清空列表引用。长目录读取可能在 View 销毁后仍回调旧状态。

建议：在 onDestroyView dispose 并清空引用；需要跨 View 重建保留的导航/滚动状态放到独立状态宿主，而不是依赖 View 实例。

### P2：无障碍动作缺少名称

位置：`MiuixScriptListHost.kt:344`、`:506`。

HeaderIcon/RowIcon 的 Image `contentDescription` 为 null，按钮 Box 没有额外语义名称。返回、排序、运行和更多可能只能暴露无名称可点击节点。

建议：提供资源化的 action label/semantics。Compose 已有虚拟语义树，不需要恢复旧 ImGui AccessibilityNodeProvider。

### 已知未完成：项目菜单、刷新与完整操作矩阵

`showProjectActions()` 仍是空方法；文件选择器、下拉刷新、项目工具条、更多操作与适配矩阵尚未收口。保持实验开关默认关闭，完成这些行为回归前不得删除 ExplorerView。
