## 发布硬门

新增 `tools/check-android-16kb.py`，不依赖 NDK、不使用第三方白名单：

1. ELF64 PT_LOAD 的对齐值、文件偏移与虚拟地址满足 16 KB 映射条件。
2. RELRO 按 16 KB 圆整后不能保护后续可写数据。**独立 RELRO LOAD 的末尾不圆整不自动判错**，按 Android 官方文档例外处理。
3. APK 内未压缩 native library 的 ZIP data offset 为 16 KB 对齐；压缩库及运行时抽取的 assets 分别处理。
4. 除 `lib/arm64-v8a` 外，还检查 Node runtime 和 CLI 资产，避免漏掉延迟加载的库。

`tools/dev-update.ps1` 在复制发布文件、改写 update.json 前强制执行；`-SkipBuild` 不能绕过。Gradle `:app:verify16kbAlignment` 使用同一个检查器。旧 PowerShell 白名单工具保留作历史诊断，不能作为发布依据。

对照验证：旧 dev-1194 **失败**，指出 Flutter 引擎和 Node libc++ 两项；升级候选 dev-1195 的 **22 个 64 位 ELF 全通过**。
