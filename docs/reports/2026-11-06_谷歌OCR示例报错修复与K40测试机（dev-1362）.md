## 二、谷歌 OCR 示例：两个真因（不是同一个 bug）

### 真因 1：`:script` 进程从未初始化 MlKitContext

```text
文字识别失败：MlKitContext has not been initialized (__ocr__.js#67)
```

- ML Kit 的 `InitProvider` 只在**主进程**跑；`:script` 进程必须自己 `MlKit.initialize(context)`。
- **Node 的 `:node24` 一直有这段**（`Node24HostBridge.java:659-669`），Rhino 侧漏了 → 所以同样的 OCR 在 Node 能跑、在 Rhino 挂。
- 更坑的是：`new Ocr(runtime)`（= `$ocr.create()`）**不报错**，直到第一次 `detect()` 才抛 —— 所以「失败兜底到 ppocr」的既有逻辑从来没被触发过。

修复：
1. `Ocr.java` 新增 **幂等** `ensureMlKitInitialized()`（`MlKitContext.getInstance()` → 失败则 `MlKit.initialize(appContext)`；拿不到 Context 返回 `false`），构造函数里调用；
2. `__ocr__.js`：`mlkit` 起不来时**提前**退到随包 PP-OCRv6，并如实暴露 `requestedBackend / backend / degraded / degradedFrom / degradeReason`；
3. `__plugins__.js`（Rhino 插件 shim）：选后端前先问 `Ocr.ensureMlKitInitialized()`，不再把「死」后端排在前面；
4. `qjs-plugins.js`（QuickJS）：同源保护（队友 `imgui-re` 完成，+155 行，含直接 `$ocr.create` 的 guard）。

### 真因 2：`console.log(result)` 序列化 Java 对象图

```text
Wrapped java.lang.IllegalArgumentException: class androidx.recyclerview.widget.RecyclerView
declares multiple JSON fields named mAccessibilityDelegate (__json2__.js#234)
```

- `detect()` 原来把 **Java `OCRResult` 对象**直接塞进数组；该对象带 `android.graphics.Rect` 和 `javaObject`（原始 ML Kit 对象），
- 官方示例第一行就是 `console.log(result)` → 我们的 console 走 `__json2__.js` 序列化 → 顺着 Java 引用一路走到宿主 Activity/RecyclerView → 崩。

修复：`detect()` 逐项转成**纯 JS 对象**（字段与 PDF 文档一致，`bounds` 额外给 `x/y/width/height`）：

```jsonc
{"text":"13:01 。m","confidence":0.59375,
 "bounds":{"left":66,"top":34,"right":276,"bottom":69,"x":66,"y":34,"width":210,"height":35},
 "rotation":0,"rotationConfidence":0}
```

原始对象改为 **方法** `raw()`（方法不会被 JSON/console 序列化，能力不丢）。

## 五、边界与未做

1. **ML Kit 与 PP-OCR 结果不同**：同一张图 ML Kit 行数同为 18，但文本与置信度不同（`13:01 。m` / 0.5938 vs `13:01m` / 0.9668）。降级链是「能用」，**不是等价**。
2. `ensureMlKitInitialized()` 只在本进程做一次初始化；`:script` 进程被回收后重新起脚本会再做一次（幂等，开销可忽略）。
3. `qjs-plugins.js` 的 QuickJS guard 队友已写，但**本轮只验证了「缺 ensure 时安全降级」**；含新 Java 方法的构建（dev-1362）还没单独复跑 QuickJS 的 mlkit 路径。
4. `apk_build` 切 apksig/加 V3 未做（见上）；`apk_build_project`/`apk_inject_gadget` 的返回体还没加顶层 `alignment`（内部 `verification.zip.alignment` 已有）。
5. MI8 上的历史结论（截图耗时、示例通过率等）**未在 K40 复测**；后续默认以 K40 为准。
