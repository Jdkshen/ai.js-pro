## 3. P0：修复空格契约、计数和残局拒绝

### 3.1 已确认的契约不一致

`src/vision/recognizer.js` 的 EMPTY 分支使用 `chars[index] = null`。`tools/recognize-board.js` 的 `scoreGrid()`（阅读时约 498–524 行）却用 `ch !== '.' && ch !== '?'` 计数，会把 null 空格计成棋子。

要求：

- 明确内部格子统一为 EMPTY / PIECE / UNKNOWN 三态，FEN 字符层明确空格表示；跨模块转换只在明确边界进行。
- 计数只接受七种合法棋子字母及其大小写，例如正向检查 `/^[RNBAKCPrnbakcp]$/`；不能用“不是两个排除值”替代校验。
- 检查 `consistency.charsOf()`、时序融合、评测、伪标签、采集器和打印工具的空格约定；兼容输入中的 null 和点号时集中转换。
- 无图像、无检测器、布局不可解析、全部识别失败必须返回失败原因，不能进入最优候选或成功率分母。

验收用例：

- 开局：32 PIECE、58 EMPTY、0 UNKNOWN，总数 90。
- 合法残局：分别含 2、4、8 枚棋子，其余为 EMPTY；计数、FEN 和定位接受规则一致。
- 含 1 个 UNKNOWN 的 90 格数组：三种状态数量准确，不把 UNKNOWN 算为空或棋子。
- 不合法字符、长度不足、全空棋盘、缺将、布局解析失败：有明确拒绝原因。

### 3.2 删除棋子数量的硬门槛

当前 `pickGrid()`（约 573 行）要求 `pieces >= 24`；代价函数默认期望 28 枚。这不适用于合法残局。

要求：

- 不以“至少 24 枚”或“至少 9 枚”作为通用棋盘有效性条件。
- 首次定位联合检查网格范围、检测框残差、图像棋盘证据、可见将帅及棋规；少子残局信息不足时拒绝并提示人工校准，不能伪造成功。
- 已有可信局面时，可把前一局面子力数作为软约束，允许合法吃子造成变化；会话重置后不得继承旧先验。
- 两套 K40 坐标只能作为候选种子；游戏布局、旋转、缩放改变后重新验证，不能声称已适配所有布局。

## 4. P1：拆开耗时，优化几何搜索

### 4.1 先消除反复加载

`scoreGrid()` 目前调用 `run()` 时没有传入共享 detector。`run()` 支持注入，但未注入时会 load，结束时 close。因此“171 次推理 / 19.8 秒”同时包含重复模型加载和其他处理，不足以定位推理瓶颈。

要求：

- 每次校准任务只加载一次检测器，候选评分注入同一个检测器和实际 detectorRequest。
- `scoreGrid()` 保留调用方的模型路径、标签、方形或矩形输入尺寸、阈值及必要选项，不能在构造临时 opts 时丢失。
- 明确所有权：调用方传入的 detector 不由内部关闭；内部创建的 detector 在 finally 关闭，错误、取消和早退均不泄漏。
- 在模型切换或线程间传递时遵守宿主对象线程约束，不跨线程分享原生检测器句柄。

### 4.2 将几何运算与重跑检测分离

- 对同一帧，先在足够覆盖候选棋盘的固定区域做检测，缓存原图坐标的框中心、类别和分数。
- 尝试不同 origin/step 时，优先对缓存框做格点分配、残差和冲突评分；只有裁剪范围明显改变、证据不足时再推理。
- 不把“修复后未知格为 0”当作唯一早停条件。联合报告未修复残差、出界、冲突、实际修复动作和校准可信度。
- 几何搜索在初始化、UI 布局改变或恢复时执行；稳定对局复用几何，但每帧检查漂移证据。
- 先比较现有搜索、共享 detector 搜索、缓存框几何搜索三种实现，选择确实稳定更快的方案，不先引入复杂新模型。

性能报告必须分列：捕获、模型加载、预处理、DNN 推理、格点搜索、像素判色、修复、总耗时；包括冷启动、热运行 p50/p95、候选数、实际推理次数和失败率。取消等待有上限。使用同一批帧对比，不预先承诺 FPS。

## 7. P2：标签与微调先做审计，再开实验

### 7.1 修正失败归因

“约 3% 兵种错误经 ×41 增强变成约 1/4 错框”没有足够证据。同同比例扩增不会自然改变错误比例。报告中应区分已观察到的退化、已确认的错标签、尚待验证的因果解释。

先核对：

- 七类 class ID 与标签文件顺序、原图和增强图的坐标变换、裁剪后框截断、letterbox、宽高归一化。
- 真正错框数 / 总框数、漏标、重复标、错色对兵种标签的影响，以及各类增强是否偏向错样本。
- 初始化 checkpoint 的来源、实际训练参数、冻结层效果、模型输入输出契约、导出前后同图预测一致性。
- 800 张和 22,958 张的 mAP 比较是否同初始化、同验证集和训练预算；相同数值不能直接证明“数据量已经饱和”。

### 7.2 伪标签使用边界

- 投票标签保存模型来源、原始分数、票数、像素结果、规则结果和人工状态。
- “仓内票必须在多数中”作为可比较的过滤策略，不能自动认定无偏正确。
- 含不确定棋子的图像不允许直接作为无标签背景训练。优先完整人工标注或排除该样本。
- 用空格贴片覆盖 UNKNOWN 的方式会改变棋盘纹理与几何上下文，只能列为单独实验，不作为默认真值修复。

### 7.3 实验矩阵和替换规则

依次比较：现役权重原始流水线、现役权重修复后的流水线、验证集阈值调整、几何/阵营/时序消错、人工干净标签保守微调。每轮只改一个主要因素。

`freeze=10、lr=1e-5、3 epochs` 是候选配方，不保证提升；核查所用版本实际冻结对象和可训练参数。按验证集选阈值与 checkpoint，独立测试集冻结后只用于最终比较，不反复用其挑模型。

新模型替换必须同时考虑整盘布局正确率、可信覆盖率、占用格错误、各类短板、域内回归和真实端到端耗时。微小百分点差异证据不足时保留现役模型。每个候选保存模型 SHA256、来源 checkpoint、训练清单、参数、评测输入清单和原始结果；默认资产不能因训练脚本成功就被覆盖。

## 8. P2/P3：推理侧算法试验

保留 160 ROI 作为基线，优先改进真实证据利用：

1. 阵营判色：采样原图有效笔画，排除木纹、高光、棋盘线和选中框。对比现有 RGB 与候选颜色特征，在验证集确定阈值，保留 UNKNOWN。棋规翻色单独记录，不能当作像素已经判对。
2. 时序：仅融合真实新帧、同会话同几何且兼容的局面；动画和走子发生时重置或分段，不把重复旧帧算成多个投票。
3. 合法后继：从上一可信局面枚举有限合法走法，与当前视觉证据评分；不得把引擎预测当作观察真值。候选差距不足或证据矛盾时暂停并恢复。
4. 疑点复核：原图高分辨率复看可疑格先作为对照。现有整盘 YOLO 直接裁成单格可能分布失配，不能假设必然提高精度。必要时训练专用分类器并开发有明确输出契约的分类 API。
5. 六列检测输出仅包含最终框、分数和类别，不能从中虚构完整七类概率或 EMPTY 概率；需要分布时明确扩展模型输出或独立分类器。
6. 矩形 160×320 和 320 方形作为同测试集对照；报告捕获加推理加确认的总延迟，不能只用 DNN FPS 代表自动走棋速度。
