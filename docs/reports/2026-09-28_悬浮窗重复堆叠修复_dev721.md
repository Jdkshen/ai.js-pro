# 悬浮窗重复堆叠：取证与修复

2026-09-28，K40（cccc62c7）。用户现场截图可见多条同款面板；`dumpsys window` 显示多组属于 `com.jdkshen.aijspro` 的悬浮窗，面板总线状态 `running=false`。取证后仅停止 AI.js Pro，游戏仍留在前台，重复窗口归零。

## 原因

1. 面板默认每 60 分钟用 `engines.execScriptFile` 启动一个新实例。旧实例只清自身心跳和部分定时器，假设运行时会回收脚本；它可能继续存活，旧窗口因此累积。退出钩子也漏掉独立日志窗。
2. 主页面按钮原有重复启动检查，但直接运行资源脚本、快捷方式和外部 Intent 绕过按钮检查。
3. 初版修复试图用 `engines.all()` 枚举其他实例。真机 QuickJS 实测该 API 只暴露当前脚本，且脚本引擎 ID 是 `.id` 属性、不是 `.getId()` 方法。该初版 dev-720 没有通过真机重复启动验证，已由最终 dev-721 替代。

## 最终修复

- 面板脚本创建窗口前读取跨脚本共享的短期占用记录；活动面板每秒续约，重复启动直接结束，异常结束后记录会过期。
- 自动重载用短期交接令牌允许新实例接管；旧实例显式关闭主窗、收起窗、日志窗和画板，再调用脚本退出。退出钩子独立逐个清理所有窗口，不因一个清理失败跳过其余窗口。
- 自动重载后旧实例不能继续续约，新实例独占面板。
