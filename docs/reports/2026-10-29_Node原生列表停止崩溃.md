# Node 原生列表停止崩溃（dev-1284 / Android 36）

## 用户现场

用户确认在**停止脚本**时发生崩溃。堆栈为 `RecyclerView.validateViewHolderForOffsetPosition` → `GridLayoutManager` → `ViewPager`，界面为 `NodeUiLocalActivity$Slot1`，网格 ID 为 `grid`，Adapter 为 `MyAdapter`。这些类名、结构与内置 Node「使用 Android 原生界面」M3 示例一致。

这是 Java 层列表状态异常；和此前 native 图形栈 destroyed mutex 崩溃是不同的问题。

## 底层时序缺口

`Node24Service.Job.cancel()` 原先先执行 `beginCallbackShutdown()`，再取消 native Node，最后异步清理界面。`beginCallbackShutdown()` 立即禁止生成类回调；`getItemCount()` 失去 Node 回调后返回基本类型默认值 0。与此同时，`NodeUiLocalSession.closeOpening()` 只异步请求 Activity.finish，旧 RecyclerView 及旧 ViewHolder 仍可能参与布局。

这样，固定不变的示例数据也可能被 Java 布局端观察成“先有项目，随后突然为 0，且没有更新通知”，符合现场位置不一致的错误。原系统的细节触发时序仍需 Android 36 现场复测；不能仅凭代码分析声称已在测试手机复现同一崩溃。

## 本轮修改

- 在关闭 Node 回调之前，等待 Android 界面线程清理本地 Node UI。
- 递归解绑旧界面中的 RecyclerView Adapter、停止滚动，再用空容器替换旧 Activity 内容，最后关闭 Activity。覆盖 ViewPager 中已创建的页面。
- UI 清理后才发布回调关闭状态，继续沿用已有 native 取消和进程回收机制。
- 清理等待上限 2 秒，异常保留日志。没有修改 RecyclerView 框架，也没有用 catch 吞掉用户提供的位置异常。
- 新增设备用例 `modules/engine/src/test/device/node24-recycler-stop.js`：固定 120 项网格持续滚动和请求布局，停止时应记录 `STOP_GRID_DETACHED`，用于确认 Adapter 在 Java→Node 回调仍可用时解绑。
