# Node M3 四项底层优化（2026-10-24）

## 范围与实现

按用户确认的四个方向独立实现，复用本仓库和公开库接口。高级版反编译结果只用于判断调用路径，没有复制其实现。

| 方向 | 本轮落地 |
| --- | --- |
| Java 桥 | Node 24 自带 V8 新增 `__ajsJavaFastCall`，JNI 缓存入口方法 ID、包装类型和转换方法；宿主分配每次脚本内稳定的成员 ID，复用已有对象句柄。基本类型/null/对象引用的同步方法调用不再构建或解析 JSON。每次仍按参数选择重载，无参方法可复用已解析 Method。 |
| 动态类 | 原生成器提取共享 GenerationPlan；直接生成 Smali，经 smali/dexlib2 在内存组装 DEX，Android 8+ 用 InMemoryDexClassLoader 加载，跳过 Classfile/JAR/dx/D8。保留异步 defineClass、生成类加载器链和 Dex 生命周期管理。普通用户 JAR 的 D8 路径保留。 |
| 图片 | `NodeUiImageLoader` 接入 Glide 4.8，使用内存/磁盘缓存、按 View 尺寸解码和 BitmapPool；替换请求、关闭/重建会话、超时/中断会取消对应 Target，禁止过期图片覆盖新图。资源由 Glide 管理。 |
| 布局 | 继续使用已有原生 LayoutInflater/编译 XML 和批量 inflate；修正会话加载器初始化被清空及后续 defineClass 后的加载器更新，单个和批量 XML 都读取当前脚本最新生成类加载器。 |

## 保持的约定与边界

V8 始终在 Node 线程运行。类型化调用复用原生回调调度队列，嵌套 Java 调用仍回原 Java 回调线程执行，UI 对象调用沿用真正的 Android 主线程切换和同步返回值。

类型化通道目前覆盖同步方法的 scalar/null/已有 Java 对象引用参数；数组、普通 JS map、Class 参数、监听器以及显式异步/UI 线程模式继续使用原转换路径。旧原生桥或测试宿主没有新入口时自动使用旧协议。不宣称所有调用都已去掉 JSON。

成员 ID 绑定 Class 身份与静态/实例模式，结果和接收对象不缓存；上限 4096，溢出回退原协议，已发出的 ID 保持有效，脚本结束统一清理。加载另一个 Dex 不会把旧 ID 错绑到新 Class。

本轮是 Node 运行层优化，没有更换宿主 Flutter 架构。高级版 M3 框架和静态调用路径的对比见同日《高级版M3框架与加载路径对比》；没有高级版真机启动耗时对照，不能宣称已经与高级版同速。

## 依赖与构建

新增引擎依赖 `org.smali:smali:2.5.2`、`com.github.bumptech.glide:glide:4.8.0`。Smali 的内存组装调用参照[公开实现](https://github.com/JesusFreke/smali/blob/v2.5.2/smali/src/main/java/org/jf/smali/Smali.java)；Glide 目标清理遵循其 [RequestManager 生命周期接口](https://github.com/bumptech/glide/blob/v4.8.0/library/src/main/java/com/bumptech/glide/RequestManager.java)。

旧 Node 源码目录已经不存在，本轮从 Node 官方取回精确的 24.22.0 公共头文件，校验官方 SHASUMS256 后按构建脚本所需目录布局放置，文件内容未修改；ABI 定义仍使用已部署 Android core 配套的 `config.gypi` 和 `node_base.target.mk`。头文件包 SHA-256：`00e9f08b9057f9f5428387a5ffd496e53f274565b40b144b7ba876700755352a`。未替换 libnode 或 libc++。

DP 独立 SDK 任务分别负责直接 DEX 生成及图片加载器，主助手负责 JNI/脚本桥、布局会话、接入、复核和真机验证；任务不涉及现有 DP 桌面聊天。
