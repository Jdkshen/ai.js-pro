# Node UI 关闭后误报错修复（task-185）

日期：2026-10-20。执行：t1-native-services。验证机：K40（cccc62c7，dev-1132 待填）。

## 1. 问题

t2 dev-1131 必现：Node UI（colored-button / NodeAndroidUI）按 BACK 关闭后 ~2.6s 弹「错误/脚本运行失败：java.io.IOException: Node24 service disconnected」+ E 堆栈；纯 Node 单文件正常结束不报错。

## 2. 根因（K40 dev-1131 复现日志）

```
00:23:42.793 NodeUiActivity: C-BACK pressed
00:23:42.795 NodeUiBridgeService: C-BACK: cancel Node job id=...
00:23:42.809 Node24Service: execute returned id=... exitCode=1 cancelled=true uiCloseCancel=false
00:23:42.809 Node24Service: post-execute ... nodeUiActivity=true ...
00:23:45.305 Node24Service: cancel watchdog: force halt id=... pool=true finished=false
00:23:45.376 RunnableJSExecution: ScriptException: java.io.IOException: Node24 service disconnected
```

- BACK → NodeUiBridgeService 广播 cancel → Node24Service Job.cancel()；execute 很快以 cancelled=true 返回；
- 返回后还要执行 closeUiAfterExecution（NodeUiActivity/Binder 清理）、bridge.close 等；此时 Job.finished 仍为 false；
- 池进程取消的 watchdog 2.5s 到点，看到 finished=false 就 force halt 杀进程；
- :script 侧 Node24Client 在结果到达前失联 → IOException: Node24 service disconnected → ScriptException → ScriptHostService 报 102 ERROR → PocScriptHost 弹错误 Toast。

## 3. 实现

- Node24Service.Job 新增 volatile executeReturned：execute 返回/抛出的瞬间置 true；
- 池进程 cancel watchdog：若 finished || executeReturned 则不再 kill（清理完成后自然回复 CANCELLED，进程保持 warm）；legacy :node24 行为不变；
- 结果先回复再清理：collect-result 后立即 reply(result)（附带 elapsedMillis/cancelled 合并），避免 UI/Binder 清理耗时导致客户端还在等结果；外层兜底仍保证未回复路径会 reply 一次；
- :script 侧无需改：CANCELLED 已由 Node24JavaScriptEngine 映射为 ScriptInterruptedException → ScriptHostService 固定「脚本已停止」102，PocScriptHost 本来就静默处理；
- 真实异常（脚本抛错/引擎崩溃）仍走 ERROR，不受影响。

### 结论

用户主动关闭 Node UI = 静默正常结束（CANCELLED 路径），不再误报脚本错误；纯 Node 正常结束 SUCCESS；真实异常仍报错。
## 6. 限制

1. 池进程取消后不再杀进程（task-175/181 设计：保持 warm 复用），由结果自然结束；若清理永久卡死，客户端仍有自己的超时兜底；
2. legacy :node24 进程仍保留 800ms/1.5s 硬兜底（旧行为不变）。
