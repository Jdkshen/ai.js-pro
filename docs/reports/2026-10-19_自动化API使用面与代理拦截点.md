# 2026-10-19 自动化 API 使用面盘点 + :script 代理拦截点 spec（Phase1 P1-A）

> 目标：为 IAutomationHost 代理落地提供“改哪里、覆盖哪些 API”的精确清单。
> 契约（已定稿，不再改）：`apps/app/src/main/aidl/com/stardust/autojs/host/IAutomationHost.aidl`（17 个方法）、`docs/reports/2026-10-19_IAutomationHost契约与JSON协议.md`。
> 本文件只写 spec，不改代码、不跑 gradle/adb。
> 证据来源：
> - 示例脚本语料：本仓库 `samples/` + `apps/app/src/main/assets/sample/`（528 个 js，含 Rhino/QuickJS/Node 样例、象棋工程）；对照 Pro 官方示例 `.artifacts/pro-samples/`（205 个 js）。
> - 引擎实现：`modules/engine`（SimpleActionAutomator/UiSelector/AccessibilityBridge/Images/QuickJsHostBridge/Rhino 全局 JS 层）、`modules/automator`（UiGlobalSelector/UiObject/GlobalActionAutomator）。
> - 现状：`apps/app/src/flutterpoc/.../scriptproc/ScriptHostService.java`（Phase1-B，:script 已能跑脚本，但 `:script 里 auto/click/selector 仍不可用`，见其类注释 line 60-61）。

## 0. 结论（TL;DR）

1. **代理要覆盖的“面”比节点树小**：示例里出现最多的是 **截图/图像**（captureScreen+requestScreenCapture：本仓库 106 次/91 文件，Pro 示例 30 次/29 文件）与 **坐标类操作**（click/press/longClick/swipe/gesture）和 **少量节点操作**（.click/.setText/.find/.exists）。IAutomationHost 的 17 个方法足以覆盖 **≥85%（Pro 示例≥95%）** 的自动化调用面。
2. 引擎侧有 **两层** 实现，拦截点不同：
   - **Rhino**：全局函数由 JS 层 `init.js → __globals__/__automator__/__selector__/__images__` 动态生成，**在 JS 层替换**最省事（新增 3 个 `__*_remote__.js`，按 runtime property 分流）；
   - **QuickJS**：全局函数（`click/press/longClick/swipe/gesture/back/home/...`、selector/auto 子集、截图）每一步都收敛到 **Java 类 `QuickJsHostBridge`** 的方法（click@852、globalAction@868、selectorCreate@5854、autoCall@5863、automatorCall@5898、requestScreenCapture@904…），**在 Java 方法入口按 remote 开关分流**即可，native cpp 不用改。
3. 注入位置：`apps/app/src/main/java/com/jdkshen/aijspro/autojs/AutoJs.java:186 createRuntime()`（本已是宿主覆盖点，现有 `putProperty("class.settings", ...)` 就在 188），追加 `runtime.putProperty("automationHost", client)`；进程判断用现有 `App.kt:100,115-119 isNativeIsolationProcess()`（已把 `:script` 算进隔离进程）或新增 `Processes.isScriptProcess()` 等价物。
4. auto 门控默认关：`:script` 侧读 Pref（建议 key `automation_host_enabled`，默认 false）→ 关时保持现状（:script 里无障碍 API 不可用），开时才装 remote 层；主进程 AutomationHostService 由 task-19 实现、:script 客户端 `AutomationHostClient` 由 task-20 实现。
5. 主要风险集中在：主进程无障碍未就绪/超时（5s）、截图权限、**节点序号在 findNodes→clickNode 之间失效**、坐标缩放、以及契约缺口（quickSettings/powerDialog/splitScreen、currentPackage/currentActivity、input、scroll 动作、auto.service 没有对应 AIDL 方法）——这些列入 P1.1/P1.2 或明确降级行为。

## 2. 每个 API 的引擎实现与无障碍依赖程度

依赖等级定义：
- **A 纯坐标**：只需要“执行手势/全局动作”，不需要节点树（主进程无障碍服务 dispatchGesture/performGlobalAction 即可）；
- **B 需要节点树**：必须拿到 AccessibilityNodeInfo 树做搜索/动作（findNodes/clickNode/…）；
- **C 需要无障碍实例/系统权限**：无障碍 Service 单例、当前包/Activity、截图权限、通知监听等。

## 4. :script 侧拦截点设计（RemoteAutomationBridge / RemoteAutomator 挂载方案）

### 4.1 总体结构（新增类，建议放 `modules/engine/src/main/java/com/stardust/autojs/automation/remote/`，或就近放 `core/accessibility`）

    AutomationHostClient (task-20，:script 侧 Binder 客户端)
      - bindService(ComponentName("com.jdkshen.aijspro", "com.jdkshen.aijspro.automation.AutomationHostService"))
      - linkToDeath + 重连 + isConnected()
      - 把 17 个 AIDL 方法封装成同步 Java API（含 selectorJson / strokesJson 序列化）
    RemoteAutomation (门面，挂在 runtime property "automationHost" 上)
      - isReady()/waitForReady(timeout)/isAccessibilityEnabled()
      - click/longClick/press/swipe/gesture/back/home/recents/notifications
      - select(selectorJson)/find(selectorJson)/getInfo(...)/clickNode/.../setTextNode
      - screenshot(path)
    RemoteUiObject / RemoteUiSelector（JS 可见代理，Rhino/QuickJS 各一层薄封装）
      - 属性：text/desc/id/className/packageName/bounds/clickable/enabled/depth
      - 动作：click/longClick/setText
      - 查找：find/findOne/exists（:script 侧对 findNodes 结果做二次过滤）

### 4.2 运行进程判断 + 开关

- 现有判断：`apps/app/src/main/java/com/jdkshen/aijspro/App.kt:100`（`if (isNativeIsolationProcess())`）与 `App.kt:115-119`（注释明确写“Phase0 :native 或 Phase1 :script”）。建议抽成公开工具（如 `Processes.isScriptProcess()` / `App.isIsolationProcess()`）供 AutoJs/ScriptHostService 共用；引擎模块内可用 `ActivityThread.currentProcessName()` 兜底，避免跨模块依赖 app。
- 开关：新增 Pref（建议 key `automation_host_enabled`，默认 false）：
  - 主进程设置页写 Pref（同 app SharedPreferences，:script 进程可读）；
  - 不用 IScriptHost 消息传（IScriptHost 协议已定稿，避免改 task-15/16/17 落地）；
  - :script 侧在 `App.onCreate` / `AutoJs.initInstance`（仅 :script 分支）读一次；关闭时 AutomationHostClient 不 bind、runtime 不注入 property，行为与现状一致。
- 绑定时机：:script 的 App.onCreate（隔离进程分支）里 `AutomationHostClient.ensureBound(context)`；主进程 AutomationHostService 未就绪时 isReady=false，脚本侧先阻塞在 auto.waitFor / 首次调用超时（见 §5）。

### 4.3 Rhino 侧拦截点（JS 层替换，推荐）

为什么在 JS 层：Rhino 全局函数全部由 `modules/engine/src/main/assets/init.js` 组装：
- `init.js:111 require("__globals__")(runtime, global)`（toast/sleep/currentPackage 等）；
- `init.js:116-125` 自动模块循环 `scope[m] = require('__' + m + '__')(scope.runtime, scope)`（含 __automator__/__selector__/__images__/__RootAutomator__ 等）；
- `__automator__.js:215` `global.auto = auto`；`:217 __asGlobal__(runtime.automator, ['back','home','powerDialog','notifications','quickSettings','recents','splitScreen'])`；`:218 __asGlobal__(automator, ['click','longClick','press','swipe','gesture','gestures','gestureAsync','gesturesAsync','scrollDown','scrollUp','input','setText'])`；
- `__selector__.js:4-9` 把 `runtime.selector()` 的方法（Java `UiSelector.java:65` + `UiGlobalSelector.kt:47-432`）逐个挂全局；
- `__images__.js:104` 把 runtime.images 的 captureScreen/read/copy/load/clip/pixel 挂全局；`:169-223` 是 requestScreenCapture/captureScreen 实现。

改法（新增文件，不动原模块逻辑；代码由 task-20 落地）：
1. 新增 `modules/engine/src/main/assets/modules/__automator_remote__.js`：导出 `function(runtime, global)`；若 `runtime.getProperty("automationHost") == null` 直接 return；否则覆盖全局 click/longClick/press/swipe/gesture/gestureAsync/gestures/gesturesAsync/scrollDown/scrollUp/setText/input + back/home/recents/notifications/quickSettings/powerDialog/splitScreen + auto.waitFor/auto.service(null)/auto.root/auto.rootInActiveWindow + automator.* 同名别名（与 __automator__.js:217-218 对齐）。
2. 新增 `__selector_remote__.js`：远程版 selector() 与全部全局过滤函数（text/id/desc/className/packageName/bounds/clickable/...）；返回 JS 侧 RemoteUiSelector（链式收集条件，find/findOne/untilFind/exists/waitFor 时序列化 selectorJson 调 host，再把结果包成 RemoteUiObject）。
3. 新增 `__images_remote__.js`：覆盖 captureScreen/images.captureScreen/requestScreenCapture；request 直接 resolve；capture -> `runtime.getProperty("automationHost").screenshot(tempPath)` -> `images.read(path)`，失败抛 `Error("截图失败：主进程未授权/超时")`。
4. 在 `init.js` 模块循环之后（约 init.js:126）追加 3 行：
   `if (runtime.getProperty("automationHost")) { require('__automator_remote__')(runtime, global); require('__selector_remote__')(runtime, global); require('__images_remote__')(runtime, global); }`
   （或改三个原模块末尾做同样判断——二选一，第一批建议只改 init.js 并新增 3 个文件，回滚容易。）
5. Java 注入：`apps/app/src/main/java/com/jdkshen/aijspro/autojs/AutoJs.java:186-197 createRuntime()` 追加 `runtime.putProperty("automationHost", automationHostClient)`（仅 :script 且 Pref 开启；与现有 `putProperty("class.settings", ...)` 同模式）。

## 5. 风险与降级行为（建议 task-19/20 按此实现并写测试）

| 风险 | 场景 | 建议降级/处理 | 验收 |
| --- | --- | --- | --- |
| 主进程无障碍未就绪 | 脚本启动时主进程无障碍未连接（或用户没开） | auto.waitFor()：先查 isAccessibilityServiceEnabled()（不需要连上），再轮询 isReady()（默认 10s，可 Pref 配）；超时抛清晰错误 `Error("自动化宿主未就绪：请先在主进程开启无障碍")`；坐标类 API 未就绪时返回 false + console.warn（不抛，避免脚本直接崩） | 无障碍开/关两种情况 |
| AIDL 超时（契约 5s） | Binder 回调慢/主进程主线程卡 | client 层再包 6s 超时 -> false/空；findNodes 返回空数组；连续 N 次超时后 isReady() 降为 false 并触发重绑 | 注入 sleep 的假 host |
| 节点路径/序号失效（find->click 之间树变化） | 点击前树刷新导致 selector+index 匹配到别的节点 | 动作前用同一 selectorJson+index 重新匹配（契约语义）；失败重试 1 次（重新 findNodes）；仍失败返回 false + console.warn；禁止长期持有 path 做动作（契约没有按 path 动作的方法） | 点击期间 mock 树变化 |
| 坐标密度/缩放 | 脚本用逻辑坐标 vs 设备真实像素 | 约定 AIDL 坐标一律设备像素；:script 侧若脚本经 setScreenMetrics 指定逻辑分辨率，由 RemoteAutomation 负责换算（与本地 SimpleActionAutomator.setScreenMetrics 同规则），host 不再二次缩放；主机分辨率可用 getLatestNodeDump 的 bounds 或 host 内部 DisplayMetrics | 1080p/2K 两种密度 |
| 截图权限 | 主进程没有 MediaProjection 授权 / Android 14 限制 | 契约 screenshot 返回空串 -> :script 抛 `Error("截图失败：请在主进程授权截图")`；requestScreenCapture() 在 remote 模式直接 resolve（不弹系统框），真正失败在第一次 capture 时暴露；建议 task-19 在 host 首次截图时懒请求主进程 Activity 授权 | 未授权/已授权 |
| 主进程崩溃/重启 | :script 与主进程 Binder 断 | client linkToDeath -> 重绑；重绑期间 isReady()=false，执行中的节点/坐标调用返回 false；脚本可 auto.waitFor() 等恢复；主进程 AutomationHostService onBind 返回同一宿主实例（无状态，天然可重建） | kill 主进程后脚本降级不崩 |
| 权限/安全 | exported=false、同 uid；外部进程不能调 | host onBind 里校验 Binder.getCallingUid()==Process.myUid()（双保险）；:script 只信任固定 ComponentName | 代码审查 |
| 性能 | 每次 selector 操作都拉整棵树 | getLatestNodeDump 在 client 侧做短 TTL 缓存（150-300ms）；findNodes 优先用 dump 本地过滤或由 task-19 host 侧过滤；waitFor/untilFind 轮询间隔 >=100ms | findOne 循环 100 次耗时 |
| 线程 | AIDL 同步调用阻塞脚本线程（契约允许 5s） | Rhino 侧与本地 automator 一致（本地也阻塞）；QuickJS 侧注意不要在主 Looper 线程长阻塞（同现有行为）；gestureAsync 第一批不做真异步，返回 true 即可 | 冒烟 |

## 附录 B：selectorJson 序列化约定（:script 侧实现建议）

- RemoteUiSelector 内部用 LinkedHashMap 累积条件，find/findOne/exists/waitFor 时 `new JSONObject(map).toString()` 传给 host；
- 字符串精确->text，包含->textContains，前缀->textStartsWith，正则->textMatches；desc/descContains 同理；id 精确；className/packageName 精确；bounds 用 `{"left":l,"top":t,"right":r,"bottom":b}`；布尔键 clickable/enabled/scrollable；depth/index 整数；
- 契约没有的过滤条件（descStartsWith/idContains/classNameContains/boundsInside/row/column/visibleToUser 等）不塞进 JSON：host 返回结果后在 :script 侧用本地条件二次过滤（字段不足时降级为忽略 + console.warn 一次）；
- waitFor/untilFind = 轮询 findNodes（默认 1s 超时、100ms 间隔，可传参），期间任一次 isReady()==false 即抛未就绪错误。

## 附录 C：需要 Lead 拍板/跨任务协作的点

1. 契约缺口（quickSettings/powerDialog/splitScreen、currentActivity、input、节点 scroll、auto.setMode/setFlags）：按契约冻结原则第一批全部降级；若用户反馈高频再走契约 v2（新增方法只能追加，不能改事务序号）。
2. currentPackage 的近似实现（根节点 packageName）在“通知栏/系统界面在最上层”时会不准，P1 上线说明里要写明限制。
3. auto 门控 Pref 的 key/默认值：建议 `automation_host_enabled=false`，由主进程设置页控制，:script 只读；若 Phase1 验收要求默认开启再改默认值（一行）。
4. 截图权限的请求归属：建议主进程 AutomationHostService 首次 screenshot 时懒请求 MediaProjection（弹主进程 Activity），:script 侧不弹任何系统框；若希望“主进程启动时就请求”，task-19 需在设置页/启动流程加一步。
5. 坐标缩放约定：本 spec 采用“AIDL 坐标=设备像素，:script 侧按 ScreenMetrics 换算”，与本地 SimpleActionAutomator.setScreenMetrics 一致；task-19 实现时不要再次 scale（否则 2 倍误差）。
