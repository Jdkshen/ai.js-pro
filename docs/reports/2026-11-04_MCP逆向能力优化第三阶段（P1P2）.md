## 三、测试与构建

- MCP 单测：**424 项全过**（上阶段 366 → +58）：`McpAppTraceTest` 18、`ToolkitDecompileViewTest` 12、`ToolkitFridaSessionTest` 9、`ToolkitNativeAnalysisTest` 8、`ToolkitTransformsTest` 6、`ToolkitEvidenceExportTest` 5。
- 构建门：R8、ELF 16KB、平台阴影守卫、Retrofit 签名检查通过。
- 修过两处集成缺陷（都在编译/真机阶段抓到）：① `listTools()` 里 app_trace 工具插入位置与公开目录顺序不一致，导致 MCP 启动自检报「工具定义与公开目录不一致」而停服；② 同步类逆向工具（Frida 会话 / native 分析）未走 `runtime.reverse`，落进了 APK 工具的 workspaceId 分支。
- 发布：LAN -> `dev-1335`；仅 LAN、未 push、未建 Release。

## 四、未做 / 已知边界

1. **§10 持久 attach 未实现**：`frida_session_open` 只登记会话与消息通道，`attached=false` 如实返回；真实执行仍走 `frida_eval`。
2. **§7 r2 命令不执行**：只生成 `af/afn/wx` 等命令文本（`executed=false`）；noreturn 目前只能以注释形式携带。
3. **§9 日志可见性**：普通应用 UID 只能拿到有限 logcat；无证据时按 `unknown` + `uncertainty` 返回，不改任何系统设置。
4. **§12 二进制文件不做内容脱敏**：只在清单里标注 `sensitiveHits`；文本文件默认替换为脱敏副本。
5. **§11 不声称算法/密钥已被证实**：`verified=true` 只代表“已请求的断言全部通过”。
6. 其它历史边界仍在：任务 owner 非安全边界、无定时 GC、`hostExecutable` 只按文件存在性判断、Shizuku 在 `:tools` 进程未真机验证。
