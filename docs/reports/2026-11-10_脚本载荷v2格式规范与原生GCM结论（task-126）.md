## 一、v2 格式规范（定稿）

```
偏移    长度  内容
0..5    6    魔数 77 01 17 7F 12 12（沿用 v1）
6..7    2    flags：低字节=执行模式，高字节=载荷类型（0/1/2/3）
8       1    版本 = 0x02   ← 旧产物此字节不是 0x02
9..11   3    保留 = 00 00 00（**必须为 0，读到非 0 即拒绝**）
12..23  12   随机 GCM IV（**每个文件都不同，绝不复用**）
24..    密文 ‖ 16 字节 GCM tag（tag 长度 128 位）
```

- **AAD = 偏移 0..11 的 12 字节头**（魔数 + flags + 版本 + 保留）⇒ 头部任何一位被改都会导致完整性校验失败（而不是被静默忽略）。
- **密钥（真 256 位）**：`key = SHA-256("aijspro-script-key-v2|包名|盐|证书指纹")`，取**64 个 hex 字符 → 十六进制解码 = 真 32 字节**（对比 v1：只取前 32 个 hex 字符、当文本用 ⇒ 有效熵 ≈128 位）。
- **算法**：`AES/GCM/NoPadding`，`GCMParameterSpec(128, iv)`，`SecretKeySpec(key, "AES")`（JCE 标准，无需第三方库）。
- 字段来源：包名/盐/证书指纹来自产物自带的 `project.json`（`packageName` / `scriptSalt` / `signatureFingerprint`），盐仍是 16 字节随机（32 hex）。

### 旧格式如何被识别与拒绝（点名，不静默）

| 情况 | 判据 | 行为 |
|---|---|---|
| 旧产物（v1） | 魔数匹配但**第 9 字节 ≠ 0x02** | **点名错误**：`旧加密方案已下线（载荷版本字节不是 0x02），请用新版打包器重新打包该工程。`（**不尝试用旧算法解开、不静默失败**） |
| 本产品之外的载荷 | 魔数不匹配 | 具名错误：`脚本载荷魔数不匹配（不是本产品的加密载荷）` |
| 太短 | 长度 ≤ 24 | 具名错误：`脚本载荷太短：N` |
| v2 保留字节非 0 | 偏移 9..11 任一非 0 | 具名错误：`v2 保留字节必须为 0（位置 i）` |
| 密文/tag/IV/头部被篡改，或密钥不对 | GCM tag 不匹配 | 具名错误：`脚本载荷完整性校验失败（GCM tag 不匹配：密文/头部被篡改，或密钥不对——包名/盐/证书指纹不匹配）`（**可读**，不是裸 `AEADBadTagException`） |

## 二、`script_crypto.c` 能否 GCM —— **明确结论：不能**

取证方法：对 `modules/engine/src/main/cpp/script_crypto.c`（732 行）做原语命中文数统计 + 阅读实现：

| 原语/关键词 | 命中数 |
|---|---|
| `gcm` / `GCM` | **0** |
| `ghash` / `GHASH` | **0** |
| `galois`（不分大小写） | **0** |
| `ctr` / `CTR` | **0** |
| `cbc` / `CBC` | 6 |
| `tag` / `aad` | 0 |

- 该文件自实现的是：**SHA-256**（`:25-124`，含 `sha256_compress`）与 **AES-256 解密**（`:191 aes256_expand_key` / `:219 add_round_key` / `:230 inv_shift_rows` / `:241 inv_mix_columns` / `:253 aes256_decrypt_block`），以及 **CBC** 组合（`:277`）。
- 它的载荷装载是**尾部 footer** 结构：`[库内容][脚本载荷(密文)][magic "AIJSPv1\0"][载荷长度小端 uint32][SHA-256(载荷)]`（`:433-438`、`kFooterMagic` `:435`）。
- ⇒ **没有 GHASH/CTR 等 GCM 所需构造**，自己加 GCM 等于新写一套经过验证的密码学实现 ⇒ **按你的要求不硬上**。

### 因此 v2 的落地方式（定稿，代码待 dev-1472 后动）

1. **v2 只走 JVM 路径**（`ScriptEncryption`，JCE `AES/GCM/NoPadding`）；打包端同样用 JVM 侧实现写 v2 载荷。
2. **原生只认 v1**：产物是 v2 时，运行端**不得**调用 `setHardenedParams(...)`（否则会把 v2 载荷交给只懂 v1 的原生路径）；原生若收到第 9 字节 ≠ 0x02 之外的 v2 载荷，必须回**点名错误** `原生解密库不支持 v2（AES-256-GCM）：v2 载荷必须走 JVM 路径；原生只认 v1。`
3. **密钥硬化两端同时改**（v2 是 JVM-only，所以「两端」= **打包端 JVM 派生** 与 **运行端 JVM 派生** 必须逐字一致；原生侧**不需要**跟着改，因为它不再参与 v2）：`SHA-256("aijspro-script-key-v2|包名|盐|指纹")` 的 64 hex → 解码 32 字节。
4. **跨端一致性断言**：固定一组 `(包名, 盐, 指纹)` 的 key 值写进测试（C 侧若将来要参与，可比对同一锚点）。
