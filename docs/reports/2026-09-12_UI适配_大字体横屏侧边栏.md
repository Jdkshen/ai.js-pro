## 0. 先看这三条结论

1. **侧边栏抽屉宽度以前是死代码。** `MiuixDrawerHost` 里写的 `304 * density` 从未生效：`activity_main.xml` 的
   `<fragment android:layout_width="match_parent">` 会在 `onCreateView` 之后覆盖掉它，抽屉实际一直是
   「铺满整屏减去 DrawerLayout 的 64dp 最小边距」。K40 上实测**竖屏 904px、横屏 2144px（占 89%）**。
   已修：竖屏 836px（=304dp）、横屏 836px、320dp 窄屏 739px（=84% 上限）。三档都有 `dumpsys` 边界证据。
2. **顶栏 200% 字体并没有真的裁切。** 静态审计预估「200% 必裁」（22sp × 2.0 行高 ≈ 53–66dp vs 固定 56dp），
   但真机 200% 实测标题单行完整、未被裁。改动仍保留（`heightIn(min=)` + `maxLines/overflow`），
   性质是**去掉固定高度上限**、防止 200% 以上的字体缩放与厂商 ROM 行高差异，**不是**修复一个已发生的破损。
3. **横屏适配无法在这台机器上稳定复现，原因在系统侧而不在 App。** 强行 `wm user-rotation lock 1` 后，
   启动 App 会把显示打回竖屏；`dumpsys window displays` 显示
   `mLastOrientationSource=WindowedMagnification`（无障碍「窗口放大」接管了旋屏），
   而 App 自身请求的是 `SCREEN_ORIENTATION_UNSPECIFIED`（**代码里没有任何 `setRequestedOrientation`**）。
   后来手机平放触发自动旋转，才拿到真实横屏（2400×1080）证据。

## 1. 改了什么（9 个文件，全部在 miuix 皮肤内）

| 文件 | 改动 | 触发的验收项 |
|---|---|---|
| `ui/main/drawer/MiuixDrawerHost.kt` | 抽屉宽度改为 `min(304dp, 窗口宽 × 84%)`，在 attached 后与父布局变化时重新施加（因为 XML 的 match_parent 会覆盖它） | 侧边栏、窄屏、分屏、横屏 |
| `ui/main/MiuixMainNavigationHost.kt` | 顶栏 `height(56.dp)` → `heightIn(min = 56.dp)`；标题 `maxLines = 1` + `Ellipsis`；4 个顶栏动作按钮触摸目标由 48×**44**dp 改为 48×**48**dp | 大字体、侧边栏按钮 |
| `ui/main/MiuixSearchActivity.kt` | 搜索浮层根 Column 加 `imePadding()` + `verticalScroll()`（键盘弹出后按钮仍可达）；选项行 `height(36.dp)` → `heightIn(min = 48.dp)`；排序/筛选按钮 40dp → 48dp；「修改于 …」补 `overflow = Ellipsis` | 大字体、键盘、触摸目标 |
| `theme/MiuixBackButton.kt` | 圆盘视觉保持 36dp，**触摸目标扩到 48dp**（10+ 个二级页唯一的返回入口） | 触摸目标 |
| `ui/sample/MiuixSampleFragment.kt`、`ui/plugin/MiuixPluginFragment.kt` | 工具栏 `height(54.dp)` → `heightIn(min = 54.dp)`；副行补 `maxLines/overflow` | 大字体 |
| `ui/resource/MiuixResourceFragment.kt` | 资源分类对话框与 `ResourceDetailDialog`：可变高区域改 `weight(1f, fill = false)`，正文加 `verticalScroll`，操作按钮留在滚动区外；底栏 `height(72.dp)`→`heightIn(min=72.dp)` + `navigationBarsPadding()`、64dp 圆钮 `TopCenter`→`Center`；元数据首尾项补 `maxLines/overflow` | 横屏、安全区、大字体 |
| `ui/project/MiuixBuildActivity.kt` | 3 个 `SuperDialog` 列表 `heightIn(max=320/360/380.dp)` 前加 `weight(1f, fill = false)`，高度不足时先压缩列表、保住「取消/完成」 | 横屏 |
| `miuix/AndroidManifest.xml` | 日志页、MCP 历史页补 `configChanges="orientation\|screenSize\|keyboardHidden"`；日志页补 `adjustResize` | 横屏 |

**故意没改**（静态审计报了，但真机证据不支持）：

- **抽屉/页面的 inset 补齐**：审计说 `fitsSystemWindows="false"` 会让状态栏压住抽屉。真机实测状态栏 80px，
  抽屉首卡片从 111px 开始——**没有被遮挡**，加 `safeDrawingPadding()` 只会造成双重留白。
- **`android.max_aspect = 2.1`**：K40 是 20:9（2.222）> 2.1，但横屏实测窗口拿到的是全宽（`DrawerLayout 0,0-2320,956`），
  说明 `targetSdk 28` 下该 meta-data 已被系统忽略。改了没有收益，只会扩大影响面。

## 3. 本轮**没有**验到的（不要当成已通过）

1. **搜索浮层**（`imePadding` + `verticalScroll`）：编译通过，但没在真机上实际弹出键盘验证按钮可达。
2. **资源页 / 打包页对话框的 `weight` 改动**：编译通过；横屏下按钮是否真的始终在窗口内没有截图验证。
   （其中 `PermissionDialog` 的固定头部在 200% + 横屏仍可能自身超窗，本轮未做结构调整。）
3. **`navigationBarsPadding()` 的实际效果**：`targetSdk 28` 非 edge-to-edge 下若 inset 为 0 则视觉不变。
4. **返回键 48dp 触摸目标**：只做了代码与编译验证，没有做点击命中测试。
5. **日志页 / MCP 历史页的 `configChanges`**：旋转不再重建 Activity，但没有实机旋转验证状态保留。
6. **横屏无法稳定复现**（见第 0 节第 3 条），因此「横屏」这一项的证据只有那一次自动旋转。
