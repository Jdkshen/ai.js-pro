# MCP 手机终端与编译入口

> **2026-10-25 决定：取消手机端 Java/C/C++/Android APK 源码编译工具链。** 不再引入 buildtools 插件、ECJ/clang/aapt2 组件或相关编译能力；只保留 MCP 终端控制（terminal_exec/read/write/stop/list、get_build_tools）以及既有 D8/Smali 转换能力。此前工具链 A-E 预研与插件代码已回退，不得重新引入。

日期：2026-10-25。用户要求给 MCP 增加终端，用于 C/C++、Java、DEX 和 Android 构建；随后确认复用 AI.js Pro 应用内已有终端。

## 本轮范围

复用现有终端执行路径，抽出共同的异步进程管理，应用界面和 MCP 分别管理自己的会话。不是电脑代理编译，也没有自动下载整套 SDK。当前更新源仍为 dev-1244；**candidate-1245 已装 MI8 并通过本轮验收，尚未发布**。

最终 APK：`.artifacts/mcp-terminal-20261025/final-candidate/AI-js-Pro-Flutter-release-candidate-1245.apk`，137696691 字节 / 131.32 MiB，较 dev-1244 增加 53240 字节。SHA-256：`f72c0cebc6e17dc6b55f1a7d6aec36789d81716bf60b1c93035d8bd87e202158`。MI8 已安装 APK 的摘要与该文件一致；22 ELF 无白名单 16KB 对齐、Retrofit 最终 DEX 泛型/注解和体积预算均通过。保守 R8 + 原开发通道测试签名，未改更新清单或仓库版本。

新增六项 MCP 工具：terminal_exec、terminal_read、terminal_write、terminal_stop、terminal_list、get_build_tools。公开目录由 45 增至 51（42 个 canonical + 9 个原有兼容名）；自动 camelCase 调度别名仍可用。服务版本 1.6.0。

- 命令立即返回 jobId，合并 stdout/stderr，UTF-8 解码；分块读取支持没有换行的编译进度。
- 每任务保留 256Ki 个 UTF-16 字符，使用 offset/nextOffset 分页；旧输出被淘汰时返回 truncated/outputStart。完整大日志可由调用方重定向到项目文件。
- 最多 3 个活跃进程，保留 16 条记录；取消中的启动仍占并发位，避免反复启停绕过上限。
- 写入 stdin 独立排队，不让不读 stdin 的编译器阻塞 MCP 请求；eof 关闭输入，inputError/pendingInput 可观察实际写入状态。
- 每命令经 setsid 创建独立进程组，停止/超时结束同组子进程，不调用 stop_all_scripts。子进程自行 setsid 脱离的守护程序不在管理范围。
- timeoutSeconds 默认 300、范围 1..3600，是执行期限；terminal_read.waitMillis 最大 10000，只等待输出。STOPPED/TIMED_OUT 与编译失败分开，processActive=false 表示清理结束。
- MCP 服务关闭会清理自己创建的终端；手机界面退出清理界面自己的终端。服务重启后不恢复历史记录。
- workingDirectory 通过现有 McpPathRules 校验，位于操作目录内。shell 是应用 UID；cwd 约束不是命令沙箱，也不提供 ADB/root 权限。非 PTY，不支持全屏终端程序或完整终端作业控制。

现有终端界面同步改用同一底层，增加持续输出、stdin 输入、停止按钮，显示最多 64Ki 字符，默认命令执行期限 1 小时。

## 编译支持边界

| 目标 | 本轮状态 | 还需要什么 |
|---|---|---|
| JAR/class → DEX | 复用内置 D8；Android 8.0/API26+ | JVM 编译产物、必要 library/classpath |
| Smali → DEX | 复用内置 Smali | Smali 源文件 |
| Java 源码 → class/DEX | 终端可调用外部编译器；主 APK 没有 JDK/javac/ECJ | 兼容手机的 Java 编译器及 Android API stub |
| C/C++ → ELF/.so | 终端可调用外部编译器；未捆绑 clang/sysroot | 手机 ABI/Android 兼容 LLVM、链接器、sysroot、构建工具 |
| Android 工程 → APK | 可执行已配置工具链的构建命令；未声称端到端已支持 | 兼容 JDK/Gradle/SDK/aapt2/签名工具；原生工程还需 NDK |

get_build_tools 只定位 PATH 中的命令，不执行未知编译器，不自动安装。found=true 不能当成工具已通过试编译。电脑 SDK/NDK 主机工具不能直接当作 Android ARM64 编译器使用。

内置 CLI 由 `AndroidBuildTool.main` 统一分发 D8/Smali，在独立 app_process 中执行，防止编译器 main 的 System.exit 退出宿主。AIJS_APK / AIJS_BUILD_MAIN 是手机终端预置环境变量：

```sh
mkdir -p out && CLASSPATH="$AIJS_APK" app_process /system/bin "$AIJS_BUILD_MAIN" d8 --min-api 26 --output out input.jar
CLASSPATH="$AIJS_APK" app_process /system/bin "$AIJS_BUILD_MAIN" smali assemble src -o classes.dex
```

Java D8 CLI 与主 APK 现有依赖共用，没有新增一份编译器；org.smali:util 原先已在 runtime 依赖中，此处显式纳入编译 classpath 以调用 Smali CLI。大型 C/C++/Java/Android 工具链后续走可选插件，遵守主 APK 体积约束。

Android 对可执行文件位置和应用 UID 有约束，不能把终端有 shell 等同于拥有 Termux 的完整包管理环境。官方依据：[Android 10 执行权限变化](https://developer.android.com/about/versions/10/behavior-changes-10#execute-permission)、[D8 输入输出与 classpath](https://developer.android.com/tools/d8)、[NDK 主机与目标工具链](https://developer.android.com/ndk/guides/other_build_systems)。
