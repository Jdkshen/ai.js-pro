## 2. 三项改动

### A｜frida_session_open.pid 去掉 default=1

- schema：`pid` 从 `num(1,Int.MAX_VALUE,1)` → **`num(2,Int.MAX_VALUE)`（无默认值，最小值 2）**（`ToolkitReverseTools.kt:120`）；
- runtime：`target.pid?.let { require(it >= 2) }`，错误文案说明「pid 1 是 init，不是目标应用进程；省略 pid 时按 packageName 解析会话目标」（`ToolkitFridaSession.kt:336` 附近）；
- 描述同步（`ToolkitReverseTools.kt:27`）：packageName 必填 + 可选 pid。

**理由**：pid 1 = init，旧默认值等于「省略就绑 init」，没有任何可用语义；而 pid 本身是可选覆盖（省略时按包名解析），所以保留可选、去掉默认、并显式拒绝 <2。

### B｜mt_ 别名从下标窗口改为显式名单

- 旧：`names.take(58).filter { it != toolkit_status }` —— 在前 58 项里插入任何工具都会**静默**改变 57 个 mt_ 别名的集合；
- 新：`private val mtAliasTargets = listOf(...)` **显式 57 项** + `init { check(无重复); check(全部在 names 里) }`（`McpToolkitCatalog.kt:107-180`）。

**验收**：`McpToolSurfaceInvariantTest.toolkitCatalogNamesAndAliasesAreConsistent` 断言别名集合与目标存在性（改动前后 57 个逐字相同）。

### C｜扁平结果的 data 镜像（含 64KiB 护栏）

- 新增 `McpToolResultShapes.mirrorFlatResult(result, limitBytes = 64KiB)`（`McpToolResultShapes.kt:36-68`）：对扁平、无 data、非 {ok,...} 信封、非失败的成功结果补一份 data 深拷贝，**保留全部扁平顶层字段**（不改成信封，避免破坏 .4 现有断言）；
- 超过护栏时不补，改在 `structuredContent` 里写 **`dataOmitted{reason,bytes,limitBytes}`**，让调用方知道这里本该有 data 但太大，而不是静默缺失；
- 接线点是 `tools/call` 的**单点**（`McpTools.kt:108-113`）：`mirrorFlatResult(applyScalarMirror(...))`，覆盖主进程 / 工具桥 / 自动化三条路径。
