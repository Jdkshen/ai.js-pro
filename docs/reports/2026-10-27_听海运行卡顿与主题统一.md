# 听海 1.2.1：运行卡顿与主题统一

2026-10-27。私有 Node 工程更新；宿主仍为 MI8 上的 dev-1267-tinghai-candidate，没有发布新宿主 APK。

## 卡顿原因与修复

1. 原来暂停/后台仍每 500ms 设置同一批文字、图标、ProgressBar，并对根容器 suppressLayout 和重新发布 PlaybackState。现在暂停后无周期 UI 重画；播放时每次只写变化的值。控件实例各自缓存，重建后的新控件仍得到完整初始状态，写入失败可重试。
2. 播放回调直接复用给出的状态，不重复读取完整队列；新增内部采样 getPlaybackState，仅播放时读取一次原生位置，不每帧重新读取时长/克隆整个队列。原 getState 的完整快照接口保持原有语义。
3. 媒体状态事件/跳转立即发布，稳定播放每 5 秒校准一次；Android PlaybackState 带位置、速度和时间戳供系统显示。暂停状态不反复广播，通知本身此前已有缓存，本次没有把通知误认成每 tick 重建。
4. 进度写入不再抑制全树布局；歌词高亮只改旧/新两行，离开歌词页解除引用。UI 刷新合并到最新状态，重建时清除待更新标记。
5. 图片缓存建立文件索引，避免逐张扫描目录；复用当前曲封面状态，不再为每张图反复克隆播放队列。解码边界只读一次，图片赋值不再抑制根布局。
6. 同样的专辑取色不重复重建；正在滚动或弹窗打开时延后换色。覆盖页面打开时先刷新当前可见页，隐藏首页等返回时再更新，避免一次换色同时重建两套页面。

## 主题统一（按用户确认，只改听海复刻）

- 首页“最新/最热”等主色按钮，用 primary + onPrimary；悬浮按钮使用 primaryContainer + onPrimaryContainer；播放按钮使用 secondaryContainer + onSecondaryContainer。
- 卡片统一 surfaceContainerHigh，删除截图阶段的 RGB 手工偏移；底栏保留正常 Material 表面层次。
- 喜欢、媒体库加入、循环状态的图标随真实状态更新，选中态使用当前主题强调色；修复播放页打开后状态图标未初始化、自动切歌后部分按钮仍引用旧歌曲的问题。
- 输入框光标、选择高亮、警告卡片和文字使用对应的主题角色。图片上白字/第三方平台标识属于图片内容，不强制染成按钮色。
- 启动根布局先计算当前主题背景，不再固定使用旧紫黑色。系统/浅色/深色、专辑动态色、纯黑设置继续保留。

## MI8 对比测量

同一台 MI8 ce4d2bdb、Android 15、同一宿主与同一歌曲；CPU 从 /proc/PID/stat 读取，CLK_TCK=100，以下是单核百分比。

| 场景 | 1.2.0 | 1.2.1 |
| --- | ---: | ---: |
| 首页暂停，10 秒 CPU | 16.36% | 7.06% |
| 首页暂停，10 秒新绘制帧 | 29 | 0 |
| 播放器播放，10 秒 CPU | 20.26% | 11.99% |
| 播放器播放，10 秒新绘制帧 | 49 | 21 |
| 八次相同滑动，帧耗时 P95 | 31ms | 17ms |
| 八次相同滑动，CPU | 58.79% | 56.75% |

数据是本机各一次采样，不能外推所有设备、网络和刷新率；暂停后 0 新绘制帧时帧耗时分位数没有意义。滚动 CPU 降幅较小，本轮改善主要是避免无效布局、减少长帧及稳定播放/暂停开销。首次复杂页面创建和每曲的同步持久化成本仍存在，不宣称彻底不卡或原版所有功能 100% 相同。
