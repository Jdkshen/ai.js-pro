## 2. Bug2 修复（W2 task-22）

`ToolkitWorkspaceInventory.kt`：**A** caller 身份默认化（省略 owner/clientId 时按服务端默认身份判定，不再把自己写的 `mcp-host/server-default` 记录判成 `other_owner`；**显式传值时行为与旧版逐条一致**、真实第三方记录仍受保护）；**B** 新增 `includeEditSessions`（默认 false，显式 true 才允许连编辑会话一起释放，覆盖 temporary 与 expired）；**C** 每行补 `sessionIds` + 新增 `blockedBy` 计数与点名 workspaceId/命令的 `nextActions`；**D** inventory/`artifact_open`/autoGc 失败提示里那条「照抄仍 0 命中」的命令改成真能生效的组合（autoGc 自身仍保守，不擅自删会话）。

**K40 before/after**：

| | before（dev-1418） | after（dev-1419） |
|---|---|---|
| `gc{dryRun:true}` | `wouldDeleteCount=0`、`callerOwner=null`、原因含 `other_owner`+`unknown_client` | `callerIdentitySource=server-default`、**`other_owner`/`unknown_client` 消失**、`blockedCount=5`、`nextActions` 点名 `apk_session_release{workspaceId:"146b7097-…"}` |
| `+includeTemporary,minAgeMinutes:0,includeEditSessions` | 1 / 0 | **4 / 8**（个 / 释放会话） |

**顺带**：我们自己的不变量测试当场抓到 `includeEditSessions` **没写进 inputSchema**（客户端发现不了）→ 已补进 `assets/mcp/toolkit-apk-schemas.json`。

## 3. 入口误导修复（W2 task-23）

`apk_read_signature` 默认现在返回 `verification:"not_run"` + `verificationReason`（**`verified=false` 表示「没跑验签」，不是「验签失败」**）+ `verifyWith:"apk_verify{workspaceId}"`；新增 `verify:boolean`（默认 false）→ true 时**复用** `ToolkitApkVerifier` 返回逐方案状态；并补了 `apk_read_signature` 的**专属描述**（此前只有通用兜底文案）。

**K40 实测**：默认 `verification=not_run / verified=false / hasSchemes=false`；`verify=true` → `verification=executed / verified=true / status=valid / schemes.V1,V2,V3=valid, V3.1=not_run`。
