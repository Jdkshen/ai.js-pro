# Node 选中事件与旧协议菜单兼容

日期：2026-11-01。承接 dev-1301。对应 A03 的一个具体子集；全部剩余范围见 [当前剩余对齐清单](2026-11-01_剩余对齐清单_dev1302.md)。

## 修复内容

1. 原生导航的 `item_selected` 使用正确的 `onNavigationItemSelected(MenuItem)`，通知回调返回接受选中。旧代码实现了另一个方法名，实际选择不触发 JS；旧协议监听则返回 false，阻止真实选中状态改变。
2. Spinner 等 AdapterView 使用 `AdapterView.OnItemSelectedListener`，保留 itemId、parent、position、child，避免把 Material 导航监听接口套在 Spinner 上。
3. 兼容 Activity 补齐五项已有协议菜单命令，并与本地 View 共用同一实现：`getSelectedItemId`、`setSelectedItemId`、`getMenuSize`、`getMenuItemId`、`menuItems`。支持 BottomNavigationView/NavigationRailView；Toolbar 可读菜单，不支持导航式选中时明确报错。
4. 反射监听器识别两种选择回调名，boolean 接口返回 true；Object 的 equals/hashCode/toString 不生成幽灵事件。自动导航和协议监听遵循相同选中契约。

Material 1.12.0 的接口以 `onNavigationItemSelected` 的 true 接受新项，参见 [官方对应版本源码](https://raw.githubusercontent.com/material-components/material-components-android/1.12.0/lib/java/com/google/android/material/navigation/NavigationBarView.java)。脚本 `view.on('item_selected')` 是通知；直接使用 Android Java listener 的返回契约保留。

## 边界

- 本轮五项菜单命令不包含任意菜单增删、标题/图标编辑和旧协议的完整视图树。
- 原生 AdapterView 提供完整四参数；旧协议仍只发 itemId。协议 getSelectedItemId 仍使用 int，超过 32 位的 AdapterView 行 id 窄化需另补，当前用例使用小整数。
