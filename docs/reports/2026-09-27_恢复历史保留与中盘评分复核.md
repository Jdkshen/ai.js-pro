# 恢复历史保留与中盘评分复核

日期：2026-09-27。象棋项目：0.6.35。App：dev-713。

## 这次修了什么

1. **恢复时丢失棋谱**。K40 现场日志显示，已经确认对方 `a5a3` 后进入恢复，恢复后的盘面仍与已确认基准一致，却调用 `trackAdopt` 重新开段，完整历史变为部分历史。
2. **恢复后一直等待**。状态机曾收到“几何不可信”时，定位成功只发送 `RECOVERED`，没有恢复内部可信标记，后续观测仍无法正常推进到搜索。
3. **定位失败后的旧坐标复用**。原限频只检查距离上次定位的时间；失败后也可能跳过下一次定位。现在实际重定位开始时取消可信，失败后保留恢复状态，按间隔重试；旧坐标不再用于识别、重建基准或点击。
4. **结束状态保护**。晚到的恢复结果不能解除暂停、停止或对局结束状态。

这些修复提高棋谱连续性和恢复可靠性，不保证把当前残局变成胜局。旧版本已经丢掉的历史不会凭空补齐。

## 实现与维护入口

以下路径相对于 `apps/app/src/main/assets/sample/QuickJS 新引擎/项目与打包/象棋自动走棋/`。

| 文件 | 作用 |
| --- | --- |
| `src/services/position-tracker.js` | 新增 `reconcile()`，恢复时核对盘面、轮次与合法着法；保留 `adopt()` 的显式重开语义 |
| `src/automation/driver/baseline.js` | 保存恢复前基准与推断的单步/双步，交给账本核验 |
| `src/automation/driver/history.js` | `trackRebuild()` 统一恢复记账，记录保留次数；新追加着法才更新走子计数与循环检测记录 |
| `src/automation/driver/verification.js` | 仅可信坐标允许快速恢复；定位失败必须重试；成功后传递可信标记与几何版本 |
| `src/automation/driver/loop.js` | 坐标不可信时暂缓识别与基准修补，继续触发恢复重试 |
| `src/automation/state-machine.js` | 采纳明确的定位成功结果，保护暂停、停止和对局结束状态 |

恢复对账规则：

- **同盘、同轮次**：原棋谱保持不变，不重复记账、不增加位置版本。
- **相差一手或连续两手**：恢复前盘面、轮次必须与账本一致；先在独立临时账本逐手验证合法性，再核对最终盘面及轮次，整条链通过后才写入正式账本。
- **轮次错误、无法解释的盘面、缺失基准或非法着法**：沿用显式采纳新基准的降级流程，不伪造缺失着法。
- **已有部分历史**：可保留这部分，不能因为恢复就冒充完整历史。
- **新会话、手工改基准**：仍走原有重开流程，不把上一局棋谱带入下一局。

后续新增恢复入口应调用 `trackRebuild()`，不要无条件调用 `trackAdopt()`。成功定位时发送带 `geometryTrusted: true` 和有效 `geometryVersion` 的 `RECOVERED`；快速恢复不伪造定位成功信息。

## 中盘评分 112 → 0 的复核

手机原记录：约 1 秒搜索选择 `c6a6`、深度 14、评分 112；对方 `c7b5` 后，选择 `b1d1`、深度 15、评分 0。这发生在后续恢复丢失历史之前，不能全部归因于棋谱丢失。

PC 使用 `Pikafish dev-20260919-6a59ee2f`，Threads=2、Hash=256、Contempt=40、MultiPV=3，分别用 1/5/15 秒对记录中的两个 FEN 复算，每次重置对局。

| 位置 | 1 秒 | 5 秒 | 15 秒 |
| --- | --- | --- | --- |
| `c6a6` 之前 | `c6d6`，d18，cp9 | `c6d6`，d26，cp8 | `c6d6`，d32，cp13 |
| 对方 `c7b5` 之后 | `b1d1`，d19，cp0 | `b1d1`，d28，cp3 | `b1d1`，d34，cp3 |

原着 `c6a6` 在前两档复算的候选评分均为 cp2。加深搜索后未重现“明显优势”，提示原来的 112 可能是短时搜索的评估波动；当前证据不足以认定错失必胜。

限制：这里是 PC 上的局面快照复算，未还原手机当时完整历史、缓存和计时条件，不能作为理论和棋或绝无更好走法的证明。本次没有擅自改变用户设定的搜索时间。
