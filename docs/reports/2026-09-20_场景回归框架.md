# 场景回归框架：把一次真机故障固化成一条场景（2026-09-20）

> 起因：用户「重新弄这个框架吧」。之前所有离线测试都是 `tools/self-check.js` 那种
> **一个模块一个断言** 的写法，而真机上反复踩的坑几乎都不是模块级逻辑错 ——
> 是**组装错 / 端到端行为错**（框分没传进融合、抢救路径顺序不对、几何错位把子写进隔壁格、
> 灰度重试该跑没跑）。真机复现一次要截图 → 定位 → 跑一局（~10s），还常常要靠运气碰上那帧。
>
> 目标（用户验收口径）：① PC 上一条命令跑完全部场景，打印通过/失败；② 加场景要便宜（造假宿主 + 断言）；
> ③ 收编现有 self-check / 契约测试到同一入口；④ **真机上也能一键跑同一批场景**。

## 1. 长什么样

```
tools/
  run-regress.js          ← 入口（PC 与真机同一份；PC 上顺带跑 legacy 套件）
  regress/
    harness.js            ← 断言 + 场景注册 + 组装糖（t.host / t.pipeline / t.recognize）
    index.js              ← 场景清单（显式注册；真机没有 Node 的 fs）
    cases/*.js            ← 场景库（一条场景 = 一次真机故障）
  fake-vision-host.js     ← 假宿主（本轮补齐新契约：裁剪帧 / 灰度帧 / 帧账目）
```

```bash
# PC
node tools/run-regress.js                 # 全部场景 + self-check + 格子契约
node tools/run-regress.js --only king     # 按名字/标签过滤
node tools/run-regress.js --report .artifacts/regress.txt   # 留档（PC 默认不写文件）

# 真机（同一批场景）
adb shell am start -S -n com.jdkshen.aijspro/com.jdkshen.aijspro.external.open.RunIntentActivity \
  --es path "/sdcard/xiangqi-p4/proj/tools/run-regress.js"
```

## 2. 首批 8 条场景（全部来自这一周真机踩过的坑）

| 场景 | 钉住的边界 |
|---|---|
| 帅/将抢救（有框） | 字形读不出但**有框** ⇒ YOLO 候选法（零开销）救回，且不误伤同宫的仕 |
| 帅/将抢救（无框） | 字形路（九宫 9 格）救回；带 `hiddenFromDetect`；断言**没有**走 YOLO 路、**没有**白花灰度 |
| 帅/将抢救（反例） | 宫里的红仕（label=A、字形=仕）**不许**被补成帅 ⇒ 规则门否决整帧 |
| 规则补全（低分字形） | 帅 0.51 分 ⇒ 记 `?` 后由规则层补全；**不是**「抢救」（把用户的一次性调试脚本收成正式场景） |
| 灰度重试 | 彩色「印市」0.49 ⇒ 灰度「師」0.70 ⇒ 救回；断言真的申请了灰度帧 |
| OCR 全废（反例） | 一个都认不出时：确认数 0、不许乱补、不许崩 |
| 几何错位（反例） | 框整体偏**半格** ⇒ 全被拒、非九宫格子不许出现子 |
| 基线（对照） | 正常帧：无抢救、无灰度、规则门通过 —— 防止「抢救」类改动变得过于激进 |

## 3. 本轮顺带发现 / 修掉的东西

1. **假宿主落后于真契约**：真宿主早就 `prepareRegion`/`releaseFrame` 了（先裁再送、灰度重试），
   假宿主还只认「整帧 + region」⇒ 补齐：裁剪帧令牌（能从令牌反推出是哪一格）、
   每枚子的**彩色/灰度两套读数**（`ocr` / `ocrGray`）、`stats()` 帧账目（断言不泄漏）。
   ⚠️ `cellOfRegion` 要同时认 `{x,y,width,height}`（找色那条路）与 `[x,y,w,h]`（OCR 那条路），
   否则找色会静默判成「没有墨迹」—— 一改就红了两条老用例（已修）。
2. **「整格错位」这一层抓不住**：把检测框整体下移**一格**时，框心正好落在错格中心 ⇒ 距离 0 ⇒
   距离闸门放行，流水线会安静地把每个子写到隔壁格。⇒ 场景改为**半格**错位（能被挡下），
   并在注释里写清：整格/整行错位靠**几何体检**（面板 `grid-sanity` + `quality`），不是这一层的事。
3. **`tool.detection.rejected` 是数组不是计数**（断言写错过一次），场景里改为 `.length`。
4. **PowerShell 的 `*>` 会把子进程 UTF-8 输出按 GBK 转码再存成 UTF-16** ⇒ 日志全乱码。
   ⇒ 框架自己落盘（Node 用 `fs.writeFileSync(..., "utf8")`、真机用 `files.write`），
   PC 上默认不写文件（`assets/sample/**` 是打包内容，不许随手丢文件），要留档加 `--report`。
5. `BASE_DIR` 在 PC 上是**反斜杠**：`__dirname.replace(/\/tools$/, "")` 在 Windows 上匹配不到 ⇒
   先 `replace(/\\/g,"/")` 再剥（本仓库 `tools/*.js` 的老写法在 PC 上跑不了，新文件统一用新写法）。

## 5. 以后怎么加场景

在 `tools/regress/cases/` 新建模块（首行 `// @engine quickjs`），把路径加进 `tools/regress/index.js`：

```js
module.exports = {
    name: "一句话说明（会打进日志）",
    tags: ["pipeline", "king"],
    run: function (t) {
        const host = t.host({ pieces: [...], hiddenFromDetect: ["4,9"] });
        const pipeline = t.pipeline(host);
        const result = t.recognize(pipeline, host, 3);
        t.equal(result.chars[85], "K", "(4,9) 应当被救回成红帅");
        t.ok(result.validation.ok, "规则门应当通过");
        t.equal(host.stats().leaked, 0, "临时帧不许泄漏");
    }
};
```

断言失败不会中断场景（一次列出全部失败）；`t.skip("原因")` 用于设备/PC 专属场景。
