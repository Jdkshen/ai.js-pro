# AI.js Pro 高精度耗时与案例同步更新说明

> 历史快照说明，更新日期：2026-08-31。  
> 适用范围：QuickJS 新引擎、Rhino 兼容引擎、图色与 YOLO 示例；结论应结合当前源码复核。

## 1. 本次更新目标

解决示例日志中大量出现 `0ms` 的问题，并保证 APK 更新后，手机文件管理中的内置示例能够同步为最新版本。

本次更新不只是修改日志显示格式，而是把计时源替换为真正的高精度单调时钟。

## 2. 问题原因

旧示例普遍使用：

```javascript
const startedAt = Date.now();
// 执行操作
const elapsedMs = Date.now() - startedAt;
```

`Date.now()` 只能返回整数毫秒。找色、参数转换等操作如果执行时间不足 1ms，计算结果就会被截断为 `0ms`，无法用于准确比较性能。

另外，应用首次启动时会把 assets 中的内置示例复制到应用私有目录。只更新 APK 内的 assets、但不刷新手机上的历史副本时，文件管理仍可能打开旧示例。

## 3. 核心改动

### 3.1 QuickJS 新增 `performance.now()`

QuickJS Native Core 新增原生高精度计时函数，并在启动脚本中提供标准接口：

```javascript
const startedAt = performance.now();
// 执行操作
const elapsedMs = performance.now() - startedAt;
console.log(elapsedMs.toFixed(3) + " ms");
```

底层使用 C++ `std::chrono::steady_clock`：

- 不受系统时间调整影响；
- 返回带小数的毫秒值；
- 适合性能测试、帧耗时和算法耗时统计。

主要实现文件：

- `modules/autojs/src/main/cpp/quickjs_jni.cpp`
- [QuickJS 双引擎架构](../architecture/QUICKJS_ENGINE.md)

### 3.2 Rhino 使用 `System.nanoTime()`

旧 Rhino 引擎不能直接使用 QuickJS 的原生 `performance.now()`，因此兼容示例统一使用：

```javascript
function __nowMs() {
    return Number(java.lang.System.nanoTime()) / 1000000;
}

function __formatMs(value) {
    return Number(value).toFixed(3);
}
```

这样可以在原引擎中获得单调、高精度的耗时结果，便于和 QuickJS 新引擎进行对比。

### 3.3 统一耗时格式

图色、截图、模板和 YOLO 相关示例统一保留 3 位小数：

```text
[耗时] 截图: 49.826 ms
[耗时] 单点找色: 2.373 ms
[耗时] 多点找色: 1.207 ms
```

不再只输出 `0ms`、`1ms`、`2ms` 这种整数结果。

> 极短操作如果真实耗时低于 `0.0005ms`，保留 3 位小数后仍可能显示 `0.000ms`。这属于显示精度边界，不是旧版整数毫秒截断问题。

### 3.4 截图缓存与新帧混合模式

截图接口改为两种明确模式：

```javascript
// 默认立即使用当前最新缓存帧，不等待静止页面产生新帧。
const latest = captureScreen({ mode: 'fast', size: 720 });

// 最多等待 100ms 获取新帧；超时后回退到最近有效帧。
const fresh = captureScreen({
    mode: 'fast',
    size: 720,
    fresh: true,
    timeout: 100
});
```

默认模式用于普通找色、模板匹配和 YOLO 循环，避免 `ImageReader` 没有产生新帧时无限阻塞。`fresh` 模式用于必须等待画面变化的场景，`timeout` 范围为 0～5000ms。首次截图没有任何缓存可回退时，超时会抛出异常。

Rhino 兼容引擎默认同样立即获取最新缓存；需要新帧时使用 `images.captureScreen(true, 100)`。

## 8. 后续开发规范

新增性能示例时应遵循以下规则：

1. QuickJS 使用 `performance.now()`；
2. Rhino 使用 `System.nanoTime()`；
3. 统计代码必须使用单调时钟，不能使用系统日期时间；
4. 日志统一使用 `toFixed(3)` 输出毫秒；
5. 截图、预处理、推理和后处理应分段计时；
6. 性能对比应进行预热，并统计多次运行的平均值；
7. 修改内置示例后必须更新迁移版本标记，确保手机端旧缓存能够同步刷新。

推荐格式：

```javascript
const startedAt = performance.now();
const result = runTask();
const elapsedMs = performance.now() - startedAt;
console.log("[耗时] 当前操作: " + elapsedMs.toFixed(3) + " ms");
```
