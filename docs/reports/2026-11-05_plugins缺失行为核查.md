## 0. 结论摘要

脚本执行 $plugins.load("com.hraps.ocr") 时，当前三个引擎行为不一致：

| 引擎 | 插件未安装时的行为 | 是否有清晰提示 | 顶层脚本会中断吗 |
|---|---|---|---|
| Rhino | 不抛错；__plugins__.js 对已知 OCR 包回退内置 OCR，返回 shim 实例，console.warn 一次 | 有中文 warning，但没有错误码；shim 带 __aijsBuiltInShim=true | 不会（fallback 成功时）；只有回退失败/其它包名才抛 |
| QuickJS | 抛 Java 异常：InternalError 包 QuickJsJavaInterop$InvocationFailure，内含 Plugin$PluginLoadException 和 PackageManager$NameNotFoundException | 不清晰：没有「插件未安装」中文提示，只有长 Java 类名 | 未捕获则会；try/catch 后可继续 |
| Node24 | $plugins 根本不存在 -> ReferenceError: $plugins is not defined；用 require('plugins').load(...) 则是异步 rejection | $plugins 只有 ReferenceError；require 路径有中文「插件未安装：…」但无错误码 | 未捕获的 ReferenceError/未处理 rejection 会让脚本 FAILED |

因此不能笼统回答会/不会中断，必须先看引擎；Rhino 目前的 hraps fallback 与另外两个引擎不一致。

## 1. 实测方法

用 MCP run_script 在 MI8 上执行最小脚本（不构建、不安装）：

- Rhino：try/catch 包 $plugins.load("com.hraps.ocr")，观察返回值；
- QuickJS：同上；
- Node24：先打印 typeof $plugins，再 try/catch 直接调用；另用 require("plugins").load(...).then(..., ...) 观察 Promise；
- 再去掉 try/catch 测未捕获路径，确认 execution 状态。

测试使用 MCP 独立 execution；未停止任何他人任务。

## 5. 当前问题归纳

1. 跨引擎语义不统一：同一包名 com.hraps.ocr 在 Rhino 不报错（shim），在 QuickJS 报长 Java 异常，在 Node24 直接 $plugins 未定义。
2. 缺少结构化错误码：当前只有 InternalError / JavaException / ReferenceError / AutoJsPluginsError 等运行时类型，没有 PLUGIN_NOT_INSTALLED 之类稳定字段。
3. QuickJS/Rhino 通用插件缺少清晰中文提示：用户看到的是 NameNotFoundException、PluginLoadException，无法一眼区分「插件没装」「插件 SDK 元数据坏」「入口脚本缺失」「引擎不支持」。
4. Rhino 的 hraps fallback 是兼容，不是插件等价：模型/识别率与真实浩然插件不同；只在 package 缺失时启用，装插件后原样使用插件实现。
5. Node24 的 $plugins 不存在，但错误提示依赖引擎差异；调用方若从 Rhino 示例迁移会直接 ReferenceError。
6. 异步差异：Rhino/QuickJS 的 $plugins.load 是同步；Node 普通插件 load 返回 Promise，不 await/catch 会在异步阶段失败。

## 6. 建议的统一错误文案与错误码（仅建议，未改代码）

建议在宿主 Java 加载层（Rhino/QuickJS 共用 Plugins.load，Node 在 Node24PluginLoader.load）统一分类，再由各引擎 JS 层包装成同一形状：

### 6.1 错误码

| code | 触发条件 |
|---|---|
| PLUGIN_NOT_INSTALLED | PackageManager 抛 NameNotFoundException / 包不存在 |
| PLUGIN_METADATA_MISSING | 包存在但没有 org.autojs.plugin.sdk.registry |
| PLUGIN_ENTRY_MISSING | 插件没有 assets/scripts/index.js 或入口导出不是函数 |
| PLUGIN_LOAD_FAILED | registry 类加载/loadDefault/资产复制失败等其它错误 |
| PLUGIN_ENGINE_UNSUPPORTED | 当前引擎不支持该插件形态（如 Node 同步 API / 旧 SDK 不兼容） |
| PLUGIN_BUILTIN_SHIM_USED | 非错误；已知 OCR 包缺失但成功使用了内置 shim |

### 6.2 建议 JSON 形状

~~~json
{
  "code": "PLUGIN_NOT_INSTALLED",
  "pluginPackage": "com.hraps.ocr",
  "engine": "quickjs",
  "installed": false,
  "message": "插件未安装：com.hraps.ocr。请在「插件」页安装对应 Auto.js 插件 APK 后重跑脚本。",
  "hint": "这不是脚本语法错误：本机没有该插件 APK；安装后原脚本可直接重试。",
  "nextActions": [
    "打开「插件」页搜索并安装 com.hraps.ocr 插件 APK",
    "安装后重新运行脚本；若只需 OCR，可改用内置 OCR（会标记 __aijsBuiltInShim=true）"
  ],
  "builtInFallback": false
}
~~~

### 6.3 文案规则

- 不把 Java 异常/ClassNotFound 原样丢给用户；统一为「插件未安装：包名」+ 安装建议；
- 保留原始异常的 cause/rawError 字段供排障，但主 message 必须是中文可执行提示；
- Rhino hraps fallback 建议改为可机读的 warning：code=PLUGIN_BUILTIN_SHIM_USED、builtInBackend=ppocr、shim=true，而不是只有 console.warn；
- QuickJS 建议补齐与 Rhino 相同的 hraps/tomato fallback，或至少统一 PLUGIN_NOT_INSTALLED 错误，避免同脚本在两引擎表现不同；
- Node24 建议在 prelude 增加兼容别名 $plugins = require('plugins')，或文档明确 Node 必须用 require('plugins') 并 await；普通 load 的 rejection 也统一使用上面 JSON 形状。

## 7. Auto.js Pro 官方插件安装方式与我们是否支持

### 7.1 官方方式

Auto.js Pro 插件是独立 APK，不是脚本目录里的 zip：

1. 插件 APK 在 AndroidManifest.xml 的 application 下声明 metadata：org.autojs.plugin.sdk.registry，值为实现 loadDefault 的 registry 类；
2. 安装插件 APK（官方 Pro 的「插件」页下载/安装，或系统 APK 安装器手动安装）；
3. 脚本调用 $plugins.load("插件包名")；宿主通过 PackageManager 找包、反射 registry、复制插件 assets/scripts/，执行入口 index.js；
4. plugins.load 只加载已安装插件，不负责下载/安装；未安装就是 NameNotFound。

本项目内可对照：
- 插件页/安装说明：docs/architecture/项目说明.md:328（读取带 registry 元数据的真实插件，支持 APK 安装入口）
- 插件 APK 结构：docs/guides/象棋插件_打包与使用.md:34-40
- 三引擎 API 说明：docs/guides/API_REFERENCE.md:270-282

### 7.2 我们的支持范围

| 能力 | Rhino | QuickJS | Node24 |
|---|---|---|---|
| 已安装 SDK 插件 APK 通用加载 | 支持（Plugins.java） | 支持（同一 Java loader + qjs 适配） | 支持（Node24PluginLoader，需真实 mainScriptPath + Java 对象；普通 load 为 Promise） |
| 同步 $plugins.load | 支持 | 支持 | 不直接支持（无 $plugins；用 require 且异步） |
| hraps/tomato 缺失 fallback | 支持（内置 OCR shim） | 不支持（只有官方 MLKit fallback） | 不支持（只有官方 MLKit 内置构造器） |
| 官方 MLKit OCR 缺失 fallback | 支持 | 支持 | 支持 |
| 自动下载/安装 hraps/tomato 官方插件 | 不支持；需用户提供/安装插件 APK | 同左 | 同左 |
| 内置 shim 等同真实插件识别效果 | 否；仅结构兼容，模型/准确率不同 | 无 shim | 无 shim |

结论：对已安装的通用 Auto.js SDK 插件 APK，三引擎基本都支持加载；对未安装的 hraps/tomato，目前没有统一的自动安装/统一下载，Rhino 只提供 OCR 兼容 shim。真实插件需要用户自行取得并安装对应 APK；官方插件页/系统安装器是安装入口，MCP 的 $plugins.load 不是安装器。
