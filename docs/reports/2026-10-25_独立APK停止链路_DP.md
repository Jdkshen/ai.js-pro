# 独立 APK 音量上键停止链路（inrt / DP）

日期：2026-10-25  
范围：`apps/inrt` 打包运行时模板（独立 APK），不改主程序 `apps/app` 与共享 `modules/engine`。  
状态：代码与轻量 JVM 测试完成；**未跑 Gradle、未重建模板、未装真机**，最终模板由主控统一构建验证。

## 1. 结论

独立 APK 里音量上键停不掉脚本悬浮窗，根因不是单个开关，而是三条链路叠在一起：

1. **按键通道在错误的进程**：无障碍服务 `SelectToSpeakService` 在引擎 manifest 中没有 `android:process`，固定落在主进程；而 inrt 正常路由把脚本引擎、UI/浮窗放在 `:script`。旧 `onVolumeUp()` 只在当前进程调 `AutoJs.instance!!.scriptEngineService.stopAllAndToast()`，主进程的执行表通常是空的，所以按了等于没停。
2. **初始化策略错误**：旧 `GlobalKeyObserver` 在类加载时 **无条件** 注册无障碍监听并创建 `ShellKeyObserver`（root getevent），每个进程（包括 `:script`）都会执行；`init()` 反而是空实现。既没有按进程归属收敛，也可能在启动时拉起 root shell。
3. **去重状态会误伤下一次按键**：旧实现用 4 个跨源布尔做去重，且 `onKeyEvent` 的 DOWN 分支错误设置 `mVolumeUpFromAccessibility = true`。无障碍事件先把 UP 标志置位后，root 来源的下一次 UP 会被当成重复丢掉；DOWN 分支还会污染下一次 UP。

本次修复：

- 无障碍音量上键紧急停止**独立注册**，不再受「音量上键停止所有脚本」开关限制。
- `GlobalKeyObserver` 只在**主进程**注册；`:script` 的 `App.onCreate` 直接跳过。
- 主进程收到按键后走 `ScriptEngineService.stopAllByVolumeUp()`：主进程本地 `stopAll()` + hook 发**显式、非导出**广播到 `:script`；`:script` 的 receiver 只做本进程 `stopAllAndToast()`，不再回传，避免循环。
- root getevent 只在用户同时开启「音量上键停止所有脚本」和「使用Root权限自动启用服务」时启动；两者默认组合不会拉起 root（root 开关默认 false），因此不会新增启动时的 root 弹窗。
- 去重改成按 keyCode + 来源 + 200ms 窗口的纯 JVM 类，DOWN/UP 互不污染，状态不会无限残留。
- 保留 inrt 原有语义：音量下键仍是 no-op；`ui.layout` 的 `ScriptExecuteActivity` 聚焦路径仍由 shared 代码处理。

## 2. 进程映射（inrt 正常路由）

| 进程 | 组件/职责 | 音量键接收方式 | 停止落点 |
| --- | --- | --- | --- |
| `com.jdkshen.aijspro.inrt`（主进程） | `App`、`AutoJs`（`ScriptEngineService` 实例通常无执行）、`SplashActivity`、通知监听、定时任务 receiver、FileProvider；**无障碍服务 `SelectToSpeakService`** | 无障碍 `onKeyEvent` -> `stickOnKeyObserver` -> `GlobalKeyObserver`；可选 root `getevent`（仅显式开启 root 设置） | 本地 `stopAll()` + hook 广播到 `:script` |
| `...inrt:script` | `App`/`AutoJs`、Rhino/QuickJS 引擎与执行表、`InrtScriptActivity`/`LogActivity`/`ScriptExecuteActivity`/`SettingsActivity`、`InrtTaskService`、悬浮窗与 `OverlayRegistry` | 没有无障碍实例；正常不注册 `GlobalKeyObserver`。`ScriptExecuteActivity` 聚焦时走 shared 的窗口路径；其余 Activity 未拦截音量键 | 新 manifest receiver `InrtVolumeUpStopReceiver` 收广播后本地 `stopAllAndToast()`；shared 的 `stopAll()` 负责关闭本进程 `OverlayRegistry` |
| `...inrt:node24` / `:node24_1..3` | 引擎模块声明了 Node24 截图授权 Activity；inrt manifest 未声明 `Node24Service`，正常打包路由不会使用 | 不接收（没有注册按键/停止入口） | 未覆盖；若以后 inrt 接入 Node24，需要另加中继 |
| 其它 `:xxx` | 当前 inrt 没有 `:native` 等其它脚本进程 | 不接收 | 不适用 |

`InrtProcessRole` 的判定规则（纯函数、可单测）：

- 进程名为 `null`、空、`unknown` 或等于包名 -> 主进程；
- 精确等于 `包名:script` -> `:script`；
- `:node24`、`:script_2` 等都不算主进程/`:script`。

> 打包页会把 template 的 `package` 改成项目包名（`ManifestEditor.setPackageName`），所以运行时进程名是 `<项目包名>:script`，不是写死的 `com.jdkshen.aijspro.inrt:script`。本实现统一使用 `context.packageName` 拼接，未写死模板包名；receiver 的 action 字符串只是同包显式广播的标识，不用于跨应用匹配。

`unknown` 归主进程是保守处理：宁可多注册一次主进程紧急入口，也不要在进程名读取竞态里把停止入口丢掉。

## 3. 按键链路

### 3.1 无障碍主通道（默认）

```text
音量上键
  -> 主进程 SelectToSpeakService.onKeyEvent
  -> AccessibilityService.stickOnKeyObserver
  -> GlobalKeyObserver.onKeyEvent (只处理 ACTION_UP 且 !isCanceled)
  -> VolumeKeyDeduplicator（同一次按压跨源去重）
  -> onVolumeUp()
  -> ScriptEngineService.stopAllByVolumeUp()
       -> volumeUpStopAllHook（仅主进程安装）
            -> InrtStopRelay.relayToScript()
                 -> 检查 :script 是否在 runningAppProcesses
                 -> 显式广播到 InrtVolumeUpStopReceiver（process=:script, exported=false）
                      -> InrtStopRelay.stopLocal()
                           -> ScriptEngineService.getInstance().stopAllAndToast()
                           -> shared stopAll() 关闭本进程 OverlayRegistry
       -> 主进程 ScriptEngineService.stopAll()
```

要点：

- 紧急停止不看 `Pref.shouldStopAllScriptsWhenVolumeUp()`；即使脚本通过 `$settings` 把它关掉，音量上键仍停。
- `stopLocal()` 使用 `ScriptEngineService.getInstance()`，不碰 `AutoJs.instance` 的 `lateinit`，避免引擎未初始化时按键路径抛异常。
- receiver 只本地停止，不再次调用 `stopAllByVolumeUp()`，因此不会出现 main -> :script -> main 循环。
- 广播是显式 component + `exported=false`，只允许同包同 UID；不跨应用、不控制其它包。

### 3.2 窗口聚焦路径

- `ui.layout` 项目：引擎的 `ScriptExecuteActivity` 在 `:script`，`dispatchKeyEvent` 的 `ACTION_UP` 调 `stopAllByVolumeUp()`；没有 hook 时本地 `stopAll()` 已能停 `:script`。
- 主进程 legacy/fallback 脚本窗口：同一个 shared `ScriptExecuteActivity` 在 main 中运行，hook 已安装，会先把停止广播到 `:script`，再本地停 main。
- inrt 自己的 `InrtScriptActivity`（透明 trampoline）和 `LogActivity` 没有新增键拦截；它们不消费音量键。若悬浮窗所在 Activity 聚焦，主要仍靠主进程无障碍通道。

### 3.3 root getevent（可选回退）

- 只在主进程、且 `shouldStopAllScriptsWhenVolumeUp() && shouldEnableAccessibilityServiceByRoot()` 同时为真时创建 `ShellKeyObserver`。
- 旧实现是无条件创建；本次修复后，默认安装（root 开关 false）不会因为启动 App 拉起 `su`。
- root 来源和主进程无障碍来源共用同一个 `VolumeKeyDeduplicator`，200ms 内同一按键只执行一次。
- root 来源的 `onKeyUp("KEY_VOLUMEUP")` 同样进入 `onVolumeUp()`，走同一条跨进程中继。

### 4.1 与反馈的一处源码核对

反馈里说「用户音量运行设置默认 false」。当前仓库中：

- inrt：`Pref.shouldStopAllScriptsWhenVolumeUp()` 默认 **true**（`apps/inrt/.../Pref.kt`），`res/xml/preference.xml` 也是 `android:defaultValue="true"`；
- 主程序：`apps/app/.../Pref.java` 的 `isRunningVolumeControlEnabled()` 默认 **false**。

inrt 旧代码即使该值为 true，也只停当前进程，所以仍然停不到 `:script`；值为 false 时更会在 `onVolumeUp()` 里直接跳过。本次修复把紧急停止与这个开关解耦，两种取值都能停。root 回退则必须额外满足 root 开关，避免默认安装弹 root。

### 未执行 / 未验证边界

1. **没有跑 Gradle、没有重建 `template.apk`**：上面的 Kotlin CLI 检查使用临时 stub 代替真实 `AutoJs`/设置/任务类，且不覆盖真实 R/BuildConfig、Manifest merge、最终 D8/R8 与打包，仍须由主控构建验证。
2. **没有真机/模拟器**：以下都未实测：
   - `android:process=":script"` 的 manifest receiver 在目标 ROM 上能否被显式广播正常拉起/命中；
   - 无障碍服务实际连接后，HyperOS/MIUI 是否稳定转发音量键；
   - `:script` 已运行、未运行、正在启动三种时序；
   - 悬浮窗聚焦/非聚焦时按键实际落到 Activity 还是系统。
3. **无障碍是主通道**：如果用户没有启用无障碍服务，且没有开启 root 回退，音量上键不会停止；这是权限边界，不是本次代码能绕过的。
4. **按键通道只挂在主进程**：`:script` 不再启动第二份 root getevent。若主进程没有运行、无障碍也没连接（例如只被定时任务拉起 `:script`），该场景没有音量键入口；这是为了避免重复 root shell/弹窗而保留的架构边界。
5. **root getevent**：只有两个开关都开启才启动；`su` 授权/拒绝、getevent 输出格式、部分机型无权限等未验证。默认安装不会启动，符合「不新增 root 弹窗」。
6. **`:script` 存活检查**依赖 `ActivityManager.getRunningAppProcesses()`；部分 OEM 可能返回空/受限，代码会保守地照常广播。若进程刚死/刚起，存在一次跳过或额外拉起进程的竞态，未实测。
7. **OverlayRegistry 清理依赖主控已修改的 shared `ScriptEngineService.stopAll()`**；如果最终模板没有包含该共享改动，receiver 的 `stopAllAndToast()` 仍会停引擎，但悬浮窗可能残留。最终模板必须以主控版本为准。
8. **Node24 / `:native` 未覆盖**：inrt manifest 当前没有 `Node24Service`/`:native` 停止端点；若后续接入，需要单独中继。
9. **inrt 自有 `InrtScriptActivity`/`LogActivity` 未拦截音量键**：窗口聚焦路径只覆盖 shared `ScriptExecuteActivity`；若某机型把按键只送给这两个 Activity 而不送无障碍，本次修复不会命中。
10. **音量键不会被消费**：无障碍 `onKeyEvent` 返回 false，系统音量仍可能变化；这是 shared 无障碍服务原有行为。
11. **设置变更生效时机**：root 开关在 `:script` 的设置页修改后，主进程下次启动才会重新判断是否安装 root getevent；未做跨进程设置热监听。

## 6. 给主控的验收建议

1. 用包含 shared `stopAll()` 清理 `OverlayRegistry` 和 `stopAllByVolumeUp()` hook 的引擎版本重建 `template.apk`。
2. 安装独立 APK，确认：
   - 只开无障碍、音量开关开/关两种情况下，`:script` 的 Rhino/QuickJS 悬浮窗都能被音量上键停止；
   - 日志出现 `C-INRT-STOP: stop relay sent` 与 `received stop-all`；
   - `:script` 停止后 `OverlayRegistry` 无残留；
   - `ui.layout` 的 `ScriptExecuteActivity` 聚焦路径仍停；
   - 音量下键行为不变；
   - 首次启动不出现新的 root 授权弹窗。
3. 复测进程列表：停止后 `:script` 可被系统回收，主进程无障碍监听仍在。
