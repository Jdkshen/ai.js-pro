- 插件那份：`apps/inrt/build.gradle:74-103` 的 `buildApkPlugin` 依赖 `:inrt:packageRelease`，把 `inrt-arm64-v8a-release-unsigned.apk` 复制成 `plugins/apkbuilder-plugin/src/main/assets/template.apk`，并写/校验 `template-manifest.json`。`plugins/apkbuilder-plugin/README.md:11-17,26-40` 说明插件分发这份全量模板，主 APK 不再为用户不需要的打包功能付 80+MB。

- 运行时回退：`apps/app/src/main/java/.../build/ApkBuilderPluginHelper.java:27-46` 的模板查找顺序是 `/sdcard/template.apk` → 插件落地缓存 → 已安装插件 → 主程序自带 `assets/template.apk`；旧/自编包可能只有宿主内置瘦身模板。
- 两份不同步是有意/已知状态：`apps/app/src/main/java/.../autojs/build/Node24TemplateConsistency.java:34-44` 明确记录了 2026-10-30 的宿主模板与 2026-10-29 的插件模板 Node runtime 哈希不同；`docs/REMAINING_WORK.md:124` 也记录插件模板仍是旧全量，待下次插件发版用新 inrt release 重建。

**结论：两份都建议保留；插件模板需要在下一次插件发版时同步/重建，不是删除项。**
