## 3. 五项任务与独占文件

以下 `plugins/buildtools-plugin` 及其包路径为拟新增。主控若改名，要在分派前统一替换。

### A. 编译工具插件、组件清单与安装管理

目标：提供可选工具插件和可复用的组件描述/环境解析，让宿主明确知道哪些组件可用、来自哪里、如何启动。

独占：`plugins/buildtools-plugin/` 的模块 build.gradle、AndroidManifest.xml、插件入口、`.../toolchain/core/**`、插件自己的 proguard 与组件描述文件。**排除 B/C/D 各自的代码和 fixture 子目录**。根 settings.gradle、宿主 Gradle、宿主 PluginRegistry、发布脚本均由主控修改。

交付：

- 插件发现、组件版本、ABI/API 匹配、能力与依赖描述；禁止仅凭文件存在或 PATH 命中就标记 VERIFIED。
- 组件包/安装路径、SHA-256、上游地址、版本、许可证、依赖和所需空间清单；大二进制不要提交到普通 Git。
- 分阶段准备后切换生效；失败不破坏旧组件。验证中断、包损坏、空间不足、目录穿越和升级后旧路径失效的处理。
- 离线运行路径；第一次需要下载时，终端能读到进度与明确错误，不在后台无限重试。
- 与 B/C/D 明确插件 APK、数据包、DEX/JAR、native 可执行文件的归属；不要把跨 UID 私有目录默认为可访问。

验收：未安装/已安装/损坏/ABI 不匹配均可区分；独立组件可列出；主控能用描述生成真实启动参数；更新组件失败后原已用组件仍可运行。

### B. Java 源码 → class/JAR → DEX

目标：手机本地 Java 编译，复用现有 D8，输出可加载且行为正确的 DEX。

独占：插件的 `.../toolchain/java/**`、Java 编译专属测试、`fixtures/java/**`、`components/java/**` 元数据。不得直接改已有 AndroidBuildTool、engine/build.gradle、宿主 proguard 或 MCP 目录；把接入修改清单交主控。

交付：

- 评估可在 Android 上真实运行的源码编译器，并记录来源、版本与支持的语言级别。轻量编译器和完整 JDK 是不同能力；不能只实现轻量编译就声称 Gradle 所需 JDK 已齐。
- 编译器自身的运行形式必须正确：普通 JVM class JAR、DEX、手机 JDK 的使用路径分别验证；不能把桌面 JAR 直接当作可被 ART 执行的 DEX。
- `source/target` 或 release、classpath、Android API stub、编码、输出目录与诊断行列；编译器运行库与工程目标 API 的 classpath 分开。
- CLI/插件入口在独立进程运行，成功/语法错误/缺失依赖均有真实退出码和日志；禁止在宿主调用会 System.exit 的编译器 main。
- class/JAR 交给现有 D8，支持必要 lib/classpath。先明确 Java8 基线，再单独记录 Java17 能力；未验证部分写明边界。

验收：多源文件/包结构、中文和空格路径、JAR 依赖、一个 Android API 示例、错误定位、重复构建和停止编译。最终 DEX 由独立测试进程加载调用并得到预期值；不能只检查“文件非空”。不默认让宿主加载任意业务测试 DEX。

### C. C/C++ → ELF 可执行文件、SO

目标：在 Android ARM64 本地完成预处理、编译、链接和运行；交付可供 APK 阶段使用的 JNI SO。

独占：插件的 `.../toolchain/native/**`、`components/native/**`、`fixtures/native/**`、原生工具链获取/校验专属辅助脚本。不得改主程序 QuickJS/Node/OpenCV 原生库或共用 NDK 配置。

交付：

- Clang/C++、链接器、必需 binutils、头文件、Android sysroot、C++ 运行库及动态依赖的完整清单；逐项确认 Android 主机 ABI，不只检查输出目标 ABI。
- **先做可执行路径验证**：目标 SDK/SELinux、插件安装后的 nativeLibraryDir、宿主 UID 启动和依赖加载都要有证据。不能把下载解压到私有/共享目录后 chmod 作为已证明可运行的方案。
- 工具链版本和来源、ELF 依赖、许可证、压缩/安装体积；所选路径必须无需 root、无需降低宿主 targetSdk，也不依赖用户另装 Termux。
- 命令行编译一个 C 程序、一个使用 STL 的 C++ 程序、一个 JNI SO；输出 API/ABI、sysroot、C++ 库和链接选项可控。
- 配套 make/CMake/Ninja 是否纳入首批须明确说明；用于“完整 APK/Gradle 原生构建”的部分不能只给 clang 单文件样例就算完成。

验收：手机运行 C/C++ 程序得到预期输出，JNI SO 在独立测试应用加载调用成功；无缺失 DT_NEEDED；错误日志、并发任务隔离与取消不残留编译子进程。64 位插件工具和输出 SO 跑 16KB 静态检查；真正 16KB 内核运行另列待实机验证。

### D. Android 源码项目 → 签名 APK；标准 Gradle 项目

目标：补齐资源、manifest、Java/DEX、native、打包、对齐、签名和依赖链。

独占：插件的 `.../toolchain/android/**`、`components/android/**`、`fixtures/android/**`、Android 构建专属测试。需要 B 的 Java 能力、C 的原生入口和 A 的描述；依赖未完成时先用明确 fixture 接口，不能以 mock 成功充当端到端验收。

必须区分两层交付：

1. **最小原生 APK 流水线**：Manifest + res/assets + Java 源码 → 资源编译/链接、R 类、源码编译、D8、ZIP、对齐、签名 → 安装并启动。测试至少含 Activity、字符串/布局资源、assets 文件和一个依赖 JAR；再增加 JNI SO 用例。
2. **标准 Gradle Android 项目**：在手机有可运行 JDK/Gradle，固定并记录 AGP/SDK/Build Tools 组合及依赖仓库/离线缓存，真正执行 assembleDebug（测试用 --no-daemon，避免守护进程脱离任务）。验证 Gradle 调用到的 aapt2/原生工具是手机可执行版本。最小 APK 流水线通过后，这一层仍须单独验收。

还须交付：

- aapt2、平台 android.jar、对齐/签名工具的手机运行形式与依赖，不得直接调用电脑 SDK 的 Windows/Linux 主机二进制。
- Java stub JAR 与资源链接所需平台包分别说明；资源链接不能假定只有一份 classes JAR 即够。
- Gradle 依赖、插件仓库、首次下载进度、失败原因及离线复跑；固定已验收范围。若 Kotlin/Compose/其他第三方 Gradle 插件未测，明确列出，不能宣称任意 Android 工程均兼容。
- 复用现有签名/归档代码前，先区分“脚本运行模板 APK”和“源码工程构建”。绝不以替换模板 assets 冒充编译源码。
- 单独测试包名、测试签名与签名校验；不覆盖 AI.js Pro 本体，不导出生产私钥，不自动上传/发布生成的 APK。

验收：两层各自提供从干净工程到安装运行的命令、完整手机日志和 APK SHA；安装后实际界面/资源/JNI 行为正确。错误 Java、错误资源、依赖失败分别能定位；中断后可重建，旧产物不会被误当成本次成功。

交付与验收：

以下是主控定稿时必须包含的语义，不是已发布 JSON 协议：

| Diagnostics | stage、文件/行/列（编译器可提供时）、消息、退出码；原始完整日志仍可读取 |

## 6. 验证矩阵和交付格式

| 层面 | 必须给出的证据 |
|---|---|
| 编译器可用性 | 手机 ABI/API、真实 UID、启动路径、版本输出、最小试编译及实际运行 |
| Java | 多文件/依赖/Android API、class/JAR→DEX→独立进程调用结果、错误行列 |
| Native | C、STL C++、JNI SO、动态依赖、16KB 静态检查；内核实测另计 |
| APK | 干净源码构建、签名/manifest/资源/native、安装启动、Gradle 标准工程单独通过 |
| 生命周期 | 编译进行中持续输出、输入、超时、单任务停止、MCP/界面退出清理；无本轮编译进程残留 |
| 多任务 | 至少两个构建任务并存，取消一个不影响另一个；输出和产物不串任务 |
| 组件管理 | 未安装、离线、损坏、ABI 不符、下载中断、空间不足、升级失败可诊断/恢复 |
| 宿主回归 | 现有终端与 D8/Smali、网络更新泛型硬门、三引擎既有能力；K40 不参与破坏性测试 |

每个工作任务提交独立 MD，列出：修改文件、实际命令、依赖来源/许可证、设备/版本、产物 SHA、通过与未通过项、明确未做的范围。建议各自写到 `docs/reports/toolchain-20261025/A-*.md` 等独占文件，主控汇总，不同时编辑一个总报告。

每项状态只使用“未开始 / 实施中 / 待集成 / 已验收 / 受阻”；无真机产物证据不能标记已验收。接口 stub、桌面编译、文件存在、PATH 命中和 mock 成功均不等于手机构建成功。

## 7. 构建、设备与发布规则

- 先 `. ./tools/jdk17.ps1 | Out-Null`；本机 JDK17 用于开发构建，不代表手机已经有 JDK。
- 完整主界面构建保留 `-PflutterPoc=true`；仅 Java/原生修改无需重建 Flutter AOT，改 Dart 必须重建。PS 脚本含中文须 UTF-8 BOM。
- 测试日志先写文件再读，别通过管道过滤正在运行的 Gradle；以退出码判定，不把正常 stderr 当作失败。
- 只由主控在 MI8 串行安装/构建验证；每次先看当前任务，已有其他工作时等其完成。当前用户对 MI8 的安装测试授权保留，K40 业务保护保留。
- 本文**不是发布授权**。先交付可审查的候选、主程序/插件签名、体积、SHA 和验收表；发布按用户后续明确指令及 tools/publish.ps1 进行。
- 不裸跑 dev-update.ps1、不造假版本测试。候选/设备/更新源版本须重新读取再计算，不照抄本文版本号。
- 工具链插件内新增 ELF 也须纳入检查；不能只检查原宿主的 22 个 ELF。不得为通过检查降低 targetSdk、关掉 R8 或恢复不兼容的旧 native 库。
