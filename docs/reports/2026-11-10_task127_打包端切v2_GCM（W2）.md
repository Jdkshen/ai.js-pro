# task-127：打包端切到 v2（AES-256-GCM + 真 32 字节密钥）（W2）

## 一、改动清单
### 1. ApkBuilder.java（8 处）
- **导入**：去掉 AdvancedEncryptionStandard（CBC），改用引擎冻结实现 com.stardust.autojs.engine.encryption.ScriptPayloadV2。
- **字段**：String mKey / mInitVector ⇒ byte[] mKeyV2（v2 没有「String 密钥/固定 IV」这两个概念）。
- **两处载荷加密**（原来的 writeHeader + AdvancedEncryptionStandard）⇒ ScriptPayloadV2.encrypt(plain, mKeyV2, …)：
  · encryptedPayload(plain, flags)：把 v1 的 short flags 拆成 (载荷类型=高字节, 执行模式=低字节) 传进去；
  · encryptBytes(File)：flags 全 0；
  两处都不再自己写文件头（头 + 12 字节随机 IV + tag 全由 v2 API 负责 ⇒ IV 每文件不同）。
- **派生**：mKeyV2 = ScriptPayloadV2.deriveKeyV2(packageName, salt, fingerprint)（真 32 字节，不再自己拼 SHA-256、不再走 ScriptKeyDerivation.deriveKey/deriveVector）。
- **必然写字段**：scriptSalt + signatureFingerprint 仍在写 project.json 之前必然写入（task-123 已落，本轮沿用）。
- **fail-fast 两条**：① 需要密钥但拿不到指纹 ⇒ throw（文案含「不会静默降级」）；② **scriptStorage=native 且 encryptLevel>0 ⇒ throw new IOException(ScriptPayloadV2.NATIVE_UNSUPPORTED_MESSAGE)**（原生只懂 v1/CBC，v2 必须走 JVM；不静默降级）。
- **KDoc**：把「key=MD5(...)/vector=MD5(...)」的过期描述改成 v2 口径。

## 三、未验证边界 / 需要你确认的一点
1. **flags 参数语义与你的文字描述相反（请一句话确认）**：你写「flagsLow = 执行模式、flagsHigh = 载荷类型」，但冻结实现里 **第 3 个参数直接写 header[6]、第 4 个写 header[7]**（ScriptPayloadV2:105-106），而 header[6] 是 flags 的**高字节**（大端 byte6*256+byte7）⇒ 要让「低字节=执行模式、高字节=载荷类型」这个 v1 语义成立，必须传 **(载荷类型, 执行模式)**。我按**代码 + v1 布局**这么做（ApkBuilder 传 (flags>>8)&0xFF, flags&0xFF），并用真跑的测试钉住 header[6]=类型、header[7]=模式。若你的本意是「第 3 个参数就是模式」，那 ApkBuilder 与测试都要对调——**请确认这一条**。
2. ApkBuilder 的编译未离线验证（见上），真机/构建由你跑。
3. androidTest（ApkBuilderEncryptionTest）本轮只做静态改写，未在设备上执行（真机验收归你）。
4. 「native + 加密 ⇒ 明确失败」这条路径没有真机触发过（需要用户选 scriptStorage=native 且加密等级>0）。
5. 引擎侧 ScriptEncryption 的 v2 读取窗口（W1 负责）与打包端无耦合：打包端自己做加密，**不依赖 ScriptEncryption**（钉子已断言 ApkBuilder 里 0 命中 ScriptEncryption.）。
6. 旧格式点名拒绝由运行端 decrypt 抛（LEGACY_REJECTED_MESSAGE）；打包端不校验自产载荷（按你的口径）。
