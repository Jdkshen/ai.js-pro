## 1. `<clinit>` 实现（W2，方案 A）

- **机制**：生成 `com.aijs.instrumentation.AijsApplication`（`.super` = 原 `application@name`），`<init>` 只调父构造，**`<clinit>` 里 `System.loadLibrary("aijsgadget")` 且整段 `.catch Ljava/lang/Throwable;` 只 `Log.e`**；作为新的 `classesN.dex` 追加，Manifest **只把 `application@name` 指向它**——不重编资源、既有 DEX 一个字节不动。
- **接线**：`preloadMode` 枚举加 `clinit`（另有可选 `clinitTarget`）；失败码 `PRELOAD_CLINIT_UNSUPPORTED_APPLICATION`（原类 final/接口/不在 DEX 集/声明 `appComponentFactory`/已存在同名类）、`PRELOAD_CLINIT_MANIFEST_PATCH_FAILED`、`PRELOAD_CLINIT_DEX_ASSEMBLY_FAILED`，**失败不产出 APK**。
- **诚实性**：返回 `runtimeVerified=false / verificationScope=static_dex_manifest_only / timingNote`「保证早于 `attachBaseContext`；父类先初始化，故不保证早于加固壳自身 native 初始化」；`assessment()` 的 `classInitializer.implemented=true`（顶层与 `dtNeeded` 内两处同源），**provider / dt_needed 的 `earlyLoad`/`preloadImplemented` 仍为 false**。

| 工具 | 改动 | 默认值 |

| file_search | `recursive` 移出 required | true |

## 6. 未做 / 边界

2. `appComponentFactory`（Android 10+）场景、壳把 Application 放在加密/动态加载 dex 的场景：工具会**明确失败**（设计取舍），未在真实壳样本上验证。

4. `file_replace_text.expectedReplacements=-1` 意味着默认不做替换数校验（取舍已记录）。
