# 象棋算力结论与参数开放（含规则胜前置）· 2026-09-25

回答用户问题：「是算力不够还是怎么样，赢不了对面的？」

## 结论：算力不是主要矛盾

| 依据 | 内容 |
|---|---|
| 对手底牌（09-23 取证） | 「特级大师」= 游戏内置 Pikafish：`libpikafishso.so` + `assets/pikafish.nnue`（34MB 旧网络）、`go depth 25 movetime 5000`、**单核**、传完整 `moves` 历史 |
| K40 深度实测（`tools/pikafish-depth-probe.js`，50.7MB NNUE） | 开局 1s/2线程 = 18 层、10s/2线程 = 23 层；中局 3s = 16、10s = 20、30s = 23；**中局 10s/8 线程反而 18** |
| PC 深算对照（`blunder-hunt.py`） | 对手 depth25 的选点 与 我方 8s（25~34 层）在 **9 个关键节点着法完全一致**；拉到 20s（depth 54）路线不变 |
| 战况累计（PC 链，09-23） | **0 胜 15 和 13 负** —— 「赢不了」的 15 和是同档互掐的正常结果，**13 负才是真问题** |

⇒ 同档引擎 + 双方不失误 = 稳和；靠「算得更深」买不到胜势（20s 只把深度 36→54，路线不变）。
⇒ 输的那些局要按**链条失误**查（报告里抓到过：幻影清理把贴脸将军的黑车当分身删掉 → 双车绝杀没应；
双击把棋盘点放大等），而不是怀疑算力。

## 本次改动（0.6.17）

### 1. 参数开放到悬浮窗

参数行由两列改为**三列**：算棋滑条 / 线程滑条 / **哈希按钮**。

- 算棋滑条上限 10s → **20s**（残局加时；实测 10s→30s 只 +3 层，20s 是折中）；
- 哈希按钮点按换档 **64 → 128 → 256 → 512 MB**，与另两个参数一样写 `storages` 持久化；
- 哈希改档后 `configurePikafish` 把引擎标记为需重启，**下一次算棋**由原生会话应用（档位表之外的值不收）；
- 用户给的目标配置现在可纯手工在面板上摆出：**算棋 8.0s + 线程 2 + 哈希 256M**
  （等价的 autorun：`{"movetimeMs":8000,"pikafish":{"threads":2,"hashMb":256}}`）。

⚠️ 线程仍建议 **2~3**：实测 K40 上 8 线程同局面更浅（nps 只涨 ~1.6×，被四核调度的开销拖平）。

### 2. 「规则胜」的前置条件可见化（不碰引擎与规则）

规则胜 = 让 Pikafish 靠**完整着法历史**自己判对手的长将/长捉犯规。前提是历史必须传进去且是 `complete`：

- 启动日志新增「**引擎历史通道**」自检：宿主是否有 `$pikafish.analyzePosition` ——
  没有的话引擎只按当前 FEN 搜，重复局面/长将判罚**用不上**（以前是静默退回，日志看不出）。
- 运行时跟踪 `positionTracker.historyStatus`，**变化时**记一行：
  - `complete` → 「着法历史：完整（引擎能判长将/长捉 —— 规则胜走的就是这条）」；
  - `partial` / 无 → 「⚠ …引擎看不到完整重复局面…想吃规则胜：先换局，停在标准开局，再点「轮到我」」。
- 进度行第三行最前面加 `历史 完整/部分/无`；换局（新会话）后状态重新报一次。
- 驱动算棋日志细化（以前四种情况都写「当前FEN」）：
  `历史 完整` / `历史 部分` / `历史 不可用（宿主缺 analyzePosition）` / `历史 无（未确认局面）`。

想走规则胜：**从标准开局建立完整历史**（面板 `NEW_SESSION` → 停在标准开局 → 点「轮到我」），
中途接管（`setPartial`）或基准被改正（`downgrade`）都会退成 `partial`，规则判罚就没了。

### 3. 配套：面板加载冒烟（PC）

新增 `tools/panel-load-smoke.js`（PC 专用）：给最小宿主桩后 `require` 两个入口脚本，只验证**模块加载期**。
本次靠它发现 **哈希常量必须定义在顶层 `XML` 构建之前**（`XML` 在模块加载时就用到
`HASH_BTN_W`/`HASH_DEFAULT`，放到后面会直接 TDZ 报错、面板起不来）。

为什么需要它：`tools/run-regress.js` 只覆盖 `src/**`，**两个入口脚本不在里面**；而这类错误
`node --check`（语法）也看不出来 —— 真机表现是面板直接起不来。
用法：`node tools/panel-load-smoke.js`（默认悬浮窗入口）/ `node tools/panel-load-smoke.js main.js`。

## 证据与边界

- PC：`node tools/run-regress.js` —— 场景 **11/11**、自检 **307/307**、契约 **19/19**；
  留档 `reports/regress/rg-2026-09-25-params-history.txt`；面板加载冒烟 `PANEL LOAD OK`。
- **未做真机验证**：三列参数行在小屏/大字体下的显示（哈希列 200px 基准宽）、哈希换档是否被原生会话真正应用、
  完整历史下引擎是否真的走出「逼对手犯规」的着法。
- 同档引擎没有「保证取胜」的参数；能稳和，赢要靠**规则**与**对手失误**。
