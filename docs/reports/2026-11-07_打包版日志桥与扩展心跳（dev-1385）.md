# 打包版日志桥 + VSCode 扩展心跳（dev-1385）

> 用户先问「为什么后面日志 VSCode 上不打印了」，又说「ab」= A/B 两个方案都做。
> A = 让**打包后的独立 APK**也能在 VSCode 看日志；B = 给扩展加**日志心跳**，一眼分清「脚本静默」还是「链路断了」。

## 一、先定位：为什么打包版没有日志

Lead 扫了两份打包模板的 dex（宿主瘦身模板 + 插件模板）：

| 关键字 | 宿主瘦身模板 | 插件模板 |
|---|---|---|
| `DevPluginServer` / `DevPluginFrames` | **no** | **no** |
| `client_version` / `device_id` / `read_file` / `inspect_layout` | **no** | **no** |
| `HostConsoleSink` / `ScriptHostService` | **no** | **no** |
| `GlobalConsole` | YES | YES |
| `9317` | no | no |

→ 结论：**打包版压根没有调试通道**，只有宿主 app 有。所以打包版在 VSCode 里永远是空的。

（顺带排除一个误报：设备上每 30 秒一次的 `SocketException: Broken pipe` 来自 **MT 管理器 `bin.mt.plus`**，与本项目无关。）

## 二、A：打包版 log-only 日志桥

### 设计（安全优先）

| 项 | 取值 |
|---|---|
| 能力面 | **只发日志**：仅处理 `hello` 握手 + `log` 帧；`read_file`/`screenshot`/`inspect_layout`/任何 `command` **一律忽略** |
| 进程 | **只在 `:script` 进程**（脚本日志只进 `:script` 的 `AutoJs.globalConsole`；挂主进程收不到） |
| 默认 | **关闭** |
| 开关 | 打包项目 `project.json` → `launchConfig.logBridge`（打包页「VSCode 日志」写入）；另有调试逃生口 `SharedPreferences: inrt_log_bridge_enabled` |
| 端口 | `9317`；被占用时**不崩**，每 30s 重试 |
| 协议 | 与宿主一致：设备先发 `hello`，再读客户端 hello（`client_version >= 1`）；日志帧 `{"id":N,"type":"log","data":{"log":"…"}}` |

### 改动

| 文件 | 内容 |
|---|---|
| `apps/inrt/.../inrt/debuglog/InrtLogFrames.java`（新，105 行） | 帧编解码 `[int32 len][int32 type][payload]`，type 1/3，256MB 上限 |
| `apps/inrt/.../inrt/debuglog/InrtLogBridge.java`（新，473 行） | 9317 监听、hello、只发日志、命令帧丢弃、单线程 writer、`try/finally` 防重入、bind 30s 重试 |
| `apps/inrt/.../script/InrtScriptThreadHost.java`（+175） | `:script` 的 AutoJs 就绪后启动；`shutdown()` 停止；`ConsoleImpl` 日志源适配；读 `assets/project/project.json` 或 pref |
| `apps/inrt/src/test/.../InrtLogFramesTest.java`（新） | 帧往返 / gzip / 超限拒绝 / 本地 socket hello+log / 命令帧忽略 |
| `modules/engine/.../project/LaunchConfig.java` | 新增 `logBridge`（`@SerializedName`，默认 false）+ getter/setter |
| `apps/app/.../autojs/build/ApkBuilder.java` | `AppConfig.logBridge` 字段 + 从工程配置解析 + 写进产物 `project.json` + `setLogBridge()` |
| `apps/app/src/flutterpoc/.../PocPackaging.java`、`PocWorkspace.java` | 新建工程的 `launchConfig` 默认带 `logBridge:false` |
| `flutter-ui/lib/project_page.dart`（+13/−1）与 widget 测试 | 打包页「VSCode 日志」开关，读写 `launchConfig.logBridge` |

### 真机验证（K40，用「打包版运行时」= inrt 模板包，链路与打包版同源）

**⑤ 模板**：宿主瘦身 `19,811,683 B / sha 47D9C4EE…`、插件 `88,445,288 B / sha EEC94C5C…`，两者 `classes3.dex` 均含 `InrtLogBridge`/`InrtLogFrames`/`log bridge started`。

### 踩坑（已记录）

`:inrt:dexBuilderRelease` 在受限 JVM（`-XX:+UseSerialGC -XX:TieredStopAtLevel=1`）下报 **`Out of space in CodeCache for adapters`** → **重建模板必须清空 `JAVA_TOOL_OPTIONS`**（app 构建才用受限参数）。

## 三、B：VSCode 扩展日志心跳（0.3.7）

| 项 | 内容 |
|---|---|
| 新模块 | `vscode-extension/src/logHeartbeat.ts`（纯逻辑、不 import vscode、可注入时钟） |
| 行为 | 静默 ≥ 阈值 → `[设备] ⏱ 链路正常，已收 N 行；脚本静默 45s（最近 23:10:02）`；静默 ≥ 2×阈值后恢复 → `[设备] ▶ 日志恢复（静默 95s）` |
| 命令 | `aijspro.logStatus`（随时打印每连接：已收行数 / 最近日志 / 静默时长） |
| 配置 | `aijspro.logHeartbeatSeconds` 默认 **30**，`0` 关闭；只在静默时输出，不刷屏 |
| 测试 | `test/logHeartbeat.test.cjs` **7/7**（未静默/静默/恢复/0关闭/多连接独立/每 tick/statusLines） |
| 出厂 | `typecheck 0`、`build 0`、`npm run package` → **aijspro-vscode-0.3.7.vsix**、`code --install-extension --force` 成功、`--list-extensions` 显示 `0.3.7` |

判定口径（写进 README）：面板出现「已断开/连接失败」= 扩展侧掉线；只有心跳没有新行 = 链路正常、脚本没输出；连心跳都没有 = 面板不是当前这个（或窗口没重载）。
