## 二、打包版跑不了 / 受限的类型（附证据）

| 类型 | 结论 | 证据 |
|---|---|---|
| **Node 引擎工程** | 打包版**靠内嵌 `libnode.so` + `:node24` 进程**跑；但 `features.nodejs=disabled` 的产物**直接跑不了** | `assets/node24/**` + `source-engine-upgrade/**` 是 node 运行时/CLI 的资产（`McpEngineDiagnostics` 的 `NODE_ASSET_PREFIX`）；该开关会把它们剔掉（条目 27→0，Lead dev-1464 真机）。**未核**：`.node.js` 在 `:node24_N` 里的实际拓扑 |
| **需要无障碍的样例** | 打包版能跑，但**先要用户手动开无障碍 + 装包后 rebind** | `AccessibilityCheck` 五态（task-44/46）；「装包/强停后必须 rebind，否则本地直订 0 事件」（task-64 操作事实） |
| **需要悬浮窗的样例（悬浮控制）** | 能跑，但**必须先授悬浮窗权限** | `OverlayPermissionCompat`（无 `data` 的 `MANAGE_OVERLAY_PERMISSION` 自动补 `package:`，仍失败回退 `FloatingPermission.manageDrawOverlays`，task-77） |
| **`自定义ABI` 声明 v7a** | **v7a 现不可产出** ⇒ 产物只有 arm64-v8a，声明 v7a 只出 warning | dev-1464/1465 + task-102：插件模板 v7a 0 条、`libppocr` 只有 arm64；`AbiPolicy` 策略是「≥1 可产出 ⇒ warning 不失败」 |
| **需要网络的样例**（dsh 手机客户端 / Vue2+Vant / React） | 能跑但要网络；dev-server 类在打包版**未核** | 扫描标记 `net`；打包版没有 dev server（未核） |
| **`removeOcr=true` 产物里的 `$ocr`** | 能跑但 OCR **点名报错**（不是崩溃） | task-99/105/107：三引擎同句「OCR 能力未随包（optimization.removeOcr=true）…」 |
| **`removeOpenCv=true` 产物里的图色/SIFT** | **跑不了**（OpenCV libs 被剔） | task-63 的 `removeOpenCv` 策略（默认 false）；dev-1465 只对 OCR 做了 A/B，**OpenCV 的 A/B 未做** |
| **ImGui/浮窗项目 + `activity.*`** | 会**保持 headless**（有意） | `ScriptHostRouting.kt:33` 的 ImGui 判据（task-114） |

## 三、建议真机跑的 6 个代表样例（覆盖 UI/浮窗/图色/node/协程/权限）

| 顺序 | 样例 | 覆盖 | 期望（一句话） |
|---|---|---|---|
| 1 | Rhino 引擎/复杂界面/使用Android原生界面 | **UI + `activity.*`** | 界面出、`activity` 不再 ReferenceError（task-78 靶子） |
| 2 | Rhino 引擎/项目与打包/悬浮控制 | **浮窗 + engines + 权限** | 悬浮窗出现；无权限时给可抄文案 |
| 3 | Rhino 引擎/图片与图色处理/找图 | **图色/找图** | 匹配出结果且无 `UnsatisfiedLinkError` |
| 4 | Node 引擎/Node.js/脚本引擎与通信/Node.js启动Rhino引擎与通信 | **Node + 跨引擎** | 两引擎互通（注意用的是**默认产物**，不是 nodejs=disabled） |
| 5 | Rhino 引擎/协程/ui中使用协程 | **UI + 协程** | 界面出、协程回调正常 |
| 6 | QuickJS 引擎/项目与打包/dsh 手机客户端 | **QuickJS + UI + 网络**（权限类差异顺带看运行时申请） | 界面出并能联网 |
