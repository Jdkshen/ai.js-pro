# Node 原生资源与动态回调修复验收

2026-11-03。对应[原始问题报告](2026-11-03_Node原生界面编译资源加载失败.md)。LAN 自动更新源仍为 dev-1318；本轮修复候选，不切换更新源，不 push。

## 1. 两个独立根因

**第 53 行 BottomNavigationView 崩溃来自平台 API 副本。** 新增 `io.github.reandroid:ARSCLib:1.4.0` 的 JAR 包含 `android/content/res/XmlResourceParser`、`android/util/AttributeSet` 及四个 `org/xmlpull/v1` 类型。R8 将它们作为程序类型参与优化；最终 dev-1318 DEX 中保留 5 个相关定义。其 `SupportMenuInflater.inflate` 实际被编译为：

```java
this.mContext.getResources().getLayout(i); // 返回值被丢弃
AttributeSet attrs = Xml.asAttributeSet(null);
parseMenu(null, attrs, menu);
```

排除这些副本后，dev-1324 反编译恢复为：

```java
layout = this.mContext.getResources().getLayout(i);
AttributeSet attrs = Xml.asAttributeSet(layout);
parseMenu(layout, attrs, menu);
```

同一进程的反射调用正常，直接调用错误，正与该编译产物相符。原报告的“资源挂载方式是根因”被排除，不需要 ResourcesProvider、ApkAssets、删除 app:menu 或退回 legacy inflater。

**M3 网格空白来自动态 DEX 的空值判断写反。** `Node24DirectDexGenerator.emitReturnFromObject` 原本使用 `if-nez v0, :default_zero`，有效值跳到默认 0/false，而 null 走拆箱。JS 的 `getItemCount()` 确实返回 8，Java 布局侧却读到 0；View 已挂载、有正常尺寸且未 suppressLayout。现改为 `if-eqz`，只对 null 返回默认值。此缺陷影响动态 Java 子类的所有基本类型返回值。

## 2. 修改

- `apps/app/build.gradle`：固定上游版本，构建 Android 专用 ARSCLib JAR，排除 `android/**`、`org/xmlpull/v1/**` 和失效签名文件，保留资源处理实现。JVM 单测单独依赖实际 XML Pull API。
- `tools/check-android-platform-shadowing.py`：扫描 JAR `.class` 及 APK 每个 DEX 的 class_defs，拒绝平台类型定义，允许普通 API 引用；损坏文件拒绝放行。
- preBuild、候选构建、publish 和 dev-update 接入检查；复用已有 APK 也要在修改在线更新文件前通过检查。
- `Node24DirectDexGenerator.java`：修正空值分支。
- 引擎回归检查实际遍历生成 DEX 的返回路径和分支偏移，验证八种基本类型保留有效值，并验证 null 返回默认值。
- 扫描器测试覆盖普通引用、多 DEX、污染 JAR、正常实现和损坏 DEX。
