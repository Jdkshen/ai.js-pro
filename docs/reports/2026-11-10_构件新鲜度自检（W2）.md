# 构件新鲜度自检（W2 / task-88）

## 0. 为什么要有它（今天两次真机事故）
1. apps/app/src/main/assets/template.apk 是**签入的二进制**：引擎/inrt 改动后不重建 ⇒ 打包版一直跑旧引擎（dex 里 SjbcApi/ScriptHostRouting/MultiProcessPrefs 全 0 命中，SJBC 首测被误判成「功能没实现」）。
2. output/flutter-poc/payload/jniLibs/<abi>/libapp.so 默认**复用锁定 payload**：flutter-ui/lib 改了不加 -RebuildAot ⇒ UI 文案永远看不见。

## 1. 交付：tools/check-artifact-freshness.ps1
~~~
pwsh -File tools/check-artifact-freshness.ps1                 # 默认：mtime 判据
pwsh -File tools/check-artifact-freshness.ps1 -Deep           # 追加内容级判据（推荐）
pwsh -File tools/check-artifact-freshness.ps1 -Deep -Json     # 机器可读
# 参数：-Root（假目录测试用） -TemplatePath -PayloadDir -SkipTemplate -SkipAot -Deep -DeepStrict -Json -NoFail
~~~
判据：
- 模板：apps/app/src/main/assets/template.apk 的 mtime vs「影响模板的源集合」最新 mtime（modules/*/src/main/**、apps/inrt/src/main/**、apps/inrt/build.gradle*）。
- AOT：output/flutter-poc/payload/**/libapp.so 的 mtime vs flutter-ui/lib/**（+ 两个 pubspec）最新 mtime。
- -Deep（模板侧，可靠）：在 template.apk 的 classes*.dex 里找 SjbcApi / ScriptHostRouting / MultiProcessPrefs（只在源码里确实存在该名字时才要求，避免重命名误报）；内容级通过时把 mtime 的 STALE 翻成 FRESH（正是 checkout 打乱 mtime 的假阳性）。
- -Deep（AOT 侧，仅提示）：见 §5 —— 明文搜索被实测证伪，永远只报 WARN、不做门禁。
- -DeepStrict：把模板的内容级不一致算 STALE（AOT 侧仍只 WARN）。
输出：每行 FRESH / STALE(kind=..., reason, newest=<file>@<time>) / WARN，末行「结论：FRESH / STALE（N 项）」；退出码 0/1（-NoFail 可强制 0）。

## 2. 自检的测试（三态 + JSON）
~~~
node tools/tests/artifact-freshness.test.mjs      # RESULT 4 artifact-freshness checks passed
~~~
临时目录 + 假 mtime（不依赖真实大文件、不跑 gradle）：① FRESH（两行 FRESH、exit 0）② STALE(template)（exit 1，且给出「先跑 build-slim-template.ps1」）③ STALE(aot)（exit 1，且给出「加 -RebuildAot」）④ -Json 形态（stale=true，checks 里能定位 aot）。测试自动挑 pwsh/powershell（本机只有 Windows PowerShell 5.1）。

## 3. 接线补丁（build-release-candidate.ps1，由 Lead 落）
param 里加一个开关：
~~~powershell
    # 明确跳过构件新鲜度自检（不推荐：会静默打进旧引擎/旧 UI）
    [switch]$SkipFreshnessCheck
~~~
在 payloadDir 赋值那一行（约 69 行）之后、其余校验之前插入：
~~~powershell
# ---- task-88：构件新鲜度自检（模板 / AOT 静默过期是今天踩过两次的坑）----
if (-not $SkipFreshnessCheck) {
    Write-Host '[0/5] 构件新鲜度自检（模板 / Flutter AOT）' -ForegroundColor Cyan
    $freshnessArgs = @{ Root = $repo; Deep = $true }
    & (Join-Path $repo 'tools/check-artifact-freshness.ps1') @freshnessArgs
    if ($LASTEXITCODE -ne 0) {
        throw @'
构件已过期（STALE）：这次 release 会把旧引擎 / 旧 UI 打进包。
· STALE(kind=template) → 先跑：.\tools\build-slim-template.ps1
· STALE(kind=aot)      → 加 -RebuildAot（或先跑 tools/flutter-poc/build-aot.ps1）
· 只是本地试验要强过：加 -SkipFreshnessCheck（不推荐）
'@
    }
}
~~~
建议默认用 -Deep（不加 -DeepStrict）：mtime 判据当门禁，内容级只给信息，避免启发式误报挡死出包。

## 4. 第 ④ 条（build-slim-template.ps1 的坑）——已由 Lead 修复，我只做复核
Lead 在 ErrorActionPreference = Stop 之后加了 PSNativeCommandUseErrorActionPreference = false（tools/build-slim-template.ps1:34-37）。复核结论：
- 根因不止 JAVA_TOOL_OPTIONS：gradlew 把「注: …使用了已过时的 API」这类提示写 stderr，PowerShell 5.1 下被当成 NativeCommandError，Stop 语义直接中止整个脚本（Lead 连撞两次）。
- 该行只让原生命令的 stderr 不再升级为终止性错误；真正的失败仍由 LASTEXITCODE 判定（脚本里 packageRelease 与 verify 两处都在查）⇒ 语义正确、不漏失败。
- 我没有改这个文件（避免与 Lead 冲突）。

## 5. 本仓库实测（2026-11-10，本机）
~~~
[FRESH-CHECK] template dex markers: required=[SjbcApi,ScriptHostRouting,MultiProcessPrefs] missing=[]
FRESH(kind=template, 模板不旧于引擎/inrt 源集合) newest=modules/engine/.../QuickJsHostBridge.java@2026-11-10T01:39:16Z
FRESH(kind=aot, payload 不旧于 flutter-ui 源码) newest=flutter-ui/lib/project_page.dart@2026-11-10T01:32:14Z
WARN(kind=aot-deep, payload 里明文搜不到最新 Dart 文案（快照编码，搜索不可靠 → 仅提示）)
[FRESH-CHECK] 结论：FRESH（模板与 AOT 都跟得上源码）   → exit 0
~~~
- payload mtime 09:35:34 > project_page.dart 09:32:14 ⇒ AOT 确实是新的一版（与 dev-1456/1457 重建时间一致）。
- AOT 明文搜索被实测证伪：连 K40 截图里已确认存在的文案（加密等级 / 脚本和加密 / 运行库与资源 / SJBC 资源目录）在 libapp.so 里明文 UTF-8 全部找不到 ⇒ Flutter AOT 字面量不是明文存储 ⇒ 该判据只配做提示（已写进脚本注释；-DeepStrict 也不提升它）。
- mtime 判据对源集合 glob 敏感（把 test/ 排除前后，模板那条在 STALE↔FRESH 间翻转过）⇒ 单靠 mtime 会误判，靠模板侧 -Deep（dex 内容）兜住。

## 6. 未验证边界
1. 未跑构建/装机/发布/git；自检只读 mtime 与 zip 条目，未触发 gradle。
2. 影响模板的源集合是手工维护的列表（modules/*/src/main、apps/inrt/src/main、apps/inrt/build.gradle*）；将来新增会进模板的模块要同步，否则漏判。
3. AOT 侧只有 mtime 能当门禁：若 checkout/复制把 payload mtime 弄新而内容旧 → 假 FRESH（明文搜索不可靠，没法内容兜）。缓解建议：让 build-aot 往 AOT 写一个可 grep 的版本戳（如 versionCode 字符串），下次就能做真内容判据。
4. 只在 Windows PowerShell 5.1 跑过（本机无 pwsh 7）；PS1 必须存为 UTF-8 with BOM，否则 5.1 按 ANSI 读中文会解析失败（本次踩到，已保持 BOM）。
5. -Deep 模板判据依赖三个类名存在；都被重命名时不报（有意保守）。
