# DP 任务 1：Node M3 示例首屏 setup 调度与重建（2026-10-24）

> 此为 DP 首次交付记录；主助手的后续修正、实际构建和最终 MI8 验收以[五项优化任务与验收](2026-10-24_五项优化任务与验收.md)为准。

> 本文为 DP 首版交付记录。主助手真机验收发现宿主导航绑定不可依赖，已恢复显式导航，并补抽屉返回和 await 中途关闭保护。最终实现、性能和验收以 [五项优化任务与验收](2026-10-24_五项优化任务与验收.md) 为准；下文“仅宿主导航监听”的结论没有直接采用。

## 结论

在 `使用Android原生界面/main.js` 内做了有界的调度/幂等改动，不修改核心 UI 宿主、不新增跨库 Java helper、不删除示例功能：

1. **可见内容优先**：`afterFirstFrame` 后依次执行控制台页监听 → Grid → 下一拍 Drawer；`setAdapter` 后先让出一拍再 setup 离屏 Drawer。
2. **控制台 binding 真正懒取**：`onContentViewSet` 不再提前访问 `binding.console`/`binding.toggleButton`，首次进入第 1 页（含恢复时已停在第 1 页）才取并注册一次。
3. **Drawer 菜单懒初始化**：邮件标题和菜单点击监听推迟到 Drawer 第一次滑出；抽屉图标/开合动画仍由 `ActionBarDrawerToggle` 负责。若 setup 完成前抽屉已被点开，补一次 `isDrawerOpen/isDrawerVisible` 检查。
4. **去重 listener**：删除示例对 `BottomNavigationView.setOnItemSelectedListener` 和翻页时 `setSelectedItemId` 的重复注册/同步，改由 dev-1240 宿主 `NodeUiHost.wireNavigation` 负责；示例只保留控制台懒加载所需的 ViewPager 监听。
5. **重建/关闭安全**：用 contentView 身份代替一次性布尔 flag；Activity 重建后新 view 会重新 setup；旧 view 的延迟回调、关闭后的回调都丢弃。这同时修复了 dev-1240 中 `_deferredSetupStarted` 不随重建复位、新内容不再 setup 的问题（静态代码路径）。

未做设备/Gradle/ADB 验证，**不声称首帧或整页耗时已改善**；本轮只改变调度顺序与懒初始化边界。

## 基线与本轮实际检查

- 基线：`e5660dca` / dev-1240。
- 参考：[原生 setup 延迟与控制台懒加载](2026-10-24_原生setup延迟与控制台懒加载.md)、[布局与绑定桥批量优化](2026-10-24_布局与绑定桥批量优化.md)。
- 旧报告 dev-1240 单轮阶段耗时：`_setupViewPager` 978→1112ms（134ms）、`_setupDrawer` 1123→1363ms（**240ms**）、`_setupGrid` 1376→1558ms（182ms）；控制台当时已不在启动阶段。按该阶段记账，本轮把 Drawer 移到 Grid 之后，可让 Grid **少等一个 Drawer 阶段**；这是调度推断，不是本轮实测。
- 静态路径证据：
  - `NodeUiHost.wireNavigation`（`modules/engine/src/main/java/com/stardust/autojs/engine/node24/NodeUiHost.java:2121`）已安装底部导航 ↔ ViewPager、Toolbar → Drawer；`NodeUiActivity.onCreate` 在 inflate 后调用 `wireNavigationFor`（`apps/app/src/main/java/com/jdkshen/aijspro/engine/NodeUiActivity.java:165`）。
  - `JsViewPager.onFinishDynamicInflate` 会自建 adapter（`JsViewPager.java:27`），但编译资源路径由系统 `LayoutInflater` 直接 inflate（`NodeUiRenderFix.inflateFramework`，`NodeUiRenderFix.java:51`），不会触发该回调，所以 `initAdapterFromChildren()` 必须保留。
  - `activity_main.xml` 在布局 inflate 时已 include `page_main`/`page_console`/`page_settings`；设置页没有 JS setup，只有 XML 控件。仅改 `main.js` 无法安全地把这些页面/控件改成懒构建。
  - dev-1240 的 `onContentViewSet` 即使用户从不打开控制台，也会提前取 `console`/`toggleButton`；`_deferredSetupStarted` 不随 Activity 重建复位，新 contentView 会跳过整个 deferred setup；`_consoleReady` 同样不会复位，即使 setup 重跑也不会初始化新控制台。

## 代码改动（仅 `main.js`）

文件：`apps/app/src/main/assets/sample/Node 引擎/Node.js/Node.js中使用UI/使用Android原生界面/main.js`

- **状态与生命周期**：`_setupView` 记录当前 contentView，`_closed` 标记真正关闭；`onCreate` 清空旧 view，`onDestroy` 置关闭位并清标志。`onContentViewSet` 对同一 view 幂等，只注册一次 fab 监听。
- **调度**：`_isCurrentView(view)` 同时校验身份、关闭位和 `isFinishing()`；`_scheduleDeferredSetup` 在 `afterFirstFrame` 回调入口再次校验；`_setupDeferred` 顺序为 `_setupViewPager(view)` → `await _setupGrid` → `setTimeout(0)` → `_setupDrawer`，每项独立 try/catch。
- **控制台**：`_setupConsoleLazy(view)` 在第一次 page=1 时懒取 binding；`_setupViewPager` 在加完监听后检查 `getCurrentItem()===1`，覆盖重建/恢复时已停在控制台页的情况；`_consoleReady` 在每次新 contentView 时复位。
- **Drawer**：`_setupDrawer` 保留 `setSupportActionBar`、`ActionBarDrawerToggle`/`syncState`/`addDrawerListener(toggle)`；新增一个 `DrawerLayout.DrawerListener` 接口代理，在首次 `onDrawerSlide(offset>0)`/`onDrawerOpened` 调用 `_setupDrawerMenu(navigation)`；`_setupDrawerMenu` 用 `_drawerMenuReady` 保证只配置一次。
- **ViewPager**：不再覆盖宿主底部导航监听，也不再在翻页回调里重复 `setSelectedItemId`；只保留 `onPageSelected(1)` 触发控制台懒加载。`initAdapterFromChildren()` 保留（编译资源路径需要）。
- **未改**：页面 XML、Grid 的 8 条初始数据/8 张图、`ui.inflateBatch` 8 个 item、控制台日志等级逻辑、FAB/Snackbar、About 菜单、返回路径、权限/设置页控件。

## 未做与限制

- **没有构建/装机/设备测量**：按任务约束未启动 Gradle/Flutter、未用 ADB、未发布。首帧、首批卡片、首次抽屉/日志的 P50/P95 均未在本轮测量；不能根据本报告宣称具体毫秒收益。顺序调整也没有减少 ViewPager/Grid/Drawer 的原生 setup 总工作量，只是让可见 Grid 不再排在离屏 Drawer 之后，并减少了重复 listener 与 eager 菜单调用；不能据此宣称整页 setup tail 降低。
- **页面 View 仍 eager inflate**：`activity_main.xml` 在进入 JS 前已 include 三个页面，设置页/控制台页控件由 XML inflate；要真正懒构建页面需要改 XML/宿主，超出本任务文件范围。本轮只做 JS 侧 setup 懒加载。
- **Drawer chrome 未完全懒化**：图标/开合动画和 `setSupportActionBar` 仍在首帧后的 setup 中；只把菜单内容/监听推迟。完全推迟会影响抽屉图标和既有菜单路径。
- **依赖 dev-1240 宿主**：底部导航 ↔ ViewPager 同步现由 `NodeUiHost.wireNavigation` 提供。若把本示例放到没有该 host wiring 的旧宿主，底部导航点击同步会缺失（控制台懒加载的 page listener 仍在）。本示例随 dev-1240 分发，未声明旧宿主兼容。
- **首次打开抽屉**仍可能执行 `ActionBarDrawerToggle`/菜单懒配置；若用户恰在 Drawer setup 前打开，`isDrawerOpen/isDrawerVisible` 检查会补配置，但仍需真机确认接口代理回调时序。
- **Grid 批量预生成未缩减**：8 个 item 是首批网格内容的一部分；改成少量预生成会把 inflate 成本移到滚动，现有报告没有证据支持，故未做。
- **About/设置/权限/FAB/返回**：未改相关代码路径；设置页本身只有 XML 控件，无 JS 行为可测。
