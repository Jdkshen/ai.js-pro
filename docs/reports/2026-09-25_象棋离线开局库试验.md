# 象棋离线开局库试验（2026-09-25）

## 目的与边界

给现有 AI.js Pro 象棋脚本加入一个**可撤销的本地开局库试验**。本试验只覆盖开局；中残局仍由设备上的 Pikafish 搜索。它不能单独解决上一局在 109 回合后和棋的问题。

运行时没有网络请求。试验库放在手机 `/sdcard/xiangqi-p4/opening-book-vetted.json`；没有此文件、局面未命中、着法被排除或不合法时，`engine-router` 原样调用 Pikafish。用户显式设置固定搜索层数时也保持实时搜索，不走试验库。删除该文件并重启脚本即可关闭试验；同步调用可显式传 `openingBook: false`。

## 来源与授权

- 棋谱来源：[Wukong xqdb 的 40,711 局 ICCS 棋谱](https://github.com/maksimKorzh/wukong-xiangqi/blob/main/xqdb/xqdb/xqdb_masters_40711_UCI_games.pgn.zip)。仓库 README 说原始对局采自 wxf.ca，仓库代码标注 MIT；原始棋谱的再分发许可还须核实。因此原始压缩包和生成的试验 JSON 都留在 `.artifacts/` 或手机本地，**没有打入 APK、没有发布**。
- 该批 PGN 没有可靠的胜负结果字段。**出现频率不是棋力评分**，不能据此单独自动走棋。

## 构建过程

1. 提取 PGN 到 `.artifacts/opening-book-trial/`。
2. `node tools/build-opening-book.js <PGN> <中间JSON> 12 8`：按完整着法串去重，使用项目自己的象棋棋规校验前 12 个半回合，形成「棋盘布局 + 轮到谁 → 候选着法与频次」。
3. `python tools/vet-opening-book.py <中间JSON> <试验JSON> --engine <pikafish.exe> --limit 120 --movetime 700 --max-loss-cp 20`：在电脑上用 Pikafish MultiPV=3 复核频次最高的 120 个局面；只在候选与首选的分差不超过 20 厘兵时考虑频次，其他情况取引擎首选。此评估时间很短，只用于试验，不能当作深度开局研究。
4. 将试验 JSON 推到手机上述路径。脚本运行时再检查 **精确盘面、轮次、排除表和合法着法**；任何一项不符合即回到手机 Pikafish。

## 结果

- 原始 40,711 局；完整着法去重后 40,296 局；前 12 个半回合棋规校验通过 40,296 局。
- 频次索引共 3,111 个局面，约 327 KB。电脑端复核前 120 个，生成的试验库约 44 KB；其中 120/120 的最终着法都通过项目棋规校验。
- 用**同一批来源棋谱**回放统计命中率：第 1、4、8、12 个半回合分别为 100%、70.2%、38.7%、14.9%。这是训练来源内的覆盖率，**不是独立对局的胜率或命中率**。
- Node 路由测试验证：命中开局库、不合法/被排除时回到 Pikafish、显式关闭开局库。既有 `run-regress.js` 为 11/11 通过；`panel-load-smoke.js` 通过；Gradle 的两个示例脚本检查通过。
