# 示例「一运行就报错」：伴生资源没跟着走（已修，dev-604 已发布并真机复验）

日期：2026-09-16。真机：K40 `cccc62c7`、Mi8 `ce4d2bdb`（Android 15）。

发布：**dev-604**（versionCode 604，SHA-256 `6dad0030…`，手机拉清单 200）。

## 现象

从示例里打开一个示例（编辑器里点「运行」）就报错。最典型的是：

```
E: Wrapped java.lang.NullPointerException: image = null
    at file:///android_asset/modules/__images__.js:449
```

## 复现与定位（A/B 实测，K40）

拿内置示例 `Rhino 引擎/图片与图色处理/找图/找出马里奥.js`（第 2~3 行
`images.read("./super_mario.jpg")` / `images.read("./mario.png")`）跑两次，**只差图片在不在同一目录**：

| 条件 | 结果 |
| --- | --- |
| 只有脚本，同级没有图片 | `NullPointerException: image = null`，`at current.js:4:0` ❌ |
| 把 `mario.png` / `super_mario.jpg` 放进**同一目录** | `D: {156.0, 187.0}`，0.073 秒跑完 ✅ |

`images.read()` 找不到相对路径的文件时**返回 null**（不抛错），下一行拿 null 当图像用才炸。

## 根因：两个入口都没有「示例自己所在的目录」

| 入口 | 以前怎么做 | 为什么错 |
| --- | --- | --- |
| 示例页「运行」 | `Scripts.run(SampleFile(asset).toSource())` —— 跑 APK 里的正文 | 执行配置写死 `workingDirectory = Pref.getScriptDirPath()`（`Scripts.kt:122`），工作目录是 `/sdcard/脚本`，示例的 `./mario.png` 在那儿不存在 |
| 示例页「查看/编辑」 | `importSampleWithName(...)` —— **只导入那一个 .js** 到脚本目录，编辑器再打开它 | 伴生图片/模型/`layout.xml`/子模块都没跟过去；顺带还会和别的示例撞名（各工程的 `main.js` 都叫 main.js） |

受影响的不止找图类：`ui.layout(files.read("./layout.xml"))` 的项目型示例、`require("./子模块.js")`、
`files.path("./client-runtime.jar")` 都是同一类。纯算术/控制台类示例不受影响。

> 注：资源页（「资源」tab）里同样的位置**早就改对了** —— 它的注释写着
> 「工程是多文件树：`require('./src/xx.js')` 只解析磁盘路径 …… 所以先把整份工程拷到临时目录，
> 再从磁盘运行入口脚本」。示例页当时没有跟进，这次补齐。

## 修法

新增 `model/sample/SampleFiles`（落盘 / 导入共用的工具）：

1. `materialize(context, assetPath)`：把示例本体**连同同目录的伴生文件**补到
   `files/sample/<相对路径>`（已存在的文件不覆盖；同级文件只 stat 一遍，不读内容）。
2. `copyAssetTree(context, assetPath, target, overwrite, maxSubdirBytes)`：递归复制，
   单个子目录超过 8 MB 就跳过（示例里的 YOLO 模型库 18.8 MB 是用 `asset://` 引用的，不依赖磁盘副本）。
3. `importForEdit(context, assetPath)`：导入到 `<脚本目录>/<目录名>/`，目录里有 `project.json`
   就用目录名（导入后仍是工程），否则用示例自己的名字（不再和不相关的示例撞名）。

改动点：

- 示例页 `MiuixSampleFragment.run()`：改成 `Scripts.run(ScriptFile(磁盘那份))` ——
  `Scripts.run(File)` 本来就把工作目录设成文件父目录（`workingDirectory(file)`），
  磁盘那份的伴生资源就在旁边，于是相对路径成立。落盘失败才回退到旧的「跑 assets 正文」。
- 示例页 `MiuixSampleFragment.view()`：改用 `SampleFiles.importForEdit()`，导入成「一个示例一个目录」。
- 资源页 `MiuixResourceFragment.runBuiltin()` 的单文件分支：和工程分支一样先落到 cache 再跑磁盘文件
  （`runProjectCopy` 增加 `entryName` 参数；复制走带体积上限的 `SampleFiles.copyAssetTree`）。

真机仪器测试 `apps/app/src/androidTest/java/com/jdkshen/aijspro/sample/SampleFilesImportTest.java`
（Mi8，`:app:connectedMiuixCompatDebugAndroidTest`）：

```
tests="4" failures="0" errors="0"
  materializePutsCompanionFilesNextToSample              ✅ 落盘后同级有 mario.png / super_mario.jpg
  importForEditCopiesWholeSampleDirectoryIntoScriptDir    ✅ 导入成「找图/」+ project.json + mario.png
  importForEditKeepsProjectCompanions                     ✅ 「dsh 手机客户端/」+ layout.xml + client-runtime.jar
  importForEditUsesSampleNameWhenDirectoryIsNotAProject   ✅ 无 project.json 时用示例名建目录
```

设备上的实际结果（Mi8 `/sdcard/脚本/`）：

```
dsh 手机客户端/    ← main.js + layout.xml + client-runtime.jar + project.json + …
找图/              ← 6 个示例 + block.png/hellokitty.jpg/mario.png/mushroom.png/super_mario.jpg + project.json
截图并识别文字(MLKitOCR)/   ← 2 个 OCR 示例（该目录没有 project.json，用示例名）
```

另外在 K40 上用「文件管理 → 示例代码 → Rhino 引擎/图片与图色处理/找图 → 找出马里奥.js → 编辑器 → 运行」
实跑（这条路径本来就是「跑磁盘那份」）：控制台输出 `D: {156.0, 187.0}`，0.069 秒结束，**不再报 image = null**。

发布包 **dev-604** 装到 K40 后的端到端复验（示例页「运行」按钮，就是这个 bug 的入口）：
点「教程 → QuickJS 新引擎 → 项目与打包 → dsh 手机客户端 → main.js → 运行」后，控制台是

```
V: 开始运行[/data/user/0/com.jdkshen.aijspro/files/sample/QuickJS 新引擎/项目与打包/dsh 手机客户端/main.js]
```

即确实改成了跑 **files/sample 里那份**（工作目录就是示例自己所在目录），随后示例自身的 UI
（`尚未连接` / `刷新` / `设置` 那个界面）正常起来 —— 说明 `layout.xml`、`client-runtime.jar`
这些伴生文件都被读到了；控制台没有 `Cannot find module` / `image = null`。

## 未覆盖 / 仍然存在的老状态

- 示例页「运行」按钮的**点击级**验证已在 dev-604 上补齐（见上）；剩下没覆盖的是「打包单文件示例」那条链
  （仍只导入单文件）。
- 以前版本导入的**单文件副本**（如 `/sdcard/脚本/YOLO持续识别.js`）不会被自动改写 ——
  它们还是缺资源的旧形态；编辑器里可以从内置版本「重置」，或删掉后重新打开（会按新规则导入成目录）。
- 「打包单文件示例」（示例页 → 打包）仍然只导入单个 .js：打包单文件脚本本来就只要脚本本体；
  要连资源一起打包请用「打包（项目）」。
