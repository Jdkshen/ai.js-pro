# dev-1244：更新下载 0% 修复与发布

状态：**已发布 dev-1244，小米 8 已覆盖安装并验证实际应用下载器；K40 仍保留原版本和任务。** 用户截图的错误已定位并修复。

## 现象和确诊

用户能检查到 dev-1243，但点击应用内直接下载后停在 0%，提示：

```text
Unable to create call adapter for class io.reactivex.Observable
for method DownloadApi.download
```

这条错误发生在 Retrofit 解析接口时，尚未发出下载请求。旧版普通 HTTP/curl 的成功不能证明应用内下载器可用；此前发布核验漏掉了实际 Retrofit 下载路径，本轮补齐。

直接读取已发布 dev-1243 的 DEX 得到：

- DownloadApi.download 的实际 Signature 为 `(Ljava/lang/String;)Lio/reactivex/Observable;`，丢失 ResponseBody 类型参数。
- Observable 和 Deferred 的类型参数声明缺失；Config/UpdateCheck/User/Topic 的相关泛型返回值也变为原始类型。
- 源码已有 `-keepattributes Signature`，但 R8 full mode 仍会处理未显式保留的泛型包装类。[Retrofit 官方当前规则](https://github.com/square/retrofit/blob/trunk/retrofit/src/main/resources/META-INF/proguard/retrofit2.pro)也单独处理反射依赖的返回包装类型；本项目仍使用 Retrofit 2.3 和较老的 RxJava 适配器。

使用 REA Android 入口时返回 Windows 平台能力不支持；实际 DEX 取证改用本机已安装 dexlib2 2.5.2。未声称取得 REA/JADX 的反编译证据，也没有安装额外工具或执行 APK 来完成静态读取。

## 修复

1. `apps/app/proguard-rules.pro` 显式保留 Observable、Deferred、Retrofit Call/Response 的类/接口声明及泛型元数据，没有整体保留所有 RxJava 库成员。
2. `DownloadManager.download` 延迟创建 Retrofit 调用；接口初始化异常也进入 Observable 错误通道，现有进度对话框可以正常走 onError 关闭，不再遗留 0% 窗口。ResponseBody 使用独立资源关闭。
3. 新增 `tools/check-apk-retrofit.py` 和 `tools/apk-audit/CheckRetrofitSignatures.java`，读取最终 APK 的所有 DEX，检查当前 10 个 API 方法、2 个包装类的泛型，以及下载接口 GET/Streaming/Url 注解。
4. 候选构建与显式 APK 发布均加入该硬门；旧 dev-1243 负向检查明确失败，新 dev-1244 通过。发布器主动选择 JDK17，避免系统默认 JDK8 不能执行检查器。

不通过关闭 R8 或跳过检查绕开问题。新包保留 dev-1243 的大文件分享修复，Flutter AOT 未改动，复用上一版已经重建且验证的 payload。

首个测试探针直接使用 Class.forName 时走到了错误加载器，未发出下载请求；改为应用 Context 的 ClassLoader 后完成验证。该探针错误保留在证据目录，未当成应用下载失败。

这不是在原 Android 16 手机上进行的全流程 UI 回归，也没有自动点击其系统安装器。原手机需通过浏览器覆盖安装后复测；本轮没有再次测试全部三引擎 API 或之前大文件分享的接收端行为。
