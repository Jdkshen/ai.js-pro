## 3. 发现：events.observeToast() + events.on('toast') 叠加时 toast 通道 0 回调
- 实测（间隔 8s 发 4 个 toast，避开配额）：rawToastKind=4（accessibility_event 里 kind=toast 4 条）而 viaOn=0 / viaOnToast=0。
- 代码依据：Events.java:212-219 检测到专用观察者已挂时跳过 kind 通道，把投递责任交给 AccessibilityNotificationObserver；本次观察者 0 次回调 ⇒ 事件被静默丢掉。
- 这是「避重」实现的一个前提未成立的洞：建议 W1 复核 observeToast() 路径（同包 toast 是否被有意跳过？delegate 优先级/token 时序？），并考虑「观察者未投递时回退发 kind 通道」的兜底。
- 反证边界：本次是本应用自己的 toast；若观察者有意跳过同包，则这是「本应用 toast 收不到」，需用别的应用发 toast 做对照才能定论。
