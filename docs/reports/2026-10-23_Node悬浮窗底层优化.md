## 1. 与规格的差异（重要）

规格假设「原生 setPosition 会 removeView+inflate+addView」，实际代码里：

- `Node24LocalOverlay` 早已有 `case "move"`（`updateViewLayout`）和 `enableDrag`/触摸事件队列（task-201/218）；
- 真正重建来自 JS 层 `floating_window.js` 的 `setPosition/setSize` 调用 `_reShow()`（close+show）；
- 所以本轮以 JS 改为调用原生 update 为主，原生只补 `resize/setTouchable/metrics` 与触摸节流。

## 2. 实现

### 2.1 JS（`modules/engine/src/main/assets/node24/modules/floating_window.js`）

- `setPosition/moveTo`：可见时调用原生 `move`（`updateViewLayout`），不再 `_reShow()`；
- `setSize`：调用原生 `resize`；
- `setTouchable`：调用原生 `setTouchable` 改 flags，不再重建；
- `getSize()`：调用原生 `metrics`，返回真实像素；根 View `getWidth/getHeight/getLocationOnScreen` 同源；
- `binding` 增加 `setAlpha/setBackgroundColor/setTextColor/setPadding/setLayoutParams/getWidth/getHeight/getLocationOnScreen`；
- 触摸轮询：有 `touch`/`drag` 监听时 16ms，否则 100ms；
- 兼容开关：`createWindow({ legacyRebuild: true })` 可回退旧的 close+show 重建路径。

### 2.2 原生（`Node24LocalOverlay.java`）

- 新增 `resize`、`setTouchable`、`metrics` action；`metrics` 返回 root 真实宽高、屏幕坐标、content 宽高、visible；
- `viewCommand` 扩展：`setAlpha/setBackgroundColor/setTextColor/setPadding/setLayoutParams/getWidth/getHeight/getLocationOnScreen`；
- 触摸事件：ACTION_MOVE 与拖动事件均按 16ms 节流后入队（JS 16ms 轮询），窗口拖动仍逐事件 `updateViewLayout` 保持跟手；
- `move` 行动作保留原有 `updateViewLayout` 逻辑。

## 4. 已知限制

- `setViewFromXml` 在 show 之后调用目前只记录 XML、不会热替换视图（仍建议 show 前设置；需要热替换时应提供显式 reload）；
- `binding.<id>.<style>` 需在 show 之后调用才会解析 viewId；show 前调用会抛「浮窗里没有 id」；
- `raw View` 尚未暴露（本轮用高频白名单命令替代）；如确需任意 View API，可后续用 Node24 的 `$obj` 对象句柄注册 View；
- `hide/show` 仍走 close+show，位置/尺寸已零重建，但 hide 后 show 会重新 inflate；
- 触摸 MOVE 在启用 enableDrag 时由 drag 事件接管，普通 touch MOVE 走 touch 事件（已按 16ms 节流）。
