# SIFT 缓存与渐进搜索（dev-771）

## 借鉴象棋引擎的方式

用户要求参考象棋引擎减少计算量。检查了仓库 `third-party/Pikafish/src/thread.h`、`engine.h`、`nnue/simd.h`、`misc.h` 和 Android CMake：它使用常驻工作线程、置换表、增量评估、NEON 和预取。

现有 OpenCV features 已使用 O3、NEON 及 TBB 并行，因此主要改善来自减少重复的特征提取和索引构建。此次将“复用已算数据”“先较小规模搜索”“只处理目标附近”应用到 SIFT：

1. 每个 matcher 缓存最近一次实际缩放灰度、特征点、描述子和 FLANN 索引。默认 `reuseScene:true`；逐字节比较实际灰度输入及特征参数，相同才复用。不同图片句柄可以复用，同一 Mat 被修改也会失效，缓存不依赖指针或抽样哈希。
2. 原两矩阵 `knnMatch(query,train,...)` 实际每次 clone matcher 并重建 FLANN。现在 `add/train` 后使用已训练索引查询；像素或特征参数变化时清空索引，匹配失败也丢弃近似索引以便下次重新训练。
3. `fast:true` 在较大区域先按请求 scale 的2/3搜索，至少8个可靠内点及合格几何才接受。失败后按请求 scale 完整搜索。默认 fast:false，示例显式开启，完整分辨率旧入口保持原参数。
4. 局部跟踪框在 padding≥16 时向外对齐16像素，防止亚像素几何抖动改变裁剪边界。目标移动出区域会重新搜索；背景在区域以外变化时仍可复用该区域特征。padding<16 保持原像素边界。

缓存命中后仍执行最近邻查询、比率过滤、RANSAC 和坐标还原，当前阈值仍有效；调试图使用本次颜色。没有直接复用旧点击坐标。每个 matcher 只保留一套场景数据并随回收释放。

新增结果字段：`featureCacheHit`、`indexCacheHit`、`searchScale`、`searchPasses`、`timings.cacheCheckMs`。缓存检查计时独立于 featureMs，多次搜索尝试的耗时相加。两引擎缓存示例显示特征复用状态和分段耗时。

## 实测

K40 / Android 16 / arm64。预读 1080×2340 场景、172×206 模板，场景 scale:0.5、模板 scale:1，无绘图，预热后5次中位数。以下在同一新版构建内分别测试，时间包含整个 API 调用。

| 模式 | QuickJS | Rhino | 条件 |
| --- | ---: | ---: | --- |
| 单次完整全图 | 208ms | 213ms | 每次重新创建模板，不启用 fast |
| 单次低分辨率优先搜索 | 140ms | 143ms | 每次重新创建模板，fast:true，9～10个可靠内点 |
| 缓存模板但强制重算全图 | 193ms | 190ms | reuseScene:false |
| 缓存模板、相同全图 | 4ms | 6ms | 特征和索引命中 |
| 缓存模板、背景像素变化 | 184ms | 189ms | 两图交替，每帧一个背景像素变化，缓存失效 |
| 局部跟踪强制重算 | 12ms | 13ms | reuseScene:false，向外对齐搜索框 |
| 相同区域局部跟踪 | 2ms | 4ms | 特征和索引命中 |
| 区域外背景变化的跟踪 | 2ms | 3ms | 背景变化在跟踪区域以外 |

首次 fast 搜索缓存模板后原生阶段约111ms，场景特征约100ms。原参数完整全图仍需约190ms；fast 失败再完整搜索会增加一次尝试，本次 scale:0.45 回退样本约277ms。低分辨率结果四角略有差异，中心偏移小于1像素。不能把静止画面缓存速度作为每帧变化或首次全图的速度。

线程调试：dev-770 相同场景使用1/2/4/8线程的两轮5次中位数分别约309/202～205/152～175/186～188ms，4线程在该设备上较快；默认8线程已经启用 TBB。调试脚本恢复原配置。OpenCV 的线程数配置影响共享处理任务，且不支持并发修改，因此本次优化在匹配器内实现缓存和渐进搜索。[OpenCV 线程配置说明](https://docs.opencv.org/4.13.0/db/de0/group__core__utils.html)

```javascript
var matcher = images.createSiftMatcher('小图.png', {fast:true,track:true,scale:0.5});
// 在循环内截图并匹配，结束后回收 matcher 和图片。
var result = matcher.match(frame);
```
