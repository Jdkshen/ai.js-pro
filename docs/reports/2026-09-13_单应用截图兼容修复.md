# 单应用截图兼容修复与小米 8 排查

## 问题与改动

- `ScreenCaptureRequester` 之前在 API 34+ 使用 `createConfigForDefaultDisplay()`，主动取消了单应用选择。改为系统默认 `createScreenCaptureIntent()`，恢复单应用/整屏选择。
- `ScreenCapturer` 接入 `onCapturedContentResize`，同步调整既有 VirtualDisplay 和 ImageReader。收到实际捕获尺寸后，不再让宿主方向监听覆盖应用窗口尺寸。不重复创建投屏会话或复用授权令牌。
- 接入可见性回调。目标不可见时清理缓存并明确提示；再次可见、尺寸变化后不回退到旧代截图。不按亮度判断画面有效性，正常黑色界面不会被误判。
- 默认首帧等待预算 2 秒；已有有效帧时仍立即返回，正常循环预算不变，自定义/零超时不被改写。未修改 YOLO 模型、推理线程数、输入尺寸或原生预处理。
- 串行处理 reader 切换与缓存所有权，忽略旧 reader 排队回调。尺寸变化或系统终止会话时，保留尚被调用方使用的 raw frame 到下一帧/显式释放，避免在 native copy 中途关闭底层缓冲。
- 停止的会话不能再返回旧帧；再次调用 requestScreenCapture 会重新请求授权。明确区分不可见、超时、被系统停止三类中文错误。

Android 14+ 依据：[Media projection 官方文档](https://developer.android.com/media/grow/media-projection)。在现代 Android 上捕获实际窗口形状优先于旧的强制方向参数；脚本应读取截图实际尺寸。单应用坐标属于应用画面，不自动等同于整屏点击坐标。

## 使用限制

系统录屏会启动另一条 MediaProjection 会话并终止原截图会话，它的帧不会自动转交给 AI.js Pro。当前截图通道不能承诺同时使用系统录屏和识别。请停止系统录屏后重新授权；若必须并行，需要另行评估替代截图通道与相应权限。

本地构建、探针、截图和日志位于 `.artifacts/capture-mi8/`，不提交这些产物。未修改手机录屏设置、未覆盖用户示例脚本。初期只安装本地修复包，后续经用户明确要求已发布到现有 dev 更新源，见下节。
