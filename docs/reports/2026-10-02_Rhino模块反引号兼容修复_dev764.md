# Rhino 模块反引号兼容修复（dev-764）

日期：2026-10-02。

## 用户反馈与复现

用户截图为 `utils.js` 内的 `floaty.rawWindow()`，布局使用多行反引号字符串，包含 button、canvas，以及箭头函数点击监听和 Canvas draw 回调。

在 K40 / dev-763 上构造结构等价的最小复现：

- 直接作为 Rhino 主脚本运行：布局创建、ID 访问、监听注册、实际绘制均通过，约 1.2 秒绘制 36 帧。
- 同一代码放入模块，主脚本通过 `require('./floaty-template-utils.js')` 调用：报 `InternalError: illegal character (.../floaty-template-utils.js#6)`。
- QuickJS 直接运行：布局和箭头函数点击监听注册通过，Canvas draw 注册失败，报 `Error: 不支持的浮窗控件事件：draw`。

这说明 Rhino 的模板字符串转换漏了模块入口；QuickJS 的布局字符串支持和 Canvas 绘制回调支持是两个能力。

## 源码改动

- 新增 `modules/engine/src/main/java/com/stardust/autojs/engine/module/TemplateLiteralModuleSourceProvider.java`，包装现有模块源 provider，在编译前复用入口脚本的模板转换。
- 在 `RhinoJavaScriptEngine.initRequireBuilder()` 接入该 provider，覆盖模块名加载、URI 加载、内置 assets 和嵌套 require。原有解密逻辑仍由被包装的 provider 处理。
- 转换时关闭原 reader，保留 URI、基础路径、安全域和缓存校验对象；不存在和未修改的模块原样透传。不能转换的模板保留原文，不改变父引擎。
- 新增 4 项单测，验证嵌套中文与空格路径、XML 模板插值及模块缓存、元数据及 reader 释放、未修改/缺失模块、未支持的标签模板。

## 当前使用方式与剩余边界

该绘图脚本使用 Rhino；在入口脚本顶部添加：

```javascript
// @engine rhino
```

若 `utils.js` 是 `require()` 模块，标记应加在调用它的主脚本中，模块布局保持原写法。
