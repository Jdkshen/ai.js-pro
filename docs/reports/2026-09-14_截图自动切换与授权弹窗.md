# 截图自动切换与授权弹窗

## 使用

`requestScreenCapture({mode: 'auto'})`。Android 11+，需用户开启 AI.js Pro 无障碍服务。

YOLO持续识别增加第三项“自动切换”；新增“截图自动切换测试.js”，不覆盖用户已经编辑过的示例。

自动模式初始使用无障碍兼容截图。通知监听未连接时弹说明框，提供“去开启”“暂不开启”，只打开系统通知使用权设置，不替用户批准权限。此功能仅检查应用包名、通知通道、运行标志，不读取通知正文，不保存或上传通知。

已连接且确认系统录屏结束、稳定 1.5 秒后，弹系统截图授权。用户确认后恢复高速；用户取消后保留兼容，不在同一轮录屏反复提示。再次检测到录屏启动后允许新一轮恢复提示。

原来的 `projection` 高速模式和 `accessibility` 兼容模式不变。自动模式默认截图超时 2000ms，仍保留用户显式传入的超时；高速帧继续走 ImageReader 缓存，不添加逐帧睡眠。

## 边界

- 识别 SystemUI 的 `screen_record` 和 `issue_record` 持续录屏通知；录制已保存的非持续通知不当作录屏中。
- 小米 8 的 Lineage 系统支持初始空闲识别；其他系统必须先观察到支持的录屏通知，才可判断该轮录屏已结束。未知 OEM 录屏、监听断开、锁屏时不触发恢复授权。
- 通知是针对受支持系统录屏的辅助信号，不是任意第三方 MediaProjection 的权威状态 API，不能承诺全品牌、全部第三方录屏通用。
- 系统撤销高速截图后，下一帧切换兼容；只有授权完成且重新检查状态后才创建新投影。旧令牌不复用。脚本停止后忽略迟到的授权回调。
- 无障碍截图是整个屏幕，受系统约 3 FPS 限制，不是高速 YOLO 推理通道。恢复高速时仍由系统允许用户选择单应用或整个屏幕。

## 验证

- QuickJS 三 ABI 原生库重新编译通过。
- 截图状态、自动切换策略、录屏通知分类：20 项单元测试，0 失败。
- Debug APK 构建、示例引擎标记与 Native 新鲜度校验通过。
- 真机权限弹窗、录屏中连续取帧、用户批准后的自动恢复：分别记录实际验证结果，未批准的权限不通过 ADB 自动授予。

### 小米 8 实测进度

- dev-578 已安装并发布到原 dev 更新源；手机读取更新清单 HTTP 200，APK SHA 校验通过。
- 00:03 首次自动模式取帧成功到第 20 帧；随后无障碍服务断开，测试中断。该时间与 `uiautomator dump` 检查重合，怀疑诊断工具 UiAutomation 抑制了无障碍服务，因此后续取帧测试不再使用该工具。此轮不记作完整通过。
- 用户手动开启通知使用权，ADB 只读确认服务已列入授权清单。
- 00:04:44 申请高速截图授权，00:04:51 用户确认后日志“截图通道：高速（自动恢复）”；连续截图超过 120 帧。系统投影持有者已变为 AI.js Pro。
- 完整启停循环通过：00:04:59 系统录屏接管后自动切换兼容；00:05:02 至 00:05:37 持续取帧，系统投影持有者仍为 SystemUI；00:05:42 录屏结束后申请授权，00:05:46 确认后恢复高速，继续超过 630 帧。
- 测试中用户还启动了 YOLO持续识别，两份自动截图脚本同时运行，日志出现无障碍全局截图限频争用及两份独立授权请求。这不是单脚本重复提示，但当前没有跨引擎共用高速截图会话；Android 不支持以各自新授权同时维持两个投影。已安排仅清理自建测试，不停止用户 YOLO。建议一次只运行一个自动截图脚本。
- 取消不反复弹窗经过纯逻辑单元测试；真机取消授权的专门验收尚未执行。
- 自建测试在 00:07:41 正常结束，共 2209 帧；用户 YOLO 保持运行，未执行停止全部。当前单独 YOLO 仍处兼容通道，跨引擎同时授权的场景不记为支持；需要单独重新运行自动模式，或在用户确认后另行实现共享截图协调。
