# 两局负局的禁手策略修复

日期：2026-09-27。最终发布和装机版本：dev-719，象棋脚本 0.6.39。

## 实际问题

- 20:42 开始的一局：第 96 回合，求胜模式硬排除 g7g4/g7g8 等近均势候选，迫使引擎选择明显劣势着法。上次算棋分数不能证明本次换招安全。
- 22:34 开始的一局：求胜已关闭，第 33 回合仍把 c5c9（将军）与 c9c5（安静退车）的循环误认为连续长将，排除了能维持局面的 c5c9。
- 两局详见同目录对应负局复盘。问题位于脚本着法筛选，不是这两处关键转折上的原生引擎首选。

## 修复

1. 计划重复不再生成长将硬禁手；将已核验棋谱交给 Pikafish 的历史搜索判断重复责任。游戏实际拒收过的着法仍保留硬排除。
2. 求胜重复和避免兑子统一成为搜索后的软偏好，使用本次同层候选评分，按我方分数方向比较。只在配置的均势窗口内、损失不超过 20cp 时换招；缺失分数、杀棋标记或候选较浅时不替换。
3. 替换后同时更新着法、评分、深度和主变，预思考使用所选着法的主变。同步与 worker 路径一致。
4. 加入两局真实棋谱回放、真实拒收保留、红黑方分数、缺失分数、杀棋和预思考种子回归。
