# inrt 定时任务端到端（task-160，2026-10-19）

## 结论
inrt 打包模板补齐了定时任务的**调度初始化 / 持久化 / 服务 / 权限 / work_manager**；在 K40 上以 inrt debug APK（= 打包运行时本体）验证：
`addDailyTask` → 任务落盘 → **reboot** → BOOT_COMPLETED 恢复 → 到点拉起打包工程脚本并写标记文件，全链路 PASS。

## 过程中修复的真实问题
1. inrt 模板原本完全没有定时任务：无 receiver/service/权限/持久化/work_manager 注入；
2. `work_manager.add*` 返回 id=0：schedule 未分配 id（已补 `store.nextId()`）；
3. 跨进程任务丢：SharedPreferences 每进程缓存，:script 写的任务主进程 Alarm 广播读不到（`task not found id=2`）→ 改为 filesDir JSON 每次读盘；
4. 到点拉起被 `mScriptExecution` 守卫直接 return → `launchHeadless()` 先复位；
5. `:script` init.js 兜底把 JavaPackage 当构造器 → 补 inrt 类 + typeof 判断；
6. 多进程重复 rescheduleAll 的读写竞争 → 只有主进程做启动恢复，:script 只保留 scheduler 上下文。

## 限制（已明确）
- 只实现 `addDisposableTask/addDailyTask/addWeeklyTask` 与 query/get/remove；`addBroadcastIntentTask/addActivityIntentTask` 等意图任务**未实现**（打包产物无 IntentTask 子系统）；
- 任务 `path` 仅持久化展示，实际到点执行**固定为打包工程入口**（打包产物只有一个工程）；
- `SCHEDULE_EXACT_ALARM` 未授权时降级 `setAndAllowWhileIdle`（可能延迟）；
- 测试脚本里 `exit()` 在 headless 任务中未能中止后续代码（会继续执行），正常脚本应自然结束；该行为可另立 follow-up。

## 构建要求
本次改的是 `:inrt` 模板；宿主 dev-1110 不会自动更新打包模板，需要：
1. `gradlew :inrt:assembleRelease`；
2. `powershell -File output/flutter-poc/rebuild-inrt-template.ps1`（刷新 `plugins/apkbuilder-plugin/src/main/assets/template.apk`）；
3. 再构建 dev-1110 宿主 APK；打包产物用新模板后即带定时任务能力。
