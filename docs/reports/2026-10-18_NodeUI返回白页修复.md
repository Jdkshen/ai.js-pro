# Node UI 返回白页修复（dev-1033）

2026-10-18，Asia/Shanghai。用户反馈：运行 Node 原生界面后按返回，会露出白色界面，还要再返回一次。

## 修改与原因

DP 实现代码，Codex 审查、构建并在 `DQKFJB59596L45BI` 验证。仅修改 `modules/engine/src/main/java/com/stardust/autojs/ScriptEngineService.java` 的执行路由与相邻说明/启动日志。

旧 `executeInternal()` 对所有带 UI 模式标记的 JavaScript 都先打开 `ScriptExecuteActivity`。Node 随后又由 `NodeUiHost` 打开 `NodeUiActivity`，形成：

```text
GlassFlutterActivity → ScriptExecuteActivity（空宿主）→ NodeUiActivity
```

返回时真正的 Node UI 被关闭，底下还有一个通用宿主。修复后识别实际引擎为 Node24 时，跳过通用脚本 Activity，继续通过 `RunnableScriptExecution` 执行；Node 的唯一界面由 NodeUiHost 管理。Rhino / QuickJS UI 和 headless 的已有路由保持。

核心条件在 `ScriptEngineService.java:211`：

```java
if (uiMode && !sHeadlessUiMode && !isNode24) {
    return ScriptExecuteActivity.execute(mContext, mScriptEngineManager, task);
}
```

没有修改 NodeUiActivity 的返回/销毁逻辑，没有通过透明主题或自动多按一次返回遮盖问题，也没有更改上轮图标/标题修复。

## 为什么上轮验收漏掉

此前用的设备脚本首行是 `"nodejs";`，第二行才是 `"ui nodejs";`。当前执行模式解析只读取首个字符串，因此该测试被当成普通模式，经过了不同的执行入口，未创建通用 UI Activity。

本轮在独立目录复制示例，入口明确为首行 `"ui nodejs";`，其余脚本正文和资源不改。fixture 保存在 `output/node-back-blank/fixture-ui-node/`。未修改用户原始脚本和内置示例。
