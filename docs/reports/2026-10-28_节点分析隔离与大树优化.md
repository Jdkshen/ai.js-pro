# 节点分析：隔离、超时取消与大树优化（2026-10-28）

目标：继续 2026-10-27 静态对照后的实现工作，先处理抓取超时/取消/退出，再优化大树点选与主线程工作，并做分析 UI 的进程隔离。已发布 **dev-1272**（仅 LAN），不代表 AJ Pro 全量等价。

## 已实现

- 抓取统一入口：`CaptureRequestGate` + `NodeCaptureBudget`；单物理抓取、8 s 预算、15000 节点/256 层上限；超时/取消丢弃晚到结果，不把 UI 恢复当成 Binder 已终止。
- `LayoutInspector` 提供可取消请求；窗口刷新与当前窗口共用同一线程池，避免每超时新建线程。
- 超限抓取改为返回已采到的**部分树**并标记 `truncated`，不再整次分析直接丢空。
- 新增 `:inspector` 独立渲染进程（`InspectorHostService`、`InspectorProcessBridge`、`InspectorSnapshotTransport`）：主进程采集，快照经同 UID 随机 token 缓存目录传给子进程；文件大小/节点数/深度校验。
- 子进程渲染离屏快照；切换范围图/层次树、搜索、属性面板和改进生成器保留。
- 大树点选使用 `InspectorHitIndex` BVH；范围图不再每次触摸全树 BFS，绘制改为缓存 Path。
- 搜索改为后台线程 + 代次校验；窗口刷新和打开有超时恢复；主题从主进程调色板同步到子进程。
- 音量下退出监听接入 `GlobalKeyObserver`，打开时注册、关闭时移除。
- 隔离失败（快照写入/绑定/超时/子进程崩溃）回退旧主进程分析窗；`:inspector` 开关/退出与主 Activity 退出清理已接。
- 窗口上限统一为 32 并截断；缓存目录启动清理；刷新超时上调到 20 秒。
- 面板/搜索/菜单/属性弹窗改用动态调色板；NodeInfoView 属性读取移到后台。

## dev-1273 抖音修复

- 现象：从悬浮菜单打开节点分析，抖音等第三方应用只显示自身菜单/对话框或空树。
- 原因：`CircularMenu` 先弹出 Material 进度对话框再抓取，进度窗成为 active/application window，目标应用窗口被遮挡或树变稀疏。
- 修复：取消抢占焦点的进度对话框，改用 Toast；悬浮菜单收起后延迟 350 ms 让目标应用恢复 active/focused，再抓取；保持预算、取消和隔离链路不变。
- 真机验证：抖音 `com.ss.android.ugc.aweme.mobile`，日志 `activeRoot window=2406 package=com.ss.android.ugc.aweme.mobile`、`snapshot nodes=748`、`status=SUCCESS`；范围图正常覆盖抖音界面。

## dev-1277 Node24 60 秒超时修复

- 现象：`demo.js` 的 `watchVideos` 默认 5–8 条、每条 30–60 秒，总时长必然超过 60 秒；实测 Node24 脚本在约 60.9 秒被 `STOPPED / stopReason=interrupted`，Rhino 80 秒正常，确认是 Node24 引擎上限。
- 根因：`Node24JavaScriptEngine.DEFAULT_TIMEOUT_MILLIS=60_000`，`Node24Service` 与 native host 也限制 60 秒。
- 修复：普通 Node 脚本上限提升到 `3_600_000`（1 小时）；UI 脚本仍保持原保活语义；`Node24Service` 校验同步到 1..3600000ms；取消/停止仍走既有 cancel，不依赖 deadline。
- 真机：70 秒 Node 脚本 7 个 10 秒 tick 全部执行并 `SUCCEEDED`（71.0s）；修复前 60.9s 被中断。
- **dev-1277**：142,371,681 字节 / 135.78 MiB，SHA-256 `e46ee07521dbd083316fde5d3e5a8193013487b26649bee15b6970c3abd4cdf6`；LAN 已发布，MI8 已装。
