# 修「打包版 `require("./脚本.js")` 报 outside of a module」+ 重建模板（dev-1401）

> 用户截图：打包产物（Nycspro）运行时 `主线任务.js:1` 的 `require("./脚本.js")` 失败：
> `Error: Can't resolve relative module ID "./脚本.js" when require() is used outside of a module`（`jvm-npm.js:92`）。

## 根因

`jvm-npm.js` 里 `require = Require`（裸函数、无 parent 模块），`findRoot(parent)` 在 parent 为空时返回 `Require.root`，
而 `Require.root = files.cwd()` **只在加载 jvm-npm 的那一刻计算一次**。我们的入口脚本是「顶层裸脚本」（没有 CommonJS 的 `module` 包装），
所以相对 require 只能靠这个 root：打包版里它与**脚本自身目录**不一致（或引擎复用时仍是上一个脚本的目录）→ 解析失败 →
回落到 Rhino 原生 require → 抛 "outside of a module"。

## 修复

| 文件 | 改动 |
|---|---|
| `modules/engine/src/main/assets/init.js` | 暴露 `__ajsSetRequireRoot(dir)` |
| `modules/engine/src/main/java/com/stardust/autojs/engine/RhinoJavaScriptEngine.kt` | 每次执行入口脚本前用「脚本自身目录」刷新 require 根（`JavaScriptFileSource.file.parentFile`，拿不到退回 `cwd()`） |

踩坑：`if (setter is Function)` 会被 Kotlin 的 `kotlin.Function` 遮蔽 → 必须写 `org.mozilla.javascript.Function`；且 Rhino 的 `Function.call` 收 `Object[]` 不是 varargs。

## 验证（K40 真机）

| 场景 | 结果 |
|---|---|
| 打包运行时（自建 `:inrt:assembleDebug`，assets/project 解压到 `files/project` 执行） | `cwd=require.root=/data/user/0/…/files/project`；`REQUIRE_OK hello-from-sub` ✅ |
| 对照组：手动把 `require.root` 改错 | **复现用户那句报错** ✅（病因确认） |
| 主 App · Rhino / QuickJS | 两个引擎都 `REQUIRE_OK` ✅ |
| MCP 冒烟脚手架 25 项 | 24 PASS / 0 FAIL / 1 SKIP ✅ |

## 模板重建（打包版必须重打才生效）

`tools/build-slim-template.ps1`：`template.apk` sha `47D9C4EE…` → **`C64815DB16D0AFB6…`**（18.9MB，`verifySlimPackagingTemplate PASS`）；
dev-1401 候选 APK 内嵌模板与仓库模板**逐字节一致**，且新模板 `assets/init.js` 含 `__ajsSetRequireRoot` ✅。

**踩坑**：`build-slim-template.ps1` 内部 `$ErrorActionPreference=Stop` + 原生命令 stderr 会被当成终止错误（gradle 的 deprecation 提示就中断了脚本）→ 外层设 `$PSNativeCommandUseErrorActionPreference = $false` 才能跑完。

## 打包器取模板的优先级（决定用户下一步要不要清理）

`ApkBuilderPluginHelper`：`/sdcard/template.apk`（手动覆盖）> 宿主缓存 `files/apk-builder/template.apk`（插件落地副本）> app 内置 `assets/template.apk`。
K40 实测前两者均**不存在**，所以会直接用新模板；其他设备若存在旧副本需删除后再打包。
