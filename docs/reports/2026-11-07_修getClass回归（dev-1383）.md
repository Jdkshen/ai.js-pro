# 修 getClass().getName() 回归（打包版 UI 崩溃）— dev-1383

> 用户报错（打包后的包）：`android.view.InflateException: ... Java class "com.stardust.autojs.core.ui.widget.JsLinearLayout" has no public instance field or method named "getName". (file:///android_asset/modules/__ui__.js#408)`

## 一、根因（K40 真机复现确认）

`__ui__.js:408` 就是 **view.getClass().getName()**。

- **dev-1380** 为支持 `Packages.<类>.class` 新增 `AijsNativeJavaClass`，并在 `WrapFactory` 里**把所有 Class 对象都包成它**。
- `NativeJavaClass` 的语义是「类引用」——只解析**静态成员**；Rhino 原生是把 `obj.getClass()` 返回的 Class 包成 **NativeJavaObject**（所以 Class 的**实例 API** 可见）。
- 结果：`getClass().getName()` / `getSimpleName()` / `isArray()` 全部报 `has no public instance field or method named ...`。

K40 实测（dev-1382）复现：`new LinearLayout(context).getClass().getName()` 报错；`.getClass().getSimpleName()` 报错；`Packages.java.lang.String.getName()` 报错；而 `.class.getName()`、`valueOf(123)` 正常。

**影响版本：dev-1380 / 1381 / 1382**（dev-1379 及之前无此包装，不受影响）。

## 二、修复（AijsNativeJavaClass.kt）

1. **静态成员优先** —— 保持 `Packages.X.staticMethod()` 语义。
2. **补回 Class 实例 API** —— 名字属于 `java.lang.Class` 的**实例**成员（CLASS_API_NAMES）**且本类没有同名静态成员**时，先返回 Class 实例成员。
   - 「同名静态成员」这条必需：`java.lang.reflect.Array.newInstance` 与已废弃的 `Class.newInstance` **同名**，无条件走 Class API 会把它抢走（单测实测报 `Cannot find method java.lang.Class.newInstance`）。
3. **兜底回退** —— `super.get` 找不到静态成员时 Rhino 是**抛异常**（不是返回 NOT_FOUND），此时再给一次 Class 实例成员机会，仍没有才抛原错误。
4. `has()` / `in` 运算符与 `get` 一致。

## 四、⚠️ 打包版为什么不会自己好（重要）

见 `docs/reports/2026-11-07_打包版引擎来源与模板新旧.md`：独立 APK 的 engine dex 与 `assets/modules/*.js` **来自 template.apk 预置副本**，不是当前 app 动态复制（证据：ApkBuilderPluginHelper.java:74-103、ApkPackager.java:51-65、ApkBuilder.java:183-255）。三份模板的 engine dex **都早于 dev-1380**；K40 的 `/sdcard/template.apk`（10-18 最老）**优先级最高**。

**所以光升级 app、或拿旧包再打一次都不会好。** 正确顺序：

1. 用修复后的源码**重建模板**（本轮已做：宿主瘦身模板 `08838A9D…` → `8B5F1009…`；插件模板 88,424,956 → 88,438,580）。
2. **重新构建 app**，让它内置新模板（→ dev-1384）。
3. 用户装新 app → **重新打包**工程 → 新包引擎才含修复。
4. 设备上若有 `/sdcard/template.apk`（老模板优先级最高）需更新或删除。

（`apps/inrt/build.gradle:129` 是 implementation project(engine)，模板直接编译 engine 源码，所以重建模板必然带上本次修复。）

## 六、同类隐患（队友排查，本轮未动，避免扩大改动面）

1. `AijsJavaStaticMethod`：int/Integer 同分依赖反射顺序；byte/short/char/long 无范围检查；Object 位置的整数变 Integer；varargs 不展开；函数 name/arity 丢失。
2. WrapFactory 还有 `setJavaPrimitiveWrap(false)`、UiObjectCollection/View/Paint/Method 特化等覆盖点。
3. `AijsNativeJavaClass` 未覆盖 `has("class")` 与 `getIds()`。
