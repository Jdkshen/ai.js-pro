**建议钉子（可直接派给 owner）**：新增 `PluginIdentityPinsTest`（JVM 层可跑，不需要真机）：
1) 断言 `MiuixPluginFragment.KNOWN_PLUGIN_PACKAGES` 的集合 **==** 各 `plugins/*/plugin.json` 里 `package` 的集合（读文件即可）；
2) 断言 `PluginDownloads.APK_BUILDER_PLUGIN_PACKAGE` **==** `plugins/apkbuilder-plugin/plugin.json` 的 `package`；
3) 断言每个 `plugins/<id>/build.gradle` 的 `applicationId` 字符串 **==** 同目录 `plugin.json` 的 `package`（源码正则抽取）；

### ② 脚本密钥派生：**两份实现**（Java 与 C），只有注释级一致（高危）

- Java：`modules/engine/src/main/java/com/stardust/autojs/project/ScriptKeyDerivation.java:20-21`（`KEY_PREFIX = \"aijspro-script-key|\"`、`VECTOR_PREFIX = \"aijspro-script-vec|\"`）
- C：`modules/engine/src/main/cpp/script_crypto.c:324`（`static const char kKeyPrefix[] = \"aijspro-script-key|\"`）+ `:5/:316` 的公式注释
- **逐字比对结论：两处字符串一致 ✓**（我今天读了两边原文）。
- **但**：`scripts/reports/2026-11-10_加密硬切换与原生解密契约取证（task-122）.md` `三.4` 明说：**原生与 Java 派生的逐字一致性「只有注释级证据，没有交叉跑过一次」**。
- **风险**：v2 硬化（`aijspro-script-key-v2`、64 hex 解码 32 字节）要求**两处同时改**；只改一侧 ⇒ **静默解不开**（表现为 padding/AEAD 失败，**不是**点名错误）。
**建议钉子**：① JVM 侧用**冻结常量**断言：`deriveKey(\"com.x\", \"00…0f\", \"AB:CD…\") == <写死的 64/32 hex>`（已部分存在）；② C 侧加一个**自检导出口**（或打包端调一次原生 `selfTest()` 返回 key 的 hex），断言与 Java 相同输入得到**同一串** ⇒ 这才是真正的交叉对拍。
