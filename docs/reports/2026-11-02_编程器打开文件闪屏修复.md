# 编程器打开文件闪屏修复（dev-1310 候选）

## 现象与证据

用户反馈从文件列表打开编程器会闪一下。在小米 8（ce4d2bdb、Android 35）已安装的 dev-1309 上实际录屏复现：编辑器工具栏和代码上半部分已经呈深色，下半部分短暂露出白块。按 30 fps 抽帧，frame 22（0.733 秒）白块占测量区域 55.65%，前后帧均为深色。

这次证据指向 WebView 首帧表面尚未完整绘制，同时网页初始背景和主题模块加载较晚；不是用户脚本执行崩溃。系统 Activity 启动预览也没有独立跟随编程器当前主题，作为同一入口的补充一并修复。

原始证据（本机、未提交）：`.artifacts/editor-flash-20261102/before-dark.mp4`、`before-metrics.json`、`before-frame-22.png`、`before-frame-25.png`。

## 修改

1. WebView 和它的原生容器使用对应 Ace 主题的不透明底色；首次加载地址带入当前深浅主题，网页在 body 和 Ace 创建之前设置背景、颜色模式。
2. 提前加载已有的 Tomorrow Night、TextMate 主题模块，取消首屏固定先切到深色的行为。后续切换主题同步 html/body 与原生底色，初始 CSS 不覆盖 Ace 的正式主题。
3. 首次 WebView 保持附着，通过透明度暂缓呈现。当前文档完成准备、提交排队的主题/字体/光标恢复、Ace 重新布局并跨两次动画帧后，再经原生视觉状态回调显示。没有固定延时显示，也不在每次切标签时重新隐藏。
4. 回调检查当前文档、活动状态、宿主销毁状态和请求序号，防止快速切换、退出时旧回调错误显示。
5. Pro 编程器独立关闭静态启动预览，窗口背景在首次内容创建前同步当前主题；不修改原有返回栈。

这里使用的 `postVisualStateCallback` 是 Android 提供的 DOM 更新与下一次绘制之间的同步接口，不能用 `onPageFinished` 代替首帧就绪。[Android WebView 官方说明](https://developer.android.com/reference/android/webkit/WebView.html#postVisualStateCallback(long,%20android.webkit.WebView.VisualStateCallback))。

### 真机结果

统一使用自建 30 行 JavaScript 文件，从文件列表的编辑按钮打开并录屏；测量区域为缩至 90×180 后的 `(8,35)-(82,155)`。深色统计 RGB 均大于 220 的白像素，浅色反向统计 RGB 均小于 60 的深色像素。统计仅用于发现大块反色闪帧，另外人工查看最终截图，确认实际代码和高亮可见。

| 场景 | 30fps 抽样帧数 | 反色区域最大比例 | 结果 |
| --- | ---: | ---: | --- |
| 深色，安装后首次打开 | 78 | 白色 0% | 通过 |
| 深色，关闭后重开第 1 次 | 74 | 白色 0% | 通过 |
| 深色，关闭后重开第 2 次 | 74 | 白色 0% | 通过 |

未再出现旧版下半块白色闪帧，也没有留下不可操作的空白编辑区。真实点击编辑区、输入标记、保存并通过 Node 读回文件成功；撤销、再次保存并读回原文成功。自建文件已关闭标签并删除，用户已有标签、深色主题及启动浮窗保留。测试视频、截图、逐帧数据和输入/保存记录在 `.artifacts/editor-flash-20261102/`。
