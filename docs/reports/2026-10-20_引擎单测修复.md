# 引擎单测修复：Rhino 样例引擎判定 + 文本文件 Intent 样例

日期：2026-10-20。范围：`modules/engine` 单测（330 项）与 `apps/app` Miuix 单测回归。

## 1. 问题

`:engine:testDebugUnitTest` 330 项中 3 项失败（327 pass / 3 fail）：

1. `RhinoSampleSyntaxTest.rhinoSamplesShouldCompile`：290 个样例里 42 个被当成 Rhino 编译失败。其中多数是 `Node 引擎/` 下的 Node 样例（首行 `"nodejs";`），例如：
   - `Node 引擎/Node.js/Node.js与Android和Java交互/继承Java类-SQLite数据库.js`
   - `Node 引擎/Node.js/Node.js中使用UI/React/src/App.js`（ES module import）
2. `TextFileIntentSampleTest` 两个用例：
   - `viewStreamAndClipDataReadTheirUris`
   - `missingUriShowsSetupAndReadFailureClosesStream`
   样例 `apps/app/src/main/assets/sample/Rhino 引擎/任务/读取文本文件.js` 直接读 `intent.data`，未处理 `EXTRA_STREAM` / `ClipData` / URI 缺失 / 读取异常 / finally 关流，和测试契约不一致。

## 2. 修复

### 2.1 Rhino 样例按运行时引擎筛选

`RhinoSampleSyntaxTest` 改用运行时的引擎判定（`JavaScriptSource.engineFromDirective`）：

- 首行字符串指令 `"rhino";` / `"quickjs";` / `"nodejs";`；
- `// @engine rhino|quickjs|node24` 注释；
- 无指令时按样例目录归属：`Node 引擎/`、`QuickJS 引擎/` 不算 Rhino 样例；其余（含 `"auto"`/`"ui"`）按运行时默认 Rhino 检查。

结果：**检查 Rhino 样例 151 个，按引擎/目录跳过 139 个 Node/QuickJS 样例，剩余 0 个语法错误**（没有通过“skip 全部失败项”来蒙混；真正的 Rhino 样例仍全部编译）。

### 2.2 文本文件 Intent 样例与 mock 契约一致

重写 `读取文本文件.js`（保持 Rhino/ES5 语法）：

- 按 `getData()` → `getParcelableExtra(Intent.EXTRA_STREAM)` → `getClipData().getItemAt(0).getUri()` 顺序取 URI；
- URI 缺失：提示“请在任务中将本脚本添加到外部Intent触发”，不打开流；
- 读取成功：alert 文件内容；`finally` 中 `stream.close()`；
- 读取异常：`finally` 仍关流，异常继续抛出（让调用方/测试看到真实错误）；
- 保留原有 `exit()` 行为。
