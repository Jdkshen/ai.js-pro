# 小米超级岛：三引擎脚本运行状态测试版

日期：2026-10-27。用户手机报告系统版本 3.0.3.06，授权先实现并提供 APK，由用户安装验证。候选版本 `dev-1268-island-test` / versionCode 1268。本轮不改公开更新源，不安装到 K40；没有把小米8普通通知验证代称为澎湃OS3上岛验证。

## 交付目标

Rhino、QuickJS、Node 脚本共用一条实时运行通知；支持系统时附加小米 OS2 焦点通知 / OS3 超级岛参数。主机不支持或权限未开通时保留普通运行通知，前提是系统允许该应用和通知通道发通知。

摘要显示运行数量及运行时长，展开卡片显示最近提交的脚本、引擎、少量其它任务和停止/查看入口。默认“停止当前”指最新提交的一个执行项，不按文件路径停止，因此同一个文件运行两次可分别处理。“停止全部”复用已有跨进程停止链路。

点击通知或“查看任务”进入原生运行状态页，可逐个停止、全部停止，查看超级岛系统能力、协议版本、焦点通知权限、普通通知/通道是否开启，并复制诊断 JSON。页面使用宿主主题调色板；离开后停止轮询，不依赖 Flutter AOT 新界面。

## 实现

- `ForegroundService` 保持原有租约和常开前台服务行为，由新增 `RunningScriptNotifications` 在后台每2秒读取实时任务快照；内容变化才刷新，岛上时长约10秒校准，普通通知使用系统 Chronometer。不会每帧运行 JS 或频繁读取定时任务数据库。
- `PocRuntime.runningTasksForNotification()` 仅提取原有任务页的运行项，涵盖主进程、:script、:native，Node池通过:script登记避免重复；legacy Node 保持原来的可选合并规则。
- `HostScripts` 增加通知用的快照/单项停止薄桥，单项停止复用 token 路由；主进程 UI 执行先走 ScriptEngineService.stopExecution，普通执行才 forceStop。
- `PocScriptHost` 缓存本次任务引擎及提交时间，通知刷新不再反复读取每个脚本文件头；native 路径补提交时间，主进程由 onStart 的引擎 tag 提供时间。排队任务计时从提交起，不是纯 JS CPU 时间。
- `XiaomiFocusSupport` 按官方查询 `persist.sys.feature.island`、`notification_focus_protocol` 与 `canShowFocus`；查询在后台，服务缓存60秒，诊断页回前台重新读取。没有绕过焦点通知或系统通知权限。
- `XiaomiFocusPayload` 构造 param_v2、baseInfo、大小岛、actions 引用；Native extras 注入 `miui.focus.actions` / `miui.focus.pics`。按 Unicode code point 限制文本，最终 UTF-8 参数严格小于3072字节。`filterWhenNoPermission=false`、不自动展开、不更新排序，保留普通通知回退。
- Action 使用不可变 PendingIntent、具体执行 token 和本次服务的随机 nonce。服务重建前的旧停止按钮不能停止新一轮执行；处理前再核对当前活跃 token。未导出诊断 Activity；停止服务无新增导出入口。
- 最后一个任务结束时先移除旧通知，再根据保活设置显示普通服务通知或关闭，避免“任务已结束但岛还保留旧内容”。极短任务可能在2秒合并窗口内完成，不强制闪岛。

### 计数可信度修复

统一执行表之前是无锁 LinkedHashMap，而且普通线程先启动后登记；极快脚本可能先结束/删除、再被 put 回形成幽灵项。本轮加入同步 ScriptExecutionRegistry 和稳定快照，普通执行先登记再启动，UI 启动与登记在同一锁内完成；无引擎失败、启动失败清除对应执行项。正常 UI/Looper 执行仍等真正 engine remove，不在成功回调提前删表。

没有扩大到宿主重启后的任务 query 协议、UUID token 改造或 Node owner binder death 全面治理；主进程被杀后仍存活的孤立宿主任务不保证重新枚举。本轮沿用原任务页的跨进程登记与清理语义，不声称已经解决全部崩溃恢复缺口。

## 安装后怎么测

1. 安装测试 APK，开启 AI.js Pro 的系统通知权限；如果应用通知设置有焦点通知开关，也开启。
2. 解压配套“三引擎通知测试脚本.zip”，先运行 Rhino，再运行 QuickJS，最后运行 Node。文件使用显式引擎注释，每个运行90秒，不调用无障碍、不点击其它应用。
3. 回到桌面，等数秒观察超级岛。无岛时拉下通知栏，先看是否有“3个脚本运行中”；点通知进入“脚本运行状态”。
4. 点“停止当前”应只少一个（默认最近提交的 Node）；其它任务继续。状态页可再逐个停止，或停止全部。
5. 再运行一个并等待90秒自然结束，确认岛撤除；若设置保留前台服务，留下“后台服务已开启”通知是正常行为。
6. 若仍不上岛，点“复制诊断信息”，回传 JSON 和通知/岛截图。重点区分系统能力、协议、应用通知、焦点权限。焦点权限未开通不能仅靠客户端代码承诺上岛。
