## 2. 代码改动（W4 task-10 / task-12）

### A. 503 写失败不再可能杀死 accept 循环

- 旧：catch (_: Exception) → Error（如 OOM）仍会穿出 acceptConnections 的 while。
- 新：catch (Throwable) + 记录（noteListenerFailure：respond_503 / accept / prepare_socket）；acceptConnections 外包 try/finally，循环真退出时 alive=false。
- 选型：**不退出循环**（退出就等于回到「占端口再也不 accept」），改成「重试 + 留痕」，健康状态可从 get_status 读。

### B. 顶层 running 与真实监听同源

- running = liveListening && listenerAlive；旧值移到 **persistedRunning**（不能当健康判据）。
- 新增 **listener{alive,failureCount,degraded,lastFailure}**；status 新增 **degraded**（实例在但 accept 循环死；此时 listening=false）。
- 注意两个同名 degraded：status=degraded＝循环死了；listener.degraded=true＝**失败过**（failureCount>0）但循环可能还活着。
- 兼容性：消费方只有 McpTools.get_status（已同步）；App 内 UI/readState/isRunningFresh 读 SharedPreferences，未改动；健康路径字段值不变。

### C. 自愈链路真修（不是改文案）

- 旧：McpAutoLifecycle 有 lastError != null 前置 → 启动失败后**永不再试**（而 recovery 文案还承诺会自动拉起）。
- 新：新增纯策略 McpAutoStartPolicy（RETRY_AFTER_MS=30s）；McpService.lastError 自定义 setter 同步 lastErrorAt；McpAutoLifecycle 改用 canAutoStart()。

### D. 503 补标准 Retry-After: 1（task-12）

- 与 body 的 retryAfterMs 同源（唯一常量 BUSY_RETRY_AFTER_MS=1000L，秒数向上取整）。
- 评估后**有意不做**的两项：D1 503 加 CORS（503 产生在「一个字节都没读」时拿不到 Origin；只能反射任意 Origin＝安全倒退）；D3 body 改 JSON-RPC 形状（不读 body 不可能知道请求 id，伪造 id:null 更糟）。
