## 1. 六项源码缺陷的处理

| 问题 | 本次实现 |
|---|---|
| Compose 返回/刷新回到顶部 | `LazyListState` 提升到 Host，按目录独立保留；刷新时不移除已显示的非空列表；切目录未读完时不拿旧目录或空数据测量新目录的列表状态 |
| Compose 新建四项无响应 | Fragment 按当前使用的列表取 `ExplorerPage`，新建文件夹、文件、导入、项目共用现有 `ScriptOperations` / `ProjectConfigActivity`，不再要求旧 `ExplorerView` 必须存在 |
| 搜索只切目录，没有定位高亮 | 按存储根或内置示例根校验 canonical 路径，生成根到父目录的导航路线；读取后按文件路径找到排序后的行，滚动并高亮约 1.8 秒；清除原过滤条件以免隐藏命中项 |
| 删除后仍显示旧文件 | 去掉弹确认框后立即刷新；Host 监听 `ExplorerChangeEvent`，在真正删除成功后刷新，同时接收新建、导入、重命名、项目变更通知 |
| Host 没有销毁清理 | `onDestroyView` 保存状态并 `dispose`，取消加载与 Host 持有的操作订阅，注销文件变更监听，清空 View/Host/菜单引用；加载序号阻止旧结果覆盖新页面 |
| 图标操作无障碍名称缺失 | 返回、项目操作、排序方向、排序方式补名称与按钮角色；运行/更多按钮名称包含文件名；文件行补打开与长按动作名称、高亮选中状态 |

装饰性文件图标仍保持 `contentDescription = null`，名称来自文件行文本，不重复朗读图标。
这次未实现仍属于 S4 的“项目页标题/指南针 → 项目操作菜单”，也未补文件列表实验开关的设置入口。

## 2. 同步修复默认旧列表的状态保存

实验开关 `aijspro.experimental.miuix_file_list` **仍默认关闭**，没有擅自切换用户界面。因此也修改了 `ExplorerView`：

- 保存第一条可见行及像素偏移，不再只记录“完全可见”的行号。
- 进入编辑器、切目录、返回、窗口脱离时记录位置。
- 用 `scrollToPositionWithOffset` 一次排队恢复，去掉会覆盖用户新操作的延迟二次滚动。
- Fragment 保存目录栈和各页位置，在正常状态保存/页面重建后恢复。
- 取消旧加载并校验页面与加载序号，防止快速切目录、返回或销毁后晚到的结果覆盖界面。
- 搜索高亮的延迟清理也检查加载序号，避免影响另一目录。

新旧列表用 `ExplorerPageFactory` 重建目录页，保留项目和内置示例的页面类型。
Compose 状态另保存过滤条件、待定位目标和按路径锚定的当前位置。
这是 Fragment 保存状态恢复，不是承诺 force-stop / 清数据后永久保留浏览位置。
