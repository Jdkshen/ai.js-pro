# R01：Node Java 反射空可变参数修复（候选 dev-1293）

日期：2026-10-31。依据：[高级版与三引擎剩余对齐总账](2026-10-30_高级版与三引擎剩余对齐总账.md) 的 R01。

## 现象

Node24 的 Java 互操作在 `findMethod` 里只按「参数个数完全相等」匹配：

- `java.lang.String.getMethod("toString")` 面对 `getMethod(String, Class<?>...)` 时，
  本应自动补一个空的可变参数数组，旧实现认为 2 != 1，直接报找不到方法。
- 只有显式写 `getMethod("toString", [])` 才能工作。

## 修复

- `Node24JavaArguments` 新增 varargs-aware 的 `compatible / coerce / score`：
  - 零个、一个、多个尾随实参分别打包成空数组、单元素数组、多元素数组；
  - 显式 JS 数组按「直接传数组」处理，省略写法与显式空数组结果一致；
  - 基本类型展开按组件类型收窄（Double → int 等）；
  - 固定参数个数的方法优先于 varargs 重载。
- `Node24HostBridge` 的 `findMethod`、`findConstructor`、`invokeMethod`、构造器 `newInstance`
  全部改用同一套规则；删除旧的只比较参数个数的本地 helper。
- 异常语义不变：`invokeMethod` 仍解包 `InvocationTargetException` 并保留 cause，
  找不到方法仍是带类名/方法名/参数描述的 `NoSuchMethodException`。

## 边界

- 单个 `null` 尾随实参按「一个 null 元素」处理，没有把它当成整个数组；
  要传整个 null 数组需要走显式类型/数组路径。
- 构造器 varargs 走同一套 helper，但还没有单独的真机构造器用例；
  可在 Java/Dex 互操作盘点（A01）里补。
- 本次只改 Node24 的 Java 反射匹配；QuickJS 侧本来就有自己的 varargs 处理，未改动。
