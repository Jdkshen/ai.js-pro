## 指标口径

- **严格**：单元格必须与真值完全一致（**含阵营**）。
  ⚠️ 曾经把大小写归一化，等于「颜色判错不算错」—— 那样会把 81.9% 报成 88.5%，所以口径必须是严格的。
- 「只看兵种+位置」：只用来定位问题属于「认错子」还是「认错色」。
- **未知格数**：自动走棋的出手闸门就是「未知格必须为 0」，所以它单独报。

## 结果（2026-09-13）

| 模型 | 会话级几何校准 | 严格盘面级 | 平均未知格 | 纯颜色错 |
|---|---|---|---|---|
| 仓内 chessai_160 | 关 | 221/270 = **81.9%** | 6.0 | 18 |
| 仓内 chessai_160 | **开** | **262/270 = 97.0%** | 1.0 | 0 |
| v4（训练到约 20/50 轮时抽样） | 关 | 222/270 = 82.2% | 7.0 | 19 |
| v4（同上） | 开 | 261/270 = 96.7% | 2.3 | 0 |
| 仓内 chessai_160 + **翻色修复** | 开 | **265/270 = 98.1%** | **0.0** | 0 |

结论：
1. **几何校准是决定性的**（+15 个点）：定位原点有约 10px 系统性偏差（三帧一致选出 `(-6,-3)`），
   对齐后格心采样点才落在棋子中心，阵营判定才准（颜色错 18 → 0）。
2. **v4 目前不比仓内好**（校准后 96.7% vs 97.0%，未知格 2.3 vs 1.0），但它域内 mAP50 更高（0.59 vs 0.53）→
   等 50 轮跑完再看。
3. 剩下的错基本只有两处硬漏检：`(5,0)` 黑士 与 `(4,7)` 红炮（三帧都漏），属于模型召回问题。

## 这轮查出并修掉的两个真问题

1. **棋规反查把「颜色错」当「多一个子」丢掉**（`consistency.repair`）：
   模型把黑士判成红仕 → 同时触发「仕士不在九宫」和「红仕 3 个」→ 修复直接把这枚子降级成未知（真的少一个子）。
   现在两条分支都先试**改阵营**（翻完不引入新硬违规、另一色未满就翻），只有真的多子才降级。
2. **校准的搜索代价不能只看未知格**：有了翻色修复后，任意偏移都能凑出「0 未知格」，
   搜索会立刻停在未对齐的 `(0,0)`，反而把颜色正确性丢掉（颜色错 0 → 18）。
   现在代价 = `修复动作数 × 1000 + 未知格数`（先看修复动作，再看未知格）。
