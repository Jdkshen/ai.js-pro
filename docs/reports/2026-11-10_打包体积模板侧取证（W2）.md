## 2. 分批最小改动（默认行为必须不变）
**第一批（确定无用才排除；建议先做）**
1. 排除 org/antlr/codegen/**（ANTLR 工具模板；保留 org/antlr/runtime/** 与其余 org/antlr/**）。落点：打包期的「模板条目过滤」——NativeLibPolicy 只管 .so，所以需要一条**资源级**排除规则；模板重建脚本（build-slim-template.ps1，Lead 的文件）里也建议同排除，源头更干净。
2. ai_js_pro_logo.png / ic_launcher.png 换 WebP 或降分辨率（资源侧改动，不动打包策略；预计省 ~1.9 MiB raw）。落点：inrt/engine 的 res 源（本机源码里未找到同名文件 ⇒ 先定位再换，见「未验证边界 3」）。
**第二批（工程显式声明才省；每条独立开关、默认 false）**
3. optimization.removeOcr（默认 false）→ 剔 libmlkit_google_ocr_pipeline.so + libppocr.so + assets/mlkit-google-ocr-models/**（合计 raw ~17.4 MiB、压缩 ~8 MiB 级）。落点：NativeLibPolicy.kt:31/53 + ApkBuilder.java:689-706（与 task-95 一致）。
4. features.nodejs=disabled → 剔 assets/source-engine-upgrade/** + assets/node24/**（合计 raw 2.18 MiB）。前置：McpEngineDiagnostics.kt:24/105/141 改成「资源缺失 → degraded」而不是报错。
5. （可选）v2/v3-only 签名 → 省 META-INF 的 MANIFEST.MF + CERT.SF ~0.5 MiB；需确认 minSdk 与低版本校验策略。
6. （需真机 A/B）libc++_shared.so 去重：改 node 运行时加载器去 lib/ 取，才可只留一份。
不建议：单独删 libopencv_dnn.so（DT_NEEDED 硬依赖，删了 OpenCV 直接挂）。

## 3. 未验证边界
1. **未跑构建/装机/发布/git**；没有真机 A/B，本表「是否必需」全部是**静态取证**结论（零命中 / DT_NEEDED / 读点 file:line），不是运行期实测；运行期侧由 task-95 覆盖。
2. 本机复跑用的是**旧模板形态**产物（lib 只有 7 条），只用来验证方法与压缩占比；**生产形态数字以 K40 清单为准**。
3. ai_js_pro_logo.png / ic_launcher.png 的**源码位置未定位**（apps/modules 下 grep 同名零命中）⇒ 换图前要先在 inrt/engine 的 res 里按 drawable 名找到真身；两处字节数相同只是**高度疑似同一张图**，未做逐字节比对。
4. org/antlr/codegen/** 的「零命中」是对**本仓 Java/Kotlin** 的 grep + 我们对 ANTLR 的已知用法（只 import org.antlr.runtime）；**没有**验证第三方 jar（smali/dexlib2 等）运行期是否读这些 .stg（smali 自带 antlr runtime 语法解析、不用 ANTLR 工具的 codegen 模板，属推断）。
5. 排除「模板条目」需要一条新的资源级过滤规则（现有 NativeLibPolicy 只管 .so，PackageOutputExclusions 只管工程 copy）⇒ 落点建议已给，但**未实现**（按用户要求只出建议，避免一次性改一堆）。
6. META-INF 的 v1 签名是**我们的输出**（ApkSignerV1），不是模板遗产 —— 与「0.54M 是遗产可删」的直觉相反，改动前务必确认 minSdk 策略。
