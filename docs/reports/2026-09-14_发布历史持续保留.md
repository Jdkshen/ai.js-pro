# 发布历史持续保留

截图中的 30 条来自 `tools/serve-updates.ps1` 的默认参数 `HistoryLimit = 30`。此前每次发布都会截断 `update-history.json`，更新清单的 `oldVersions` 也只剩这些记录。

## 修改

- `HistoryLimit` 默认改为 `0`，持续保留全部发布记录。正数仍可显式启用截断；正常发布流程不传该参数，因此默认不限数量。
- 历史 JSON 读取失败时终止发布，避免用空历史覆盖已有记录。
- 新增 `tools/render-update-history.ps1` 和 `tools/templates/release-history.html`，发布后自动生成完整历史网页，更新说明经过 HTML 转义。
- 历史记录按版本号去重，重复发布同一版本会更新该条记录。

## 旧记录恢复

从本地日志补回 17 个版本：536、537、539、541–554。合计由 30 条恢复到 47 条。

537、539、541、552 找回原更新说明；其余 13 条标明原说明未能恢复。536 依据发布产物校验和手机 HTTP 200 记录恢复；552 由后续成功发布 553 时记录的更新源及手机版本确认；其余版本均有成功发布完成标记。536 的日期取日志文件修改日期，其他日期取日志文件名。

原 `update-history.json`、`update.json`、`release-history.html` 及恢复证据审计文件保存在 `.artifacts/history-backup-20260914-194625/`。更早缺少可核实发布记录的版本没有补造。

本次仅修改发布工具和历史元数据；当前更新包仍为 dev-586，APK 文件、校验值和下载地址保持原值。这里保留的是版本记录与更新说明；旧 APK 的归档需要另行实现。

- 32 条历史默认全部保留。
- 再次发布 dev-586 后仍为 32 条，同版本只有一条，说明被更新。

- 损坏的历史文件触发终止，历史和原清单不被覆盖。
- 测试前后真实 `update.json` 的文件哈希一致。
