## 第一批：UI 优化（优先完成）

### 主页面

当前 `main.js` 是长表单与大量同级按钮。重排为以下层级：

## 第二批：修剩余安全缺陷

### 修复 detect 定位分支的错误成功

`tools/recognize-board.js` 的 `pickGrid(..., {mode:'detect'})` 当前选择最低代价候选后，返回 `ok: !!best.result.ok`。而 `recognizer.result.ok` 只表示布局串可以生成，可能仍有缺将帅、UNKNOWN 过多、覆盖率不足或棋子数量异常。

要求：

- detect 与 cached 两条路径共用同一个候选验收函数；验收将帅、非法字符、UNKNOWN 上限、覆盖率、兵种上限以及有效图像证据。
- 返回结构统一包含 `accepted`、拒绝原因列表、pieces/empty/unknown/coverage/violations。
- 加反例测试：缺将、将帅都缺、UNKNOWN 过多、框在棋盘外、合法 2/4/8 子残局。
- 禁止用 `result.ok` 替代“适合用于自动执行”的判断。

### 模型和配置一致性

- 当前唯一随包模型实际是 `chessai_160x320_v5r.onnx`，输入 `[1,3,320,160]`，SHA-256 `6A695F00A845705E4B8F26AA6E991B5FB2AB1A7BB81FD2BCBF8B89A6EF84BECB`。
- UI、README、运行日志统一显示 `160×320 矩形档`，不要仍写默认 160×160。若要恢复方形档，只能作为单独 A/B，不得只改文件名而保留 320 高度。
- 加载时核对实际输入输出形状和七类标签，不依赖 README 声明；错误时停止识别并给出可读原因。
