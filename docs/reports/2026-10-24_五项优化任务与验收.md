## 主助手复核与修正

DP 的交付报告是首版工作记录，不能替代主助手验收。四个独立任务均已通过 `status/result` 确认完成；任务 3/4 共用一个 worker，避免 Gradle 文件冲突。

1. **M3 导航**：首版依赖宿主 `wireNavigation`，VM 模拟中存在该绑定，实际本地资源 Activity 却不能靠它完成底部切页。主助手恢复示例的显式监听器（setter 替换旧监听），用当前页判断避免回调环，并补“宿主导航缺失”的测试条件。不能按首版报告宣称已删除全部重复导航代码。
2. **M3 生命周期**：补 `defineClass` await 恢复后的页面身份检查，关闭中的 Grid 不再安装 adapter；新增中途关闭用例。补 `onBackPressed`：抽屉可见时先关闭抽屉，随后一次返回退出 UI。真机已见首页、抽屉、日志、设置、FAB Snackbar 和退出后的原页面，截图 `five-integrated-interactive-screen-*`。
3. **M3 性能**：最终脚本在同一 dev-1240 宿主上，改前/改后暖运行各 5 轮。Grid setup end 改后 `[1043,994,965,1044,981]ms`，中位 **994ms**，对照 1307ms 约少 **24%**。`onContentViewSet:end` 中位 748→650ms。Drawer setup end 改后中位 1666ms，晚于旧脚本全部 setup 的约 1307ms；它被排到卡片布局后面，不能宣称所有 setup/图片/用户点击首帧都快了 24%。没有冷启动或端到端 P95 结论。
4. **缓存**：BasicFileAttributes.fileKey 在 Windows 可为空。主助手补创建时间和可用 Unix ctime 作为元数据；所有身份字段都不可用时拒绝缓存快路径，重新完整 SHA；没有用假 inode。JDK17 文件测试 **10/10**。仍是应用私有目录的安装状态缓存，不防同 UID/root 蓄意伪造；首次/升级后完整校验保留。
5. **探针与诊断**：补 Symbol.toStringTag/getClass 自定义 getter 与异常 message getter 的保护；真实模板 Node VM 测试通过。pool fallback 同时拒绝 CancellationException、InterruptedException、Error 和过深异常链。诊断改用 ActivityManager 同 UID 进程列表，取消每次状态刷新枚举全部 /proc。记录当前进程 MCP 的真实失败时间/类型/执行 ID，不复制源码、路径、堆栈或异常消息。
6. **构建**：Flutter AOT 成功后 robocopy 的成功退出码 1 原来会泄漏到调用者，主助手在成功完成处明确返回 0。release 候选脚本增加单 worker/受控 JVM heap，避免默认并行构建造成内存压力。第一轮实际 release 构建被清单硬门正确拦下：共享清单的 Receiver 没被低优先级 overlay 移除；现拆到 `src/flutterpocDebug/AndroidManifest.xml`，release 仅共用业务清单，保留最终清单硬门。

## Release 构建问题的实际处理

1. 首轮被最终清单校验拦截：共享清单内的 DebugCommandReceiver 无法被低优先级 overlay 清除；已将声明拆入 debug 专属清单，而不是放松校验。

3. 2048MB 重试暴露上游 JAR 的缺失引用：Flutter 未启用的 Play Store 分包、ANTLR/StringTemplate 桌面 GUI、log4j 桌面 JavaBeans 配置、R8 JVM XML 路径、Joda 注解和 SLF4J 可选绑定。已逐个核对调用点，并按生成的**具体类型**添加 dontwarn；未添加全局忽略规则，也未移除运行期 D8/Smali 能力。新缺失类型仍使构建失败。
4. 最终候选构建和真机验证结果见后续记录。另一个工作项同时在修改象棋插件及其版本字段，本轮没有接管或覆盖这些变更；候选 App 版本通过 Gradle 属性单独注入。
