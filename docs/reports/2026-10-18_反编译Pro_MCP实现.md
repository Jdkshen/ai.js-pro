## 0. 结论摘要（先看这 8 条）

> **2026-10-18 已在真机补做运行时实测**：Pro 默认监听 `*:8765`（通配 0.0.0.0）、无令牌、CORS `*`、POST 任意路径等价、GET 一律 405 —— 详见 §12。以下第 1/2/3/4/5 条已由实测坐实。

1. **Pro 有 MCP，但类名不是 McpService/McpHttpServer**：`org.autojs.autojs.ui.edit.aiagent.mcp.MCPService`（Android Service，跑在 `:script` 进程、前台服务）+ `...mcp.McpServer`（真正用 `ServerSocket` 手写 HTTP 的实现），另有 `McpFloatingControl`（悬浮球）、`ScreenCaptureActivity`（MediaProjection 截屏）、`MCPService$State`、`McpServer$ServerInfo`、7 个工具类。
2. **默认端口是 8765，不是 8788**：`McpServer.DEFAULT_PORT = 8765`、`McpServer.MAX_PORT = 8795`，被占用时由 `bindAvailablePort()` 在 8765..8795 之间顺延。**8788 是我们 POC 自己的默认端口**——实测设备上 `127.0.0.1:8788` 属于 `com.jdkshen.aijspro`（uid 10267），Pro 的 `LocalDataServer` 监听 `127.0.0.1:19888`（uid 10219），Pro 的 MCP 当时未启动。
3. **端点 POST /mcp**，JSON-RPC 2.0，只需 `initialize` / `tools/list` / `tools/call`；dex 里**没有** `text/event-stream`、`Mcp-Session-Id`、`mcp-session` 之类常量，说明 Pro 走的是**一次性 JSON 响应（无 SSE / 无会话）**——与我们 POC 的「stateless Streamable HTTP」一致。
4. **Pro 的 MCP 没有令牌认证**：全 dex 的 `authorization`/`Bearer` 只出现在 okhttp/Hpack 等三方库；且随包技能文档 `assets/skills/Auto.js-AIAgentSkills.md` 原文写着「当前 MCP 服务不要求 Token；如服务端未来增加认证，必须使用用户提供的凭据」。
5. **Pro 默认允许跨域**：`McpServer` 有 `sendCorsResponse(OutputStream)` 方法（说明实现了 CORS 响应头，通常含 OPTIONS 预检）。
6. **Pro 没有 autoStart 持久化开关**：全 dex 无 `auto_start`/`autoStart` 常量，也没有 BOOT_COMPLETED → MCPService 的链路；启动入口全是用户操作（AI 助手面板、悬浮球、工具箱里的「远调·MCP」）。
7. **状态靠 SharedPreferences aiagent_mcp_state + 10 秒心跳**：键 `running` / `updated_at` / `port` / `local_url` / `lan_url` / `error`，`HEARTBEAT_TIMEOUT_MS = 10000`，UI 只有在 `updated_at` 足够新时才认为「运行中」。
8. **工具集（Pro 名）**：`runScript`、`checkSyntax`、`getUiLayout`、`captureScreen`、`getMcpLog`、`stopAllScripts`、`learnAutoJsSkill`（对应类 `RunScriptTool`/`CheckSyntaxTool`/`GetUiLayoutTool`/`CaptureScreenMcpTool`/`GetMcpLogTool`/`StopAllScriptsTool`/`LoadAutoJsSkillTool`）。

## 5. 调用链

### 5.1 启动

```text
[用户操作：AI 助手面板 / 悬浮球 / 工具箱「远调·MCP」]
        │
        ├─(A) 反射路径：LocalMcp.onStartCommand(service, intent)
        │        └─ worker ─► McpServer.startOrGetMcp(ctx)        // 单例，已有则复用
        │                    ─► MCPService.saveRunning(ctx, info)  // 写 prefs: running/updated_at/port/local_url/lan_url
        │                    ─► sendBroadcast(MCP_STATE_CHANGED)   // 通知 Flutter/工具箱刷新
        │                    ─► lanAddress(ctx, port) + "/mcp"     // 生成对外地址
        │                    ─► NotificationManager.notify(1001, ...)
        │                    ─► Log.i("AumaLocalMcp", "Offline MCP is running")
        │
        └─(B) 服务路径：MCPService.start(ctx)  // 静态 native
                 └─ startForegroundShell() → startForeground(1001, buildNotification(), type)
                    ├─ showFloatingWindow()  (WindowManager + 拖拽)
                    ├─ startForegroundCompat() / enableMediaProjectionForeground()
                    └─ 心跳 statusTicker（Handler，10s 内刷新 updated_at）
```

### 5.2 停止

```text
MCPService.stop(ctx) / Intent(action=...mcp.STOP)
   └─ McpServer.stopMcp() → server.stop() → serverSocket.close() + serverThread.interrupt()
      └─ saveStopped(ctx) → prefs.running=false，清 error/updated_at
         └─ removeFloatingWindow() + stopForegroundService()
```

### 5.3 一次 MCP 请求

```text
TCP accept (serverLoop)
  └─ handleClient(Socket)
       ├─ 读 HTTP 请求行/头（手写 HTTP，非框架）
       ├─ OPTIONS → sendCorsResponse(out)                // 跨域预检
       ├─ POST /mcp → handleJsonRpc(body)
       │     ├─ method=initialize      → handleInitialize(session, req)
       │     ├─ method=tools/list      → handleToolsList(session)      // ToolSpec.toJson() 列表
       │     ├─ method=tools/call      → handleToolsCall(session, req)
       │     │        └─ ToolSpec.method.execute(arguments)  // McpMethod
       │     │             ├─ RunScriptTool      → McpServer.runScript(source, path)
       │     │             ├─ CheckSyntaxTool    → 编译校验
       │     │             ├─ GetUiLayoutTool    → 无障碍 UI 树
       │     │             ├─ CaptureScreenMcpTool → ScreenCaptureActivity(MediaProjection)
       │     │             ├─ GetMcpLogTool      → getMcpLogFile()/readTailText(file, maxChars)
       │     │             ├─ StopAllScriptsTool → stopAllScripts()
       │     │             └─ LoadAutoJsSkillTool → readAutoJsSkill()（assets/skills/Auto.js-AIAgentSkills.md）
       │     ├─ 成功 → createSuccessResponse(id, result)
       │     └─ 失败 → createErrorResponse(id, code, message, data)
       └─ sendHttpResponse(out, code, contentType, body)
```

| getUiLayout | {} | 获取当前界面的 UI 布局 XML、节点数量和控件结构 | 每个新任务开始时优先调用 |
| runScript | source 或 file，可选 config | 执行 Auto.js 源码或脚本文件 | checkSyntax 通过后调用 |
| stopAllScripts | {} | 停止所有正在运行的 Auto.js 脚本 | 仅用户明确允许时 |
| checkSyntax | {code} | 检查 JavaScript 语法并返回错误 | 每次生成/修改脚本后 |
| captureScreen | format?、quality?、dataUri? | 截图并返回图像信息 | UI 树不完整/自绘/图色场景 |
| getMcpLog | maxChars? | 读取脚本执行日志 | 失败/无响应/需确认后台状态 |

参数规则（原文要点）：

- runScript 必须提供 source 或 file 之一；config 虽声明 path/delay/interval/loopTimes/arguments，但**执行端默认使用固定配置**，不要依赖它。
- checkSyntax 只做语法检查，不代表控件存在或权限开启。
- captureScreen 默认 png、质量 100。
- getMcpLog.maxChars 默认 20000，上限 200000。
- 执行结果记录 success、scriptId、result 或 error。

> 第 7 个工具 learnAutoJsSkill 不在文档表格里，但代码里是 `AUTOJS_SKILL_TOOL = "learnAutoJsSkill"` + LoadAutoJsSkillTool，返回上面这份技能文档——**这是 Pro 让 AI 客户端「自举」的关键设计**。

## 7. 生命周期 / 通知 / 悬浮窗

- **前台服务**：通知 id 1001、渠道 autojs_mcp（名 本地 MCP，IMPORTANCE_LOW=2）、setOngoing(true)、点击打开 App（PackageManager.getLaunchIntentForPackage）。

## 9. 可直接落地的修改建议

> 按「先对齐行为、再加分」排序；每条给出落点文件。**本轮未改任何代码，仅建议。**

### P0（不修就是功能/GKI 问题）

**P0-1 端口：默认 8765，冲突时 8765..8795 顺延**
- 落点：`apps/app/src/miuix/java/com/jdkshen/aijspro/mcp/McpSettings.kt`（KEY_PORT 默认值 8788 → 8765）
- 落点：`McpService.onCreate`（McpSettings.port(this) 传给 McpHttpServer）
- 做法：McpHttpServer.start() 捕获 BindException，端口 +1 重试到 8795；成功后把**实际端口**写回设置/状态（Pro 的 saveRunning 就是把实际 port 持久化，客户端读状态而不是猜端口）。
- 同步：docs/HANDOVER.md、docs/MCP_SCRIPT_SERVICE.md 里所有 8788/18790 示例需更新（或保留 8788 作为「兼容旧版」）。
- 设备证据：ss -ltn 显示 8788 属于我们（uid 10267），Pro 的 19888 属于 com.boyai.auma。

**P0-2 foregroundServiceType + 生命周期**
- 落点：`apps/app/src/miuix/AndroidManifest.xml` 的 `<service android:name="...McpService">`
- 做法：加 `android:foregroundServiceType="dataSync|connectedDevice"`（targetSdk 34 必需，否则 startForeground 抛 MissingForegroundServiceTypeException）；stopWithTask 由 true 改 false，onStartCommand 返回 START_STICKY（Pro 做法），使划掉任务后 MCP 仍可用。
- 取舍：若产品语义坚持「关 App 就停服」，可只加 type、不改 stopWithTask，但要把这一点写进 UI 文案。

**P0-3 状态持久化 + 心跳（避免假「运行中」）**
- 落点：`McpService.kt`（新增 statePrefs 写入）、`MiuixMcpActivity.kt`（状态读取）
- 做法：照 Pro 的 aiagent_mcp_state 契约写 running/updated_at/port/local_url/lan_url/error；服务每 3–5 秒刷新 updated_at；UI 判定 running && now - updated_at < 10000；onDestroy 写 running=false。
- 好处：进程被系统回收或服务换进程时，UI 不再一直显示「运行中」。

### P1（对齐 Pro 客户端体验）

**P1-1 工具名 camelCase 别名（低风险、高收益）**
- 落点：`McpTools.kt` 的 listTools() 与 dispatch
- 做法：注册表加别名映射：runScript→run_script、checkSyntax→check_syntax、getUiLayout→get_ui_layout、captureScreen→capture_screen、getMcpLog→read_apk_logs、stopAllScripts→stop_script、learnAutoJsSkill→learn_autojs_skill；tools/list 同时返回主名（snake）与 title，dispatch 两种都接受。
- 好处：Pro 的提示词/技能文档可直接喂给我们的 MCP 客户端。

**P1-2 参数/返回字段对齐**
- checkSyntax{code}：若缺失应补（纯语法校验，不执行）。
- getMcpLog{maxChars}：默认 20000、上限 200000，尾部读取（对应 Pro readTailText）。
- captureScreen{format,quality,dataUri}：默认 png/100。
- runScript 返回加 success/scriptId/result/error 顶层字段做兼容。
- 落点：`McpTools.kt` 各 tool(...) 定义与 McpToolSchema。

**P1-3 CORS**
- 落点：`McpHttpServer.kt`（serve() 的响应头构造）
- 做法：所有响应加 `Access-Control-Allow-Origin: *`、`Access-Control-Allow-Headers: Content-Type, Accept, MCP-Protocol-Version`、`Access-Control-Allow-Methods: POST, GET, OPTIONS`；OPTIONS 直接 204。
- 依据：Pro 有 sendCorsResponse(OutputStream)，官方实现允许跨域（浏览器内 MCP 客户端需要）。

**P1-4 鉴权策略与 UI 提示**
- 现状：我们默认 Bearer + 只绑 loopback；Pro 无鉴权 + 默认对局域网开放。
- 建议：**不要**为「像 Pro」而默认取消 token；改为：
  - 保持 lanEnabled=false 默认（更安全），但把「局域网」开关旁说明改为「Pro 默认对局域网开放且无令牌；本 App 打开后会生成令牌」；
  - 状态页/复制地址展示「本机地址（免令牌）/局域网地址（需 Bearer）」两行（MiuixMcpActivity 已有「本机地址」，补一行局域网）；
  - 若确实需要零配置直连，用 lan_no_token 显式开关 + 风险提示（allowLanWithoutToken 参数已存在，接上 UI 即可）。

**P1-5 协议细节对齐（§12 实测后新增）**
- **路径宽容**：Pro 对 `POST / `、`POST /foo` 与 `POST /mcp` 一视同仁；建议我们至少接受 `/` 与空路径（或统一 404 → 仍执行），避免用户把 `http://ip:8765/` 填进客户端就失败。
- **错误语义**：JSON-RPC 错误（-32601/-32700/-32603）仍回 HTTP 200；只有方法不允许回 405、预检回 204。我们需确认现有实现是否给 400/500，若不同建议按 Pro 对齐（客户端兼容性更好）。
- **initialize**：Pro 固定回 `protocolVersion: "2024-11-05"`，无视客户端版本；我们若做协商，建议至少保证对 2025-06-18 客户端仍返回它认识的版本，避免客户端主动断开。
- **notifications/initialized**：Pro 返回 -32601（未实现通知）。我们若实现，应返回 202/空 200 而不是错误。
- **工具信封**：主形态用纯 `content:[{type:"text",text:"<JSON 字符串>"}]`（Pro 形态，兼容性最好），`structuredContent` 作为**附加**字段；工具业务失败用 `success:false` 放在 text JSON 内，`isError` 可作为附加。
- **batch**：Pro 不支持 JSON 数组（-32700）。我们可以不支持，但错误信息应可读（Pro 直接把 org.json 异常抛给客户端）。
- 落点：`McpHttpServer.kt`（状态码/路径判定）、`McpTools.kt`（信封/错误）。

### P2（增强）

- **P2-1 learnAutoJsSkill**：把技能文档做成资产（Pro 是 assets/skills/Auto.js-AIAgentSkills.md），工具返回全文；我们 McpTools.kt:222 已有类似读取，改名 learnAutoJsSkill 并补 camelCase 别名即可。
- **P2-2 截屏专用 Activity**：Pro 用 ScreenCaptureActivity（:script、excludeFromRecents、enableMediaProjectionForeground）承接 MediaProjection 授权，避免打断正在跑的脚本；我们的 capture_screen 若在主进程请求授权会打断 UI，可照抄。
- **P2-3 状态广播**：用 MCP_STATE_CHANGED 这类包内广播替代 Compose 的 750ms 轮询（MiuixMcpActivity.kt:92），省电且刷新及时。
- **P2-4 错误文案对齐**：本地 MCP 启动超时 / MCP 操作失败： / 服务操作失败： / Local MCP start failed（日志）；端口占用时给「8765..8795 均被占用」而不是笼统「端口启动失败」。

### 12.2 HTTP 语义（实锤，curl 实测）

| 请求 | 结果 |
|---|---|
| `POST /mcp` / `POST /` / `POST /foo` | 全部 200，行为一致 → **路径完全不校验**（端点只是习惯写法） |

| `OPTIONS /mcp` | `204 No Content` + CORS 头 |

| 会话 | 无 `Mcp-Session-Id`、无 `Cache-Control`、无 SSE |

> 结论：Pro 是**无状态、每请求一响应、连接即关**的极简 JSON-RPC over HTTP；不是 Streamable HTTP 的 SSE 分支。

### 12.4 错误语义（实测）

| 场景 | 返回 |
|---|---|
| 未知方法 `foo/bar` | `-32601` `Method not found: foo/bar`（HTTP 200） |
| 未知工具 `nope` | `-32601` `Tool not found: nope` |
| 非法 JSON | `-32700` `Parse error: Expected ':' after not at character 6 of {not json`（org.json 原文） |
| JSON 数组（batch） | `-32700` `... JSONArray cannot be converted to JSONObject` → **不支持批量** |
| `notifications/initialized` | `-32601 Method not found: notifications/initialized` → **不支持通知**（客户端发也无害） |
| 工具内部业务失败 | 仍返回 `result`，失败信息在 text 的 JSON 里（`success:false`） |
| 工具内部未捕获异常 | `-32603` `Internal error: "INVOKEVIRTUAL Object npe"` + `data` 字段（异常字符串） |

### 12.5 工具返回信封（实测）

统一形态（**没有** `isError`、**没有** `structuredContent`）：

```json
{"content":[{"type":"text","text":"{\n  \"valid\": true\n}"}]}
```

具体样例：

- `checkSyntax`：`{"valid":true}`；语法错时 `{"valid":false,"error":"    语法错误 (script.js#1)","line":1,"column":9,"type":"SYNTAX_ERROR"}`
- `learnAutoJsSkill`（maxChars:80）：`{"success":true,"tool":"learnAutoJsSkill","learned":true,"asset":"skills/Auto.js-AIAgentSkills.md","truncated":true,"content":"---\ntitle: ...","nextStep":"请基于已学习的技能先观察界面，再调用 getUiLayout 或 captureScreen；生成脚本后先调用 checkSyntax，再调用 runScript。"}`
- `getMcpLog`：`{"success":true,"packageName":"com.boyai.auma","path":"/storage/emulated/0/Android/data/com.boyai.auma/files/logs/log.txt","exists":true,"size":4882,"truncated":true,"content":"..."}`
- `runScript` 文件不存在：`{"success":false,"error":"java.io.FileNotFoundException: /sdcard/nope.js: open failed: ENOENT (No such file or directory)"}`
- `getUiLayout`（无障碍未开）：JSON-RPC `-32603 Internal error`（不是 success:false）
- `captureScreen`（无 MediaProjection 授权）：**6 秒内无任何响应**（请求挂起，等授权）

> 注意：text 里的 JSON 由 org.json 序列化，斜杠被转义成 `\/`（如 `\"path\":\"\/storage\/emulated\/0\/...\"`）；下游要按「JSON 字符串里再套 JSON」二次解析。

### 12.6 实测对我们最要紧的 4 个修正

1. **端口/绑定**：Pro 默认 `0.0.0.0:8765`（不是 loopback、不是 8788）。LAN 默认开放。
2. **鉴权**：任何请求无 token 直接可用；CORS `*`；无会话。
3. **路径**：Pro 不校验路径，POST 任意路径等价；对客户端更宽容（老客户端写错路径也能用）。
4. **信封**：Pro 只有 `content[].text`（内嵌 JSON 字符串），失败靠 `success:false`；我们多了 `structuredContent` 与 `isError`（更规范，但**若要兼容 Pro 生态客户端**，应保留纯 text 形态作为主路径，structuredContent 作为附加）。
