# 构件新鲜度自检加固：标记注册表 + 推导标记（W2 / task-91）

## 0. 要修的漏判
引擎加了 SjbcApi.forCurrentEngine()（QuickJS 分支）后模板没重建，但 -Deep 报 FRESH(kind=template) —— 因为标记集写死为三个**更早**的符号（SjbcApi/ScriptHostRouting/MultiProcessPrefs），**新符号没被要求** ⇒ **假 FRESH**。

## 1. 标记集改成可维护 + 防漂移
新增 **tools/artifact-markers.json**（version=1，键=类名/方法名，值含 since 版本与注释，共 6 组 15 个标记）：
- sjbc-core：SjbcApi/SjbcVm/SjbcKeySource/SjbcV5Container/SjbcHostFunctions
- sjbc-entry（今天漏判的那批）：forCurrentEngine/sjbcCall/toScriptValue/runJson/runEntryJson
- host-routing：ScriptHostRouting；cross-process-prefs：MultiProcessPrefs；script-broadcast：ScriptBroadcastReceivers/BroadcastReceiverRegistry
- abi-noise：warningLevel（**app 侧**符号，当前 sourceGlobs 只搜 modules/* 与 apps/inrt/src ⇒ 该组恒为「源码里不存在」→ 不参与判定，仅作文档）
规则（脚本内）：
- **只要求「确实出现在源码里」的标记**（单趟 Select-String 正则或，避免 15×上万文件的慢扫）；
- **防漂移 WARN**：某一组里既有「在源码里」又有「已不在源码里」的标记 → WARN(kind=markers-registry, 提示同步本文件)。

## 2. 更硬的证据：推导标记（模板 mtime 之后改过的源文件）
- 取「模板 mtime 之后改动过的 modules/*/src/main/** 与 apps/inrt/src/main/** 文件」：优先 **git（只读查询：git log --name-only --since=… -- modules apps/inrt）**；git 不可用/无结果时退回 **mtime 扫描**。
- 从最新文件里正则抽**公共/受保护成员名**（public|protected ... name(），过滤：长度 >=6、排除 get/set/is/on/to 前缀与通用名（toString/equals/create/build/run/init/…），最多取注册表 derived.maxMarkers（默认 5）个。
- 这些名字 + 注册表标记**一起到模板的 classes*.dex 里找**；**缺任何一个 ⇒ 每条一个 STALE(kind=template, marker-missing:<name> (since …) → 先跑 build-slim-template.ps1)**，退出码 1。（应急开关：-NoDerived 跳过推导；-MaxDerivedMarkers N 覆盖个数。）
- 反过来，**内容级全通过时把 mtime 的假 STALE 翻成 FRESH**（checkout 打乱 mtime 的场景）。

## 3. 测试（tools/tests/artifact-freshness.test.mjs → **5/5 PASS**）
新增用例「新符号未进模板 ⇒ STALE(marker-missing:forCurrentEngine) 且 exit 1」：
- 伪造一份**真 zip** 模板（ZipFile::CreateFromDirectory 造出带 classes.dex 的 template.apk，dex 内容就是可被搜索的文本）；
- 源文件声明 public fun forCurrentEngine(...)（mtime 比模板新）⇒ dex 里没有它 ⇒ **STALE + exit 1** ✓；
- **反向对照**：把该标记写进 dex 再跑 ⇒ FRESH 且无 marker-missing ✓（证明 STALE 来自「标记缺失」而不是别的）。
既有 4 条（FRESH / STALE(template) / STALE(aot) / -Json）保持通过。

## 4. 本仓库实测（2026-11-10，同一份脚本、三次运行）
1. 加固前（旧写死标记集）：-Deep → **FRESH(kind=template)**（就是那次**假 FRESH**）。
2. 加固后第一次运行（模板还是 dev-1458 那份）：derived markers from git(--since=…) files=2 required=[forEngine,forCurrentEngine,liveBridgeCount,activeBridgeCount,registeredIds] → template dex: missing=[liveBridgeCount,registeredIds] ⇒ **STALE(kind=template, marker-missing:liveBridgeCount / registeredIds)**、exit 1 ✓ —— **正是要抓的那类「引擎加了新符号、模板没跟上」**（这两个是模板重建后 W1 又加的诊断方法）。
3. 你随后重建模板（dev-1459）后再跑：注册表 14 个标记（sjbc-core 5 + sjbc-entry 5 + host-routing + cross-process-prefs + script-broadcast 2）missing=[]、derived files=0（模板已比所有引擎源新）⇒ **FRESH(kind=template)**、exit 0 ✓。
命令：powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-artifact-freshness.ps1 -Deep（本机 pwsh 7 不存在，全走 Windows PowerShell 5.1）。

## 5. 与 -DeepStrict 的关系
task-91 起，**注册表标记与推导标记的缺失本身就是 STALE（默认就挡）**，不再需要 -DeepStrict；该开关**保留但已无实际作用**（注释里写明「历史开关」）。AOT 侧的明文搜索仍**永远只 WARN**（快照编码，实测证伪），不受 -DeepStrict 影响。

## 6. 未验证边界
1. **未跑构建/装机/发布**；脚本里只有一处 git 调用，是**只读查询**（git log --name-only --since=…），不写仓库、不做任何提交。
2. 运行时间：本仓库全量 -Deep 约 **77 秒**（源集合多趟文件枚举 + 一次 19.8MB dex 的 Latin-1 搜索）；出包前可接受，想快可 -SkipAot / -NoDerived。
3. 推导标记是**启发式**：极端情况会误报（例如新加的方法名只出现在接口/注释里、或被 R8 内联进别的类）；缓解 = 只取 public/protected 成员 + 停用词过滤 + -NoDerived/-MaxDerivedMarkers 应急；**注册表标记是人工判定，误报风险低**。
4. PS 5.1 两个坑（本次都踩到并已修）：① 读无 BOM 的 UTF-8 JSON 必须显式 -Encoding UTF8（否则中文/结构都读坏）；② PS1 文件本身必须 **UTF-8 with BOM**（否则按 ANSI 解析中文直接语法错）。
5. 注册表里 abi-noise（warningLevel）是 app 侧符号，当前 sourceGlobs 搜不到 ⇒ 恒不参与判定（有意，避免把 app 类当模板类）。
6. AOT 侧判据未变（只有 mtime 能当门禁；要吃真内容判据需在 AOT 里放可 grep 的版本戳）。
