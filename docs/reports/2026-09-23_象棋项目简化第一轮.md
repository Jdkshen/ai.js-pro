# 象棋项目简化第一轮（2026-09-23）

## 为什么先做这一轮

项目已能识别、算棋和执行，但入口有主页面与悬浮窗两套 UI，视觉有 `legacy`、`auto`、`diff` 三种路径；`auto-driver.js` 与悬浮窗脚本都很长。直接大规模重写会触及落子安全闸门和大量真机特例。本轮先清除已证实不用的代码与重复状态，并使版本与日常入口清晰。

## 已收口

- 23 个没有生产引用的 `tools/p4-*.js` 从 APK 内置工程移到 `docs/archive/xiangqi-p4-probes/`，内容和 Git 历史保留；归档后不保证原位可直接运行。
- 删除零运行期引用的 `src/vision/onnx-ocr-adapter.js`、`src/vision/piece-fusion.js`；正式 OCR 入口仍是 `ocr-runtime.js`，新视觉融合仍是 `evidence-fusion.js`。
- 悬浮窗只保留 `visionPipelineMode` 一份模式状态，并删掉永远不可能进入的原生整窗拖动分支；标题区限频拖动保持原有行为。
- 新增 `src/app/version.js`，主页面与悬浮窗共用工程版本 `0.6.1`；`project.json` 的名称说明与版本同步。宿主 APK 的 `dev-xxx` 版本另行记录。
- 把过时长 README 归档，工程与工具目录改用简明入口说明；更新模型文件名。

## 验证与边界

`node tools/run-regress.js`：场景 11/11、自检 296/296、格子契约 19/19；`node --check` 通过；Android 四项内置资源校验通过。没有改变默认视觉模式、点击通道、棋规、Pikafish 搜索或落子确认规则。真机完整自动对局与 UI 拖动仍需现场验收。

下一步如果继续瘦身，应先从同一回放截图比较主页面、悬浮窗及探针的盘面结果；确认一致后再统一视觉入口。`auto-driver.js` 的拆分应围绕事实账本、观察、搜索、执行与确认的明确边界进行，避免为了文件变短而增加状态副本。
