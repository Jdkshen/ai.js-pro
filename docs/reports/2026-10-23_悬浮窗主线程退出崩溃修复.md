# 悬浮窗主线程退出崩溃修复（dev-1211 修复，dev-1213 发布）

用户提供 `悬浮窗-ab2e79fab35444808d1cf5ec86266d08.zip`，其中 `AI.jsPro崩溃复盘.md` 记录了 Redmi Android 16 / dev-1210 上七次停止脚本时的主线程崩溃。本轮对照实际宿主源码修复了回调异常边界，并构建 dev-1211 安装包。安装验证在空闲 MI8（ce4d2bdb，Android 15 / SDK 35）进行。K40 的象棋任务未停止、未安装宿主更新。

## 根因与修复

`Timer.callFunction()` 原来已有 `catch (Exception)`，但捕获后调用 `runtime.exit(error)`。后者停止引擎后仍会抛出 `ScriptInterruptedException`，这个第二次抛出没有边界捕获，最终逃出 Android 的 Handler / Looper。这比原文所写的“Timer 无 catch”更准确。

新增 `MainThreadCallback`：在脚本调用栈已经展开的 Java 回调出口处，调用宿主的正常停止流程，并仅容纳其停止异常。原始脚本错误仍上报；其他清理错误和直接抛出的致命 Error 不静默吞掉。保持 `ScriptRuntime.exit()` 的立即中止语义。

脚本主动 `performClick()`、`emit()` 或 `window.close()` 时可能同步重新进入 Java。若 Rhino 的外层脚本还在执行，异常继续向外展开，避免捕获后错误地执行 `exit()` 后面的代码。单元测试和真机程序触发点击均覆盖此场景。

接入点包括：

- Timer 的 timeout、interval、immediate 和直接 post；移除已停止回调并在 finally 清理记录。
- Rhino 的 Java 接口代理、Activity 生命周期和菜单事件。
- View 的点击、触摸、按键、滚动和列表事件，以及对话框回调。
- 浮窗异步操作与原生关闭按钮。同步 close 保持向外中止脚本。
- 列表创建、绑定失败后的终止与占位 View；占位对象不再触发同一个失败的 item_bind，绑定上下文和 inflate 标志始终恢复。

文档另提到旧版 `ResourceID #0xffffffff`。实际 Node 宿主资源查找已在旧修复中返回 0，但 Node24 的 `ui.R` 代理遇到桥接错误时仍返回 -1。本轮把错误、缺少 ID 和旧 -1 统一为 Android 的“无资源”值 0，并增加真实 ui.js 的 VM 契约测试。有效资源 ID 保留。

## 对原复盘的核实

`run_script(wait=true, timeoutSeconds=...)` 超时只返回 `timedOut=true`，不会自动停止仍在运行的脚本，见 `McpTools.waitFor()`。本轮实际验证的是等待超时后显式调用 `stop_script`；没有修改这项 API 行为。因此，原文把超时本身说成强停原因的结论应视为未证实。

压缩包内 Aurora 的 `quit()` 已经包裹 `exit()`，属于旧宿主的脚本兜底。本轮保留原脚本和图片资源。修复重点在宿主，使未包裹的回调 exit 也能安全停止。单独换 Aurora 文件不能补齐旧 APK 的这些缺口。
