## 2. 通知 action / 点击事件

### 2.1 协议（Node ↔ :node24 宿主）

请求 kind=notification：

    {kind:'notification', action:'notify', id:15601, title, text, ticker, ongoing, autoCancel, actions:[{title:'动作A'},...]}
    {kind:'notification', action:'cancel', id}
    {kind:'notification', action:'cancelAll'}

宿主实现（Node24HostBridge）：NotificationChannel node24；每个 action 与内容点击各自建 `PendingIntent.getBroadcast`（action=按钮序号，内容点击=-1），指向 ACTION_NODE_NOTIFICATION_EVENT；动态注册的 receiver 收到后 `enqueueEvent(__ajs_notification_event, {id, action, title})`，prelude 的轮询把它派发给 JS 监听。

### 2.2 JS API

    const notification = require('notification');
    notification.notify(15601, { contentTitle:'...', contentText:'...', actions:['动作A','动作B'] });
    notification.on('click', e => { /* e.id, e.action(>=0 表示按钮), e.title, e.isAction */ });
    notification.on('action', e => { ... });
    notification.addAction(id, '追加按钮');
    notification.cancel(id); notification.cancelAll();

## 3. 无障碍事件订阅

### 3.1 通路

    AccessibilityService.onAccessibilityEvent
      -> AccessibilityEventForwarder 的 AccessibilityDelegate（仅 subscribed 时转发）
      -> sendBroadcast(ACTION_NODE_ACCESSIBILITY_EVENT, json)
      -> :node24 Node24HostBridge 的 receiver -> enqueueEvent(__ajs_accessibility_event)
      -> Node 轮询 -> prelude dispatch -> accessibility.on(type)

订阅由 :node24 发 ACTION_NODE_ACCESSIBILITY_SUBSCRIBE 广播控制；没有订阅时 delegate 直接返回，不产生广播开销。

### 3.2 JS API

    const accessibility = require('accessibility');
    accessibility.on('view_clicked', event => { event.packageName; event.className; event.windowId; event.getWindowId(); });
    accessibility.on('toast', event => { event.text; });
    accessibility.on('window_content_changed', event => { event.contentChangeTypes; });
    accessibility.off(type, handler);
    const event = await accessibility.nextEvent('window_state_changed', 5000);

## 5. floating_window 缺口（本轮未实现）

现状：`kind:ui op:floatingWindow` 只有 show(text,x,y,width,height)/close/closeAll；`modules/node24/modules/floating_window.js` 的 setViewFromXml 只能提取文本、on('touch'|'drag'|'click') 明确抛错，enableDrag/addFlags 为形状保留。

要真正实现需要：

1. 主进程按 Auto.js XML 布局 inflate 出真实 View（复用 com.stardust.autojs.core.ui.inflater 或 ui.js 的 inflater 管线），addView 到 WindowManager overlay；
2. overlay 的 onTouch 事件（含 ACTION_OUTSIDE/WATCH_OUTSIDE_TOUCH）与子 view id 的 click/longClick 事件通过 NodeUiBridgeFacade 事件通道回传 :node24，prelude 再投递给 window.on('touch')/view.on('click')；
3. view.binding 的 id 映射、enableDrag 手势识别、setPosition/setSize/addFlags 的实时更新（现在靠 close+show 重建，会闪烁）。

工作量与风险集中在 inflate 语义（自定义标签/text、bg、layout_weight 等）和事件回传通道，建议单开任务实现，本轮不交付半成品。

## 8. 已知限制

- notification 的平台 Notification.Builder 没有 setSilent，silent 选项暂忽略；
- accessibility 事件对象没有 Pro 的 event.source(UiObject)：跨进程只传序列化字段，需要节点对象时请用自动化选择器 API；`accessibility.windows`/`root()` 仍走现有自动化桥，不在本轮；
- `accessibility.enableService({toast:true})` 的 toast 参数语义仍是打开服务，事件订阅需要 AccessibilityService 已启用（否则订阅广播无人接收，脚本可先查 status）；
- floating_window 与 dialogs customView 见第 4/5 节。
