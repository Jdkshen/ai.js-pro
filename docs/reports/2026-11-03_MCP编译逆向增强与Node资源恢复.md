## chess-auto 真实失败

用户 Android 17 日志明确为 `project-res.apk` 与宿主资源表摘要不匹配。资源包按旧宿主编译，不能通过改 JSON 摘要绕过校验；仅凭这条日志不能归因为 Android 17 AssetManager 兼容错误。

- 校验保留，错误补充期望/实际资源表 SHA-256。
- 工程完整入口使用 `nodejs ui` 指令，保持原控制器和运行逻辑。
- 失败后显示可复制诊断和修复按钮，首次操作显式下载资源组件，按手机当前宿主重新 link。
- 恢复页通过 `ui.setMainActivity(Activity, {hostResourcesOnly:true})` 只使用宿主控件；此选项仅允许 `layoutXml`，不加载工程表、不绕过编译布局校验。
- 重编前后核对源码摘要，成对提交 APK/sidecar，失败恢复旧文件；随后同步当前 staging 并通过 `ui.startActivity` 切回正式界面。
- AAPT2 可能自动添加 `.feature` 后缀；sidecar 取编译结果的实际资源表包名，而非推测清单里的名称。
- staging 留源目录映射，配置及重编资源可回到原工程目录；下载的原始 ZIP 不覆盖。

## 可选组件

主 APK 不内嵌 JADX/AAPT2 payload；用户明确安装后下载。

| 组件 | 本轮 payload 大小 | 后端 |
|---|---:|---|
| apk-resources | 30,058,485 字节 | Termux aapt2 16.0.0.4-4 与传递依赖、Android 35 android.jar |
| jadx | 2,921,068 字节 | JADX 1.5.6 + dex-input，预编译 DEX，独立 app_process |

默认清单在 LAN `/components/<id>-arm64-v1.json`，可传 `manifestUrl`。下载前校验清单约束，下载后核对大小/SHA-256、限制解压路径/数量/总量，再激活。源依赖版本和摘要记录在各 payload 的 `upstream-lock.json`。JADX 要求 Android 8+；反编译供阅读，不保证可原样重编译。未恢复已取消的完整 Gradle/Java 源码工具链项目。

JADX 使用应用私有缓存作为 JVM 临时目录，避免 Android 上不存在的 `/tmp`。Java 阅读从快照提取 DEX，不处理无关的 APK 资源 XML；显式 `dexEntry` 时只读取指定 DEX，防止同名类误选。资源内容继续走专用资源工具，未关闭 XML 安全校验来规避 Android 解析器差异。

## 明确边界

调用图是有预算的静态分析，反射/动态调用/运行时分派会标出潜在或未知，不能当作完整证明。分包先读取成员，不合并安装，也未验证整组签名/Manifest 一致性。ZIP 16KB 对齐不等于 ELF LOAD 段已重编译。验签通过不等于设备能安装或业务功能可运行。后台任务重启后未完成项标为 INTERRUPTED，不自动重放写操作。

本轮没有验收独立打包 APK、长时间象棋对弈、所有第三方 Widget 或 Android 17 原机；不能把设置页/组件测试当成这些项目通过。Java 阅读最多 32 个 DEX、单项 64MiB、合计 128MiB，超出明确拒绝。Node/npm/Gradle 工程的完整源码编译不属于这次资源编译接口。

每个工具进程最多缓存 8 个操作目录；工作区最多 16 个、快照合计 1GiB。测试后只按本轮专用源路径清理临时工作区，保留其他历史临时数据与用户文件。组件能力查询不会执行编译器，`verified=false` 表示该次只读查询没有运行验证，不能替代本报告的实测证据。
