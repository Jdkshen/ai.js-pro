# Node 原生与独立 APK 兼容

## 原因与修复

- K40（主宿主 dev-1273）用自身打包能力构造了独立 Node 测试项目：首次启动红字 `Unsupported JavaScript engine: nodejs`。`JavaScriptSource` 之前识别脚本首行 `"nodejs"`，却不接受工程配置中的 `nodejs`；现在统一识别 `nodejs` 引擎别名及 `// @engine nodejs`，`type: node` 工程无显式引擎时也选 Node，显式引擎及单脚本覆盖优先级不变。
- 独立运行时继承引擎注册，却未声明 Node 池服务；补齐四个非导出服务与主/脚本桥，并限制仅主进程恢复定时任务与注册任务广播。异步引擎继续走工作线程，不阻塞脚本主 Looper。
- 1281 宿主内置精简模板缺少 `libnode.so`。Node 入口、Node 工程或显式启用 Node 的工程打包时从宿主 APK 复制完整且同版本的 Node 脚本与运行库到工作区；项目类型、脚本级和工程级引擎配置都会参与判断。其他不需要 Node 的工程不额外带这份库。缺少运行资产时报错而不是产出不完整 APK。Node 编译加密尚不支持，选择该模式时明确拒绝，不再误生成 Rhino 字节码。
- Node 原生 UI 的批量 `view.attr({...})` 现在调用自定义 Widget 属性 setter，并只在旧宿主缺方法时回退；补 `view.on('check', handler)` 并保持 Rhino 参数顺序。
- 独立包 Node UI 之前报 `NodeUiLocalActivity$Slot1` 找不到：将原 Activity 移入共享引擎，独立包补三个 Node 进程 Activity，保留宿主停止广播和主题。
- 将现有无障碍自动化客户端、宿主服务、遍历实现和 AIDL 下沉共享引擎，原有类名和主应用服务声明保留；独立包新增同 UID 私有主进程服务。独立 APK 必须启用它自己的无障碍服务。

## 已验证

- K40 上用旧宿主的真实 ApkBuilder 与测试模板打包、安装、启动自有测试包：基础 Node 24.22.0 输出 `NODE_PACK_K40_STARTED` 和 `NODE_PACK_K40_DONE`，正常完成。
- 相同 K40 路径复现 UI 原错误 `ActivityNotFoundException`；更换已修复模板后重打、安装、启动，日志输出 `NODE_PACK_UI_STARTED`，系统界面树确实显示 `Node UI probe`。测试仅拒绝了自有测试包请求的电话及存储权限，并返回原游戏；没有停止其他脚本。
- 进一步打包原生控件测试：K40 上复选框从未选到选中和人工点击取消均收到 `check` 回调，Node 创建 Java `StringBuilder` 并调用方法输出 `native-bridge`。自定义 Widget 批量属性在本地契约覆盖，尚未真机验证。
- 宿主 `dev-1282-node-pack-test` 使用内置精简模板打包，将产物安装到 K40，确认控件可见、复选框 true/false 回调及 Java 调用通过。产物 84,190,126 字节，3 个 Node 运行库的 SHA-256 均与 runtime.json 一致，20 个 ELF 的 16 KB 检查通过。
- 在小米 8 的 `dev-1283` 宿主打包独立自动化测试应用，临时开启该测试应用自己的无障碍服务，Node 查询到按钮、点击返回 true，脚本收到点击回调，实际界面文字变为 `AUTO_CLICKED`；主应用 Node 节点查询也通过。测试应用和临时授权已清理，原无障碍配置已恢复。
- 最终 `dev-1284` 再用没有引擎声明、只配置 `type: node` 的同一工程打包，产物包含正确的 Node 库并在小米 8 再次验证界面、节点查找和实际点击；恢复原无障碍设置。混合引擎工程的 Node 运行库策略由 JVM 测试覆盖，完整实机场景待测。

## 仍待确认

完整高级版原生 UI/Java API 尚未逐项对齐；例如 touch、key、scroll_change 等事件和 long_click 的消费语义仍需检查。独立包的手势、截图、带混合引擎的 Rhino 主入口工程和更多真实项目仍需实机验证。Node 的编译加密暂不可用；旧版手动覆盖模板和独立插件旧模板需要更新，不能把本轮内置模板的结果推广到它们。
