## 对照结论

| 范围 | AJ Pro 高级版 | 当前 AI.js Pro | 判断 |
|---|---|---|---|
| 抓取和显示 | 无障碍根/窗口 → 队列生成 NodeInfo 快照 → 原生范围图/层次树 | 同类快照架构；增加去重、消失节点容错、根选择/重试和抓取诊断 | 没有证据表明此功能靠 J2V8、Glide 或某种特殊 UI 框架加速 |
| 进程 | 合并清单把 FloatyService 和 SelectToSpeakService 配在 `:script` | 两个服务均未指定 process，application 也未指定，使用主进程 | 这是实质隔离差距；AJ 仍与其脚本进程共享，不是每个分析窗口独立沙箱 |
| 快速退出 | 分析基类 fw1 注册无障碍按键监听，键码 25（音量下）关闭；close 时移除监听 | 分析窗处理返回键、菜单退出和窗口关闭；未注册对应音量下退出监听 | 音量上停止脚本与关闭内置分析工具是不同链路，不能混为已经对齐 |
| 属性面板 | 明确字段表 28 项 | 31 项，额外显示 checkable、enabled、focused | 当前属性并非比 AJ 少；两边这份表都不包含 hint/stateDescription/uniqueId 等现代字段 |
| 搜索与切换 | 所检查分析窗菜单包含属性、生成代码、视图切换、窗口选择、保存、退出 | 额外有节点搜索、大小写切换、上一/下一项、读取文件；切换视图保留搜索/选中状态 | 这些功能已实现，不应再次列为待补齐；不据此断言 AJ 整个 APK 都无搜索入口 |
| 多窗口 | 抓取时建立 Capture.windows 的窗口快照，菜单切换该批快照 | 抓取也保留窗口快照；窗口选择另外可隐藏分析层并重新获取可见窗口，显示类型、层级等 | 双方都可能在初次抓取时遍历多个窗口，不能简单归因“只有我们全量抓窗口才慢” |
| 点选 | 命中子节点中取最小面积，递归时按父框命中裁剪分支 | 队列遍历全树取最小面积，long 面积防溢出；也可命中根和父框之外的子节点 | 当前避免递归栈问题，但每次触摸扫描全树；两边最小面积策略都不能完整表达遮挡层级 |
| 代码生成 | 属性选择与高级生成器；含父子定位、集合项处理、查找/动作组合 | 属性勾选一键复制与“更多”；高级生成器已有父子回退、集合项、findOne/untilFind/waitFor/exists 和动作 | 不是缺少高级生成器；当前生成操作仍同步在界面线程，需处理大树耗时 |
| 保存格式 | Gson 序列化嵌套 NodeInfo，文件为 `LayoutFiles/<包名>-<时间>.layout.json` | `aijs-layout/version=1` 扁平节点记录；有文件列表、读取、分享、大小/深度校验 | 当前不能直接读取 AJ 原始布局 JSON；如要互通需专门导入适配 |
| 主题 | 基类使用 ContextThemeWrapper 和 MaterialAlertDialogBuilder 构建弹窗 | 多处直接写死白底、深灰字、绿色按钮，未统一使用宿主动态调色板 | 当前深色/主题色不一致有直接源码证据；未实测 AJ 的全部主题效果 |

## 当前更值得修改的地方

### P0：让抓取和窗口刷新有明确结束路径

`LayoutInspector.kt:38,50,77` 使用单线程执行器；抓取虽离开 UI 线程，但没有总时限、节点/深度预算、取消令牌和请求代次。`NodeInfo.kt:190` 的实时抓取只有 visited 去重，没有节点/时间上限。`LayoutSnapshot` 的 30000 节点、256 层、16 MiB 限制只约束文件路径，不能当成实时抓取已经有限额。

`InspectorFloatyWindow.java:199` 先把分析层设为 GONE，180ms 后刷新窗口，只在完成回调恢复；没有超时恢复。`CircularMenu.java:288` 的转圈同样依赖完成回调。慢或阻塞的提供方可能造成长时间等待或分析层一直不恢复。这是代码风险，尚未在本轮真机复现。

修改方向：统一抓取请求 ID、预算与取消状态；超时必须让界面恢复并解释原因，丢弃晚到/已取消结果；限制排队和并发，不能每超时一次就无限创建线程。Android Binder 调用不一定响应 interrupt，不能把“取消 UI 等待”写成“远程系统调用已被立即终止”。

### P0：补分析工具自己的退出链路

对齐音量下退出分析，保留音量上全局停止脚本，按键去重，注册/注销与窗口生命周期绑定；退出时关闭搜索、对话框并拒收旧回调。先核对无障碍权限和系统按键分发，不用音量键逻辑吞掉正常脚本事件。

### P1：减少大树上的主线程工作

- `LayoutBoundsView.java:149,169` 每个触摸事件都扫描全树并 invalidate；`draw:131` 每次重绘遍历全树，绘制单框还会创建临时 Rect。可以缓存平铺节点/绘制数据、减少同一选中项的重复重绘，再按需要建立空间索引。
- 不宜照抄 AJ 的“父框不命中就不搜子节点”作为唯一优化，否则可能漏掉超出父边界的合法节点。增加同区域候选循环、父/子跳转，并明确 visibleToUser/drawingOrder 的取舍。
- `InspectorFloatyWindow.java:333` 搜索及结果文案生成同步遍历；`CodeGenerateDialog.java:117` 同步生成定位代码。适合后台计算、主线程提交结果，附请求代次和有界结果列表。
- `NodeInfoView.kt:30` 一次读取全属性，`NodeProperties.read` 会触发 idHex 的资源查询。可把昂贵属性查询延后或移到后台，而不只是让 RecyclerView 复用行。
- 验收应记录不同树规模的抓取时间、点选/搜索延迟和主线程帧耗时；本轮没有双方同场景测速，不能给出 AJ 快几倍的结论。

### P1：分阶段隔离分析 UI

建议研究专门 `:inspector` 渲染进程，通过有界快照/文件描述符传递数据。采集继续在无障碍服务一侧执行，主题、会话、退出、MCP/覆盖层状态都要有进程间协议。

不能只在现有 FloatyService 上加 process：当前 `AutoJs.getInstance()`、静态窗口管理、监听器和任务注册均存在进程本地状态，直接搬服务会断链；也会影响脚本浮窗。先设计 IPC 和失联清理，再做崩溃隔离验收。

### P2：主题、属性和布局互通

统一菜单、搜索面板、属性弹窗和高级生成器的深浅色/动态主题；保留节点选框的可辨识颜色。补现代无障碍字段时同步快照版本、属性说明和选择器实际支持范围，不能把所有只读信息都生成为 selector 调用。

如用户需要导入 AJ 的 `.layout.json`，新增单向导入并转换到现有离线快照；继续执行大小、节点、深度和类型校验，不反序列化活动 AccessibilityNodeInfo，也不直接替换当前文件格式。
