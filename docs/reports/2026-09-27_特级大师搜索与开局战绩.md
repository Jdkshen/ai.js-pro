象棋项目版本：0.6.37。对手档案按用户确认设为「天天象棋·特级大师」。运行时全部在手机内完成，不连接电脑算棋。

这些改动尚未经过多局实战的胜率对照，不能据此承诺每局获胜。

## 怎么用

1. 更新 App 后重新打开内置「象棋自动走棋」，核对主页面显示 **0.6.37**。已经导入到文件管理的项目是独立副本，不会仅因安装 APK 自动变成新版；保留自己的修改，重新导入新版到新目录。
2. 主页面的算棋设置展开「引擎与策略」，点击「策略与战绩 · 特级大师」；浮窗第二排也有「策略战绩」。关键步复核、手机预思考、开局战绩参考默认开启，可分别关闭，两个入口同步。
3. 使用限时搜索。目标深度模式保持原有含义，不额外做复核或预思考。原有思考时间、线程、Hash、开局步数不会被这次更新强制改写。
4. 从标准开局开始，让脚本建立完整棋谱。预思考在**我方这一步已被确认、正在等对方**时启动，不会把预测当作识别事实。
5. 游戏实际结束后，打开「登记 / 更正对局结果」，选择对应时间和红黑方，登记我方胜、和或负。未完成或误选可以改成「不计入」。相同对局更正结果会替换，不会新增一局。
6. 「查看战绩与统计规则」显示人工确认结果与完整棋谱结果。停止脚本不会自动判负，评分高不会自动判胜。这里只统计当前确认的对手档案；换其他难度时先关闭开局战绩参考，勿将其结果登记到本档案。

本地开局库仍需存在于 `/sdcard/xiangqi-p4/opening-book-vetted.json`。没有库时直接使用手机原生 Pikafish；战绩功能不会凭空生成开局库。

## 实现与修改入口

以下路径相对于 `apps/app/src/main/assets/sample/QuickJS 新引擎/项目与打包/象棋自动走棋/`。

### 关键步复核

- `src/engine/critical-review.js`：纯策略函数 `plan(board, side, chosen, raw, options)`。
- `src/engine/pikafish-engine.js`：同一局面、同一已确认棋谱进行第二次原生搜索，保留排除表与候选规则。
- `src/automation/driver/search.js`：传入上一次红方视角评分，显示复核原因及是否采用结果。

触发条件：我方视角评分比上次下降至少 120cp；最近三个不同深度（至少深度 8）的 MultiPV 第一候选连续变化；目标格是车、马或炮；引擎给出杀棋距离。代码会把驱动的红方视角与 UCI 的走棋方视角统一后比较。

追加预算 `min(基础预算, 3000ms, max(0, 15000ms - 基础预算))`，不足 100ms 不复核。这里限制的是普通首轮加复核的预算；已有「排除表全部挡住后拓宽候选再搜」仍可能另花一轮时间，JNI 的超时收尾也不算正常搜索预算。

复核只做一次，失败、着法非法、违反排除表或完成深度小于首轮时保留首轮。不会因为复核而绕过原有棋规检查、点击票据或杀棋的第二帧佐证。

### 手机预思考

- `src/automation/prethink.js`：预测局面、身份键和后台结果生命周期。
- `src/automation/search-worker.js`：独立 QuickJS 线程；`cooperative:true` 时取消只标记作废，待有界原生调用返回后回收句柄。
- `src/automation/driver/search.js`：等待对方时启动，轮到我方时先让后台任务退出，再启动正式搜索。

```js
const predictedCommand = verifiedCommand + " moves <预测应手>"; // 已含 moves 时只追加着法
// 实际实现先验证预测应手合法，并计算其后的我方局面。
worker.start(predictedFen, {
    positionCommand: predictedCommand,
    movetime: 2500, // 实际取 500..2500ms，受当前基础时间约束
    timeoutMs: 3500,
    openingBook: false,
    criticalReview: false,
    multiPv: 1
});
```

身份键包括盘面、轮走方、完整的当前棋谱命令、会话号和引擎配置。只有完全匹配才记「预思考命中」。猜错、暂停、换边、换局或改引擎配置会作废结果。

当前实现是**有界提前搜索、预热原生 Hash，然后按实际棋谱继续正式搜索**。它没有发送 UCI `go ponder / ponderhit`，也不直接用预测着法点击。后台尚未返回时，正式搜索会等待它退出，界面仍可处理停止操作；超时不强行并发搜索。它可能提高同一正式预算内的搜索深度，也可能因对方秒走而增加等待，实际收益需要真机对局统计。

### 开局记录与筛选

- `src/services/opening-results.js`：档案、棋谱快照、人工结果和统计。
- `src/engine/opening-book.js`：先按原有规则生成评分差不超过 30cp 的候选池，再参考该盘面的同对手、同红黑方战绩。
- `src/ui/strategy-menu.js`：主页面与浮窗共用交互。
- `src/app/session-settings.js`：`criticalReview / prethink / openingLearning` 三项开关。

记录位于 App 的 `storages.create("xiangqi-opening-results-v1")`：`ids` 索引、`game:<id>` 棋谱、`result:<id>` 人工结果分开保存。棋谱后续更新不会擦掉已确认结果。没有 30 局截断；清除应用数据或卸载可能删除这些记录。

只接受从标准开局连续确认的棋谱；识别修订导致历史部分缺失后，这局不参与开局筛选。统计只回放前 24 个半回合，同一盘面每局最多贡献一次。所有安全候选各有至少 5 局，且 `(得分 + 2) / (局数 + 4)` 的差达到 0.1 时才优先选经验较好的候选；胜得 1 分、和得 0.5 分、负得 0 分。样本不足保持原随机逻辑，关闭随机仍保持固定主着法。该阈值是启用门槛，不是统计显著性的证明。

生产入口显式传 `recordGames:true`；离线回放默认关闭持久记录，避免测试棋局污染真实战绩。

## 顺带修复

- 后台线程参数没有完整传递开局步数、已走手数与随机开关，现在与同步路径一致。
- 重复确认或账本拒收的着法不再增加开局已走手数。
- worker 正常结束后不再额外 interrupt；无旧线程的首次启动不再无条件等 400ms，真正重启仍保留退场间隔。
- 过期算棋结果在写评分、预判与日志之前丢弃。
- 预思考不改变等待阶段的截图频率，避免把观察循环误加速到每 120ms 截图。
