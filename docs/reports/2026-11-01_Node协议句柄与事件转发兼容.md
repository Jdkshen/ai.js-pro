## 问题与实现

| 问题 | 根因和本轮修改 |
| --- | --- |
| 协议 click 的 once/off/prepend 与原生 View 不同 | 删除独立 clickHandlers 与其他 handler 数组，协议、marker、原生监听统一使用 EventEmitter；安装成功后才登记处理器，失败不留幽灵监听 |
| 移除监听后仍读取状态，或重新登记叠加 TextWatcher | 清除实际 polling 状态与持有集合；一次性监听消费后停止读取；保留已安装的宿主监听标记，重注册不重复安装 |
| 同一句柄再次查找返回不同对象 | 缓存公开 Proxy 本身，链式返回同一个门面；marker 在可用时解析真实协议句柄，共享监听与移除状态 |
| 轮询转发到真实 View 时一个异常阻断其他监听 | 统一到逐监听隔离派发；手动 emit 继续保留标准 EventEmitter 异常传播 |
| 纯内联 XML 报“工程声明资源但没有 project-res.apk” | 等确定是资源布局后才告警；内联布局无需为创建普通控件编译工程资源，明确资源加载失败的告警仍保留 |
| 手机实际报“无效的 View handle：view-1” | 旧界面的 findViewById 在 :nodeui 生成句柄，uiRequestView 却在 Node 槽本地查找；现在转发到界面会话并归一化为 viewCommand，嵌套 params 保留且不改变原输入 |
| 旧 Activity 每次查同一 View 都发新句柄，且缺三类监听入口 | Activity 复用有身份反查和上限的 ViewHandleRegistry；点击、开关、文本和选中事件共用引擎的监听安装代码，通过显式 sink 回到 Activity 自己的事件队列 |

主要实现：`modules/engine/src/main/assets/node24/ui.js`、`NodeUiHost.java`、`apps/app/src/main/java/com/jdkshen/aijspro/engine/NodeUiActivity.java`。内部 Java 桥接方法用于两个渲染路径复用，不把内部类/方法数量计作新增公共脚本 API。
