## 1. 为什么只做别名

范围提案 §5 的判断：**破坏性改名换不来收益、风险却很大**（.4 的脚本、我们自己的文档/示例/smoke 全都在用旧名）。所以只做**新增派发别名 + 长期共存**：新代码可以立即用族前缀，旧名永远有效。

## 2. 做了什么（W4 task-33）

- `McpToolCatalog.familyAliases`：**16 条**——`dex_read_class_outline/dex_xref/dex_search_members/dex_call_graph/dex_hierarchy/dex_interface_table/dex_list_classes/dex_list_methods` → 对应 `apk_dex_*`；`so_inspect/so_list_items/so_map_address/so_xref/so_disassemble/so_analyze_control_flow/so_patch_instructions/so_patch_string` → 对应 `apk_native_*`。
- **只派发、不广播**：只进 `canonicalByAlias`（`tools/call` 用），**不进 `names`/tools/list** → advertised 仍 **224**、canonical 仍 **215**，不占客户端上下文；`chain_resume`/`entry_`/`crypto_` 三个新工具本来就是目标前缀。
- 类初始化新增 **6 条校验**：目标必须是 canonical、不得与 canonical 同名、**不得进 names**、不得覆盖既有别名（camelCase 派发名 / Pro 别名 / `mt_*`）、解析自洽、无重复。
- 未知工具**近邻提示池**改为 `names + familyAliases.keys` → `dex_bogus` 的提示里会出现 `dex_*`；`tool_schema` 支持按别名查询并回显 `familyAliases[]`；`initialize.instructions` 加一句说明「新旧名等价、别名不出现在 tools/list、参数用 `tool_schema` 查」。
