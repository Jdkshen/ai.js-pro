用户拍板：不要打包插件，就在软件里面打包。本轮把**默认路径与错误引导**里的插件依赖全部摘掉（插件模块本身**未删**，仅作为最后手段保留）。

## 一、改动清单
1. ApkBuilderPluginHelper.missingTemplateMessage(Context)（原无参）→ **自足指引**：
   - 说明「内置 assets/template.apk 不可用」；
   - 附**应用内模板自检**结果（TemplateSelfCheck.checkBundled 的 problems + 三条修法）；
   - 明确一句：打包**不需要**安装任何插件；插件模板只是内置模板损坏时的**最后手段**。
   - 调用点 :136 改为传 context。
2. 插件档语义写清（:114-116 注释）：**默认不找插件**；只有 1) /sdcard 覆盖 2) 宿主缓存 3) merged 内置 三档都不成立时才会走到；插件模板仅最后手段。
3. templateStatus 三处文案去插件味（**只改文案、不改判定**）：
   - 宿主缓存：已从打包插件落地 → **宿主缓存（内置模板与宿主 lib 合成）**（有来源标记时写成「宿主缓存（模板来源：…）」）；
   - 插件档：插件已安装，首次打包时会把模板落地 → **最后手段：插件模板（仅当内置模板损坏时才会用到）**；
   - 末档（内置资产也读不到）：未安装打包插件 → **内置模板不可用：请重装主程序、或清掉 files/apk-builder/ 后重试、或把 template.apk 放到 /sdcard/template.apk**。
4. 新增 apps/app/src/main/java/com/jdkshen/aijspro/build/TemplateSelfCheck.kt（纯 JVM、只读、可单测）：
   - 判据与 gradle 任务 verifySlimPackagingTemplate **等价**：体积 6–20MiB、必需条目 AndroidManifest.xml/classes.dex/resources.arsc、瘦身模板**不得含 lib/**；
   - fixes() = 三条**自足**修法（重装 / 清 files/apk-builder/ / /sdcard/template.apk 覆盖），**永不含「装插件」**；
   - 入口：check(File) / check(byte[]) / check(stream,label,size) / checkBundled(openAsset) / Result.describe() / Result.userMessage()；
   - 触发方式按你定的 (a)：**只在打包落到最后兜底档时**把自检结果打进错误信息（零额外开销），并作为**只读入口**供 UI/MCP 调用；**不动启动路径**。
5. 新增 apps/app/src/test/java/com/jdkshen/aijspro/build/TemplateSelfCheckTest.kt（7 项，纯 JVM）：健康模板通过 / 缺必需条目报错且三条修法齐 / 含 lib/ 被拒 / 体积上下界（偏小、偏大、未知不判）/ 非 zip 不崩且给修法 / **文案与修法里不得出现「插件」** / checkBundled 缺资产与正常两态。
6. **默认值不改**：openTemplateSelection(context) 仍 forceBundled=false（语义：先 /sdcard → 宿主缓存 → merged 内置；true 仅用于内置模板修复/自检）；**未删插件模块**。
