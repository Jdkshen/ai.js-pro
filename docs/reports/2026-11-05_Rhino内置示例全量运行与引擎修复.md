# 内置 Rhino 示例全量运行与引擎修复（dev-1348 → 1351）

> 起因：用户反馈「跑一下 rhino 里面的示例 有报错了」。做法：把内置 160 个 Rhino 示例真机全量跑一遍，把**属于我们引擎的**问题修掉。

## 一、方法（可复现）

1. 示例在 APK assets：`apps/app/src/main/assets/sample/Rhino 引擎/**`（187 项：js + png/jpg + project.json + res/…）。
2. MCP 只能运行**磁盘上的 .js**，所以先把整棵树（含图片/资源）`adb push` 到 `/storage/emulated/0/脚本/__rhino_full` —— 只复制 .js 会漏掉 `block.png`／`res/` 这类依赖，导致「假失败」。
3. 逐个 `run_script {path:"__rhino_full/<rel>", engine:"rhino", wait:true, timeoutSeconds:5-6}`；`status=RUNNING` 的（UI/长循环）立刻 `stop_script`。

## 二、结果（160 个）

| 批次 | 成功 | 常驻运行（UI/循环） | 失败 |
|---|---|---|---|
| 0–79 | 30 | 43 | 7 |
| 80–159 | 27 | 52 | 1 |
| **合计** | **57** | **95** | **8** |

8 个失败全部是**环境/配置**或已给出清晰提示：

| 示例 | 失败原因 | 性质 |
|---|---|---|

| `事件与按键、触摸监听/通知监听.js` | `通知服务未运行，请重新启用通知权限` | 权限未授 |
| `事件与按键、触摸监听/按键监听.js`、`长按返回…`、`音量键控制程序.js` | `无障碍服务未连接：按键监听需要无障碍已启用并处于连接状态（serviceInfo 为空…）`（**原来是 NPE**） | 无障碍连接状态 |
| `任务/视频文件提取mp3文件.js` | `app 类型对话框需要本应用有界面（当前没有可用的 Activity）` —— MCP 无界面运行；从 App 界面跑不会有这个问题 | headless 限制 |
| `脚本引擎/停止所有正在运行的脚本.js` | 它把自己也停了（示例语义如此） | 设计如此 |

## 三、修掉的 6 个引擎缺陷

1. **R8 裁掉只被脚本反射调用的 OkHttp 成员**（影响面最大）
   现象：`HTTP网络请求/文件上传.js` → `TypeError: Cannot find function addFormDataPart in object okhttp3.MultipartBody$Builder`。
   实测：R8 包里该类只剩 13 个方法、没有 `addFormDataPart`。
   修复：`modules/engine/proguard-rules.pro` 与 `apps/app/proguard-rules.pro` 增 `-keep class okhttp3.** { public *; }` / `okio` 同理；重新构建后**在 DEX 里实测字符串 `addFormDataPart` 已存在**，示例从失败变为正常上传（RUNNING）。
2. **`__http__.js` 响应 body 为 null 时崩**
   `r.body.string = body.string.bind(body)` → `Cannot call method "bind" of undefined`（`获取网页.js`、`文件下载.js`）。
   修复：body 为 null 时给 `string()="" / bytes()=[] / json()=null` 并附 `emptyReason`；同时用跨版本 `createFileBody/createStringBody`（`file.asRequestBody` → `RequestBody.create(mediaType,file)` → `create(file,mediaType)`）替换写死的静态 create，不可支持的请求体给可读错误。
3. **`$zip` 相对路径没按脚本 cwd 解析**
   现象：`Zip文件压缩与解压.js` → `zipDir failed: 不是文件夹: ./zip_test/`（目录其实已创建成功）。
   根因：`Zips`/`ZipFile` 直接用 `new File(path)`，而进程 cwd 不是脚本目录。
   修复：`Zips` 增加 `resolve()`（复用 `Files.path()`，与 `files.path()` 完全一致）并传给 `ZipFile`；`zip/zipDir/zipFile/zipFiles/unzip/list/open` + `ZipFile.addFile/addFolder/addFiles` 全部解析。示例 **SUCCEEDED**。
4. **`console.setGlobalLogConfig` 缺 log4j 直接崩脚本**（上一轮已修，本批回归确认）——降级为内置日志 + 提示一次。
5. **`Events.observeKey()` 在 `serviceInfo == null` 时 NPE**
   现象：3 个按键示例报 `NullPointerException: …AccessibilityServiceInfo.flags on a null object reference`。
   修复：显式判空并抛 `ScriptException("无障碍服务未连接：按键监听需要无障碍已启用并处于连接状态…")`。
6. **画布绘制线程把 `ScriptInterruptedException` 抛成 FATAL、直接杀 `:script` 进程**
   现象：跑 `画布/贪吃蛇.js` 后停止脚本，logcat 出现成片 `FATAL EXCEPTION: pool-*-thread-*`，异常来自 `ScriptCanvasView.performDraw` → `ScriptRuntime.exit`。
   修复：`pool.run { try { execute { … } } catch (ScriptInterruptedException) { log } catch (Throwable) { log } }`，并把内层 `catch(Exception)` 放宽到 `Throwable`、先落 `mDrawing` 再 `exit`（exit 自身也包 `runCatching`）。
   验证：跑画布示例 → 停止 → **FATAL_COUNT=0**，随后新脚本仍能正常运行（进程没死）。

## 四、边界

1. `RUNNING` 只代表**启动正常且在运行**（UI/长循环示例），不等于界面与交互被人工验收过。
2. 网络类示例（上传/下载/获取网页）依赖设备联网与目标站点可用。
3. 需要 root、通知监听、已连接无障碍的示例在本次设备状态下无法跑通，但报错已从「看不懂的 NPE/TypeError」变成可执行的中文提示。
4. 本批未做：QuickJS/Node 引擎示例的全量同样跑法（下一步可复用同一镜像 + 运行脚本）。
