# 停止全部/任务页覆盖 Node24 uiScript（task-167）

日期：2026-10-19。执行：t1-native-services。验证机：K40（cccc62c7）。

## 1. 问题

t2 在 K40 dev-1115 复验：任务页「运行中任务=空无一物」（:node24 明明在跑）；点「停止全部脚本」只 toast「已停止全部脚本」+ `PocScriptHost: 没有登记在案的 :script 任务`，:node24 未退出、浮窗不消失。

根因：Node UI/overlay（uiScript）脚本真正执行在 :node24 的 Node24Service（单任务 keep-alive，hold 最长 600s）；:script 宿主的 RUN 会先结束/不登记，因此主进程任务页的数据源（ScriptEngineService + PocScriptHost + PocNativeRunner）看不到它；旧 stopAllScripts 只停 :script/:native/主进程旧引擎，没有触达 :node24。

## 2. 实现

### 2.1 :node24 任务状态/控制通道（Node24Service）

- 新增广播：`ACTION_NODE24_STATE = com.jdkshen.aijspro.NODE24_STATE`（started/finished/cancelled + id/filename/uiScript/startedAt/cancelled），在 job 被接受、job 结束（finally）时发送；
- 新增控制接收器：`ACTION_NODE24_CONTROL = com.jdkshen.aijspro.NODE24_CONTROL`（同 UID 非导出注册），支持 `cancel`（by id）、`cancelAll`、`query`（把当前 active job 以 started 广播重新上报，用于主进程重启/登记晚于任务启动）；
- 取消仍走既有 Job.cancel 链路（task-166 已保证关 overlay、结束 :node24 进程、watchdog 兜底）。

### 2.2 主进程任务登记表（PocNode24Jobs，新增）

- 注册 STATE 广播接收器维护 `RUNNING`（token=`node24:<id>`，name/filename、engine=Node24、detail=运行中/运行中 · Node UI、startedAt）；
- `PocRuntime` 静态初始化时 installIfNeeded + 主动 query 补登记；
- `snapshot()` 供任务页合并；:node24 进程不在时（取消/崩溃后广播可能来不及）按 ActivityManager 进程存活自动 prune；
- `cancel(token)`：先移除登记再发 CONTROL cancel；`cancelAll()`：清空登记 + 发 cancelAll。

### 2.3 PocRuntime 接线

- `tasks()`：在 ScriptEngineService / PocScriptHost / PocNativeRunner 之后追加 PocNode24Jobs 运行任务；
- `stopTasks()`：支持 `node24:` token（任务页行内 ✕ 直接取消 :node24 任务）；
- `stopAllScripts()`：在宿主进程/主进程引擎/NodeUiActivity.closeAll 之后增加 `PocNode24Jobs.cancelAll()`，确保 FAB「停止全部」与通知栏停止都能触达 :node24；
- 任务页停止后的轮询刷新逻辑复用（cancel 即先移除登记 → 列表立即变空，随后 :node24 退出/浮窗消失）。

## 5. 限制 / 注意

1. 广播为同 UID 非导出，依赖 :node24 与主进程同包；跨进程注册失败只影响任务页展示，不影响停止（控制广播退化为无效）；
2. :node24 进程被系统杀死时 started 广播可能残留，snapshot 用进程存活自动清理；
3. 同一脚本若 :script 与 :node24 都登记，任务页可能出现两行（一个宿主 RUN、一个 Node24 任务）；本任务优先保证「能看到/能停」，去重可按 path/name 后续优化；
4. query 补登记是异步广播，主进程刚启动时任务页第一次刷新可能晚几百毫秒（下次刷新即可见）。
