# 打包版启动路径与日志桥开关位置（2026-11-07 只读调查）

> 目标：确认独立 APK 的启动链路、activity_main 的可见性、产物内配置、现有调试开关，以及 AutoJs.globalConsole 能否作为 9317 日志桥的数据源。
> 结论基于源码阅读；本轮未改产品代码、未跑 Gradle/构建/安装。

## 0. 先给结论（TL;DR）

| 问题 | 结论 |
|---|---|
| 打包版入口 Activity/Application | 不是宿主生成，直接复用 inrt 模板的 .App 与 .SplashActivity；ApkBuilder 只重写清单身份和资源 |
| activity_main/ConsoleView/新 Switch | activity_main 只有 ConsoleView，当前没有新 Switch；它由打包版 LogActivity 使用，默认可见 |
| 打包版配置 | 产物 assets/project/project.json，由 ApkBuilder 从源工程复制并重写；模板自带的 project.json 在 prepare 时被删掉 |
| 现有调试开关 | 打包链路没有日志桥/调试桥开关；只有 hideLogs/showSplash/引擎/无障碍/图像/加密/签名等 |
| 开关建议 | (b) 写打包项目 project.json 的 launchConfig.logBridge，打包时带入产物；默认 false；不建议先做打包版内设置入口 |
| AutoJs.globalConsole | 存在；App 初始化 inrt.AutoJs，脚本 ConsoleImpl 会转发到 GlobalConsole；但日志桥必须挂在 :script 进程 |

## 1. 打包版怎么启动脚本

### 1.1 模板来源：inrt 自己就是运行时

- 模板就是 :inrt 的 release APK：apps/inrt/build.gradle:74-103，task buildApkPlugin 依赖 packageRelease，把 build/outputs/apk/release/inrt-arm64-v8a-release-unsigned.apk 复制为 plugins/apkbuilder-plugin/src/main/assets/template.apk（74、75、83、84、86-91）。
- 打包器取模板：apps/app/src/main/java/com/jdkshen/aijspro/build/ApkBuilderPluginHelper.java:74-103（openTemplateApk 按 /sdcard/template.apk、缓存、插件、assets 顺序找）。
- :inrt 直接依赖 :engine/:engine-rhino：apps/inrt/build.gradle:127-130；所以模板里本来就有 com.stardust.autojs.AutoJs 与 ConsoleView。

### 1.2 入口 Activity/Application：来自模板，不是 ApkBuilder 生成

- Application：apps/inrt/src/main/AndroidManifest.xml:34-35，android:name=".App"；实现见 apps/inrt/src/main/java/com/jdkshen/aijspro/inrt/App.kt:30-42。
- 启动 Activity：apps/inrt/src/main/AndroidManifest.xml:65-73，.SplashActivity 带 MAIN/LAUNCHER；实现见 apps/inrt/src/main/java/com/jdkshen/aijspro/inrt/SplashActivity.kt:31-54。
- 脚本执行 Activity/日志 Activity 都在 :script：AndroidManifest.xml:51-63（LogActivity/InrtScriptActivity/ScriptExecuteActivity）；SplashActivity 默认把执行交给 LogActivity：SplashActivity.kt:128-145。
- InrtProcessRole 只判断主进程/:script（apps/inrt/src/main/java/com/jdkshen/aijspro/inrt/InrtProcessRole.java:21-29），不是启动入口。

宿主打包器实际只做三件事：

1. 解压模板：apps/app/src/main/java/com/jdkshen/aijspro/autojs/build/ApkBuilder.java:109-110、137-140；third-party/ApkBuilder/apkbuilder/src/main/java/com/stardust/autojs/apkbuilder/ApkPackager.java:51-65。
2. 改清单身份/图标/权限：ApkBuilder.java:949-984（updateProjectConfig 只 setAppName/setPackageName/setVersionCode/setVersionName/replaceIcon/permissions/accessibility，没有替换 Application/Activity 类名）。
3. 重新签名：ApkBuilder.java:1321-1343；ApkPackager.java:67-73。

所以：打包版运行时就是 inrt 的那套 Activity/Application，不存在宿主另生成的入口。宿主侧的 Flutter/Native 打包页负责调用 ApkBuilder：当前活跃入口是 Flutter（apps/app/src/main/java/com/jdkshen/aijspro/ui/project/ProjectConfigActivity.java:15-18 明确«统一 Flutter»），Flutter 桥在 apps/app/src/flutterpoc/java/com/jdkshen/aijspro/flutterpoc/PocPackaging.java:421-507 构造 ApkBuilder；MiuixBuildActivity 是旧路径（apps/app/src/miuix/.../MiuixBuildActivity.kt:769-770）。

### 1.3 启动顺序（打包版）

1. App.onCreate（App.kt:39-42）：GlobalAppContext.set → AutoJs.initInstance → 定时任务/停止中继初始化。
2. SplashActivity.onCreate（SplashActivity.kt:35-54）：读 assets/project/project.json 的 launchConfig（56-62），按 showSplash 决定是否显示启动页；然后 main()。
3. main() 申请权限（SplashActivity.kt:84-94）；权限结束 runScript()（147-161）。
4. runScript 调 handoffToScriptProcess（SplashActivity.kt:97-145）：hideLogs=false 启动 LogActivity(:script)，hideLogs=true 启动 InrtScriptActivity(:script)；成功后 finish。
5. LogActivity/InrtScriptActivity 在 :script 初始化 InrtScriptThreadHost（InrtScriptThreadHost.java:69-110），把 GlobalProjectLauncher.launch 投到 :script 主 Looper；GlobalProjectLauncher 是 AssetsProjectLauncher("project")（apps/inrt/.../launch/GlobalProjectLauncher.kt:11）。
6. AssetsProjectLauncher.prepare（AssetsProjectLauncher.kt:270-281）把 assets/project 解到 filesDir/project，运行工程入口脚本；runtime 配置来自 ProjectConfig.fromAssets（46 行）。

## 2. activity_main、ConsoleView 与新 Switch

### 2.1 当前源码：activity_main 只有 ConsoleView，没有 Switch

- apps/inrt/src/main/res/layout/activity_main.xml:2-29：根 LinearLayout + AppBarLayout/Toolbar（16-22）+ ConsoleView（24-29）；没有 Switch/CheckBox。
- 全 apps/inrt/src/main/res/layout 的 Switch 搜索结果为空；只有 SettingsActivity 的 preference.xml 有 SwitchPreference（apps/inrt/src/main/res/xml/preference.xml:7-33）。

### 2.2 它在打包版会不会显示：会，但只在 LogActivity 且 hideLogs=false

- 使用点：apps/inrt/src/main/java/com/jdkshen/aijspro/inrt/LogActivity.kt:61-66，setContentView(R.layout.activity_main)，findViewById(console) 后 consoleView.setConsole(AutoJs.instance.globalConsole as ConsoleImpl)。
- LogActivity 在打包模板清单里：AndroidManifest.xml:51-53（:script）。
- 默认启动路径把它拉起：SplashActivity.kt:128-137（hideLogs=false → LogActivity，EXTRA_LAUNCH_SCRIPT=true）；AssetsProjectLauncher.kt:99-117 也会在 hideLogs=false 时跳到 LogActivity。
- 隐藏时不会显示：Pref.shouldHideLogs（Pref.kt:43-45）或 project.json 的 launchConfig.hideLogs（LaunchConfig.java:13-14、SplashActivity.kt:130-137）为 true 时，走 InrtScriptActivity/直接 headless 执行，activity_main 不被 inflate。
- 因此它不是“只有把 inrt 当独立 runtime 才用”的界面：打包版与独立 inrt 共用同一套 LogActivity；只要 hideLogs=false，打包 APK 里也能看到 ConsoleView。

### 2.3 如果新 Switch 放在 activity_main

- 会显示：仅当 LogActivity 被打开时显示；它不会出现在 SplashActivity（activity_splash.xml）或 SettingsActivity（activity_settings.xml）。
- 不会显示：hideLogs=true 的打包产物默认直接进 InrtScriptActivity/headless，用户看不到 activity_main，自然看不到这个 Switch。
- 结论：把日志桥开关只放 activity_main 不可靠；如果要让用户随时打开/关闭，至少还需要 SettingsActivity 或悬浮入口，且要绕开 hideLogs 的路径。

## 3. 打包版自己的配置/资源在哪

### 3.1 产物内确实有 assets/project/project.json

- 模板自带一份占位配置：apps/inrt/src/main/assets/project/project.json:1-13（name=打包测试/packageName=xx.xx/main=main.js 等）。
- 但打包时模板的 assets/project 会被清掉：ApkBuilder.java:403-415 prepare 后 deleteTemplateProject；418-426 递归删除；注释 407-408 明确“模板不提供第二个工程的文件或配置”。
- 用户工程由 copyProjectToWorkspace 复制到工作区 assets/project：ApkBuilder.java:530-555；随后 syncProjectJsonAndDeriveKeys 重写 project.json：1181-1319。
- 因此产物里的 assets/project/project.json 是宿主生成的，不是模板那份。

### 3.2 宿主写进 project.json 的字段（ApkBuilder.java:1187-1315）

| 字段 | 写入位置/行为 |
|---|---|
| name/packageName/versionName/versionCode | 1198-1209 |
| engine | 1210-1212 |
| launchConfig.hideLogs / showSplash | 1215-1220 |
| launchConfig.requestPermissions | 1221-1231 |
| launchConfig.splashText | 1232-1236 |
| main | 1248-1249 |

运行端读同一份：SplashActivity.kt:56-62（ProjectConfig.fromAssets）；AssetsProjectLauncher.kt:45-47（filesDir/project + ProjectConfig.fromAssets），prepare 再解压资产到 filesDir/project（270-281）。另有 assets/project/main.js、splash.png（ApkBuilder.java:72、910-923）及工程资源。

### 3.3 其它身份配置

- 清单 label/package/version/icon 由 ApkBuilder.updateProjectConfig 写进 AndroidManifest 工作区（949-984）。
- resources.arsc 包名由 buildArsc 重写（1030-1067）；最终由 ApkPackager 重新签名。

### 4.2 结论：没有日志桥/调试桥开关

- LaunchConfig.java:11-67 只有 hideLogs/showSplash/splashText/requestPermissions。

- ApkBuilder.java 的内部类 AppConfig:1366-1591（字段 1366-1391、setter 1394-1582）没有 debug/bridge/port；build/sync 路径 949-984、1187-1315 也没有写调试开关。
- 宿主 App 自己的“允许远程调试/9317”是主程序设置页（flutter-ui/lib/service_drawer.dart:687-736、flutter-ui/lib/computer_connection.dart:14、715-717），属于主程序，不会复制进打包模板。
- 当前若想开日志桥，打包链路里没有现成入口，必须新增。

## 5. 建议：开关放哪

### 5.1 三选一

| 方案 | 结论 | 理由 |
|---|---|---|
| (a) 打包时写产物 assets 的标志文件 | 不推荐 | 产物已有 assets/project/project.json，再加 flag 文件是第二套配置源；读取/校验/打包页展示都要各写一遍，且看不出与 launchConfig 的关系 |
| (b) 读打包项目 project.json 的字段 | **推荐** | 已有 ProjectConfig/LaunchConfig 读取链；ApkBuilder 已经把源 project.json 复制进产物并重写；打包页已有“启动配置”卡片；只加一个默认 false 字段即可 |
| (c) 打包版内提供设置入口 | 暂不推荐 | 当前 hideLogs=true 时 activity_main 根本不显示，设置入口会被藏掉；日志桥是开发者/打包期能力，默认不应让安装后的普通用户随意暴露调试端口 |

### 5.2 推荐的最小改动路径（方案 b）

目标：打包页一个“日志桥(9317)”开关，写进项目 project.json 的 launchConfig.logBridge；打包时随工程 assets 进入 APK；inrt 在 :script 启动时读取并只在 true 时启动桥；默认 false。

| # | 文件 | 改动 | 估算 |
|---|---|---|---|
| 1 | modules/engine/src/main/java/com/stardust/autojs/project/LaunchConfig.java | 新增 @SerializedName("logBridge") boolean 字段（默认 false）+ shouldLogBridge()/setter；位置可跟 hideLogs 同组（13-31） | 6-8 行 |
| 2 | flutter-ui/lib/project_page.dart | 新增 logBridge 状态；values() 的 launchConfig（165-170）加 logBridge；load 读 launch['logBridge']（327-329 附近）；启动界面卡片加一个 SwitchListTile（1624-1647 附近） | 10-15 行 |
| 3 | apps/app/src/main/java/com/jdkshen/aijspro/autojs/build/ApkBuilder.java | 若要覆盖“单脚本打包”也生效：AppConfig 加 logBridge 字段 + setter，syncProjectJsonAndDeriveKeys 在 1215-1220 附近 put launchConfig.logBridge。项目目录模式其实可依赖 copyProjectToWorkspace + sync 保留该字段，但建议显式加 | 8-12 行 |
| 4 | apps/app/src/flutterpoc/java/com/jdkshen/aijspro/flutterpoc/PocPackaging.java | 若走 AppConfig 显式字段：runBuild 的 launch 段（445-452）加 appConfig.setLogBridge(launch.optBoolean("logBridge", false))；若走 project.json 保留则可不改 | 2-3 行 |
| 5 | apps/inrt/src/main/java/com/jdkshen/aijspro/inrt/script/InrtScriptThreadHost.java | initialize 在 ensureInrtAutoJs(context) 之后（93 行附近）读 assets/project/project.json；true 时用 AutoJs.instance.globalConsole 启动 9317 日志桥 | 5-10 行 |
| 6 | 队友的 log-only 9317 桥 | 接收 GlobalConsole / Console 回调；只在 :script 起服务 | 队友负责 |

总计除桥实现外约 30-45 行。默认关闭；打包页明确写“仅调试使用，会把脚本日志暴露到局域网 9317”。不建议把开关塞进 activity_main（hideLogs 时会消失）。

实现要点：

- 优先级顺序：packaging UI → 源 project.json 的 launchConfig.logBridge → ApkBuilder 复制/重写 → 产物 assets/project/project.json → inrt 启动读取。
- 若选择只依赖 project.json 保留（不改 AppConfig），必须确认走的打包路径一定执行 copyProjectToWorkspace 并保留 launchConfig 未知键；当前 ApkBuilder.syncProjectJsonAndDeriveKeys 是“取现有 launchConfig 再覆盖已知键”（1215-1218），会保留 logBridge。
- 桥必须只在 :script 启动，见第 6 节。

## 6. 打包版里的 AutoJs 与 globalConsole

### 6.1 存在性

- 基类存在：modules/engine/src/main/java/com/stardust/autojs/AutoJs.java:44（public abstract class AutoJs），字段 mGlobalConsole 在 56，创建在 67、79-80。
- inrt 子类：apps/inrt/src/main/java/com/jdkshen/aijspro/inrt/autojs/AutoJs.kt:28（extends com.stardust.autojs.AutoJs）；App.kt:42 调 AutoJs.initInstance(this)。
- 模板包含 :engine（apps/inrt/build.gradle:127-130），所以打包版 DEX 里有 com.stardust.autojs.AutoJs。

### 6.2 脚本日志会进 globalConsole

- 每个进程的 AutoJs 构造时创建 GlobalConsole：AutoJs.java:67、79-80。
- runtime 的 ConsoleImpl 拿到 globalConsole：AutoJs.java:138（setConsole(new ConsoleImpl(mUiHandler, mGlobalConsole))）；ScriptEngineServiceBuilder 也注入同一份（AutoJs.java:105-111）；inrt AutoJs.kt:94-102 的 createRuntime 调 super，所以 inrt 打包版同样走这条。
- 脚本 console.log 最终走 ConsoleImpl.printLine，转发 mGlobalConsole.println：modules/engine/src/main/java/com/stardust/autojs/core/console/ConsoleImpl.java:182-198（196-198 是转发行）。
- GlobalConsole.println 用 log4j 记录（GlobalConsole.java:26-41）；LogActivity 直接把 AutoJs.instance.globalConsole 传给 ConsoleView（LogActivity.kt:64-65）。
- **所以答案是有，且正常运行脚本时 globalConsole 会收到日志。** 但注意进程边界：
  - 打包版脚本在 :script（SplashActivity.kt:128-137、LogActivity.kt:32-42、AssetsProjectLauncher.kt:146-189），而 App.onCreate 也会在 :script 执行（App.kt:39-42）。
  - 因此 :script 里有自己的 AutoJs 实例/globalConsole；InrtScriptThreadHost 还在 ensureInrtAutoJs 里兜底初始化它（InrtScriptThreadHost.java:285-320）。
  - 日志桥若放在主进程，看到的会是主进程的那份 globalConsole，收不到 :script 脚本日志。**桥必须挂到 :script 的 AutoJs.instance.globalConsole，或把 :script 的 log 转发给主进程。**

### 6.3 挂载建议

在 InrtScriptThreadHost.initialize（69-110）里，ensureInrtAutoJs（93）成功之后：

1. 读 ProjectConfig.fromAssets(context, ProjectConfig.configFileOfDir("project"))（AssetsProjectLauncher.kt:45-47 同款；实际 asset 路径是 project/project.json）。
2. 如果 launchConfig.shouldLogBridge() 为 true，start bridge(AutoJs.instance.globalConsole)。
3. 桥只监听 GlobalConsole/ConsoleImpl 输出，不提供执行/文件能力；默认 false；日志桥服务结束随 :script 进程退出。

这样 bridge 与引擎、脚本、LogActivity 同进程，日志来源一致；不需要额外在 activity_main 放 Switch。

## 7. 检查清单（给接线）

- [ ] 入口：确认打包产物 AndroidManifest 仍是 .App + .SplashActivity（不是宿主另生成）。
- [ ] config：打包后 unzip 确认 assets/project/project.json 有 logBridge 字段。
- [ ] off：默认包不监听 9317。
- [ ] on：打开打包页开关后重新打包，:script 进程启动桥；脚本 console.log 能在 VSCode 收到。
- [ ] hideLogs=true 的包也能开桥（桥不依赖 activity_main）。
- [ ] 校验端口只在 :script，不误暴露主进程。
