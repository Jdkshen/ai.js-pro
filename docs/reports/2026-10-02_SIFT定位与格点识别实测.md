# SIFT 定位 + 格点字形/颜色识别：修改与真机复测

## 结果

在 Redmi K40（Android 16 / SDK 36）上，QuickJS、Rhino 均完成同一组测试：9 张原始象棋截图、2 张变换图片、1 张无棋盘图片，以及 3 次重复帧识别。

| 检查 | QuickJS | Rhino |
| --- | --- | --- |
| 8 张稳定原始局面，严格比较全部 90 格 | **8/8 整盘全对** | **8/8 整盘全对** |
| 原始 9 帧（含落子动画；真值 `?` 一格跳过） | **806/809，99.6%** | **806/809，99.6%** |
| 红黑阵营错认 | **0** | **0** |
| 平移 60×80 px，画布 1200×2600 | **90/90**，重新定位 | **90/90**，重新定位 |
| 缩至 810×1800（原图 75%） | **90/90**，重新定位 | **90/90**，重新定位 |
| 无棋盘图片 | 返回 `board-not-found` | 返回 `board-not-found` |
| 落子动画 `skin2-04.png` | `usable=false` | `usable=false` |
| RGB 灰度权重、回收后副本独立性 | 2 项通过 | 2 项通过 |

稳定原始局面加两张变换图共 10 帧，**900/900 格正确**。动画帧仍保留原始错误用于计分：r4c3、r5c3 读成未知，r5c5 将飞行中的棋子读成黑马；没有把这些位置排除后再宣称全对。

本结果是同一浅木皮肤测试集的复测成绩；新皮肤需要对应的字形模板和几何标定。

## 修改后的流程

1. **SIFT 只负责定位棋盘**：`createSiftMatcher` 的模板从 `skin-a.png` 裁出；用匹配四角及模板内网格标定计算当前原点、格距。识别模块不接收真值 FEN。
2. **复用几何，逐帧重新认子**：对两段河界文字做 NCC 位置校验，分数均 ≥0.97 才复用网格；校验失败、画面变换或连续复用满 30 帧时重新跑 SIFT。返回 `geometryCacheHit` 区分两种路径。
3. **格点附近识别字形**：复用工程 `glyph-recognizer.js` 的占位检查、粗细两层 NCC 和多尺度复核；每次扫描全部 90 个位置。
4. **颜色校验**：車、馬、炮的红黑共用字形，在匹配到的笔画上根据颜色区分阵营。
5. **完整性标记**：有未知格，或双方将帅数量不是各一个时，`usable=false`。实际自动走棋还需要工程已有的棋规与多帧稳定校验。

几何缓存仅保存棋盘位置及参考纹理，每帧都重新读取棋子；不同局面返回不同的 FEN。当前字形识别器接受轴向网格，明显旋转、透视变形会返回 `unsupported-board-perspective`，需要矫正后再识别。

## Rhino 适配与源代码修正

- 修正 `modules/engine/src/main/assets/modules/__images__.js` 的 **`images.grayscale()` 通道顺序**。`ImageWrapper` 是 RGB/RGBA；旧 `BGR2GRAY` 会把浅木棋子亮面压暗，导致占位门把棋子全部过滤。改为按通道数使用 RGB/RGBA 灰度转换，单通道输入返回独立副本。
- 数值复核：红、绿、蓝、白转换为 **76、150、29、255**；灰度副本在源灰度图回收后仍有效，原彩色图也保持有效。
- 现有字形模块为 QuickJS 编写。准备工具生成同步模块的 Rhino `var` 兼容副本，避免旧 Rhino 循环内常量绑定导致的重复使用已回收图片。
- Rhino 测试适配器用 Mat 裁图保留灰度通道，用 `countNonZero` 统计二值图，单次 `TM_CCOEFF_NORMED + minMaxLoc` 获取小窗口最高分。字形识别器已有金字塔，避免再次走旧模板 API 的金字塔及提前接受路径。

**测试方式**：设备宿主为 dev-771；Rhino 测试脚本加载工作区修改后的完整 images 模块工厂，再运行公开的 SIFT、灰度接口。测试覆盖的是新源模块和新测试流程，源文件哈希记录在结果中。
