# 系统录屏并用：独立截图 API

## 根因

小米 8（ce4d2bdb，Android 15）日志 23:18:01 明确记录：`Stopped MediaProjection to start new incoming projection`。YOLO 此前正常运行，系统录屏启动后停止了 AI.js Pro 的 MediaProjection。dev574 的授权/尺寸/清理修复不解决两个投影会话并用。

## 本轮修改

- 新增 `AccessibilityScreenCapturer`，使用 Android 11+ 官方 `AccessibilityService.takeScreenshot(Display.DEFAULT_DISPLAY, ...)`。不创建 MediaProjection，不启动第二条录屏。
- 无障碍服务元数据声明 `canTakeScreenshot`；不自动授予或开启无障碍，不修改打包页权限默认值。
- QuickJS / Rhino 支持显式 `requestScreenCapture({mode: 'accessibility'})`。这是整个屏幕截图，不是单应用截图；不会在单应用授权停止后偷偷扩大截图范围。
- 普通 `requestScreenCapture('portrait')` 保持原高速 ImageReader 路径；没有改模型、输入尺寸、线程数和推理实现。
- 无障碍截图由所有脚本共享的请求锁串行化，350ms 请求间隔；系统返回限频错误时在超时预算内重试。每次返回新的实际截图，不用重复旧帧伪造 FPS。
- 兼容通道默认等待 2000ms；QuickJS 仍可指定 `timeout`。中断/超时的晚到回调回收像素，HardwareBuffer 和临时 Bitmap 显式释放。每次截图仍转换为既有 NativeFrame，YOLO 调用不变。
- 原 YOLO 持续识别示例增加截图通道选择；新增独立 `YOLO录屏兼容测试.js`，避免必须重置用户已修改的旧示例才能试用。

## 使用

1. 安装 dev575。
2. 手动开启 AI.js Pro 无障碍。若更新前已开，需要关闭再开启，使服务重新加载截图能力。
3. 启动系统录屏。
4. 示例 → QuickJS 新引擎 → YOLO目标检测 → DNN → YOLO录屏兼容测试.js。
5. 检查连续 60 帧、画面与识别正确，以及系统录屏是否仍在进行。也需反向顺序（先识别后启动录屏）回归。

## 验证边界

- 三个 ABI 原生库已重新编译成功。
- 截图状态既有 7 项针对性单元测试通过；主应用构建及示例资源守卫通过。
- 新截图请求的 QuickJS/JNI/Java 调用在小米 8 实机已跑通；未开启无障碍时返回明确中文权限错误，无录屏授权对话框、无闪退。
- 截至本轮发布前，小米 8 的 `enabled_accessibility_services` 为 null，因此实际取帧、与系统录屏并用、颜色/坐标、长稳和速度仍未验收。不能宣称并用已通过。
- Android 16 未测试。安全保护画面仍受系统截图限制，不尝试绕过。
- 无障碍通道受系统截图频率限制，目标是并用兼容，不保证原约 34 FPS。普通高速模式不受此限频逻辑影响。
- 未重建或覆盖用户已有的 `template.apk`，本次不宣称打包 APK 模板已包含该截图能力。

官方依据：[AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[Media projection](https://developer.android.com/media/grow/media-projection)。
