# inrt 定时任务补全（task-162，2026-10-19）

## 结论
在 task-160 基础上补齐 Lead 指出的 4 个限制，K40 用 **inrt debug APK（= 打包运行时本体）** 验证：
1. **广播 Intent 任务**：`work_manager.addBroadcastIntentTask({action,path})` → 主进程动态注册 → adb 广播 → 拉起 `scripts/alt2.js` PASS；
2. **任务 path 按具体脚本执行**：`addDisposableTask({path:'scripts/alt.js'})` → 到点执行工程内 `scripts/alt.js`（不再固定 main.js）PASS；
3. **headless exit() 中止后续**：`ScriptRuntime.exit()` 主 Looper 分支也抛 `ScriptInterruptedException`；`exit()` 之后写文件的代码未执行 PASS；主机 dev-1110 回归 `EXIT_AFTER` 也不出现；
4. **exact alarm 未授权引导**：新增 `InrtExactAlarmPromptReceiver`（Toast + 设置页 + 通知）；K40 ROM 默认授予精确闹钟（appops deny 后 `canScheduleExactAlarms()` 仍 true），用 DEBUG-only 强制开关走未授权分支，实测设置页 `Settings$AlarmsAndRemindersAppActivity` 打开、通知「定时任务需要精确闹钟权限」出现。

## 实现摘要
- 新增 Intent 任务模型/持久化/注册表：`InrtIntentTask`、`InrtTaskStore`（intent_tasks 数组）、`InrtIntentTaskRegistry`、`InrtIntentTaskCommandReceiver`；
- `InrtWorkManagerModule` 增加 `addBroadcastIntentTask/addIntentTask/getIntentTask/removeIntentTask/queryIntentTasks/getAllIntentTasks`；`addActivityIntentTask` 明确抛中文（需要无障碍活动监听，inrt 暂不支持）；
- `InrtTaskService`/`InrtTaskReceiver` 透传 `scriptPath`，`AssetsProjectLauncher.launchHeadlessScript(path)` 解析工程内相对路径并执行；
- `InrtTimedTaskScheduler`：schedule 前检查 `canScheduleExactAlarms()`，未授权时 Toast + 广播主进程 prompt receiver；
- Manifest：新增两个 receiver（intent 命令、精确闹钟引导）；
- `ScriptRuntime.exit()`：清理后无条件抛 `ScriptInterruptedException`（headless 主 Looper 也能中止后续）。

## 限制
- 仅广播 Intent 任务；`addActivityIntentTask`（按 Activity 启动触发）未实现——需要 Accessibility 活动监听，inrt 打包运行时暂不提供；
- 任务 path 支持**打包工程目录内**相对路径（如 `scripts/alt.js`）或绝对路径；不支持工程外脚本加密/资源表；
- Intent 动态 receiver 只在主进程存活期间有效；进程被杀后由下一次 App 启动/BOOT 恢复（与 Pro 的静态 receiver 行为有差异）；
- K40 ROM 无法真实复现「精确闹钟未授权」，引导分支用 DEBUG-only 开关验证；发布包逻辑相同。

## 构建要求
本次改的是 `:inrt` 模板 + engine（ScriptRuntime/init.js），需要：
1. `gradlew :inrt:assembleRelease`；
2. `powershell -File output/flutter-poc/rebuild-inrt-template.ps1`（刷新 `plugins/apkbuilder-plugin/src/main/assets/template.apk`）；
3. 再构建宿主 dev 包；否则打包产物仍是旧模板。
