## 结论

**没有全部补齐。** 当前 MCP 公开目录仍为 26 个工具，文件检索、示例、任务执行、引擎探测、工作区编辑与回退均有入口。对照已反编译的高级版，仍缺 5 项直接能力；停止范围和日志也有差异。脚本 API 已支持某功能，并不表示该功能已有直接 MCP 工具。

本次先修正已确认的参数类型、探针文件和结果混用、函数成员探测、临时脚本生命周期及完成状态发布顺序，没有新增公开工具。

## 本次已修正

### 1. 4 个参数的 Schema 类型与处理器不一致

此前以下参数都公布为 `string`，但处理器只接收原生布尔或数字；客户端按 Schema 传字符串时会被忽略并采用默认值：

| 参数 | 修正后的类型 |
|---|---|
| `list_scripts.recursive` | `boolean` |
| `workspace_cleanup.applied` | `boolean` |
| `workspace_cleanup.olderThanHours` | `integer` |
| `workspace_cleanup.keepAppliedHours` | `integer` |

提取 `McpToolSchema` 供真实工具定义使用，并保留其他参数类型与必填规则。

### 2. 探针文件与输出不隔离

此前所有请求写入并删除脚本目录内同一个 `mcp_api_probe_tmp.js`，可能覆盖同名用户文件，或在并发时互相覆盖、删除。提取结果时也使用同一个日志标记，可能误取另一探针输出。

现改为内存 `StringScriptSource`，每次生成独立源名称和 UUID 日志标记，仅提取本次标记，不写入用户脚本文件。

两种探针都显式添加引擎指令。核实引擎调用链后，无指令脚本当前默认仍为 Rhino；不能把“此前 Rhino 没写指令”直接断言为已发生错误引擎执行。本次显式化是为减少对默认行为的依赖。

### 3. 函数自身成员被漏掉

`probe_engine_api` 的描述包含 `function`，但原先仅对 `object` 调用 `Object.keys`。现在对象和函数都枚举自身可枚举成员，继续保留 200 项上限。原型与不可枚举成员仍不包含在结果中，探针不等于完整 API 签名库。

### 4. 等待超时提前删除临时脚本

指定 `engine` 的 `run_script` 会生成临时副本。此前 `wait` 返回（包括超时）就删除副本，脚本可能仍在运行或等待开始。

现在临时副本使用原子创建的独立名称，在成功、异常或启动失败时清理；等待超时不删除，也不会自动停止脚本。等待结束与实际执行结束使用不同的生命周期。

### 5. 结束状态先于日志准备

此前回调先公布 `SUCCEEDED` / `FAILED`，再存结果和日志，等待方可能返回尚未填充的日志。

现先保存数据再发布终态，降低探针拿到空结果的风险。普通任务日志仍来自全局控制台，本次独立标记只解决探针结果混用，未实现所有任务日志隔离。
