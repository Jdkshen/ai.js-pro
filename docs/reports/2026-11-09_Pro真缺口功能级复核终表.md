# Pro 真缺口功能级复核终表（非 V8 部分）

> 输入：[`2026-11-09_与Pro9.3.11对照_真缺口二分与两项补齐评估.md`](2026-11-09_与Pro9.3.11对照_真缺口二分与两项补齐评估.md) `1.2（159 个「真缺口」，判据=**简单名在我们仓库从未出现**）。
> 本轮：对其中**非 V8/Prolog 部分**逐个做**功能级**复核（V8 那 ~30 个整条线都没有，未逐条核）。
> Pro 侧 = `.artifacts/AutoJsPro源码树-2026-11-09/源码树/business/`（505 个 .java）；我们侧 = `modules/` + `apps/` + `plugins/`（1,149 个源文件）。
> **全部结论来自可复跑的文件级/类名级实扫 + 功能关键词搜索**，不是转述。

## 〇、方法（可复跑）

1. **重算清单**（我自己跑，不照抄 `1.2 的聚合行）：

   ~~~text
   扫 Pro business/**/*.java 505 个 → 取「文件名去扩展名」的简单名
   与我们 8 个源集根的 1,149 个 .java/.kt 文件名求差
   → Pro-only 164 个；剔除 V8/Prolog（包含 .v8. 或名以 V8 开头或 PlutoJS）40 个
   → 非 V8 候选 124 个（与报告 `1.2 的「预计 ~120」一致）
   ~~~

2. **声明级复核（关键修正）**：上一步是**文件名级**，会把「嵌套类 / Kotlin 文件门面」误判成缺口。逐条再用 `^\s*(public|internal|...)?(class|interface|enum class|object|annotation class)\s+<简单名>\b` 扫我们全部源码 → **124 个里只有 2 个**（`AndroidResources`、`PermissionConfig`）在我们仓库有**同名类型声明**（都是 `ProjectConfig` 的**嵌套类**）。其余 122 个在**类型声明级**也确实没有同名类型。
3. **功能关键词搜索**（本表判据）：对每个候选，按其**功能**（不是名字）在我们仓库搜：类名 / 关键方法名 / 注释里的中文名 / 领域词（如 `TaskScheduler`→`TimedTask`/`timed task`；`Aapt2`→`aapt2`；`SafeWindowBridge`→`RawWindow`；`ImagePool`→`ImagePool`/`recycle`）。命中的给出**文件:行**；无命中的判「真缺」。
4. **判定口径**：`已等价`=找到承担同一职责的实现（**换名/换模块/换形态**都算，写明差异）；`真缺`=没找到承担该职责的实现；`待定`=有部分能力但不构成等价，需产品决策。
   ⚠️ 本表**不含**行为级验证（未跑 Pro/我们的脚本对照），是**静态功能复核**。

## 二、建议补齐清单（按性价比排序）

**P0（便宜 + 直接提升脚本兼容性）**
1. **`automator.AccessibilityEventWrapper` + `automator.GestureOnMainThreadException`**：都是「让脚本侧事件/错误可读」的小包装，改动面小；异常类型还直接改善排查体验。
2. **`core.content.BroadcastReceiver` / `BroadcastReceiverInterface`**：脚本侧广播接收是常见需求，我们 **0 命中**（`registerBroadcastReceiver` 无实现）→ Pro 脚本迁过来会直接失败。
3. **`core.pref.TraySharedPreference`（+ `PrefContentProvider`）**：成本低；决定「悬浮窗偏好是否可被脚本按 URI 读写」。
4. **`core.ui.attribute.LinearLayoutAttributes`**：同包已有 10 个 Attributes，补 1 个成本极低。

**P1（中等成本、缺口明确）**
5. **`core.image.ImagePool` / `UnrecycledImageDetectedException`**：图像对象池 + 泄漏护栏；收益是**性能与稳定性**（高频截图脚本），不改语义、风险低。
6. **`core.looper.LooperThread`**：脚本线程模型的一环（已有 `ThreadCompat` 可依托）。
7. **`ui.widget.RadioButtonCompat` / `ScrollAwareExtendedFabBehavior`**：纯控件级，成本低，只在 Pro 风格 UI 上有感。

**P2（成本高/收益存疑，建议先评估）**
8. **可视化编辑器整族**（`VisualEditor*` + `hrapps.visual.lib.*` 共 7 个）：Pro 的**差异化功能**，不是脚本兼容性缺口；需产品路线决策。
9. **`project.SigningConfig*/PublishInfo/AssetProjectTemplate`**：属「打包 UI 产品化」缺口；当前用固定签名身份 + 构建脚本，**待产品决策**。
10. **`core.ui.aapt.Aapt2`**：构建期能力已有，只缺脚本侧 API；先确认是否真有脚本调用。

**有意不补**：`wxapi.WXPayEntryActivity`（无微信支付）、`QVMProtect`/`tool.QVMProtect`（不做 QVM 加固）。
**不建议补（我们更全/有等价形态）**：`TaskScheduler*`、`execution.*Kt`、`core.web.CookieManager*`、`core.floaty.SafeWindowBridge`、`core.console.{LogView,UiConsole,FileConsoleViewKt,LogCatAppender}`、`core.image.{ImageSimilarity,RhinoColorFinder}`、`view.accessibility.{WindowInfo,Capture,AsyncAccessibilityDelegate,AccessibilityServiceUtilsKt}`、`pio.PFilesKt*`、`enhancedfloaty.FloatyService`、`debugserver/contentprovider` 两个调试类。
