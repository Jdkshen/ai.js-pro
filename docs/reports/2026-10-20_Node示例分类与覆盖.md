## 5. 回归工具用法

```powershell
# 0) 只发现/分类，不碰设备
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test-node-samples-device.ps1 -ListOnly

# 1) 默认回归（自动执行可自动化的示例；白名单自动跳过）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test-node-samples-device.ps1 -DeviceId cccc62c7
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test-node-samples-device.ps1 -DeviceId cccc62c7 -TimeoutSeconds 30

# 2) 只跑一批（子串或正则）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test-node-samples-device.ps1 -Filter 找色 -DeviceId cccc62c7 -AllowScreenCapture
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test-node-samples-device.ps1 -Filter 图片与颜色处理 -DeviceId cccc62c7 -AllowScreenCapture -TimeoutSeconds 60
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test-node-samples-device.ps1 -Filter 象棋识别 -DeviceId cccc62c7 -TimeoutSeconds 40

# 3) 跑工程类示例（React/Vue/传统界面等）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test-node-samples-device.ps1 -Filter 传统界面 -DeviceId cccc62c7 -IncludeProject

# 4) 额外白名单文件（每行一个正则，# 注释）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test-node-samples-device.ps1 -SkipListFile tools\node-samples-skip.txt
```

参数速查：

| 参数 | 说明 |
| --- | --- |
| `-DeviceId` | adb serial；缺省要求恰好一台在线设备 |
| `-Filter <substr/regex>` | 只跑相对路径匹配的示例；匹配到工程类会自动带工程根目录 |
| `-TimeoutSeconds` | 单例超时（默认 20，任务要求范围 5–30） |
| `-SkipPatterns` / `-NoSkipPatterns` | 交互类白名单（默认含 悬浮窗/无障碍/截图/音乐/插件/网络服务/无限循环等）；传空或加 `-NoSkipPatterns` 可关闭 |
| `-SkipListFile` | 附加白名单文件（每行正则） |
| `-IncludeProject` | 执行工程目录下的示例（逐文件推送工程根目录，保留目录结构） |
| `-AllowScreenCapture` | 临时 `appops set ... PROJECT_MEDIA allow`（跑截图/图色类示例用，结束后恢复原值；仍弹系统授权时该例判 SKIP） |
| `-MaxSamples` | 本次最多执行几个 |
| `-ListOnly` / `-KeepScripts` | 只列分类 / 保留设备上的 push 文件 |

示例文件头可用 `// device-test: skip` 显式跳过（新示例推荐写原因，如 `// device-test: skip 需要人工授权`）。
另外自动跳过：`keepRunning()` 无限运行、`main.node.js`/`main.js` 工程入口、以及存在 `project.json`/`package.json` 的工程目录（除非 `-IncludeProject` 或 `-Filter` 命中）。

### 判定与产物

- `PASS`：logcat 出现 `execute returned ... exitCode=0`（且无 `SCRIPT_ERROR`），或出现 `运行结束` 且无脚本异常；
- `FAIL`：`exitCode != 0` / `SCRIPT_ERROR` / `FATAL EXCEPTION` / harness 异常；
- `TIMEOUT`：超时且无完成标记（前台被其它 App 抢占时会转 `SKIP` 并注明）；
- `SKIP`：白名单（交互/工程/无限运行）、截图授权弹窗、或运行期间前台被抢占。
- 每次输出：`output/node-samples-regress-<时间戳>/summary.json`、`summary.md`、`logs/<序号>-<示例名>.log`；脚本退出码 0 = 无 FAIL/TIMEOUT，1 = 有失败。

## 7. 维护约定

1. 新增 Node 示例必须带 `"nodejs";` 指令；会被自动跑到的示例应能在 20s 内自行结束，否则在文件头加 `// device-test: skip <原因>`。
2. 改了 Node 宿主注入模块/引擎后，至少跑一次 `-Filter <受影响分类>`；发 dev 包前建议跑一次默认全量。
3. 白名单默认模式维护在脚本 `-SkipPatterns`；新增交互分类时同步更新本文与脚本注释。
4. 工程类示例（含 `project.json`）不默认执行；需要时 `-IncludeProject` 或 `-Filter`。
5. 本工具只读仓库 sample，不会修改/删除示例文件；设备侧只写 `/sdcard/脚本/_node_samples_regress_/` 并在结束后清理。
