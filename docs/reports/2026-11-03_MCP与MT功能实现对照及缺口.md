## 3. 源码确认的其他缺口

以下已由当前源码确认，但没有在手机上逐项双端复现，不与上面的实测结果混写。

| 功能 | 当前实现缺口 | 主要位置 |
|---|---|---|
| APK 关键条目保护 | raw copy/patch/delete 还缺统一的 DEX、resources.arsc、AXML 分类和保留规则；不是所有目标都应允许按普通 ZIP 条目处理 | `McpApkToolkit.kt:347-361`、`:453-464` |
| DEX 方法编辑 | 编译后只检查类描述符，未核对 replacement 方法的名称/参数/返回类型与 locator 是否一致 | `ToolkitDex.kt:114-134` |
| AXML/DEX 新建 | `missing` 主要只实现普通 zip_entry 分支，缺 AXML 与新增类的语义路径 | `McpApkToolkit.kt:325-343` |
| APK 局部文本编辑 | 多个 edit 按顺序作用于变化后的文本，没有全部针对同一原始文本匹配；LF 归一化后的保存也未完整保留原条目行尾风格 | `McpApkToolkit.kt:209`、`:330-342` |
| 资源读取 | `resolveDepth`、`maxItemsPerValue`、variantSets 未实现；XML 最大预算 65536，而 MT 为 1048576 | `McpApkToolkit.kt:294-304` |
| 资源新增 | 部分带 type 属性的 path/reference 根节点类型推导、批量 name/type 一致性待补 | `ToolkitResources.kt:60-63`、`McpApkToolkit.kt:306-322` |
| ZIP 加解密 | 加密读文本/读字节/解压/更新未实现，不能只补 zip_create 就称完成 | `McpZipToolkit.kt` 的 ensureReadable、create、update、test 路径 |
| 原生 data xref | 当前只扫描对齐指针字面值，未把 REL/RELA 重定位槽纳入交叉引用 | `ToolkitElf.kt:219-262` |
| 汇编广度 | 内置 AArch64 汇编只支持少数指令，其他指令依赖可选 C/C++；可选汇编器也只接受 AArch64 | `ToolkitElf.kt:311-322`、`McpToolkitProvider.kt:53-76` |
| APK 构建 | 普通既有条目的压缩方法未完整保留；session_check/build 的待编译数量、变更分类、签名摘要等输出不全 | `McpApkToolkit.kt:409-450` |
| MCP 返回工作流 | 搜索实际返回 items，而复制的契约描述指向 data.hits；分页、nativeLocation、nextActions、资源 results 等输出还需一致化 | `McpApkToolkit.kt`、`toolkit-apk-schemas.json` |

不要把 `targetVersion` 的 16/64 位差异直接等同于数据错误：令牌应由当前服务读取并原样回传，不能跨服务复用。是否要求与 MT 客户端完全同形应单独决定；但 zip_update 多了强制参数已经造成实际调用失败。

## 5. 不应误判的差异

- **Java 反编译不是 MT 这 57 个 MCP 工具的要求。** MT 的 DEX 文本接口就是 Smali，不能因为 MT GUI 能看 Java 就把它列为 MCP 的必补项。
- **完整间接调用图、完整数据流不是双方已承诺的能力。** MT 也将 CFG 标为有界，不能把 complete=false 本身列为缺陷。重定位 data xref 是另一项明确缺口。
- **AArch64 等长窗口、expectedHex 和 NOP padding 已有基本实现。** 缺的是其他架构、一般汇编及 padding 内字符串增长。
- **签名读取不等于密码学验签。** MT 的工具也说明只读取信息；本轮缺口是 scheme 和证书覆盖，不是缺少“保证可安装”。
- 两个应用的工具目录、访问权限配置、独立签名身份不同属于产品配置差异，不能要求 AI.js Pro 依赖 MT 的私有目录或密钥。
- RE2 与 MT 的正则差异原先只能叫兼容风险；本轮 lookahead 已经实测，因此现在可以明确列为行为差异。

## 6. 建议修复顺序与验收

1. **P0：统一目标分类与构建检查。** 先封住普通 ZIP 删除/拷贝/字节写入对保留条目的误用；测试必须证明被拒绝后会话、DEX 和原始快照均不变。
2. **P1：恢复 MCP 主工作流。** 搜索覆盖和返回结构、AXML locator、新建 DEX、方法身份及原子文本编辑；同一夹具与 MT 双测后，验证返回 locator/cursor 可直接传入下一工具。
3. **P1：完整资源读写与签名信息。** default 归一化、逐项错误、完整 XML 预算、引用/集合参数、V2/V3/V3.1 证书检测及元数据。用 v2-only 和批量部分失败夹具验收，不能只测 v1 包或单项成功。
4. **P1：ZIP 加密和调用契约。** 创建、正确/错误密码、读文本/字节、解压、更新保留未改条目、CRC/HMAC 校验；zip_update 的版本保护若保留，应作为可选扩展并明确描述。
5. **P2：原生补丁/引用与正则。** ARM/Thumb/x86/x86-64、AArch64 一般指令、padding 窗口、REL/RELA；正则兼容必须保留资源预算和取消，不能直接无界切换引擎。
6. **最后统一构建、签名、分页和诊断输出，再做整链回归。** 在完成前只可称部分能力可用，不能按“MT 功能已全部对齐”发布。

这些任务都必须保持“不依赖 MT”。主助手应独占 `McpApkToolkit.kt`、构建/发布及真机；给 DP 拆辅助模块和单测时明确文件归属，避免多个任务同时改这个集中路由文件。
