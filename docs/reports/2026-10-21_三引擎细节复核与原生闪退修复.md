# 三引擎细节复核与 Pikafish 致命退出修复

本轮由“把三个引擎的功能细节核对一次”开始，随后接到象棋手机 native SIGABRT 的诊断记录。最终发布 **dev-1194**，象棋插件 APK 更新为 **1.0.1 / 2**。正式主 App 版本仍为 1.0.2 / 465。工作区尚未提交。

## 1. 象棋闪退：发现可独立复现的致命输入路径

原象棋设备是 `192.168.10.4`、型号 `2602BRT18C`、API 36；读取时已安装 dev-1192。它不是本轮 USB 测试使用的 K40 / 小米 8。用户提供的旧 crash buffer 在多个线程出现 `pthread_mutex_lock called on a destroyed mutex`，其中包括 RenderThread 和 hwuiTask0。

不能仅据此断言“无障碍截图 + 游戏动画 + 悬浮窗”就是唯一根因。两个直接证据：

1. 该设备 `ApplicationExitInfo` 中，与 22:18、22:23、22:27、22:31 等闪退 PID 对应的记录为 **reason=1 / status=1**，即自行退出、退出码 1。最近的这些记录没有可读取的 trace。没有把几天前 `:native` 进程的 tombstone 误用为本次证据。
2. 在 K40 的 dev-1192 上，**不截图、不创建悬浮窗、不点击游戏**，只启动 `PikafishNativeBridge` 并输入下面的局面，即复现主进程退出、MCP 断开和同样的 destroyed-mutex 日志：

```text
9/9/9/9/9/9/9/9/9/9 w - - 0 1
```

调用链：`nativeAnalyze` 只有 FEN 行宽等外形校验 → UCI `position` → `Engine::set_position` → `Position::set` 发现缺将等语义错误 → `UCIEngine::terminate_on_critical_error` → **`std::exit(1)`**。非法历史走法同样进入这条退出路径。命令行引擎被嵌入 Android 后，该调用会终止整个宿主；退出时其它线程仍活跃，可能继续报告已析构 mutex。RenderThread 日志不能排除这条先发生的退出路径。

已有分治中，“不走子”也意味着后续局面/历史输入不同，因此尚不能据此排除输入问题。用户项目 `autoplay/engine.js` 确实使用 `$pikafish.analyzePosition(baseFen + history)`；它本来准备在历史分析失败时回退，但原生退出使 JS 无法收到错误。

### 修复

- 在共享 JNI 入口用**原引擎的 `Position::set` 和 `UCIEngine::to_move`**验证局面及每一步历史。校验在独立临时 Position 上完成，不修改当前会话。
- 缺将、多棋子、兵种位置错误、非法回合计数、非法历史等返回 `error: invalid-position: ...`，宿主/插件门面返回 `ok:false`；这些输入不会再进入会调用 `exit(1)` 的 UCI 命令路径。
- 原生致命错误文本同时写 Android 日志，避免只留在重定向后的 UCI 内存缓冲中。
- `libpikafish.so` 和插件 `libxiangqi_engine.so` 均按同一份修复源码重新编译。没有修改上游命令行版的退出契约。

### 验证与边界

- JNI 直接调用 **6 项**：缺将、非法历史、多棋子、Rule60 越界、错误后仍运行、正常 quit。
- QuickJS 真实 `$pikafish` **5 项**：错误返回、错误后合法搜索、非法历史返回、随后合法历史搜索、连续 25 次错误输入后仍存活。合法搜索实测返回 `b2e2`，合法历史后返回 `c6c5`。
- Node 加载真实插件 1.0.1 **5 项**：启动、非法局面、非法历史、随后合法搜索、正常退出。
- 这些测试证明已修复一条确实产生该崩溃表现的路径；**尚未完成原象棋设备 dev-1194 上的真实对局长跑，不能据此排除其它 native 问题**。错误权重、内存分配失败等上游其它 `exit` 路径不在本次位置校验的覆盖范围。

取证工具是 `tools/probes/export-native-crashes.js`。Android 12+ 允许通过自身进程的 `ApplicationExitInfo.getTraceInputStream()`读取 native tombstone；本次最近退出记录返回 null，已如实记录。参见 [Android 官方说明](https://developer.android.com/reference/android/app/ApplicationExitInfo#getTraceInputStream())。

## 2. 三引擎本轮修补

| 范围 | 发现及修复 |
|---|---|
| Rhino 图色 | 显式 `threshold:0` 被 `||` 改成默认阈值，导致精确找色误命中；保留零值，修复 findColor / findAllPointsForColor，补正 similarity=0 |
| QuickJS 文件 | listDir 忽略过滤函数；open 缺失文件假装空文件。现在执行名称过滤并报告真实文件错误 |
| QuickJS 定时器 | setTimeout / setInterval / setImmediate 丢附加参数；现在按调用顺序传入回调 |
| QuickJS 子引擎 | execScript / execScriptFile 丢 arguments、path 数组；补齐嵌套参数、路径与默认 cwd。engines.all 的空子引擎不再抹掉全集 |
| Node 并发归属 | 多个脚本首次 myEngine 得到最新任务的 ID / 参数，子执行事件串线。改为真实任务 ID 贯穿请求和 owner 注册表；子执行按父任务投递及清理，覆盖合法 ID=0 |
| Node 引擎句柄 | 修正其它引擎的 source / className，once 与监听列表变更不再重复调用或漏掉相邻监听 |
| Node 存储 | 三个池进程各自缓存 SharedPreferences 会丢键。改由私有、未导出的主进程 ContentProvider 串行读写原有存储文件，检查 commit 结果 |
| Node events | require('events') 恢复可构造的原生 EventEmitter 及静态 API；保留自家模块级 emit，0 / false / 空串 / null / 数组可实际往返 |
| Node 生命周期 | exit / 主线程 interrupt 真正结束当前嵌入任务；Worker 提前退出也写入终态，join / isAlive / getError 可用 |
| 文件/监听清理 | Node 缺文件读取抛真实错误；释放通知 listener receiver，修正只观察 toast 的 Rhino 监听清理 |
| 隔离进程自动化 | RemoteUiObject.exists 实际查当前窗口；远程 findOne / untilFind 尊重 interval |
| MCP 查询 | Rhino Java 对象不支持部分 ECMAScript descriptor 操作，原来整个模块查询失败。加入安全枚举、Java 公开成员与 prototype / descriptor 降级，保留“不执行 JS getter”契约 |
| Dex 示例 | files.list 返回文件名，示例误将文件名直接交给 loadDex；现在与 dexDir 拼接绝对路径 |

三引擎的原生接口形态仍有区别。Node 使用 datastore / 原生 Node 标准库，Rhino 的 storages.create 与 Node 原有字符串 storages 接口没有被强改成同一个签名。

## 4. 仍不能宣称完成的范围

- 305 个 JS 的全量编译，不等于所有交互示例、所有参数/异常分支都已在当前包逐一操作。
- Rhino 老 Pro 脚本不能直接作为 QuickJS / Node 的通用测试。错误套用 `$crypto/$zip/$settings/$colors.mapping` 的早期 QuickJS 尝试已与其实际接口测试分开，没有伪装成这些 API 等价。
- Root / Shizuku 外部条件、完整 AccessibilityEvent/source、第三方旧 V8 强依赖插件、全部 OpenCV addon、所有外部原生 View / 资源与 inrt 模板仍需专项验收。
- 原象棋设备的长期自动对局、MediaProjection 对照实验尚未完成；没有启动看门狗，也没有改它的自动走棋配置。

DP 完成了两份只读审计及限定的 QuickJS / Node 修补；主控复核、补齐跨进程与原生修复、构建和真机验证。后来追加的 native 只读审计达到 650 秒超时，未作为完成交付；本次非法输入复现及修复由主控完成。
