# crypto_（现场 hash/HMAC/AES-GCM/RSA 签验）（dev-1428）

> 日期：2026-11-09 12:1x–12:3x · 起点 HEAD 8a341d72 · K40=cccc62c7（dev-1428）

## 0. 本轮做了什么

交接单 ⑥⑦ 的第四个工具项 `crypto_` 落地（范围提案 §3）：**纯 JCA、无新依赖**，密钥**只允许显式给**（绝不读 App 私有密钥库/签名身份）。

## 1. 能力与边界（W1 task-32）

| op | 支持 | 说明 |
|---|---|---|
| `hash` | MD5/SHA-1/256/384/512（默认 SHA-256） | 流式 64KB 块 |
| `hmac` | HmacMD5/HmacSHA1/256/384/512（默认 HmacSHA256） | 密钥必填 |
| `aes_gcm` | 仅 `AES/GCM/NoPadding` | 密钥 16/24/32 字节、IV 1..16（推荐 12）、可选 AAD、tag 96..128；方向由 `mode=encrypt|decrypt` 或 `decrypt=true` |
| `rsa_sign` / `rsa_verify` | PKCS#1 v1.5（MD5/SHA1/SHA256/SHA384/SHA512withRSA，默认 SHA256withRSA） | 私钥支持 PKCS#8 DER/PEM 与 PKCS#1 PEM；公钥支持 SPKI DER/PEM 与 X.509 证书；**只给私钥时验签 = 重签 + 常量时间比较**（`verificationMethod=private_key_resign_compare`） |

- **密钥**：只允许 `keyHex` 或**工具目录内** `keyRef`（越界/非文件/超 64KiB → `KEY_INVALID`）；只回显 `keyBytes`/`keySha256Prefix`；口令加密 PEM 明确拒绝。
- **输入**：`inputHex|inputText|path` 三选一；>64MiB **读之前**就 `INPUT_TOO_LARGE`。**输出**：`outputHex`（≤64KiB）或原子写 `outPath`（**不覆盖**已存在）；**所有校验与运算都在写盘前 → 失败不留半成品**。
- **错误码可区分**：`ALG_UNSUPPORTED` / `KEY_INVALID` / `MAC_INVALID`（GCM tag）/ `DECRYPT_FAILED` / `INPUT_TOO_LARGE`。
- **诚实边界**（notes）：JCA 通用原语、不管理密钥、不做 KDF、不读私有密钥库、不做信任判断、GCM 通过 ≠ 明文语义正确；描述里同时写明「不返回密钥内容」但**不承诺密钥不落任何日志**（调用方传入的 keyHex 会留在请求记录里）。

## 4. 未做 / 边界

1. 有意不做（写进描述/notes）：KDF/密钥派生、RSA-PSS、口令加密 PEM、CBC/CTR 等其它模式、密钥生成/导入/管理（范围提案里「先不做 crypto_keys，避免变成密钥管理器」的结论）。
2. 参数严格性只对 `hash` 收紧（不适用参数显式拒绝）；其它 op 对不适用参数是「忽略」而非报错（如需全线严格可再改）。
3. `hash/hmac` 虽流式但仍受 64MiB 上限（未做「超大文件无上限流式」）。
4. X.509 证书公钥路径**只有代码级**（单测覆盖 PEM 私钥与 PKCS#8/SPKI，未造证书夹具）。
5. 随包文档与 `tools/mcp-smoke` 未同步 `crypto_`（W3/Lead scope）。
