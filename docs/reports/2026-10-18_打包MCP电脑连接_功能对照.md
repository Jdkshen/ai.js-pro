## A. 打包 APK

### 当前实现链路（代码事实）
1. Flutter 入口（`lib/browser.dart`）：
   - 项目目录 →「项目配置与打包」→ 打开**玻璃自绘打包页**（ProjectPage）；
   - 单文件/示例文件 → 先调桥把它落盘成临时项目，再打开打包页；
   - 也保留了原生 Miuix 打包页的回退（注释里提到 MiuixBuildActivity）。
2. 桥方法：`PocBridge` → `PocIntegration` → `PocPackaging`（模板/ABI 列表、签名配置、权限、进度回调、输出路径）。
3. 模板：`plugins/apkbuilder-plugin` 的 `template.apk`；插件未装/模板缺失会报错。

### 期望行为（高级版语义）
| 功能点 | 期望 |
|---|---|
| 打包页字段 | 应用名、包名、版本、图标、ABI（arm64/armeabi）、权限、签名（默认/自定义 keystore） |
| 模板检查 | 未安装打包插件时提示去安装；模板版本不匹配提示 |
| 输出 | 生成 apk 到 `/sdcard/脚本/APK输出/`，页面显示路径/大小 |
| 结果 | 打包成功 → 可直接安装（签名正确）；失败 → 具体错误（模板缺失/签名失败/资源冲突） |
| 进度 | 分阶段进度（准备/编译/签名/完成），可取消 |

### 需核对/可能问题
- [ ] 点「打包」后是否显示明确错误（下载失败/解析包错误/模板缺失/卡住）？
- [ ] 打包插件 `apkbuilder-plugin` 是否已安装、`template.apk` 是否能释放；
- [ ] 输出目录是否存在/可写、生成的 apk 能否安装（`adb install`）；
- [ ] 进度条是否走完、完成后是否有「安装」按钮；
- [ ] 单文件打包 vs 项目打包两条路径是否都正常。

### 验证命令
```powershell

& $adb -s $d logcat -c
# 在 App 里操作：文件 → 项目 → 项目配置与打包 → 点打包
```

## B. MCP

### 当前实现链路
1. Flutter：`lib/device_page.dart` MCP 区（开关、地址、复制）→ 桥 `mcpState` / `mcpSet`；
2. 桥：`PocIntegration.mcpState` 返回 `lanIp/lanUrl/localUrl/autoStart/running`；`mcpSet` 持久化 autoStart；
3. 服务：`apps/app/src/main/java/com/jdkshen/aijspro/mcp/`（`McpService`、`McpHttpServer`），默认端口 **8788**，端点 **/mcp**。

### 期望行为
| 功能点 | 期望 |
|---|---|
| 开关 | 打开后服务 running，显示「运行中」 |
| 地址 | `http://<局域网IP>:8788/mcp`（不是占位/127.0.0.1） |
| 局域网 | 同网段电脑能访问 update.json? 不，是 MCP JSON-RPC 端点；curl 能连 |
| 持久化 | 重启 App 后开关状态保持 |
| 关闭 | 立即停止监听端口 |

### 需核对/可能问题
- [ ] 开关打开后 `McpService` 是否真的 running（`adb shell dumpsys activity services | grep mcp`）；
- [ ] 显示的 IP 是否真实局域网 IP（之前修过 dev-985，重装后数据清空可能回到默认）；
- [ ] 电脑 `curl http://<IP>:8788/mcp` 是否 200/JSON-RPC 响应；
- [ ] 端口被占用（8788）时是否提示；
- [ ] 重装后 autoStart 是否恢复。

### 验证命令
```powershell
$adb='C:\Android\platform-tools\adb.exe'; $d='DQKFJB59596L45BI'
& $adb -s $d shell dumpsys activity services com.jdkshen.aijspro | Select-String 'Mcp'
& $adb -s $d shell curl -s -o NUL -w '%{http_code}' --max-time 5 http://127.0.0.1:8788/mcp
# 电脑侧：
Invoke-WebRequest http://<手机IP>:8788/mcp -Method POST -Body '{"jsonrpc":"2.0","id":1,"method":"initialize"}'
```

## C. 电脑连接

### 当前实现链路
1. Flutter：`lib/computer_connection.dart`（mode 1 = 连接电脑主机；mode 2 = 手机开服务器由电脑连）；
2. 桥：`computerPluginState` / `computerPluginSet`（mode/enabled/host）；
3. 状态字段：`clientStateKnown`、服务端/客户端状态、host。

### 期望行为
| 功能点 | 期望 |
|---|---|
| 插件检测 | 未安装电脑插件 → 明确提示「安装电脑插件」并给入口 |
| 连电脑（mode1） | 输入电脑 host → 连接状态显示「已连接」 |
| 电脑连手机（mode2） | 手机开服务器 → 电脑端可发现并连接 |
| 错误 | host 无效/超时/版本不匹配 → 具体提示 |
| 持久化 | 连接配置重启后保留 |

### 需核对/可能问题
- [ ] `computerPluginState` 返回 `clientStateKnown=true` 还是永远 false（提示「尚未获取电脑连接状态」）；
- [ ] 插件是否已安装（电脑端 VS Code 插件 / apkbuilder-plugin 是两回事）；
- [ ] host 输入后连接是否超时、是否有重试；
- [ ] mode2 服务器是否真的监听端口、电脑能否发现。

### 验证命令
```powershell
$adb='C:\Android\platform-tools\adb.exe'; $d='DQKFJB59596L45BI'
& $adb -s $d logcat -d -v brief | Select-String 'computerPlugin|PocDeviceLink|电脑连接|ComputerLink'
```
