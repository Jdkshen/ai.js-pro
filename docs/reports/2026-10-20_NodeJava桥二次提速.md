# Node Java 桥二次提速（2026-10-20）

本轮针对反复调用 Java 方法，未改 Node/V8 二进制。最终有效同机对照中，2000 次无参数 Java 调用的中位耗时从 **23.832ms 降到 16.441ms，减少约 31.0%**。该结果不能外推为所有脚本、截图或 YOLO 提速 31%。

## 实施范围

- `node24/prelude.js`：复用已解析方法的 JS 函数，预先序列化类名、方法名和接收对象；无参数请求复用固定 JSON 字符串，有参数仍逐次转换并序列化。本轮期间该改动已随并行工作区的 `1832b10e` 纳入 dev-1152，故下方 Java 缓存对照的两边均已包含它。
- `Node24NoArgCallCache`：每次任务独立保存最多 128 个成功的无参数调用绑定，每条请求最多 1024 字符。仅保存 Method 和接收对象，每次命中仍执行真实 Java 方法、转换结果并返回原 JSON 信封；不保存返回值或异常。
- `Node24HostBridge`：对 prelude 生成的规范无参数请求跳过重复 JSON 解析和方法查找；带参数、非规范格式、未命中和失败请求保留原路径。加载新 dex 时清空，任务关闭时清空并禁止重新写入。
- 对照验证采用独立包名 `com.jdkshen.aijspro.speedtest`。随后并行构建将 Java 缓存随 dev-1153 一同发布；已核对发布 APK 包含新缓存，两台在线设备当前均为 dev-1153。

## 最终有效对照

设备 `DQKFJB59596L45BI` / `2602BRT18C`，Node 24.22.0。基线为 dev-1152，测试包来自相同工作区，加入上述 Java 缓存；包名不同。两边 Node native 资产相同，身份见 `output/node-bridge-speed-20261020/artifact-identities.json`。

按测试包、基线、基线、测试包顺序串行运行。每次脚本先执行 5000 次无参数调用预热，随后 15 轮，每轮 2000 次 `android.os.SystemClock.elapsedRealtime()`；带参数对照用 `java.lang.Math.max(i, 7)`，预热 3000 次，再测 15 轮。两边各合并 30 轮，以手机端 `process.hrtime.bigint()` 计时；同时保存 Android 单调时钟整数毫秒计时。

| 项目（2000 次调用） | dev-1152 基线中位数 | Java 缓存测试包中位数 |
|---|---:|---:|
| 无参数 SystemClock.elapsedRealtime | 23.832ms | 16.441ms |
| 带参数 Math.max | 34.279ms | 34.543ms |

带参数调用约差 0.8%，本轮没有显示出明确提速。初版把所有请求都送去查询、预热缓存，带参数基准曾回退；已收窄为规范无参数请求专用入口，上表是修订后的测试包数据。

## 验证

- 12 个 JVM 测试通过：调用绑定缓存 5 个、既有反射候选缓存 7 个，覆盖容量、LRU、释放、当前结果/异常、接收对象和参数重载隔离。
- 4 个 Node JS 契约脚本通过：Java 调用、prelude 工作目录及传感器、engines、dialogs。
- 每次有效真机对照均通过 12 项检查：无参调用副作用、不同对象隔离、带参调用、字符串/对象返回、异常与恢复、整数/小数重载、数组、原始 JSON、无效 JSON，以及加载两个同名类的不同 dex 后从返回 1 切换为返回 2。
- 独立 APK 构建成功。正常 applicationId 的构建也重新执行，恢复共享输出目录的普通包名，避免留下测试包产物给后续发布脚本误用。
- 两台设备的独立测试包均已卸载。

另一次延长预热的重跑未取得有效结果；K40 的额外测试只有测试包结果，基线请求因现有 Node UI 任务占用而返回 busy。这些不完整记录均未计入上表，未停止用户的象棋 UI 任务。

DP 独立只读复核任务 `26d98c33e6ae4d8f` 在 240 秒后超时，无最终结论；本报告不引用其分析结果。优化、集成与上述验证由主代理完成。
