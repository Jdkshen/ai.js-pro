### 顺带的安全修复（队友只报告，我确认后让其修）

`resolveSourceFile` 原本对**任意可读绝对路径**无校验（`/proc`、应用私有目录、任意 `/storage`）。现在：先 `canonicalFile`（防符号链接绕过）再按允许根判定；允许根只用于读取/hash/分析。

## 二、「假必填」这一类（用户反馈里 `withLogs` 的同族）

| 工具 | 从 required 移出 | 缺省 |
|---|---|---|
| `file_read_text` | `encoding`/`targetVersion`/`limit`/`maxChars`/`startLine`/`startColumn` | 空/空/500/49152/0/0（现在**只需 `path`**） |
| `file_read_bytes` | `targetVersion`/`byteOffset`/`maxBytes` | 空/0/256 |
| `file_list` | `path`/`cursor` | 空=root / 空=第一页（`recursive`/`limit` 仍必需） |
| `file_search` | `namePattern`/`minSize`/`maxSize`/`minModifiedAt`/`maxModifiedAt`/`contentPattern`/`cursor`/`limit` | 空/-1/-1/空/空/空/空/200 |
| `file_search_text` | `encoding`/`contextBefore`/`contextAfter`/`limit`/`maxChars`/`cursor` | 空/10/20/50/32768/空 |
| `file_discover_apk` | `recursive` | true |
| `zip_list` | `entryPath`/`recursive`/`simple`/`cursor`/`limit` | 空/t/f/空/1000（现在**只需 `path`**） |
| `zip_read_text` | `encoding`/`startLine`/`startColumn`/`limit`/`maxChars`（+`password`） | 空/0/0/2000/49152（现在只需 `path`+`entryPath`） |
| `zip_read_bytes` | `byteOffset`/`maxBytes`（+`password`） | 0/65536 |
| `zip_extract`/`zip_test`/`zip_create`/`zip_update` | `password` | 空 |

**原则**：只把「有默认值或空值/哨兵语义」的移出；`path`/`query`/`pattern`/`entries`/`overwrite`/`sign` 等真必需项保持 required。运行时读取同步改成 `optional*`，缺省值与 schema 一致（**不是只改 schema**）。

**仍未做**（列入下一批候选）：`file_search`/`file_search_text` 的 5 个 type/大小写字段仍 required（需先给它们加默认值）；`apk_search` 仍需显式传 `target/query/queryType/caseSensitive/includeMatchOffsets/limit/snippetMaxChars`；`zip_extract` 的 `overwrite` 仍 required。
