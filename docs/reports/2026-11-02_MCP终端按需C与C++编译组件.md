## 设计与使用

主应用只增加组件管理 CLI、状态和 PATH 接入。编译器、链接器、头文件、标准库独立打成 ZIP，安装到应用 no_backup 私有目录；按实际使用下载，更新 APK 不需要重新下载环境。App 终端和 MCP 共用相同 app 后端，不依赖 Shizuku，也不把下载任务放入脚本引擎槽。

```sh
aijs-toolchain status
aijs-toolchain install cpp --manifest http://192.168.10.7:8080/toolchains/cpp-arm64-v1.json
clang --version
mkdir -p "$HOME/cpp-work"
cd "$HOME/cpp-work"
printf '#include <stdio.h>\nint main(){puts("Hello C");return 0;}\n' > main.c
clang main.c -O2 -o hello
./hello
# C++：clang++ main.cpp -std=c++17 -O2 -o hello-cxx
# .so：clang -shared -fPIC main.c -Wl,-z,max-page-size=16384 -o libdemo.so
# 静态库：clang -c main.c -o main.o && llvm-ar rcs libdemo.a main.o
```

上述 `aijs-toolchain` 是新增入口，dev-1305 尚未提供；不能在旧版把示例失败当作编译环境已经装好。

MCP 安装示例：

```json
{"name":"terminal_exec","arguments":{"backend":"app","command":"aijs-toolchain install cpp --manifest http://192.168.10.7:8080/toolchains/cpp-arm64-v1.json","timeoutSeconds":1800}}
```

持续使用 terminal_read 和 nextOffset 读取进度，直到 processActive=false、status=SUCCEEDED、exitCode=0。安装后新任务自动设置 PATH/CC/CXX；同一条命令的 install 成功后也刷新 PATH。get_build_tools 的 optionalComponents 返回组件状态。卸载前先结束使用组件的任务，再执行 `aijs-toolchain remove cpp`，项目源码保存在组件目录外。

## 安装流程

清单显式给出版本/ABI/minSdk、ZIP URL、SHA-256、下载/展开大小及可执行文件名单。HTTP(S) 下载在独立 app_process 中运行，沿用终端任务的超时/停止和进程组清理。流式下载与解压，限制大小/路径/条目数；跨进程安装锁、版本目录与原子激活指针，失败保留先前版本。只设置清单指定文件的执行位，不执行解压出的安装脚本。

状态和普通终端启动应读取激活快照，不等待大型下载；中断后的暂存数据在下一次安装时清理。Android 真实大小写头文件必须保留，Windows 上仍拒绝实际路径碰撞。

## 边界

- 当前基础组件：ARM64、Android9/API28+ 主机，默认生成 Android API26+ ARM64 产物。C++ 默认静态链接 libc++；复杂工程可按需配置其他链接参数。
- 不包含其他 ABI、CMake/Ninja、JDK/Java 源码编译、完整 Android APK 工程构建或调试器。
- 共享存储通常不能直接执行 ELF，产物放应用私有目录；Shizuku 身份通常不能访问该私有环境，编译选择 app 后端。
- Android target29+ 对可写私有目录执行有约束；本次检测并报告限制，不降低 targetSdk。真实 Android17/16KB 系统仍需实机验证。[Android 执行限制](https://developer.android.com/about/versions/10/behavior-changes-10#execute-permission)
- 主应用内置终端/MCP 的环境不自动注入 Node child_process，也不代表独立打包 APK 获得完整 C/C++ 工具链。
