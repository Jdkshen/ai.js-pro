# 象棋 UI 与启动流程优化（0.6.28）

## 改动

- 主页面按钮统一高度、圆角、间距与配色；固定状态卡和停止入口。操作引导为「打开游戏棋盘 → 打开悬浮窗 → 选模式后开始」。悬浮窗状态从高级区移到顶部。
- 页面打开面板时先显示「正在打开」，收到同一目录新实例的就绪心跳后才显示成功；防止重复点击创建窗口。支持通过总线关闭其他入口打开的面板。
- 「识别局面」原先读取隐藏的图片路径并把同一张图复制三遍，现改为高级区的「多图验证」，要求至少两张截图；快捷工具加入打开游戏。
- 悬浮窗提高按钮行高度，拓宽哈希/避和数值区域，提高浅色背景上的状态文字对比度；展开和收起条使用一致状态。上屏保留操作说明，源码路径、心跳实现等取证信息写完整日志。
- 红黑方可以在开始前选择并保存，驱动创建时应用；主页面与面板同步。修正 advice 模式的短名称。
- 准备阶段显示当前步骤，主操作变成「取消」；失败显示原因和「重试」。停止同时作废排队步骤，解决旧流程被停止后又设回 running 的竞态。
- 「只识别」明确只观察，不进入算棋/点击分支；跳过 Pikafish 预热。建议/自动模式仍检查引擎，自动模式保留前台检查与落子校验。

## 启动与耗时

`start-flow.js` 将启动拆为：抢循环锁 → 切回游戏 → 定位 → 检查/建驱动 → 按需预热 → 开始观察。步骤之间让出 40ms 事件循环，取消令牌贯穿启动和定位候选搜索。第一轮观察等待从 1400ms 改为 60ms，后续观察频率不变。

原始定位结果仅在「无未知格、无棋规修复、双方帅将齐全、独立圆心覆盖满足条件」时允许跳过粗扫；后续几何校验仍保留。快速启动定位预算为 8 秒，手动「定位校准」为 30 秒。预算在候选之间检查，单次原生调用不能被 JS 强行打断；超时不发布未完成搜索的候选。

K40 / dev-705 脚本测试（本地完整工程，通过独立 QA 目录与参数存储隔离）：

| 项目 | 观测 |
| --- | --- |
| 旧面板入口至就绪 | 525ms、594ms |
| 新面板入口至就绪 | 459ms、481ms、493ms |
| 新开始按钮返回 | 21ms；这只是响应耗时，并非完成定位 |
| 当前残局定位失败 | 约 8.5s 结束本次准备，保留失败原因 |
| 真机停止 | 收起条点开始后再停止，心跳为 running=false、starting=false |

这些是少量现场观测，不是不同设备的性能保证。当前这张残局在线定位/字形识别仍失败，本轮没有将它标记为「自动走棋已修好」，也未进行自动落子验收。固定 9 图评测保持 806/809（99.6%，未知 2、错误 1）。

| 主页面布局、按钮间距 | `src/ui/page-layout.js` |

| 定位预算与几何验证 | `src/app/panel/calibration.js`、`src/vision/grid-calibration.js` |

视图更新通过 `setPanelText(key, view, text)`；相同视图与相同文字不重复跨 JS/Java 桥。替换视图会重新写入。参数控件也用同一个方法。

新增启动步骤要放入步骤表，不直接堆进按钮回调；执行后再次验证取消令牌。异常统一停止会话、清计时器并释放循环锁。勿为启动速度跳过几何、轮次或落子确认。
