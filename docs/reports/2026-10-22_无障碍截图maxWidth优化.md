## 1. 实现（多任务 226/227/228）

- **B 透传（task-226）**：`accessibility.takeScreenshot({maxWidth,maxHeight})` → prelude 请求字段 → `Node24AutomationBridge.handle` 读取/clamp（0=全分辨率，上限 16384）→ `readScreenshotPixels(backend,w,h)` → `screenshotPixels(w,h,format)`；无参旧调用仍发 0,0。
- **A 缩略回读 + 打点（task-227）**：`HardwareFrame.toBitmap(maxWidth,maxHeight)` 先尝试 `Canvas.drawBitmap(hardware→software)` 缩略；`AccessibilityScreenCapturer.capture(timeout,maxW,maxH)`；`AutomationHostService.screenshotPixels` 正常路径不再 `createScaledBitmap`；新增 `A11Y_SPLIT` 日志（request/readback/scale/host capture），纯 JVM `scaleSize` 单测 8 例。Canvas 不支持 HARDWARE 源时自动回退「全屏 copy + createScaledBitmap」，保证功能不丢。
- **E buffer 复用（task-228）**：`Node24Images` 的 Raw 读取改为 single-slot direct ByteBuffer（≤32MB，`clear()+limit()` 复用，`close()` 释放，超大帧不缓存），新增 5 个纯 JVM 用例；不改变 header/预算/注册行为。

## 2. 真机结果（dev-1208，同一次脚本先全屏后 640 宽）

| 模式 | 尺寸 | n | p50 | p95 | failures |
|---|---|---|---|---|---|
| 全屏（无 options） | 1080×2160 | 20 | **239 ms** | 328 ms | 0 |
| `{maxWidth:640}` | 640×1280 | 20 | **181 ms** | 196 ms | 0 |

- 同一次运行内 640 宽 p50 比全屏低约 **24%**，尺寸确认 640×1280；
- 注意：本轮全屏 p50(239) 高于 dev-1207 报告(122)，是设备状态/热负载差异，不能直接当作回归结论；A/B 以同一轮对比为准。

## 3. A11Y_SPLIT 分段（logcat 实测）

- 全屏：request=18~41ms，readback=17~45ms，host capture=37~97ms；Node 观测到的总耗时还包含管道写/读 + `readRawStream` + Bitmap 注册，约占 100~170ms（这是真正大头）；
- 640 宽：request=23~51ms，readback=45~67ms（含 **Canvas 缩略失败后的全屏 copy**），host capture=79~113ms（含 createScaledBitmap 约 30~45ms），随后管道/解码约 70~90ms；
- **关键发现：小米 8 上 `Canvas.drawBitmap(HARDWARE→software)` 全部抛 `IllegalArgumentException: Software rendering doesn't support hardware bitmaps`**，因此「缩略回读」退化成「全屏 copy + CPU 缩放」。传输/解码字节从 8.9MB 降到 3.3MB 带来的收益是真实的（-24%），但理想中的「GPU 缩放后只回读 3.3MB」未实现。

## 4. 结论与下一步

- B（参数透传）已打通，A 已落地但受 HARDWARE→software Canvas 限制；脚本侧降采样（`capture.js` 的 accessibilityOptions）现在可以直接传 `maxWidth` 让宿主少传像素；
- `.4` 目标机需要在 1208 上复测（尤其看 `A11Y_SPLIT` 是否仍全部 fallback）；
- 若 `.4` 也 fallback，下一档优化按规格 §3：C（只回读棋盘 ROI）或 D（SharedMemory 省一次管道拷贝），或评估「硬件缩放后再回读」的 API 组合；
- 注意：设置 `maxWidth` 后返回图是缩放图，坐标/模板比例需按返回尺寸换算；Phase A `.n24r`/PNG 回退仍是全分辨率（脚本需兼容）。
