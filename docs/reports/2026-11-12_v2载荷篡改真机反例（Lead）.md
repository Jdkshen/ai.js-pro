## 一、实验结果（照实，含失败之处）

**单因素实验（只改载荷、保持证书）—— 不可构造** ✗
- 需要「用原产物的证书 `f08d88e8…` 重新签名」⇒ 必须有该私钥；
- 实测：`autojs.keystore`（在 `apps/*/build/intermediates/.../assets/` 下，2062 B）常见密码全部打不开；
  `apps/app/build.gradle:7-9` 显示正式签名走环境变量 `AIJSPRO_STORE_PASSWORD / AIJSPRO_KEY_ALIAS / AIJSPRO_KEY_PASSWORD`，本机未设；
- ⇒ **拿不到原证书私钥 ⇒ 无法在保持证书不变的前提下重签** ✗。

**双因素实验（改载荷 + 换证书）—— 跑通了，但**结论受限** ✗**
- 做法：用 python `zipfile` 重写 APK，把 `assets/project/main.js`（5,031 B）**偏移 30** 的字节 `0x42 → 0xBD` 翻转；
  实测载荷头 `7701177f1212010002000000f7ddf0ae…`（→ v2 格式：8B 魔数 + 1B 版本 `0x02` + 3B 保留 + 12B IV = 24B 头，故 30 落在**密文区** ✓）；
  再用 debug keystore 重签（证书 `f08d88e8… → 38166a4b…` ✓），装到 K40 启动；
- **结果**：脚本**没跑** ✓（`/sdcard/脚本/v2-acceptance-result.txt` 不存在 ✓）、无崩溃 ✓；
- **屏幕（LogActivity）逐字**：
  ```
  18:26:00.769/W: 脚本无法启动：密钥初始化失败（可能是签名证书/包名/加密盐与产物不一致）。
                  请用与当前安装包一致的证书重新打包。原因：java.lang.ExceptionInInitializerError
  ```
- ⇒ **结论受限** ✗：因为证书也变了 ⇒ **密钥派生先失败**（`initKey`）⇒ 根本**没走到 GCM 解密** ⇒ 这条证据只能证明「篡改绝不静默成功」，**不能**单独证明「真机在验 tag」✗。
