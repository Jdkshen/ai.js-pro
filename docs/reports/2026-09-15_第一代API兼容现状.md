# 第一代 Pro API 兼容现状

检查日期：2026-09-15。目标：用户提供的 335 页第一代 Rhino API PDF。

> 后续：[第一代 API 逐函数对照](../architecture/第一代API逐函数对照.md) 已把本报告描述的“逐函数清单尚未建立”补齐 —— 938 条条目、逐条带证据路径，并与本文的引擎结论一致。本文保留为对照前的人工结论。

## 结论

常用自动化能力已有较多实现和历史实机记录；尚未完成 PDF 全量逐函数对照。Rhino 更适合原版第一代脚本，QuickJS 已有较广的常用接口覆盖，但特殊语义仍存在缺口。使用 Rhino 不等于自动获得全部 Pro 增量功能。当前不能给出可信兼容百分比。

本次检查源码、初始化模块及历史记录，未重跑完整实机回归、未修改运行时代码、未发布更新包。

## 按引擎判断

| 能力 | Rhino | QuickJS | 证据和限制 |
| --- | --- | --- | --- |
| 文件/存储/应用/设备/日志/对话框/HTTP | 已有实现与部分历史基础回归 | 已有实现与历史实机回归 | 不等于每个重载、异常和权限路径已对齐 |
| 选择器/UiObject/坐标手势 | 原有 Android 宿主实现 | 历史记录覆盖选择器、谓词和真实手势 | 需要服务连接；注入成功不保证目标游戏接收 |
| Java 类型/反射/Bean/数组/接口 | Rhino 原生互操作基础 | 已有反射桥与历史用例 | 复杂接口、转换、异常仍应对照 |
| XML/E4X 与 UI | 原版脚本的主要兼容入口 | 已有 UI 控件代理及 Activity 接入；特殊语法仍需核查 | 旧矩阵“仅 overlay”已过时；不能据 Activity 接入判定所有 UI 已兼容 |
| JavaAdapter 任意继承 | 有 Rhino 动态适配机制 | 部分支持 | 当前宿主仅适配 WebViewClient/WebChromeClient；未覆盖 PDF 自定义 View/onDraw、多接口和构造参数全部语义 |
| 多线程/事件/计时器 | 有原有线程与闭包机制 | worker/事件已有历史验证 | 共享闭包、锁、原子变量、退出顺序不能由 worker 通过推导为全对齐 |
| 悬浮窗/图像/OpenCV | 已有实现 | 已有实现和多批历史用例 | 合成图用例不能证明真实截图授权/录屏并用已验收 |
| crypto/压缩 | 初始化暴露 runtime.crypto/runtime.zips 及 $crypto/$zips | 有 crypto 摘要/HMAC/base64 与 zips 压缩接口 | PDF 的 $crypto 密钥/加解密和 $zip 密码/AES/选项不能由基础往返测试代替；$zips 不等于 $zip |
| $work_manager | App 已注入，支持一次/每日/每周/广播、查询/删除等 | 未在 QuickJS bootstrap 中确认直接注入 | Rhino 参数解析包含 Scriptable；后台、重启、打包行为未做本次对照 |
| $plugins | 有加载器和 JS 胶水路径 | 未确认完整迁移 | 加载器传入 TopLevelScope；现有插件不能宣称全部支持，也未证实 Pro 9.2 合并打包完整兼容 |
| $ocr/$settings/$power_manager/$debug、独立 base64、Pro WebSocket | 本次未确认完整对应模块入口 | 本次未确认完整对应模块入口 | 平台底层能力或 Java 手动调用不等于 PDF 接口可原样运行；需逐项补查 |
| continuation/Promise.await | 有原有模块机制 | 明确不支持 create/await/Promise.await | bootstrap 明确抛错；“报错路径测过”不等于特性兼容 |
| WebView 同步求值 | 原有 web 入口 | inject 回调可用，injectAndWait 明确不支持 | 同步返回/异步回调存在差异 |

## 历史证据要如何理解

`docs/architecture/QUICKJS_MIGRATION_MATRIX.md` 更新于 2026-09-11，记录 Mi8 228 项 QuickJS 回归和 K40 23 项 Rhino 基础回归。这是项目场景测试数，不是 PDF API 数，也不是本次复测结果。

`.artifacts/engine-api/engine-api-diff.json` 是 2026-09-11 的顶层成员探测：公共名字数量仅说明当时暴露了接口，不能说明签名或行为一致。`module-probe.json` 的 images 枚举为空成员，不能用于推断图像模块无差异。

已有 `.artifacts/engine-test.log` 记录默认引擎相关单测失败；其时间/代码状态需重跑确认，不能宣称当前整套引擎测试全绿。

## 关键源码

- `modules/engine/src/main/assets/init.js`：Rhino 模块初始化、$ 别名和 work_manager 注入。
- `modules/engine/src/main/java/com/stardust/autojs/engine/QuickJsHostBridge.java`：UI Activity 接入及受限 JavaAdapter。
- `modules/engine/src/main/cpp/quickjs_jni.cpp`：QuickJS crypto/zips、模块表、JavaAdapter 和明确不支持接口。
- `apps/app/src/main/java/com/jdkshen/aijspro/autojs/api/timing/WorkManagerModule.kt`：第一代定时任务实现及参数转换。
- `modules/engine/src/main/java/com/stardust/autojs/runtime/api/Plugins.java`：插件加载和 scope 传入。

## 建议下一步

1. 第一代原版脚本优先使用含 Rhino 的 compat 构建，保留 QuickJS 选项。
2. 建立 PDF 逐函数清单，优先查 $crypto/$zip 精确接口、$work_manager 跨引擎入口，以及 $ocr/$settings/$power_manager/$debug/WebSocket。
3. 补齐或明确 JavaAdapter、XML/动态绑定、共享闭包线程、同步 WebView 与插件差异。
4. 用明确版本的 Pro 同脚本对照返回值、异常、事件顺序、权限和释放；按引擎分别标记结果。

详细模块页码及路线见 [第一代 API 与 V8 选型](../architecture/Auto.jsPro_API兼容性与V8选型.md)。当前目标无需 V8。
