# 编辑器剪贴板/长按选择链路修复（DP）

- 日期：2026-10-25
- 任务：AI.js Pro 编程器复制/剪切/粘贴与长按选择菜单
- 范围：`ProCodeEditorActivity` 的剪贴板/菜单/ActionMode、`AceCodeEditor`、`AceEditorHost`、`editor.js`、`androidTouch.js`、新增编辑器本地剪贴板桥
- 约束：未运行 Gradle，未启动浏览器/设备，未安装 APK，未发布，未提交；未修改运行/停止/调试方法

## 结论

已按“真实 Android ClipboardManager + Ace 当前选区 + 原生 ActionMode”重做编辑器剪贴板链路：

- 工具栏“编辑”新增剪切、粘贴；复制子菜单新增剪切选中、全选、复制全部、复制行
- 长按/拖动选择手柄后由 `androidTouch.js` 调用 `EditorBridge.startActionMode`，由 Activity 弹出原生浮动菜单：复制、剪切、粘贴、全选
- 复制/剪切不再读 Java 侧异步快照，而是动作触发时在 JS 中读取 Ace 当前选区，并**同步**写入 Android 系统剪贴板
- 剪切只有剪贴板写入成功后才删除选区；空选区、空行、空剪贴板、无文本剪贴板、剪贴板读取异常均有明确提示且不修改文本
- 粘贴读取系统剪贴板；空剪贴板提示“剪贴板为空”，不会插入空内容
- 键盘输入、IME、Ace 自带 textarea 的复制/粘贴路径未改动

## 根因

1. **长按菜单根本没有接到原生层**
   - `apps/app/src/main/assets/editor/ace/androidTouch.js` 原来只查找旧版 `autojs` JS 接口：
     `const native=typeof autojs!=='undefined'?autojs:null`。
   - 当前 `AceEditorHost` 注入的是 `EditorBridge`，不是 `autojs`，所以 `native` 恒为 `null`，`startActionMode()` 不会调用任何原生方法。
   - `editor.js` 又把缺失的 `startActionMode/finishActionMode` 补成 no-op，于是长按只选中单词，菜单永远不出现。

2. **工具栏复制路径使用异步 Java 快照，存在选中区被“吞掉”的窗口**
   - 原 `ProCodeEditorActivity.copySelection()` 先 `editor.withSnapshot(...)`，再在回调里取 `editor.getText().substring(getSelectionStart(), getSelectionEnd())`。
   - 菜单/焦点/键盘变化与 JS 快照之间存在异步窗口，选中范围可能已变化，是“菜单看似成功但复制为空/复制错内容”的直接风险。
   - `copyAll` 直接使用 Java 侧 `getText()` 快照；`copyLine` 走 `EditorBridge.copied` 后由 UI 线程再写剪贴板，均没有同步结果。

3. **没有剪切/粘贴的原生桥**
   - 原 `AceEditorHost` 只有 `copied(String)`，没有从 Android `ClipboardManager` 读回文本的接口，也没有 ActionMode。
   - 工具栏编辑菜单只有“复制”，没有“剪切/粘贴/全选”。

4. **空值语义缺失**
   - 原复制路径没有统一的空选区/空行/空剪贴板处理，菜单关闭或焦点变化后容易只得到一个空字符串。
   - 原剪贴板读取只依赖 `ClipboardUtil.getClip`，没有可区分的 JSON 结果，粘贴无法确认“没有文本”还是“读取失败”。

## 修复内容

### 1. 新增真实 ClipboardManager helper

新增 `apps/app/src/main/java/com/jdkshen/aijspro/ui/editor/EditorClipboard.java`：

- `write(Context, CharSequence)`：`ClipboardManager.setPrimaryClip(ClipData.newPlainText("AI.js Pro", text))`，写后立即读取校验，返回 `ok/empty/failed`
- `readJson(Context)`：用 `getPrimaryClip()`/`getItemAt(0).getText()` 读取文本，返回 `{"ok":true,"text":...}` 或 `{"ok":false,"reason":"empty|unavailable|error"}`
- 空字符串、null、空剪贴板、无文本 item 都不会被当作可粘贴内容
- 捕获 `RuntimeException`（含权限/OEM 异常）并转为可展示的失败原因
- 辅助纯函数 `hasText`/`pastedText` 供离线 JVM 验证

### 2. 新增编辑器本地剪贴板 JS 桥

新增 `apps/app/src/main/assets/editor/ace/editorClipboard.js`，由 `editor.html` 在 `editor.js` 之前加载：

- `copySelection`：读取 `editor.getSelectedText()`；空选区提示“请先选中内容”，不覆盖原剪贴板
- `cutSelection`：先同步写剪贴板；只有写入 `ok` 才 `session.remove(selectionRange)`；写入失败不删除文本
- `copyAll`：读取当前 session 的实时 `getValue()`；空文档不覆盖原剪贴板
- `copyLine`：读取当前行；空行提示且不覆盖原剪贴板
- `paste`：读取系统剪贴板 JSON；空/无文本/读取失败均不插入；非空才 `editor.insert(text)`
- `selectAll`：调用 Ace `selectAll`
- 剪切、粘贴、全选后恢复编辑器焦点并请求键盘，避免工具栏菜单隐藏键盘后无法继续输入
- 复制/剪切只使用 JS 当前选区，不再先清空选区或读取 Java 侧旧快照

### 3. 长按/选择手柄接入原生 ActionMode

`androidTouch.js`：

- 优先使用 `window.EditorBridge`，保留旧 `autojs` 作为 fallback
- 仅当 `selected=true` 时打开原生菜单；普通轻点（无选区）不再弹出粘贴/全选工具条
- 选区清空时调用 `EditorBridge.finishActionMode`
- 延迟的 `startActionModeIfSelectionInView` 仍然保留，拖动选择手柄后能弹出菜单

`AceEditorHost.Bridge`：

- 新增同步 `copyToClipboard(String)`、`readClipboard()`
- 新增 `showMessage(String)`（主线程 Toast）
- 新增 `startActionMode(...)`、`finishActionMode()`；原生 ActionMode 的启动/结束切回主线程，且只对当前 active owner 生效
- 删除旧的异步 `copied(String)` 路径

`ProCodeEditorActivity`：

- 实现 `ActionMode.Callback`
- `TYPE_FLOATING` 浮动菜单（API 23+；API 21/22 走默认类型）
- 菜单项：复制、剪切、粘贴、全选
- 回调方法加 `@Keep`，避免 R8 重命名框架回调
- 切换 Tab、Activity 销毁时结束 ActionMode；系统返回键/点击外部关闭时通知 JS 清空 `editor.actionMode`
- 不读取 Java 快照：菜单点击只调用 `AceCodeEditor` 的 JS 动作

### 4. 工具栏菜单

`ProCodeEditorActivity.showEditMenu` 现在为：

- 查找/替换
- 跳转
- 复制（复制选中/剪切选中/全选/复制全部/复制行）
- 剪切（直接剪切选中）
- 粘贴
- 删除
- 移动
- 折叠
- 格式化代码

原“复制全部”不再使用 Java 快照；全部改为 JS 实时读取。
