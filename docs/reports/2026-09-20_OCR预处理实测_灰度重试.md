# OCR 前先处理一下图？—— 真机实测：只用「灰度当重试」

> 2026-09-20，K40（`cccc62c7`），用户提问：「给 OCR 识别的时候处理一下颜色再给 OCR 识别？会不会更好一点」
> 探针：`apps/app/src/main/assets/sample/QuickJS 新引擎/项目与打包/象棋自动走棋/tools/ocr-prep-probe.js`
> （报告与裁剪图落 `/sdcard/xiangqi-p4/ocr-prep/<时间戳>/`，日志前缀 `[ocrprep]`）

## 1. 为什么要做这批实验

前一轮已经量到：**红帅那一格 OCR 读不出来**（真机 44ms 也认不出），靠 YOLO 定位 + 九宫 + 找色才抢救回来。
猜想是「红墨迹 `#83412D` vs 木纹背景在灰度下对比度不足」⇒ 那么**把颜色处理一下再喂 OCR** 应该更好。

不猜，直接测：同一帧、同一 OCR 会话（`$ocr.create({backend:"ppocr"})`）、同样的框心 0.70 裁剪区，
唯一变量就是**那一步预处理**。

## 4. 结论

1. **二值化（Otsu 各档）整体更差**：木纹背景被切成斑块、笔画被切断 ⇒ 识字掉到 3~12/20（「分数高」是因为它只在少数格子上有输出）。
   **放大（2×/3×）不加分还更慢**（det 阶段本来就会把长边归一到 `targetSize`）；`inRange` 这条路上基本无效。
2. **灰度**：识字数与现状持平，平均分略高、每格快 ~8ms；而且**在认不出的格子上能救回字形** ——
   红帅那格彩色读出垃圾「印市」0.49，**灰度读出「師」0.70**（「帥」只差一撇）。
3. 但灰度**也会把原本读对的格读错**：馬 1.00 → 志 0.67、兵 0.80 → 民 0.39、馬 1.00 → 空。
   ⇒ 灰度**不能当默认通道**，只能当「**彩色读不出时的重试**」。
4. **`clip`（只裁剪、不处理）与现状逐格完全一致**（两帧都是文字/分数一字不差），
   每格却省 6~8ms（少拷 ~10MB 的 1080×2400 RGBA）⇒ **已落到 `board-scan` 第一遍**
（越界/无能力时自动回退到「整帧 + region」）。⚠️ 面板日志里的「全盘 OCR 用时」不能拿来证明它 ——
   那句包含实时抓帧与并发驱动的影响（同一天量到 2767ms / 3311ms，差的是帧与负载），**受控对比只能看探针**。

## 5. 落地（改了什么）

1. **`piece-ocr.js`**：字形表收「師」→ `K`（U+5E2B）。理由写在表里：棋盘字形集合里没有「師」这个字，
   能把「師」认错的东西实际上只能是「帥」；这与已有的「兵→宾」「士→H」是同一类系统性误读。
2. **`aijs-adapter.js`** 新增两个能力（业务模块不直接碰 `images`）：
   - `prepareRegion(image, region, mode)` → 帧（`clip` / `gray`；越界或没能力时返回 `null`）
   - `releaseFrame(frame)`（原生帧不会 GC，用完必须还）
3. **`board-scan.js`**：
   - 第一遍改成**先 `clip` 再送 OCR**（等价、每格省 6~8ms）；`prepareRegion` 返回 null 时回退老路径；临时帧即时 `releasePrepared`。
   - 新增 `retryGray`（默认开）——只在
     ① 彩色那遍**没拿到可用字形**、② 宿主有 `prepareRegion`、③ **这格确实有墨迹**（找色有结论）时才重试灰度；
     救回的格子计数 `grayRetries/grayHits/grayChars`。第 ③ 条闸门是关键：空格子/假框直接跳过，不然每格白花 ~25ms。
4. **接线**：`vision-pipeline` 的帅/将抢救字形路 + 面板 `ocrBoard()` 都注入 `prepareRegion/releaseFrame`；
   `ocrBoardCache` 带 `grayHits/grayRetries`，日志 `全盘 OCR：灰度重试救回 N 格（彩色读不出，共试 M 次）`。
5. **自检 194 → 198**：灰度重试正例（含「临时帧必须释放」「空位不许重试」）、`retryGray=false`/无能力时不重试、
   字形表「帥/帅/師 归 K；飾/师 不认」、第一遍先裁剪（越界时回退「整帧+region」）。

## 5. 真机取证（K40，改动后）

```
全盘 OCR：灰度重试救回 3 格（彩色读不出，共试 5 次）
全盘 OCR 对照（读到 23 格有字，用时 2767ms）        ← 改前同样一帧是 20 格
帅/将抢救：(4,7) = K（YOLO 框类别当候选 + 九宫 + 找色颜色） —— 整帧不必退回旧路径
视觉流水线：规则门 通过｜确认 20／未定 5｜OCR 成功 28／缓存 24／框字形打架 4／补全 0
```

一次全盘扫描多 5 次 OCR（≈125ms，占该次 2767ms 的 4.5%），换回 3 个字形的证据。
