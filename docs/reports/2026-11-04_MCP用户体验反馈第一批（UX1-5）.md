## 一、逐条落地

| 用户痛点 | 实现 | 入口 |
|---|---|---|
| §2.1 后端能力分界不明确（2 次，各 5+ 分钟） | `ToolkitBackendRouting`：识别命令需要 app / shizuku，用错后端时输出首行写明「该命令需要 X 后端」并保留原始输出；可选 `autoRoute` 仅对只读白名单自动切换并标注 routedFrom/routedTo | `terminal_exec`（新增 `autoRoute` 参数 + 描述里的能力矩阵） |
| §2.2 无常驻 native 分析会话（N 次，每次约 30 秒） | `ToolkitR2Session`：r2 project 保存/加载，**一次 aaa 分析、多次查询**，默认 `e bin.relocs.apply=true`；输入哈希变化失效、命令禁止 `!` 逃逸、输出有界 | `native_session_open/plan/query/close/list`（5 个） |
| §2.3 raw 反汇编看不到重定位（白跑一轮） | `ToolkitDisasmEvidence`：pdf/pdfj/axtj 明确标注「默认不解析重定位、0 命中不是结论」，给出 `e bin.relocs.apply=true` 加固命令与 pdf↔pdg 能力差异；接线后在 `aaa` **之前**注入 | `native_function_detail`/`native_xrefs` 新增 `relocsApply`；`native_decompile`/xrefs 返回值带 `disasmKind/relocAware/evidenceLevel/hardeningCommands` |
| §2.4 shell 环境能力未知（≥5 次） | `ToolkitShellCapabilities.matrix()`：busybox 风格清单（grep 无 \b/\s、cat 无 -n/-A、无 zip/jar/7z 只有 tar、python 链接坏、node 可用）并逐条给替代写法 | `shell_capabilities`、`shell_classify_failure` |
| §2.5 node 内联脚本易被转义破坏（3 次） | `nodeScriptCommand()`：推荐「写脚本文件再运行」，给出安全引号命令与 argv 语义（0=node、1=脚本、2=第一个参数），明确别用 `node -e` 传复杂脚本 | `node_script_command` |
| §2.6 崩溃缓冲清理语义不明 | `crashBufferSemantics()`：只清 crash ring buffer、不是同步屏障、旧条目可能仍被读到；给可核对的时间窗/PID 过滤步骤，SIGKILL/旧时间戳/非目标 PID 不算新崩溃 | `crash_buffer_semantics` |
| §2.7 路径一致性（外部重组后旧脚本集体失效） | `McpRootStability`：进程内记录 root 首次/变化与时刻，root 变了就明确提示旧绝对路径可能失效 | `get_status.rootStability` |

规模：公开入口 **205**（经典 196 + 9 兼容别名）；逆向工具 38；terminal 分类含 4 个新辅助工具。

## 三、测试与构建

## 四、未做 / 边界

1. **autoRoute 只覆盖只读白名单**（logcat -d / pm list / dumpsys / settings get / am get-* 等）；写操作一律只提示、不自动切换，避免静默改变副作用。
2. **`routedFrom/routedTo` 目前只在输出首行**；要变成结构化字段需要扩展 `McpTerminalJobs`（本轮未动）。
3. **r2 会话元数据不跨进程持久化**：project 文件在磁盘，但会话列表在内存，工具进程重启后需重新 open（project 仍在，可用于重新加载）。
4. **会话查询超时**：大库的首次 `aaa` 仍可能超过 60s；本轮不加自动预算推断，调用方应显式给 `timeoutSeconds`（≤300）或先用小批量。
5. **shell 能力清单是用户 busybox 实测基线**，不是真机动态探测；不同 ROM 可能不同。
6. `classifyFailure` 是保守文本启发式：无法判断时返回 `unknown` 且 `capabilityGap=false`，不猜。
