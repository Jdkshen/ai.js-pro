## 本轮修改

| 部分 | 当前结果 | 保留的同步路径 |
| --- | --- | --- |
| 算棋 | 一个常驻 QuickJS Worker，搜索、预判、预思考共用；重建驱动时复用 | 显式 inline 或宿主无消息通道时 |
| 截图、稳定帧、识别 | 沿用 0.6.62 的常驻视觉 Worker | 启动定位、重新定位、校准、点击前复查、走后确认；窗口后台采集不可用时降级 |
| 日志、诊断 | 独立常驻 IO Worker，批量保存日志、探针及绘制诊断 JSON | 诊断 PNG、配置/互锁小文件、视觉文件 IPC；没有消息通道、尚未握手就退出的文本兜底 |
| ImGui | 沿用原生绘制、拖动线程 | 无新增修改 |

生产代码新增 `runtime/task-worker.js`、`task-service.js`、`io-queue.js`、`io-task.js` 和 `automation/search-task.js`。`automation/search-worker.js` 改为常驻通道客户端。`game-session` 保留搜索通道，配置改变导致驱动重建时不会再创建第二个搜索 Worker。

每个通道通过 `events.bus` 传 JSON 内存消息，启动握手后才发送任务，每次仅发送一个尚未确认的任务。队列最多 64 项、4 Mi 字符 JSON 文本。独立通道名和递增任务编号隔离结果；取消作废结果，旧 JNI 搜索自然收尾后才开始下一任务。超时后的通道停止接受任务，返回失败，不启动同步搜索与旧 JNI 重叠。

IO 写入按序执行；关闭时发送一个有界批次，Worker 即使在父脚本退出后仍能排空。重复任务编号重发确认，不重复追加日志。正常日志仍按 20 行或 2 秒批量提交，原 8 MiB 上限保留。停止时及心跳中补齐尾部刷新。

实机测试发现当前 QuickJS 的显式 `exit()` 没有触发本地 `events.on("exit")`。面板现对该引擎的 `exit()` 增加幂等清理：先关闭业务和任务通道、提交最终日志、关闭视觉资源与窗口，再调用原宿主退出。外部强制终止或进程被杀仍无法保证执行脚本清理；子 Worker 在失去心跳后协作退出。
