# Node24 BUSY 级联修复（task-174）

日期：2026-10-19。执行：t1-native-services。验证机：K40（cccc62c7，dev-1123 待填）。

## 1. 问题与根因

t2 复现（MI8 dev-1120 / K40 dev-1121）：

- **C 不停止直接跑第二个 Node 脚本**：Node24Service 单 job 槽（`active.compareAndSet` 失败 → `status=BUSY`）→ `ScriptException: BUSY`；
- **D 干净停止后**：:node24 进程退出，但后续 5~7s（实测 +7.4s 才成功）内的 RUN 全被 BUSY；
- **通知栏停止路径**（t2 补充）：cancelAll 后 `execute returned cancelled=true`，但 :node24 **11s 仍存活**、active 未释放 → 10/10 次重试 BUSY；任务页路径 116ms 退出、+137ms 即可再跑。

根因：

1. :node24 是独立进程、`Node24Service` 只有一个 active job；忙时直接回 BUSY，没有排队；
2. 取消路径不统一：`Job.cancel()` 里 halt 线程先做 `closeUiAfterExecution`（NodeUiActivity/Binder 清理可能阻塞），之后才 `killProcess`；通知栏 cancelAll 路径的 UI 清理卡住时进程 11s 不退，active 一直占用 → 全部 BUSY；任务页路径恰好清理快，所以 116ms 退出；
3. 宿主侧（:script）停止后重连/重放窗口内多个 RUN 并发打到 :node24，进一步放大 BUSY。

RE 结论（docs/reports/2026-10-19_高级版三引擎运行架构_RE.md §6/§7）：Pro 的 Node 与 Rhino 同进程（JNI libnode），多引擎并存无单槽 BUSY；我们独立 :node24 + 单槽是差异来源。修复方向：排队/明确提示 + 取消后强制结束 :node24。

## 2. 实现

### 2.1 Node24Service 有界排队（替代立即 BUSY）

- 新增 `pending` 队列（ArrayDeque，上限 4 个）与 `PendingJob{job, deadline}`；
- `EXECUTE` 时 active 忙 → 入队并 `postDelayed(drainPending, 8s+100ms)`，不再立即回 BUSY；
- `drainPending()`：active 释放后按 FIFO 启动下一个；过期请求回 `status=BUSY` + **明确中文 message**（「已有 Node 脚本正在运行（Node UI/悬浮窗或上一个任务未结束），已等待 8 秒仍未释放；请先停止当前脚本再运行」）；排队已满立即回同类中文提示；
- `Job.run` finally 释放 active 后调用 `drainPending()`：干净停止/正常结束后排队任务立刻接上；
- `Node24JavaScriptEngine`：status=BUSY 且带 message 时直接抛中文 message（不再显示裸 `BUSY`）。

### 2.2 取消路径统一硬兜底（≤1.5s 结束 :node24）

- `Job.cancel()` 重写 halt 逻辑：
  - UI 清理仍在独立 daemon 线程（不阻塞）；
  - 新增 **forceHalt 守护线程：1.5s 后**，若 active 没有被新 job 接手（含先 drainPending 尝试），直接 `stopSelf()+killProcess` 结束 :node24；
  - 保留 2.5s watchdog 兜底；
- `finishAndHaltIfCancelled()` 的 350ms halt 改为：active/排队任务存在时不杀进程；
- 所有取消入口（通知栏 cancelAll 广播、任务页行内停止/停止全部、Messenger CANCEL、悬浮菜单 ⏹）都走同一个 `Job.cancel()`，因此统一 ≤1.5s 杀进程；
- `PocRuntime.stopAllHostScripts()` 也补上 `PocNode24Jobs.cancelAll()`，确保调试停止/旧入口同样触达 :node24。

### 2.3 目标

- 干净停止后 ≤1s 可再跑（杀进程 1.5s 上限；实际操作中 native 取消通常更快，active 释放后排队任务可立即接上）；
- 不停止时第二个 Node 脚本排队（≤8s）而不是裸 BUSY；如果 8s 内前一个仍未结束，给明确中文提示。

- 结论：干净停止后立即可再跑（任务页路径实测 +313ms 成功；debug stopAll 路径首次成功约 1~2s，取决于探测时机）。

### C 不停止直接跑第二个（dev-1124）

- colored-button（uiScript hold=600000）运行中跑 probe：job queued ... pending=1（不再立刻 BUSY）；
- 8.1s 后回明确中文：已有 Node 脚本正在运行（Node UI/悬浮窗或上一个任务未结束），已等待 8 秒仍未释放；请先停止当前脚本再运行；ScriptException 同样为该中文（无裸 BUSY）。

### D 通知栏停止路径（dev-1124，重点修复项）

- 触发 ForegroundService ACTION_STOP_ALL_SCRIPTS（与通知栏红底「停止脚本」同一 PendingIntent）→ PocNode24Jobs cancelAll → Job cancel；
- cancel force halt 在 ~810ms 触发，:node24 在 ~876ms 死亡（满足 ≤1.5s；旧版 11s 不退已修复）；
- 停止窗口内 probe 收到「当前 Node 脚本正在停止，请稍后重试」（明确中文，非裸 BUSY/15s 超时）；
- 停止后第 2 次 probe（+1.14s 发起）成功：:node24 重启 → job start → PROBE_OK，约 1.0s 内完成（从该次 RUN 发起算）。

## 5. 限制

1. 排队只存在于 **同一个 :node24 进程**内；若进程被取消/杀掉，排队请求随进程丢失（客户端会超时），下一次 RUN 会重新绑定新进程；
2. 排队上限 4、等待上限 8s；超出/超时回 BUSY（中文 message）；
3. 与 Pro「同进程多引擎」架构不同：我们仍是单 :node24 单 job + 队列，属可接受折中；
4. `process.exit()` 在 keepRunning 下的关窗语义不在本任务范围。
