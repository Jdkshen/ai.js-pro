# Node 内联 UI 与原生监听语义修复

日期：2026-11-01。发布基线：dev-1299。本轮继续高级版兼容总账 A03；没有把全部高级版 API 标为完成。

## 已核实的问题

MI8 的 dev-1299 上运行 `modules/engine/src/test/device/node24-ui-inline-events.js` 的初始 20 项用例，**12 项失败**。`ui.layout(XML)` 的根 View、`root.binding.name`、Android ID 和普通 click/off 实际可用；旧报告中“内联 binding 没有 viewId、on 不回调”的笼统结论已不成立。

真实问题在原生事件派发：`realViewMember` 同时向 `extras.events` 和另一份 handler 数组登记监听，而 Android 回调只遍历后者。后者既不保存 EventEmitter 的 once 包装器，也不保留 prepend 顺序、重复注册和统一移除语义。

确证表现：

- click/check/text_change 的 once 执行两次，一次性监听计数不归零；
- 相同函数重复注册被合并，移除一份与查询数量不一致；
- prepend/prependOnce 执行顺序错误；
- removeAllListeners 后，旧 handler 数组仍可能接收原生回调；
- once 内再次 performClick 时重复进入；手动 emit 与原生事件使用两套一次性状态；
- 无显式 ID 的原生 View 同样受影响，不能归咎于布局 ID。

## 实现

`modules/engine/src/main/assets/node24/ui.js`：原生 View 的注册、计数、排序、移除以同一 EventEmitter 为准，删除重复登记。原生派发读取 rawListeners，保留 once 的“调用前移除”和重入保护；逐个处理器捕获异常，避免一个错误阻断后续监听。协议句柄仍保留原有 handler 表，由公共派发函数处理，不改变原生事件参数、消费规则和宿主协议。

直接调用 `view.emit` 继续遵循 EventEmitter 的异常传播规则；原生 Android 回调的异常会记录后隔离处理。
