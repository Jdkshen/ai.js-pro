## 0. 这是什么（先说可信度）

- 目标：**AutoJs Pro 9.3.11-0 GP**（`org.autojs.autojspro`），**360 加固（Jiagu）+ Dex2C**。
- 来源：运行 App → root 扫描 `/proc/<pid>/mem` 按 `dex\n035` 扒出 **50 个 dex**（约 61 MB）→ 其中**只有 6 个与应用有关**（dex_02/03/04/05 业务、dex_06 APK 自带壳 dex、dex_07 空壳），其余 43 个是 `/apex/**/javalib/*.jar` 系统框架 dex。
- 产物：**1,112 个 `.java`（约 27.7 万行）+ 240 个 `.smali`**；业务类覆盖 **1510/1510 = 100%**（`org.autojs.*` 604 + `com.stardust.*` 906）。
- ⚠️ **不是能编译的工程**：没有 `build.gradle`、没有资源、没有第三方 jar；`Dex2C` 的 native 方法在 JADX 里只有 `native` 占位。

## 3. 四条关键链路（类名都已在树里核对）

### 3.1 启动链
`AndroidManifest.application = com.stub.StubApp`（壳）→ `libjiagu_a64.so` 解密业务 dex 到匿名 rwxp → 壳反射 `entryRunApplication` → **`org.autojs.autojs.App`（`public final class App extends MultiDexApplication`）** → **`autojs.AutoJs`（`public final class AutoJs extends AbstractC2254`，父类不在业务包里，未反）** → `ScriptService`。
**主界面是 Flutter**：`SplashActivity extends AppCompatActivity` → `MainActivity extends FlutterActivity`；而 `org.autojs.autojs.flutter.FlutterActivity extends io.flutter.embedding.android.FlutterActivity`，另有 `FlutterService extends Service`（共 5 个 Flutter 集成类）。

### 3.2 脚本执行链
`ScriptService` → **`com.stardust.autojs.engine.ScriptEngineManager`** → 按 source 类型分派：`RunnableScriptExecution`（普通）· `ActivityScriptExecution`（`ScriptExecuteActivity`）· `LoopedBasedJavaScriptExecution` → `RhinoJavaScriptEngine extends JavaScriptEngine` → **`LoopBasedJavaScriptEngine`（自建 Looper + 自泵）** → `ScriptEngineProxy`；异常走 `notifyException + destroy`，正常走 `notifySuccess + destroy`；另外 `RootAutomatorEngine` 是 root 输入专用引擎。

### 3.3 UI 自动化链
脚本 `selector()` → **`com.stardust.automator.UiGlobalSelector`**（`UiSelector` 的桥）→ `automator.filter.*`（TextFilters/IdFilter/BoundsFilter/BooleanFilter…）→ `automator.search.DFS|BFS` → **`core.accessibility.AccessibilityBridge.windowRoots()`** → `view.accessibility.AccessibilityService`（`getWindows()/getRootInActiveWindow()`）→ `UiObject`/`UiObjectCollection` 的 `click/setText/performAction`；跨线程靠 `UiHandler.post + VolatileBox`。

### 3.4 图像 / 找色 / 找图 / OCR
`runtime.api.Images`（脚本 `images.*`）· `core.image.ColorFinder`（有 **native** 直接扫 MediaProjection 的 `ByteBuffer`）· `core.image.TemplateMatching`（金字塔降采样 + mask）· `ImageWrapper/ImagePool`；截图走 `core.image.capture.ScreenCapturer/Requester`；OCR 走 `runtime.api.OCR` → **`org.autojs.autojspro.ocr.v2.OCRPredictorNative`**（Paddle，default/slim 模型）。

### 3.5 工程打包 / 脚本加密（这条最值得抄）
`project.ProjectLauncher` · **`ProjectConfig`（`project.json` 字段全集，`@Keep`）** · `AssetProjectTemplate`（**模板来自 Flutter assets**）· `core.ui.aapt.Aapt2` · `engine.encryption.ScriptEncryption` · `SigningConfigWithPassword`。

## 5. 加固层的不可读边界

- `com.stub.*`（544 类）**不在源码树里** —— 它一直在 APK 自己的 `classes.dex` 上，没参与脱壳。
- **Dex2C**：业务 4 个 dex 合计 24,461 类 / 133,838 方法 / **2,622 native**；`SplashActivity.onCreate` 本身就是 native（入口逻辑在 `libjgdtc.so`）。
- 因此「抽 dex 重打包」这条路走不通（native 方法体不在 dex 里）；可行的是 **LSPosed hook** 或**改 smali + 保留壳**。

## 6. 读这棵树的坑（我核对出来的）

### 6.1 `libs/okhttp3-internal/` 不是 okhttp
360 把**混淆后的业务/运行时类**重命名进了这个包名：我在该目录里 grep 到 **64 处**引用 `org.autojs.*`/`com.stardust.*`，例如 `dex02/okhttp3/internal/io/dh3.java` import 了 `GlobalKeyObserver`、`Pref`、`TraySharedPreference`、`RhinoJavaScriptEngine`。
→ 原文档的**包级依赖图**里「几乎一切都指向 `okhttp3.internal.io`」是**混淆假象**，不能当架构事实读。

### 6.2 覆盖率是「类级」的，不是「方法级」的
1,112 个 java 里只有 **505 个是业务类**；101 个业务类**只有 smali**（名字不可打印，如 `org.autojs.autojs.ui.doc.Ϳ`，多为匿名/内部类，代码已内联进外层 java）；**3 个类含 `JADX ERROR`**（`AccessibilityServiceTool` / `LayoutJsonOpenActivity` / `FileExplorerTreeView`）。

### 6.3 其它
- 无 `build.gradle`/资源/三方 jar → 只能当**只读源码**看（IDE 里设 sources root）。
- `Base.apk` 的 `assets/.jgapp` 只有 16 字节 —— 业务 dex 是**运行时解密**出来的，不在归档里。
- 5 个 dex 的 **Adler-32 与 body 自洽但 SHA-1 是旧值**：加固在打包阶段换方法体后只重算了 CRC。

## 7. 与我们仓库（ai-js-pro）的对照

| 维度 | 这份 9.3.11 脱壳树 | 我们的仓库 |
|---|---|---|
| 布局 | **单 app + 混淆包**（业务全在一个 dex 集） | **宿主 + 模块**：核心在 `modules/{engine, engine-rhino, automator, common, rhino-language}`，`apps/app` 只 26 个 autojs/stardust 源文件 |
| 引擎 | Rhino + **V8/Prolog（`PlutoJS`）** | Rhino（`ScriptEngineManager` 在 modules 命中 55 处、`LoopBasedJavaScriptEngine` 18 处）；`apps/inrt` 里 `XJavaScriptEngine` 继承 `LoopBasedJavaScriptEngine` |
| UI | IDE(java) + **Flutter 主界面**（`flutter.*` 5 类） | 自己的 Flutter 宿主（`apps/app` + `flutter-ui`/`flutter-payload-base`） |
| 无障碍 | `NoMemoryLeakAccessibilityService` | 未找到该类（我们的实现另有其名） |

**结论（差距清单）**：想在能力上向 Pro 9.3.11 靠，三块是我们没有的 —— ① `org.autojs.autojspro.v8.*`（V8/Prolog 全 API 面）；② `org.autojs.autojs.flutter.*`（Flutter 与脚本引擎的桥：`FlutterScriptsChannel`/`SettingsService`）；③ `NoMemoryLeakAccessibilityService` 那套防泄漏无障碍基类。反过来，**`project.*`（`project.json` 全集）+ `ScriptEncryption` + `Aapt2`** 这条打包/加密链我们已经有自己的实现，可拿来逐字段对照。
