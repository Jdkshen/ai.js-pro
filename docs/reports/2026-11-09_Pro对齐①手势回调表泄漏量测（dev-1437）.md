# Pro 对齐 ①：手势回调表泄漏「先量」的结论（dev-1437，K40 实测）

> 目的：Pro 9.3.11 用 `android.accessibilityservice.NoMemoryLeakAccessibilityService`（占框架包名 + 反射 `mGestureStatusCallbackInfos`/`mGestureStatusCallbackSequence`/`mLock` + 事后 `removeGestureCallbackInfo`）修「`dispatchGesture` 在框架回调表里留条目」。我们**先量再决定要不要照做**。
> 手段：新增 `dev_gesture_probe`（`report`/`stress`）+ `GestureDispatchProbe`（跨进程派发计数）。

## 一、环境与就绪

- K40 `cccc62c7`，**Android 16 / API 36**（`ro.build.version.release=16`、`sdk=36`，LineageOS 底包）。
- 无障碍服务组件名：**`com.jdkshen.aijspro/com.google.android.accessibility.selecttospeak.SelectToSpeakService`**（声明在 `modules/engine/src/main/AndroidManifest.xml:109`）。
  用 `adb shell settings put secure enabled_accessibility_services <组件>` + `accessibility_enabled 1` 打开后：`settings` 显示 `Enabled services:{{…SelectToSpeakService}}`，工具里 `serviceAvailable=true`，实例类 `com.google.android.accessibility.selecttospeak.SelectToSpeakService`。

## 二、结果

### 2.1 反射读不到 Pro 依赖的那两个字段（关键负面结果）

```
table = {supported:false, size:null, sequence:null,
         reason:"在 …SelectToSpeakService 及其父类上找不到隐藏字段
                 mGestureStatusCallbackInfos / mGestureStatusCallbackSequence"}
```
→ **在 Android 16 上这两个隐藏字段已不存在（或改名）**，也就是说 **Pro 的 `NoMemoryLeakAccessibilityService` 那套修补在本 ROM 上不可行**（它的实现强依赖字段名 + 反射 + 事后从 `SparseArray` 删除）。

### 2.2 压测能跑，计数自洽

| 项 | 值 |
|---|---|
| 2000 次（带回调） | `ok=true` · `failed=0` · `stoppedBy=completed` · **893ms** |
| 4 轮（每轮请求 20000，**被工具上限夹到 10000**） | 带回调 2×10000、不带回调 2×10000，全部 `failed=0` |
| 累计计数 | `dispatched=42000` / `withCallback=22000` / `withoutCallback=20000` / `files=[gesture-dispatch-9063.txt]` ✅ 与各轮数字逐项对得上 |

（`count` 上限 10000 写在工具描述里；我请求 20000 是**被夹到 10000**，不是丢数。）

### 2.3 40k 次派发前后内存（`dumpsys meminfo com.jdkshen.aijspro`）

| 指标 | 之前 | 之后 | 变化 |
|---|---:|---:|---|
| Java Heap (PSS kB) | 19,276 | **6,004** | ↓（发生了 GC，无累积） |
| Native Heap (PSS kB) | 26,520 | 26,588 | +68 kB（噪声级） |
| TOTAL PSS (kB) | 144,144 | 130,792 | ↓ |

## 三、判定（①的结论）

1. **不按 Pro 的方式做**：它依赖的隐藏字段在 Android 16 上不存在；即使存在，强反射 + 框架包名占用也是跨版本脆的。
2. **没有观察到值得修补的泄漏**：40,000 次派发（其中 20,000 次走「带回调」= 会进框架回调表的路径）后，Java Heap 没涨、Native Heap 只涨 68 kB。若 20k 条回调条目真被残留，量级约 1 MB —— 低于本次观测分辨率，但至少**没有线性增长的迹象**。
3. **工具留下**（`dev_gesture_probe`）：以后换 ROM/版本、或怀疑手势路径卡顿时，可以直接量（`report → stress → report`）。

## 四、顺带发现（对「类兼容」有用）

**我们和 Pro 都在「占用别人的包名」**，只是占的谁不同：
- Pro：`android.accessibilityservice.NoMemoryLeakAccessibilityService`（占**框架**包名，为了拿到框架类的非公开成员）；
- 我们：`com.google.android.accessibility.selecttospeak.SelectToSpeakService`（占 **Google** 包名，声明在 manifest 里，`AccessibilityServiceTool.sAccessibilityServiceClass` 指同一个类）。
→ 以后讨论「要不要像 Pro 那样占框架包名」，前提要写清：我们**已经在用同类手法**，只是目的不同（Pro 为反射、我们为服务被发现/可启用）。

## 五、边界与未验证

1. 只做了**字段名探测**，没做「枚举 service 类全部字段找改名等价物」——如果 Android 16 只是改了名，我们这次看不到。
2. 内存读数粒度是 `dumpsys meminfo` 的 PSS（±数百 kB），**不是**精确的泄漏判定；也没做 50 万次长跑或 `Runtime.totalMemory()/Debug.getNativeHeapAllocatedSize()` 精读。
3. K40 是 Android 16；Pro 的实际用户多在 Android 9–13，**结论不能外推**到那些版本（字段在旧版本可能存在）。
4. 我为量测用 `adb settings put secure` **临时打开了无障碍服务**（未回滚）——设备上会一直显示「已开启无障碍」；要关我随时可以 `settings delete`。
5. `stress` 会真的派发手势并短暂占用无障碍手势通道（本次 42000 次全部成功，未观察到副作用）。
