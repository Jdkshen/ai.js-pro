# Node 截图授权修复（task-180）

日期：2026-10-19/20。执行：t1-native-services。验证机：K40（cccc62c7，dev-1130）。

## 1. 问题与根因

t2（MI8 dev-1126）：#34 特征匹配(全分辨率找图) 走到 requestScreenCapture → 启动 Node24CaptureConsentActivity（:node24）后系统 MediaProjection 授权框不出现：dumpsys 无窗口、focus 仍主 Activity、Consent Activity paused；appops allow 无效；脚本卡 55s。

根因（dev-1129 实测日志）：
1. Node24CaptureConsentActivity 固定在 :node24 进程，而 dev-1129 起 Node 引擎跑在池进程 :node24_1/_2/_3；Session/PENDING 是进程内静态表 → 授权 Activity 在 :node24 查 token 查不到，onCreate 立即 finish()（paused/无窗口、无系统框）；
2. :node24 是后台进程，直接 startActivity 会被 Android 10+ 后台 Activity 启动限制（BAL）拦下。

## 2. 实现

1. 新增主进程 `Node24CaptureRelay` BroadcastReceiver（apps/app/src/main/java/com/jdkshen/aijspro/engine，manifest 声明、非导出）：:node24 发同包广播 `com.jdkshen.aijspro.NODE24_CAPTURE_CONSENT`（带 job token + 目标授权页类），主进程（通常有可见 Activity）用 PendingIntent 启动授权页，获得 BAL 豁免；
2. 新增池进程授权页子类 Node24CaptureConsentActivity1/2/3，manifest 分别声明在 :node24_1/_2/_3（基类去 final）；Session.request 按 `/proc/self/cmdline` 判断当前进程选对应类，Relay 校验目标类名后启动；
3. 授权结果仍在请求进程的 Session 内闭环（不跨进程回传 Intent）；主进程 Activity 启动失败时保留直连兜底。

## 3. 修改文件
