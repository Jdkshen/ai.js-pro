# 听海原版与三份 Node 示例：功能对照与补修

日期：2026-10-27。检查对象为用户提供的 `base.apk` 与 `听海复刻.zip` 修正版；不代表宿主全部 API 的覆盖认证。

## 先看结论

**目前没有完整复刻原版功能。** 上一轮通过的是 Node UI 稳定性和页面构建优化。五页 `听海UI.js` 实际完成的交互仍主要是五页导航和单条合成海浪的播放/暂停；搜索、收藏、歌单、分类筛选、设置等大多数入口没有事件和数据层。

本轮直接安装原版，按可见入口整理 **42 项功能/入口**。下表分别说明实测到了什么、只看到了什么，以及尚未验证的边界，不能把“有设置页”当作设置效果已验证，更不能把未实现项解释成 Node 不兼容。

本轮另外确认并修复两份单页脚本的播放状态问题：M3 真实循环、曲终状态/重新播放、重建后旧时钟归零，以及白噪音版音量标签同步。**这不等于已补齐完整音乐 App。**

## 本轮实际修了什么

### M3 循环与结尾状态

原实现 `S.repeat=false`，但 MediaPlayer 无条件 `setLooping(true)`；点击循环只改文字颜色。现在初建播放器及开关都使用同一个 repeat 状态，并通过 completion 回调停止计时。关闭循环后停在 `00:26`，填充条停在结尾；再次点击播放会归零重播。循环开启后真正跨过文件末尾继续播放。M3进度读取真实MediaPlayer位置，跨越一轮后的暂停/继续不会误跳回0。

没有把“上一首/下一首都重播”的单曲行为包装成完整切歌；随机、歌单、设置等仍在缺项表中。

### 重建后的时钟和音量

先在真机复现：M3 重建后仍保留约691ms旧累计位置；白噪音版保留约677ms旧计时，音量实际状态/滑块为23%，标签却显示70%。现在释放播放器时同步归零时钟、清理截止时间，并在重新绑定/渲染时按真实音量更新滑块与标签。音量偏好保留，已释放播放器不会冒充旧位置继续播放。

同时去掉了 M3 文件头中“ImageView/SeekBar.setProgress一定触发SIGABRT”的未经证实注释；因果判断仍以退出原因与堆栈为准。

## 真机验收

- `before-recreate-results.json` / `after-recreate-results.json`：M3 位置归零；白噪音版计时归零，23%状态、滑块、标签一致。
- `repeat-result.json`：非循环完成、结尾显示、播放完后重播、真实循环、关闭循环均通过。通过 seek 到结尾前450ms加快覆盖，未假装等待了多轮26秒播放。
- `local-controls-result.json`：27%音量事件真实回写；5分钟按钮设置约300000ms截止时间；为测试缩短截止时间后，确认到期同时暂停 JS 与真实 MediaPlayer；取消定时通过。没有实等5/15/30分钟。
- `fullui-result.json`：五页主界面启动、导航与返回通过；搜索和主题入口无行为已确认，并标为缺失。
- 原版实际创建并删除本轮 `Audit_20261027` 歌单，计数0→1→0；真实歌曲前后切换与拖动进度均由系统 MediaSession 验证。下载、外部歌单导入、歌词结果、长时间后台行为和所有设置效果仍未全量验收。

## 下一步补齐顺序

1. 建立统一曲目模型、播放器控制器和真实队列：上一首/下一首、seek、完成/错误状态、随机/循环、MediaSession与后台控制。
2. 完成本地数据闭环：媒体库/喜欢/歌单创建编辑删除、持久化、排序和计数；先用可控本地音频证明行为。
3. 给全部可见入口接入实际交互：搜索、结果/空态、歌单详情、分类状态、所有设置；设置值必须真正影响播放器和页面。
4. 联网能力使用可配置的数据提供者，接入歌曲/封面/歌词/下载/链接导入，并分别验证网络失败、取消、权限拒绝。
5. 全部功能明确后，再对照原版做截图、间距、动态主题和动画对齐。原版此机为动态青色主题，当前五页固定深色、M3固定浅紫色；视觉相似不代表功能相等。

宿主已经能执行原生 View 事件与音频接口。本轮缺少大量回调/业务数据的地方应先补示例代码；不能仅为了让死按钮“看起来能点”继续修改底层桥。

## 使用本轮工程包

宿主 APK 沿用上一轮性能候选，本轮只需替换工程 ZIP。打开具体 JS，用 Node 引擎运行；主界面为 `听海UI.js`。`听海M3.js` 和 `听海.js` 是另外两种单页演示，不是原版完整功能的替代品。所有未实现项以本表为准。
