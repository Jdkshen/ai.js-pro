# P2-1 跨桥同名方法判定：无可安全抽取项（W1，2026-11-12）

**结论句**：P2-1 经**逐方法定点并排细读** ⇒ **(a) 可抽 0 条** ✓；同名方法要么是**有意差异**（各桥语义不同），要么是**对外契约**（脚本/宿主按名调用）。因此本条**不写 helper、不写测试、不动任何 Java**，交付形态就是「**结论 + 证据**」。

## 0. 为什么不是「抽不动」，而是「不该抽」
收益与成本不成比例：唯一技术上成立的候选（`error(String)`）只值 ~8 行去重，却要走完整批流程（helper + 金标准特征测试 + 审查 + 出包 + 真机冒烟）⇒ 按「**收益小 ⇒ 不做**」收口。

## 2. 两条方法论（值得留档）

1. **「同名 ≠ 重复」** ✗：跨类/跨桥的同名方法必须先分类 **(a) 可抽 / (b) 名同义不同 / (c) 对外契约**，**再**决定动手；本条的 6 组 (b) 就是硬抽会改行为的实证。
2. **抽取脚本只用于筛候选，判定必须定点并排细读** ✓：脚本按「声明 + 花括号配平」抽体会在**重载**与**含同名调用的方法**上抓偏（本次它把 `close` 抓成了别的函数体内的调用点、把 `ok` 抓成了分发器）⇒ 凡「同一对」都要回到 file:line **逐字对比**才算证据。

## 3. 边界（照实）
- 全部判定来自**源码逐字对比**（含体量/字节数）⇒ **无真机**；语义等价最终仍以真机三引擎冒烟为准；
- 本次**未**新建 helper、**未**新增测试、**未**修改任何 Java/JS ✓；
- 若将来要保留一条「形状相同、仅文案不同」的去重范式，唯一候选是 `error(String)`（需先写金标准特征测试 + Lead 明确点头）。

## 4. 重开条件与范围声明（W2 复审建议，task-158 补）
