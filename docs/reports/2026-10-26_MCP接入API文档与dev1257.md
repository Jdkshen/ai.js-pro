# MCP 接入 API 文档与 dev-1257

用户要求把 App 内 API 文档提供给 MCP，更新安装包。新增 `search_api_docs` 和 `read_api_doc` 两项只读工具；现有引擎执行、示例读取与接口探针保留。主助手实现、集成与验收，DP 只做独立只读审查。

## 功能与使用

- MCP 与 App WebView 读取同一个 `docs/api-reference-data.js`：756 条参考、29 个来源。生成器 schemaVersion=2 增加 `content`，现行指南保留 Markdown 原文；传统 HTML 转为可读 Markdown，`pre` 内代码保留换行、缩进、中文和 HTML 实体原义。WebView 渲染沿用同一记录的 `html`。
- `search_api_docs`：query 可省略（目录浏览），空格分隔多关键词、大小写不敏感、标题优先；按 engine/category/kind 筛选。默认 offset=0、limit=10，limit=1..20。返回 categories、id、摘要、来源、引擎标注、indexSha256、nextOffset/hasMore。
- `read_api_doc`：id 使用搜索结果，建议同时传 indexSha256。返回 Markdown content；默认 maxChars=16000、范围 128..32000，offset/nextOffset/contentLength 按 UTF-16 字符计算，用 nextOffset 拼接。分页不切开代理对，可能位于代码块中间。
- 索引 ID 随更新可能变化；有 indexSha256 的旧读请求会明确要求重新搜索，不会静默错配。工具参数的类型、范围、未知字段与非法 ID 均校验。
- 只解析 JSON，不执行 JS，不访问网络，不创建脚本任务/浮窗，不占运行槽；首次查询才加载并缓存，多个并发读取共享一次初始化。
- 每项返回 `supportEvidence=documentation_only` 和 scope/hint。legacy 仅标注 Rhino，按 Node/QuickJS 筛选不会返回传统原文；不能把文档标注当作高级版全兼容/运行验证。真实成员用 probe_engine_api，实际行为仍需目标引擎测试。
- UI 手册 6.1 的范围改为 Rhino/QuickJS，6.2–6.4 的 Node 专题改为 Node；其余跨引擎章节仍须按段落读兼容限制。每项补充 engineNote，传统原文保留 link。修正人工/内置 MCP 指南旧数量并注明截图是旧版；早期 MCP_SCRIPT_SERVICE.md 标记为历史入口，避免新智能体误读旧 Node 能力结论。
- `initialize.instructions`、`learn_autojs_skill`、工具 schema、分类与指南同步。MCP serverInfo 版本 1.7.0；59 个规范工具、9 个公开兼容别名，共 68 名称。确定性的驼峰调用别名仍由目录自动生成，未重复公告。

调用示例（第二步使用第一步实际返回的字段）：

```json
{"name":"search_api_docs","arguments":{"query":"loadResources","engine":"nodejs","limit":5}}
{"name":"read_api_doc","arguments":{"id":"api-N","indexSha256":"sha256:第一步实际值"}}
```

升级后需重连 MCP 客户端/刷新工具缓存，才能看到新增两项；已建立的客户端工具列表不会自动替换。
