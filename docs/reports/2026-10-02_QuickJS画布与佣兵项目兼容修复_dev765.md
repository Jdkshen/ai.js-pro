# QuickJS 画布与佣兵项目兼容修复（dev-765）

日期：2026-10-02。修复落在 AI.js Pro 应用源码。用户提供的 `华仔部落_佣兵战纪脚本.zip` 保持原样。

## 真实项目复现

将 ZIP 解压到 `.artifacts/user-project-mercenaries/hz_ybzj`，在 K40（Android 16、1080×2400、440 DPI）运行测试副本。主界面、原始 utils 与原始 `@se7en/float_menu-rhino` 均来自 ZIP。测试副本仅将后台 HTTP / WebSocket 地址改为本机关闭的端口，避免测试期间向第三方上传日志和设备信息；未修改游戏流程或注册判断。

主程序使用 `"ui";` 和裸 XML（E4X），应由 Rhino 执行。给入口加 QuickJS 标记时，应用会因 E4X 布局选择 Rhino；这个项目不能作为“全部业务已原生运行于 QuickJS”的证据。QuickJS 另以用户截图对应的反引号布局和实际绘制回调验证。

## 修复内容

| 问题 | 应用源码处理 |
| --- | --- |
| QuickJS 的 `board.on('draw', …)` 被拒绝 | 新增 `qjs-canvas.js`，支持浮窗与 UI Canvas 的 draw、once、增删监听、帧率设置；回调在所属 QuickJS 线程执行，传入 ScriptCanvas 与对应控件 |
| 帧率计算为 `100 / fps` | 改为 `1000 / fps`，正数帧间隔至少 1 ms |
| 窗口关闭时绘制线程仍操作已销毁 Surface，出现 SIGSEGV | 双引擎改为绘制离屏 Bitmap、完成后提交；Surface 锁只包围原生提交，销毁时等待提交结束，JS 回调不持有 Surface 锁 |
| 画布关闭、布局替换、强制停止后的资源清理 | 双缓冲复用；借出的帧在回调结束后释放；浮窗递归关闭 Canvas，QuickJS UI 替换和退出关闭旧 Canvas；引擎退出兜底回收 |
| Rhino 模块中的 `{ drawMatches }` 与 `show() { … }` 解析失败 | 入口和 CommonJS 模块共用 `RhinoSyntaxPreprocessor`，使用 Rhino 解析器定位缺失语法，转换普通属性／方法简写，保留 E4X、注释、正则和不能转换的原文；E4X 引擎选择也使用相同兼容转换 |
| 箭头函数不能转换为 Runnable | 修复 `threads.start`、线程池 execute，以及 NativeView 的 post、postDelayed、postOnAnimation 和 removeCallbacks 参数适配；保留箭头函数的词法 this 和适配对象身份 |
| 控件 Symbol 私有字段被拒绝 | `NativeJavaObjectWithPrototype` 实现 SymbolScriptable，保留 Symbol 身份、实例字段和原型访问器接收者 |
| Rhino 缺少 Map 导致悬浮菜单构造失败 | 初始化时补 Map 的键身份、NaN/零、顺序、迭代器、增删、clear、forEach 和 size；已有构造器原样保留 |
| Pro 的 `runtime.floaty.rawWindow(global, factory)` 缺失 | 增加 scope + Function 的 rawWindow/window 重载，创建控件并返回原生窗口对象 |
| 子线程申请截图抛出 ContinuationPending | continuation 仅在 UI 线程等待，后台线程使用阻塞结果等待 |
| 原项目默认加载官方 MLKit 插件但插件未安装 | Rhino 在该官方插件包缺失时提供内置离线 MLKit 的构造器、detect、release、isReleased；已安装插件优先，其他插件错误继续抛出 |
| `attr('text', value)` 静默无效，设备宽高空白 | TextView（含按钮与输入框）增加 text/hint 的实时读写；通用控件增加 enabled 的实时读写 |

主要源码在 `modules/engine/src/main/assets/modules/qjs-canvas.js`、`rhino-map.js`，以及 `core/graphics`、`engine/RhinoSyntaxPreprocessor.java`、`runtime/api/Floaty.java`、`core/ui/attribute` 等目录。

Map 是适合小型菜单的兼容实现，查找为线性扫描；迭代期间保留已删除条目的位置，结束后可压缩。不宣称哈希表性能或旧 Rhino 全部现代 ECMAScript 已兼容。键相等、迭代和修改行为参考 [ECMAScript Map 规范](https://tc39.es/ecma262/multipage/keyed-collections.html#sec-map-objects)。

## 用法

QuickJS 入口使用 `// @engine quickjs`，布局传反引号字符串；`"ui";` 布局也支持字符串。实际示例已加入：**QuickJS 新引擎 → 画布 → 悬浮画布.js**。

```javascript
// @engine quickjs
var w = floaty.rawWindow(`<frame><canvas id="board" w="*" h="*"/></frame>`);
w.board.setMaxFps(30);
w.board.on('draw', function (canvas, view) {
    canvas.drawARGB(180, 20, 24, 32);
});
```

Rhino 的原项目入口保持 `"ui";` 和 E4X 布局；require 模块无需另加引擎标记。
