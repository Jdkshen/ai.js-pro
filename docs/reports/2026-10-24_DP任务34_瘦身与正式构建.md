## 二、实际文件改动

### 1. `apps/app/build.gradle`

1. **Flutter release 源集**：`-PflutterPoc=true` 时，release 与 debug 一样加入：
   - `src/flutterpoc/java`
   - `src/flutterpoc/res`
   - payload 的 `assets` 与 `jniLibs`
   - `src/flutterpoc/AndroidManifest.xml`

   同时 release 的 Java 源集排除 `**/DebugCommandReceiver.java`，避免调试类进入正式 dex。

2. **release 的清单策略不被覆盖**：release 以 flutterpoc 清单为底后，用 `androidComponents` 把
   `src/release/AndroidManifest.xml`（`WRITE_SECURE_SETTINGS` 移除）和新增的
   `src/flutterpocRelease/AndroidManifest.xml`（调试 Receiver 移除）追加为静态 overlay；
   合并后的 `processMiuixCompatReleaseMainManifest` 再检查最终清单。

3. **release embedding 依赖**：`flutter_embedding_release.jar`、relinker、tracing、
   exifinterface、lifecycle-process、window-java 现在同时挂到 `debugImplementation` 与
   `releaseImplementation`；release 不再只是“能编译 Activity 但运行时缺 Flutter 类”。

4. **payload 硬校验**：`verifyFlutterPayload` 增加必需文件存在性检查（runtime、embedding、
   flutter_assets、libflutter、libapp），并检查 embedding jar 内确实有
   `FlutterActivity` / `FlutterEngine`，避免把不完整 jar 带进 release。

5. **ABI 防错**：Flutter release 默认只启用 arm64 output（payload 只有 arm64；debug 仍
   保持三 ABI split 不变），避免产出缺 libflutter 的 x86/v7a“能装但打不开”包。
   `-PflutterPocAbi=arm64-v8a` 可显式收窄/固定 split；`verifyFlutterReleaseAbiSupport`
   再检查 release 期望 ABI 在 payload 中真实存在。直接 `assembleRelease -PflutterPoc=true`
   不需要额外 ABI 参数即可只出 arm64 release；普通 debug/release（不带 `-PflutterPoc`）
   仍保持三 ABI。

6. **分阶段 R8/资源裁剪**：
   - `-PreleaseR8=true`：开启 release 的 `minifyEnabled`。
   - `-PreleaseR8Optimize=true`：额外允许 R8 optimize；默认不传时生成
     `.artifacts/generated/r8/release-conservative.pro`，内容仅 `-dontoptimize`。
   - `-PreleaseShrinkResources=true`：必须同时有 `-PreleaseR8=true`；默认关闭，且会打印
     动态 `getIdentifier` 资源风险警告。
   - debug 仍固定 `minifyEnabled false` / `shrinkResources false`。

7. **签名门禁**：release 只有两种情况可继续：
   - 四项 `AIJSPRO_*` 齐全，使用已有正式签名；
   - 或显式 `-PflutterReleaseTestSigning=true`，使用 AGP 本机 debug keystore。
   两者都没有时 `verifyReleaseConfiguration` 直接失败；正式签名和测试签名同时存在时前者优先，
   但构建脚本会拒绝这种含糊组合。

8. **版本注入**：`versionCode` / `versionName` 默认仍取 `project-versions.json`；可用
   `-PappVersionCode` / `-PappVersionName` 注入构建候选，避免改仓库版本文件。

9. **模板注释纠正**：原 `apps/app/build.gradle` 约 209 行“宿主不再包含
   assets/template.apk”与 `verifySlimPackagingTemplate` 的硬门事实矛盾。已改为：模板仍由
   `plugins/apkbuilder-plugin` 维护/分发，同时 `apps/app/src/main/assets/template.apk`
   仍是硬门输入，不能按旧注释删除。

10. **修复既有 release 清单校验的 Groovy 问题**：原校验用
    `groovy.xml.Namespace.name`（QName）去匹配 `XmlSlurper(false,false)` 的字符串属性键
    `android:name` / `tools:node`，在 Groovy 3 下实际匹配不到；`find()` 空结果返回
    `NoChildren` 而不是 `null`，`== null` 判断也会误判。现已统一改为字符串键并用
    `.size() == 0` 判断，release 的 `WRITE_SECURE_SETTINGS` 与调试 Receiver 检查才真正生效。

### 2. `apps/app/proguard-rules.pro`

- 删除过时/无效的 `-keep class * extends c`；
- 删除不再存在的 `com.some.package...` 占位规则、旧 support-v4 Fragment / GMS `SafeParcelable`
  等与本项目依赖不符的规则；
- 增加 `*Annotation*,Signature,InnerClasses,EnclosingMethod,Exceptions` 属性保留；
- 明确保留：
  - `com.jdkshen.aijspro.**`（宿主、MCP、Flutter POC、插件桥）；
  - `com.stardust.**`、`org.autojs.**`（Rhino/QuickJS/Node、无障碍、原生 UI inflater）；
  - `org.mozilla.javascript.**`、EventBus、editor、msgpack；
  - `io.flutter.**`、`androidx.window.**`、relinker、Flurry、Bugly、AVLoading；
  - JNI native 方法及其描述符类；
  - `@JavascriptInterface` 方法、WebViewClient/WebChromeClient 回调；
  - XML 反射构造的 View 构造器、Activity 的 `(View)` 回调；
  - Parcelable/CREATOR、Serializable、Enum、R 字段、Gson `SerializedName`；
  - `@Keep`、`@Subscribe`、`@ScriptInterface`。

**保守策略说明**：以上保留范围使 R8 目前主要裁剪未被引用的依赖/库代码，而不是宿主和引擎代码。
因此本次不能声称“R8 一定省了多少 MB”；必须由实际 `assembleRelease` 产物测量。

### 3. `apps/app/src/flutterpoc/AndroidManifest.xml`

调试广播增加：

```xml
android:permission="android.permission.DUMP"
```

`android:permission.DUMP` 的保护级别包含 `development`，adb shell 可发送，普通第三方应用
拿不到；`exported=true` 保留以兼容现有 `am broadcast` 调试流程。MCP 组件没有改动。
候选脚本默认保留 VS Code USB 自动发现 provider；只有在与真 Auto.js Pro 同机安装冲突时，
才显式加 `-NoUsbDiscovery`（对应 `-PdevPluginUsbDiscovery=false`），它只移除 USB 自动发现，
LAN 连接与 MCP 服务不受影响。不要因为使用该可选开关就误判为 MCP 被关闭。

### 5. 新增 `tools/flutter-poc/build-release-candidate.ps1`

- 只构建、不发布、不安装、不改 `update.json` / `project-versions.json`；
- 默认复用已锁定 payload，不重建 AOT；只有显式 `-RebuildAot` 才调用 `build-aot.ps1`
  （可再加 `-AotOffline` 走离线 pub 缓存），不强制联网；
- 固定 `-PflutterPoc=true -PflutterPocAbi=arm64-v8a`；默认保留 VS Code USB 自动发现
  provider，同机安装冲突时用 `-NoUsbDiscovery` 显式去掉；
- 正式签名走 `AIJSPRO_*`；没有正式签名时必须显式 `-TestSigning`；
- 拒绝 `*-unsigned.apk`；
- 对最终 APK 检查 `lib/arm64-v8a/libflutter.so`、`lib/arm64-v8a/libapp.so`、
  `assets/flutter_assets/AssetManifest.bin` 确实被包装，防止“Gradle 源集对了但 merge 缓存
  丢了 payload”；
- 用 `apksigner` 校验证书并识别 Android Debug；
- 用 `aapt2` 检查 release 清单无 `DebugCommandReceiver` / `DEBUG_RUN` /
  `WRITE_SECURE_SETTINGS`，且非 `application-debuggable`；
- 默认跑 `tools/check-android-16kb.py`，可选跑体积审计/预算/基线；
- 复制到 `.artifacts/flutter-release-candidate`，写 SHA-256 sidecar；
- **PS1 为 UTF-8 with BOM**（已检查 `EF BB BF`）。

### 6. 新增 `tools/audit-apk-size.py` 与 `tools/tests/test_apk_size_audit.py`

审计工具特性：

- 按组统计 raw / compressed contribution / share：`dex`、`lib/<abi>`、`assets/<top>`、
  `res`、`META-INF` 等；
- 单独报告 ZIP 容器开销（签名块/本地头/中央目录），不把 compressed entry 总和当成文件大小；
- 直接从中央目录读原始 entry name 字节，统计：
  - 非 ASCII 且 **有效 UTF-8** 的条目数；
  - 无效 UTF-8 条目数；
  - ZIP UTF-8 flag 设置数、无 flag 的非 ASCII 数；
- 支持 `--baseline`、`--max-total-mib`、`--max-growth-mib`、`--max-growth-percent`、
  `--json`、`--top`，预算不通过时退出码 1；
- 对无效 UTF-8 名称不再依赖 `zipfile` 先解码，先读中央目录，避免审计本身崩掉。

测试为纯合成 ZIP，共 6 项，覆盖分组/总量、无 UTF-8 flag 的中文名、无效 UTF-8 名、
基线/预算、JSON/CLI 和分类。

## 四、主助手建议执行顺序

```powershell
# 1) 本地测试签名 + 默认无 R8（先验证 Flutter release 本体）
.\tools\flutter-poc\build-release-candidate.ps1 `
  -VersionCode 1241 -VersionName 1.0.2 -TestSigning

# 2) 保守 R8（默认 -dontoptimize，仅 shrink）
.\tools\flutter-poc\build-release-candidate.ps1 `
  -VersionCode 1241 -VersionName 1.0.2 -R8 -TestSigning

# 3) 显式 R8 optimize（只有 2 通过后再试）
.\tools\flutter-poc\build-release-candidate.ps1 `
  -VersionCode 1241 -VersionName 1.0.2 -R8 -OptimizeR8 -TestSigning

# 4) 资源裁剪（必须已有 res/raw/keep.xml 与动态资源审计；默认不推荐）
.\tools\flutter-poc\build-release-candidate.ps1 `
  -VersionCode 1241 -VersionName 1.0.2 -R8 -ShrinkResources -TestSigning
```

正式构建时不要加 `-TestSigning`，先设置四项 `AIJSPRO_*`。脚本会拒绝没有正式签名或没有
显式测试签名的 release。若设备上同时装有真 Auto.js Pro，追加 `-NoUsbDiscovery` 以避免
provider authority 冲突；它不影响 MCP/LAN。

直接跑 Gradle 时 `-PflutterPoc=true` 的 release 会自动只启用 arm64 output；显式
`-PflutterPocAbi=arm64-v8a` 也会固定同一结果，两者都不应产出缺 Flutter 引擎的 v7a/x86 包
（`verifyFlutterReleaseAbiSupport` 仍会检查 payload 里确有对应 ABI）。
预期产物路径：`apps/app/build/outputs/apk/miuixCompat/release/app-miuix-compat-arm64-v8a-release.apk`
（若 Gradle 输出命名变化，以 `build/outputs/apk/miuixCompat/release/` 下最新的 arm64 release
APK 为准；脚本会拒绝 `*-unsigned.apk`）。
