# 打包图片残留与细节检查

检查日期：2026-09-27。范围：脚本打包、项目图标/启动图、项目目录刷新，以及近期导入/打开流程的剩余细节。不是全仓库完工验收。

## APK 里为什么有 Auto.js 图片

在 dev-703 的 `assets/template.apk` 中实际发现 `assets/project/auto.js.png`。源文件来自 `apps/inrt/src/main/assets/project/auto.js.png`，属于模板自带的演示工程。

旧流程先解压模板，再覆盖/追加用户工程；用户工程没有同名文件时，模板图片仍留在工作区，最后被重新打进 APK。模板自带的 `main.js`、`project.json` 也存在同样的串入风险。不是用户工程主动引用了这张图。

同时确认主应用一直携带旧模板：dev-703 内嵌模板与仓库旧 `template.apk` 字节一致；构建主应用时没有自动重建运行时。

## 本次已处理

| 问题 | 处理 |
|---|---|
| 模板演示文件混入产物 | `ApkBuilder.prepare()` 解包后清空工作区的 `assets/project`，再复制当前项目；删除失败即中止，避免假成功。模板源文件里的旧图片也已移除。 |
| 用户自己有同名图片 | 不按文件名删除用户文件；清理先于复制，项目自带的 `auto.js.png` 会原样保留。 |
| 项目 `icon: "res/logo.png"` 不生效 | `AppConfig.fromProjectConfig()` 以项目目录解析相对路径，绝对路径继续支持；图标缺失或不能解码时明确报错。 |
| 默认图标与启动图不一致 | 模板默认桌面图标换为现有 AI.js Pro 图标；启动布局默认引用 `ic_launcher`，因此跟随项目图标。显式配置的 `splash.png` 继续优先。 |
| 切换打包项目沿用上一项目设置 | 切换源项目时重置图标、启动图及运行配置，再加载新项目；权限默认值没有变更。 |
| 运行时模板过期 | 主应用 `merge*Assets` → `:inrt:buildApkPlugin` → `:inrt:packageRelease`；正常编译主应用会同步模板，复制任务有输入/输出声明。 |
| 新建项目改位置后列表不刷新 | 通知实际项目父目录刷新，不再使用最初进入页面时的父目录。 |
| 文件操作提示重复 | UI 线程显示提示后立即返回，避免再次排队显示。 |
| 删除提示误称一定可恢复 | 只有确认移入备份且备份存在时才显示“可在最近删除恢复”；直接删除不再显示可恢复，失败时不承诺原文件一定完整。 |

清理只影响打包临时工作区，不删除用户源项目。已经生成的旧 APK 不会自动变化，需要更新主应用后重新打包。

## 仍未完成的细节

1. **打包页的文件选择器尚未完全统一。** `MiuixBuildActivity.FilePickerDialog` 仍是独立的 `SuperDialog` + 文件列表，源码、输出目录、启动图、签名文件选择没有全部接入公共选择器；目录读取仍在界面线程，读失败还可能显示成空列表。后续应给公共选择器增加脚本/工程、图片、密钥库类型及对应过滤，再迁移这些入口。
2. **ZIP 导入不是完整的工程导入。** 外部 ZIP 可以进入导入流程，但当前是复制到目录，不自动解包、验证 `project.json` 并打开工程；应用内部导入列表也尚未把 ZIP 纳入统一流程。
3. **外部大文件/慢提供方的保存体验。** 打开时已后台复制，但 `ExternalEditorDocument.write()` 在编辑器保存调用中仍同步写提供方，需要后台保存、进度和防重复提交；目前不能据此声称大文件保存流畅。
4. **布局与文件边界需要专门补测。** 本轮没有完成横屏、超大字体、软键盘遮挡，以及通用 MIME 对应二进制附件的拦截验证。应分别验证，不能把正常文本打开通过当成所有附件都兼容。

建议下一轮先统一打包选择器，再完成 ZIP 工程导入，之后处理外部文件保存与边界场景。
