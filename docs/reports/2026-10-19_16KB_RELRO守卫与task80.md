# 16KB 页对齐守卫修复 + task-80 RELRO 圆整（2026-10-19）

## task-80：自研 native 补 common-page-size
- 现状：主引擎 `modules/engine/src/main/cpp/CMakeLists.txt`（4 处）与 `pikafish/CMakeLists.txt` 已有 `-Wl,-z,max-page-size=16384` + `-Wl,-z,common-page-size=16384`；
- 缺口：象棋插件 `plugins/xiangqi-plugin/src/main/cpp/CMakeLists.txt` 只有 max-page-size，RELRO 末尾未圆整；
- 修复：补 `-Wl,-z,common-page-size=16384` 并跑 `plugins/xiangqi-plugin/src/main/cpp/build-native.ps1` 重新链接；
- 验证（NDK r27c llvm-readelf -l）：
  - 修复前 `GNU_RELRO: 0x1b18e0 + 0xb720 = 0x1bd000`（非 0x4000 对齐，pad=0x1000）；
  - 修复后 `GNU_RELRO: 0x1b18e0 + 0xe720 = 0x1c0000`（0x4000 对齐，pad=0x0）；
  - `libxiangqi_engine.so` 大小不变（1,807,360B），仅段布局变化。

## task-79：守卫脚本 + gradle task（顺手修复一个真实 bug）
- 守卫存在：`tools/verify-16kb-alignment.ps1` + `:app:verify16kbAlignment`（`-Pverify16kbApk` 指定产物、`-Pverify16kbStrictRelro` 严格模式）；
- 发现 bug：`apps/app/build.gradle` doLast 用了 `executionResult.get().exitCode`（Gradle ExecResult 无此属性），任何一次运行都会 `No such property: exitCode` 假失败；已改为 `exitValue`；
- 修复后实测：
  - 非严格：`BUILD SUCCESSFUL`，19 个 arm64 .so，FAIL 0、WARN 1（libflutter 上游 allowlist，LOAD p_align=0x1000）；
  - 严格：`BUILD SUCCESSFUL`，FAIL 0、WARN 9（均为 opencv/mlkit/c++_shared/flutter 等 allowlist，自有库 quickjs/aijscrypto/ppocr/pikafish/plugin 全 OK）。
