# Node24 JS 回调异常逃逸主线程修复（dev-1251）

日期：2026-10-25。用户报告 dev-1250 / Android 36 崩溃：

```text
java.lang.IllegalStateException: JavaScript callback threw an exception or was cancelled
  org.autojs.source.engine.Node24Engine.nativeInvokeCallback(Native Method)
  ... Node24HostBridge$NodeJsCallback.lambda$asInterface$0(SourceFile:1306)
  ... java.lang.reflect.Proxy.invoke
  $Proxy4.run
  android.os.Handler.handleCallback / Looper.loop
```

## 根因

`Node24HostBridge.NodeJsCallback` 把 JS 回调异常重新抛给 Java 调用方。该回调是 Android 主线程 Handler 的 `Runnable`；异常沿 Looper 逃逸，成为未捕获主线程异常，直接杀应用。native 对“取消”和“脚本真实抛错”可能共用同一条泛化错误文本，原逻辑在 `mCallbacksClosing` 未及时置位时仍会重抛。

## 修复

- 新增 `shouldContainCallbackError(closing, failure)`：
  - `mClosed`/`mCallbacksClosing` 时包含；
  - `Looper.myLooper() == mainLooper` 时包含；
  - 错误文本含 cancelled/canceled 时包含。
- `NodeJsCallback` 捕获后记录 logcat（`Node JS callback failed; contained ...`），返回 Java 默认值，不再抛入 Looper。
- 生成类回调路径同样处理；Node 线程上的真实同步回调错误仍按原语义传播，脚本仍可捕获。
