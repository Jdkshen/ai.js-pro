## 1. 实现（多任务拆分为 task-220/221/222 与 task-223/224/225）

### Phase A（dev-1206）

- `RawScreenshotFormat`（engine）：32B 小端头 `N24R/version=1/width/height/rowBytes/format=ARGB_8888/reserved`，纯 JVM `newHeader/parseHeader/validateLength`；
- 宿主 `AutomationHostService.screenshot()`：路径 `.n24r` 时改用 `FileOutputStream+FileChannel` 写头 + `Bitmap.copyPixelsToBuffer` 的 ARGB_8888 连续像素；其它路径保持 PNG。
- `Node24Images.readRawFile()`：路径限 cache/files 私有目录；头/长度/预算校验；`Bitmap.createBitmap + copyPixelsFromBuffer + register`，失败回收。
- `Node24AutomationBridge`：Raw 优先、`readRawFile` 失败换新 UUID 回退 PNG；finally 删除临时文件；错误文案保持原样。

### Phase B（dev-1207）

- AIDL `IAutomationHost` 新增 `ParcelFileDescriptor screenshotPixels(int maxWidth, int maxHeight, int format)`；
- 宿主 `screenshotPixels`：binder 线程截图 → `createPipe()` 立即返回 readEnd → daemon 线程写头 + 像素，写完/异常关闭写端并 recycle，不阻塞 Binder；
- `AutomationHostClient` 实现委托，`RemoteAutomationBridge.Backend` 增加带 default 的方法 + static 包装；
- `Node24Images.readRawStream(InputStream)`：读满 32B 头/像素、预算校验、`copyPixelsFromBuffer + register`；
- `Node24AutomationBridge`：PFD → `readRawStream`；失败回退 Phase A `.n24r`；再失败回退 PNG；PFD 用嵌套 try-with-resources 关闭，三级错误 `suppressed`。

- MCP 快速通道与普通 PNG 回退均保留，任何一级失败自动降级。
