# Rhino 包装语义丢失排查（只读分析）

日期：2026-11-07  
范围：`modules/engine/src/main/java/com/stardust/autojs/rhino/`、`modules/engine/src/main/java/com/stardust/autojs/engine/RhinoJavaScriptEngine.kt` 的 `WrapFactory`、以及被它引用的 `NativeView`/`ScriptJavaObject`/`JavaReflectiveInvocation`。  
方法：只读代码，不跑构建/设备，不改产品代码。

**一句话结论：Class 实例 API 已基本补回，但包装层仍有同类语义丢失——最直接的是 `AijsNativeJavaClass` 现在让 `java.lang.Class` 的实例成员优先于目标类自己的静态成员（例如 `RomUtil.getName()`、`PFiles.getName(path)` 会被 `Class.getName` 遮蔽）；此外还有 `has("class")`/枚举、静态方法重载/数值范围、`setJavaPrimitiveWrap(false)`、`UiObjectCollection`/`View`/`Paint`/`Method` 特化带来的语义缺口。**

## 2. Class 对象：修复前/后与 API 清单

### 2.1 修复前后机制

- **dev-1380 原路径**：`WrapFactory` 把所有 `Class` 包成 `AijsNativeJavaClass`，`get` 只有 `name == "class"` 特判，其余走 `NativeJavaClass`。`NativeJavaClass` 解析的是**静态成员**，因此 `obj.getClass().getName()`、`getClass().getSimpleName()`、`Packages.java.lang.String.getName()` 这类“Class 实例方法”报：
  `InternalError: Java class "...JsLinearLayout" has no public instance field or method named "getName"`。
  证据：`AijsNativeJavaClass.kt:37-45` 的回归注释；`getClass().getName()` 在 `__ui__.js:408` 的实际崩溃记录（Lead 已给）。
- **dev-1383 修复路径**：
  - `:42-45`：`name in CLASS_API_NAMES` 时先走 `classInstanceMember(start,name)`；
  - `:46-53`：`super.get` 抛 `EvaluatorException` 再尝试 Class 实例成员；
  - `:64-65`：`classView` 是 `NativeJavaObject(this,targetClass,Class::class.java)`，把 `targetClass` 当 `java.lang.Class` 的实例查成员；
  - `:70-76`：`CLASS_API_NAMES` 由运行时的 `Class::class.java.methods/fields` 动态生成；
  - `:60-61`：`has` 同步返回 true。

### 2.2 依赖「Class 对象被当作 Class 实例」的常见写法

下表中“修复前”指 dev-1380（无 `CLASS_API_NAMES/classView`），“修复后”指当前 dev-1383 路径。运行时不存在的方法（不同 Android API/隐藏 API）不在此表保证范围；修复后按 `CLASS_API_NAMES` 动态可用性工作。

| API 组 | 典型写法 | 修复前 | 修复后 | 备注 |
|---|---|---|---|---|
| 名称/身份 | `getName`, `getSimpleName`, `getCanonicalName`, `getTypeName`, `getPackageName`, `getPackage`, `getModule`, `toString`, `hashCode`, `equals`, `getClass` | 失败 | 可用 | `getClass` 返回 Class 的 Class，仍会再包成 AijsNativeJavaClass；`hashCode/equals/toString` 来自 `Class` 的 public 方法（含 Object 继承） |
| 父类/接口 | `getSuperclass`, `getGenericSuperclass`, `getInterfaces`, `getGenericInterfaces`, `getComponentType`, `getDeclaringClass`, `getEnclosingClass`, `getEnclosingMethod`, `getEnclosingConstructor` | 失败 | 可用 | 返回值若为 Class，经 WrapFactory 再包成 AijsNativeJavaClass；`getDeclaringClass` 对局部/匿名类可为 null |
| 成员反射 | `getFields`, `getDeclaredFields`, `getMethods`, `getDeclaredMethods`, `getConstructors`, `getDeclaredConstructors`, `getClasses`, `getDeclaredClasses`, `getField`, `getDeclaredField`, `getMethod`, `getDeclaredMethod`, `getConstructor`, `getDeclaredConstructor` | 失败 | 可用 | 返回的 `Method` 元素经 WrapFactory 变成 `ReflectiveMethodObject`，其 `invoke` 语义见第 4 节；返回数组为 NativeJavaArray |
| 继承/判定 | `isAssignableFrom`, `isInstance`, `isInterface`, `isArray`, `isPrimitive`, `isEnum`, `isAnnotation`, `isSynthetic`, `isAnonymousClass`, `isLocalClass`, `isMemberClass`, `isRecord`, `isSealed`, `isHidden`, `desiredAssertionStatus` | 失败 | 可用 | `isAssignableFrom` 的实参若是 AijsNativeJavaClass，会作为 Java `Class` 传给 Class 方法（NativeJavaClass 是 Wrapper）；建议回归测一次跨 dex 类 |
| 转换/子类 | `cast`, `asSubclass`, `arrayType`, `componentType` | 失败 | 可用（运行时存在时） | `cast` 返回对象后由 WrapFactory 正常包装；`arrayType/componentType` 取决于 Android API/隐藏 API |
| 注解/资源 | `getAnnotations`, `getDeclaredAnnotations`, `getAnnotation`, `getDeclaredAnnotation`, `getAnnotationsByType`, `getDeclaredAnnotationsByType`, `getResource`, `getResourceAsStream`, `getProtectionDomain`, `getSigners` | 失败 | 可用（受 Android 安全/隐藏 API 限制的除外） | 注解返回值/注解数组按普通 Java 包装；`getProtectionDomain` 可能 SecurityException（非包装层问题） |
| 枚举/记录/密封 | `getEnumConstants`, `getEnumConstantsShared`, `getRecordComponents`, `getPermittedSubclasses`, `getNestHost`, `getNestMembers` | 失败 | 可用（运行时存在时） | `getEnumConstants` 对非 enum 返回 null；`getRecordComponents` 等 Android 版本可能没有 |
| 静态 Class 方法 | `Class.forName(...)`（经 `Packages.java.lang.Class.forName`） | 可用（本就走 NativeJavaClass 静态成员） | 可用 | 不在 Class 实例 API 表；属于静态路径，修复前后都不应受影响 |

**修复后仍不等于“原生 NativeJavaObject 行为”**，因为现在仍是 `AijsNativeJavaClass` 子类，且 `get` 有 Class API 优先规则。

### 2.3 Class 包装剩余的同类隐患（重点）

| # | 隐患 | 证据 | 后果 |
|---|---|---|---|
| C1 | **Class 实例 API 遮蔽目标类静态成员** | `AijsNativeJavaClass.kt:42-45` 先查 `CLASS_API_NAMES`，`:46-53` 才查 `super.get`（静态成员） | 任何目标类若有 public static `getName/getSimpleName/getMethods/getFields/cast/isInstance...`，脚本拿到的会是 `Class` 的同名实例方法，而不是目标类静态方法。仓库中直接证据：`third-party/settingscompat/library/src/main/java/ezy/assist/compat/RomUtil.java:82` 的 `public static String getName()`；`modules/common/src/main/java/com/stardust/pio/PFiles.java:377` 的 `public static String getName(String filePath)`。前者会返回类名字符串而不是 RomUtil 名称，后者参数个数不匹配/行为错误 |
| C2 | **`has("class")` 不一致** | `:60-61` 只判断 `CLASS_API_NAMES || super.has`，没有 `name == "class"`；`:32-36` 却让 `get("class")` 返回 Class | `cls.class` 可用，但 `"class" in cls` 为 false；依赖 `in` 做能力探测的脚本会误判 |
| C3 | **Class 实例 API 不可枚举** | 未覆写 `getIds`/`getAllIds`；只有 `get`/`has` | `Object.keys(cls)` / `for (var k in cls)` 看不到 `getName/getSimpleName...` 和 `class`；工具/序列化代码可能以为没有这些成员 |
| C4 | **静态字段若为 Function 会被当静态方法** | `:54-56`：`value is Function && value !is NativeJavaClass` → `AijsJavaStaticMethod` | 目标类 public static 字段如果存放 Rhino `Function`/函数对象，会被调用包装；字段读取/赋值语义改变。常规 Java 字段不太可能是 Rhino Function，但这是类型判断缺口 |
| C5 | **Class API 名称是运行时动态集合** | `:70-76` 用 `Class::class.java.methods/fields` | 不同 Android 版本可用 API 不同；写死在报告里的清单只能作为当前环境参考；脚本不要假定 JDK 全量 API |
| C6 | **`classView` 与 `AijsNativeJavaClass` 是两套包装** | `:64-65` 新建 `NativeJavaObject(this,targetClass,Class::class.java)` | `classView` 上的方法/返回值仍走本 WrapFactory；对返回 Class 的方法会再次包装；不是完全原生 Class 对象。一般行为正确，但 identity/cache 与原生不同 |

## 3. `AijsJavaStaticMethod`：整数优先重载的语义缺口

代码位置：`AijsNativeJavaClass.kt:79-223`；`call` 在 `:85-121`，重载选择在 `:125-151`，实参转换在 `:153-184`，数组收窄在 `:186-213`。

| 方面 | 现状 | 丢失/风险 |
|---|---|---|
| 触发范围 | `:104` 仅当任一实参是整数值 JS Number 才尝试自定义重载 | 纯小数/字符串/对象/boolean 参数仍走 Rhino 原实现；这条“只改整数优先”的设计本身正确 |
| 重载选择 | `:125-151` 遍历 public static 方法，按分数选最高 | 分数表只覆盖基本类型；`int` 和 `Integer` 同为 100（`:160-161`），靠 `owner.methods` 反射顺序决定，结果非确定；`float` 整数分数 20、`double` 10（`:170-173`），若同时存在 float/double 会选 float，和原生 Rhino/Java 重载可能不同 |
| 整数范围 | `int` 用 `d > MIN && d < MAX`（`:161`），`long/short/byte/char` 没有范围检查（`:163-169`） | `byte/short/char` 用 `toInt().toByte()/toShort()/toChar()` 会静默截断；`Double.toLong` 对超大值饱和；`Int.MIN_VALUE/MAX_VALUE` 本身被排除在 int 之外。与 `JavaReflectiveInvocation` 的严格范围检查不一致 |
| Object/Number 形参 | 整数 Number 对 `Object/Number` 转 `Integer`（`:174-175`） | 原 Rhino 可能保留 Double；Java 方法通过 `getClass()` 看到 Integer 而非 Double，重载/反射/序列化语义变化 |
| 数组/Object 形参 | `NativeJavaArray` 只在形参 `isArray` 时 unwrap（`:155`）；形参 Object 时 `:179` 直接 `type.isInstance(value)` | 可能把 `NativeJavaArray` 包装对象本身传给 Java Object 形参，而不是 Java 数组 |
| 异常 | `:112-114` 捕获 `InvocationTargetException`，直接抛 `WrappedException(target)` | 不走 Rhino 的 `Context.throwAsScriptRuntimeEx`；与 `AndroidContextFactory.hasFeature(FEATURE_ENHANCED_JAVA_ACCESS)` 只在 `throwAsScriptRuntimeEx` 调用帧打开 feature 13 的机制不完全对齐，Java Error/异常对象形态可能不同；未捕获时错误类型/栈也不同 |
| 函数元数据 | 返回 `BaseFunction` 子类，未实现 `getFunctionName/getLength` 等 | 静态方法的 `fn.name/fn.length`、property/identity 与原生 `NativeJavaMethod` 不同；依赖函数元数据的脚本/序列化可能受影响 |
| 静态字段 | `:54-56` 对任何 `Function` 都包装 | 见 C4 |
| varargs | `parameterCount == args.size`（`:131`） | JS 多参数传给 `String...` 等方法时通常不能命中；会回退原生解析，但“整数优先”在该类 varargs 上不生效；不保证原生 varargs 的展开完全一致 |
| `char`/boolean | `char` 只从 Number 转（`:168-169`）；boolean 未在 `convertArgument` 显式处理 | 混合整数+boolean 的调用若存在候选会被判 INVALID 后回退，通常不丢；但自定义评分表不是完整 Rhino 转换规则 |

## 4. `ReflectiveMethodObject` / `JavaReflectiveInvocation`

包装位置：`RhinoJavaScriptEngine.kt:262-263`；类在 `ReflectiveMethodObject.java:29-59`；转换在 `JavaReflectiveInvocation.java`。

| 覆盖点 | 证据 | 丢失/风险 |
|---|---|---|
| 只替换 `Method.invoke` 属性 | `ReflectiveMethodObject.java:29-59` 只对 `"invoke"` 返回自定义函数，其它成员 `super.get` | `Method` 的 `getName/getParameterTypes/getDeclaringClass...` 等仍是原生 JavaMembers，未丢 |
| 每次 get 新建 invoke 函数 | `:30-57` | `method.invoke === method.invoke`、函数 name/length、缓存 identity 与原生不同 |
| 参数转换 `toJava` | `:61-70`：Number/Boolean/String/Character 原样；其它 `Context.jsToJava(value,Object.class)` | 对 Java 引用类型形参，`JavaReflectiveInvocation.coerce` 的 `target.isInstance(value)` 若 value 仍是 Rhino wrapper，可能不 unwrap，最终把 wrapper 传给反射（`JavaReflectiveInvocation.java:150-153` 直接回退原值） |
| varargs / JS 数组 | `JavaReflectiveInvocation.java:32-73` 只把 `Object[]` 当作显式 varargs 数组；`ReflectiveMethodObject` 的 `toJava` 可能把 Rhino 数组变成 `NativeArray/其他` | JS 数组字面量传给 varargs 的展开语义没有原生反射路径保证；测试只覆盖 Java `Object[]`/primitive varargs（`JavaReflectiveInvocationTest.java:101-120`） |
| 返回值 | `ReflectiveMethodObject.java:45-48` 用 `Context.javaToJS(result,scope)` | 与 Rhino 原生路径大体一致，但会重新触发本 WrapFactory 的 Class/View/Paint 包装；返回值不是“未经过包装”的原生结果 |
| 异常 | `:49-54`：`InvocationTargetException` 取 cause 后 `Context.throwAsScriptRuntimeEx`；其它 Throwable 同样 | 异常路径比 `AijsJavaStaticMethod` 更接近 Rhino；仍受 `AndroidContextFactory` feature 13 条件影响 |
| 目标对象 | `toJava(args[0])` | 目标为 JS 包装的 Java 对象时依赖 jsToJava unwrap；若失败会在反射层报 argument type mismatch |
| 严格范围 | `JavaReflectiveInvocation.coerce` `:75-153` 对整数/char 有范围检查 | 比静态方法包装严格；但 `target == Object/Number` 保留原值（`:76-79`），与静态方法包装“整数转 Integer”不一致——两条路径的语义不同 |

## 5. `AndroidContextFactory` 的覆盖与语义

| 覆盖点 | 代码 | 覆盖/丢失 |
|---|---|---|
| XML 安全解析探测 | `AndroidContextFactory.java:73-77, 111-132` | 平台不支持 `FEATURE_SECURE_PROCESSING` 时返回 false，关闭 Rhino E4X 的强制安全配置；平台支持时保持。丢失的是“强制安全解析”的保证，换 XML 可用性 |

### `setJavaPrimitiveWrap(false)` 的具体影响清单

- Java 方法声明为 `Object`/`Number` 返回值时，`Boolean/Integer/Long/Double/Float/Character/Byte/Short` 变成 JS 原始值，`typeof` 从 `object` 变为 `boolean/number/string`。
- 原 Rhino 下可对这些返回值调用 Java 方法（`getClass()`、`toString()`、`equals()` 等）或依赖 `NativeJavaObject` 的 `getClass` 判断；关闭后数字/布尔没有 Java 方法。
- `instanceof Object`/`instanceof java.lang.Integer`、JS 严格相等、对象 identity 行为改变。
- `java.util.Map.get`、`List.get`、反射 `Method.invoke` 等常返回 Object 的接口最容易触发。
- 该选择是 Pro 对齐（`if(javaBoolean)` 恒真历史 bug），不是错误；但应在产品文档/回归中明确“Object 位置的 Java 基本类型不再装箱”。

## 8. View/NativeView、ScriptJavaObject 等其它包装

### 8.1 `NativeView` + `ViewExtras`

| 点 | 证据 | 语义/风险 |
|---|---|---|
| View → NativeView 缓存 | `ViewExtras.java:47-55` 按 View tag 缓存 | 同一 View 被不同脚本/引擎复用 NativeView 时，可能保留旧 scope/prototype/回调；跨脚本隔离需验证 |
| 子 View 按字符串 id 查找 | `NativeView.java:100-105` | 缺失 Java 成员时若子 View id 同名，返回 View；`has` 未同步（`:67-73`），`in` 与 `get` 不一致；缺失成员从“报错/undefined”变成 View |
| 属性 | `:68-72, :76-99` | ViewAttributes 走 prototype；`get` 对普通属性/方法走 super；非属性名可能落到子 View |
| 箭头函数适配 | `:86-98, :152-175` | 只对包含 `Listener` 或 `post/postDelayed/postOnAnimation...` 的函数包 `AdaptedFunction`；其它 Java 接口回调仍可能不接受箭头函数 |
| WebView client | `:77-83, :117-146` | 只对 `setWebViewClient` 特判 `InjectableWebClient`；其它 client/子类不受影响 |
| NativeView prototype | `:62-64` | prototype 是 `NativeJavaObjectWithPrototype`；对象成员/符号属性；枚举缺失见总表 |

### 8.2 `ScriptJavaObject`

- `ScriptJavaObject.java:23-27`：`supports` 覆盖 Context/WindowManager/MediaPlayer/MediaSession/Closeable。
- `:29-52`：只包装 `registerReceiver/unregisterReceiver/addView/removeView/removeViewImmediate/release/close`；成功调用后 `resources.called`。
- 丢失：这些成员返回的是新的 `BaseFunction` 包装，identity/name/length 与原生 Java 方法函数不同；`has/getIds` 未改，属性枚举看不到包装；被观察方法是否抛异常不影响 wrapper 创建，但 `resources.called` 只在成功返回后调用。
- 未覆盖：Closeable 的其它方法（如 `flush`）不观察；Context 的其它生命周期方法不观察。

### 8.3 `OverridingJavaObject` / `ProxyJavaObject`

- `OverridingJavaObject.java:49-81`：`__overrides__` 优先；`getIds` 未覆盖；`get` 当 override 返回 null 时不回退；只服务资源垫片场景。
- `ProxyJavaObject.java:30-68`：`put` 有 setter 时不再 `super.put`；`get` 把 Java null 当未找到继续 getter（`:54-62`）；`getDefaultValue` 固定 `toString()`（`:66-68`）；`has` 不反映动态键。
- `ProxyObject` 是 `NativeObject` 子类（`UI` 使用），不是 Java 对象包装；不在本次 Class 语义表内。

### 8.4 死代码/潜在雷

- `BindingNativeJavaObject.java:19-29`：`initMembers` 空实现；若未来被接入，所有 Java 成员解析都会消失。
- `NativeJavaClassWithPrototype.java`：当前 main 无调用；`memberNotFound` 检查 `NativeJavaObjectWithPrototype` 字符串（`:86-88`），不是本类，保护条件不匹配；`getIds` 未覆盖。
- `TopLevelScope`、`AutoJsContext`、`NoSecurityController`、`AndroidClassLoader`：属于 context/scope/classloader 基础设施，不是 Java 对象包装主路径；其中 `NoSecurityController.getDynamicSecurityDomain` 恒 null（`:19-22`）是安全语义选择。

## 9. 结论：还有没有同类隐患？

**有。** Class 实例 API 的修复只补了“Class 作为 Class 实例”的那一层，没有恢复“包装子类仍应遵守 NativeJavaClass/NativeJavaObject 的静态/实例优先级”这一层：

1. **最高优先级**：`AijsNativeJavaClass.get` 的 Class API 优先（`:42-45`）会遮蔽目标类静态成员；`RomUtil.getName()`、`PFiles.getName(path)` 是可复现的真实类。建议把“静态成员优先、Class 实例成员回退”作为默认顺序，或明确制定同名规则并加测试。
2. **一致性**：`has("class")`、`getIds` 未与 `get` 同步；`"class" in cls`、`Object.keys(cls)` 结果不可靠（`:60-61`，无 `getIds`）。
3. **静态方法包装**：整数优先/无范围检查/`InvocationTargetException` 直包装/函数元数据丢失，与 Rhino 原生重载和 `JavaReflectiveInvocation` 严格转换不一致（`AijsNativeJavaClass.kt:125-184`；对照 `JavaReflectiveInvocation.java:75-153`）。
4. **全局 primitive wrap**：`setJavaPrimitiveWrap(false)` 改变 Object 位置基本类型的所有语义（`RhinoJavaScriptEngine.kt:241`）。
5. **特化包装**：`UiObjectCollection` 数组化、`View` 子 View 查找/缓存、`Paint` int 优先丢返回值、`Method.invoke` varargs/引用类型、`ScriptJavaObject` 函数 identity 等都各有边界（见第 4–8 节）。

### 建议的回归测试（不改产品代码，供后续修复使用）

- Class 实例 API：`obj.getClass().getName()/getSimpleName()/getSuperclass()/isAssignableFrom(...)/getDeclaredMethods()/getFields()/getEnumConstants()`；`"class" in cls`；`Object.keys(cls)`。
- 静态冲突：`Packages.ezy.assist.compat.RomUtil.getName()`（0 参 static）、`Packages.com.stardust.pio.PFiles.getName(path)`（1 参 static）、以 `Packages.java.lang.String.getName()` 作为 Class API 对照。
- 静态包装：`String.valueOf(123/1.5)`、`Math.max(1,2)`、`Array.set(int[],0,5)`，以及 `Integer.valueOf(...)` 返回 Object 的 `getClass()`/typeof 对照。
- 反射：`Method.invoke(target, jsObj)`（引用类型形参）、显式 JS 数组传 varargs、Java Error/Exception 的 catch 形态。
- 原始 wrap：Java 方法返回 `Object` 的 Integer/Boolean 的 `typeof`、`getClass`；`UiObjectCollection.size()/isEmpty`；`Paint.setColor` 返回值（若有）；View 子 id 与 `in`。
