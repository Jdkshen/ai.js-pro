# 应用内更新安装失败修复（FileProvider → PackageInstaller 会话）

> 2026-11-02。现象：手机内「检查更新」能发现新版本、下载与 SHA-256/签名校验都通过，但点安装后没有安装界面（或提示「找不到安装应用的活动」）。真机日志定位到 androidx FileProvider，改为 PackageInstaller 会话安装后修复；dev-1318 发布。

## 一、现象与定位

真机（.4 Android 17、MI8 Android 15 均可复现）日志：

```text
W System.err: java.lang.IllegalArgumentException: Missing android.support.FILE_PROVIDER_PATHS meta-data
W System.err:   at androidx.core.content.FileProvider.getFileProviderPathsMetaData(SourceFile:718)
W System.err:   at androidx.core.content.FileProvider.parsePathStrategy(SourceFile:737)
W System.err:   at androidx.core.content.FileProvider.getPathStrategy(SourceFile:687)
W System.err:   at androidx.core.content.FileProvider.getUriForFile(SourceFile:466)
W System.err:   at com.stardust.util.IntentUtil.getUriOfFile(SourceFile:140)
W System.err:   at com.stardust.util.IntentUtil.installApk(SourceFile:108)
W System.err:   at com.stardust.util.ApkInstallActivity.startInstaller(SourceFile:112)
```

下载器、UpdatePackageVerifier（SHA-256、包名、签名）都正常；失败点只在最后把文件交给系统安装器这一步。

## 二、根因

- androidx.core:core:1.13.1 的 FileProvider.parsePathStrategy 先调用
  PackageManager.resolveContentProvider(authority, GET_META_DATA)，再对返回的 ProviderInfo
  调用 loadXmlMetaData(...)。
- 实测这两台设备上该 API 返回的 ProviderInfo.metaData 为 **null**，而同一 APK 用
  getPackageInfo(GET_PROVIDERS | GET_META_DATA) 取到的 provider 却有
  android.support.FILE_PROVIDER_PATHS，XML 也能正常打开（说明 APK/清单本身没问题）。
- metaData == null 时 loadXmlMetaData 必然返回 null → FileProvider 抛上面那条异常；
  ApkInstallActivity 捕获后只弹「找不到安装应用的活动」，用户看到的就是「更新不了」。
- 影响面：所有走 FileProvider 装 APK 的入口（应用内更新、MCP apk_install 最终都走
  ApkInstallActivity），与具体版本无关；只有手动 adb / 文件管理器安装才不受影响。

## 三、修复

modules/common/src/main/java/com/stardust/util/ApkInstallActivity.java：

1. **优先 PackageInstaller 会话安装**（不依赖 FileProvider/content URI）：
   - SessionParams(MODE_FULL_INSTALL) → createSession → openWrite/fsync 写入 APK；
   - 动态注册 RECEIVER_NOT_EXPORTED 接收器，session.commit(pendingIntent.getIntentSender())；
   - STATUS_PENDING_USER_ACTION → 用返回的 EXTRA_INTENT 拉起系统安装器；
     失败/成功分别提示并收尾，异常时 abandonSession。
2. 会话不可用（非 Android 8+、ROM 限制等）时**回退**旧的 FileProvider + ACTION_VIEW 流程。
3. 「安装未知应用」授权流程保持不变（Android 8+ 未授权仍先跳设置页）。

## 四、验证

- 两台真机先安装 dev-1317（含修复；旧内置更新已坏，需手动装一次）：
  - .4（Android 17）：经 Shizuku shell pm install -r /data/local/tmp/aijs-1317.apk
    （/sdcard 因 SELinux 不可直接读，先拷到 /data/local/tmp）。
  - MI8（Android 15）：adb install -r。
- 在两台机器上调用安装入口（与更新按钮相同的 IntentUtil.installApkOrToast）：
  - 无 FileProvider 异常；
  - .4 直接拉起系统安装器（com.miui.packageinstaller 的 InstallStart / NewInstallerPrepareActivity）；
  - MI8 因未开启「安装未知应用」正确跳到该设置页（允许后返回继续，属预期行为）。
- dev-1317：144,048,420 B，SHA-256 5484e4490ef9b45098482fb887f17ae4a001edb328f83d68fef585b4132ebc0c（修复后的测试包，未发布）。
- dev-1318：144,048,424 B，SHA-256 c96dd6c00117315f32de72cdb3c47a62dde7ea6b263ec90b450dc5f281aabb91，已发 LAN。
- **端到端复测（.4 运行 dev-1317，LAN 为 1318）**：直接调用与「直接下载」按钮相同的链路——
  `VersionService.checkForUpdates` → 检出 1318（isNewer=true）→ 下载 144,048,424 B →
  `UpdatePackageVerifier.verify`（SHA-256/包名/签名）通过 → `IntentUtil.installApkOrToast` →
  系统弹出 MIUI 安装器（`com.miui.packageinstaller`，界面含「未查询到此应用的 ICP 备案信息」「继续安装 / 退出」）。
  说明内置更新已恢复。

## 五、边界与后续

- 已经安装 ≤ dev-1316 的设备，内置更新仍然是坏的，需要**手动安装一次** dev-1317+（本次 .4 用 Shizuku、MI8 用 adb 完成）；之后应用内更新恢复。
- K40 仍为 dev-1312，未改动（业务机）；需要时应手动升级一次。
- 会话安装会拉起系统安装确认界面，不会静默安装；「安装未知应用」权限仍由用户控制。
