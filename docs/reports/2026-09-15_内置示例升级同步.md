# 内置示例升级后不会自动更新（已修）

日期：2026-09-15　相关版本：dev-602

## 现象

新版本里改好的示例，手机**升级安装后仍然是旧的**：
「示例」在新版本里已经修好（本仓库 2026-09-15 修了 7 个一运行就报错的 Rhino 样例、
2 个 OCR 样例改用内置 `ocr` 模块），升级后从**文件管理 →「示例」文件夹**里点开跑，
照样是旧的报错内容，必须手动点「重置所有示例」才对。

## 根因

示例目录是**懒拷贝**：`WorkspaceFileProvider.listSamples()` 在浏览到某个示例目录时，
只对**磁盘上不存在**的文件才从 `assets/sample` 落盘：

```java
PFile file = new PFile(new File(directory, child).getPath());
if (file.exists()) {
    return file;          // ← 存在就返回，内容不比对、不覆盖
}
```

升级 APK 只会替换 APK 内的 `assets/`，**不会碰** `files/sample`，于是：

| 面 | 内容来源 | 升级后是否最新 |
| --- | --- | --- |
| 发布的 APK | `assets/sample` | ✅ 与仓库逐字节一致（362 个文件零差异） |
| 示例页（Miuix）「运行」 | `assets`（`SampleFile.toSource()` → `AssetManager.open`） | ✅ 总是最新 |
| 示例页「查看/编辑」 | 导入到**脚本目录**的副本 | ❌ 不覆盖（编辑器内有「重置」入口，会先备份） |
| 文件管理 →「示例」文件夹 | `files/sample` 懒拷贝 | ❌ **存在即跳过，永远停在首次落盘那份** |

设备实测（K40，当时装的 dev-600）：4 个样例的 md5 全部等于**修复前**那个版本的内容，
说明磁盘副本确实没跟着版本走。

## 修法

新增 `BundledSampleSync`（`model/sample/`），在 `App.onCreate → init()` 里调用
`syncIfNeeded(this)`：**versionCode 与上次同步时不同**（`Pref.getSampleSyncedVersionCode()`）
才跑一次，且跑在 IO 线程上，任何异常只记日志，不影响启动。

同步规则：

1. 磁盘没有 → 从 assets 落盘（`created`）；
2. 与内置内容逐字节一致 → 跳过（`unchanged`）；
3. 内容不同，但磁盘那份 == 上次同步写下的 md5（说明用户没动过，差异来自内置版本更新）→ 直接覆盖（`updated`）；
4. 否则（首次同步，或与记录不符 = 用户改过）→ **先把磁盘那份备份到 `files/sample-backup/<相对路径>`**，再覆盖。

内置里没有的文件（用户自己放进示例目录的）一律不碰，也不删除内置里已下架的旧文件。
每次同步结束把「写下去的内容 md5」记到 `files/sample-sync-state.txt`，供下次区分
「只是版本旧」和「用户改过」。

## 真机验证（K40 `cccc62c7`）

安装本次构建（versionCode 465，覆盖已装的 dev-600）后启动：

```
[首次同步] 内置示例已对齐到 versionCode 465：新增 23，更新 23，已是最新 316，备份用户改动 23
  → 设备上 OCR 样例 md5 338531c3（旧） → 1f9e8ba5（新，= 仓库 = 发布包）
  → 备份里的那两个 OCR 样例 md5 = 338531c3 / ab3c1fe9，即「覆盖前的那份」，没有静默丢内容
[第二次启动] 无同步日志（版本门控生效），样例 mtime 不变
[强制再同步一次] 新增 0，更新 0，已是最新 362，备份 0
  → 幂等：不会反复覆盖，也不会让备份目录越滚越大（仍 23 个文件）
[模拟用户改过某个示例] 往 RootAutomator2.js 追加一行后强制再同步：
  新增 0，更新 1，已是最新 361，备份用户改动 1
  → 备份目录 23 → 24，备份里那份 == 用户改后的 49d9176c
  → 示例本体已还原成内置版 8d8cdf96
```

复现脚本（都在 `.artifacts/`，目录本身不入 git）：

- `.artifacts/tools/cmp-samples.py`：比对「设备 `files/sample` / 仓库 assets / 已发布 APK」三份内容
- `.artifacts/tools/device-touch-sample.py <设备号> mark`：改写设备上的某个示例（中文路径由设备侧 `find` 取回，
  重定向在 `run-as` 内部执行，避免 shell uid 权限不足）

## 没验证到的 / 已知取舍

- **首次同步会备份 23 个文件**：这一版是「第一次带同步逻辑的版本」，没有历史记录可比对，
  按「可能是用户改过的」处理 —— 备份内容正确（= 覆盖前那份），代价是首次多出 23 个备份文件。
  之后每次同步只有真正内容变化的文件才会产生备份。
- 备份目录 `files/sample-backup/` 在应用内**不可见**（示例文件夹的列表来自 assets），
  只能通过 adb/文件传输查看；保留它是为了「用户改动不静默丢失」。
- 内置里已下架的旧示例不做删除（留在磁盘上，列表来自 assets 所以也看不见）。
- 只同步「文件管理里的示例文件夹」；示例页「查看/编辑」导入到脚本目录的副本仍由编辑器内的
  「重置」负责（那条链路本来就会先备份）。
