## 2. Bug3 ★① 落地：端口探测改主动 socket.connect（W1 task-24）

- 新增 `ToolkitFridaPortProbe`：`Socket().connect(host,port,timeoutMs)`，四态 `listening_reachable / refused / timeout / error:<异常类名>`，**超时与拒绝分开**；`probeTimeoutMs` 默认 800（50..10000 可调）。
- `frida_status / frida_processes / frida_eval` 统一返回 `probe{...}`，且探测**放在组件解析之前** → 未装 frida 组件也能拿到端口证据。
- `/proc/net/tcp[6]` 降级为**可选补充**：读不到只记 `readable=false/readError`，**不再等于「端口未监听」或「组件未安装」**；`connectDiagnosis` 增加 `recommendations/recovery`，首条即「应用域读不到 /proc 是预期，以 probe 为准」。
- 分类：`probe=timeout && !sameUid` → `selinux_loopback_suspect`；`probe=reachable` → 直接否掉 DROP（`port_reachable`）。

## 4. 未做 / 边界

1. **§11 P2（统一二进制变换 / VM 辅助）未做**：需要先定算法清单与验收口径（他们文档里也只给了方向）。
2. 真 `timeout` 的**成因**未独立证明（K40 上空地址超时符合预期，但「SYN 被 SELinux 丢弃」与他们设备上的表现只在他们的证据链里）；`probeTimeoutMs` 默认 800ms 会让端口挂起时 `frida_status` 多等最多 800ms（与「只读快路径」有张力，已留参数）。
3. `frida_session_open/read/close/list` 四个工具**未加 probe**（本轮只统一了 status/processes/eval）。
4. probe 只证明网络可达性，**不能**证明 token/版本/握手层问题（K40 未装组件，那条无法验证）。
5. `/proc/net/tcp` 仍是可选补充（有 root/shizuku 时可用于交叉核对），未删除相关命令。
