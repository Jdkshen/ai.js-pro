# 2026-10-19 Node UI 返回键语义（task-178）

> 用户反馈：Node UI（NodeUiActivity）按导航返回键后脚本没有立即结束，页面返回/桌面后脚本仍在跑。
> 目标：查 Pro 的 ScriptExecuteActivity / V8ScriptExecuteActivity 返回键实现，对照实现我方语义：返回 = 结束对应 execution + 关闭 Activity + 清理 overlay，并做 K40 验证。
> 改动范围：apps/app/src/main/java/com/jdkshen/aijspro/engine/NodeUiActivity.java、NodeUiBridgeService.java；docs/reports。

## 0. 结论

1. Pro 9.3.11 的返回键语义分两种：
   - Rhino UI（ScriptExecuteActivity，:script 进程）：返回先发 JS back_pressed 事件，JS 可 consume 阻止退出；未 consume 则 super.onBackPressed → finish → onDestroy 里 scriptEngine.destroy()，脚本结束。无确认弹窗。
   - Node UI（V8ScriptExecuteActivity，:script 进程）：onBackPressed 只走 JS delegate（__onBackPressed）；没有 JS 接管时退回 super.onBackPressed（Activity finish）。onDestroy 只 delegate super.onDestroy，没有 engine stop/destroy。即 Pro 的 Node UI 默认返回只关闭 Activity，不立即结束 Node 脚本；没有确认弹窗。
   - 所以「高级版是不是返回立即结束」：Rhino UI 是；Node UI 默认不是。用户看到的现象与此一致，但产品要求我们返回即结束。
2. 我方旧实现：NodeUiActivity 无 onBackPressed；默认 finish → onDestroy → CloseListener → :node24 NodeUiHost.onClosed 置 CLOSE_REQUESTED → Node24Service.UiLifecycleWatcher 每 200ms 轮询，UI closed 后再等 1s 宽限（fallback 3s）才 cancel native。因此返回后脚本还会跑 1s+，任务页 :script token 也在这之后才收尾。
3. 新语义：NodeUiActivity.onBackPressed → NodeUiBridgeService.requestStopForBack(session, projectDir) → 按 session/projectDir 找到 :node24/_N 的 active job id → 广播 ACTION_NODE24_CONTROL(cancel,id) → Node24Service 立即 cancel native/关 UI → Node24JavaScriptEngine evaluate 返回 CANCELLED → :script 宿主 token 收尾；Activity 同时 finish，onDestroy 的 destroy 事件继续清 overlay。返回后不再等 1s 宽限。
4. 无确认弹窗：Pro 两个 Activity 都没有确认框；我方也没加，保持返回即停。

## 1. Pro 证据（类/方法/行号）

反编译源码：.artifacts/pro-apk/auma-src/sources（jadx）；样本 APK：output/auma-base.apk（com.boyai.auma 9.3.11-0）。

### 1.1 Rhino：com.stardust.autojs.execution.ScriptExecuteActivity

文件：.artifacts/pro-apk/auma-src/sources/com/stardust/autojs/execution/ScriptExecuteActivity.java

- onBackPressed（约 611-618 行）：new SimpleEvent() → emit(back_pressed, simpleEvent)；if consumed return；否则 super.onBackPressed()。
- finish（约 442-462 行）：mScriptExecution 非空时，有未捕获异常则 onException，否则 notifySuccess；再 super.finish()。
- onDestroy（约 639-682 行）：清 sInstances；mScriptEngine 非空时 notifySuccessIfNotFinished、scriptEngine.put(activity, null)、scriptEngine.setTag(activity, null)、最后 scriptEngine.destroy() → 引擎销毁、脚本结束。
- onKeyDown（约 692-697 行）：emit(key_down, keyCode, event, SimpleEvent)；consumed 或 super.onKeyDown。
- 结论：Rhino UI 返回 = finish + engine destroy = 结束脚本；JS 可 consume back_pressed/key_down 阻止；无确认弹窗。

### 1.2 Node/V8：org.autojs.autojspro.v8.api.ui.V8ScriptExecuteActivity

文件：.artifacts/pro-apk/auma-src/sources/org/autojs/autojspro/v8/api/ui/V8ScriptExecuteActivity.java

- onBackPressed（1932-1934 行）：doDelegateMethod(new C6971(), onBackPressed, new Object[0])。
- doDelegateMethod（1785-1814 行）：从 JS delegate 对象取 __ + method；若是 V8Function 则调用 JS；否则 callSuper.call(...)。
- 默认 C6971.call（450-460 行）= V8ScriptExecuteActivity.super.onBackPressed() → Activity 默认 finish。
- onDestroy（2079-2081 行）：doDelegateMethod(new C6991(), onDestroy)；默认 C6991.call（744-754 行）= super.onDestroy()，没有 Rhino 的 engine.destroy/notify 逻辑。
- 内部类 C6956 extends f26（132 行起）：mo4026 在 Activity 启动时 notifyStart 并触发 JS newActivity；mo4027 在 Node 引擎结束时 notifySuccess；Activity finish 不是执行结束信号。
- JS Activity 基类（APK assets/v8/built_in_modules/ui/activity.js）：Activity extends AndroidActivity；__ 代理把 __onBackPressed 委派给 JS onBackPressed；用户 Activity 可定义 onBackPressed 接管。默认基类无强制 stop。
- 结论：Pro Node UI 返回默认只 finish Activity，不立即结束 Node 脚本、不弹确认；是否结束由脚本自己的 onBackPressed/生命周期决定。

### 1.3 与浮窗的关系

- Rhino UI 与 Node UI 的 Activity 在 Pro 都声明在 :script 进程（manifest：ScriptExecuteActivity / V8ScriptExecuteActivity process=:script）；Activity 结束就是执行宿主结束（Rhino 直接 destroy；Node 由执行层/Service 关闭链路兜底）。
- Pro 的浮窗（FloatyService/FloatingControllerView）不是 Activity，系统返回键不直接投递给浮窗；浮窗关闭走自己的 close 按钮/回调。

## 2. 我方旧实现与问题定位

文件：apps/app/src/main/java/com/jdkshen/aijspro/engine/NodeUiActivity.java

- 旧代码无 onBackPressed/onKeyDown；系统返回走 AppCompatActivity 默认 → finish()。
- onDestroy（旧 659-681 行）只清 sCurrent、notifyClosed（CloseListener）、super.onDestroy。
- CloseListener 由 NodeUiBridgeService.onCreate 设置（session -> dispatchClosed(session)）；dispatchClosed 向 :node24 的 NodeUiActivityClient 发 MSG_EVENT(type=destroy)。
- Node 侧 NodeUiHost.onClosed()（modules/engine/.../NodeUiHost.java 约 370-379 行）置 sActivityMode=false、CLOSE_REQUESTED=true、enqueueEvent(destroy)、setUiMode NONE。
- Node24Service.UiLifecycleWatcher（约 544-634 行）每 200ms 轮询 hasNodeUiActivity/hasUiOverlay；看到 UI 从有到无且 closeRequested 后，再等 UI_CLOSE_GRACE_MS=1000ms 才 engine.cancel()；UI missing fallback 是 3000ms。
- 旧行为：返回 → Activity 关闭 → 1s/3s 后才 cancel native → Node24JavaScriptEngine.evaluate 返回 CANCELLED → :script token 收尾。期间任务页仍显示、脚本仍在跑。
- 旧实现没有把「返回」和「脚本结束」显式关联：Node 脚本忙循环/阻塞时，UI 关闭后只能等 watcher 超时。

## 3. 我方新实现（task-178）

### 3.1 NodeUiActivity.onBackPressed

NodeUiActivity.java 新增字段 mBackStopRequested（防重复）和：

    @Override public void onBackPressed() {
        if (mBackStopRequested) { super.onBackPressed(); return; }
        mBackStopRequested = true;
        Log.i(TAG, NodeUiActivity: C-BACK pressed session= + mSessionId + project= + mProjectDir);
        try { NodeUiBridgeService.requestStopForBack(mSessionId, mProjectDir); }
        catch (Throwable error) { Log.w(TAG, requestStopForBack failed, error); }
        super.onBackPressed();
    }

- 顺序：先请求 stop（异步 Binder/广播），再 finish Activity；不阻塞主线程。
- 旧链路保留：onDestroy → notifyClosed → bridge dispatchClosed destroy → NodeUiHost 关闭状态/清 overlay。

### 3.2 NodeUiBridgeService：session/projectDir → Node job id

- 字段：NODE_JOBS（job id → NodeJob(id, filename, uiScript, startedAt)，由 Node24Service.ACTION_NODE24_STATE 广播维护）；SESSION_PROJECTS（session → projectDir）；SESSION_JOBS（session → job id，show 时尝试绑定，started 广播晚到后按 projectDir 补绑）。
- onCreate：installNodeJobReceiver() + queryNodeJobs()（向 :node24/_N 主动 query active job，避免广播早于服务创建）。
- requestStopForBack(session, projectDir) 静态入口：主线程 stopNodeJobForBack → resolveNodeJobForBack 优先 session 映射；其次按 projectDir 与 job.filename 父目录匹配（canonical File，兼容 staging 私有目录）；取最近 startedAt 的 uiScript=true job。
- 找到后 cancelNodeJob(jobId)：Intent(ACTION_NODE24_CONTROL).setPackage(...)，extra command=cancel、id=jobId；未找到则 query 一次、350ms 重试；仍无则记日志并依赖旧 UI close 兜底（不误杀其它 Node 脚本）。
- 映射规则避免误杀：只接受 uiScript=true 且有 projectDir 匹配的 job；projectDir 为空退化为最近启动的 uiScript；匹配不到不 cancel。

### 3.3 结束链路（与 task-175 token 体系配合）

    NodeUiActivity.onBackPressed
      → NodeUiBridgeService.requestStopForBack(session, projectDir)
      → resolveNodeJobForBack → jobId（:node24_1..3 当前 active job）
      → sendBroadcast(ACTION_NODE24_CONTROL, command=cancel, id=jobId)
      → Node24Service.Job.cancel()：failPendingForCancel、Node24Engine.cancel() native 立即取消、cleanup 线程 closeUiAfterExecution 关 UI/floatingWindow；当前实现 cancel 的 800ms force halt 对池进程同样生效（实测 :node24_N 被结束），legacy :node24 也会 halt —— 见 §5/§6 的引擎侧跟进
      → Node24Engine.execute 返回 CANCELLED → Node24Service.reply(status=CANCELLED)
      → Node24JavaScriptEngine.doExecution 抛 ScriptInterruptedException
      → :node24 进程被 force halt 时 Node24Client 报 Node24 service disconnected → :script PocScriptHost execution 失败结束 → token 移除（任务页该任务消失，但状态是失败）
      → Activity finish + onDestroy destroy 事件继续清主进程窗口

- 说明：Activity 只知道 Node UI session，不知道 :script 的 token；不能直接调 :script stop。新实现通过 :node24 active job id 取消真实执行，:script token 随 evaluate 返回自然收尾——等价于 cancel 对应 execution。
- 为什么不在 Activity 里直接 PocScriptHost.stop(token)：主进程没有 :script token（Node 任务 token 在 :script PocScriptHost；Node UI Activity session 是另一个 UUID），且 :script 进程只能 Binder 操作。当前取消链从 :node24 入口走，状态会广播/回传，不会误杀 :script 其它 Node job。
- 浮窗 overlay：Node24Service.cancel 的 closeUiAfterExecution 调 Node24HostBridge.closeUiOverlay()：先 floatingWindow closeAll，再 NodeUiHost close；主进程 NodeUiBridgeService 的 OVERLAYS 被清空。全屏 Activity 有系统返回键走新 cancel；浮窗没有 Activity onBackPressed，仍走 ✕/close 回调 + CLOSE_REQUESTED/Watcher（本次不改）。

## 4. 与 Pro 差异（有意选择）

| 项 | Pro Rhino UI | Pro Node UI | 我方新实现 |
| --- | --- | --- | --- |
| 返回键动作 | JS back_pressed 可 consume；否则 finish | 只 delegate JS __onBackPressed；默认 super.onBackPressed=finish | 直接请求 cancel 对应 Node job，再 finish |
| 是否结束脚本 | 是（onDestroy scriptEngine.destroy） | 默认否（onDestroy 不 stop engine） | 是（cancel native；当前引擎侧 force halt 让 :script 以 IOException 收尾并移除任务） |
| 确认弹窗 | 无 | 无 | 无 |
| JS 可否拦截 | 可 consume back_pressed/key_down | 可由 Activity.onBackPressed 接管 | 本版不支持拦截；按产品要求返回=结束；如需支持需新增跨进程回执协议 |
| overlay 清理 | Activity/浮窗各自 | NodeUiHost close/CLOSE_REQUESTED | Node24Service cancel cleanup 统一 closeUiOverlay + Activity onDestroy destroy |

## 6. 风险与限制

1. JS Activity 的 onBackPressed 拦截被移除：Pro Node UI 允许脚本接管（如简易文件浏览器 WebView 返回上一级）；本实现按 Lead 要求返回=结束 execution，会直接结束。若后续要保留脚本拦截，需要 Node→Java 的「是否 consume」回执，当前未做。
2. session↔job 映射依赖广播时序：show 早于 started 广播时用 projectDir 匹配+query 兜底；若同一 project 同时跑多个 uiScript Node 任务（理论上 pool 支持并发），选最近启动的一个；映射失败则不 cancel，退化为旧 UI close 宽限行为（不会误杀）。
3. legacy :node24 回退：Node24Pool.legacyEnabled 时也走同一 ACTION_NODE24_CONTROL 协议，Node24Service（非池进程）cancel 后会按原逻辑 halt，行为一致。
4. 池进程行为与 task-175 文档不一致：Node24Service.Job.cancel 的 800ms force halt 对 :node24_N 同样生效，实测返回键取消后 :node24_1 消失且 Node24Client 报 disconnected，:script 任务以 IOException 收尾。建议引擎侧把 pool 进程的 cancel 兜底改成不 kill（保留 warm 复用），让 evaluate 返回 CANCELLED，任务页显示取消而非失败；这属于 modules/engine 的后续改动，不在本次写作用域。
5. 返回键只在 NodeUiActivity（全屏 Activity）生效；floating overlay 没有系统返回键，仍由 ✕/close/stop 入口关闭。
