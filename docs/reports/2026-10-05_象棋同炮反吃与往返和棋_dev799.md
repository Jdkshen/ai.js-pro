# 象棋同炮反吃与连续往返修复

## 现场

K40 dev-798 / 象棋 0.6.67，08:40:53 开始、09:11:40 结束的这局，结果页面显示人机对战总步数达到上限判和。原日志已保存为 `.artifacts/k40-draw-dev798.log`，结果截图为 `.artifacts/k40-draw-dev798.png`。

与前一局故障不同，本局没有持续账本拒收，已有避重复候选确实换过招。仍有三处遗漏：

1. 08:45:59 黑炮 `d7d2` 吃红炮，旧红炮落点事实被找色证伪，程序把前基准里的红炮先置空，resync 重开历史。随后借回旧盘推导出真实应手，但先前棋谱已经丢失。
2. 求胜下限原为 0cp。后半局 -6～-11cp 的近均势评分关闭了安全换招比较。
3. 原检测仅比较整盘加走方。对手不同应手时，我方车 `e4d4 / d4e4` 连续往返也不会形成相同整盘，因此未进入重复候选。

## 修改

- 观察层只在原始新盘具有唯一合法应手解释、落点实际读数一致且阵营证据支持观测时，撤销旧落点提示并保留完整前盘面。仍由轮次层跨帧佐证后连续入账；不把预测写成观测。没有唯一解释的冲突继续执行原修订路径。
- 默认求胜窗口改为行棋方视角 -25～80cp，仍遵守现有 20cp 分差、搜索深度和杀分保护；用户显式配置下限 0 仍有效。保护日志说明评分窗口造成的回退。
- 只记录成功、非重复入账的我方着法。连续三次同子 `A→B、B→A、A→B` 后，下一次 `B→A` 成为软偏好候选；对方每次走不同着法也适用。任何一方吃子、无着法的新基准、基准修订、换局、换边都清空往返段。
- Worker 与同步搜索使用同一候选出口和评分保护。往返着法不加入硬排除表；无可靠替代时保留引擎首选。
- 更新工程 README 与项目结构文档。
