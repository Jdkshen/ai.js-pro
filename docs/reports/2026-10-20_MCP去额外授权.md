# MCP 去额外授权（dev-1157）

- 时间：2026-10-20
- 背景：用户在手机端找不到「编辑授权 / 运行授权」开关（该 UI 原在已移出构建的 Miuix 页面），MCP 工具实际永远拒绝写入/运行（`写入授权未开启` / `运行授权未开启`）。
- 决定：**MCP 服务开启即视为完整授权**，不再要求额外开关。

## 改动

1. `McpService.kt`：服务启动后 `allowWrite = true`、`allowExecution = true`（仅运行期间有效，停止即复位 false）；启动历史记录改为「已授权读写/运行」。
2. `McpTools.kt`：移除 `run_script/stop_script/engineProbe` 里的运行检查、`requireWrite()/requireExecution()` 改为 no-op；工具描述与 `initialize.instructions` 去掉「需运行/写入授权」，改为「MCP 服务开启即拥有读写与运行权限（局域网访问仍需 Bearer token）」。
3. 安全边界保持在网络层：局域网请求必须带 `Authorization: Bearer <token>`；本机 loopback 免 token；「局域网免令牌」危险开关默认关闭（未改）。

## 验证（K40，dev-1157）

- 抽屉 → MCP 服务打开：`C-MCP: state=running port=8765 lanUrl=http://192.168.10.5:8765/mcp`。
- 从 PC 用 LAN + Bearer token 调 MCP：
  - `initialize` → 200，instructions 已是新文案；
  - `workspace_mkdir {path:"__mcp_noauth_probe"}` → `created:true`，设备 `/sdcard/脚本/__mcp_noauth_probe` 存在；
  - `run_script {source:"console.log('MCP_AUTH_PROBE_OK'); files.write(...)"}` → 返回 `executionId=mcp-1`，logcat 出现 `MCP_AUTH_PROBE_OK`，`/sdcard/脚本/__mcp_noauth_probe.txt` 内容 `ok`。
- 验证后已清理探针目录/文件。

## 版本

- dev-1157 已发布到本地更新源；K40 / MI8 已安装。
- 后续如需「恢复授权开关」：在 Flutter 设备页加回两个开关并让 `McpService` 读取 `McpSettings` 即可（代码路径仍在）。

## 2026-10-20 追加（dev-1176，用户要求完全免令牌）

- **网络层也完全免令牌**：`McpHttpServer` 不再校验 `Authorization`（带错 Bearer 也忽略，不会 401）；本机 / USB 转发 / 局域网一致。
- `initialize.instructions`、MCP 状态页、隐私政策文案同步更新为「完全免令牌，客户端只需 URL」。
- MCP 单测同步改为免认证语义（`tokenIsIgnoredAndRequestsAlwaysReachHandler` 等），CI 恢复绿。
- 实测：PC 从局域网 `http://192.168.10.6:8765/mcp` 不带任何 Authorization 调 `initialize` → **200**，返回正常 JSON；带错误 Bearer 同样 200。
- 安全提示：局域网 HTTP 未加密，服务绑 0.0.0.0 且免令牌，仅建议在可信局域网/本机使用，不要暴露到公网。
