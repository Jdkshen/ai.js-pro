## 1. P1：QuickJS 原生定时器「自取消」释放后使用（属实 → 已修）

命中机制（与复核一致）：

- `dispatchDueTimers()` 把存储槽里的回调**直接**交给 `JS_Call()`；回调里 `clearInterval(自己的 id)`
  会释放同一份引用 ⇒ **正在执行的函数对象被释放**（复核在 K40 上用 dev-716 同一份 `libquickjs.so` 复现 SIGSEGV/139）；
- 自取消之后再抛异常：收尾路径还会 `JS_FreeValue(timer->callback)` ⇒ **二次释放**。

修复（`modules/engine/src/main/cpp/quickjs_jni.cpp`）：

- `dispatchDueTimers()`：为本次调用单独 `JS_DupValue` 一份回调引用；成功路径与两条异常路径都先释放这份
  「调用引用」；存储槽的释放统一改走新的 `freeTimerCallback()`（先置 `JS_UNDEFINED` 再释放，**幂等**）。
- `nativeClearTimer()`：**先把槽位置空、再释放** —— 回调正执行时（自取消），dispatcher 收尾不会再二次释放。

业务命中路径（复核所指，逐一确认存在）：面板保活心跳（`src/app/panel/lifecycle.js`，心跳内自动重载 →
`clearInterval(aliveTimer)` 自取消）、长按 `holdTimer` 的清尾、传感器注销回调等。

## 2. P2：竞争策略「半成品」补链（属实 → 已修）

1. **worker 参数透传**（`src/automation/search-worker.js`）：
   - 载荷与 `workerTask()` 补齐 `openingBook / criticalReview / previousScore / openingLearning /
     bookOwnMoves / ownMovesMade / bookRandom`；结果回传新增 `review / excludeRelaxed / bookLearned`。
   - 修复前：prethink 的 `openingBook:false` 到不了引擎（预思考会命中开局库秒回、Hash 根本没热身）；
     正式搜索的开局库步数闸门、关键步复核、开局学习在 worker 路整条断链。
2. **协作取消**（`search-worker` 新增 `cooperative:true`；装配层对共享 worker 显式打开）：
   - `cancel()` 只**作废结果**、绝不打断 native 搜索；句柄留到终端状态（drain），期间 `isRunning()` 为 true；
   - `start()` 在新搜索前做**有界 drain 等待**（3s）——不再用 400ms 间隔冒充「退出确认」；
   - 超时（引擎没按预算返回 = 可能卡死）仍是唯一保留 interrupt 的硬停路径。
   - 驱动侧配合：`deferred-compute` 路径 + `isThinking()` 计入 deferred，驱动级回放验证
     「忙碌的预思考只**推迟**正式搜索、不叠加两次 JNI 搜索」。
3. **关键步加时复核**（`src/engine/pikafish-engine.js` 接入 `critical-review.plan`）：
   - 采信条件（缺一不可）：复核给出候选 + 着法合法 + 不在排除表 + **复核深度 > 首搜**；
   - 复核抛错/不满足 ⇒ 保留首搜着法并带 `review:{accepted:false, error/reason}`（绝不会因复核丢棋）；
   - 复核搜索用独立预算（`extraMs`，即 `critical-review.plan` 的上限计算），固定层数模式不触发。
4. **开局学习**：
   - 装配 `driverState.openingRecord = opening-results.createSession()`（`cfg.recordGames===true` 时，面板传 true）——
     此前 `driver/history.js`、`driver/turn.js` 里全是判空护栏，功能实际没接通；
   - `opening-book.pickLine(entry, {results})` 支持战绩数据（挑选判据**只有一份**：`opening-results.choose`：
     每个候选 ≥5 局、平滑得分差 ≥10%）；`engine-router` 按局面键查 `stats()`，命中时结果带 `bookLearned:true`；
   - `probe()` 现在**拒绝主着法在该局面上不合法的坏条目**（见 test-opening-book 的 `e0e9` 用例）。
