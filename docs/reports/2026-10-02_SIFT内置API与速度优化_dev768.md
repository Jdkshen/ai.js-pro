# SIFT 内置 API 与速度优化（dev-768）

## 用户需求与实现

用户希望真实 SIFT 示例减少代码，并提高重复匹配速度。新增两个双引擎 API：

```javascript
var result = images.matchSift('大图.png', '小图.png');
var matcher = images.createSiftMatcher('小图.png', {track: true});
try { var next = matcher.match(frame); } finally { matcher.recycle(); }
```

- `SiftMatcher.java` 完成 SIFT 特征、FLANN KNN、Lowe 比率、RANSAC、坐标还原及可选调试绘图，减少脚本逐个读取特征点的桥接调用。
- 缓存模板特征和算法对象，场景/模板支持图片或本地路径。借用图片不回收调用方数据；路径解码和临时 Mat 由后端回收。
- 可选 `track: true` 先搜索上次目标附近，局部至少 8 个可靠内点；局部失败自动全图回退，尺寸变化重置，显式 region 优先。默认关闭，保留全图搜索语义。
- 匹配图复用本次特征与内点，不重新匹配。matcher 可手动 recycle/close，脚本退出自动清理。
- QuickJS images 是冻结对象，加载时创建扩展包装并同步 `$images`；Rhino 调用同一 JS 安装器。避免 QuickJS 引导阶段误覆盖主脚本 CommonJS exports。
- 双引擎 main.js 各 7 行，缓存示例各 11 行；去除随示例复制的 250 多行 sift.js。Rhino 旧全分辨率入口也使用新 API。
- 补齐编辑器补全索引、离线 images 文档和 [使用指南](../guides/SIFT特征匹配示例.md)。

## 速度实测

Redmi K40 / Android 16 / arm64，同一大图 1080×2340、模板 172×206；场景 scale: 0.5，模板 scale: 1。不绘图，输入图片已解码，各预热一次后取 5 次中位数，测量包含 JS → Java 及资源清理。

| 方法 | QuickJS | Rhino |
| --- | ---: | ---: |
| 原 JS SIFT 模块，单次全图 | 313 ms | 227 ms |
| 新 matchSift，单次全图 | 232 ms | 219 ms |
| 缓存模板，全图搜索 | 213 ms | 206 ms |
| 缓存模板 + track，位置稳定 | 30 ms | 15 ms |
| 新 API，单次传两个文件路径 | 270 ms | 272 ms |

QuickJS 全图单次约快 26%；Rhino 全图单次改善较小。明显提速来自模板缓存和缩小场景搜索区域，位置稳定时跟踪约为旧全图的 10 倍 / 15 倍；首次及丢失后的全图回退仍承担全图成本。路径输入会重复解码，实时截图建议直接传图片对象。

全图保留约 11 个可靠内点，跟踪时约 18 个，中心定位误差小于 5 像素。FLANN/RANSAC 有随机性，不把固定内点数量作为通过条件。

曾尝试场景特征上限 1500/2000 与更低缩放，虽减少耗时，但这组图片会丢失目标。默认 maxFeatures 保持 0，不用限制特征数量换取速度。
