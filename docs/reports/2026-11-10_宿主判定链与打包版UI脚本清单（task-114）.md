# 宿主判定链（打包版 UI 脚本能不能跑）—— 判定依据 + 真机可验清单（task-114）

日期：2026-11-10。范围：**引擎侧宿主判定链**（只读取证 + 文档；本轮**未跑 gradle**，Lead 正在出包）。

## 一、判定链（唯一来源 = `ScriptHostRouting`）

`modules/engine/src/main/java/com/stardust/autojs/execution/ScriptHostRouting.kt`：

| 判据 | 位置 | 语义 |
|---|---|---|
| `needsActivityHost(isUiMode, hasUiLayoutCall, usesActivityApi, hasImGuiMarker)` | `:19-34` | UI 模式 **且**（有 ui.layout 家族调用 **或** 用了 `activity.*`），**且**不是 ImGui/浮窗项目 |
| `textUsesActivityApi(text)` | `:38-43`（正则 `:54` `\bactivity\s*\.`） | 正文出现 `activity.`（属性访问；`activity . startActivityForResult` 也命中） |
| `textUsesUiLayout(text)` | `:47-52`（正则 `:55` `\bui\s*\.\s*(layout\|layoutFile\|inflate)\s*\(`） | 正文出现 `ui.layout(` / `ui.layoutFile(` / `ui.inflate(` |

判定顺序（逐条，`:23-33`）：
1. **不是 UI 模式** ⇒ `false`（纯 `auto` headless）——即使正文有 `activity.*` 也不上宿主；
2. 有 `ui.layout` 家族调用 ⇒ **`true`**（**ImGui 标记也拦不住这一条**，ImGui 项目不写 ui.layout ⇒ 不冲突）；
3. 没有 `ui.layout` 且没有 `activity.*` ⇒ `false`；
4. 有 `activity.*` 且 **有 ImGui 标记** ⇒ `false`（**必须留在 headless**：native 上下文不能跨线程）；
5. 其余（有 `activity.*`、无 ImGui）⇒ **`true`**。

### 「`"ui";` 但正文没有 `ui.layout`」会怎样

- 正文**没有** `activity.*` ⇒ 判 `false` ⇒ **headless**（与修复前行为一致）：脚本能跑，但 `activity` 全局要么未定义、要么是 `null`（见 §四.1），碰到 `activity.x` 会 `ReferenceError` / `TypeError`。
- 正文**有** `activity.*` ⇒ 判 `true` ⇒ **Activity 宿主**（task-78 修的就是这条）。
- 所以「`"ui";`」本身**不是**判据（只是 UI 模式的声明）；真正的判据是正文里有没有 `ui.layout` 家族或 `activity.*`。

## 二、app 版 / 打包版是否同源

- **判据同源**：inrt（打包版启动器）`apps/inrt/src/main/java/com/jdkshen/aijspro/inrt/launch/AssetsProjectLauncher.kt` `import` 并使用 `ScriptHostRouting`（`:19` 导入；`:112-114` 用 `textUsesActivityApi` 打 headless 警告；`:203` 把 `activityApi=` 打进路由日志；单测 `ScriptHostRoutingTest.inrtLauncherUsesTheSharedRoutingPredicate` 钉住「必须调用 `needsActivityHost(`/`textUsesActivityApi(`」）。
- **注入同源**：`activity` 全局由**共享**方法注入 —— `modules/engine/src/main/java/com/stardust/autojs/execution/ScriptExecuteActivity.java:211-215` 的 `public static void attach(ScriptEngine engine, Activity activity)` → `engine.put("activity", activity)`；app 侧在 `prepare()`（`:224-225`）里 `attach(mScriptEngine, this)` 调用它。
- **headless 路径**：`ScriptExecuteActivity.java:283` 会 `mScriptEngine.put("activity", null)` ⇒ 那条路径下 `activity` 是**已定义但为 null**（不是 undefined）。
- **不伪造**：inrt 的 headless 分支只**打警告**（`C-INRT: headless 执行没有宿主 Activity…`），不造假的 activity（`:110-115`）。

## 三、真机可验清单（步骤 → 期望 → 失败看哪里）

### 用例 A：`"ui";` + `ui.layout(...)`
1. 工程 `main.js` 第一行 `"ui";`，正文调用 `ui.layout('<vertical>…</vertical>')`（或 `ui.inflate`）。
2. 打包 → 安装 → 从图标启动（界面路径）。
3. **期望**：`ScriptExecuteActivity` 承载，脚本进入 `runScript(activity)`，界面正常显示、`ui.emitter`/`activity` 可用；logcat 出现路由日志且 `activityApi=false`（若正文确实没写 `activity.`）。
4. **失败看哪里**：logcat `C-INRT:` 路由行（`route=…` / `activityApi=…`）；若是白屏 ⇒ 路由被判 headless（检查 `ui.` 与 `(` 之间是否有换行/别名）。

### 用例 B：`"ui";` + 只有 `activity.*`（用户实报那类）
1. 工程 `main.js` 写 `"ui";` + `activity.getEventEmitter()`（**不写** `ui.layout`）。
2. 打包 → 安装 → 启动。
3. **期望**：走 Activity 宿主 ⇒ `activity` 已定义（对象）；`activity.runOnUiThread(...)` 正常；**不再是** `ReferenceError: "activity" is not defined`。
4. **失败看哪里**：logcat 路由行 `activityApi=true`（判据命中）；若 `route=headless` ⇒ 判据没进包或没调用（先跑 `check-artifact-freshness.ps1 -Deep` 确认模板含 `ScriptHostRouting`）；若 `activity` 为 `null` ⇒ 走了 `:283` 那条 headless 注入路径。

### 用例 C：纯 headless `auto`（无 `"ui";`）
1. 工程 `main.js` 只有 `auto.waitFor()` / `click()` 等。
2. 定时任务 / 服务路径触发（或从界面进入）。
3. **期望**：`route=headless`、**不注入** Activity；脚本正常执行完；**没有** Activity 相关报错。
4. **失败看哪里**：logcat `C-INRT: headless 执行没有宿主 Activity…` 只在脚本**用了** `activity.*` 时才出现（`:112` 的条件）⇒ 纯 auto 脚本**不应**出现这行；出现即说明判据误命中。

###（补）用例 D：ImGui/浮窗项目 + `activity.*`
1. ImGui/浮窗工程（正文含 ImGui 标记）里也写了 `activity.*`。
2. 打包 → 启动。
3. **期望**：**保持 headless**（`needsActivityHost(false)`）⇒ native 上下文留在 `:script` 线程；脚本不被拽进 Activity。
4. **失败看哪里**：若被拽进 Activity ⇒ native 崩溃/黑屏，检查 ImGui 标记是否被识别为 `hasImGuiMarker=true`。

## 四、已知坑

1. **`activity` 可能是 `null` 而不是 undefined**：`:283` 的 headless 路径显式 `put("activity", null)` ⇒ 脚本文本先出现 `typeof activity` 得到 `"object"`，随后 `activity.x` 抛 `TypeError: Cannot read property ... of null`（**不是** `ReferenceError`）。排障时两种报错都要认。
2. **`"ui";` 不等于 UI 脚本**：判据不看这行声明；只写 `"ui";` 而正文没有任何 `ui.layout`/`activity.*` 的脚本会 headless（能跑，但没有 `activity`）。
3. **`ui.xxx` 与 `floaty` 混用**：判据里 `ui.` 只认 `layout/layoutFile/inflate`（`:55`），`ui.run`/`ui.emitter` 等**不算**；浮窗项目通常写 `floaty.*` ⇒ 不触发宿主判据，保持 headless（与 ImGui 同理）。混用时若同时出现 `activity.*` ⇒ 会按第 5 条判 **需要宿主**（浮窗 + activity 同用是允许的，只是失去 headless）。
4. **文本判据是保守的**：正则只看 `activity.` 属性访问（`:54`），字符串/注释里出现（`'myActivity.x'`）不算（单测 `textPatternsMatchTheRealScriptShapes` 钉住）；因此**动态拼接** `global['activity']` 之类不会命中 ⇒ 需要显式写 `activity.`。
5. **判据不进包 = 假绿**：打包版跑的是模板里的引擎 ⇒ 改了 `ScriptHostRouting` 必须重建模板（新鲜度门禁 `check-artifact-freshness.ps1 -Deep` 的标记里含 `ScriptHostRouting`）。
