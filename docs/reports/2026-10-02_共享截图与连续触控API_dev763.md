# 共享截图与连续触控 API（dev-763）

## 用户请求

把用户提供的 `引擎共享截图权限.zip`、`touch.zip` 整理为内置 API，并添加到应用示例。ZIP 保留原样，解压和反编译检查产物在本机 `.artifacts/user-api-packages/`。

## 完成内容

- Rhino / QuickJS：新增 `images.shareScreenCapture()`、`images.useSharedScreenCapture(token)`，普通同步截图及无障碍截图可共享。
- 会话按参与引擎引用计数；主引擎退出后，已连接的子引擎继续截图。最后一个参与引擎退出才释放。失效凭据明确报错。
- 共享捕获和图片拷贝在同一锁内执行，每个引擎持有独立图片，避免原 ZIP 直接共享整个 Images 对象导致图片回收互相影响。
- 普通投影使用捕获会话自己的 HandlerThread，避免主引擎 servant Looper 退出时中断子引擎捕获；不复用授权 Intent 创建第二个虚拟显示。
- 新增 `touch.create({backend: "root" | "shizuku" | "adb"})`，提供 `down(id,x,y)`、`move(id,x,y)`、`up(id)`、`exit()`、状态查询和 `$touch` 别名。
- 复用内置 RootAutomator2；Root 支持多指，Shizuku 支持单指。补齐参数和顺序检查、最后坐标 UP、异常与脚本停止时抬起所有手指。
- 修正 RootAutomator 抬起部分手指后新手指重复占用槽位，以及重新按第一指时没有选择槽位 0 的问题。
- 子引擎启动等待处理 null 引擎，并将 RunnableScriptExecution 的跨线程引擎引用改为 volatile。
- 新增 6 个示例、编辑器 API 索引及离线文档。QuickJS 扩展从 JS 资源加载，保留现有原生捕获通道；未修改 C++。

## 范围与未验证项

- 共享凭据只在当前应用进程内有效。async 截图流、auto 自动切换通道暂不共享，会明确报错。
- Root 多指会话最多跟踪 10 指；设备物理槽位数可能更少。当前 K40 的应用无法执行 su，因此 **Root 多指真实注入尚未在有 su 的设备实测**；状态与异常收尾已做单元测试，Shizuku 单指已实测。
- 原 touch ZIP 的 JNI 物理触摸回调不照搬；使用现有 events.observeTouch / events.onTouch，回调遵循 events 格式。内置实现不执行 ZIP 的全局 chmod / SELinux 设置。
