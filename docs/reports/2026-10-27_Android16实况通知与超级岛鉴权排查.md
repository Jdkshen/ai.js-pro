# Android 16 实况通知与小米超级岛：实机鉴权排查

## 用户现象和根因

用户在dev-1269复制的诊断全部开启：Xiaomi、Android16、islandSupported=true、focusProtocol=3、notificationsAllowed/focusAllowed/runningChannelAllowed=true，脚本运行数1；用户确认通知栏显示运行通知，桌面无岛。随后补充：听海播放音乐可以上岛，并提供USB。

原诊断只查用户开关和任务计数，没有核对实际Notification或小米平台鉴权。实机MCP读取证明岛JSON存在、UTF8约1116字节、通道importance=4，不能把问题归结为权限未开启。USB抓到：

```
E/FocusPlugin: onAuthFailed 0|com.jdkshen.aijspro|1|null|10450 com.jdkshen.aijspro
```

系统已解析并布局模板后因鉴权失败移除。安装包的`com.xiaomi.xms.APP_ID`和`BUILD_TYPE_DEBUG`都为空，用户确认未开通小米超级岛服务。独立通知/去掉FGS标记以及临时增加isFocus标记的对照也返回onAuthFailed。没有把私有字段当授权绕过，也没有伪造App ID或证书。

音乐是MediaSession媒体通道，与普通脚本任务不同；音乐能上岛不能证明自定义模板已获授权。小米官方专属模板依然需要接入配置。此前“缺App ID”的判断只针对专属模板，不应泛化为所有上岛方式。

## 另一条可用路径

这台系统支持Android标准实况通知。1269没有声明POST_PROMOTED_NOTIFICATIONS，实测permission=-1、canPostPromotedNotifications=false。

本轮增加普通manifest权限、Android16的android.requestPromotedOngoing、短文案android.shortCriticalText；保留ongoing/BigTextStyle/内容Intent和单项/全部停止。移除setSilent(true)引入的silent/分组语义，沿用用户渠道设置/OnlyAlertOnce。支持且允许公开接口时优先标准通道，避免混用未注册小米模板；未支持设备保留原有回退。

初版1270实测：permission=0、canPostPromoted=true、hasPromotableCharacteristics=true，flags=262250（含FLAG_PROMOTED_ONGOING）。USB桌面截图明确出现黑色胶囊“1项”，三引擎并发为“3项”。这条系统标准路径不要求先取得小米专属App ID，实际成功仅针对本轮真机/系统，不代表全部OS3设备。

## 代码与诊断

- LiveUpdateSupport区分普通权限、公开实况接口、实际promoted标志、小米App ID配置与未验证的平台授权。
- ScriptStatusActivity新诊断包括实际通知、载荷/字节数/通道、请求和提升状态、最近发送时间/错误；焦点用户开关不再等同平台接入成功。
- NotificationDeliveryState只在发送成功后提交指纹，失败可重试，过期主线程队列不能提交旧状态；显式刷新会重发。
- 设置跳转在ROM无专属入口时回退应用通知设置。本机缺少专属Settings常量/Activity，不能声称专属设置入口可用。
- 427项App JVM全部通过（原417+6发送状态场景+4路线场景）。引擎代码本轮未修改。
