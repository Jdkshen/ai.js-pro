# 修「dev-1401 后仍复现 require 报错」——两条独立成因（dev-1404）

> `.4` 12:21 截图：打包产物 `主线任务.js` 仍报 `Can't resolve relative module ID "./脚本.js" when require() is used outside of a module`。回复稿：[output/MCP-FEEDBACK-REPLY-dev1404.md](../output/MCP-FEEDBACK-REPLY-dev1404.md)。

## 成因①：受保护/编译型入口没走到修复（新发现）

```text
AssetsProjectLauncher → EncryptedScripts.toSource(file,"main") → CompiledJavaScriptSource(name,className,bytes)   ← 无文件路径
RhinoJavaScriptEngine.doExecution: if (source is CompiledJavaScriptSource) return executeCompiledScript(source)  ← 提前 return
dev-1401 的 applyRequireRootFor 只在**文本路径**调用 → 编译入口从未刷新 require 根
```

**修**：`CompiledJavaScriptSource` 增 `scriptPath`（`EncryptedScripts.toSource(file)` 传入）；编译分支也调用 `applyRequireRootFor`（目录取 `scriptPath`，退 `cwd()`）。

## 成因②：打包模板可能陈旧（"以为换了其实没换"）

取模板优先级：`/sdcard/template.apk` > 宿主缓存 `files/apk-builder/<versionCode>/template.apk` > app 内置 `assets/template.apk`。前两级会盖掉内置的新模板。

**修**：
- `ApkTemplateInspector`（新）：流式读模板内 `assets/init.js`，检测 `__ajsSetRequireRoot` 标记 → `engineRequireRootFix` / `templateStale` / `engineInitSha256` / `warnings` / `nextActions`；
- `ApkBuilderPluginHelper.openTemplateSelection(...)`：选模板同时产出指纹；`openTemplateApk` 打日志（含陈旧告警）；`templateSummary()` 供 `get_status` 用；
- `get_status.template`：K40 实测 `bundled_assets` + `engineRequireRootFix=true` + `templateStale=false` + detail「含 __ajsSetRequireRoot」；
- 打包版启动日志新增 `C-INRT: engine requireRootFix=… initJsSha256=… scriptStorage=…`。

## 集成期修队友(W-H)留下的 4 处编译问题

1. `ApkBuilderPluginHelper.java`：`openTemplateApk` 换实现后**旧实现尾部片段未删** → 花括号失衡 -2（`class/interface/enum expected` × 100）；
2. `ApkTemplateInspector.java`：`org.json.put()` 的**受检 `JSONException`** 未处理（`Info` 构造器与 `toJson()`）→ 改用安全 `put/append` 助手；
3. 同文件一处多行字符串被正则改动打断（缺 `);`）；
4. `McpTools.get_status` 侧：该 Gson 版本**没有 `JsonParser.parseString`** → 改 `JsonParser().parse(...)`。
