# 产出自动归到项目目录 —— 不再靠人提醒（dev-1382）

> 用户诉求：「调用 MCP 要能**提醒**被调用的 AI：不要到处掉、产出统一放同一个**项目文件夹**、没有就创建一个。不能每次都靠人提醒，否则 AI 就不做。」
> 做法：把它做成**产品行为**——MCP 自己会在 instructions 里说、会把输出自动归位、并暴露可查的约定；同时保留显式控制。

## 一、问题现场（先取证）

K40 脚本根目录当时的状态：

```text
根目录 8 个目录：xiangqi-draw | .xiangqi-node-sync-20261029-2200 | __ocr_samples | __align_test |
              .autojs-glass-trash | __proj_test | .keyStore | __verify
根目录 6 个文件：out-v3.apk(145MB) | out-v3b.apk(145MB) | out-v3c.apk(145MB) | detail-full.apk | detail-sum.apk | .mcp-terminal-jobs.json
```

→ **4 个 `__` 垃圾目录 + 约 435 MB 散落 APK**，全是 AI 调 MCP 时随手写的。

## 二、现在的行为（K40 dev-1382 实测）

| 机制 | 实测结果 |
|---|---|
| **① MCP 自己会提醒** | `initialize.instructions` 新增强制规则：「产出目录（强制）：所有 APK/ZIP/反编译/截图/导出/证据必须落在操作根下的项目目录 `<root>/<项目名>/`；没有就先 `project_folder{action:"create",name:"<项目名>"}`（需要默认再 set）；不要写 `<root>` 根目录，也不要用 `tmp/out/test/__xxx` 一次性名字。**工具返回 `organized` 说明它已帮你归位——看到就说明你原本写错了位置**」 |
| **② 新工具 `project_folder`** | `state` → `{"projectDir":null,"candidates":["MCP测试","xiangqi-draw"],…}`；`set{name:"MCP测试"}` → `{"projectDir":"…/MCP测试","isDefault":true}`；`create`、`tidy` 同工具 |
| **③ 默认自动归置** | 裸文件名/直接落在操作根的输出 → 自动进默认项目，**返回体带 `organized`**：`file_write_bytes("stray-bare.txt")` → `MCP测试/stray-bare.txt`，`organized={from,to,projectDir,reason:"default-project",label:"file_write_bytes"}`；`apk_job_export("exported-bare.json")` → `MCP测试/`；`capture_screen(savePath:"shot-bare.png")` → `MCP测试/` |
| **④ 不越权** | 显式子目录 `MCP测试/notes/kept.txt` **不改写**（无 `organized`）；`organize:false` 的 `stray-optout.txt` **留在根**（无 `organized`） |
| **⑤ 可发现** | `get_status.outputConventions` = `{projectDir, defaultProject, rule, toolsWithOrganize[23 个工具], note}`；`toolkit_status` 同源（**两份实现已合并为一份**） |
| **⑥ 清理既有垃圾** | `project_folder{tidy}`：`dryRun:true` 先给计划（`moved:[{from,to}]`），`dryRun:false` 只**移动**不删除 → 把 `stray-optout.txt` 收进 `MCP测试/_incoming/` ✓ |
| 顺手 | `file_move.overwrite` 由 required 改为可选默认 `false`（假必填）；`file_move` 缺参时错误文案直接点名 `sourcePath`/`destinationPath` |

### 已接入自动归置的工具（23 个）

`file_write_bytes`、`file_edit_text`、`file_patch_bytes`、`file_copy`、`file_move`、`file_delete`、`file_create_directory`、`file_delete_directory`、`file_replace_text`、`file_truncate_bytes`、`file_append_bytes`、`file_append_text`、`capture_screen`、`evidence_export`、`apk_build`、`artifact_export`、`apk_copy_entry`、`zip_create`、`zip_extract`、`apk_build_project`、`apk_inject_gadget`、`apk_decode_project`、`apk_job_export`。

- `zip_update` 是**原地**修改输入 ZIP，移动会破坏 `targetVersion`/原子覆盖语义 → 有意不归置。
- 规则只作用于「**直接落在操作根**」的输出；`<root>/<任意子目录>/x` 一律不动（尊重调用方）。

### 现场收拾

根目录原有的 4 个垃圾目录 + 5 个散落 APK（约 435 MB）已用 `file_move` 搬进 `MCP测试/`，根目录恢复为 4 个正常目录 + 1 个隐藏文件；此后新产出会被**自动**归位，不需要人提醒。

## 三、合并期修掉的问题（Lead 收口）

| 问题 | 处置 |
|---|---|
| 队友 C 的调用点用 `organize(File,args):OrganizedPath`，A 的落盘实现是 `organize(String,Boolean,String):Result`（**接口分叉**） | 加兼容重载 + `OrganizedPath.organized` 别名，**行为仍只有一份实现** |
| `AndroidToolkitRuntime.kt` 头部 KDoc 里写了 `apk_*/zip_*`，其中的 **`*/` 提前结束块注释** → 语法错误 | 改写该行（KDoc 内不得出现 `*/`） |
| `ToolkitExtraTools.transform` 引用了未定义的 `organized`（B 的助手只接在 export 路径） | Lead 把 `organizeOutput` 接到 transform 的写盘前，并把 `store` 传进 `transform` |
| `toolkit_status.outputConventions` 与 `get_status` 各有一份（短版 vs 全版） | `McpToolkit` 改为委托 `McpOutputConventions.describeFor(...)`，只留一份 |
| `apk_build`/`apk_job_export`/`apk_build_project`/`apk_inject_gadget` 的 schema 没声明 `organize` | 补齐（JSON 两处 + `ToolkitReverseTools` 两处） |
| 10 个 zip/归置单测失败（输出被移走 / `default-project` vs `auto-project`） | 测试统一 `organize=false`（精确路径语义）；两个新用例断言改为 `auto-project`（首次自动建项目） |
