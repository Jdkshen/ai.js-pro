# 主题切换提速与系统跟随统一

## 问题

侧栏手动主题触发 AppCompat 全局 uiMode 变更，主界面未声明处理 uiMode，会重建 Activity 和五个预加载页面。侧栏“跟随系统”原来只更新 Compose 状态；BaseActivity 和 ThemeColorManagerCompat 仍强制手动 YES/NO。编辑器 AppThemeRepository 另用 app_theme_mode，而 ProCodeEditorActivity 又用手动夜间标志覆盖有效系统主题。日志中的原生 ConsoleView 只在创建时上色。

## 修改

- 以 key_night_mode 和 follow_system_theme 为共同主题选择；跟随系统优先，关闭后恢复保存的手动选择。
- ThemeColorManagerCompat 监听两个选择，先同步 Compose 状态，再设置 AppCompat YES / NO / FOLLOW_SYSTEM。去除夜间切换时保存和反复覆盖旧主题主色的额外通知。
- 主界面自行处理 uiMode，刷新玻璃导航、系统栏和文件列表颜色，保留页面适配器、文件夹及滚动状态。显式向 DecorView 派发配置变更，更新 Compose LocalConfiguration：缺少此步骤会出现原生深色、Compose 顶栏浅色，已由截图像素回归测试发现并修复。
- AppThemeRepository 读取同一份主题选择，监听偏好及应用配置变更，合并重复通知。编辑器主题菜单和侧栏使用同一设置，编辑器不再用手动开关覆盖系统主题。
- 日志 AndroidView 在有效主题变化时重新上色，同色重复重组跳过；终端监听统一调色板并在切换时保留当前命令输入，浅色终端使用浅色背景。旧编辑器 Themes 也读取有效主题。
- Compose 深浅调色板缓存，避免每次重组重新构造。

uiMode 原位更新依据：[Android 深色主题配置变更说明](https://developer.android.com/develop/ui/views/theming/darktheme)。
