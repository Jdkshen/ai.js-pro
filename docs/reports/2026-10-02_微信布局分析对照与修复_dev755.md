# 微信布局分析对照与修复（dev-755）

## 结论与验证边界

用户反馈悬浮窗分析微信节点时完全空白。本次已修复源码中的缓存、窗口选择、节点遍历及失败通知问题，并发布、安装 dev-755。

K40 原先没有安装微信。经用户授权，从微信官方网站下载并安装 8.0.79，验证腾讯签名。未登录账号。目前已验证欢迎页和手机号登录页；登录后的首页、聊天页及小程序尚未验证，用户反馈的具体空白页面还未复现。

必须区分修复与复现：dev-753 在这台 K40 上已经可以分析微信欢迎页。这次修复解决了确定存在的兼容性差异和失败处理缺口，不能据此认定它们就是用户原来遇到的空白原因。

## Pro 对照结果

参考本项目 `.artifacts/pro-apk/auma-src/sources/` 中的反编译源码；同机测试使用已安装的 `org.autojs.autojspro`，版本 Pro 9.3.11-0。

| 项目 | Pro 实现/实测 | 本次源码处理 |
| --- | --- | --- |
| 框架节点缓存 | 捕获前调用框架缓存清理；API 33 起调用 `clearCache()`，旧版反射清理 | `clearNodeCache()` 同时清理快速根节点和框架缓存；旧 ROM 拒绝反射时继续尝试捕获 |
| 窗口 | 读取交互窗口列表，构造多窗口 Capture | 读取窗口列表并优先选择应用窗口，避开键盘和分析悬浮层；未增加 Pro 的完整多窗口选择界面 |
| 遍历 | 队列遍历 NodeInfo | 改为队列遍历，防重复节点；子节点失效时隔离异常 |
| 资源 ID | 按需查询 | 延迟查询并缓存包资源；查询异常不阻断整棵树 |
| 服务类名 | 实际组件为 `com.google.android.accessibility.selecttospeak.SelectToSpeakService` | 本项目保留 `com.stardust.autojs.core.accessibility.AccessibilityService`；同页节点已可读取，不能认定必须更名 |

Pro 与本项目都没有在服务 XML 中声明 `isAccessibilityTool`。没有证据证明本次微信页面的节点属于系统限制读取的敏感节点。

官方 API 参考：[AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。

## 源码改动

- `modules/automator/src/main/java/com/stardust/view/accessibility/AccessibilityService.kt`：清理框架节点缓存。
- 同目录 `LayoutCaptureSelector.java`：依据应用窗口类型、活动状态、输入焦点和层级选择根节点。窗口列表不可用时保留活动根节点回退。
- 同目录 `LayoutInspector.kt`：把远程节点查询放到后台线程；最多三次捕获尝试；失败也通知监听器；监听器异常互相隔离；完成后释放 `isDumping` 状态。服务信息读取也纳入异常保护。
- 同目录 `NodeInfo.kt`：队列遍历和按需读取资源 ID，保留父节点、子节点顺序、深度及位置。
- 浮动菜单、范围分析窗口、快捷设置磁贴、广播入口：空捕获不再打开空白分析窗口，改为结束等待并提示无法读取节点。
- `DevPluginServer.java`：区分捕获超时和已经完成但无节点的情况。
- `strings.xml`：加入明确的捕获失败提示。
