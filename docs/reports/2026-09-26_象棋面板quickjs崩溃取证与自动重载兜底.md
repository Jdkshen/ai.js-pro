# 象棋面板 quickjs 崩溃取证 + 「崩溃前哨 / 自动重载」兜底（2026-09-26）

用户报「为什么跑着软件就崩了」。取证结论：**崩在 quickjs 引擎内部（`libquickjs.so` 的 `JS_DefineProperty`），
不是 09-25 晚那批 pikafish / quickjs_jni 桥改动引起的**；本次加了两个兜底：崩溃前哨（定位下一次崩溃）
与自动重载（把「崩在长跑中」的概率摊薄）。

## 二、兜底 A：崩溃前哨（下次崩能指到动作）

- `悬浮窗运行与测试.js`：`stageMark()` 走 `console.log`（**只进 logcat/GlobalConsole，不上屏**）；
  `tick()` 里打 `tick:begin / tick:guard-done / tick:driver-done / tick:end`。
- `src/automation/auto-driver.js`：新增可选依赖 `opts.stage`（缺省 no-op）；
  `tick()` 打 `drv:tick / drv:poll / drv:observe:begin|end|fail`；`handleEffect()` 打 `effect:<TYPE>`
  （COMPUTE / EXECUTE_TICKET / VERIFY / RECOVER …）。
- ⚠️ `wrapDriverDeps` 对 `stage` 直接透传（不包裹计时，否则每 tick 十几条会把「依赖 top」顶满）。

**用法**：崩溃后取 `adb logcat -d -s GlobalConsole:V | Select-Object -Last N`，最后一条 `[stage]` = 死在哪个动作。

## 三、兜底 D：自动重载（默认 60 分钟）

- 配置：autorun `"autoReloadMin": 60`（**0 = 关**）；`src/app/config.js` 的 DEFAULTS + parseAutorun 已支持（非法值告警并按默认）。
- `performAutoReload()`（`悬浮窗运行与测试.js`，心跳 1s 里做「安全时刻」判定）：
  1. **先** `engines.execScriptFile(自身路径, { path: BASE_DIR })` 拉起新实例 —— **失败就什么都不动**（老面板继续用，5 分钟后再试）；
  2. 成功后 `handingOff = true` → `stopLoop()`（释放循环锁）→ 清 `aliveTimer` / `holdTimer`；
  3. 脚本没有定时器会被引擎回收 → exit 钩子关窗口/画板，不留僵尸面板。
- 「**上次在跑**」自动继续：`markPanelRunning()` 写 storages（与滑动条同一个 `paramStore()`，键 `running`）：
  - `startLoop()` 写 true；`stopLoop()` 写 false（交接时跳过）；exit 钩子写 false（交接时跳过）；
  - **native 崩溃走不到 exit 钩子 ⇒ 保住 true**；重开面板时启动尾部读回 → `keepGameInFrontOnce()` + `startLoop()`。
- 安全条件：不在点击租约中 / 不在启动中 / 不在算棋中（JS 单线程，心跳执行时 tick 一定没在跑）。
