## 本轮修复

1. `touch`、`touch_down`、`touch_up`、`touch_move` 共用一套原生 OnTouchListener；阶段事件先于通用事件，共享事件对象。可以调用原生 MotionEvent 方法、将事件传回 Java；消费结果同步返回 Android。
2. `key`、`key_down`、`key_up` 共用 OnKeyListener，保留键码、原生 KeyEvent、来源 View。
3. `long_click` 修正为 `(event, view)`：只有 event.consumed 控制原生返回；处理器存在或 `return true` 不再误吞默认行为。
4. 增加 `scroll_change` 的新旧坐标，要求 Android 6 / API 23 以上。它是滚动后通知，不撤销滚动。
5. 补充 prepend/once、事件名称、处理器数量/副本、最大监听警告阈值等常用 EventEmitter 控制入口，保留 click/check/item_created/draw。
6. 每个真实 View 支持 `findView(nameOrId)`、`extras`、`clearViewBindingCache()`。查找限当前子树、缺失返回 null；清缓存同时影响已保存的 binding 引用。去掉内容根 View 额外代理，保留 Java View 身份。
7. 自定义 Widget 通过 `view.extras['autojs.widget']` 暴露实例，与 Widget.of(view) 一致。
8. 更新 [Node UI 手册](../guides/NODE_UI_API.md) 和离线 API 索引，让 App 与 MCP 读取同一份参数、消费规则、限制和代码。增加内置“原生 View 事件与状态”示例。
9. 重新构建 inrt 与主应用内置打包模板，避免宿主已修、独立 Node APK 仍带旧 JS。外置旧 apkbuilder 插件模板未替换。

## 使用边界

- consumed 必须在同步回调中设置；await 后修改不能影响已返回的 Android 输入分发。
- MotionEvent 是借用对象，不能在回调结束后保存并继续使用。延后处理应先提取坐标等普通值。
- 原生回调里做同步网络、长时间计算仍会阻塞输入。新增事件不代表 UI JS 在 Android 主线程执行。
- 未列出的原生事件仍明确报错，不伪装成已支持。所有高级版列表事件、自定义事件、第三方控件事件尚未全量补齐。
- 这一轮不改 Rhino/QuickJS 事件签名，不改 K40 运行中的业务。
