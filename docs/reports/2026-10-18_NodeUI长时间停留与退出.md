# Node UI 长时间停留与退出

本轮从 Rhino 页面对照回归中发现：Node M3 页面停留超过约 30 秒再返回，会报 TIMEOUT。此前修复的额外空 Activity 已消除；这次是脚本执行寿命与界面寿命脱节。

## 复现与原因

设备 `DQKFJB59596L45BI`，dev-1034，隔离副本首行 `"ui nodejs";`。原始脚本和资源未修改。

`output/node-ui-compare/dev1034-node-back.log`：09:34:10 开始执行，09:34:40 native 返回 `exitCode=1 cancelled=true timedOut=true`；Java 又维持可见 UI，09:34:55 按返回后才回传 TIMEOUT。日志末尾重放的 Node stdout 有缓冲，不能据此认定 JS 在退出前仍存活。

两个原因共同存在：

1. Node UI 的原生事件循环使用普通脚本的 30 秒预算，而 Java 的 10 分钟 hold 在 native 返回之后才开始，无法让 JS 继续工作。
2. `ui.js` 在销毁时未释放轮询和 `$autojs.keepRunning()` 定时器；即使延长预算，返回也不能自然结束脚本。

## 修改范围

DP 实现，Codex 审查与验证。精确基线位于 `output/node-ui-compare/node-lifetime-baseline/`。

- `Node24Service.java`：UI / 显式 hold 复用现有有界 UI 预算作为 native 事件循环时限；普通脚本保持请求时限（通常 30 秒）。移除 native 已结束之后的第二段 Java hold。实际超时、取消、脚本异常仍按原分类返回。关闭残留界面后再释放 active job。
- 同文件生命周期观察线程：先观察到实际 UI 才判定关闭；给 JS 销毁清理留宽限，未及时退出则取消 native。启动阶段、后台仍存活的 Activity、没有 UI 的 keepRunning 不当作“已关闭”。执行结束后停止观察，防止已关闭引擎被再次取消。
- `node24/ui.js`：销毁回调之后、主动关闭和轮询失败时释放定时器与保活，恢复 Java 全局代理。重复关闭幂等；旧 Activity 清理保留销毁回调中新开的替换 Activity。
- `NodeUiHost.java`：新 UI 启动前清空上一轮静态事件和关闭标记，复用现有 Activity 的分支不清队列。
- 收集 Node 日志前恢复 stdout/stderr 并等待管道读取线程结束，保留退出时的最后日志。该补丁由 DP 准备，Codex 在主实现完成后集成。

没有改动 native 库、Node24Client 的等待预算、普通脚本默认时限或用户脚本。

## 边界

UI 预算仍有上限（10 分钟）；本轮不是无限运行能力。启用 UI 预算的识别仍复用已有 `uiScript` / hold 标记。

未做整整 10 分钟的真机等待；上限由代码审查与 native 预算日志核对，已实际验证跨过原 30 秒边界。未运行完整 Gradle 单测套件。直接通过低层宿主显示 UI 却不维持 JS 事件循环的脚本，现在会在原生执行返回时关闭界面。

进程静态事件当前没有完整的 session 标签；本轮处理已排队的上一轮残留，跨 session 的极晚回调尚需完整协议隔离。是否复现此风险以连续运行测试为准，不把有限次通过等同于任意重叠时序都已证明。
