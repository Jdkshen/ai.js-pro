# 悬浮日志长时间运行后 ✕ 关闭 exitCode=1 修复（task-195）

日期：2026-10-20。执行：t1-native-services。验证机：K40（cccc62c7）+ 新机（DQKFJB59596L45BI），dev-1140 待填。

## 1. 问题

新机（dev-1139）用户日志：悬浮日志运行 15.124s → 结束行 → 200ms 后 `E SCRIPT_ERROR: Node 脚本异常退出，exitCode=1`；K40/MI8 6.9/8.2s 关闭为 exitCode=0。怀疑 overlay polling / process.exit / 宿主关闭竞态导致 Node 原生以 1 退出（或 exit 钩子抛错改变退出码）。

## 2. 根因分析

- `process.exit()` 原生退出码会被以下情况改成 1：exit/beforeExit 钩子抛错（Node 语义）、关闭瞬间 overlay polling 仍打宿主桥产生未处理异常；
- prelude 的 dialog/sensors/ui 等模块注册了 process exit 钩子；若宿主已关闭（✕ 关闭 UI 后），钩子里的宿主调用可能抛错；
- K40 长等待 15/16s 复测 exitCode=0，说明是竞态/设备时序相关，需在引擎侧把 exit 语义收口。

## 3. 实现

1. prelude 包装 `process.exit`：先 `hostValue({kind:'lifecycle',action:'exitRequested',args:{code}})` 记录退出请求，停 keepalive、停 overlay polling，再调用原生 exit；
2. prelude 给所有 `exit`/`beforeExit` 钩子包 try/catch（含已注册的 dialog/sensors/ui 钩子）——钩子抛错不再改变退出码；
3. `Node24HostBridge` 新增 lifecycle.exitRequested 记录（mExitRequested/mExitRequestedCode + exitRequestedCode()）；
4. `Node24Service`：结果判定优先 exitRequested——code==0 强制 SUCCESS/exitCode=0（即使 native 返回 1）；非 0 保留失败并带 code；未记录时退回 native exitCode；
5. `floating_window.js`：polling 整个 tick try/catch、事件分发逐条 try/catch；窗口关闭/无窗口时停止 polling；暴露 `__ajsStopOverlayPolling` 供退出包装调用。

## 6. 限制

1. exitRequested 是 prelude 层记录，非 Node 原生 exit code；如果脚本绕过 process.exit（如 native abort/崩溃）仍按 native 结果报错；
2. exit 钩子抛错会被吞掉并打一行 console 提示，不影响退出码。
