高级版基准为本地 `output/auma-base.apk`，包名 `com.boyai.auma`，版本 9.3.11-0，SHA-256 `e0010eafdd7ab8bd204e67ffdca3ec1ac7c1c0a4180ca42311fe8ebe2c0fb31a`。

| v1 原始行 | 938 | 其中 201 行是章节标签 |

| v2 声明记录 | 3,042 | 含类、类型、接口、属性、枚举、重载等，不全是可调用 API |

| 账本总记录 | 3,980 | 938＋3,042，包含上述 201 标签 |
| 当前 status=unverified | 3,980 | **说明账本仍是声明层初始状态，没有回填；不是 3,980 个接口都没实现** |

## 8. 何时才能说“全部对齐”

每条实际 API 需要同时记录：实现位置、引擎、参数/返回/异常、线程与事件语义、权限/资源释放、宿主/独立包、示例入口、版本/设备、可复核证据。

状态至少区分 `未盘点 / 代码缺失 / 行为不同 / 已实现待测 / 受环境阻塞 / 已验收 / 按设计专属`。先把可调用功能与纯类型/标签分开，再谈可计算的分母。不能用声明数量、MCP 工具数、文档条数或单测数量给出“99%兼容”。

不应以追求文件结构相同为目的，取消已交付的 Node24 三槽、MCP、自家电脑连接或进程隔离。Node 标准库/npm、Rhino E4X 和 QuickJS 语言差异应明确分类，不能盲目给所有引擎塞同名替代品。
