# 象棋“等稳定”卡住：现场与绘制隔离

发布：宿主 dev-796 / 象棋工程 0.6.65，2026-10-05。

## 现场证据

K40（cccc62c7，Android 16）安装 dev-794 时，面板停在“等稳定”。最后一手 e6f6 已确认，对方随后 e9d9，但面板日志与总线心跳停止更新。最后日志为后台观察结果返回；视觉、搜索和 IO Worker 随后因为失去父脚本心跳而协作退出。

对仍存活的应用取了两次 `debuggerd -b` 非崩溃线程快照。`Script-4` 位于 `ImGuiDrawingOverlay.update → QuickJsHostBridge.drawUpdate`，实际等待在 ART 的 `ConcurrentlyProcessMovingPage / HandleSigbusFault`；同时 `HeapTaskDaemon` 在 `MoveBlackDensePageForUpdate / UpdateNonMovingPage` 等待。两次快照之间没有恢复。这证明业务观察循环被绘制调用中的运行时等待占住；不能将它归因于“平均帧差阈值过严”，也不能仅凭快照断定整个系统异常的具体根因。

现场文件：`.artifacts/k40-stable-stuck-panel.log`、`k40-stable-stuck-logcat.txt`、`k40-stable-stuck.png`、`k40-stable-native-stacks.txt`、`k40-stable-native-stacks-repeat.txt`。

## 应用侧改动

- ImGui 的 `drawing.update` 仅提交不可变 JSON 与文字，最多保留一份待处理请求；新的请求覆盖未处理的旧请求。
- GL 线程取得最新请求并解析；只有完整解析成功才替换画面，错误请求记录日志并保持原画面。提交新请求不预先清空箭头。
- 关闭清除待处理请求，拒绝关闭后的提交。
- 后台观察增加 `vision:render:begin/end` 阶段日志，方便区分绘制和观察采纳的卡点。
- 稳定帧阈值、轮次推导、将帅安全门、点击票据、搜索预算没有改变。

这是一项应用侧隔离：它减少同步绘制处理对面板的占用，不能修补设备上的 ART，也不能保证共享运行时的所有访问都不会遇到系统回收异常。
