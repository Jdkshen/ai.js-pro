## 实际修复

1. **界面启动中关闭**：`NodeUiLocalSession` 的 opening、attach、close、destroy 用同一状态锁保护；启动中的会话也计入清理检查。关闭会撤销 token 并唤醒 `show`，迟到的 Activity 无法挂回会话；旧 Activity 的销毁不会清掉新会话。
2. **真实 UI 的公共接口**：编译资源模式下，`ui.currentActivity/getCurrentActivity/getWindow/findViewById/inflate/setContentView` 使用当前进程的真实 Activity/View。替换 content 后同步会话根 View，关闭时移除 Java View binding 钩子。未找到 View 返回 null；关闭后要求 Activity 的操作明确报错。布局资源的负数 int32 id 保留。
3. **任务返回字段**：对照高级版 APK 随包 `assets/v8/built_in_modules/work_manager.js`，把宿主 ISO 星期日 7 转为 Pro Node 的星期日 0；补 `path`、JS `Date` 类型的 `dateTime`、`type`、非意图任务的 `action:null`。创建、查询的数组结果和单任务结果统一转换，保留原来的真实 DB id。
4. **设置改为真实开关**：旧实现仅写独立 `storages`，应用设置没有跟着变化。现在通过现有主进程 Messenger 通道读写 `Pref`，覆盖高级版导出的全部 5 个布尔项：stableMode、enableAccessibilityServiceByRoot、stopAllOnVolumeUp、noConsoleOnLaunch、foregroundService。前台服务开关复用现有 UI 的实际启停逻辑。未知项、非法 action、非 boolean 值或宿主错误不会冒充成功。

DP 独立审查发现启动关闭竞争；主控修复并验证。DP 独占新增 `NodeSettingsBridge.java` 和 `NodeUiBridgeService.java` 的设置分支，主控审阅、集成及真机测试。没有向现有 DP 桌面聊天发送消息。

## 尚未解决

- **Android 15 的动态 Dex finalizer 报错**：M3 探针 exitCode=0 后约 15 秒，GC 时出现两条 `Failed to close dex file in finalizer`。本次未观察到进程闪退，但原因尚不确定。将 Node 生成类改成 InMemoryDexClassLoader 的实验仍复现，因此已完整撤回该实验；最终源码没有修改 AndroidClassLoader 或 Node24HostBridge 的类装载方式。不得把此项写成已修复。
- **资源尚未编译的原生 UI 工程**仍走旧 dynamic/marker 路径；本批真实 UI 的验证以按宿主 APK 编好的 project-res.apk 为前提。传统 grid/list/canvas、React/Vue/Web UI、通用 plugins.load、完整 OpenCV addon 等旧缺口仍在。
- 任务的高级 Java task 对象、全部 Date/number 输入和 activity intent task 还没有逐项等价验收；本批修复并验证的是原始任务示例实际使用的字段与操作。创建查询删除通过，也不等于已经验证未来定时触发。
- 44 个可执行候选含子脚本/组件，并非 44 个独立项目，尚未全部交互验收。不能将这批通过数当成三引擎 API 全等或高级版全兼容。

后续优先级：动态 Dex 回收原因 → 非编译资源 UI 与传统 UI 真正回调 → 插件/Web UI → 剩余原始示例逐项验收。
