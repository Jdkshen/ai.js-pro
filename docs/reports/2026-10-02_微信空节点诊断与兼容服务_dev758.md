## APK 对照发现

依据官方微信 8.0.79 / 3200 APK 和本地 Auto.js Pro 9.3.11-0 APK：

1. `AccExptServiceKt.DefaultWhiteServiceList` 包含 `com.google.android.accessibility.selecttospeak.SelectToSpeakService`。
2. `AccExptService.checkHasServiceInList` 读取已启用服务，将“包名/服务类名”与名单作字符串包含匹配。名单还可由 `clicfg_acc_white_service_list` 扩充。
3. `AccUtil.isAccessibilityEnabled` 在触摸探索、强制配置与缓存等判定之外，会查询该白名单。
4. `AccExptService.needClearNodeInfo` 在上述判定为 false 且清空比例配置不为零时，按配置返回 true，结果缓存 5 秒。
5. `MMAccessibilityDelegateWrap.onInitializeAccessibilityNodeInfo` 在该条件成立时可直接返回，不初始化类名、子节点等信息；另一路会调用 `clearInfo`。
6. Pro 的实际 APK 服务声明使用上述 `SelectToSpeakService` 类名，而本项目 dev-757 使用 Stardust 服务类名。

这条链路与用户的“只有微信包名、没有类名和子节点，Pro 同页能读”高度匹配。它提供了针对性的兼容修复依据；仍需用户原机验证是否还受其他配置影响。

反编译注意：本地 JADX 的常规输出把 `rd6.o0.D` 的包含判断条件显示反了。已用 fallback 指令输出核对：`indexOf` 结果小于零返回 0，否则返回 1，确认为包含匹配，不能直接照搬常规输出中的 `< 0` 表达式。
