# MCP 与电脑连接修复验收

环境：K40（cccc62c7）、Android 16；VS Code 已安装的官方 Auto.js Pro 扩展 9.0.9；电脑 192.168.10.7，手机 Wi-Fi 192.168.10.5。

最终版本：**dev-1048，已发布并安装到 K40**。更新源 http://192.168.10.7:8080/update.json 与 APK 均返回 HTTP 200；清单大小、SHA-256 与实际产物一致。

## 修复内容

- MCP 继续公开 39 项工具；32 个规范名称均接受 camelCase 调用，并保留 learnAutoJsSkill 等历史拼写。
- CORS 只接受 http/https 的 localhost、127/8、::1 Origin；预检不调用工具，实际请求保留 Bearer/Host 校验。
- 路径兼容反斜杠和允许根目录内的绝对路径；继续拒绝越界、NUL、目录边界外访问。
- 未知工具或调用参数形状错误返回 -32602，未知方法 -32601；执行业务失败仍返回 result.isError。
- MCP 地址枚举优先 Wi-Fi/热点/有线并过滤 VPN/蜂窝等接口，启动和心跳复用同一地址逻辑。
- 电脑连接默认走 ws-rpc 21029，显式 :8327 保留旧协议；修正真实动态监听端口、授权连接数、重试取消、mDNS 注册与 provider 状态。
- Flutter 移除没有发现方式时硬编码显示 provider 的逻辑，外置源码已更新并重新生成 AOT。
- 补上打开抽屉期间每 2 秒的电脑连接状态刷新，复用既有生命周期与去重保护；否则后台实际已重连，抽屉还会保留旧的未连接/mDNS 状态。

## 收尾发现与处理

候选 dev-1047 在实际关闭调试服务器时出现主线程 NetworkOnMainThreadException：Service.onDestroy → ProRpcServer.stop → Session.close → WebSocket.close 写关闭帧。

dev-1047 曾从最新更新源撤回，当时暂时恢复 dev-1046；回归完成后已正式发布 dev-1048。dev-1048 改为外部关闭直接释放 socket，不写网络、不等待写锁；对端 close 帧的回应只在读线程处理。

修复后的协议 16 项（原 13 + 3 个真实 socket 关闭回归）及连接状态 18 项，合计 34 项 Gradle 专项测试通过。在 K40 上完成 3 轮已有官方插件连接时关闭服务器：PID 始终为 9126，三个动态端口 38023/40595/39513 与对应电脑 TCP 会话均关闭，server_enabled=false，无该进程的新崩溃。证据为 1048-server-stop-results.json、1048-server-repeat-results.json。

最终抽屉补丁打入 AOT 后，再次装机验证：抽屉保持打开即自动显示“电脑已连接 / ws-rpc / mDNS”；31 项 MCP 检查再次通过。结束时关闭两项测试服务，PID 9127 保持不变，端口 40591 与电脑会话已关闭，无新崩溃；手机停在宿主文件主界面。MCP/电脑服务开关恢复为测试前的关闭状态，未开启写入/执行授权或重置令牌。
