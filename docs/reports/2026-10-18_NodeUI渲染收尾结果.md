## 根因与最终修改

### 1. MaterialButton 的图标被 inflater 最后一步清空

`TextViewInflater.applyPendingAttributes()` 原先对所有 TextView 无条件调用 `setCompoundDrawables()`，即使没有待应用的 drawableLeft/Top/Right/Bottom。该调用重置了 MaterialButton 的相对方向 compound drawable；`getIcon()` 字段仍非空，所以旧日志的 Drawable、尺寸与 tint 正常不能证明图标实际在绘制。

`TextViewInflater.java:408` 新增 5 行：四个 pending drawable 均为空时直接返回。有显式 drawable 属性时保持原来的合并与清理行为。不需要在 adapter 的 create/bind 或每帧反复恢复图标。

本示例没有自己的 drawable 目录，爱心/分享实际引用宿主 engine 的有效 PNG，当前问题不需要增加 vector 解析或生成 project-res.apk。试做的资源解析/adapter 补丁已按会话开始时的快照撤回，以下文件 SHA-256 与 `output/codex-node-review-baseline` 完全一致：`MaterialButtonAttributes.java`、`NodeUiHost.java`、`ProjectResources.java`、`Drawables.java`。基线中的用户未提交改动保留。

### 2. 原 Toolbar 被内容覆盖，额外标题栏又重复计算状态栏

示例 XML 已声明 `AppBarLayout + MaterialToolbar`，但动态 inflater 没有应用 ViewPager 的 ScrollingViewBehavior，内容从顶部绘制。旧兜底无条件在外面再加一个硬编码标题栏，并手工追加 152px 状态栏 padding，产生大片留白。

- `NodeUiRenderFix.java:69`：仅动态路径、布局无 Toolbar 且有实际 title 时补标题栏；使用传入标题，删除硬编码演示标题和手工状态栏高度；删除 Activity 根树的 compound drawable 绘制补丁。
- `NodeUiActivity.java:193`、`:261`：尊重已有 Toolbar、标题及 behavior；仅动态路径、无 behavior 且布局后确实重叠时，以实际重叠量增量调整滚动内容 topMargin。通过 `isLayoutRequested()` 防止待布局时重复累加，并隔离过期 content 的延迟回调。
- framework inflater 成功时不套动态标题栏或修改布局。
- 审查中撤掉额外的 onNewIntent/重载改动，本次未改变桥协议、onDestroy 关闭通知或 Flutter 返回链路。

### 3. 动态 AppBar 参数默认值与 XML 不一致

首轮真机滚动复验发现 Toolbar 仍会滚走。原因是程序式 `AppBarLayout.LayoutParams(width,height)` 默认 scrollFlags=1，而 XML 构造器在未声明 layout_scrollFlags 时默认 0。

- `DynamicLayoutInflater.java:322`：仅新生成的 AppBar 子布局参数恢复 XML 缺省值 0，保留已有合法参数。
- `BaseViewInflater.java:177`、`:651`：补 layout_scrollFlags 属性解析，保留显式 `scroll|enterAlways` 等符号组合、none/noScroll、十进制和十六进制参数的表达能力。不再靠 Activity 无条件清除所有滚动标志。

最终修改范围为以上 **5 个 Java 文件**，另加本报告。
