### 8.4 两个新踩的坑（已记入记忆）

1. **Rhino：不能给 `Object.create(runtime.xxx)` 已存在的 Java 方法名赋值**（装配期抛异常会直接让整个引擎 init 失败，表现为所有脚本都启动不了）→ 需要改行为时用「Java 侧重载/新方法」而非 JS 覆盖。
2. **MIUI（K40）：`am start -S` 强停 App 会解绑无障碍服务**，且 `settings put` 需在 App 进程启动之后执行才会真正绑定（顺序：先起 App → 再 `settings put secure accessibility_enabled 0/1` + `enabled_accessibility_services`）。用无 `-S` 的 `am start RunIntentActivity` 跑探针即可保住无障碍。

### 8.5 补修：`app.getTopActivity` 生命周期对齐（dev-741）

发布 740 后对发布实例复测发现：`app.getTopActivity()` 在「MainActivity 已在前台 + 透明 RunIntentActivity 叠加」场景返回 `null`。

根因：我们的 `AutoJs` 生命周期回调只有「created/resumed 时设、**任何 pause 都清空**」一套 `currentActivity` 语义；Pro 是**两个独立字段**：
- `currentActivity`：created/resumed 设、pause 清空（Pro 同款）；
- **`topActivity`：created/resumed/started 都设，只在“被记录的那个 Activity 被销毁”时清空**（Pro `AbstractC4934$C4940` 原文）。

修复：`AppUtils` 增加独立 `mTopActivity` 字段；`AutoJs` 补 `onActivityStarted`/`onActivityDestroyed` 回调（destroyed 带 `== activity` 守卫）。

验证：同一「MainActivity + RunIntentActivity 叠加」场景，740 返回 `null` → 741 返回 `RunIntentActivity@...`；完整 probe4 在 741 实例上全绿（含 WebSocket 全链路、selector、observe）。

dev-741 发布：版本 741 / SHA-256 `sha256:0385732215f85429324074bce6f5f8f8606907daee3048d8ab4847f8e02cfc35` / 手机拉清单 HTTP 200；K40 实例已升级到 741 并重挂无障碍。

### 9.5 冒烟发现并修复的真实问题

- `$crypto.generateKeyPair("RSA")`（省略长度）**必崩**：Rhino 把省略参数传成 `Undefined.SCRIPTABLE_UNDEFINED`（toString="undefined"，但 `instanceof org.mozilla.javascript.Undefined` 为 **false**）→ 被当数字解析抛 `For input string: "undefined"`。
  修复：`Crypto` 增加 `isUndefined()` 判定（instanceof + toString 双判）并对 `Debug/ZipSupport/ColorMapping` 同类判定同步加固。
  复测：`Rhino 引擎/消息处理(加密、摘要、编码)/加密解密.js` FAIL → **PASS**。
- **`images.rotate(90/180/270)`（QuickJS）必崩**：bootstrap 包装层在 native 已返回正确旋转尺寸的情况下，**又给帧对象赋 `width/height`**；而 `wrapFrame` 的属性是 `Object.defineProperties` 只读（未加 `writable: true`）→ 抛 `TypeError: 'width' is read-only` 并中断整个脚本（`QuickJS Images Advanced 测试.js` 在 `rotate(frame, 90)` 处直接终止）。
  修复：删除 `images.rotate` 里多余的尺寸赋值（`quickjs_jni.cpp` bootstrap；native `NativeFrameStore::rotate` 本就按 90/270 交换 logical 尺寸）。已重编三 ABI 原生库。
  验证：已复测 `QuickJS Images Advanced 测试.js` FAIL → **PASS**（dev-744）。
- **数据库 API 补齐（dev-745）**：见 §9.3；关键坑：AOSP `SQLiteSession` 在 `onBegin` 回调返回后才登记事务栈——事务体若写在 `onBegin` 里，`setTransactionSuccessful`/`endTransaction` 必抛 `Cannot perform this operation because there is no current transaction`（K40/Android 11+ 实测）。
- **箭头函数 → Java 接口（dev-745）**：Rhino fork（1.7.7.2）的 `NativeJavaObject.coerceTypeImpl` 对 interface 目标只认 `instanceof NativeFunction`；`function(){}` 的编译产物是 InterpretedFunction（可），`ArrowFunction` 不是 → 直接传箭头给 `setOnClickListener` 抛 Cannot convert。修复：`ArrowFunctionSupport` 用 `compileFunction` 把箭头包成转发函数；`NativeView.get` 对 `name.contains("Listener")` 的方法对象包装并缓存。
- **`require` 在含空格路径崩（dev-745）**：`ModuleSourceProviderBase.loadSource` 对 "/" 开头的 moduleId 调 `URI.create`（Android 的 URI 容忍非 ASCII、不容忍空格）→ `AssetAndUrlModuleSourceProvider` 在 `loadSource` 里把空格转 `%20`（file: 打开时还原）。
