## 0. 结论摘要（先看这段）

1. **Pro 的「电脑连接」就是 `org.autojs.autojs.debugserver` 子系统**，被 R8 整体改名塞进了 `okhttp3/internal/io/` 这个假包（不是 okhttp）。类名混淆了，但 Kotlin 的 `@Metadata` / `@s2(c="…")` / `@jm1("…")` 标注保留了**原始类名、源文件名、行号和 RPC 方法名**，因此可 1:1 还原。
2. **端口 9317 在本 APK 里根本不存在**（6 个 dex 的字符串表 + `lib/arm64-v8a/libapp.so` 全量扫描均 0 命中）。Pro 服务端用的是 `InetSocketAddress(0)` **动态端口**；「手机主动连电脑」的默认端口是 **21029**；FTP 是 **21030**。
3. **握手不是 `hello` / `client_version`**，而是 **JSON-RPC 2.0 over WebSocket**：首个调用是 `debug.authorize(token)`，返回设备信息 DTO（`protocolVersion=1`、`appVersion="Pro 9.3.11-0"`、`appVersionCode=9131100`、`deviceName`、`deviceId`、`uuid`）。
4. **帧格式**是「4 字节大端整数类型 + 负载」，类型 1 = JSON，类型 2 = 二进制（36 字节 ASCII 通道 id + 数据）。JSON 也是装在二进制 WS 帧里发的。
5. **两种模式**：`mode=2` 手机监听（ServerState `DISCONNECTED/CONNECTING/LISTENING`）；`mode=1` 手机回连电脑 `ws://host:port`（ClientState `DISCONNECTED/CONNECTING/CONNECTED`，断线后 1 s 重试、最多 3 次，然后提示 `Failed to connect or lost connection of <uri>`）。**关闭客户端模式是空实现（no-op）**。
6. **发现机制有两条**：
   - `ContentProvider`（给 adb / USB 用）：authority `com.boyai.auma.debug.provider`，path `debug-server`，列 `state/type/port`，`type` 固定 `"ws-rpc"`，`state` 是 ServerState 的 **ordinal**（0/1/2），`port` 读的是真实 `ServerSocket` 端口。
   - **mDNS/NSD**（给局域网用）：服务类型 `_autojsprodebug._tcp.`，服务名 `AutoJsProDevice-<uuid>`，无 TXT 记录。
7. **鉴权**：手机弹 `DebugAuthConfirmActivity` 显示 `md5(token)` 大写、每 2 字符一段用 `:` 连接（`AB:CD:EF:12:34:56`），用户在电脑上比对后确认；20 s 超时即拒绝。之后**每次调用**都必须带**顶层** `token` 字段，否则返回 JSON-RPC error `{code:3, message:"Forbidden"}`。
8. **和我们 POC 的协议不是同一代**：我们用 `{id,type,data}` 帧 + `hello`/`client_version=4` + 固定 9317/8327；Pro 用 `ws-rpc` + JSON-RPC。**自研扩展目前无法与真 Pro（含旧包 `org.autojs.autojspro`）互通**，两条链路完全独立。

## 2. 传输层：WebSocket + 4 字节帧头

`RpcService.WebSocketJsonRpcConnection`（`C6642$֏`）：

    // 发送 JSON：先写 4 字节类型 1，再写 JSON 字节
    void sendJson(ObjectNode json) {
        ByteArrayOutputStream out = new ByteArrayOutputStream();
        new DataOutputStream(out).writeInt(1);
        mapper.writeValue(out, json);
        webSocket.send(out.toByteArray());
    }

    // 发送二进制：类型 2 + 36 字节 ASCII 通道 id + 数据
    void sendBinary(String id /* len==36 */, byte[] data) {
        if (id.length() != 36) throw new IllegalStateException("Check failed.");
        ByteArrayOutputStream out = new ByteArrayOutputStream();
        new DataOutputStream(out).writeInt(2);
        out.write(id.getBytes(UTF_8));
        out.write(data);
        webSocket.send(out.toByteArray());
    }

接收侧（`C6643.mo15141`）：读 `buffer.getInt(0)`
- `==1` → `position(4)` 之后按 Jackson 解析成 JSON，交给 `JsonRpcServerAndClient` 处理；
- `==2` → 读 36 字节通道 id（ASCII），`position(40)`，其余字节作为二进制回调给等待该 id 的挂起协程（`WebSocketJsonRpcConnection.getBinary(id, timeout)`）；
- 其它类型 → `return false`（丢弃）。

对比：我们的 `DevPluginFrames` 也是「类型 + 负载」，但类型是 **byte**、负载是自定义 JSON，且没有 36 字节通道 id。

    String ns   = parts[0];          // debug / vfs / rsync

## 4. 握手与鉴权（真正的「连接状态机」入口）

### 4.1 调用序列

    [PC] ---- ws://<phone-ip>:<dynamic-port>  (或 phone 主动连 pc: ws://pc:21029) ----> [Phone]
    [PC] {"jsonrpc":"2.0","id":"<uuid>","method":"debug.authorize","params":{"token":"<token>"}}
    [Phone] -> 若 token 未授权：弹 DebugAuthConfirmActivity，显示 md5(token) 大写分组
    [Phone] <---- {"jsonrpc":"2.0","id":"<uuid>","result":{
                         "deviceName":"Xiaomi MI 8",
                         "deviceId":"<稳定设备号>",
                         "uuid":"<本次会话 UUID>",
                         "appVersion":"Pro 9.3.11-0",
                         "appVersionCode":9131100,
                         "protocolVersion":1 }}
    [PC] 之后每次请求都必须带顶层 token：
         {"jsonrpc":"2.0","id":"…","method":"debug.runFile","token":"<token>","params":{"file":"…"}}

- 顶层 `token` 是**扩展字段**（不在 `params` 里）。判定依据：`zl1.m11888(requestJson, out)` 在分发前遍历拦截器 `im1.mo5653(al1Var)`（`zl1.java:837`），`u2.mo5653` 在该对象上读 `method` 与 `token` 两个**顶层**字段。
- `debug.authorize` 的参数 `token` 在 `params` 里（`@km1("token") String token`）。

### 4.2 鉴权失败的错误码（`mr3` = JSON-RPC error）

| 场景 | code | message |
|---|---|---|
| 请求不是 JSON 对象 / 非 authorize 且无 token | `2` | `params should be a object` / `no token field or token is not a string` |
| token 不在本连接已授权集合 | `3` | `Forbidden` |
| 用户在手机上点了拒绝 / 20 s 超时 | `3` | `user rejected` |

> 注意语义反直觉：`DeveloperModeAuthorizer` 的 `CompletableDeferred<Boolean>` 在**用户拒绝**时被 `complete(TRUE)`，因此 `authorize` 里是 `if (result) throw mr3(3, "user rejected")`；超时（`withTimeoutOrNull(20000)` 得 `null`）按 `false` 处理，同样落到 `user rejected`。

### 4.3 授权弹窗（`DebugAuthConfirmActivity`）

- 入参：`Intent.putExtra("token", token)`，`addFlags(0x10000000)` = `FLAG_ACTIVITY_NEW_TASK`。
- 展示码：`md5(token)` → 大写 → **每 2 个字符一段、`:` 分隔**（`e55` 分组 + `C4997.m13324(list, ":")`）。例：`A1:B2:C3:D4:E5:F6`。
- 结果：`hb.f7727.remove(token).complete(true/false)`，随后 `finish()`。
- 已授权设备持久化：`TrayPreferences(app, "debug")` 的 `getStringSet("devices")` 读入 `DeveloperModeAuthorizer.devices`（**代码中未发现写入点**，见「未知项」）。
- 会话内缓存：`u2.f19003: Set<String>`（按连接授权成功后加入）。

## 5. 状态机

### 5.1 枚举与迁移（`a3.java`）

    enum ServerState { DISCONNECTED, CONNECTING, LISTENING }   // a3.EnumC0866
    enum ClientState { DISCONNECTED, CONNECTING, CONNECTED }   // a3.EnumC0865

| 动作 | 迁移 | 代码 |
|---|---|---|
| 开服（`startServer`） | 仅在 `DISCONNECTED` 时：`DISCONNECTED → CONNECTING`；`RpcService.start()` 成功后 → `LISTENING`；任何异常被 `catch(Throwable)` 吞掉后仍置 `LISTENING`（**注意：失败也会显示 LISTENING**） | `d3.java` |
| 关服（`disconnectServer`） | `Running → Stopping → Stopped`，关闭所有 WS 连接、取消 `Job`、`NsdManager.unregisterService`，最后 `→ DISCONNECTED` | `c3.java` |
| 连电脑（`connectToServer(ip, port)`） | `ClientState` 由 `C6653` 的连接回调驱动（`CONNECTING → CONNECTED`，断开回 `DISCONNECTED`） | `b3.java` / `C6653` |
| 全空闲判定 | `a3.m1674() = (serverState==DISCONNECTED && clientState==DISCONNECTED)` | 日志/上报据此短路 |

`RpcService` 内部还有自己的四态机：`Stopped / Starting / Running / Stopping`（`EnumC6644`，`Mutex` 保证 `Stopped→Starting` 原子性）。

### 5.2 状态变更的对外事件

状态是 Kotlin 委托风格 `kz2` 观察者（`a3.C0867` / `a3.C0868`），每次变化：

    // C0867.mo1676（serverState）
    ScriptService.f1244.m723(y2.f22606, mapOf("server_state" to newValue.name(), "count" to 0));
    LocalMcp.debugState(newValue);              // 同时喂给 MCP 面板
    // C0868.mo1676（clientState）
    ScriptService.f1244.m723(y2.f22606, mapOf("client_state" to newValue.name(), "count" to 0));

- `y2.f22606 = "<混淆后的 y2 类全名>.state"`（`f76.m4104(cls, sb, ".state")`），即跨 Flutter/JS 的**内部事件总线 key**；
- `count` 恒为 **0**（`y2.mo5770("state")` 也硬编码 `"count", 0`）；真正的连接数在 `C6653.f30086.size()`，只出现在 `State.connectionCount` 的 `toString()` 里，**没有**被送出去。

### 5.3 Flutter ↔ Java 指令桥（`y2`）

    查询：action = "state"
      返回 { server_state: "LISTENING|CONNECTING|DISCONNECTED",
             client_state: "CONNECTED|CONNECTING|DISCONNECTED",

- 冷启动自动开服：`b2.m2307()` 读同一键为 `true` 就 `y2.enableServer(context)`；另注册广播 action `"svibN0q3D52vIAKC"` 触发同一动作。

## 6. 两种模式的实际行为

### 6.1 服务器模式（手机监听）

- `WebSocketServer` 构造：`super(new InetSocketAddress(0), ma6.f11477, …)` → **端口 0，由内核分配**；`startServer()` 返回 `InetSocketAddress(port=真实端口)`。
- 真实端口只通过两个出口暴露：
  1. `DebugContentProvider.query()`：`((InetSocketAddress) serverSocket.getLocalSocketAddress()).getPort()`；
  2. NSD 注册的 `NsdServiceInfo.port`。
- NSD 注册（`RpcService.start` 的协程体内，`o74.smali`）：

      NsdServiceInfo info = new NsdServiceInfo();
      info.setServiceName("AutoJsProDevice-" + RpcService.uuid);  // uuid = UUID.randomUUID()
      info.setServiceType("_autojsprodebug._tcp.");
      info.setPort(address.getPort());
      nsdManager.registerService(info, NsdManager.PROTOCOL_DNS_SD, RpcService.INSTANCE);

  回调 `onRegistrationFailed/onServiceRegistered/...` **全部空实现**（不重试、不提示）。

### 6.2 客户端模式（手机回连电脑）

- `b3`：`URI.create("ws://" + ip + ":" + port)` → `WebSocketServerAndClient.connectTo(uri)`。
- 去重：已存在同 URI 的连接 → 只 `reset retry count`（`C6654.m15150()`）。
- 重连（`C6653.mo15146` / `C6657`）：连接关闭后 `delay(1000)`，若 `retryCount < 3` 则 `retryCount++` 并重连（日志 `retry connecting %d/3: <uri>`）；第 4 次失败 → `bo0.m2610(reason ?: "Failed to connect or lost connection of <uri>")`（应用级提示）。
- 当前实现**没有**「记住上次电脑地址」的偏好项；host 只存在于 Flutter 侧 `set_debug_service` 的入参里。

## 8. 日志与工程目录

- `DebugLogAppender`（`r2.java`，log4j appender name=`"debug"`）：
  - 空闲（`DebugService.isIdle()`）时直接 return，不产生任何流量；
  - 文案：`MM-dd HH:mm:ss.SSS <file>/<LEVEL>: <message> <stacktrace>`；
  - 路径重写：`<cacheDir>/remote_project` → `remote:/`；`<filesDir>/.remote` → `.remote`；
  - 投递：对**每个**已连接 WS 发 `debug.clientLog` 通知。
- 远端工程目录：`DebugService.remoteProjectDir = File(context.getCacheDir(), "remote_project")`（对应我们 `cache/remote_project/<hash>/` 的约定）。
- 另有 `RemoteTerminalService`（`openTerminal` → `{id, localPort}`，本地起 TCP 转发）和 `RSync`（文件同步，带 `SyncFilesTask` / `FileWalker`）。

## 9. 与我们 POC 实现的差异（逐条）

> POC 侧代码：`apps/app/src/main/java/com/jdkshen/aijspro/pluginclient/DevPluginServer.java`、`DevPluginFrames.java`、`DebugServerProvider.java`、`DevPluginPrefs.java`、`DevPluginServerService.java`；电脑侧 `vscode-extension/src/connection.ts`、`manager.ts`。

| # | 维度 | Pro 9.3.11（真实） | 我们的 POC | 影响 |
|---|---|---|---|---|
| 1 | 服务端端口 | `InetSocketAddress(0)` 动态，运行期通过 provider / mDNS 公布 | 固定 `9317`（`DevPluginServer.PORT`，L85；`bind(new InetSocketAddress(PORT), 8)`，L163） | **官方扩展绝不认我们的 9317**；反过来我们也接不上官方扩展 |
| 2 | 帧协议 | 4 字节大端类型（1=JSON / 2=二进制）+ `36` 字节通道 id | `DevPluginFrames` 自定义（byte 类型 + JSON） | 二进制层不兼容 |
| 3 | 应用层 | JSON-RPC 2.0，`method="ns.name"` | 自定义 `{id, type:"command"|"bytes_command"|"hello", data}` | 语义层不兼容 |
| 4 | 握手 | `debug.authorize` 返回 `AuthInfo` | 设备先发 `hello`（`device_name`/`device_id`），扩展回 `hello` 带 `client_version=4`（`connection.ts:337`） | 双向都不认识对方的握手 |
| 5 | 版本协商 | `protocolVersion=1` + `appVersion`/`appVersionCode` | `client_version=4`（手机只 `mClientVersion=asLong(...)` 存着，不校验、不回报） | 版本不匹配时双方都静默 |
| 6 | 鉴权 | token + 手机端 6 段 MD5 确认码 + 20 s 超时 + 持久化设备集合 | 无鉴权（连上即用） | 安全性差距；官方扩展的 authorize 拿不到我们的响应会直接失败 |
| 7 | 状态机 | `ServerState{DISCONNECTED,CONNECTING,LISTENING}` / `ClientState{DISCONNECTED,CONNECTING,CONNECTED}` | `isRunning()` + 反射 `mConnectingSocket` 推 `CONNECTED/CONNECTING/DISCONNECTED` | 命名可对齐，语义可保留 |
| 8 | 状态事件 | `server_state` / `client_state` / `count` 三键事件（`count` 恒 0） | UI 直接轮询/反射 | 建议按 Pro 的键名补一条事件通道 |
| 9 | USB 发现 | authority `com.boyai.auma.debug.provider`，`type=ws-rpc` | authority `org.autojs.autojspro.debug.provider`（旧包名），`type="legacy"`，`port=9317`（`DebugServerProvider.java:25/38-44`） | 官方扩展在真机上会读到 `type=ws-rpc`；我们的 provider 也可能因 authority 不同而没被读 |
| 10 | mDNS | `_autojsprodebug._tcp.` | 无 | 局域网自动发现缺一条路 |
| 11 | 回连默认端口 | **21029**（`y2.smali:348` `const/16 v0, 0x5225`） | **8327**（`DevPluginServer.COMPUTER_PORT`，L100） | 真 Pro 主动连我们的 8327 会失败 |
| 12 | 重连策略 | 断开后 `delay(1000)`，最多 3 次，失败提示 | 自研重连线程（3 s 超时，无次数上限） | 行为不同，可保留但建议对齐日志/上限 |
| 13 | 关闭客户端模式 | 空实现（no-op） | 会清 host、断连接 | 我们比 Pro 完整，可保留 |
| 14 | 电脑地址持久化 | 无偏好；host 仅来自 Flutter 入参 | `computer_host`（`DevPluginServer.java:98`） | 我们更好，可保留 |
| 15 | 服务开关持久化 | `9Zidw8H1YWzUx5PP`（`SettingsService`/`b2`） | `DevPluginPrefs` 的 `isServerEnabled` | 等价，键名不同无所谓 |
| 16 | 日志通道 | `debug.clientLog`（notification，每条日志一帧）+ `debug.debugEvent` | `broadcastLog` 塞进 `response.data` | 通道形态不同 |
| 17 | 工程目录 | `cacheDir/remote_project` | `cache/remote_project/<hash>/` | 基本一致 |
| 18 | 额外能力 | `enableFtpServer`(21030)、`enableVfs`、`rsync.syncFiles`、`openTerminal` | 无 | 可选择性补齐 |

**关于「9317 是 Pro 的协议」这一假设**：在本次抽出的目标 APK（6 个 dex + libapp.so）以及旧包 `base.apk`（`org.autojs.autojspro`）的字符串层面，都**没有** 9317 这个端口常量，也没有 `client_version`/`hello` 这套字段；两版都是 `ws-rpc` + `_autojsprodebug._tcp.`。结论：9317 + hello 是我们自研扩展的私有协议，**不是** Pro 的历史协议（至少不是这两个已拉取版本）。

## 10. 可直接落地的修改建议

> 按优先级排列；只给方案与落点，**本次未改任何代码**。

### P0-1（若目标是「与官方扩展/真机 Pro 互通」）：实现 `ws-rpc` 通道

1. 在 `pluginclient/` 新增 `ProRpcConnection`（OkHttp `WebSocket` 或 `Java-WebSocket` 均可）：
   - 帧编码：`DataOutputStream.writeInt(1) + json` / `writeInt(2) + 36B通道id + payload`；
   - 解码：`ByteBuffer.getInt(0)` 分派，`==1` 走 Jackson/Gson，`==2` 按 36 字符 id 交给等待者。
2. 方法表按 §3.1 的 23 个方法名注册，先实现 `debug.authorize`、`debug.runFile`、`debug.runProject`、`debug.stop`、`debug.stopAll`、`debug.listFiles`、`debug.inspectLayout`、`vfs.*` —— 覆盖我们现有 `DevPluginServer` 的 run/stop/inspect_layout/screenshot/list_files 能力。
3. 保留现有 `hello` 协议作为 `legacy` 分支：`9317` 端口走 legacy，动态端口走 `ws-rpc`。

### P0-2：修掉固定端口与发现信息

1. `DevPluginServer` 增加动态端口模式（`new ServerSocket(0)`），把真实端口存字段，供 `DebugServerProvider` 与 mDNS 读取。
2. `DebugServerProvider`（`DebugServerProvider.java:25/38-44`）：
   - 增加第二个 authority `com.boyai.auma.debug.provider`（新包名），保留 `org.autojs.autojspro.debug.provider` 兼容旧扩展 —— 两个 `<provider>` 声明指向同一实现即可；
   - `type` 按通道返回：legacy 分支 `"legacy"`，ws-rpc 分支 `"ws-rpc"`；
   - `port` 返回真实端口，未监听时返回 `0`（Pro 就是这么做的），`state` 用 `0/1/2` 三态而不是只有 0/2。
3. 新增 `NsdManager` 注册：`_autojsprodebug._tcp.` + `AutoJsProDevice-<uuid>`，`setPort(真实端口)`；停服时 `unregisterService`。

### P0-3：端口常量语义修正

- 在 `DevPluginServer` / `DebugServerProvider` 注释里把「9317 是 Auto.js Pro 的端口」改为「9317 是本项目自研扩展的默认端口；Pro 9.x 用动态端口 + 21029 回连端口」。
- 新增常量 `PRO_COMPUTER_DEFAULT_PORT = 21029`，用于「尝试按 Pro 默认端口回连电脑」的场景（可选）。

### P1-1：把鉴权补上（对齐 Pro 的 authorize）

- 新增 `debug.authorize(token)`：token 未授权时弹「MD5 六段码」确认框（复用 Pro 的呈现方式：`md5(token).toUpperCase()` 每 2 字符一段、`:` 连接），20 s 超时视为拒绝；
- 之后每个请求校验**顶层** `token`，失败返回 `{code:3,message:"Forbidden"}`；
- 设备集合持久化到 `DevPluginPrefs`（对应 Pro 的 `TrayPreferences("debug").getStringSet("devices")`）。

### P1-2：状态机对齐命名

- 在 `DevPluginServer` 内暴露 `ServerState`/`ClientState` 两个枚举（名字照抄 Pro），替换现在 `isRunning()` + 反射 `mConnectingSocket` 的推断；
- 每次变化发事件 `{server_state, client_state, count}`，`count` 用真实连接数（Pro 这里恒 0，是它的缺陷，我们没必要学）。

### P1-3：回连行为

- 重连 `delay(1000)`、最多 3 次、失败提示 `Failed to connect or lost connection of <uri>`（可本地化）；
- 关闭客户端模式时除了清 host，还应取消重连 Job（Pro 是 no-op，我们保持现状更好）。

### P2：可选能力

- `debug.enableFtpServer`（端口 21030）→ 让电脑用 FTP 浏览手机文件；
- `debug.enableVfs` → 返回 `{root, home}`，配合 `vfs.*` 做虚拟文件系统；
- `rsync.syncFiles` → 增量同步工程（比我们整包推送 zip 更省流量）；
- `debug.clientLog` 通知 → 日志按条推，而不是塞在响应里。

### P2：文档/扩展侧

- `vscode-extension/src/manager.ts` 的「默认 9317」「回连 8327」应改注释为**私有协议**；若要支持真 Pro，需要另写 `ProWsRpcClient`（`debug.authorize` → 顶层 token → 动态端口）。
- 扩展侧目前**完全没有**用 adb `content query` 做 USB 发现（`grep "debug.provider" vscode-extension/src` 为空），官方扩展有；要不要补取决于是否要免 IP 连接。

## 11. 未知项 / 局限

1. `DeveloperModeAuthorizer.devices`（`TrayPreferences("debug").getStringSet("devices")`）**只见到读、没见到写**：本次 jadx 有 182 个类反编译失败（smali 可读但未逐类枚举全部写入点），不排除写入在某个失败类里。→「记住这台电脑」是否真的持久化，需要在真机上验证（授权一次后杀进程重连是否还要点确认）。
2. `RpcService` 顶层 `start/stop/connectTo` 的方法体被 R8 内联进协程类（`o74` = `RpcService$start$2`），`Ԩ.smali` 只剩 7 个方法；本文的 `start` 流程是**从 `o74.invokeSuspend` 逐指令读出来的**，逻辑可信，但方法级调用栈无法直接列出。
3. 旧包（`org.autojs.autojspro`，`base.apk`）只做了字符串层面比对（`ws-rpc`、`_autojsprodebug._tcp.`、authority 存在），**未逐类还原**；其默认端口是否也是 21029 未验证。
4. 「插件版本匹配与错误提示」在手机侧**不存在**：Pro 只是把 `protocolVersion` 放在 authorize 返回值里，是否兼容由电脑端扩展判断，手机不报错、不阻断。所以「版本不匹配提示」要么在扩展侧实现，要么我们自己在 `authorize` 里加校验（会与官方扩展行为不一致，需权衡）。
5. Flutter 侧 UI 文案（如「主动连接电脑」「正在连接」「没有任何连接信息，请先连接到WiFi或开启手机热点哦~」「请输入用于调试的VSCode所在电脑的IP地址。需要手机和电脑在同一局域网中，比如连接到同一WiFi。更多信息参见连接教程。」）是从 `libapp.so` 的 UTF-16 字符串区**偏移匹配**得到的，存在同段干扰，个别字符可能不准，仅作参考。
