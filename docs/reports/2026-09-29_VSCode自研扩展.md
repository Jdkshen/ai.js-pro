# 自研 AI.js Pro VS Code 扩展（连接/运行/日志/推送/文件浏览）

日期：2026-09-29（晚，dev-728 发布后）
目标：不再依赖官方 `hyb1996.auto-js-pro-ext`，电脑端用自己的 VS Code 扩展打通
「连接 → 运行文件/工程 → 实时日志 → 停止 → 保存推送 → 设备文件浏览」。

## 手机侧（本仓库）

- 新命令（官方扩展没有的扩展命令，走同一份 `DevPluginFrames` 协议与
  `command` / `response_<id>` 消息模型）：
  - `list_files`：列出脚本目录（`path`、`recursive`），返回
    `{files:[{path,size,mtime}], dirs:[...], truncated}`；
  - `read_file`：读文件，内容以 **bytes 帧**返回，`response` 里带 `md5` 供配对；
  - `write_file`：写入 UTF-8 文本（父目录自动创建）。
- 路径安全：所有路径相对手机脚本目录，规范化后校验，`../` 与符号链接逃逸直接报错
  （`DevPluginFileService.resolve`）；单文件读取上限 8MB。
- 实现：`DevPluginFileService`（纯逻辑，可 JVM 单测）+ `DevPluginServer.Session`
  的 `handleFileCommand`（后台线程读写、失败在 `response.data.error` 里给原因）。
- 官方扩展兼容：不发送这三个命令时行为完全不变；其余命令（run/stop/stopAll/save/
  rerun/run_project/save_project）沿用原路由。

## 扩展工程（`vscode-extension/`）

`jdkshen.aijspro-vscode`，TypeScript + esbuild，无运行时 npm 依赖（zip 由 `src/zip.ts`
自己写：deflate-raw + UTF-8 文件名）。

| 文件 | 职责 |
|---|---|
| `src/protocol.ts` | 帧编解码（`[u32 len][u32 type][payload]`）、md5 |
| `src/connection.ts` | 一条设备连接：hello 握手（设备先说）、命令/bytes_command、`response_<id>` 配对、`log` 事件、read_file 的 bytes 配对 |
| `src/manager.ts` | 监听 8327（手机回连）+ 主动拨 9317；多设备、自动重连、记住地址（跳过 USB 回环地址） |
| `src/tree.ts` | 「AI.js Pro 设备文件」树（懒加载 list_files） |
| `src/extension.ts` | 命令、状态栏、输出面板、保存自动推送、工程 zip 推送（带 deletedFiles 增量） |
| `src/zip.ts` | 最小 zip 生成器 |

功能：连接/断开 + 自动回连、运行当前文件（编辑器标题栏 ▶）、推送并运行整个工程、
停止当前/全部、实时日志、保存自动推送（`aijspro.pushOnSave`）、设备文件打开/下载/
运行、多设备切换（`aijspro.devices`）、排除项 `aijspro.exclude`。

图标：扩展徽标与标题栏「运行当前文件 / 推送并运行工程」按钮都用应用图标
（`modules/engine/.../ai_js_pro_logo.png` → `images/icon.png`，由 `scripts/make-icon.py` 生成）。

## 断点调试（DAP，dev-731 + 扩展 0.2.0）

官方扩展的「断点调试」是唯一还没对齐的大块能力。本版把**应用内置 Rhino 调试器**直接
接进 VS Code 调试协议（DAP），不引入任何第三方依赖。

### 手机侧（dev-731）

`pluginclient/DevPluginDebugService.java`（新）复用 `DebuggerSingleton` 的 `Debugger`：

| 命令 | 说明 |
|---|---|
| `debug_run` | 新开调试会话：停掉上一个 → `[debug]` 前缀编译运行 → `debugger.attach(execution)`；断点 1-based |
| `debug_set_breakpoints` | 运行中整体替换断点集 |
| `debug_resume` | `continue / next / stepIn / stepOut` → `resume/stepOver/stepInto/stepOut` |
| `debug_evaluate` | `Dim.contextSwitch(frame)` + `Dim.eval(expr)` |
| `debug_variables` | `ref=0` 是当前帧作用域对象；子属性（对象）由设备分配新的 ref |
| `debug_terminate` | 结束会话（`forceStop` + 清断点） |

设备 → 扩展推送 `debug_event`：`started` / `stopped`（含 `reason`、`line`、`frames`）/ `output` /
`terminated`。调用栈与变量建立在**新增的** `Debugger.dim()` 访问器（引擎侧一行改动，暴露
`Dim` 的 `frameCount/getFrame/StackFrame.getUrl/getLineNumber/getFunctionName/scope/eval`）。

### 扩展侧（`vscode-extension/src/debug.ts`）

手写 `vscode.DebugAdapter`（`DebugAdapterInlineImplementation`），映射关系：

| DAP | 设备协议 |
|---|---|
| `launch` | 等设备连接（可带 `host` 自动连）→ 读 `program` 文件 → 记下断点 |
| `setBreakpoints` | 未运行时缓存，`configurationDone` 后随 `debug_run` 一起下发；运行中走 `debug_set_breakpoints` |
| `configurationDone` | `debug_run(name, script, lines)` |
| `stopped/output/terminated` 事件 | 设备 `debug_event` → DAP 事件（脚本日志在调试时也转发进「调试控制台」） |
| `stackTrace` | `stopped` 载荷里的帧缓存（帧 id = index+1） |
| `variables` | DAP ref = 设备 ref + 1（作用域 = ref 1） |
| `evaluate` | `debug_evaluate`，帧 id 减一 |
| `continue/next/stepIn/stepOut` | 同名命令 |

入口：命令「AI.js Pro: 调试当前文件(Debug File)」（编辑器标题栏/命令面板）或 F5（扩展提供
`resolveDebugConfiguration`，无需 launch.json 也能调当前文件）。`debuggers` 贡献点类型 `aijspro`、
语言 javascript。

### 验证（真机 + 隔离实例）

1. **设备协议 E2E**（`vscode-extension/test/debug-phone.ts`，K40 via adb forward）：
   断点命中第 4 行（栈帧 `work@4` + 全局 `@8`）→ `a + b = 3`、`b = 2` → 作用域变量
   （`b=2`）→ `next` 到第 5 行（reason=step）→ 清断点继续 → 脚本跑完（`DEBUG_SUM 3` /
   `DEBUG_END` 日志回传）→ `terminated`；重跑后 `debug_terminate` 立即结束。
2. **DAP 端到端**（`test/isolated-debug-e2e.ps1`）：干净 profile 装 VSIX → 新窗口打开临时
   工作区（一个 .js）→ 环境钩子自动连机、下断点（第 4 行）、`startDebugging` → 扩展日志
   捕获 `ready:` / `breakpoints: 4` / **`stopped line=4 reason=breakpoint frames=2`**。
   （注意：CLI 装扩展会产生一个临时实例，必须先等它退出、清 `CachedProfilesData` 再开窗口，
   否则新窗口沿用旧扫描结果、扩展不会激活——踩过一次。）

### V1 边界

- 只支持 **Rhino（第一代 API）**；QuickJS 脚本没有断点能力。
- 手机侧**同一时间只允许一个调试会话**（与 App 内置编辑器调试互斥）；`debug_run` 会顶掉上一个。
- 多帧的「作用域」都指向**栈顶帧**（设备协议只有 `ref=0` 是作用域）；`evaluate` 支持指定帧。
- 不支持 `pause`（Rhino 调试器没有暂停运行中脚本的入口）、不支持条件断点/日志断点/`setVariable`。

## 图色助手（dev-735 + 扩展 0.3.0）

官方扩展的「图色助手」是第二个大块能力：把手机屏幕拉进 VS Code，取色/框选/多点后直接生成
Auto.js 代码。本版把移植它，依旧零第三方依赖（截图、取色、模板裁剪全在 Webview/canvas 里做）。

### 手机侧（dev-735）

`pluginclient/DevPluginScreenshotService.java`（新）+ `DevPluginServer.handleScreenshot`：

| 命令 | 说明 |
|---|---|
| `screenshot` | 无障碍全屏截图（`AccessibilityScreenCapturer`，与布局分析同一通道：Android 11+ 且开启无障碍）→ PNG bytes 帧 + `response{width,height,size,md5}` |

要点：
- 走无障碍通道，**不弹 MediaProjection 授权**、不影响脚本自己的截图状态；系统对截图有限频，服务端限时 2.5s 等待。
- **原图尺寸回传**（不缩放）——扩展里量到的坐标就是屏幕坐标，生成的 `images.pixel(img, x, y)` 可直接用。
- 命令跑在单线程 `FILE_WORKER` 上（无障碍截图不能在主线程等）。

### 扩展侧（`vscode-extension/src/color.ts`）

Webview 面板「AI.js Pro 图色助手」（Beside 列打开）：

- 滚轮缩放（10%~800%）、拖拽平移、适应窗口/100%；鼠标位置带十字线 + **11×11 放大镜**（12x，中心像素高亮）。
- 三种模式：**取色**（单击取色，实时悬停取色）/ **框选**（拖拽选区）/ **多点**（依次点击，首点为基准）。
  - 单击取色会**固定该点**（黄色方框+圆圈标记，底部「固定」栏显示坐标/颜色）：移动鼠标只更新「悬停」栏，
    复制/插代码/测试都用固定点（无固定点时用悬停点）；「清除固定点」/重新截图释放。
- 底部状态栏：坐标、`#AARRGGBB`、`#RRGGBB`、int（十进制+hex）、rgb 以及对应色块。
- 生成代码（插到当前编辑器光标处，无编辑器时开新文件）——**写法对齐官方示例**
  （`sample/QuickJS 新引擎/图色处理/*.js`）：`requestScreenCapture('portrait')` 授权、
  `captureScreen({ mode: 'full' })` 取帧（变量名 `screen`）、命中结果 `JSON.stringify(point)`、结束 `screen.recycle()`；
  颜色字面量为**示例风格的 `#RRGGBB`**（大写）；找色/多点默认带**取样点附近的 `region`**（四周 ±100px，夹紧屏幕）
  与示例级阈值（findColor 24 / findMultiColors 20）。授权仍优先无障碍通道（不弹授权）。
  - 取色 → `images.pixel(img, x, y)` + `colors.toString` 日志
  - 找色 → `images.findColor(img, "#ffRRGGBB", { threshold: 4 })`
  - 多点找色 → `images.findMultiColors(img, 首点颜色, [[dx, dy, 颜色], …], { threshold: 4 })`
  - 找图 → 框选 → 「保存模板并插入找图代码」：裁剪区存到工作区 `templates/<x>_<y>_<w>x<h>.png`，插入 `images.read("templates/….png")` + `images.findImage(img, template, { threshold: 0.9 })`（模板用「推送并运行整个工程」同步到手机；相对路径相对于手机上的工程目录）
- 「截图另存到工作区」把当前截图存成 `shot-<时间>.png`；「重新截图」重拉一张。
- **测试（在手机上真跑一次）**：按钮「测试取色 / 测试找色 / 测试多点 / 测试找图」——
  把一段临时脚本通过现成的 `run` 命令发到手机上：脚本先 `images.requestScreenCapture({mode:'accessibility'})`
  重新截一张（**不弹授权**），再跑对应查找，最后 `console.log("AIJS_TEST " + JSON)` 回传；
  扩展从设备日志里解析结果 → 面板状态栏显示「命中 (x, y) 帧 w×h / 未命中 / 错误」，
  并在图上画一个青色虚线圆标记。
  - 复用已有协议：**手机侧零改动**（无需新命令）；测试脚本用 `__aijsResult(对象)` 手写 JSON 序列化，
    不依赖 `JSON` 全局（Rhino 下更稳）。
  - 实测（K40）：`images.requestScreenCapture({mode:'accessibility'})` → `true`，
    `captureScreen()` 1080×2400，`images.pixel/findColor/findImage/fromBase64/toBase64` 全可用。
- 截图 PNG 先落到扩展存储（`storageUri/screenshots/`），Webview 通过 `asWebviewUri` 加载（不走 data URL，体量小、不卡）。

### 边界

- 手机侧需 **dev-735+**；Android 11 以下不支持无障碍截图（后续可补 MediaProjection 通道）。
- 需要**无障碍服务开启**（与布局分析同一开关）；开关关着时截图返回明确报错。
- 放大镜/取色依赖 canvas 像素读取（PNG 经 `asWebviewUri` 加载）。
- **色彩口径必须跟 QuickJS 对齐**（用户报「取色和多点色都不对」的根因）：无障碍截图的缓冲区是**广色域**，
  Android 写 PNG 时会带 `iCCP` 色彩配置；浏览器 canvas 会按配置做色彩管理，面板读到的值 ≈ **Rhino** 的
  `images.pixel`（会转 sRGB），而 **QuickJS** 的 `images.pixel` 返回**原始像素值**。同一帧同一像素实测：
  PNG 原始 = `#3874cb`（=QuickJS `#FF3874CB`），canvas/转换后 = `#1876d2`（=Rhino `#ff1876d2`）。
  修法：写盘前用 `stripColorProfile()` 去掉 `iCCP/sBIT/gAMA/sRGB` 块（canvas 按 sRGB 直读 = 原始值），
  并让「测试」脚本固定跑 QuickJS（首行 `// @engine quickjs`）。⚠️ 用 Rhino 跑同一份代码时数值会不同。
- QuickJS 的帧对象是「属性式」API：`img.width / img.height / img.pixelWidth`（**没有** `getWidth()`）——
  测试脚本里的尺寸探测两种写法都兼容（`typeof img.getWidth === "function"` 优先，否则读 `.width`）。
- **点对象的打印形状也对齐了 Auto.js（dev-737）**：Auto.js/Rhino 的 `findColor/findMultiColors/findImage`
  返回 Java `org.opencv.core.Point`（x/y 为 double），所以 `"" + point` → `{100.0, 575.0}`、`JSON.stringify`
  → `{"x":100.0,"y":575.0}`；QuickJS 原来是纯 JS 对象，拼接得到 `[object Object]`。修法：在 QuickJS 的
  JS 包装层（`logicalPointOf()` 等，实为 `quickjs_jni.cpp` 内嵌的 JS）与原生 `pointValue()` 给返回点挂
  **非枚举** `toString`（形状 `{x.0, y.0}`）→ `JSON.stringify` / `Object.keys` / `for-in` 均不受影响。
  ⚠️ 改原生 cpp 后必须重跑 `modules/engine/src/main/cpp/build-quickjs.ps1`（`jniLibs` 是预编译产物，
  gradle 有 `verifyQuickJsNativeLibrariesFresh` 闸门）。
- **模板大于搜索区域 = 报错（dev-738 修正）**：`findImage/findImageInRegion/matchTemplate` 的模板比搜索区域大时
  抛 `Template WxH is larger than source/search region WxH`（与 Rhino 引擎同文案）。依据：反汇编 **Auto.js Pro 9.3.11
  的两份第三方发行（五云 `org.autojs.autojspro` / 高级版 `com.boyai.auma`，核心逐指令一致）**——其旧 API 走
  `new Mat(src.rows-tpl.rows+1, src.cols-tpl.cols+1)`，模板更大时负尺寸直接进 OpenCV 原生层。
  2026-10-01 真机实测进一步确认：**Pro 的表现是「原生挂死」（无返回、无异常、`do_epoll_wait` 常驻）**，
  `try/catch` 捕不到——我们的友好抛错优于 Pro；完整证据、四引擎兼容矩阵与工具见
  `2026-10-01_AutoJsPro逆向与图色API对照.md`。
  2026-09-12 曾短暂改成「未找到返回 null」（误改），已在 dev-738 回退；`01-图色 API 自动回归.js`（断言抛错）
  与 `10-图色查找补充接口.js`（8x8 用例改为预期报错）在 dev-738 真机实测通过（`IMAGE_LOOKUP_EXTRA_DONE`）。
- 「测试」是**重新截一张**再找：面板里那张截图没变，所以命中标记的坐标属于「测试那一刻」的屏幕；
  画面变化很大时以面板上的「重新截图」为准。测试脚本会占用一次脚本运行（与手动跑脚本共存）。

## 边界与注意事项

- 本扩展与官方 `hyb1996.auto-js-pro-ext` **都会监听 8327**：两者同时启用时只有一个能拿到
  回连接收端（先启动者占用；另一个仍可主动连手机 9317）。实测本机常规窗口里官方扩展已占
  8327；要用自研扩展的“手机自动回连”，先禁用官方扩展（或反过来只用一个）。
- 开发钩子 `AIJSPRO_E2E_CONNECT=host[:port]`：激活后直连该设备；`AIJSPRO_E2E_DEBUG=<行号>`
  自动下断点并启动调试；`AIJSPRO_E2E_COLOR=1` 自动打开图色助手；`AIJSPRO_E2E_DEBUG_LOG=<文件>`
  把上面这些流程的日志落到文件。都只用于自动化测试。
- 未实现：官方新版 RPC。
- 树视图依赖 dev-729+ 的 `list_files`；旧版本手机端会显示「读取目录失败」。
- 断点调试需要 dev-731+ 手机端 + 0.2.0+ 扩展；图色助手需要 dev-735+ 手机端 + 0.3.0+ 扩展。
- **「脚本编辑器」才是目标**（`src/editor-tracker.ts`）：运行 ▶、图色助手插代码都只认
  `scheme=file/untitled` 的编辑器；焦点在输出面板/调试控制台等非脚本文档时自动回退到最近编辑的脚本
  （踩坑：焦点在「AI.js Pro」输出面板时点 ▶，扩展把日志文本当脚本发到手机，手机上报
  `missing ; before statement`；往输出面板插代码则静默失败）。
