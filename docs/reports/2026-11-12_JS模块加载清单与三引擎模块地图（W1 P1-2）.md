## 2. 谁加载哪些 JS，按什么规则（每引擎各一条，含 file:line）

### 2.1 Rhino（app 内脚本 + 打包版主引擎）
- 引导：`RhinoJavaScriptEngine.kt:52` 直接打开 `assets/init.js`（唯一根级 JS）。
- 模块解析：`:234-239` 用 Rhino CommonJS `ModuleSourceProvider`（`AssetAndUrlModuleSourceProvider` + `SoftCachingModuleScriptProvider`），`:342 private val MODULES_PATH = "modules"` ⇒ **`assets/modules/*.js` 是按 `require("<名字>")` 解析的，不是固定清单**。
- ⇒ 这解释了「54 个里 29 个在 engine 的 java/kt 无字面引用」：它们由**脚本或其它模块按名 require**、或由 `init.js` 挂载。**因此「无字面引用」不能当死代码判据**（Phase 1 第 3 条的口径在这里被证实）。
- 待补（Phase 2 一次 grep 即可）：把 `require("<名>")` 的**名字集合**从 `assets/modules/**` 与 `assets/init.js` 里抽出来，与 54 个文件求差，才是「真未加载」候选。

## 3. 三引擎模块地图与「同名不同实现」（实测碰撞 5 组）

按「去掉 `__` 前缀/后缀与扩展名」归一化后，`assets/modules/*.js` 与 `assets/node24/**` 有 **5 组同名**：

| 归一化名 | Rhino 侧 | Node24 侧 | 备注 |
|---|---|---|---|
| console | `modules/__console__.js` | `node24/modules/console.js` | 各自实现 |
| media | `modules/__media__.js` | `node24/modules/media.js` | 各自实现 |
| ocr | `modules/__ocr__.js` | `node24/modules/ocr.js` | **已有同源文案/判据加固**（`OcrAvailability` + 三处同句） |
| plugins | `modules/__plugins__.js` | `node24/modules/plugins.js` | 各自实现 |
| ui | `modules/__ui__.js` | `node24/ui.js` | Node24 侧为注入式 UI（`Node24Service:598`） |

另有 **QuickJS 专属**：`modules/qjs-*.js`（console/sjbc/dialogs 等，见 2.2）——它们**不参与**上面的同名碰撞（是 QuickJS 兼容垫片）。

## 4. 对后续 JS 改动的直接约束（这就是本清单的用途）
1. 改 `assets/modules/**` 任一文件 ⇒ 先确认它是「Rhino require 按名」还是「被 init.js 挂载」；改名前一定先查 `require("<旧名>")` 的命中（**改文件名 = 断链**）。
2. 改 `assets/node24/**` ⇒ 文件名**必须**与 `Node24Prelude.java:46-57` 清单一致（清单是硬编码字符串）；新增模块要同时加清单。
3. 改 `assets/modules/qjs-*.js` ⇒ 文件名**必须**与 `QuickJsHostBridge.java:409` 数组一致。
4. 同名 5 组（console/media/ocr/plugins/ui）改一侧不影响另一侧 ⇒ **必须成对改或明确只改一侧**；OCR 那组已有「同源文案 + 同源判据」的复用面，可作范本。
