# 打包产物里还看得到 js 文件：目录工程脚本收进加密容器

日期：2026-09-29（晚，dev-727 发布后）
触发：用户在打包产物（象棋助手 APK）里发现除入口外的上百个 `.js` 文件全部可读。

## 现象与根因

- 「快照 so」（`encryptLevel=2` + `scriptStorage=native`）此前只对**入口脚本**生效：
  `writeEntryScript()` 把 main.js 编译成 QuickJS 字节码、加密并嵌进 `libaijscrypto.so` 尾部，
  然后在工作区删掉 `assets/project/main.js`。
- 但 `copyProjectToWorkspace()` 的目录分支是**整目录原样拷贝**：`src/**`、`tools/**`、
  `tests/**` 等 214 个 `.js` 以明文落在 `assets/project/**`，解包 APK 即可读到全部源码。
  → 实测旧产物 `xq-0645-new.apk`：`assets/project` 下 214 个 `.js` 全部明文（含 `version.js`）。

## 设计

- 新增**脚本容器**：目录工程里除入口脚本外的所有 `.js` → 打包成 zip（条目名 = 工程相对路径，
  `/` 分隔、UTF-8）→ 整体加密（AES/CBC + 8 字节文件头）→ 写成
  `assets/project/scripts.pack`；原文件从工作区删除，空目录骨架一并清掉。
- 新载荷类型 `PAYLOAD_TYPE_SCRIPT_PACK = 3`（`EncryptedScriptFileHeader`），常量
  `ScriptProtection.SCRIPT_PACK_FILE = "scripts.pack"`（打包端与运行端共用）。
- 运行端（`AssetsProjectLauncher.prepare()`）：复制资产后若发现 `scripts.pack`，先按
  `EncryptedScripts.decryptPayload()` 解密（新方案走原生库、旧方案回退 JVM），再展开到
  `filesDir/project/` 并删除容器。展开后目录布局与原来的打包方式完全一致，
  `require` / `files.read` 全部照旧，**两个引擎（Rhino/QuickJS）都不用改加载器**。
- 容器解密路径做了 zip-slip 防护（条目必须落在工程目录内）；解密失败/容器不完整时抛
  带明确原因的错误（`SplashActivity` 会把原因显示出来）。
- `EncryptedScripts.toSource()` 遇到容器载荷类型返回 null，避免把容器当源码执行。

## 顺带修复：产物目录排除没做路径规范化

用 `/sdcard/...`（符号链接路径）打开工程打包时，`copyDir` 的排除项比较是
「canonical child vs 非 canonical excluded」→ 字符串不相等 → 上一次的产物 APK 被拷进新包，
产出过一个 101 MB、里面套着上一版 APK 的自引用包。已改为排除项与子项都按 `getCanonicalFile()` 比较。

## 验证

1. **回归用例**（真机、androidTest）：`ApkBuilderEncryptionTest` 全类 **19/19 OK**，
   新增 `directoryProjectScriptsGoIntoEncryptedContainer`：
   - ① 加密档（assets 存放）：入口仍是加密文件；`src/mod.js`、`中文 目录/工具.js` 进容器；
     解密容器后逐字节等于源码；`data.json` 保持原样；产物里除入口外无 `.js`；
   - ② 快照 so 档：产物里**一个 `.js` 都没有**（入口在 so 里，其余在容器里）。
2. **端到端探针**：目录工程（入口 `require('./src/mod.js')` → 写标记）真机安装运行：
   - 加密档探针：`DIR_PACK_OK 42`；快照 so 探针：`DIR_PACK_OK 42`（容器解密展开 + require 全通）。
3. **真实场景**：手机上用 dev 版重新打包象棋工程（快照 so + QuickJS + 自动签名）：
   - 新产物 `象棋自动走棋_v0.6.45.apk`（50,998,886 B）：`assets/project` 里 **0 个 `.js`**，
     `scripts.pack`（1,028,296 B，头 `77 01 17 7F 12 12`、flags `0x0003`）、入口字节码在
     `libaijscrypto.so` 尾部；模型 `chessai_160x320_v5r.onnx` 等数据文件照旧可见；
   - 装机启动：对局工作台完整渲染（工作台 v0.6.45），全部模块从容器展开后正常加载。
   - 对比旧包：214 个明文 js → 0 个；体积 101 MB（含自引用旧包）→ 51 MB。

## 边界与后续（已知取舍）

- 运行时会**按原布局释放明文到应用私有目录**（`/data/data/<pkg>/files/project/`）——
  与修复前的行为一致；不 root 看不到。若要连私有目录也保持密文，需要再做一层
  「按需解密读取」（给 QuickJS 模块加载器接解密钩子、并验证 Rhino 的 provider 路径）。
- 非 `.js` 文件（`project.json`、模型、`.md`、`.py`、`release-manifest.json` 等）不进容器：
  入口配置必须可读，其余属于数据/PC 工具，不属「脚本源码」。若以后要求「一个文件都看不到」，
  可以把整目录（除 `project.json`/`splash.png`）都收进容器。
