# Node 原生界面示例加载失败（dev-1313+ 回归）— 排查报告与修改指引

> 2026-11-03。给接手的 AI：先读「一、结论摘要」「五、候选修复方向」，再按「八、验收标准」验证。
> 当前 LAN 发布版为 **dev-1318**；MI8 已装 1318；.4 已装 1317。仅 LAN、本地提交，不要 push、不要建 GitHub Release。

## 一、结论摘要

- 出问题的是 **Node 原生界面（Activity 路径）**，不是示例脚本本身：
  `ui.setMainActivity({realJava:true, layoutId: R.layout.activity_main})` → `NodeUiLocalActivity.onCreate` 里
  `getLayoutInflater().inflate(layoutId)` 抛 `InflateException`，卡在布局第 53 行的
  `com.google.android.material.bottomnavigation.BottomNavigationView`。
- 直接原因：BottomNavigationView 构造时按 `app:menu="@menu/menu_navigation"` 调
  `Resources.getLayout(0x7e030002)`，真机上**返回 null**（不是抛 NotFound），导致
  `SupportMenuInflater.parseMenu` 对 null parser 调 `getEventType()` → NPE → 包成 InflateException。
- 资源包本身没问题（表项、名字、值、字符串路径都对；PC 用 `tools/build-project-res.ps1` 对当前 APK 重建
  产物 SHA 与 APK 内置完全一致 `4c2c2768...`）。
- **回归窗口**：dev-1306 能跑；dev-1313 / 1315 / 1318 / 1322 全部失败。区间内 app 的
  `resources.arsc` 由 `3b615b49...` 变为 `fb8f9e48...`（+88 B，dev-1309 界面美化新增 style 导致资源 id 位移）。
- 已试过「检测 XML 打不开就重建一个 CompiledProjectResources 实例」，**无效**（1323 临时包）。
- 目前最可疑：Android 15 上 `CompiledProjectResources` 用
  `new Resources(assets, metrics, config)`（宿主 APK + 工程 `project-res.apk` 合并表）创建的 Resources，
  在 **Activity/主线程** 里 `getLayout()` 全部返回 null，但**同一进程**用脚本 API 加载同一资源包时 `getLayout()` 正常。
  即「合并资源表在 Activity 使用场景下打不开 XML」，需要换一种挂载方式或做降级。

## 三、已确认事实（都实测过）

1. 资源包内容正确：
   - 包内 `res/menu/menu_navigation.xml` 存在且可被 `aapt2 dump xmltree` 解析；
   - 布局里 `app:menu` 编译为 `(attr 0x7f04034b)=@0x7e030002`，当前 app 的 `attr/menu` 也是 `0x7f04034b`；
   - 侧车 `build/project-res.json` 的 `appResourcesSha256` 与已安装 APK 的 `resources.arsc` 摘要一致。
2. Activity 里资源表可查：
   - `getResourceName(0x7e030002)` = `com.jdkshen.aijspro.feature:menu/menu_navigation`；
   - `getValue(0x7e030002, tv, true)` → `type=3(TYPE_STRING), data=7, str=res/menu/menu_navigation.xml, cookie=9`；
   - Theme 继承链也正常（`0x7e040000 MainTheme` → app 的 Material3 主题）。
3. Activity 里任何 `getLayout()` 都 null：root layout `0x7e020000`、menu `0x7e030002`、app 自带 layout 也一样；
   `getAssets().open("AndroidManifest.xml")` 也是 FileNotFoundException（该现象在**能正常工作的脚本路径**里同样存在，
   因此只能说明「open 按名字找不到」，不单独作为判据）。
4. 同一进程用脚本 API 加载同一个资源包时：
```js
"nodejs";
const ctx = $autojs.androidContext;
ctx.loadResources("/sdcard/脚本/<sample>/build/project-res.apk");
const res = ctx.getResources();
const p = res.getLayout(0x7e030002);   // => 正常返回 XmlBlock$Parser
```
   `getLayout` 正常；`ProjectResourceBundle.load(applicationContext, dir)` 同样能拿到 parser。
5. 用同一资源包在 Activity 里重建 `CompiledProjectResources` 实例再试，仍失败（1323 临时包日志：
   「工程资源表 XML 打不开，已用同一资源包重建实例」之后依旧 inflate failed）。
6. 回归窗口（同一台 MI8 实测）：

   | 版本 | 结果 |
   |---|---|
   | dev-1306 | 正常（脚本 RUNNING，无报错） |
   | dev-1313 | 失败 |
   | dev-1315 / 1318 / 1322 | 失败（错误一致） |

   区间内 `apps/app/build.gradle` 新增了 MCP toolkit 依赖（smali/baksmali/ARSCLib/re2j），
   1315 起 APK 体积 +~1.3MB；同时 dev-1309 界面美化新增 `HomeBigCard`/`MD_*` 等 style。
   资源 id 整体位移、`resources.arsc` 摘要变化（`3b615b49...` → `fb8f9e48...`，+88 B）。

## 五、候选修复方向（建议按顺序尝试）

1. **换挂载方式（首选，针对根因）**
   - 不再用 `new Resources(assets, metrics, config)` 手工合并，改为用 `ResourcesProvider`/`ApkAssets`
     或 `AssetManager.addApkAssets()`（Android 14+ API）把「宿主 + 工程包」挂成同一个 ResourcesProvider；
   - 或对编译资源包单独建 `Resources`（只含工程包 + 必要的 app 资源），用 `Resources.Theme` 绑定，
     避免与宿主表混挂后 XML 打开失败；
   - 关键验证点：Activity 里 `getLayout(0x7e030002)` 必须返回非 null parser。
2. **Activity 侧降级兜底（改动小、先恢复可用）**
   - 若 `getLayout(layoutId)` 为 null，改为读取 `res/layout/*.xml` 文本走
     `NodeUiHost.inflateInlineLayout(this, xml, runtimeClasses)`（内联 inflater 已有，且 `<include>` 已被
     `setSessionResources` 支持）；
   - 难点：inline 没有真实 resource id，`BottomNavigationView` 的 `app:menu` 需转成脚本侧菜单数据
     （可解析 `res/menu/*.xml` 后用 `navigation.getMenu()` 逐项构造），否则底栏无菜单项。
3. **退回到不依赖编译资源包的 legacy inflater**
   - 对 `project.json` 有 androidResources 但真机无法挂载的工程，回退 `ProjectResources` + DynamicLayoutInflater；
   - 注意：`BottomNavigationView` 等原生控件仍需要真 menu id，可能要结合方向 2 的菜单构造。
4. **bisect 1307–1312 的老包**（若手头能找到 APK）
   - 已知 1306 正常、1313 坏；如能确认 1310/1312 的包是否正常，可判断是「资源表变化」还是「代码变化」触发；
   - 本地已有候选：`.artifacts/flutter-release-candidate/` 有 1313、1314、1315、1319–1323；
     `C:\Users\18101\Downloads\AI-js-Pro-Flutter-candidate-dev-1306.apk` 为 1306。
5. **顺手修正的健壮性问题**
   - `CompiledProjectResources.load` 反射失败时返回 null 会让样例退化成「需要 project-res.apk」，
     可以增加「降级到 XML 文本 inflater」的明确兜底，而不是直接失败。
