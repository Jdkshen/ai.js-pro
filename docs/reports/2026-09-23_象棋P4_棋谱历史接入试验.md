# 象棋 P4：已确认棋谱接入 Pikafish 试验（2026-09-23）

本轮在 AI.js Pro QuickJS 象棋项目中接通 `PositionTracker.positionCommand`：驱动只有在账本局面与待算局面逐格、轮次一致时，才把 `position fen <基准> moves ...` 交给搜索；worker 与同步算棋走同一参数。新宿主提供 `$pikafish.analyzePosition(...)`，Java 校验命令形态，JNI 原样投喂 UCI；旧宿主没有该方法时安全退回当前 FEN。搜索日志标出实际后端和是否使用历史。

纠正盘面或容差确认导致“基准 + 着法”无法还原当前局面时，事实层从当前已确认 FEN 重开 `partial` 段，不把过时棋谱送入引擎。标准布局但轮到黑方也不再误标为完整开局历史。未改变悬浮窗默认视觉模式，也未改动点击策略。

K40 当前安装的是 `com.jdkshen.aijspro` **dev-660**（versionCode 660）；仓库 `project-versions.json` 是 465。设备 API 探针确认 `$pikafish` 只有 `available/start/analyze/stop/quit/isRunning`，没有 `analyzePosition`。本轮没有覆盖安装旧版本，也没有启动棋局或点棋子。因此 K40 的搜索探针验证的是**兼容退回当前 FEN**，不是新 JNI 历史接口的真机执行，更不是整局胜率结论。
