# plugins.json 的权威位置与生成门禁（P0-4，W2）

## 一句话口径
**plugins.json 只在「发布插件」时由 tools/plugins-manifest.mjs 生成**；仓库里**唯一**的持久副本是
**plugin-release 分支上的 plugin-release/plugins.json** = **已发布产物**（客户端按 releases/latest/download
或 raw 取它）。⇒ **不要手改、不要删**（它不在 main 的源码树里，属于发布渠道内容）。

## 生成入口（唯一）
~~~powershell
# 一条命令：构建 3 插件 → 归集 → 生成 plugins.json → 校验 → 推公网分支 → 校验 URL
node tools/plugin-release.mjs                 # 默认分支 plugin-release
node tools/plugin-release.mjs --skip-build     # 复用已有 APK
node tools/plugin-release.mjs --no-push        # 只在本地准备（不推）
~~~
内部顺序（tools/plugin-release.mjs）：
1. [1/5] 构建 :ocr-plugin/:xiangqi-plugin/:apkbuilder-plugin assembleRelease
2. [2/5] 归集到 .artifacts/plugin-release/（文件名 = 清单 file 字段：ocr-plugin.apk / xiangqi-plugin.apk / apkbuilder-plugin.apk）
3. [3/5] **先生成** plugins-manifest.mjs --out ⇒ **再校验** plugins-manifest.mjs --check <manifest> --apk-dir <staging>
4. [4/5] 推 plugin-release 分支（worktree，只含 plugin-release/ 目录，不动 main）
5. [5/5] 校验 4 个公网 URL

## 各处 plugins.json 的性质（避免误删/误改）
| 位置 | 性质 | 处置 |
| --- | --- | --- |
| plugin-release 分支的 plugin-release/plugins.json | **已发布产物**（权威） | 不手改、不删；只由上面的发布脚本覆盖 |
| .artifacts/plugin-release/plugins.json | 本次发布的暂存（可重建） | 由脚本生成，可清理 |
| output/<任务>/…/plugins.json（如 release-drill） | 一次性演练产物 | 按目录规范**应当丢弃**，不影响发布 |

## 门禁（现在与建议）
- **已在链内**：发布脚本的 [3/5] 步**顺序正确**（先生成 → 再 --check → 才 push）✓；--check 失败会因 execFileSync 抛错而**中断发布** ✓。
- 离线自测：node tools/tests/plugins-manifest.test.mjs（清单工具单测）。
- 建议（未做，等 Lead 定）：出包脚本的新鲜度段**不**加 plugins.json 校验 —— 那段没有 apk-dir 上下文，加进去只会假红；
  若要在出包侧兜底，正确做法是「只校验**存在性/可解析/schema**」，不校验 sha256。
