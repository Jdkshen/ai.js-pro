# Node UI 关闭后清理窗口优化（task-186）

日期：2026-10-20。执行：t1-native-services。验证机：K40（cccc62c7，dev-1133）；MI8 因并发任务未能干净复测。

## 1. 问题

task-185 修复后，BACK 关闭 Node UI 不再误报错，但 UI/Binder 清理最长约 15s；此窗口内重跑被拒「当前 Node 脚本正在停止，请稍后重试」。目标：BACK 后 ≤1s 可重跑。

## 2. 根因

- `Node24HostBridge.closeUiOverlay()` 在清理阶段用 `handleUiJson(floatingWindow closeAll)` 同步关闭浮窗；
- 该命令走 `NodeUiHost.overlay → NodeUiActivityClient.overlay()`，内部 `mUpdateLatch.await(15, SECONDS)` 等待主进程 reply；
- BACK 后主进程正在收 Activity、NodeUiBridgeService 忙，reply 可能迟迟不来 → 清理阻塞满 15s，Job.finished 一直 false、active 不释放，重跑排队/被拒。

## 3. 实现

1. 清理阶段浮窗关闭改 fire-and-forget：`NodeUiActivityClient.closeOverlaysIfBound()`（发 MSG_OVERLAY closeAll，不等待 reply）；
2. UI/Binder 清理移到独立 daemon 线程 `node24-cleanup`（`cleanupStarted` 幂等），Job 只 `join(600ms)` 有界等待后释放 active；未完成的清理后台继续（bridge 是旧任务实例，不影响新任务）；
3. cancel 路径清理同样走幂等 `startCleanup`，避免重复同步清理；
4. 新增日志 `cleanup done id=... uiClose=<ms> bridgeClose=<ms>` 便于观测。

## 4. 修改文件

- `modules/engine/src/main/java/org/autojs/source/engine/android/Node24HostBridge.java`（closeUiOverlay fire-and-forget）；
- `modules/engine/src/main/java/org/autojs/source/engine/android/Node24Service.java`（异步清理 + 有界等待 + 计时日志）。

编译：`:engine:compileDebugJavaWithJavac` + `:app:compileMiuixCompatDebugJavaWithJavac -PflutterPoc=true` BUILD SUCCESSFUL（15s）。

## 7. 限制

1. 600ms 有界等待后若清理仍未完成，会后台继续；极端情况下新任务可能与旧清理线程短暂并存（bridge 为旧实例，UI 关闭按 session 精确匹配）；
2. legacy :node24 进程行为未变。
