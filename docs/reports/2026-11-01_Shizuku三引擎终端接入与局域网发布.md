# Shizuku 三引擎、终端与 MCP 接入

日期：2026-11-01。基线 `e6c889a4` / LAN dev-1303。依据[指南审阅与实施方案](2026-11-01_Shizuku改造指南审阅与实施方案.md)，用户批准实施并发布局域网更新。**已发布 dev-1305，仅 LAN；小米 8 已安装同一 APK。**

## 实现

- 主应用及独立 APK 在 Application.attachBaseContext 后立即启用 SDK 多进程模式，工作线程按需取 Binder。每进程维护接收/死亡监听、授权和真实后端 UID；未知字段保留 null。沿用核过源码的 Shizuku API/Provider 11.0.3，不为补 Binder 盲目升级整套依赖。
- 改用受控 UserService，移除旧 newProcess 反射。每个客户端进程单独连接，每条命令持有 Binder 所有者和独立进程组。停止、超时及客户端死亡清理所属命令，不停止整个 Shizuku。空闲 UserService 自动退出，后续按需重连。
- Rhino、QuickJS、Node 统一公开 `shizuku.isAvailable/hasPermission/getState/requestPermission/shell`，同时支持 `shell('id',{shizuku:true})`；Node 另支持 `require('shizuku')` 和 `require('shell').exec`。Node 命令/授权通过真正的 Java 异步执行器返回 Promise；其他两引擎在脚本工作线程调用。同步结果保持 `{code,result,error}`，非零退出保留 stdout，输出限额后继续排空，超时从连接开始计时。
- App 终端与 MCP 共用 app/shizuku 后端。默认 app UID，显式 Shizuku 不会失败后悄悄回退普通身份。MCP `terminal_exec` 增加 backend，`shell_rish` 是固定 Shizuku 的异步别名，仍用 jobId 和 terminal_read/write/stop，沿用执行开关及输入校验。
- 内置终端新增后端选择、真实连接/授权/UID 状态和主题同步。Shizuku 无法进入应用私有默认目录时，界面默认切换 `/`；显式其他目录仍保留并报告访问失败。`cd` 的默认目录随所选后端变化。
- app 后端注入 `rish` / `i` 函数。`rish -c '命令'` 与单字符串兼容形式保持参数边界；安装支持多个 APK、中文/空格/引号路径及应用私有文件。应用打开只读文件描述符，远端通过安装会话分块写入，失败/取消放弃会话；默认替换安装及当前应用用户，不隐式加 `-g --user 0`。
- inrt 补实际包名的 Shizuku Provider、权限与 metadata，engine 带 Provider 依赖和 R8 保留规则，重新生成内置瘦身模板。三套同名示例与 App/MCP 同源文档一起更新，索引 782 条。

## 与原文的必要调整

未复制手机导出的 rish_shizuku.dex，也没有往私有目录放可写 DEX。命令入口直接从已安装的只读 APK 加载本项目客户端，经同 UID 的本地 Unix socket 连接应用内网关，再使用统一远端任务后端；没有新增 TCP 端口。实际包名及随机 socket 地址由宿主注入，网关核对 peer UID 和包名。

首次实验直接在 app_process 中构造 Context 获取 Provider，真机无法取得 Binder；已删除该路径，改由真实 Application 连接。保留旧 rish 命令形状，不宣传官方 rish 完整交互能力：**没有 PTY、没有 ARM adb、没有自动启动/配对 Shizuku**。普通脚本 shell / Node 原生 child_process 不自动注入终端函数，请用公开 shizuku API。

Shizuku/Sui 服务必须由用户启动并授权；后端身份由服务决定，不能保证每台设备都是 shell(2000)。无授权、Binder 断开、命令非零、超时分别返回诊断。
