# task-123：打包端脚本密钥只用新方案（W2）

## 一、改动清单
1. apps/app/src/main/java/com/jdkshen/aijspro/autojs/build/ApkBuilder.java（:1751 一带）
   - 删掉旧 MD5 两行（key=MD5(pkg+ver+main) / vector=MD5(buildId+name)[:16]），并删掉 import com.stardust.util.MD5（已无引用）。
   - 派生只剩一条路：salt = json.optString("scriptSalt") → 缺失则 ScriptKeyDerivation.randomSaltHex()；
     mKey = ScriptKeyDerivation.deriveKey(packageName, salt, 证书指纹)；mInitVector = deriveVector(salt, fingerprint)；
     必然 json.put("scriptSalt", salt) + json.put("signatureFingerprint", fingerprint)（在写 project.json 之前，运行端读的就是这两个字段）。
   - 旧 KDoc（:117-118 / :1648-1649 描述 MD5 方案）同步改成新方案口径。
2. 拿不到指纹时不再静默降级（② 的选择）：我选明确失败，条件收窄成「确实需要脚本密钥时」——
   - boolean needsScriptKey = mEncryptLevel > 0；
   - 有指纹 → 正常派生并写盐+指纹；
   - 无指纹且 needsScriptKey → throw new IOException("打包需要脚本加密密钥，但拿不到签名证书指纹：新方案（scriptSalt + 证书指纹派生）是唯一路径，运行端已不支持旧的 MD5 方案，因此不会静默降级。请确认签名身份可用（重新生成/选择密钥库）后重试。")；
   - 无指纹且 encryptLevel=0（不产生受保护载荷）→ 不派生、不写盐/指纹（保持既有语义，不加戏）。
   理由：降级产物在运行端必然解不开（旧方案已不支持）⇒ 静默产出一个「能装不能跑」的 APK 比明确报错更糟；而正常机器上指纹总是拿得到（自签身份），所以这条是安全网而非新门槛。之所以不用「打包提示里写风险」，是因为提示可被忽略、而产物是必然坏的——那不是风险提示能救的场景。
3. apps/app/src/androidTest/java/com/jdkshen/aijspro/packaging/ApkBuilderEncryptionTest.java
   - decryptPackagedScript(...) 去掉 legacy 回退分支，改成只走新派生，并加两条断言：产物必须带 scriptSalt、必须带 signatureFingerprint（缺任一即失败）。
   - 删掉 import com.stardust.util.MD5（已无引用）。
4. 新增 apps/app/src/test/java/com/jdkshen/aijspro/autojs/build/ScriptKeyDerivationPinsTest.kt（4 项源码钉）：
   - ApkBuilder 里 MD5.md5( / legacyKey / legacyVector / import MD5 各 0 命中；
   - 必然写盐+指纹、派生只走 deriveKey/deriveVector、缺盐时用 randomSaltHex；
   - 必须含「不会静默降级」与那条错误文案、必须含 needsScriptKey = mEncryptLevel > 0、旧注释「运行端看到字段缺失会走旧算法」0 命中；
