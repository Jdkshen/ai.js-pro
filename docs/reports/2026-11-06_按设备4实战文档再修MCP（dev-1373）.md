### 途中修掉的一个真集成 bug

`app.viewFile(path,{fresh:true})` 在 **Rhino 直接抛异常**：`Java method "viewFile" cannot be assigned to (__app__.js#25)` —— prelude 想用 JS 覆盖 Java 方法。实际 `AppUtils` 已有 `viewFile(String,Object)` 重载，**JS 包装是多余的**；删掉后 Rhino 实测通过。**这类问题只有真机能发现**（单测/静态检查都过）。

## 三、未做与边界（别当成已完成）

1. `providerProcess` 的 **manifest 自动判定**与**默认进程**两条分支只在本地 harness 验证（`auto=:target explicit=:explicit default=default`），**K40 上只跑了显式分支**（手头没有入口 activity 声明 `android:process` 的样本 APK）。
2. 「失败但产物已写出」的 catch 分支**无法自然复现**（真机失败大多发生在签名产物之前），只做了代码接线与静态核对。
3. QuickJS 的 global `app.viewFile` 包装是 try/catch 尽力而为：**C++ bootstrap 定义的 global 属性可能不可写**，此时仍是旧行为；`require("app").viewFile` 路径已实现。**未在真机验证 QuickJS**。
4. `dex→smali` 回退开关（`engine=smali`）未做。
5. `file_search`/`file_search_text` 的 5 个 type 字段、`apk_search` 的 8 个必填、`zip_extract.overwrite` 仍 required（上一批遗留）。
