# task-121：Job.from() 补齐读取侧 + 通用契约钉（W2）

## 一、根因与改动
**根因（与 task-112 同源）**：W4 把 templateSource/templateLabel 只加进了 Job.json()（写出侧）与 runBuild，**没在 Job.from() 里还原**；而任务结束后 ACTIVE 被清空 ⇒ 页面轮询走**文件**路径（readJob/latestJob → Job.from）⇒ 永远读回空。K40 dev-1470 现场：日志 source=assets/template.apk 正常，但 projectBuildStatus 的 templateSource/templateLabel 都是空。

改动（PocPackaging.java）：
1. Job.from() 新增还原：
   - job.templateSource(json.optString("templateSource", "")) —— **空串保持空串，不造默认值**；
   - job.startedAt = json.optLong("startedAt", job.startedAt)（顺手核出来的第三个漏还原键）。
2. Job.startedAt 由 final 改为非 final（原来恒等于「读取时刻」，读回文件的任务时间不对）；仅 json() 读它，无其它消费者（grep 确认），改动面最小。
3. templateLabel **不需要**单独还原：它是派生函数（只认 SOURCE_* 常量，认不出返回空串 ⇒ 页面不显示），由 templateSource 决定。
4. **顺手核你点名的字段**：abis / path / sha256 / size / versionCode / encryptLevel / packageName **在 from() 里都已还原** ✓（:1017-1024）；真正缺的只有 templateSource / templateLabel（派生）/ startedAt 三个。

## 二、通用契约钉（以后加字段不会再栽）
新增 apps/app/src/test/java/com/jdkshen/aijspro/build/JobJsonFromParityTest.kt（3 项，纯 JVM 源码级）：
1. **集合差必须为 0**：从 json() 体里正则抽出所有 .put("键") ⇒ 与「from() 体里出现过的键」求差；唯一显式登记的派生键是 templateLabel（写进集合，不隐式放过）。
2. templateSource 必须**逐字还原**且用 optString("templateSource", "")（空串保持空串）；startedAt 按落盘值还原；templateLabel 仍是「认不出返回空串」的语义。
3. 真机现场键必须落在「必还原」集合里（templateSource / startedAt / warnings）。
⇒ 以后任何人只往 json() 加字段而忘了 from()，这条测试**直接红**。

## 四、未验证边界
1. templateLabel 的映射只认打包侧三个常量（bundled_assets/host_cache/sdcard_override）；真机日志里的 source 形态是 **assets/template.apk（路径形态）**，而 TemplateStatus.source 在 bundled 分支给的就是这个路径 ⇒ **label 可能仍为空**（templateLabel 认不出路径形态）。本轮**按你的要求只做「还原」、不改映射语义**；若真机上那行仍不显示，需要 W4/打包侧把 source 统一成常量形态（或在 label 里承认路径形态）——这点我标为**待复验**。
2. startedAt 只是「按落盘值还原」，没有做时区/格式处理（原本就是毫秒数）。
3. 未改 json() 写出侧任何键名或语义（默认行为不变）。
