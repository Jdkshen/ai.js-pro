### S3.5 到底改了什么（重点）

S2/S3 交付的 Compose 列表是「重新设计」，不是「UI 统一」。S3.5 按旧实现的**真实基准**重做渲染层：

- 列表上方**一个固定的 48dp 分类头**：标题（项目页=项目名 / 其他=面包屑）、返回、项目指南针、
  升降序、排序方式；返回不可用时 `alpha=0.38`
- **文件夹行整行**（不是半宽网格）、`minHeight 60dp`、44dp 圆底图标
  （普通 `#1976D2` / 项目 `#5C6BC0`）、名称 16sp、描述 12sp
- **文件行整行**、44dp 圆底 `#5cab7d`（有专属图标则显示图标，否则 22sp 白色 **type** 首字母）、
  名称 15sp、描述 11sp、可执行时 `run` + `more`
- 每行底部 `1px` 分隔线、`marginStart 74dp`、`@color/m3_list_divider`
- 两组之间**没有分组头、也没有折叠**（`dirsCollapsed`/`filesCollapsed` 从未被置 true，是死功能）

同时修掉的功能性偏差（不只是外观）：

1. 原实现对子项写死「目录在前 + 名称升序」，**完全不读用户排序设置** → 现在读写与旧实现同一份
   `ExplorerItemList.SortConfig`，并接上排序菜单（名称/时间/类型/大小）与升降序切换
2. 文件夹图标原是硬编码橙色方块 + 首字母 → 改回 `circle_folder` / `circle_project` 的固定色值
3. 补回 `run`（按 `item.isExecutable()`，不只是 JS）与 `more`
4. 补回 `reset_all` 的确认对话框（删改级操作，旧实现有 `confirmResetAllSamples()`）

新增两个可单测的纯逻辑：

- `ui/viewmodel/ExplorerListRows.kt` —— 排序/分组/折叠，不依赖 Android
- `ExplorerSorterParityTest` —— **直接调用真实 `ExplorerSorter` 当 oracle** 比对排序方向。
  它抓到过三处方向写反：`ExplorerSorter.sort` 的 `reversed()` 是**交换参数**而非取负，
  方向取决于原比较器把谁放在 `o1` 位。实测 `ascending=false`（默认）时：
  **NAME 名称升序 / SIZE 大小升序 / DATE 时间降序 / TYPE 类型升序**

## 7. 别踩这些（血泪，详见 AGENTS.md）

1. **`dev-update.ps1 -NoServe` 不阻止发布** —— 它只跳过起服务。试参数用 `-DryRun`。
   曾用 `-VersionCode 9999` 试参数，把 9999 发进真实更新源，手机永远提示有新版本。
2. **别用 `Select-String` / `Where-Object` 过滤会调 gradle 的脚本输出** —— 管道提前关闭会杀掉
   gradle，`$LASTEXITCODE` 也会失真。已因此损失两次构建，并连带干掉过常驻的 8080 服务。
   改用 `*> 日志` 再读，或用 `tools/publish.ps1`（自带 transcript）。
3. **PS 5.1 读无 BOM 的 UTF-8 `.ps1` 会按 GBK 解码** —— 中文会让引号错位、解析报错，
   且报错行号指向无辜代码。改完 `.ps1` 要回头确认 BOM 还在。
4. **`$ErrorActionPreference='Stop'` 下原生命令的 stderr 会假失败** —— Gradle 的过时 API 注记
   让脚本以 1 退出，而构建其实成功。判断成败只认 `$LASTEXITCODE`。
5. **多设备时 `adb` 不带 `-s`** —— `dumpsys` 会静默返回 0，把手机已装版本从基准里丢掉、
   版本号算小。当前已有守卫，但自己写 `adb` 调用时要注意。
