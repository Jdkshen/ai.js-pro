# 选择器运行后打开编辑器卡顿

用户视频：运行 Node.js / 无障碍 / `选择器.js`，返回列表后打开编辑器，工具栏出现，代码区长时间空白；重启后恢复。

## 已定位的阻塞点

- 在小米 8 `ce4d2bdb`、dev-1200 上灌入 2000 条带 12 次 `node snapshot ` 文本的真实 Node 日志（每条间隔 5ms），再新建编辑器 Activity。
- `am start -W` 两次分别为 4977ms、5018ms。期间给主进程发送 SIGQUIT，抓到主线程正在执行：

```text
SpannableStringBuilder.charAt
ProCodeEditorActivity.trimUnifiedLogBuffer:670
ProCodeEditorActivity.appendUnifiedLogLine:646
ProCodeEditorActivity.renderUnifiedLogSnapshot:630
ProCodeEditorActivity.attachUnifiedLog:615
ProCodeEditorActivity.buildLogPanel:578
ProCodeEditorActivity.buildWorkspaceUi:388
ProCodeEditorActivity.initializeEditor:249
ProCodeEditorActivity.onCreate:244
```

- 原实现在初始化隐藏日志面板时，循环历史日志，每行都扫描整段缓冲计数、复制所有着色 span 并 `TextView.setText`。2000 行需要约 2000 次整段处理，阻塞了编辑器初始化和主线程事件。
- `NodeView` / `UiObject` 内部保留整棵节点快照供父子导航使用；默认 `util.format` 会把 `_raw`、`_tree` 一起打印。数组里的每个节点又重复打印同一棵树，放大日志量。
- 这是已经用真机堆栈定位的主线程性能缺陷。视频设备未通过 ADB 接入，不能把开发机堆栈冒充为视频设备原始 ANR；当前也没有证据将其归因为 native SIGABRT 或互斥锁死锁。

证据保留于 `output/selector-editor-freeze/`，包括视频抽帧、旧版堆栈、日志、MCP 响应和前后比较。

## 修复

1. 编辑器历史日志只构建一次缓冲；面板隐藏时不向 TextView 发布、排版。
2. 实时日志约 100ms 合并一次，保留等级颜色、过滤、清空及滚动查看历史；打开面板立即显示积累内容，销毁 Activity 取消待刷新任务。
3. 增量维护显示行数，裁剪时单次向前找切点；同时限制最近 2000 行和 256Ki 个 UTF-16 字符，避免单长行撑爆面板。统一日志源及日志文件不因此被清空。
4. 节点自定义 `nodejs.util.inspect.custom`，日志显示单行摘要，长文本在摘要中截短并转义换行。`raw()`、`text` / `text()`、父子导航及显式 `tree()` 保留原始内容。

涉及 `ProCodeEditorActivity.java`、`accessibility_extra.js`；没有改宿主进程架构，也没有禁用无障碍或跳过选择器 API。

## 验证结果

- 本地选择器契约 33/33、日志格式 4/4 通过；新增大树节点数组、长文本/换行及导航保持两项回归。
- 小米 8 dev-1201 真实节点摘要 9/9 通过，12 个节点共 1908 字符 / 14 行，父子导航、完整原文、旧式 UiObject 保持。
- 同样的 2000 条真实日志后，新建编辑器 Activity 三轮分别为 731ms、326ms、319ms（`am start -W TotalTime`）；包含 DevTools 连接和校验完整 58 行源码，耗时分别 1.031s、0.597s、0.602s。旧版同一组负载为 4977ms、5018ms；这些是本机回归数据，不能外推为所有手机的速度。
- 原始 `选择器.js` 不删 API、不改源码，MCP 路径运行后再打开编辑器三轮均成功；Activity 打开 327ms / 324ms / 329ms，完整源码可见且无脚本错误。自动化首轮因 Flutter 保留日志页路由导致入口定位 `StopIteration`，修正测试脚本识别已在日志页后，上述完整三轮通过。
- 交互 7/7：运行选择器后在 Ace 输入并点击原生“保存”，ADB 读取文件逐字比对通过；恢复原文并保存通过；Rhino / QuickJS / Node 三引擎实时日志均显示；Error 等级过滤、清空后延迟刷新不复活旧日志通过。
- 完整 Flutter POC APK 构建通过；Java / JS / assets 改动复用原 AOT，没有重建或替换 Flutter engine。
- 发布前全部 22 个 64 位 ELF 的 16KB 静态检查通过，无白名单。现有真机仍为 4KB 内核，真实 16KB 环境验收仍是独立未完成事项。
