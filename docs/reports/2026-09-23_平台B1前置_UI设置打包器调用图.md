## 0. 结论摘要

1. **脚本根目录的唯一权威源已经收牢**：`Pref.getScriptDirPath()`。
   唯一写点是设置页（`ScriptDirPathPreference` 的 Material 分支、`MiuixSettingsActivity` 的 Miuix 分支），
   两者都带“旧目录 → 新目录”搬迁语义。其余 25 处全是**读**。
2. 但**读的方式裂成三套**，这是 B1 要收的直接原因：
   - 旧 explorer 抽象：`Explorers.workspace()` + `ScriptFile` / `ExplorerDirPage`
     （`ExplorerView`、`MyScriptListFragment`、悬浮窗 `CircularMenu`）
   - Miuix 直用 `java.io.File`（`MiuixScriptListHost`、`MiuixSearchActivity`、`MiuixSampleFragment`、`MiuixResourceFragment`）
   - 服务/工具直读（MCP `McpTools`、打包 `MiuixBuildActivity`、外部 `ScriptIntents` / `DevPluginResponseHandler`）
3. **写操作（新建/重命名/删除/导入/覆盖/回退）没有单一门面**：
   `ScriptOperations` 自己造文件（Material/Miuix 双分支弹窗），编辑器 `ProCodeEditorActivity`
   管自己的备份目录（`.aijspro-sample-backups`），MCP 有独立的“私有工作区 → apply（校验+备份+回退）”链路，
   打包器只写产物内的 `project.json`。⇒ B1 的变更门面要统一备份/回退语义，而不是砍掉其中之一。
4. B1 首批切换点（多实现、最交叉）：
   `ScriptOperations`、`MiuixScriptListHost`、`McpTools`；其后是示例导入与打包器读取源。

## 3. B1 批次切分建议（按风险从低到高）

1. **批次1 `ScriptDescriptor` + `ScriptRepository`（只读）**：
   `list(path) / stat(path) / descend(path)`（排序、过滤语义与 `Scripts.FILE_FILTER` 对齐）。
   先让 `ExplorerView`（旧）与 `MiuixScriptListHost`（Miuix）**委托同一实现**，行为不变。
2. **批次2 变更门面**：`create / rename / delete / import（含覆盖策略）` 收进 Repository，
   统一“先备份、可回退”语义（复用编辑器备份目录与 MCP apply 的校验思路），
   `ScriptOperations` 两个 UI 分支只保留弹窗与提示。
3. **批次3 示例存储**：`SampleRepository`（`SampleFiles` → list/read/import），
   文件页与 MCP `list_samples/read_sample` 同源。
4. **批次4 MCP 切换读取源**：`McpTools.scriptsRoot` 改为走 Repository（协议与工具名不动）。
5. **批次5 打包器读取源**：`MiuixBuildActivity`/`ApkBuilder` 读取工程 manifest 统一到 Repository；
   `project.json` 的写出仍由打包器负责（它是产物侧事实，不是源侧）。
6. **测试锚点**：重命名/删除/覆盖/回退 + 路径边界（scriptDir 之外一律拒绝）+ MCP 与 UI 同入口同结果。
