# 编辑器剪贴板与全进程停止修复

日期：2026-10-25。范围包含 AI.js Pro 主程序运行、编辑器运行、悬浮运行，以及重新打包生成的独立 APK。

状态：候选 1248，未发布。只使用空闲小米 8（`ce4d2bdb`）安装与测试；K40（`cccc62c7`，dev-1199）业务未中断。更新源仍 dev-1247。手机 Java/C/C++/APK 源码编译工具链仍按用户决定取消，本轮没有恢复该工作。

## 实际进程归属

| 入口／内容 | 实际执行位置 | 停止方式 |
| --- | --- | --- |
| 主界面、编辑器、悬浮菜单发起的普通 Rhino / QuickJS 文件 | 通常为主应用 `:script` | 主进程协调，向脚本宿主发 STOP_ALL |
| UI 模式、需要本机截图的脚本 | 可能在主进程；按现有路由决定 | 主进程引擎停止并关闭脚本 UI / 浮窗 |
| 原生项目 | 主应用 `:native` | NativeScriptService STOP_ALL |
| Node 脚本和本地 Node 浮窗 / UI | 通常为 `:node24_1`、`:node24_2`、`:node24_3`，另保留旧 `:node24` | 取消各槽任务，清理排队任务和窗口 |
| 打包生成的独立 APK | 自己的包名，脚本通常在其 `:script` | 该 APK 的全局按键由主进程中继到自己的 `:script`；聚焦窗口也可直接停止 |

悬浮窗口属于创建它的引擎所在进程，不是所有窗口都在主进程。主程序的“停止全部”控制 AI.js Pro 本包的脚本进程；独立 APK 有自己的包名 / UID 和停止链路。停止脚本后允许主应用与空闲 Node 槽继续存活，保留界面、MCP 和预热能力。

## 根因与修复

### 编辑器复制、剪切、粘贴

- 旧 Android 触摸脚本只寻找 `autojs`，宿主实际注入 `EditorBridge`，长按菜单无法进入原生层。
- 原生工具栏复制依赖异步 Java 快照，焦点和选区变化后可能拿到空选区。
- 主控真机复核发现另一个异常：Ace 1.44 已没有旧触摸实现使用的 `renderer.getClientPosition()`。长按计时器先抛 TypeError，尚未选词就中断。`androidTouch.js` 现通过 `textToScreenCoordinates()` 补齐这一兼容方法。
- 新增 `EditorClipboard` 与 `editorClipboard.js`，由 Ace 在动作发生时读取选区，同步通过 Android ClipboardManager 读写。剪切仅在复制成功后删除；空选区不覆盖剪贴板；粘贴可替换选区并恢复焦点。
- 原生 ActionMode 和工具栏提供复制、剪切、粘贴、全选，保留复制全部、复制行和键盘路径。

### 全进程停止与窗口清理

- `HostScripts.stopAllScripts(Context)` 统一主界面、编辑器、悬浮菜单、通知、任务页、PC stop-all、MCP 和公共引擎停止入口。
- 子进程请求先通过显式、非导出 `StopAllScriptsReceiver` 回到主进程协调；不再读取子进程自己的空任务表来判断全局任务。
- `PocScriptHost` / `PocNativeRunner` 增加 STOP_ALL 协议，移除待发 RUN，服务端同时停止已创建的执行对象。即使客户端任务列表为空，也能送达停止指令。
- Node cancel-all 即使当前槽没有 active job，也会清理 pending；现有取消与崩溃恢复机制保留。
- shared `ScriptEngineService.stopAll()` 增加本进程 OverlayRegistry 清理；公开 `engines.stopAll()` / Node bridge 触达全局协调，保留本进程停止计数和 stopAllAndToast 提示。
- App 不再在每个 Node 子进程重复恢复任务、启动 MCP / PC 连接、调度任务或恢复管理悬浮球；引擎、按键停止 hook 和异步 Glide 图片加载器仍在需要的进程初始化。

### 音量上键

- 无障碍按键观察者始终注册，不再因可选设置关闭而完全缺失；root getevent 仍按设置选择启用，默认启动不主动要求 root。
- 去掉长期残留的跨源布尔标记，改为按键 + 来源 + 时间戳去重，避免 DOWN 错误污染下一次 UP。
- Node 全屏 Activity、Node overlay root 与既有 shared UI 窗口接入相同停止入口。
- inrt 主进程只注册一份全局观察者；其同包非导出 receiver 落在 `:script`，接收后只做本进程停止，避免广播循环。
- inrt LogActivity / InrtScriptActivity 补齐聚焦窗口音量上键处理。顺带修正当前 Glide 的 nullable Transition 回调签名，否则模板不能重新编译。

### 诊断不再误报零窗口

静止浮窗的快照不是心跳。过去超过 30 秒直接丢弃快照，会把仍可见的窗口显示成 0。现在使用同 UID 活进程校验，保留老快照，并返回 `ageMs`、`snapshotOld` 和实际进程名；已退出进程仍被过滤。Node 运行结果也返回实际槽进程名，不再统一写成 `:node24`。

## 打包模板与边界

新的内置 `assets/template.apk` 已从当前 inrt 源码重建，约 19.3 MiB，SHA-256 `60343d9c973315fa96eb9d9ba7eea0bbe7703fce1ada42182a82b82f6acf7387`。lib 补齐清单仍为同样的 16 项，没有删除运行库。模板新增剔除独立运行时用不到的 npm 安装 CLI；主应用离线 Node/npm 保留。没有放宽 6–20 MiB 模板体积硬门。

此前已经打出的独立 APK 不会随主程序升级自动变化，必须用新模板重新打包。手动 `/sdcard/template.apk` 覆盖优先级仍然保留；若用户放过旧手动模板，需要选择 / 替换为新模板。独立打包插件的旧二进制本轮未发布，下一次构建插件会从当前 inrt 生成完整模板。

本次独立 APK 真机验证为 Rhino；现有 inrt 未声明 Node24Service，不能把本次主应用的三引擎测试当作 Node 独立 APK 支持证明。

非聚焦浮窗在其它应用上方时，全局物理音量键仍需要系统将事件交给已连接的无障碍服务或用户启用的 root 通道。ADB 注入按键不经过同样的无障碍过滤路径，因此全局 handler 和聚焦窗口分别测试，不宣称模拟了所有 ROM 的物理按键分发。
