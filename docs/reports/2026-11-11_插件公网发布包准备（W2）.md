## 1. 构建三个插件（需要 gradle，由 Lead 跑）
~~~powershell
# 与主程序同一套签名（AIJSPRO_*）；未配则回退 debug 签名（仅供本地自测，公网发布必须用真签名）
$env:AIJSPRO_KEYSTORE=...; $env:AIJSPRO_STORE_PASSWORD=...; $env:AIJSPRO_KEY_ALIAS=...; $env:AIJSPRO_KEY_PASSWORD=...
.\gradlew.bat :ocr-plugin:assembleRelease :xiangqi-plugin:assembleRelease :apkbuilder-plugin:assembleRelease --console=plain
~~~
产物落点（release 变体）：
- plugins/ocr-plugin/build/outputs/apk/release/ocr-plugin.apk
- plugins/xiangqi-plugin/build/outputs/apk/release/xiangqi-plugin.apk
- plugins/apkbuilder-plugin/build/outputs/apk/release/apkbuilder-plugin.apk

注意：插件必须与宿主同签名（否则装上后宿主发现不了/装不上）；发布前用 apksigner verify 或 ApkSignatureReader 核对一次。

## 2. 生成 plugins.json（node，无需 gradle）
先补齐三个描述符的 minAppVersion（当前都是 null ⇒ 生成器会跳过该插件并 WARN，这是有意门禁）：

- 已填值：465（= project-versions.json 的 appVersionCode，即「第一个带 PluginNativeLoader.createOcrSession + $ocr 直连工厂」的宿主版本）。**注意语义**：465 是**应用版本号**，与 dev-1469…1495 那套 dev 号不是一回事；所有当前 dev 构建都满足 465。
- **如实边界**：历史上若存在「appVersionCode=465 但早于直连工厂落地」的构建，也会被判「可装」——**不致命**（JS 会安全回落到内置链路或已有的点名错误），发布口径里按此写明即可。
- 若发布前 appVersionCode 又涨了，用那次的实际发布号；三个插件填同一个值（都以「直连工厂 + 注册键」为准）。
- 语义：客户端拿本机 PackageInfo.versionCode 与它比，低于就提示「先升级主程序」。

生成与对账：
~~~powershell
node tools/plugins-manifest.mjs --out <更新源目录>/plugins.json      # 自动填每个 APK 的 sizeBytes + sha256
node tools/plugins-manifest.mjs --check <更新源目录>/plugins.json --apk-dir <放三个 APK 的目录>   # 必须 exit 0
~~~
生成时会打印每个插件的 id@version 与 size（APK 未构建会显示「APK 未构建」⇒ 不可发布）。

## 3. 上传到哪个 Release + 文件名纪律
- 目标：GitHub Release Jdkshen/ai.js-pro 的 latest（客户端内置源 = 加速前缀 + releases/latest/download/<文件名>；dev-1495 的 404 日志已实证这个 URL 形状）。
- 资产文件名必须与 plugins.json 的 file 字段逐字一致：
  ocr-plugin.apk / xiangqi-plugin.apk / apkbuilder-plugin.apk / plugins.json
- 顺序：先传三个 APK，最后传 plugins.json（避免清单指向不存在的资产）。
- 传完不要改名/重签（sha256 就是按上传的那份字节算的）。

## 3.5 签名口径（重要，必须分开两件事）
- **本机没有 AIJSPRO_* ⇒ 这次构建出来的是 debug 兜底签名** ⇒ 只能作为「**本地可用的发布包**」用于真机点检四态/下载链路，**绝不能作为公网发布件**。
- **真正可发布的签名件**需要**用户的发布密钥**：上传前必须用 AIJSPRO_* 重签，且**重签后必须重新计算 sha256**（sha256 是按上传的那份字节算的）。
- 因此固定顺序是：**真签名 → 算 sha256（本脚本重新生成 plugins.json）→ 上传 APK → 最后上传 plugins.json**。

## 4. 上传后自检（两条）
~~~powershell
# 4.1 本地：清单与文件逐字节对账（必须 exit 0）
node tools/plugins-manifest.mjs --check <下载回来的 plugins.json> --apk-dir <下载回来的三个 APK 目录>

# 4.2 公网：确认真能拿到（200 + JSON 可解析），并核对每个资产的 sha256
node -e "fetch('https://gh-proxy.com/https://github.com/Jdkshen/ai.js-pro/releases/latest/download/plugins.json').then(r=>{console.log('status='+r.status);return r.text()}).then(t=>{const j=JSON.parse(t);console.log('plugins='+j.plugins.map(p=>p.id+'@'+p.version).join(','));for(const p of j.plugins)console.log(p.file+' sha256='+p.sha256.slice(0,16)+' size='+p.sizeBytes)})"
~~~
若 4.2 返回 404：说明资产名或 Release 不对（客户端会显示 network:...404，属可解释失败）。
