# GitHub 加速更新内置到 APK（dev-783）

日期：2026-10-04。已发布 [AI.js Pro dev-783](https://github.com/Jdkshen/ai.js-pro/releases/tag/dev-783)，GitHub Latest 为该版本；非草稿、非预发布。

## 实现

- `GitHubUpdateProxy` 内置 GH-Proxy 更新清单地址；更新源留空即可使用。以前手动配置的同一个代理源也按默认策略处理。
- 默认清单每次请求增加时间参数，禁用本地响应缓存。实测普通代理 `latest` URL 在发布后仍缓存 dev-781，增加刷新参数后立即得到新版本，因此 dev-783 补齐该处理。
- 默认清单请求或解析失败，自动回退 GitHub Releases API。
- 代理 APK 下载出现网络错误，自动尝试原始 GitHub URL 一次；取消下载不会触发回退。
- 下载后的 SHA-256、包名、版本与签名校验仍在下载回退逻辑之后执行，校验失败拒绝安装。
- 自定义局域网、自托管源保持原流程。设置页说明更新为“默认 GitHub 加速”。

加速与普通清单引用同一批固定版本 APK；每次发布都附带两个清单。dev-782 为首次内置版本，dev-783 为包含清单缓存修复的最终版本。

| 显式局域网源 | 得到 dev-783 的局域网 APK 地址，没有被替换成代理 |

验证后已恢复小米 8 的 dev-780，保留数据；旧版配置带版本参数的代理清单后，约 1593 ms 检测到 **780 → 783**，`isValid=true`、`isNewer=true`。代理 APK Range `0-1023` 请求返回 HTTP 206，1024 字节，约 0.39 秒。本次未通过代理下载整个 APK；测速为单次网络测量。

本地发布校验曾把手机的外部代理域名误用于局域网 HTTP 服务检查；已修复 `tools/publish.ps1`，仅在 `/update.json` 和端口匹配时跟随手机配置，否则使用 `-PcHost`。已保留 UTF-8 BOM 并通过 DryRun；K40 实际拉取本地清单 HTTP 200、版本 783。DryRun 没有发布 dev-784。

## 使用

dev-783：更新源留空即可。若希望始终直连，在设置中填入 `https://github.com/Jdkshen/ai.js-pro/releases/latest/download/update.json`。

旧版首次升级可填以下地址，避免使用此前已缓存的清单；升级后会自动处理清单刷新与回退：

```text
https://gh-proxy.com/https://github.com/Jdkshen/ai.js-pro/releases/latest/download/update-gh-proxy.json?channel=dev-783
```
