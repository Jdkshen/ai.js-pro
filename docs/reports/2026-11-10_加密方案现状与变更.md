**硬化要点（W1 口径）**：v1 的 `deriveKey` 取 SHA-256 的 **32 个 hex 字符当 32 字节**用 ⇒ **有效熵 ≈128 位**；v2 改为 **64 hex 解码成 32 字节** ⇒ **真 256 位**。

**必须同时改两处（否则静默解不开）**：Java `ScriptKeyDerivation.deriveKey` + C `modules/engine/src/main/cpp/script_crypto.c:316/324`（现为 `kKeyPrefix = "aijspro-script-key|"`）；v2 还要把 v1 的 `AES/CBC/PKCS5` 换成 **GCM**（`AdvancedEncryptionStandard` 目前是 CBC）。

### 3.3 别误删的一处回退（**不是旧方案回退**）

## 4. 安全口径（诚实版，别对外吹成 DRM）

| # | 事实 | 证据 |
|---|---|---|
| 1 | **v2 的 GCM 提供「完整性」**：密文被改动/AAD 被改动 ⇒ **校验失败**（对比 v1 的 CBC **没有**完整性，改一位可能只表现为 padding 失败或**静默解出错误内容**） | v2 口径（`3.2，**进行中**）；v1 现状见 `1.1（CBC） |
| 2 | **但它仍是「防呆 / 防随手改包」，不是强 DRM**：**包名、随机盐、证书指纹都在产物 `project.json` 里明文可读** ⇒ 任何人解包都能读到派生材料并复现密钥 | `ApkBuilder.java:1766-1767` + `1.1` 实测 |
| 3 | **换证书重签 = 解不开**（最实在的价值）：重打包/二次修改拿不到同一签名身份 ⇒ 运行端**点名拒绝** | `AssetsProjectLauncher.kt:373-376` |
| 4 | **真正的门槛是「选到编译档」**：`LEVEL_COMPILE` 把源码变成 class/字节码，产物里没有可读源码 | `ScriptProtection.java:10-11`；界面文案 `strings.xml:423` |
| 5 | **密钥熵对比**：v1 **≈128 位**（32 hex 字符按 32 字节用，AES 仍按 256 位展开）→ v2 **真 256 位**（64 hex 解码 32 字节） | `ScriptKeyDerivation.java:42`（v1）；v2 口径（**进行中**） |
| 6 | **原生路径的意义是「密钥不落到 Java 侧」**（不是「不可提取」）：原生自己派生，但 Java 侧有一份**同一公式**的实现用于回退 | `EncryptedScripts.kt:36/119-124`；`script_crypto.c:5/316` |
| 7 | **SJBC 是另一层，同为防呆式**：密钥主根也是**证书指纹**（HKDF 双密钥 + AES-256-GCM 双层 AEAD），防直接读源码、**不防有动机的攻击者** | `docs/guides/SJBC脚本保护挂载.md` `3/`8；`project_page.dart:1505`（用 SJBC 时建议 encryptLevel=0） |
