# Node Java 类路径访问兼容（task-176）

日期：2026-10-19。执行：t1-native-services。验证机：K40（cccc62c7，dev-1124/1125 待填）。

## 1. 问题

t2 dev-1122 K40：示例 #42 按键监听失败——`const KeyEvent = android.view.KeyEvent;` 触发 `ClassNotFoundException: 找不到 Java 类：android.view`（宿主收到 class name=android.view，提示「不能省略包名」）；新版 `accessibility.enableKeyEvents` 本身已 OK。

## 2. 根因

1. Node prelude 的包代理 `packageRef().get` 对**每个属性**都先尝试 `resolveClass(child)`，访问 `android.view` 时会用 `android.view` 去宿主做类解析，宿主按完整类名查找失败（ClassNotFoundException）；
2. 包级全局 `java`/`android`/`Packages` 只在 `require('rhino').install()` 时才挂到 globalThis，默认不可用（K40 dev-1123 实测 `typeof android === 'undefined'`，`$java.findClass('android.view.KeyEvent')` 正常）→ 未 install 的脚本直接 ReferenceError；
3. `$java.findClass` 对不完整类名（`KeyEvent`）没有明确中文提示。

## 3. 实现

- `packageRef().get`：**只有末段以大写开头（类名约定）才触发类解析**；中间 package 段（view/os/io/lang…）一律返回 packageRef，不对包名发 class 查询；类解析失败仍返回可 extends 的占位并给中文错误；
- 新增 `installJavaGlobals()` 并在 prelude 初始化时**默认调用**：`Packages/java/javax/android/androidx/com/org/net/io` 全局开箱可用；`require('rhino').install()` 保留且幂等（再调用只补 ensurePolling）；
- `$java.getClass/findClass`：非字符串/空 → 明确提示；不含包名 → 中文提示「需要完整类名（含包名），例如 android.view.KeyEvent；不能省略包名」；解析失败 → 中文「找不到 Java 类（已按完整类名解析）：<fullName>；<host 原因>」；
- `$java.findClass('android.view.KeyEvent')` 正常返回类对象；
- 回归：`android.os.SystemClock.elapsedRealtime()`、`java.lang.String`、`android.view.View.VISIBLE`、`java.io.File` 等既有 path-style 用法。

## 6. 限制

1. 类名解析按「末段大写」约定；全小写类名（极少见）仍按包处理，需要时用 `$java.findClass(完整类名)`；
2. 仍不支持 Java 类继承/自定义 View（defineClass 反向通道限制，error message 保持明确提示）。
